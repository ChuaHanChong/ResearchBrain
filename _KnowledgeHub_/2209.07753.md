# Code as Policies: Language Model Programs for Embodied Control

> [!summary] Summary
> Robotics at Google developed 'Code as Policies,' a method that enables pre-trained code-writing language models to directly synthesize executable Python programs for robot control. This approach facilitates precise spatial-geometric reasoning, generalizes to diverse tasks with few examples, and was demonstrated across various real robot platforms for tasks like drawing, manipulation, and navigation.

## Problem

- Existing methods for language-conditioned robot control struggle with the 'data burden,' requiring extensive and costly training data for each new skill or scenario.
- Prior large language model (LLM) approaches for robotics are limited to high-level planning, abstracting away from the perception-action feedback loop and hindering their ability to influence low-level control, generalize feedback modes, or express precise spatial relationships.
- Traditional symbolic methods are brittle and do not generalize well to novel or unseen instructions due to their reliance on explicitly defined rules.

## Method

- Pre-trained code-writing Large Language Models (LLMs) are used to directly synthesize Python programs, called Language Model Programs (LMPs), that serve as robot policies, react to perceptual inputs, and parameterize low-level control APIs.
- A few-shot prompting strategy provides the LLM with API hints and examples of instruction-to-code translations, including the use of third-party libraries (e.g., NumPy) for complex spatial-geometric reasoning.
- A novel hierarchical code generation technique allows the LLM to recursively define new functions, enabling the creation of more complex, multi-layered policy logic and facilitating more robust code generation.

## Results

- Hierarchical code generation achieved a **95%** pass rate on the new robotics-themed RoboCodeGen benchmark and improved HumanEval P@1 to **39.8%** for Codex code-davinci-002, outperforming flat generation and previous state-of-the-art.
- Code as Policies achieved **96%** accuracy on object selection and **100%** on position selection in spatial-geometric reasoning benchmarks, significantly outperforming Chain-of-Thought (**68%** and **48%**) and vanilla natural language (**39%** and **30%**).
- The method was successfully deployed on real UR5e robot arms and mobile Everyday Robots, demonstrating robust performance for tasks like drawing shapes, tabletop manipulation with nuanced spatial queries, and mobile navigation in real-world environments.

## Takeaways

> [!tip] Key Insights
> - Generating executable Python code allows language models to directly influence low-level robot control, enabling precise spatial-geometric reasoning and incorporating behavioral commonsense by leveraging external libraries like NumPy.
> - Hierarchical code generation, where a language model recursively defines undefined functions, improves performance on both general code synthesis and complex robotics-specific tasks by enabling more structured and longer code.
> - Leveraging large pre-trained code-writing language models significantly reduces the data burden traditionally associated with training robot policies, allowing for broad generalization with few-shot examples.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

The field of robotics has long grappled with the challenge of grounding natural language commands in physical actions. Traditionally, methods have fallen into a few categories:
- **Classic Methods:** These approaches often rely on lexical analysis and semantic parsing to extract structured representations from language, which then inform pre-defined policies-. While effective for specific tasks, they typically struggle with handling novel or unseen instructions due to their brittle nature and reliance on explicitly defined rules.
- **End-to-End Learning:** More recently, approaches have sought to learn direct mappings from language to actions, often using imitation learning or reinforcement learning-. While offering greater flexibility and potential for generalization, these methods demand vast amounts of training data, which is prohibitively expensive and time-consuming to acquire on real robot systems. This "data burden" remains a significant bottleneck.
- **Large Language Models (LLMs) for High-Level Planning:** The recent explosion of powerful LLMs, pre-trained on internet-scale text data-, has introduced new paradigms. LLMs have demonstrated impressive zero-shot capabilities for planning sequences of steps from natural language instructions-. Works like SayCan and Inner Monologue utilize LLMs to generate high-level plans or sequences of skills, often leveraging pre-trained, fixed robotic "skills" (e.g., behavior cloning or reinforcement learning policies)-.

**"Code as Policies" (CaP) distinguishes itself significantly from these existing paradigms.** The authors argue that while LLMs excel at high-level planning, their abstraction from the perception-action feedback loop prevents them from directly influencing low-level control, limiting their ability to:
- Generalize feedback modes (e.g., from "put the apple down on the orange" to "put the apple down *when you see* the orange").
- Express behavioral commonsense in control (e.g., "move faster," "push harder," and contextual velocity changes).
- Comprehend and execute precise spatial relationships (e.g., "move the apple a bit to the left").

Crucially, prior LLM-based planning methods *assume the existence of pre-defined skills* to execute each step in the plan. This effectively shifts the data burden from training an end-to-end system to acquiring and training a comprehensive library of robotic skills, which is still costly and domain-specific.

CaP proposes a paradigm shift: instead of generating a sequence of abstract steps that map to pre-existing skills, the LLM directly *generates the robot policy code itself*. This code, written in Python, can incorporate classic logic structures, reference third-party libraries for complex reasoning (like NumPy for spatial geometry), and directly parameterize low-level control primitive APIs. This approach eliminates the need for extensive training data for each new skill or language-conditioned policy, instead leveraging the vast knowledge encoded within code-writing LLMs. It directly tackles the limitations of previous LLM-based robot control by allowing the LLM to influence the perception-action loop and generate policies that exhibit nuanced spatial-geometric reasoning and behavioral commonsense. This makes CaP a unique and impactful contribution by pushing LLMs beyond mere high-level planning to direct, expressive, and adaptable robot control.

### 2. Key Objectives and Motivation

The primary motivation behind "Code as Policies" (CaP) stems from the limitations observed in existing methods for enabling robots to understand and act upon natural language instructions. The authors identify a critical gap: while large language models (LLMs) have shown prowess in high-level planning, they have not been deeply integrated into the perception-action feedback loop that governs real-time robot behavior.

The core objectives of this work are:
1. **Direct LLM Influence on Control:** To enable LLMs to move beyond generating abstract action sequences and directly influence low-level robot control by synthesizing executable policy code. This aims to overcome the current abstraction that prevents LLMs from grounding language in ways that generalize feedback modes, express behavioral commonsense, and comprehend precise spatial relationships.
2. **Reduce Data Burden:** To alleviate the significant data collection and model training requirements associated with traditional end-to-end learning and skill acquisition for robots. By re-purposing pre-trained code-writing LLMs, the authors aim to achieve broad generalization without additional robot-specific data.
3. **Facilitate Complex Reasoning:** To demonstrate that code-writing LLMs can generate robot policies that inherently exhibit spatial-geometric reasoning, generalize to new instructions, and infer precise values from ambiguous descriptions based on context (i.e., behavioral commonsense). This is achieved by allowing the generated code to leverage external libraries like NumPy and Shapely.
4. **Enable Reactive and Waypoint-Based Policies:** To formulate LLM-generated programs (LMPs) as a robot-centric representation capable of expressing both reactive low-level policies (e.g., impedance controllers) and waypoint-based policies (e.g., vision-based pick and place).
5. **Improve Code Generation Capabilities:** To introduce and validate "hierarchical code generation," a method that allows LLMs to recursively define undefined functions, thereby enabling the generation of more complex and structured code. A secondary objective is to show that this method also improves state-of-the-art performance on general code generation benchmarks like HumanEval.
6. **Provide a New Robotics Benchmark:** To establish a new robotics-themed code generation benchmark (RoboCodeGen) to facilitate future research and evaluation of language models in the robotics domain.

In essence, the authors are motivated to bridge the gap between high-level language understanding and low-level robot execution by leveraging the code-writing capabilities of LLMs, thereby enabling more flexible, interpretable, and data-efficient robot control.

### 3. Methodology and Approach

The core methodology of "Code as Policies" (CaP) revolves around using pre-trained code-writing Large Language Models (LLMs) to directly synthesize Python programs, referred to as Language Model Programs (LMPs), that serve as robot policies.

**A. Language Model Programs (LMPs) as Policies:**
LMPs are Python code snippets generated by an LLM that accomplish three main functions:
1. **React to Perceptual Inputs:** They process outputs from perception modules (e.g., object detectors like ViLD or MDETR), treating these as programmatic inputs from sensors.
2. **Parameterize Control Primitive APIs:** They generate code that calls and parameterizes existing low-level control APIs available to the robot (e.g., `set_velocity`, `pick_place`).
3. **Directly Executable:** The generated Python code is compiled and executed directly on the robot system at runtime.

**B. Few-Shot Prompting and Contextualization:**
The LLM (specifically, OpenAI Codex code-davinci-002 with temperature 0 for deterministic output) is prompted using a few-shot learning approach. This involves:
1. **Hints:** Providing `import` statements at the beginning of the prompt to inform the LLM about which APIs (perception and control) are available, along with type hints on how to use them. This grounds the LLM's code generation to the specific robot's capabilities.
2. **Examples:** Presenting several instruction-to-code pairs that demonstrate how natural language commands should be translated into functional Python code. These examples showcase various programming constructs, arithmetic operations, and calls to both first-party (robot-specific) and third-party libraries (e.g., NumPy for spatial reasoning, Shapely for geometry).
3. **Session Maintenance:** The system can maintain an LMP "session" by incrementally appending new instructions and generated code to the prompt, allowing for conversational interaction and reference to past actions (e.g., "undo the last action").

**C. Hierarchical Code Generation:**
A central and novel aspect of CaP is its ability to generate code hierarchically. The LLM can be prompted to define new functions recursively. This means:
- An LMP can call a function that is not yet defined.
- The system then detects these undefined functions by parsing the generated code's abstract syntax tree.
- Another specialized LMP (trained for function generation) is invoked to write the definition for that previously undefined function.
- This process is repeated in a depth-first manner, allowing for the creation of complex, multi-layered policy logic.
This "functional programming" approach, viewed as a variant of Chain-of-Thought prompting, allows for more complex code generation and improves performance, especially on tasks requiring longer code or more logic layers. It also allows LMPs to accumulate their own libraries over time.

**D. API Grounding and Third-Party Libraries:**
- **First-Party APIs:** These are robot-specific functions (e.g., `get_pos`, `put_first_on_second`). Their names are designed to be descriptive to facilitate correct usage by the LLM. Open-vocabulary object detectors (like ViLD and MDETR) are used off-the-shelf to provide the perceptual grounding for these APIs.
- **Third-Party Libraries:** The LLM's pre-training on a vast codebase means it has inherent knowledge of popular Python libraries like NumPy for numerical operations and Shapely for geometric calculations. LMPs can be prompted to leverage these libraries for spatial-geometric reasoning, allowing complex instructions (e.g., "get the left-most point," "interpolate points") to be translated into precise code without explicit programming for each scenario.

**E. Execution and Safety:**
Before execution, generated LMPs undergo basic safety checks to prevent malicious or unsafe operations. This includes ensuring no `import` statements (beyond the predefined ones), no use of `__` prefixed special variables, and no calls to `exec` or `eval` within the generated code. If the code passes these checks, Python's `exec` function is used to run the LMP within a controlled scope defined by the available APIs.

By combining the code-writing prowess of LLMs with a structured prompting strategy, hierarchical generation, and a robust API interface, CaP enables robots to interpret complex natural language instructions and generate executable policies on the fly, offering significant advantages in terms of flexibility and generalization.

### 4. Main Findings and Results

The paper presents compelling evidence for the effectiveness of "Code as Policies" (CaP) across various benchmarks and real-world robot demonstrations.

**A. Hierarchical LMPs on Code-Generation Benchmarks:**
- **RoboCodeGen:** The authors introduce a new robotics-themed benchmark with 37 function generation problems, incorporating spatial, geometric, and control tasks that encourage the use of third-party libraries. On this benchmark, hierarchical code generation significantly outperforms flat code generation across all tested LLMs (GPT-3, InstructGPT, Codex cushman, davinci). For the most capable model (Codex davinci), hierarchical generation achieved a 95% pass rate compared to 81% for flat generation. This demonstrates the benefit of allowing the LLM to decompose complex functions. The performance improved with larger models, adhering to scaling laws.
- **HumanEval:** On the standard HumanEval benchmark, hierarchical code generation also showed improvements. For Codex code-davinci-002, hierarchical prompting achieved a P@1 (pass rate at 1 sample) of 39.8%, which is higher than previously reported state-of-the-art results (e.g., 36.0% for code-davinci-001 and PaLM Coder). This indicates that the proposed hierarchical approach enhances general-purpose code generation, not just robotics-specific tasks.
- **Generalization Analysis:** An analysis across five types of generalization (Systematicity, Productivity, Substitutivity, Localism, Overgeneralization) revealed that hierarchical code generation particularly boosted "Productivity" (generating longer code or more logic layers) for larger models.

**B. Reasoning with Code vs. Natural Language (Table IV):**
To quantitatively assess the advantage of code-based reasoning, the authors created benchmarks for object selection and position selection from spatial-geometric descriptions.
- **Object Selection:** CaP (LMP) achieved 96% accuracy, significantly outperforming Chain-of-Thought (CoT) prompting (68%) and vanilla natural language (39%).
- **Position Selection:** CaP (LMP) achieved 100% accuracy, far surpassing CoT (48%) and vanilla natural language (30%).
These results highlight that while CoT helps LLMs reason about relations, LMPs excel at precise numerical and multi-step computations by leveraging Python's computational capabilities and external libraries like NumPy.

**C. Real Robot Demonstrations:**
CaP was successfully deployed and demonstrated on multiple real robot platforms, showcasing its flexibility and broad applicability:
- **Drawing Shapes (UR5e Robot Arm):** The robot could draw various 2D shapes (hexagons, lines, pyramids, circles, squares) and perform transformations (making bigger, rotating) by generating and following 2D waypoints. This demonstrated spatial-geometric reasoning and multi-step command execution.
- **Tabletop Manipulation (UR5e Robot Arm with Suction Gripper):** The robot performed pick-and-place tasks, reasoning about object descriptions ("sea-colored block"), spatial relationships ("left of the rightmost bowl," "closest to the blue bowl"), and historical context ("undo that"). It could also answer questions about the scene, leveraging open-vocabulary object detectors (MDETR).
- **Mobile Robot Navigation and Manipulation (Everyday Robots):** A mobile base robot with a 7 DoF arm successfully executed navigation tasks (e.g., "Moving in a 3m by 2m rectangle around the office chair") and manipulation tasks in a real-world kitchen environment. This demonstrated the ability to handle long-horizon reactive commands and precise spatial reasoning, using ViLD for perception.

**D. Reactive Controllers for Toy Tasks:**
The paper also showed CaP's ability to generate simple reactive controllers:
- **CartPole Balancing:** An LMP was generated to perform PD control to balance a CartPole.
- **End-Effector Impedance Control:** An LMP was created to control a UR5e robot arm's end-effector towards a goal position using joint torques, reflecting embedded knowledge of control theory in the LLM.

**E. Other LLM Capabilities Inherited:**
CaP inherited additional benefits from the underlying LLMs, such as the ability to parse commands in non-English languages and even emojis. A brittle demonstration of cross-embodiment support (adapting plans based on available robot APIs) was also shown.

In summary, the main findings confirm that CaP is a robust and highly capable method for generating expressive robot policies from natural language. Its hierarchical code generation significantly boosts performance on both general and robotics-specific coding tasks, while its ability to leverage external libraries empowers precise spatial and numerical reasoning crucial for complex robot interactions. The real-world demonstrations underscore its practical utility and generalization capabilities across diverse robotic systems and tasks.

### 5. Significance and Potential Impact

"Code as Policies" (CaP) represents a significant advancement in the field of embodied AI and human-robot interaction, offering several key areas of significance and potential impact:

1. **Bridging the Language-Action Gap with Code:** The most profound impact of CaP is its novel approach to grounding natural language in robot actions. By having LLMs directly generate executable policy code, it bypasses the need for large, robot-specific datasets for training end-to-end policies or for explicitly programming every possible skill. This directly addresses the "data burden" problem that has plagued robot learning.
2. **Enhanced Generalization and Robustness:** Leveraging the vast knowledge embedded in code-writing LLMs, CaP enables robots to generalize to unseen instructions, objects, and environments with minimal few-shot examples. This is a substantial improvement over methods that require retraining for new scenarios. The ability to utilize external libraries (like NumPy for spatial reasoning) allows for precise numerical and geometric computations that are difficult for pure natural language models or pre-trained skill-based systems to achieve.
3. **Interpretable and Modifiable Policies:** Unlike black-box neural network policies, the generated robot policies are explicit Python code. This inherent interpretability allows for easier debugging, modification, and reuse by human operators. It also provides a transparent window into the robot's "thought process" and how it translates language into action, fostering trust and collaboration.
4. **Enabling Complex, Reactive Behaviors:** CaP allows for the synthesis of complex control flows, including conditional logic (if/else) and loops (for/while), directly from natural language. This enables the creation of reactive policies that adapt to changing perceptions in real-time, such as "move rightwards until you see the apple." This level of dynamic adaptation within a generated policy is a notable capability.
5. **Accelerated Robot Development and Deployment:** By reducing the need for extensive data collection and specialized skill training, CaP could dramatically accelerate the development and deployment of robots in new domains. A system could be adapted to a new robot by simply defining its control APIs, and then LLMs could generate policies using few-shot prompts, without needing to collect thousands of demonstrations for each task.
6. **Improved Human-Robot Interaction:** The approach inherits all the benefits of large language models for human-robot dialogue, including understanding nuanced, contextual, and even ambiguous instructions. The ability to integrate "say(text)" as an action primitive allows for richer conversational interactions, where the robot can explain its actions or inquire about commands. Furthermore, the demonstrated capability to process non-English languages and emojis opens avenues for more natural and inclusive human-robot interfaces.
7. **Advancement in General Code Generation:** Beyond robotics, the "hierarchical code generation" method itself is a significant contribution, demonstrating improved performance on standard code generation benchmarks like HumanEval. This indicates a generalizable technique for boosting the capabilities of code-writing LLMs, which has implications across various software development and AI-assisted programming tasks.

**Potential Limitations and Future Work:**
Despite its significant strengths, the paper acknowledges limitations. CaP's capabilities are currently bounded by:
- **Perception API Granularity:** The robot's understanding is limited to what its underlying perception APIs can describe (e.g., it cannot describe a "bumpy trajectory" if the perception system isn't designed for it).
- **Control Primitive Availability:** The expressiveness of policies is constrained by the set of available, named control primitives. Over-saturating prompts with too many parameters can lead to issues.
- **Abstraction Gap:** LLMs may struggle with commands that operate at a significantly different abstraction level than seen in examples (e.g., "build a house with the blocks" without examples of complex 3D construction).
- **Feasibility and Correctness:** The approach assumes instructions are feasible and cannot guarantee the correctness of generated code a priori, necessitating careful safety checks and human oversight.

Despite these limitations, "Code as Policies" presents a powerful paradigm shift, offering a compelling path towards more intelligent, adaptive, and human-friendly robotic systems by leveraging the rapidly evolving capabilities of large language models for direct robot control. Its impact is likely to reverberate across both robotics and broader AI research into program synthesis and embodied intelligence.
