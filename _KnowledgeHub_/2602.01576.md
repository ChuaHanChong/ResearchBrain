# Generative Visual Code Mobile World Models

> [!summary] Summary
> gWorld is a pair of open-weight mobile GUI world models (8B and 32B) that predict the next screen as executable web code that renders to pixels, not as raw pixels. A single VLM handles this, trained on code-relabeled agent trajectories with look-ahead reasoning traces. It sets a new accuracy-versus-size frontier, beating open models up to 50.25x larger.

## Problem

- Text-based mobile GUI world models predict the next state in text, discarding fine-grained spatial layout and visual attributes such as icons, typography and color, which limits VLM-based policies.
- Pixel-generating visual world models, such as VIMO, need a complex multi-stage pipeline (OCR, masking, GPT-4o calls, diffusion). It is slow, at 160 seconds per state, and its weights are not released.
- Image-generation models mostly copy the current screen with small edits and render illegible text. Existing benchmarks convert actions to text and test only in-distribution, so real coordinate actions and OOD generalization go unmeasured.

## Method

- ==Renderable-code world modeling==: one post-trained VLM (Qwen3 VL 8B/32B) maps the current screenshot and ==coordinate action== to next-state ==web code==, which a browser renders to pixels.
- Three-step data pipeline: repurpose offline agent trajectories into ==state-action-next-state triplets==, ==relabel next-state pixels as web code== with a frontier model, and add ==reasoning traces synthesized with look-ahead== access to the true next state.
- **MWMBench**: a visual benchmark with original coordinate actions, four in-distribution sets (AitW, GUIOdyssey, AndroidControl, AMEX) and two OOD sets (AndroidWorld, Korean KApps). Scoring uses ==instruction accuracy== from a ==three-VLM judge ensemble== plus ==embedding similarity==.

## Results

- Across six benchmarks, gWorld 32B and 8B reach **79.6%** and **74.9%** average instruction accuracy. This beats GLM-4.6V 106B (**67.4%**) and Llama 4 402B (**55.7%**), and adds **45.7** and **27.1** points over the Qwen3 VL 8B and 32B base models.
- Data scaling from **37K** to **240K** samples follows a power law with average R-squared of **0.948**. Look-ahead reasoning and code relabeling each beat naive alternatives. Rendering failures fall below **1%**, and human ranking agrees with the metric (Spearman **0.806**).
- As a policy value-estimator with M3A, gWorld 8B lifts step accuracy from **62.3** to **69.9** (Gemini 2.5 Flash) and from **44.2** to **67.2** (GPT-5 Mini). End-to-end latency is **0.55s** per state, **291x** faster than VIMO.

## Takeaways

> [!tip] Key Insights
> - Choose an output representation that matches what the state is made of: structured, text-heavy GUIs suit code that renders to pixels better than direct pixel generation.
> - Image-generation world models can score high on similarity by copying the input. Judge action-conditioned correctness, and check how much output quality tracks input-output similarity.
> - Ground-truth look-ahead when synthesizing reasoning traces gives cheap, grounded supervision, and stronger world models translate to downstream policy gains at about 0.49 points per point.

## Detailed Report

### 1. Position Within the Broader Research Landscape

This work addresses mobile graphical user interface (GUI) agents, a research area concerned with systems that operate smartphones through visual observations and actions such as tapping, swiping, typing, and pressing system buttons. Recent mobile GUI agents have increasingly incorporated world models (WMs), which predict how an environment will change after an action. These predictions can support planning, action selection, policy training, synthetic trajectory generation, and risk reduction during interaction with real devices.

Existing mobile GUI world models generally use one of two representations. Text-based models describe the next state using natural language or structured textual information. They are comparatively efficient and can represent semantic changes, but they lose visual details such as exact layout, typography, colors, icons, and spatial relationships. This is problematic because many mobile policies are vision-language models whose decisions depend on the precise appearance and geometry of the interface.

Pixel-based visual world models attempt to generate the next screenshot directly. These systems preserve the visual modality, but image-generation models often have difficulty with small, discrete, and semantically important GUI elements. Text may become illegible, icons may be distorted, and layouts may not change correctly after an action. The paper discusses VIMO as an important prior example of a visual mobile GUI world model. VIMO uses OCR, masking, filtering by an external VLM, diffusion-based image generation, and text restoration. According to the authors, this pipeline creates computational cost, latency, and reproducibility concerns because it depends on multiple external models and does not release the custom diffusion-model weights.

The paper situates itself at the intersection of three areas: mobile GUI agents, generative world models, and image-to-code generation. Prior code-based world models have modeled programming environments, games, or fictional worlds, while image-to-web-code research has focused on reconstructing webpages from screenshots. The proposed contribution is to apply executable web code as the state representation for mobile GUI dynamics. Rather than predicting pixels directly, the model generates HTML and CSS that can be rendered into a mobile-sized image. The authors argue that this representation combines the semantic and linguistic strengths of VLMs with the structural and visual properties of rendered interfaces.

### 2. Objectives and Motivation

The central objective is to develop a visual mobile GUI world model that can predict an action-conditioned next interface state while maintaining textual accuracy and structural fidelity. The authors aim to address four problems.

First, the model should preserve information discarded by text-only world models. A useful next-state prediction should capture not only that an email was opened or a setting was changed, but also where elements appear, what text is displayed, which controls are active, and how the interface is visually organized.

Second, the model should avoid the rendering problems associated with direct image generation. Mobile GUIs contain highly discrete content, including short labels, buttons, menus, and forms. These elements require exact text and consistent geometry rather than approximate visual resemblance. HTML and CSS provide explicit mechanisms for representing these properties.

Third, the system should model action-contingent dynamics rather than simply copy the current screenshot. Because consecutive mobile screenshots are often highly similar, an image generator can obtain a reasonable perceptual similarity score by making minimal changes, even when it fails to apply the requested action. The proposed code-generation formulation is intended to make the model explicitly reason about the transition before producing the next state.

Fourth, the authors seek a practical and reproducible system. They introduce gWorld in 8-billion- and 32-billion-parameter versions as open-weight, single-model systems. They also introduce MWMBENCH, a benchmark intended to evaluate visual state prediction using native coordinate actions and both in-distribution (ID) and out-of-distribution (OOD) data.

### 3. Methodology and Approach

#### 3.1. Problem Formulation

The paper formulates world modeling in a Markov decision process. Given a current state \(S_t\) and action \(A_t\), the model estimates the distribution of the next state:

\[
p_\theta(S_{t+1}\mid S_t,A_t).
\]

In gWorld, the current state is supplied as a screenshot and the action is represented in the native mobile action space. The predicted next state is generated as renderable web code, together with a reasoning trace describing the expected transition.

#### 3.2. Training-Data Construction

The authors create training data from offline mobile-agent trajectories. The source datasets are Android in the Wild, GUIOdyssey, AndroidControl, and Android Multi-annotation Expo. A policy trajectory normally contains a sequence of screenshots and actions. The authors convert each episode into transition examples of the form:

\[
(S_t,A_t,S_{t+1}).
\]

They then perform two synthetic relabeling steps.

In the first step, the ground-truth next screenshot is converted into HTML code. A frontier VLM, Gemini 3 Flash, receives the screenshot and a prompt instructing it to analyze the interface and produce complete HTML5 code. The prompt emphasizes accurate text transcription, inferable button functions, mobile-first layout, and visual similarity. The resulting code is intended to render into an image resembling \(S_{t+1}\).

In the second step, the same frontier model generates a reasoning trace using the current screenshot, action, and ground-truth next screenshot. This “look-ahead” access allows the trace to describe the actual state change. During gWorld training, however, the model receives only the current screenshot and action and must predict both the reasoning and the next-state code.

The final supervised fine-tuning objective is therefore:

\[
(S_t,A_t)\rightarrow(R_t,S^{code}_{t+1}),
\]

where \(R_t\) is the reasoning trace and \(S^{code}_{t+1}\) is renderable web code. The complete dataset contains 260,000 samples, although the authors estimate that approximately 3.7 million transitions are available in the source trajectories.

#### 3.3. Model Training and Inference

The models are based on Qwen3-VL 8B and 32B. The authors fine-tune the language model and multimodal projector while freezing the vision encoder. Training uses a batch size of 64, a learning rate of \(2\times10^{-7}\), cosine scheduling, five epochs, and a maximum image resolution of 4,233,600 pixels. Inference uses greedy decoding with a maximum sequence length of 16,384 tokens.

Generated HTML is rendered in a mobile browser viewport and captured as the predicted next-state image. The authors report that rendering takes approximately 0.3 seconds per state after a one-second browser initialization cost.

#### 3.4. Benchmark and Evaluation

MWMBENCH contains six evaluation splits. Four ID splits are derived from Android in the Wild, GUIOdyssey, AndroidControl, and AMEX. Two OOD splits are newly constructed: AndroidWorld and KApps. AndroidWorld covers open-source productivity and utility applications, while KApps contains Korean-language tasks and popular Korean applications such as Baemin, Coupang, KakaoTalk, and Naver Map.

Unlike earlier benchmarks, MWMBENCH retains coordinate-based actions rather than converting them into natural-language descriptions. This evaluates whether models can use actions in a form compatible with actual mobile execution. The benchmark includes 500 sampled transitions per ID split, 686 AndroidWorld transitions, and 495 KApps transitions.

The primary metric is Instruction Accuracy (IAcc.), a binary judgment of whether the predicted state correctly follows the current state and action. Judgments are averaged across Gemini 3 Flash, GPT-5 Mini, and Claude Haiku 4.5. The study also reports image-embedding similarity using DINO v1 and DINOv2, render-failure rates, human preference rankings, and downstream policy-selection accuracy.

### 4. Main Findings and Results

Across the six MWMBENCH splits, gWorld 32B obtains an average IAcc. of 79.6%, while gWorld 8B obtains 74.9%. The strongest non-gWorld baseline in the summarized comparison is GLM-4.6V 106B with 67.4%, followed by Llama 4 402B with 55.7% and Qwen3-VL 235B with 51.5%. The base Qwen3-VL 8B and 32B models obtain 29.2% and 52.5%, respectively. Thus, post-training with the proposed data improves average IAcc. by 45.7 percentage points for the 8B model and 27.1 points for the 32B model.

gWorld also performs consistently on OOD data. Its IAcc. is 79.9% on AndroidWorld and 75.7% on KApps for the 8B and 32B configurations as reported in the main table, with the 32B model generally leading across splits. The relatively limited degradation on AndroidWorld and KApps suggests that the model can transfer action-conditioned GUI knowledge across applications and, to some degree, across language and regional interfaces.

The code representation substantially reduces structural failures. Average render-failure rates are 1.4% for gWorld 8B and 0.6% for gWorld 32B. By comparison, several VLM baselines have failure rates between approximately 1% and 40%, depending on the benchmark, and some image-generation models are not evaluated under the same renderability criterion. The authors attribute gWorld’s lower failure rate to the use of valid, executable web code rather than unconstrained image synthesis.

The analysis of image-generation models indicates that high perceptual similarity does not necessarily indicate correct world modeling. Emu3.5 and Qwen-Image-Edit obtain higher or comparable similarity in some settings but much lower IAcc. The authors report Pearson correlations of 0.92 for Emu3.5 and 0.74 for Qwen-Image-Edit between the similarity of the true transition and the similarity of the model output. This pattern suggests that these models often perform well when the true next state already resembles the input, consistent with an identity-copying strategy. gWorld shows weaker correlations of approximately 0.41–0.43, which the authors interpret as evidence that it more actively transforms the state according to the action.

Data scaling experiments using 37,000, 77,000, 129,000, and 240,000 examples show monotonic performance gains. Power-law fits across five benchmarks have coefficients of determination of at least 0.94 for most splits. Ablation studies show that trajectory-based state relabeling produces more renderable and accurate code than directly asking a frontier model to generate the next state from the current screenshot and action. Look-ahead reasoning traces also outperform traces generated without access to the target next state.

A human study involving 12 annotators and 300 annotations supports the automated evaluation. gWorld 32B has an average preference rank of 1.68, and gWorld 8B ranks second with 2.16. The reported correlations between human rankings and automatic scores are Spearman’s \(\rho=0.806\) and Kendall’s \(\tau=0.600\).

Finally, the authors test whether better world modeling improves policy decisions. In an oracle-style single-step setting with three candidate actions, adding gWorld 8B to a policy backbone improves average selection accuracy to 69.9% for Gemini 2.5 Flash and 67.2% for GPT-5 Mini. The paper reports an average relationship in which a one-point increase in world-modeling performance corresponds to a 0.49-point downstream policy improvement. The experiment isolates action selection and therefore does not establish full long-horizon agent performance.

### 5. Significance and Potential Impact

The paper’s main significance is representational. It argues that mobile GUI world models need not choose between text-only abstraction and direct pixel generation. Renderable code provides a structured intermediate format in which text, layout, controls, and styling can be explicitly represented while remaining convertible to pixels for visual policies.

The open-weight gWorld models and MWMBENCH could support more reproducible research on mobile GUI simulation. Faster inference may also make world models useful for action ranking, offline policy training, synthetic trajectory generation, and safer exploration of consequential actions without executing them on real devices.

Several limitations qualify the potential impact. The training labels and reasoning traces are generated by a frontier teacher model, which may introduce systematic errors or biases. Evaluation relies substantially on VLM-as-a-Judge metrics, despite the supporting human study. HTML is well suited to text- and structure-heavy interfaces but is less suitable for video, photographs, and other photorealistic content. The authors also use a single-frame Markov formulation and do not yet model long-term memory, which is important for tasks involving persistent state such as shopping carts or multi-page workflows. In addition, the downstream policy experiment is deliberately restricted to single-step candidate selection.

Overall, the work presents renderable code as a practical representation for visual mobile GUI dynamics and provides empirical evidence that it can improve state prediction, efficiency, and policy selection. Further validation on long-horizon interaction, real device execution, broader languages, and hybrid handling of photorealistic content would be needed to determine how well the approach functions as a general mobile environment simulator.
