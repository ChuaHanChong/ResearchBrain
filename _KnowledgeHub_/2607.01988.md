# Episodic-to-Semantic Consolidation Without Identity Drift

> [!summary] Summary
> The paper "Episodic-to-Semantic Consolidation Without Identity Drift" addresses how adaptive intelligent agents can consolidate operational knowledge without changing their cryptographically certified identity. The proposed framework reduces unproductive planner attempts by approximately 80% while ensuring the agent's identity hash remains stable.

## Problem

- Long-running adaptive intelligent agents in regulated environments face a tension between continuous operational adaptation and maintaining a stable, cryptographically verifiable identity.
- Conventional memory consolidation methods often alter the agent's underlying artifacts (e.g., model weights, prompt contexts), leading to "identity drift" that necessitates impractical continuous re-certification.
- The dilemma is that preventing consolidation inhibits crucial agent adaptation, while constant re-certification is an operational burden for compliance and auditability.

## Method

- A framework for **"identity-stable consolidation"** that structurally separates the agent's cryptographically certified ==identity manifest (M)== from its dynamically updated ==semantic memory (M_sem_A)==.
- Introduces ==structural identity invariance== (Lemma 1, Corollary 1), which formally proves that consolidation operations only write to M_sem_A, thus leaving the identity hash (derived solely from M) byte-equal.
- Employs a deterministic, auditable **v1 consolidation algorithm** that processes ==append-only episodic event logs== to derive and update structured semantic facts, exposed to planners via a read-only interface.

## Results

- Demonstrated a mean **79.82%** reduction in unproductive planner attempts when using calibrated semantic facts for grounding compared to a no-memory baseline.
- Confirmed identity hash stability: the SHA-256 hash of the IdentityManifest remained byte-equal across multiple consolidation passes, even with synthetic data.
- The v1 consolidation algorithm is computationally lightweight and scalable, with median latencies ranging from **39.9 ms** (**100 rows**) to **309.0 ms** (**100,000 rows**) and planner query latencies of **0.004 ms** at the **99th percentile**.

## Takeaways

> [!tip] Key Insights
> - Operational knowledge consolidation can be treated as a deterministic function mapping episodic event logs to a separate semantic knowledge layer, distinct from the agent's identity-defining components.
> - Explicit architectural and type-system separation of memory components allows for continuous adaptive learning (semantic memory updates) without altering the agent's immutable, cryptographically certified identity.
> - Embedding confidence values and providing audit trails within consolidated facts allows planners to leverage derived knowledge reliably while maintaining full traceability to original episodic evidence and consolidation rules.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

This research addresses a specific challenge within the field of long-running adaptive intelligent agents, particularly those deployed in regulated environments. It integrates concepts from several established research currents while introducing a novel constraint related to agent identity.

The work builds upon the **autonomic computing** tradition, which emphasizes continuous self-adaptation, monitoring, analysis, planning, and execution for deployed systems. The MAPE-K (Monitor, Analyze, Plan, Execute, Knowledge) architecture is a foundational reference. While existing work in this area, including recent developments in Information Sciences, focuses on how knowledge is represented and updated, it often implicitly assumes that the knowledge surface whose update defines the agent. This paper diverges by separating the knowledge surface (semantic memory) from the artifact defining the agent's external identity (a cryptographically certified manifest).

It draws on the **knowledge representation and reasoning** literature, specifically the distinction between episodic and semantic memory, as introduced by Tulving and further elaborated by Squire and Complementary Learning Systems theory. These traditions provide the conceptual basis for maintaining an episodic event log separate from a derived semantic knowledge layer. However, these cognitive science models do not inherently account for an engineered "identity hash" that needs preservation.

The paper contrasts with standard approaches in **continual learning** and **replay-based consolidation** in reinforcement learning. In these areas, learning mechanisms like parameter regularization, gradient projection, or replay often involve updating the agent's policy or model parameters. Such updates are generally considered performance improvements but, in this paper's context, would constitute a change to the agent's identity, requiring re-certification. This work aims to achieve knowledge update without altering the underlying policy that is bound to the identity.

Furthermore, it engages with **memory architectures for language and embodied LLM agents**, which employ reflection, skill libraries, or hierarchical memory to retain information. Current implementations typically bind the consolidated knowledge directly to the agent's operational engine (e.g., prompt context, model weights), which would cause identity drift. This paper proposes an architecture that separates consolidated knowledge from the identity-defining components.

The research also has connections to **intention-centred agent architectures** like the BDI (Beliefs, Desires, Intentions) tradition by introducing a frozen identity certificate that plays a structurally similar role to committed intentions. However, it implements this commitment via a hashed manifest and treats semantic memory as identity-orthogonal, rather than a direct view over current beliefs.

Finally, this work extends prior research on **identity-orthogonal memory**, which established the separation of an identity manifest from an episodic event log. This paper contributes by adding a *derived* semantic memory layer to this framework, proving its update also remains outside the identity hash by construction.

The central contribution is to reconcile the need for continuous operational adaptation with the requirement for stable, cryptographically certifiable agent identity, a tension not fully addressed by existing consolidation methods when applied in regulated autonomic deployments.

### 2. Key Objectives and Motivation

The primary objective of this research is to enable long-running adaptive intelligent agents to consolidate operational knowledge from their episodic experiences without altering their cryptographically certified identity. This addresses a structural tension inherent in deploying adaptive systems in regulated environments, where two often-conflicting demands arise:

1. **Adaptive Calibration:** Agents must continuously learn and adapt from lived experience. This includes updating per-task confidence based on empirical outcomes, adjusting risk posture in response to incident history, and refining operator-facing parameters to reflect ground-truth task difficulty. Without such adaptation, agents become static and less effective over time.
2. **Information Integrity and Identity Stability:** In regulated or audited contexts, agents must maintain a stable, verifiable identity. This identity, often defined by a cryptographic digest over a manifest (e.g., policy version, capability registry), is crucial for compliance, auditability, and consistent operation within cyber-physical infrastructure.

The core motivation stems from the liability introduced by conventional memory consolidation techniques (e.g., fine-tuning models, rewriting prompts, distilling policies, appending reflections). When these methods change the underlying artifacts whose hash defines the agent's certified identity, every consolidation pass effectively becomes a re-certification event. This creates an operational dilemma: continuous re-certification is impractical for compliance, while preventing consolidation inhibits adaptation, which operators cannot tolerate.

The paper aims to resolve this "stability-plasticity problem under autonomic governance" by asking: *Can an adaptive intelligent agent consolidate operational knowledge from episodic experience while its identity certificate remains byte-equal?* The authors propose that treating consolidation not as a mutation of the agent's core planner or identity manifest, but as a deterministic function mapping episodic event logs to a separate semantic knowledge layer, can achieve this. This approach seeks to allow agents to accumulate knowledge (e.g., recommended grasp forces for specific objects) as queryable facts, improving operational intelligence, without causing "identity drift" that would invalidate existing cryptographic certificates or audit contracts. The paper specifically targets embodied service agents in environments like hospitals or warehouses as a running case study to highlight the real-world relevance of this problem.

### 3. Methodology and Approach

The proposed methodology, termed "identity-stable consolidation," is realized through a framework comprising four interconnected elements designed to ensure knowledge accumulation without identity drift.

#### 3.1. Framework Overview

The framework separates the agent's state into components that are subject to change and those that define its immutable identity.
1. **Agent State Model:** Defines the agent's state as a tuple (M, M_ep_A, M_sem_A, π), where `M` is the identity manifest, `M_ep_A` is the episodic event log, `M_sem_A` is the derived semantic memory, and `π` is the planner. The identity hash `h` is strictly `SHA256(M)`.
2. **Structural Identity Invariance:** A key guarantee ensuring that the consolidation operation does not affect `h`.
3. **Deterministic v1 Consolidation Algorithm:** A specific, auditable algorithm `f: M_ep_A → M_sem_A` for populating the semantic store.
4. **Read-only Planner Interface:** An mechanism for planners to consume consolidated facts without having write access to `M` or `M_sem_A`.

#### 3.2. Agent State

The agent's state `(M, M_ep_A, M_sem_A, π)` explicitly delineates memory types.
- `M` (Manifest): A frozen dataclass with a fixed, finite set of fields that define the agent's identity. Its canonical serialization is the input to the cryptographic hash `h = SHA256(M)`.
- `M_ep_A` (Episodic Event Log): An append-only record of past interactions, partitioned by the agent's identity hash `h`. It stores timestamped observations.
- `M_sem_A` (Semantic Memory Table): A dynamically updated store of consolidated facts derived from `M_ep_A`.
- `π` (Planner): The component responsible for making decisions and generating actions, which can query `M_sem_A`.

#### 3.3. Structural Identity Invariance (Lemma 1 and Corollary 1)

The core proof of identity preservation relies on a structural property:
- **Lemma 1:** For any operation `f` belonging to the class `F_sem` (operations whose only write target is `M_sem_A`), applying `f` leaves `M` syntactically unchanged. Consequently, the identity hash `h` remains byte-equal before and after `f`'s application.
- **Proof:** This is demonstrated through "input-set inspection." The manifest dataclass's field set, fixed at type-design time, explicitly excludes any reference to `M_sem_A`. Therefore, `f`'s write footprint is disjoint from `M`'s hash-input set. This property is enforced by design and type system, not by a runtime check.
- **Corollary 1:** Extends this to any finite sequence of consolidation passes, ensuring `h` remains byte-equal throughout.

#### 3.4. Consolidation Algorithm (v1)

The initial version (`v1`) of the consolidation algorithm is deterministic and auditable.

**Schema**

The `semantic_facts` table is structured as follows:
- `id`: Primary key.
- `identity_hash`: Partitions facts by agent identity.
- `fact_kind`: Categorizes facts (e.g., `skill_success_rate`, `object_property`, `zone_risk`, `interaction_pattern`).
- `fact_key`: A stable, human-readable string identifying the specific fact (e.g., `manipulation.grasp + glass_cup + sim_relaxed`).
- `fact_value_json`: A JSON blob containing the recommended parameter, observation count, success rate (if applicable), explicit confidence value, last supporting episodic event ID, and consolidation rule version.
- `last_updated`: Timestamp of the last write.
The `(identity_hash, fact_kind, fact_key)` tuple forms a unique key, enabling upsert operations for updates.

**Algorithm Steps**

A consolidation pass for a given identity hash follows five steps:
1. **Read:** Retrieves episodic rows from `M_ep_A` recorded since the last consolidation checkpoint (itself an episodic event).
2. **Extract:** Projects structured fields (e.g., `skill_id`, `target_class`, `environment`, `outcome`) from event payloads. Rows lacking sufficient structure are skipped.
3. **Group:** Buckets records based on stable keys derived from extracted fields (e.g., `(skill_id, target_class, environment)` for `skill_success_rate`).
4. **Aggregate:** Computes statistical aggregates for each group, such as counts, success rates, parameter distributions (mean, IQR), and most common failure reasons.
5. **Upsert:** Inserts or updates a single semantic fact into `M_sem_A` for each group, incorporating cumulative observation counts, a calculated confidence value (based on count and variance), and a pointer to the last contributing episodic event. The rule version is embedded in `fact_value_json`.

- **Determinism and Idempotence:** The algorithm guarantees that two consecutive passes over the same episodic state with the same rule version produce byte-equal semantic output. It is idempotent under partial restarts and order-independent due to the commutative-associative nature of aggregates.
- **Confidence:** Explicitly records a confidence value per fact, combining observation count and within-group variance, to inform downstream planners about the reliability of the fact.

**Auditability and Scope**

- **Audit Chain:** After each pass, a `consolidation_run` event is appended to `M_ep_A`, recording the rule version, processed row range, and count of touched semantic rows. This allows traceability from any semantic fact back to its supporting episodic evidence and the rule that generated it.
- **Scope of v1 (Explicit Limitations):** `v1` deliberately does not include linguistic abstraction over free-form summaries, temporal decay or forgetting models, adversarial robustness against poisoned episodic rows, or cross-identity transfer mechanisms. These are considered out of scope to maintain determinism and auditability in the initial version.

#### 3.5. LLM-Assisted Extension (v2) (Future Work)

A potential `v2` aims to handle linguistic abstraction (e.g., deriving facts from operator notes). However, it acknowledges the trade-off with auditability due to the non-deterministic nature of LLMs. Disciplines such as provenance signing, human review gates, bounded vocabulary, and stable comparison oracles would be necessary before deployment.

#### 3.6. Planner Integration

- **Read-only HTTP Endpoint:** Exposes semantic facts via a GET request (`/api/agent/semantic`) filtered by `skill_id`, `target_class`, and `env`. Agent identity is resolved via authentication.
- **Response:** A list of confidence-ranked facts, including recommended parameters, confidence, observation count, and provenance.
- **Information, Not Authority:** Planners consume these facts as grounding information but are not required to use them. All planner intents remain subject to runtime admission, policy, and audit gates.
- **Audit Consumption:** When a planner uses semantic facts for grounding, the consulted fact IDs are recorded in the intent payload or audit trace, maintaining a complete audit trail from action to the supporting consolidated knowledge.

### 4. Main Findings and Results

The research presents empirical validation of the identity-stable consolidation framework through synthetic experiments across three main categories (V1, V2, V3) and a runtime overhead analysis (G).

#### 4.1. V1: Synthetic Deterministic Correctness

- **Fact Extraction:** A synthetic episodic database of 1000 `execution_result` rows (800 success, 200 failure) for `manipulation.grasp` resulted in exactly one `skill_success_rate` semantic fact with `{n: 1000, success: 800, rate: 0.8}`. All six per-field correctness checks passed.
- **Idempotence:** A second consolidation pass on the same database upserted zero new rows and produced a snapshot byte-equal to the first.
- **Order Invariance:** Inserting the same 1000 rows in a deterministically shuffled order produced a byte-equal semantic snapshot (modulo source-id ordering) compared to the unshuffled run.

#### 4.2. V2: Identity Invariance Under Consolidation

- **Hash Stability:** After consolidating 100 `execution_result` rows, the SHA-256 hash of the `IdentityManifest` remained byte-equal to its initial snapshot (`5f6c5afc6b3924ba4a328138...`). A second consolidation pass also yielded the same hash.
- **Hash Sensitivity:** Deliberately mutating one of the manifest inputs (e.g., `ecm_registry_hash`) correctly changed the manifest hash (`c778ffffc51d1346bb014770...`), confirming that the manifest itself is identity-bearing and the invariance result is not a trivial outcome.

#### 4.3. V3: Planner-Grounding Utility Across Four Controls

This experiment evaluated the utility of semantic facts for a planner making 1000 decisions across 10 random seeds.
- **Setup:** 200 episodic rows for `manipulation.grasp.glass_cup` (80% success) and 50 rows for `manipulation.grasp.unknown_object` (20% success) were injected. Four planner configurations were tested:
 - **`no_memory`:** Attempts every grasp regardless of skill.
 - **`uniform`:** Reads `semantic_facts`, thresholds attempts at confidence ≥ 0.5, but overrides all consolidator-known skill confidences to 1.0 (isolates structural value).
 - **`raw`:** Reads `semantic_facts`, thresholds at confidence ≥ 0.5, using the consolidator's raw success rate as confidence.
 - **`calibrated`:** Reads `semantic_facts`, thresholds at confidence ≥ 0.5, applies Bayesian shrinkage (prior mean 0.5, weight 10) to per-skill rates against a 20% held-out slice.
- **Key Finding:** The `calibrated` and `raw` controls achieved a mean **79.82% reduction** in unproductive planner attempts compared to the `no_memory` baseline (95% BCa CI [78.02%, 81.49%] across 10 seeds). This reduction was statistically significant and robust. The originally published single-seed value (74.58%) was found to be the minimum of the 10-seed distribution, understating the effect.
- **`Uniform` Control:** The `uniform` control's 95% CI straddled zero ([−4.7%, +0.4%]), indicating that simply knowing a fact exists, without a calibrated confidence signal, did not significantly improve over the no-memory baseline.
- **Sensitivity to Design Choices:** A sensitivity sweep (D sweep) confirmed the robustness of the headline reduction across various attempt thresholds (0.5 to 0.7), Bayesian shrinkage priors (0.3 to 0.5 mean, weights 5 to 20), and decision counts (N ≥ 500). Collapse regions at extreme thresholds or dominating priors were identified as non-defensible defaults.

#### 4.4. Runtime Overhead (G)

- **Per-Pass Latency:** Scaled sub-linearly with input size. Median latency ranged from 39.9 ms for 100 episodic rows to 309.0 ms for 100,000 rows, remaining within typical planner-loop budgets.
- **Semantic Table Growth:** The `semantic_facts` table grew by a constant 2 rows (O(distinct fact-key count)) regardless of episodic input size (up to 10^5 rows), consistent with the structural design.
- **Query Latency:** Planner-facing SQL queries (`SELECT ... WHERE identity_hash = ? AND fact_type = ?`) returned in 0.004 ms at the 99th percentile across 1000 requests, demonstrating low overhead for fact retrieval.
- **Memory Consumption:** The consolidator process maintained a stable 60 MB resident set with a peak delta of 15 MB at 10^5 rows.

#### 4.5. Reproducibility and Code Availability

The reference implementation (Python, ~1040 lines) and regression suite (~760 lines, 20+ test cases) are released publicly, with specific commits and data files provided to ensure reproducibility of all reported results and claims.

### 5. Significance and Potential Impact

This work introduces an information-integrity discipline for adaptive intelligent agents that addresses a fundamental challenge in their deployment: how to enable continuous operational learning without compromising a stable, cryptographically certified identity. Its significance and potential impact can be understood in several dimensions:

1. **Enabling Auditable Autonomic Deployment:** The core contribution is establishing a principled way for robots and other long-running autonomous agents to accumulate operational knowledge from experience while maintaining a byte-equal identity certificate. This is critical for regulated environments (e.g., hospitals, manufacturing) where compliance, auditability, and clear commitments are paramount. By separating operational changes from identity changes, the framework removes the burden of continuous re-certification after every learning step.

2. **Addressing the Stability-Plasticity Dilemma with Identity Constraints:** The paper successfully tackles the stability-plasticity problem, a well-known challenge in adaptive systems, but with an added, strict constraint: the agent's identity must remain cryptographically stable. Conventional continual learning methods often trade identity stability for plasticity; this work offers a method to achieve both by decoupling the learned facts from the identity-defining manifest.

3. **Enhanced Operational Intelligence and Efficiency:** The empirical results demonstrate a substantial reduction (nearly 80%) in unproductive planner attempts when semantic facts are used for grounding. This indicates that the consolidated knowledge directly translates into more efficient and effective agent behavior, making agents "operationally smarter" from their lived experience without changing who they are in a compliance sense.

4. **Deterministic and Auditable Knowledge Consolidation:** The design of the v1 consolidation algorithm as a deterministic, idempotent, and order-invariant function is significant. It ensures that semantic facts are reproducible and traceable, allowing auditors to trace any planner-consulted fact back to its supporting episodic evidence and the specific rule version that generated it. This transparency is vital for accountability in autonomous systems.

5. **Robustness and Scalability:** The sensitivity analysis confirms the robustness of the performance improvements across various configuration choices. The runtime overhead analysis indicates that the consolidation process is computationally lightweight and scalable, operating efficiently on a single CPU core with sub-linear latency and minimal memory footprint, making it suitable for frequent invocation in real-time operational loops.

6. **Structured Governance for Learning:** By treating the consolidation rule set as a versioned, governed artifact, the framework inherently integrates learning into existing operational governance structures. This means changes to how knowledge is consolidated can be managed with the same rigor as other critical system updates, preventing uncontrolled shifts in agent behavior.

7. **Foundation for Future Advanced Memory Systems:** While the v1 algorithm is intentionally limited (e.g., no linguistic abstraction, decay, or adversarial defense), it provides a stable, auditable foundation. The paper clearly articulates pathways for future extensions, such as LLM-assisted consolidation, while highlighting the necessary auditability and governance disciplines required for such advanced features. This establishes a roadmap for building more expressive memory systems on a basis of identity integrity.

In essence, this research provides a practical and formally verified solution to a critical issue in the governance of advanced autonomous agents, facilitating their secure and accountable deployment in a broader range of regulated, real-world applications.
