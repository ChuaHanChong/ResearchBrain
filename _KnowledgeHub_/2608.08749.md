# OnEvoMemory: Evolving Memory through Online Robot Rollouts for Pretrained Robot Policies

> [!summary] Summary
> OnEvoMemory is a value-guided memory module bolted onto a frozen pretrained VLA policy for long-horizon manipulation. It keeps a short-term buffer, an elite experience bank, and a transition bank, written by a learned action-conditioned value estimator and read via gated cross-attention. Offline demonstrations initialize the memory prior; successful and unsuccessful online rollouts refine writing. Success rises from 86.2% to 90.2% on LiberoLong-10.

## Problem

- Memory-augmented policies rely on external vision-language models as selectors, decoupled from the robot policy, so selection cannot adapt from online interaction outcomes.
- Predefined structures like fixed temporal windows, similarity retrieval, or hand-written update heuristics fix in advance what gets retained, regardless of the task's actual demands.
- Long-horizon tasks hinge on events like successful grasp, contact loss, or stage entry, yet no mechanism learns which of these are worth remembering.

## Method

- ==Hierarchical episode-local memory== with three banks: ==FIFO short-term raw buffer== for recent context, ==elite experience bank== for high-value states, ==transition bank== for salient value changes.
- ==Action-conditioned value estimator== emits a writing score plus retrieval key and stored value; high scores route to the elite bank, large temporal value deltas route to the transition bank.
- Retrieval mixes ==top-K similarity== with recently written entries per bank, injected into action queries by ==gated cross-attention==; online rollouts update only value estimator and memory modules, policy frozen.

## Results

- On LiberoLong-10, average success goes **86.2%** base to **88.6%** with offline-initialized memory, then **90.2%** after one round of online memory evolution.
- On RMBench SwapBlocks the frozen base policy scores **0%**; offline memory lifts it to **10.0%**, and online adaptation reaches **14.0%** success.
- RMBench SwapT moves from **0%** base to **8.0%** offline and **10.0%** online, using only **10** rollout trajectories per task (**20** per task on LiberoLong-10).

## Takeaways

> [!tip] Key Insights
> - Memory selection itself can be a learned, outcome-supervised component rather than a hand-designed heuristic, and can be trained without touching the pretrained policy.
> - Failed rollouts carry corrective signal: negative outcomes let the value estimator demote overestimated experiences, which pure demonstration data cannot supply.
> - Gains are moderate and near-zero baselines stay low, so memory alleviates but does not solve long-horizon tasks the base policy fundamentally cannot execute.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

The field of embodied artificial intelligence, particularly in robot manipulation, has made progress with policies such as vision-language-action (VLA) models and diffusion policies. However, a significant challenge in this domain is the successful execution of long-horizon tasks, which often require policies to track completed subtasks, critical interaction events, and overall task progress over extended periods. Current approaches to integrating memory into robot policies typically fall into a few categories:
- **Fixed Temporal Windows:** Policies may simply retain a fixed number of the most recent observations or actions. While straightforward, this method can quickly become overwhelmed by irrelevant information or discard crucial long-term context.
- **Similarity-Based Retrieval:** Memory systems might retrieve past experiences based on their similarity to the current state or query. This can be effective for recalling relevant past situations but relies heavily on the quality of the similarity metric and may not explicitly track task progress.
- **External Models or Predefined Rules:** Some methods leverage external vision-language models (VLMs) to identify "keyframes" or semantically important events, or they employ manually designed rules to decide what information should be stored and retrieved. Examples include approaches that use off-the-shelf VLMs to detect semantic keyframes (e.g., BPP) or high-level VLMs to select observations and generate subtask instructions (e.g., MemER). Other methods adopt predefined memory structures, such as combining sliding windows, task-boundary anchor frames, and compact tokens (e.g., MemoryWAM).

A common limitation across these existing memory mechanisms is their reliance on predetermined criteria for memory selection and updating. Whether through fixed windows, pre-trained semantic models, or hard-coded rules, these systems generally do not adapt their memory focus based on the actual outcomes of interactions with the environment. This decoupling of memory selection from the underlying robot policy's performance makes it difficult for the memory mechanism to continually refine what constitutes "important" information over time, especially when confronted with the nuances of different tasks or unexpected events. Critical events in long-horizon manipulation, such as successful grasps, loss of object contact, or transitions between task stages, have a considerable influence on subsequent decisions but are often not explicitly accounted for or adaptively learned by conventional memory systems.

OnEvoMemory aims to address this gap by introducing a system where memory selection is not static but rather learns and evolves through direct experience, specifically by leveraging successful and unsuccessful online robot rollouts. This approach seeks to enable the policy to autonomously identify and retain task-relevant information, thereby improving performance on long-horizon manipulation tasks.

### 2. Key Objectives and Motivation

The primary motivation behind OnEvoMemory stems from the observation that existing memory mechanisms for long-horizon robot manipulation often fail to adapt their focus based on real-world interaction outcomes. This limitation means they struggle to identify and retain information that is genuinely critical for task completion, especially when encountering complex or dynamic scenarios. The authors highlight that crucial events such as successful grasps, unexpected object contact loss, or the completion of intermediate task stages significantly influence subsequent decisions. Without an adaptive memory, policies may lose track of progress, repeatedly attempt already completed subtasks, or fail to recover from minor errors. This leads to the central question posed by the authors: "how can a model learn what is worth remembering?"

To address this question, the key objectives of OnEvoMemory are:

1. **To develop a hierarchical memory architecture:** The goal is to create a memory system capable of storing different types of historical information relevant to long-horizon tasks. This involves designing distinct components for recent context, high-value experiences, and salient changes in trajectory quality. This hierarchical structure is intended to provide a comprehensive yet organized representation of the robot's interaction history.
2. **To implement a learnable, value-guided memory-writing mechanism:** A core objective is to move beyond fixed temporal windows or manually defined rules for determining what information to store. Instead, the aim is to leverage an action-conditioned value estimator to assign a "writing score" to experiences, allowing the system to autonomously identify and prioritize task-relevant information for retention in the memory banks. This mechanism is designed to adaptively capture useful experiences and significant transitions based on their perceived value towards task success.
3. **To propose an online memory-evolution approach:** A critical objective is to enable the memory system to continuously refine its selection and utilization based on actual robot interaction. This involves using the outcomes of both successful and unsuccessful online rollouts to update the memory-related modules, specifically the value estimator and the memory writer. A key constraint and objective here is to achieve this online adaptation *without modifying the underlying pretrained robot policy*, thereby preserving its manipulation capabilities while improving its long-term task execution through enhanced memory. This approach seeks to provide corrective supervision for the memory mechanism from both positive and negative experiences.

By achieving these objectives, OnEvoMemory aims to enhance the ability of pretrained robot policies to effectively navigate and complete complex, long-horizon manipulation tasks by providing an adaptive and outcome-driven memory system.

### 3. Methodology and Approach

OnEvoMemory is presented as a value-guided memory mechanism designed to be initialized from offline expert demonstrations and subsequently refined through online robot rollouts. The approach is instantiated on a token-based Vision-Language-Action (VLA) policy, though the authors suggest its applicability to other policies that expose intermediate action representations.

**Overview of the System:**
Given an observation $o_t = (I_{1:V}^t, s_t, \ell)$, comprising multi-view images ($I_{1:V}^t$), proprioceptive states ($s_t$), and a language instruction ($\ell$), the base VLA policy first processes this input to produce action-query representations $Q_t = E_\theta(o_t) \in \mathbb{R}^{H \times d}$. These representations are then used in conjunction with a dynamic memory module, $M_t = \{M_S^t, M_E^t, M_T^t\}$, to inform action prediction. The memory is always read *before* the current experience is written, preventing immediate self-retrieval.

#### 3.1. Value-Guided Hierarchical Memory

OnEvoMemory employs a hierarchical memory architecture consisting of three complementary components:

- **Short-Term Raw Buffer ($M_S$):** This component functions as a fixed-capacity First-In, First-Out (FIFO) queue. It stores recent action-query representations, serving to preserve immediate visual, linguistic, and proprioceptive context.
- **Elite Experience Bank ($M_E$):** This bank is designed to retain high-value state-action experiences. Examples of such experiences include stable grasps or successfully completed intermediate task stages, which are considered crucial for robust task execution.
- **Transition Bank ($M_T$):** This component is dedicated to preserving experiences associated with salient changes in trajectory quality. This includes critical events like progress in the task, loss of contact with an object, instances of failure, or successful recovery events.

**Memory Writing Mechanism:**
The process of writing experiences into the long-term memory banks ($M_E$ and $M_T$) is guided by a learned, action-conditioned value estimator $F_\phi$. This estimator takes the enhanced action query representation ($e_{Q_t}$) and the current action ($A_t$) as input and outputs a tuple $(V_t, k_t, v_t)$.
- $V_t$: This is a trajectory-outcome-aligned writing score, indicating the estimated value or utility of the current experience for overall task success.
- $k_t$: This represents the retrieval key, used for semantic retrieval from the memory banks.
- $v_t$: This is the actual representation stored in the memory bank.

Experiences with a high $V_t$ score are considered "high-value" and are candidates for storage in the elite experience bank ($M_E$). Conversely, experiences where the absolute temporal change in value, $|V_t - V_{t-1}|$, is large are considered "salient transitions" and are written to the transition bank ($M_T$). This value-guided approach allows the system to identify and prioritize useful experiences and significant events without relying on fixed temporal windows or manually specified rules for event detection.

**Memory Retrieval and Injection:**
During retrieval, both the elite experience bank and the transition bank return two types of experiences:
1. **Semantically Relevant Experiences:** The $TopK_{sim}(Q_t, M_b^t)$ function retrieves the top $K$ experiences from bank $M_b^t$ (where $b \in \{E, T\}$) that are most semantically similar to the current action-query representation $Q_t$.
2. **Recently Written Experiences:** The $RecentK(M_b^t)$ function retrieves the $K$ most recently added experiences to ensure some temporal context from the long-term banks.
These retrieved representations ($R_E^t$ and $R_T^t$) are combined with the short-term buffer $M_S^t$ to form the comprehensive memory context $C_t$. This context is then incorporated into the base policy's action prediction through a gated cross-attention mechanism: $e_{Q_t} = Q_t + g_t MHA(Q_t, C_t, C_t)$. The gated mechanism controls the influence of the memory context. Finally, the base action decoder $D_\theta$ predicts an action chunk $\hat{A}_t$ based on the memory-enhanced query $e_{Q_t}$.

#### 3.2. Offline Initialization and Online Evolution

**Offline Initialization:**
The memory prior is established using offline expert demonstrations. These demonstrations are replayed sequentially. Earlier experiences from the demonstrations populate the memory banks ($M_S, M_E, M_T$), and subsequent observations retrieve this accumulated memory for action prediction. During this phase, action supervision (from the expert actions) and trajectory outcomes (e.g., success/failure) are used jointly to train the memory reading, writing, and injection modules, thereby initializing the value estimator and the memory's selection criteria.

**Online Evolution:**
Following offline initialization, OnEvoMemory undergoes continuous refinement through online robot rollouts. Both successful and unsuccessful trajectories collected during online interaction provide new outcome supervision. Critically, during this online adaptation phase, the pretrained vision-language backbone and the core action policy of the base VLA model remain frozen. Only the value estimator $F_\phi$ and the memory-related modules (i.e., the memory reading, writing, and injection components) are updated. This selective update mechanism allows OnEvoMemory to evolve its memory selection and utilization strategies, adapting to the nuances of specific tasks and correcting for initial biases, while preserving the fundamental manipulation capabilities of the pretrained policy.

**Experimental Setup:**
The methodology was evaluated by instantiating OnEvoMemory on QwenOFT, a specific VLA policy, as the base model. Experiments were conducted on:
- Ten tasks from the LiberoLong-10 benchmark.
- Two long-horizon tasks, SwapBlocks and SwapT, from the RMBench benchmark.
Performance was compared across three conditions: the original base VLA policy, the base policy augmented with offline-initialized memory, and the system after one round of online memory evolution. The online adaptation involved collecting 20 rollout trajectories per task on LiberoLong-10 and 10 trajectories per task on RMBench, with only the memory and value modules being updated.

### 4. Main Findings and Results

The experiments evaluated OnEvoMemory's performance by comparing a base VLA policy, the policy with offline-initialized memory, and the system after one round of online memory evolution across two manipulation benchmarks.

**Quantitative Results:**

The success rates for the evaluated benchmarks are summarized as follows:

| Benchmark / Task | Base VLA | + Offline | + Online |
| :--------------- | :------- | :-------- | :------- |
| LiberoLong-10 Avg. | 86.2% | 88.6% | 90.2% |
| RMBench SwapBlocks | 0% | 10.0% | 14.0% |
| RMBench SwapT | 0% | 8.0% | 10.0% |

- **LiberoLong-10 Benchmark:**
 - The base VLA policy achieved an average success rate of 86.2%.
 - Augmenting the policy with offline-initialized memory (+ Offline) improved the average success rate to 88.6%, representing an increase of 2.4 percentage points.
 - Further applying one round of online memory evolution (+ Online) led to an additional increase, reaching an average success rate of 90.2%. This indicates a total improvement of 4.0 percentage points over the base VLA and 1.6 percentage points over offline initialization alone.

- **RMBench Benchmark (SwapBlocks and SwapT):**
 - On these more challenging long-horizon tasks, the base VLA policy demonstrated a 0% success rate for both SwapBlocks and SwapT, indicating its inability to solve them without memory augmentation.
 - With offline memory initialization, the success rate for SwapBlocks increased to 10%, and for SwapT, it increased to 8%.
 - Following one round of online memory evolution, the success rate for SwapBlocks further improved to 14% (an additional 4 percentage points), and for SwapT, it increased to 10% (an additional 2 percentage points).

**Qualitative Observations and Analysis:**

- **Impact of Memory on Task-Stage Transitions:** The authors observed that the memory mechanism was particularly beneficial during transitions between different stages of a task. By retaining high-value experiences associated with the successful completion of subtasks, the policy was less prone to losing track of its current progress. This reduction in "getting lost" helped prevent the policy from repeatedly attempting actions corresponding to subtasks that had already been accomplished.
- **Role of Unsuccessful Rollouts in Online Adaptation:** The additional performance gains observed from online adaptation are attributed to the corrective supervision provided by unsuccessful robot rollouts. These negative examples offer crucial information for both the value estimator and the memory-writing mechanism. They help the system to revise experiences that might have been overestimated during offline initialization and to identify and retain events that are more informative for subsequent decision-making, particularly in avoiding past failures.
- **Moderation of Improvements:** While significant improvements were demonstrated, especially on the challenging RMBench tasks where the base policy initially failed, the authors note that the overall success rates for RMBench remain limited. This suggests that while OnEvoMemory offers a substantial step forward, there is still room for further enhancement in highly complex, long-horizon scenarios.

In summary, the results indicate that offline memory initialization provides a valuable foundation for improving the performance of base VLA policies on long-horizon tasks. Furthermore, the capacity for online memory evolution, driven by both successful and unsuccessful robot interactions, allows for further refinement of memory selection without requiring modifications to the underlying pretrained policy.

### 5. Significance and Potential Impact

The development of OnEvoMemory presents several significant contributions and potential impacts on the field of robot learning, particularly for long-horizon manipulation:

1. **Adaptive Memory for Long-Horizon Tasks:** The primary significance of OnEvoMemory lies in its ability to introduce a learnable and adaptive memory mechanism for pretrained robot policies. Unlike previous approaches that rely on fixed temporal windows, similarity metrics, or manually defined rules, OnEvoMemory learns *what* to remember based on the outcomes of interactions. This addresses a fundamental challenge in long-horizon manipulation where static memory structures often fail to capture dynamic task-relevant information.

2. **Enhanced Robustness and Efficiency:** By enabling policies to track completed subtasks and identify critical interaction events, OnEvoMemory can reduce redundant actions and prevent the policy from "losing track" of its progress. This can lead to more efficient and robust task execution. The qualitative finding that memory is particularly helpful around task-stage transitions highlights its utility in maintaining task coherence over extended sequences of actions.

3. **Online Refinement Without Policy Retraining:** A notable impact is the capacity for online memory evolution without modifying the pretrained base policy. This is a practical advantage, as retraining large vision-language-action (VLA) models is computationally expensive and time-consuming. OnEvoMemory's approach allows for continuous improvement and adaptation of memory selection and utilization using relatively few online rollouts, directly addressing the limitations of decoupled memory selectors. This separation of concerns — policy execution versus memory management — offers a pathway for deploying and continually refining robotic skills in dynamic environments.

4. **Leveraging Unsuccessful Experiences:** The finding that unsuccessful rollouts contribute positively to online memory evolution is significant. This implies that the system can learn from its mistakes by using negative examples to correct overestimated values and identify more informative events, thereby making the memory mechanism more robust and adaptable. This moves beyond simply reinforcing successful behaviors to actively learning from failures.

5. **Generalizability and Applicability:** While demonstrated on a token-based VLA policy (QwenOFT), the authors suggest that the proposed mechanism can be applied to other policies that expose intermediate action representations. This indicates a potential for broader impact across various robot learning architectures, offering a generalizable solution for memory augmentation in embodied AI.

6. **Advancement in Embodied AI:** OnEvoMemory contributes to the broader goal of developing more intelligent and autonomous embodied agents. By enabling robots to learn what historical information is salient and how to leverage it for future decisions, this work advances the state-of-the-art in robot cognitive capabilities and decision-making for complex, real-world tasks. The results, particularly on challenging benchmarks like RMBench where the base policy initially failed, underscore its ability to unlock new manipulation capabilities.
