# Robotic Programmer: Video Instructed Policy Code Generation for Robotic Manipulation

> [!summary] Summary
> RoboPro is a vision-language policy-code model that takes a wrist-camera image, a free-form instruction and API definitions, then writes executable robot code with no task-specific fine-tuning. Its Video2Code pipeline turns in-the-wild manipulation videos into 115k training programs. Zero-shot, it beats GPT-4o by 11.6% on RLBench and 17.4% on LIBERO, and it roughly matches the supervised PerAct baseline on RLBench.

## Problem

- Vision-language-action models map images to action tokens, but they still need fine-tuning for each new robot or environment, and real-robot trajectory collection is very expensive.
- Code-as-policy methods use language-only LLMs that need detailed text descriptions of the scene, which limits visual reasoning and generalization across environments.
- Multimodal code generators such as RoboCodeX rely on hand-built simulators and human-annotated code, which costs a lot, lacks environmental diversity and does not scale.

## Method

- ==Video2Code== plan extraction: Gemini-1.5-Flash, the Draft VLM, reads 16 key frames from about 50k instructed DROID videos and writes step-by-step, robot-centric natural-language plans.
- ==Video2Code== code translation: DeepSeek-Coder-V2 turns each plan into ==chain-of-thought== policy code using a perception/control API library backed by GroundingDINO and AnyGrasp, producing 115k image-instruction-code samples.
- **RoboPro** architecture: a SigLIP-L vision encoder feeds a code-domain CodeQwen-1.5 LLM through a two-layer MLP adaptor, trained in three stages: visual alignment, image-text pretraining, then SFT on Video2Code plus LLaVA data.

## Results

- On RLBench (9 tasks, zero-shot), RoboPro scores **42.7%** average success, against **31.1%** for GPT-4o, **23.6%** for CaP and **43.6%** for the supervised PerAct.
- On 8 LIBERO tasks, RoboPro reaches **52.4%**, against **35.0%** for GPT-4o and **14.8%** for CaP; a LoRA-fine-tuned OpenVLA reference scores **65.0%**.
- Without Video2Code data, RLBench/LIBERO success falls from **42.7/52.4** to **0.4/7.0**. With renamed APIs RLBench stays at **42.7**; with unseen task APIs RoboPro gets **44.0** against GPT-4o's **25.3**. Real-world Franka tasks: **72.5** against **60.0**.

## Takeaways

> [!tip] Key Insights
> - Ordinary manipulation videos carry procedural knowledge that can be distilled into executable code, a cheap and scalable alternative to collecting robot trajectories or hand-writing code.
> - Splitting data synthesis into two steps, a VLM that describes the plan and then a code LLM that writes the program, uses each model's strength and gives higher-quality multimodal code data.
> - Code-policy failures come mostly from logic errors (which API to call, and in what order), not from API syntax, so training on procedural knowledge matters more than knowledge of the API format.

## Detailed Report

### 1. Introduction

Robots have long promised to transform our daily lives by automating mundane tasks, yet programming them to perform varied tasks in diverse environments remains a significant challenge. Traditionally, robot programming requires domain expertise and extensive custom coding for each specific task, limiting the widespread adoption of robotic systems.

The research paper "Robotic Programmer: Video Instructed Policy Code Generation for Robotic Manipulation" introduces a novel approach to this problem. The researchers from the Chinese Academy of Sciences have developed RoboPro, a robotic foundation model that can translate visual perception and natural language instructions into executable code for robotic manipulation tasks.

### 2. The Challenge of Robot Programming

Programming robots presents several key challenges:

1. **Environment Adaptation**: Robots must function in varied environments with different objects and conditions.
2. **Task Generalization**: A robot programmed for one task often struggles to perform similar but different tasks.
3. **Natural Interaction**: End-users prefer to instruct robots using natural language rather than code.
4. **Data Scarcity**: There is limited training data showing how robots should execute specific tasks.

Previous approaches have made progress using large language models (LLMs) and vision-language models (VLMs), but they often require extensive fine-tuning or struggle with connecting visual perception to action execution.

### 3. RoboPro System Architecture

RoboPro addresses these challenges through a unified architecture that integrates:

1. **Visual Perception**: Using SigLIP-L as the vision encoder to process the robot's visual input.
2. **Language Processing**: Employing CodeQwen-1.5 (7B parameters) as the base language model to understand instructions.
3. **Code Generation**: Creating executable robot-control code that maps perception to action.

The system takes as input:
- A visual observation of the environment (e.g., an image from the robot's camera)
- A natural language instruction (e.g., "Wipe the desk")
- A predefined API library that provides perception and control modules

It then generates Python code that calls the appropriate API functions to accomplish the task. This "code-as-policy" approach offers several advantages:
- Greater expressivity than direct action prediction
- Ability to incorporate logical reasoning and conditional execution
- Transparency in how the robot makes decisions

### 4. Video2Code Pipeline

A key innovation in this research is the Video2Code pipeline, which addresses the data scarcity problem by automatically generating training data from instructional videos.

The Video2Code pipeline consists of two stages:

1. **Plan Extraction**: A "Draft VLM" (Gemini-1.5-Flash) processes video frames along with a task instruction to generate a step-by-step natural language plan.

2. **Policy Code Generation**: A "Code LLM" (DeepSeek-Coder-V2) takes the natural language plan and converts it into executable code using the provided API functions.

This approach allows the system to leverage vast amounts of publicly available instructional videos without requiring manual annotation, significantly expanding the training data available for robot learning.

### 5. Training Methodology

The training of RoboPro follows a multi-stage process:

1. **Visual Alignment**: First, the vision encoder (SigLIP-L) is aligned with the language model (CodeQwen-1.5) using a lightweight MLP adapter.

2. **Pre-training**: The system is pre-trained on image-text pairs and code generation tasks to establish strong vision-language associations.

3. **Supervised Fine-tuning (SFT)**: The model undergoes fine-tuning using the data generated by the Video2Code pipeline, plus a general vision-language dataset.

This staged approach enables the model to develop general vision-language understanding before specializing in robotic manipulation tasks, improving its zero-shot generalization abilities.

### 6. Experimental Results

The researchers evaluated RoboPro's performance on two simulation benchmarks:

1. **RLBench**: A diverse set of 36 robotic manipulation tasks
2. **LIBERO**: A benchmark with 18 household manipulation tasks

RoboPro was compared against state-of-the-art models including GPT-4o and Code-as-Policies (CaP), as well as a supervised baseline called PerAct.

The results showed that RoboPro significantly outperformed existing approaches in zero-shot task execution:
- On RLBench, RoboPro achieved a 44.0% success rate, compared to 32.4% for GPT-4o
- On LIBERO, RoboPro achieved a 51.9% success rate, compared to 34.5% for GPT-4o

The authors also conducted experiments to test RoboPro's generalization capabilities:
- **API Format Generalization**: Changing API names and function structures
- **Skill Generalization**: Adapting to new task-specific APIs
- **Data Scaling**: Testing performance with varying amounts of training data

### 7. Error Analysis

The researchers conducted a detailed analysis of the errors made by RoboPro compared to other systems. They categorized errors into several types:

1. **Logical Errors**: Incorrect reasoning about the task sequence
2. **Grounding Errors**: Failure to correctly identify objects in the environment
3. **Functional Errors**: Using incorrect API functions
4. **Execution Errors**: Problems in the physical execution of correct code

The analysis revealed that RoboPro had significantly fewer logical errors than competing systems, highlighting its improved reasoning capabilities. However, all systems still struggled with grounding errors, indicating that visual perception and object identification remain challenging.

### 8. Real-world Performance

Beyond simulations, the researchers tested RoboPro on a physical Franka Emika robot arm in a tabletop environment with various objects:

The system demonstrated impressive capabilities in the real world, including:
- Following natural language instructions like "wipe the desk" and "stack blocks"
- Handling complex multi-object manipulation tasks
- Adapting to object variations and environmental changes

### 9. Significance and Impact

The research demonstrates several important advances:

1. **Data Efficiency**: The Video2Code pipeline enables learning from unlabeled video data, significantly reducing the data collection bottleneck in robotics.

2. **Zero-shot Generalization**: RoboPro can perform new tasks in new environments without additional training, a crucial capability for practical robotic systems.

3. **Code-based Policies**: The code-as-policy approach provides transparency, interpretability, and the ability to incorporate logical reasoning.

4. **Scaling Benefits**: The authors demonstrated that performance continues to improve as more training data is used, suggesting further gains are possible with larger datasets.

### 10. Conclusion

RoboPro represents a significant step toward more adaptable and user-friendly robotic systems. By combining visual perception with language understanding and code generation, it enables robots to follow natural language instructions in diverse environments without task-specific programming.

The Video2Code pipeline addresses a critical bottleneck in robot learning by automatically generating training data from instructional videos. This approach has the potential to dramatically scale up the data available for robot training, leading to more capable and general-purpose robotic systems.

While challenges remain, particularly in visual grounding and complex task execution, RoboPro demonstrates that combining large language models with vision and code generation can produce robotic systems that are more flexible, adaptable, and accessible than previous approaches. This research opens promising avenues for developing robots that can seamlessly integrate into our daily lives and perform a wide range of useful tasks.
