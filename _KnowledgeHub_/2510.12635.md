# Memory as Action: Autonomous Context Curation for Long-Horizon Agentic Tasks

> [!summary] Summary
> Memory-as-Action (MemAct) treats working-memory management as learnable policy actions. The agent edits its own context in place with a Prune&Write operator that deletes turns by ID and writes a summary note. Dynamic Context Policy Optimization (DCPO) makes end-to-end RL feasible despite the non-monotonic context. MemAct-RL-14B matches models 16x larger while cutting context cost by about 51%.

## Problem

- Long-context agents suffer attention dilution and lost-in-the-middle failures as interaction history saturates the context, so the bottleneck shifts from capacity to actively curating what stays.
- Existing context management relies on heuristic rules, periodic summarization, or external memory controllers that ignore the agent's reasoning state, so retention cannot be optimized jointly with task performance.
- Prior RL-based memory methods impose rigid constraints such as mandatory per-step compression or coarse retrieval over a monolithic buffer, and context edits break causal-LM training assumptions of monotonic context growth.

## Method

- **Memory-as-Action** MDP: memory operations join the task actions in one ==unified policy space==, and the state is a sequence of ==uniquely ID-addressable interaction records== that the policy can reference precisely.
- ==Prune&Write operator==: one function-call action removes chosen turns by index and appends a ==synthesized memory note== in place, so memory content stays mutable and editable in later steps.
- **Dynamic Context Policy Optimization (DCPO)**: ==logically segments trajectories== fractured by context edits, so the policy trains end-to-end on standard RL infrastructure without bespoke changes and without ==train-inference mismatch==.

## Results

- MemAct-RL-14B reaches **0.591** average multi-objective accuracy versus **0.531** for Qwen3-235B and **0.514** for Search-R1, using **8.2e4** tokens, about **51%** less than Qwen3-235B and **57%** less than Search-R1.
- RL matters: multi-objective accuracy rises from **0.485** (SFT) to **0.591** (SFT+RL), and a fixed 5-turn update schedule reaches **0.516** on 8-objective tasks versus **0.543** for learned MemAct.
- Trained on at most 3 objectives, MemAct reaches **54.3%** at 8 objectives versus **39.3%** for Search-R1, and the 7B model cuts total duration by **40%** compared with Search-R1.

## Takeaways

> [!tip] Key Insights
> - Making memory edits part of the policy lets retention be optimized against task reward, beating fixed-interval schedules, sliding windows, and external memory modules that cannot see reasoning state.
> - Learned strategies adapt to backbone capacity: the 7B model prunes more often on hard tasks than the 14B model, so hand-tuned schedules would need per-model retuning.
> - Context-editing agents need training-side fixes: segmenting trajectories restores standard RL compatibility, and the approach holds under a PPO variant, so gains do not depend on the specific optimizer.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

The effectiveness of Large Language Models (LLMs) in performing complex, long-horizon agentic tasks, such as deep research or software engineering, is constrained by their ability to manage working memory. Working memory in LLMs is typically realized as the input context, which stores interaction history. However, unmanaged context can quickly accumulate irrelevant information, leading to "attention dilution" and "lost-in-the-middle" phenomena, where critical information is overlooked. This issue is known as Context Curation.

Previous research efforts to address this challenge have generally followed two main paradigms. The first focuses on expanding the LLM's raw context capacity through various long-context methods. While increasing the token window, these methods do not inherently solve the problem of managing information quality, as the effectiveness of such models still relies heavily on "Context Engineering"—the strategic curation and structuring of information. The second paradigm involves external mechanisms for context management. These include token-level compression, selective pruning, or periodic summarization, which are often computationally efficient but operate without awareness of the agent's current reasoning state, potentially leading to the loss of semantically critical information. Other approaches delegate memory operations to external controllers that manage structured information storage and retrieval. However, these decoupled architectures prevent the joint optimization of information retention and downstream task performance, as memory management decisions are not integrated into the agent's core reasoning policy.

More recent work has explored reinforcement learning (RL) to internalize memory as a learnable capability. These methods often impose rigid constraints, such as mandatory per-step compression or coarse-grained retrieval, treating context as a monolithic buffer. The current work, Memory-as-Action (MemAct), positions itself by proposing a fundamental shift: reconceptualizing context management as an intrinsic, learnable primitive that is fully integrated into the agent's policy. This approach aims to bridge the divide between task execution and memory management, enabling end-to-end optimization of both aspects within a unified framework. It specifically addresses the limitations of prior methods by allowing for fine-grained, addressable editing actions, which are intended to align memory operations with the agent's evolving reasoning needs.

### 2. Key Objectives and Motivation

The primary motivation for this research stems from the observation that while Long Language Models (LLMs) have expanded context windows, they frequently encounter performance degradation in long-horizon agentic tasks due to inefficient working memory management. The accumulation of irrelevant information leads to "attention dilution" and the "lost-in-the-middle" problem, hindering the model's ability to maintain focus and execute complex reasoning chains.

The paper identifies key limitations in existing approaches to context management:
- **Decoupled Memory Management:** Current methods often treat memory management as an external process, governed by heuristic rules or separate controllers. This decoupling prevents end-to-end optimization of information retention with respect to overall task performance. Such policy-agnostic mechanisms may delete critical information or retain redundant data, leading to suboptimal decisions.
- **Lack of Reasoning State Awareness:** External memory systems typically operate without a direct understanding of the agent’s internal reasoning state. Consequently, they cannot dynamically adapt memory curation strategies to the agent's evolving needs, which can result in the loss of crucial semantic dependencies.
- **Computational Inefficiency:** Even with expanded context windows, merely increasing capacity does not guarantee efficiency. A large, uncurated context still incurs significant computational costs for processing, leading to increased latency and resource consumption.

Against this background, the key objectives of the MemAct framework are:
1. **To propose a new paradigm for context management:** This paradigm aims to integrate working memory management directly into the agent's core policy, treating it as a set of learnable actions rather than an external or fixed mechanism. The objective is to allow agents to autonomously decide when and how to curate their context.
2. **To enable joint optimization of information retention and task performance:** By unifying memory management actions (e.g., deletion, insertion, summarization) with task-specific actions within a single policy, the framework seeks to allow end-to-end training that balances context efficiency with successful task completion.
3. **To address the computational challenges of dynamic context updates in reinforcement learning:** Non-monotonic context changes (e.g., deletions) break the causal language model assumption of strictly incremental history. An objective is to develop a training algorithm that can reconcile these dynamic updates with efficient and stable reinforcement learning, avoiding biased credit assignment.
4. **To empirically demonstrate the efficiency, adaptivity, and generalizability of learned memory strategies:** The research aims to show that agents trained with MemAct can achieve high task accuracy with significantly reduced context lengths, adapt their memory strategies to different model capabilities, and generalize these strategies across varying task complexities and domains.

In essence, the motivation is to transform context management from a static, external constraint into a dynamic, internal capability, thereby enhancing the reasoning efficiency and scalability of LLM-based agents in long-horizon tasks.

### 3. Methodology and Approach

The MemAct framework integrates working memory management as a learnable capability within an agent's policy, departing from conventional decoupled approaches. The methodology comprises an operational overview, a Markov Decision Process (MDP) formulation, and a specialized reinforcement learning algorithm named Dynamic Context Policy Optimization (DCPO).

#### 3.1. Operational Overview

MemAct internalizes context management by embedding it into the policy's action space. Instead of passively accumulating interaction history, the agent actively uses memory actions to update its context. The process involves three steps:
1. **Action Selection:** At each timestep $t$, the agent samples an action $a_t$ from an augmented action space $\mathcal{A} = \mathcal{A}_{\text{task}} \cup \mathcal{A}_{\text{mem}}$, where $\mathcal{A}_{\text{task}}$ represents standard task interactions and $\mathcal{A}_{\text{mem}}$ represents memory management operations. This allows the model to dynamically choose between reasoning and context curation.
2. **Operation Parameterization:** If a memory action is selected, the model generates specific parameters for the operation. These include a set of unique identifier (ID) indices corresponding to historical turns to be pruned, and a text field containing synthesized memory content (e.g., summary, reflection).
3. **Execution:** The system executes the pruning operation based on the specified IDs. Critically, the memory action record, including the newly synthesized memory content, is appended in-place to the context. This ensures that the curated summary remains available for future reasoning and further updates, transforming the working memory into a focused state.

#### 3.2. MDP Formulation

The agent's interaction is formalized as an MDP, with working memory structured as a sequence of uniquely addressable interaction turns.
- **State ($s_t$):** The current working memory $H_t$ is a sequence of interaction records, $H_t = [z_1, z_2, \ldots, z_k]$. Each record $z_i = (a_i, o_i, \text{id}_i)$ contains an action, its observation, and a unique identifier $\text{id}_i$ for precise referencing.
- **Action Space ($\mathcal{A}$):**
 - $\mathcal{A}_{\text{task}}$: Standard environment actions (e.g., search, web browsing).
 - $\mathcal{A}_{\text{mem}}$: The context management operator, defined as $a_{\text{mem}} = (I_{\text{target}}, c)$, where $I_{\text{target}}$ is the set of IDs to remove, and $c$ is the generated memory content (summarization, reflection, or planning).
- **Transition:**
 - For a task action, $H_{t+1} = H_t \oplus (a_t, o_t, \text{id}_{\text{new}})$.
 - For a memory action $a_t = (I_{\text{target}}, \text{content})$, the system filters $H_t$ to remove records with IDs in $I_{\text{target}}$ and appends $(a_t, o_{\text{status}}, \text{id}_{\text{mem}})$ in-place:
 $H_{t+1} = \{z_i \in H_t \mid \text{id}_i \notin I_{\text{target}}\} \oplus (a_t, o_{\text{status}}, \text{id}_{\text{mem}})$.
- **Objective:** To learn a policy $\pi_\theta(a|H_t)$ that maximizes the expected cumulative reward.

#### 3.3. Dynamic Context Policy Optimization (DCPO)

Optimizing MemAct via reinforcement learning presents a challenge: causal LLMs assume monotonic context growth, but the `Prune&Write` operator introduces non-continuous trajectories. This leads to a mismatch where deleted content might have already influenced subsequent token representations in the internal KV cache, causing biased credit assignment. DCPO addresses this by restructuring non-continuous trajectories into logically consistent, independent segments.

- **Trajectory Segmentation:** Memory actions occur at timesteps $t_{\text{mem}}^1, \ldots, t_{\text{mem}}^K$. The trajectory is re-organized into $K+1$ independent segments $\left\{\sigma_i\right\}_{i=0}^K$. Each segment $\sigma_i = (C_i, y_i)$ comprises a fixed context prefix $C_i = H_{t_{\text{mem}}^i}$ and a subsequent token sequence $y_i = y_{t_{\text{mem}}^i+1:t_{\text{mem}}^{i+1}}$. This ensures that within each segment, the sequential dependency holds locally, restoring the causal structure for stable optimization.
- **Reward Design:** Each full trajectory $\tau$ receives a sparse, terminal reward $R(\tau)$: $+1.0$ for successful task completion ($r_{\text{task}}$), $-0.1$ for constraint violations (e.g., exceeding context length or step limit, $r_{\text{pen}}$), and $0$ otherwise.
- **Reward Attribution and Optimization:** Each sampled segment $\sigma$ within a trajectory $\tau$ inherits the trajectory-level advantage $A(\tau)$. This advantage is computed using group-relative normalization: $A(\tau) = (R(\tau) - \text{mean}(R_u))/(\text{std}(R_u) + \epsilon)$, where $R_u$ is the set of rewards for all trajectories sampled for prompt $u$. The policy is optimized by minimizing an objective function $L(\theta)$ that sums clipped surrogate objectives (following GRPO) for all segments in a trajectory, ensuring gradients are computed against correctly reconstructed contexts.

#### 3.4. Implementation Details

- **Base Models:** Qwen2.5-7B-Instruct and Qwen2.5-14B-Instruct.
- **SFT Initialization:** DeepSeek-V3.1 was used to synthesize training trajectories. A staged prompting method was employed, providing soft reminders or strong instructions to use memory actions when context length fell within certain thresholds (8K-16K tokens and exceeding 16K tokens, respectively). Only successful trajectories were kept, and hints were removed to ensure autonomous learning.
- **RL Dataset:** Combined single-objective tasks from Asearcher and synthesized multi-objective tasks. Training was deliberately limited to at most three objectives to test generalization to higher complexities (4-8 objectives).
- **Training Configuration:** SFT stage for 6 epochs (batch size 256, LR 5x10^-5). RL stage using DCPO (batch size 128, constant LR 1x10^-6). Experiments conducted on NVIDIA H100 GPUs.
- **Evaluation Metrics:** Task Accuracy (LLM-based evaluator with a three-pass consensus protocol), Solved Sub-objective Count, total token usage, and frequency of tool calls.

### 4. Main Findings and Results

The experiments conducted to evaluate MemAct involved various synthetic and public benchmarks, focusing on reasoning efficiency under context pressure and generalization across task complexities.

- **Accuracy-Efficiency Trade-off:** MemAct variants demonstrated a superior Pareto frontier in terms of accuracy and context efficiency. MemAct-RL-14B achieved a multi-objective accuracy of 59.1%, surpassing Qwen3-235B (53.1%) and Tongyi-DeepResearch (56.0%). This performance was achieved with an average input context length of 3,500 tokens per step, approximately 50% shorter than Qwen3-235B and 60% shorter than Search-R1-14B.
- **Computational Cost and Latency:** MemAct-RL-14B consumed an average of 8.2 × 10^4 tokens, which is about 51% less than Qwen3-235B (16.7 × 10^4) and 57% less than Search-R1-14B (19.3 × 10^4). For latency, MemAct-RL-7B reduced total duration by 40% compared to Search-R1. This efficiency is attributed to maintaining a compact average context size, which reduces pre-fill time and improves prefix cache hit rates, and by integrating memory actions inline, avoiding costly auxiliary inference passes.
- **Ablation Analysis:**
 - **Active Context Management:** Comparing MemAct with Search-R1 (MemAct without memory actions) highlighted the benefit of active management. Despite performing more total tool calls (28.9 vs. 23.5 for 7B models), MemAct-RL-7B maintained higher accuracy by actively removing irrelevant history.
 - **Learning vs. Fixed Policies:** Reinforcement learning was found to be critical. MemAct-RL improved multi-objective accuracy from 0.485 (SFT baseline) to 0.591. A Fixed-Interval baseline, which enforced memory actions every five turns, showed reduced context size but a performance drop on complex tasks, indicating that static schedules can delete critical information, whereas MemAct learns to synchronize memory actions with the reasoning process.
- **Scalability and Generalization:**
 - **Complex Tasks:** MemAct-RL demonstrated generalization to unseen task complexities. While trained on tasks with a maximum of three objectives, it remained effective for up to eight objectives, achieving 54.3% accuracy in the 8-objective setting, significantly outperforming Search-R1 (39.3%).
 - **Domain Transfer:** MemAct exhibited stable performance across various reasoning lengths and generalized to new tool environments, such as BrowseComp-plus, even with unfamiliar web corpora.
- **Model-Specific Memory Strategies:** The framework enabled models to discover capacity-aware memory strategies:
 - **7B Model:** The 7B model, due to its limited context capacity, learned to perform more frequent memory actions (e.g., from 2.8 to 3.7 actions for 8-objective tasks in RL) and consistently removed approximately 6 records per action. It also produced longer memory records (198.7 tokens for 8-objective tasks in RL), indicating aggressive context clearing.
 - **14B Model:** The 14B model developed a bimodal pruning strategy, executing fine-grained pruning (around 2 records) to remove irrelevant context during ongoing reasoning and coarse-grained pruning (around 6 records) to clear intermediate steps upon sub-objective completion. This approach balances the need for detailed information with context space saving. This model also generally produced longer "Chain of Thought" sequences than the 7B model.
- **Robustness to Evaluation Metrics:** The relative ranking of methods remained consistent when evaluated with rule-based F1 scores, complementing the LLM-Judge metric and suggesting the observed advantages are robust.
- **PPO-based Variant:** A PPO-based variant of DCPO demonstrated competitive performance, indicating that the effectiveness of DCPO is primarily associated with its dynamic context restructuring rather than a specific policy optimization algorithm.
- **Transferability to New Backbones:** MemAct was also shown to improve the performance of a more recent open-weight backbone, Qwen3-4B, across multi-objective tasks.

### 5. Significance and Potential Impact

The Memory-as-Action (MemAct) framework presents a notable contribution to the field of Large Language Model (LLM) agents, primarily by redefining working memory management as an intrinsic, learnable capability rather than an external or fixed mechanism. This paradigm shift has several implications and potential impacts:

- **Enhanced Efficiency and Scalability:** By enabling LLMs to autonomously curate their context, MemAct significantly reduces the average context length required for long-horizon tasks. This reduction in context size directly translates to lower computational costs, improved inference latency, and reduced token consumption. This makes the deployment and operation of LLM agents more practical and scalable, particularly in resource-constrained environments or for applications requiring high throughput. The finding that MemAct-RL-14B can match the accuracy of models 16 times larger with 51% less context highlights its potential for democratizing high-performance agentic AI.
- **Improved Task Performance and Robustness:** The end-to-end optimization of memory actions alongside task execution allows agents to develop sophisticated strategies for information retention and pruning. This leads to more focused reasoning, mitigating issues like "attention dilution" and "lost-in-the-middle," thereby improving overall task accuracy and reasoning stability, especially as task complexity increases. The observed generalization of learned strategies across unseen task complexities and domains suggests a more robust and adaptable agent architecture.
- **A Foundation for Advanced Agentic Behaviors:** By treating memory management as a learnable skill, MemAct establishes a fundamental architectural building block for more sophisticated agentic behaviors. This approach encourages the development of agents that are not only capable of performing tasks but also of intelligently managing their cognitive resources. This can pave the way for agents that can learn to optimize their internal state representations in dynamic and complex environments.
- **Guidance for Future Research in Memory Systems:** The challenges identified, such as sparse rewards in long-horizon tasks, uniform segment sampling, and the lossy nature of compression, also point towards crucial avenues for future research. MemAct's framework can serve as a base for exploring more advanced reward attribution mechanisms, non-uniform memory operation sampling, and expanding the action space to include selective retrieval from external knowledge bases or tiered caching. This could lead to hybrid memory systems that combine learned curation with high-precision, scalable infrastructure.
- **Understanding Model Cognition:** The emergence of model-specific memory strategies (e.g., aggressive pruning in smaller models vs. bimodal strategies in larger ones) offers insights into how LLMs can adapt their internal "cognitive" processes to their inherent capacities. This understanding could inform the design of future LLMs that are more inherently capable of self-managing their working memory.

In summary, MemAct's contribution lies in demonstrating the feasibility and benefits of autonomous, learnable context curation, providing a more efficient, robust, and adaptable foundation for the development of future LLM-based intelligent agents.
