# MemEvolve: Meta-Evolution of Agent Memory Systems

> [!summary] Summary
> MemEvolve is a meta-evolutionary framework that jointly evolves an LLM agent's experience base and the memory architecture itself. A bilevel loop runs agents under candidate memory systems, then diagnoses failures and redesigns their encode/store/retrieve/manage modules. It is built on EvolveLab, a unified reimplementation of twelve memory systems, and lifts frameworks such as SmolAgent and Flash-Searcher by up to 17.06% while transferring across tasks, frameworks, and backbones.

## Problem

- Existing self-improving memory systems fix the pipeline by hand, so the architecture cannot adapt when different task domains demand different abstraction schemes.
- No single memory design is universally optimal: reusable-API memory suits web browsing but not math reasoning, while self-critique memory weakens in coding and tool use.
- Heterogeneous implementations across knowledge graphs, skill libraries and vector stores block fair comparison, leaving no standard substrate for controlled memory experiments.

## Method

- **EvolveLab**: a modular design space decomposing any memory into ==encode, store, retrieve and manage== under one abstract base interface, with twelve prior systems reimplemented and online/offline evaluation modes.
- ==Dual-evolution bilevel loop==: an inner loop populates memory from trajectory batches under each candidate architecture, while an outer ==meta-evolution operator== ranks candidates and spawns the next architecture generation.
- **Diagnose-and-Design** evolution: ==Pareto non-dominated sorting== over success, token cost and latency picks top-K parents, then trajectory replay yields a defect profile conditioning several constrained module redesigns.

## Results

- Flash-Searcher with GPT-5-mini reaches pass@1 of **74.71** on WebWalkerQA and **74.0** on xBench, and pass@3 of **80.61** on GAIA, surpassing OWL-Workforce and Cognitive Kernel-Pro.
- Memory evolved on TaskCraft transfers unchanged to unseen backbones and benchmarks: Kimi K2 gains **17.06%** on WebWalkerQA, with consistent **3.54-5.0%** gains across three benchmarks.
- Gains come at near memory-free cost (GAIA **$0.085** vs **$0.086**; xBench **$0.136** vs **$0.141**), whereas hand-designed baselines are inconsistent and ExpeL degrades on all three benchmarks.

## Takeaways

> [!tip] Key Insights
> - Treat the memory pipeline as a searchable design variable, not a fixed engineering choice; architecture-level search beats hand-tuning one abstraction scheme.
> - Scoring candidates on a Pareto front of accuracy, API cost and latency stops evolution from buying accuracy with runaway token spend.
> - Evolved designs converge on agentic, hierarchical, multi-level abstraction, but transfer holds only within a task regime, not across fundamentally different action spaces.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

The development of large language model (LLM)-based agents represents a rapidly evolving frontier in artificial intelligence, moving beyond static question-answering to creating autonomous entities capable of planning, executing complex tasks, and adapting to dynamic environments. A critical component enabling this autonomy is the **agent memory system**, which allows agents to accumulate experience, distill knowledge, and learn from past interactions.

Prior work in LLM agents has significantly advanced the field of "self-evolving" agents. Initially, memory systems focused on simple storage of raw trajectories for few-shot prompting. This progressed to more sophisticated approaches that abstract experiential data into various forms, such as textual insights, reasoning templates, reusable tools (e.g., APIs, code snippets), and structured knowledge representations (e.g., knowledge graphs). Prominent examples include systems like Voyager, ExpeL, Mobile-Agent-E, and SkillWeaver, each proposing different modalities and mechanisms for memory ingestion, storage, and retrieval. These systems have demonstrated impressive capabilities in allowing agents to improve their performance over time by learning from their interactions.

However, the authors identify a fundamental limitation in this prevailing paradigm: the **staticity of the memory architecture itself**. While these memory systems enable agents to evolve *within* a given memory structure, the underlying architecture (how memory is encoded, stored, retrieved, and managed) remains fixed. This fixed design poses a challenge because "no universally optimal memory architecture exists." A memory system designed for web browsing might be ineffective for mathematical reasoning, and vice-versa. Existing memory systems, therefore, act as "skillful learners" (as per the paper's analogy), proficient at learning given a fixed learning strategy, but not "adaptive learners" that can dynamically refine *how* they learn based on the task context. This limitation restricts the generalizability and long-term adaptability of LLM agents to truly open-ended environments.

MemEvolve addresses this critical gap by proposing a **meta-evolutionary framework**. Instead of fixing the memory architecture, it treats the architecture itself as something that can evolve. This positions MemEvolve as a significant advancement beyond current self-improving memory systems, moving from agent-level evolution to **meta-level evolution** of the memory system itself. By enabling the memory architecture to adapt to diverse task contexts, MemEvolve directly confronts the challenge of designing generalist agents that can truly learn and adapt across a wide spectrum of domains without requiring human re-engineering of their core learning mechanisms.

### 2. Key Objectives and Motivation

The central motivation for MemEvolve stems from the recognized limitation of existing self-evolving memory systems for LLM-based agents: their **static memory architectures**. While these systems allow agents to accumulate experience and improve, their fixed design prevents them from adapting their fundamental learning strategies to the varying demands of different tasks and environments. The paper argues that this staticity leads to suboptimal performance and limited generalizability, as a memory architecture optimized for one type of task may be ill-suited for another.

To elucidate this problem, the authors draw an analogy to human learning. They distinguish between:
1. **Mediocre learners:** Agents without memory, failing to benefit from experience.
2. **Skillful learners:** Current self-improving agents that abstract reusable skills from experience using a fixed, predefined abstraction scheme. This is likened to a student who masters a particular study technique but applies it universally, regardless of the subject.
3. **Adaptive learners:** The ideal, characterized by humans who dynamically alter their learning strategies based on the subject matter (e.g., rote memorization for literature, abstracting templates for mathematics).

The **key objective** of MemEvolve is to transition LLM agents from "skillful learners" to "adaptive learners." More formally, the paper aims to answer the question:
- "How can a memory system not only facilitate the agent system’s evolution but also meta-evolve its own architecture to achieve superior task-domain performance gains while preserving generalizability?"

To achieve this, MemEvolve's core objectives are:
1. **Jointly evolve agents' experiential knowledge and their memory architecture:** Allowing agents to accumulate experience while simultaneously refining how they learn from that experience.
2. **Introduce a tractable framework for memory architecture evolution:** Given the vast design space of memory systems, proposing a modular decomposition (Encode, Store, Retrieve, Manage) to make meta-evolution controllable.
3. **Develop a unified codebase (EvolveLab):** To ground MemEvolve in prior research, facilitate systematic experimentation, and provide a standardized platform for future research in self-evolving memory systems by re-implementing diverse existing architectures.
4. **Demonstrate substantial performance gains and generalization:** Empirically validate that the meta-evolutionary approach leads to improved task performance and that the evolved memory architectures can generalize across different tasks, LLMs, and agent frameworks.

By addressing the static nature of memory architectures, MemEvolve seeks to unlock a new level of adaptability and intelligence in LLM-based agents, enabling them to become truly adaptive and continually improving learners.

### 3. Methodology and Approach

MemEvolve tackles the challenge of meta-evolving memory systems through a two-pronged approach: first, by introducing a **modular design space** to make memory architectures tractable for evolution, and second, by implementing a **dual-evolutionary process** for joint learning.

#### 3.1. EvolveLab: Unified Codebase and Modular Design Space

Before embarking on meta-evolution, MemEvolve establishes a foundation through **EvolveLab**, a unified and extensible codebase for self-evolving agent memory systems.
- **Modular Design Space:** EvolveLab decomposes any memory system (Ω) into four fundamental and interdependent components:
 - **Encode (E):** Transforms raw experiences (trajectories, tool outputs, critiques) into structured representations.
 - **Store (U):** Integrates encoded experiences into persistent memory (e.g., vector databases, knowledge graphs, JSON).
 - **Retrieve (R):** Recalls contextually relevant memory content based on the current state and query.
 - **Manage (G):** Performs offline operations like consolidation, abstraction, or selective forgetting to maintain memory quality and efficiency.
 This modularity allows each memory architecture to be represented as a specific combination of programmatic implementations for (E, U, R, G), forming a "genotype" that can be manipulated and evolved.
- **Standardized Implementation:** EvolveLab re-implements twelve representative self-improving memory architectures (e.g., Voyager, ExpeL, SkillWeaver) within this modular design space, providing a unified `BaseMemoryProvider` abstract base class. This ensures consistency and enables fair comparisons.
- **Standardized Evaluation:** EvolveLab offers a standardized testbed with support for multiple challenging benchmarks (GAIA, xBench, TaskCraft) and evaluation paradigms (online/offline modes, exact string matching, LLM-as-a-Judge). This facilitates rigorous assessment of memory architectures.

#### 3.2. MemEvolve: Dual-Evolution Process

MemEvolve operates as a **bilevel optimization process** that jointly evolves the agent's experience base and its memory architecture. At each evolutionary iteration *k*, a finite set of candidate memory systems {Ω^(k)_j} is maintained.

- **Inner Loop (Experience Evolution):** For each candidate memory system Ω^(k)_j, the agent interacts with the environment and tasks. It populates and updates its memory state (M^(k)_t,j) based on trajectories, where new experiences (ϵ_τ) are encoded and stored according to Ω^(k)_j. This process generates a batch of trajectories T^(k)_j. The agent's performance (task success), resource consumption (token cost), and execution latency (delay) for each trajectory are aggregated into a feedback vector F^(k)_j.
- **Outer Loop (Architectural Evolution):** Based on the collected feedback summaries {F^(k)_j} from the inner loop, a meta-evolution operator (F) updates the set of memory architectures. This loop effectively learns a more effective memory architecture to accelerate future learning.

#### 3.3. Diagnose-and-Design Evolution

The meta-evolution operator **F** in the outer loop is further detailed as a "Diagnose-and-Design" process:

- **Architectural Selection:** Candidate memory architectures are ranked using multi-objective optimization, considering performance, API cost, and execution delay. Pareto-ranking is used to identify non-dominated architectures, and the top-K candidates (parent set P^(k)) are selected for evolution. This ensures that only efficient and effective architectures propagate.
- **Diagnosis:** For each selected parent architecture Ω^(k)_p, a "defect profile" D(Ω^(k)_p) is generated. This involves examining trajectory-level evidence from the inner loop's execution batch (T^(k)_p), analyzing agent outcomes, and inspecting memory behavior (e.g., retrieval failures, ineffective abstractions, storage inefficiencies). This step identifies specific architectural bottlenecks across the Encode, Store, Retrieve, and Manage components.
- **Design:** Conditioned on the defect profile, new descendant architectures {Ω^(k+1)_p,s} are constructed. This involves modifying permissible implementation sites within the modular (E, U, R, G) interface. The design step generates *S* variants by instantiating distinct yet valid configurations, ensuring that architectural changes are empirically grounded and structurally constrained.

This iterative dual-evolution, combined with the modular design space and the diagnose-and-design mechanism, allows MemEvolve to systematically refine both the agent's knowledge and its fundamental learning (memory) mechanism over time, establishing a virtuous cycle of improvement.

### 4. Main Findings and Results

MemEvolve demonstrates significant advancements in the field of LLM agent memory systems, validated through extensive experiments on four challenging agentic benchmarks (GAIA, WebWalkerQA, xBench-DeepSearch, and TaskCraft).

#### 4.1. Substantial Performance Gains

- **Improved Agent Frameworks:** MemEvolve substantially boosts the performance of underlying agentic frameworks. For instance, SmolAgent+GPT-5-Mini improved its pass@1 score on xBench from 51% to 57%, and Flash-Searcher+GPT-5-Mini saw its xBench pass@1 increase from 69% to 74%. Overall, MemEvolve led to performance gains of up to 17.06% on frameworks like SmolAgent and Flash-Searcher.
- **Robust and Consistent Improvements:** Unlike many existing self-improving memory systems which showed inconsistent or even detrimental effects on certain benchmarks (e.g., DILU degrading GAIA performance, ExpeL underperforming on new benchmarks), MemEvolve consistently delivered performance improvements (3.54% to 5.0%) across all evaluated benchmarks. This highlights its ability to discover principled and effective memory designs rather than brittle, task-specific heuristics.
- **Resource Efficiency:** Importantly, these performance gains were achieved without significantly increasing per-task API costs or execution delays. MemEvolve's API costs remained comparable to the "No-Memory" baseline, and execution delays were on par with other self-improving baselines, indicating an efficient architectural evolution.

#### 4.2. Strong Generalization Capabilities

- **Cross-Task Generalization:** Memory systems evolved on TaskCraft, a synthetic benchmark, were directly transferred and evaluated on more challenging, unseen benchmarks like WebWalkerQA and xBench-DS. These transferred memories consistently yielded performance gains (e.g., 58.82% → 61.18% on WebWalkerQA for SmolAgent), suggesting that MemEvolve learns task-agnostic principles of memory design rather than overfitting to specific datasets.
- **Cross-LLM Generalization:** Although meta-evolution was conducted using GPT-5-Mini, the evolved memory systems effectively transferred to alternative LLM backbones such as Kimi K2 and DeepSeek V3.2 without manual adaptation. For example, Kimi K2+MemEvolve improved by 17.06% on WebWalkerQA and 10.0% on TaskCraft.
- **Cross-Framework Generalization:** Memory systems evolved on TaskCraft with Flash-Searcher were successfully transferred to heterogeneous agentic frameworks like Cognitive Kernel-Pro (CK-Pro) and OWL. These transfers consistently improved the performance of these multi-agent systems despite their substantial architectural differences, demonstrating that MemEvolve discovers framework-agnostic memory abstractions.

#### 4.3. Qualitative Insights into Meta-Evolutionary Dynamics

- **Spontaneous Evolution of Efficient Architectures:** The analysis of the meta-evolutionary path (e.g., from AgentKB to Riva and Cerebra) revealed that agents spontaneously evolve increasingly efficient and agentic memory architectures. Initial architectures with frozen encoding/storage evolved to systems with multi-level abstractions, agent-driven encoding/decoding, hybrid retrieval strategies, and periodic memory maintenance.
- **Adaptive, Stage-Specific Guidance:** Evolved memory systems provide adaptive, stage-specific guidance during task execution. For example, during early planning, memory offers high-level strategies (task decomposition); during execution, it provides fine-grained tool-use suggestions and relevant context. This illustrates the practical effectiveness of the evolved memory systems in guiding agent behavior.

In summary, MemEvolve not only achieves substantial and robust performance improvements for LLM agents but also demonstrates unprecedented generalization across tasks, underlying LLMs, and agent frameworks. This is a direct consequence of its ability to meta-evolve the memory architecture itself, moving beyond static designs to truly adaptive learning systems.

### 5. Significance and Potential Impact

The work presented in "MemEvolve: Meta-Evolution of Agent Memory Systems" holds significant implications for the future of large language model (LLM)-based agents and the broader field of artificial intelligence.

#### 5.1. Enabling Truly Adaptive AI Agents

The most profound impact of MemEvolve is its departure from the conventional paradigm of manually designing fixed memory architectures. By introducing a meta-evolutionary framework, MemEvolve empowers AI agents to **learn how to learn more effectively** by adapting their core memory mechanisms. This transforms agents from "skillful learners" (who are good at learning with a fixed strategy) into "adaptive learners" (who can dynamically refine their learning strategies). This capability is crucial for developing agents that can operate robustly and efficiently in diverse, open-ended, and continuously evolving real-world environments, where no single memory design is optimal.

#### 5.2. Enhanced Performance and Generalization

The empirical results demonstrate that meta-evolution leads to substantial performance gains and, critically, strong generalization across different tasks, LLM backbones, and agent frameworks. This means that an agent's memory system can be evolved in one context (e.g., a specific set of tasks or with a particular LLM) and then effectively transferred to new, unseen contexts, leading to consistent improvements. This dramatically reduces the need for human expert intervention and re-engineering of memory systems for every new application or domain, accelerating the development and deployment of capable AI agents.

#### 5.3. A Principled Approach to Architectural Search

MemEvolve provides a principled and automated way to search the vast and heterogeneous design space of memory systems. By decomposing memory into modular components (Encode, Store, Retrieve, Manage) and employing a "diagnose-and-design" evolutionary operator guided by empirical performance feedback (including cost and delay), it offers a scalable method to discover highly effective and efficient memory architectures. This stands in contrast to the often ad-hoc or intuition-driven design processes prevalent in current research.

#### 5.4. Contribution to Open Science and Future Research

The introduction of **EvolveLab** as a unified codebase and modular design space is a significant contribution to the research community. By re-implementing twelve representative memory systems and providing a standardized testbed, EvolveLab serves as an invaluable resource for systematic study, fair comparison, and future innovation in self-evolving agent memory. This foundational work will enable other researchers to build upon MemEvolve, explore new evolutionary strategies, and accelerate progress in the field.

#### 5.5. Broader Implications for AI Systems

The concept of meta-evolution, where not just the agent's knowledge but also its underlying cognitive architecture adapts, has broader implications beyond memory systems. It opens avenues for exploring meta-learning across various components of AI agent design, such as tool-use strategies, planning algorithms, and reflection mechanisms. This could lead to more robust, autonomous, and general-purpose AI systems that can continuously improve themselves across a wider range of cognitive functions.

In conclusion, MemEvolve represents a pivotal step towards building truly intelligent and autonomous AI agents. By enabling memory systems to "meta-evolve," it tackles a fundamental limitation of current approaches, paving the way for agents that are not only capable but also inherently adaptive, efficient, and self-improving in an open-ended manner.
