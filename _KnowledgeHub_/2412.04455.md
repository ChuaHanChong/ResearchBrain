# Code-as-Monitor: Constraint-aware Visual Programming for Reactive and Proactive Robotic Failure Detection

> [!summary] Summary
> The Code-as-Monitor (CaM) framework, developed by researchers from Beihang University, Peking University, BAAI, and Galbot, introduces a unified approach for reactive and proactive robotic failure detection. It uses Vision-Language Models to generate executable monitor code based on dynamically extracted "constraint elements" for real-time spatio-temporal constraint checking, achieving improved task success rates (e.g., 17.5% higher in "Stack in Order") and reduced execution times (e.g., 34.8% less in Omnigibson) across diverse robotic tasks.

## Problem

- Robots require robust detection of unexpected failures and proactive prevention in complex, open-set environments for autonomous operation.
- Current Vision-Language Model (VLM)-based approaches for reactive failure detection are limited by slow execution, coarse 3D spatio-temporal accuracy, and lack proactive capabilities.
- Prior robotic visual programming methods often sacrifice fine-grained detail or depend on fixed primitive libraries, hindering precise constraint evaluation.

## Method

- Develops **Code-as-Monitor** (**CaM**), a framework unifying reactive and proactive failure detection by framing failures as spatio-temporal constraint satisfaction problems.
- Employs a ==Constraint Painter== module to generate precise 3D "constraint elements" (geometric abstractions of task-relevant entities) from visual observations using a fine-tuned VLM (**ConSeg**).
- Utilizes a VLM (**GPT-4o**) in the ==Constraint Monitor== to generate ==executable Python code== once per subgoal, which tracks and evaluates these constraint elements in real-time for violations.

## Results

- Achieved up to **17.5%** higher success rates and **14.4%** reduced execution time in simulated tasks like "Stack in Order" on CLIPort, outperforming prior VLM-based methods.
- Demonstrated a **34.8%** reduction in execution time and **52.2%** decrease in VLM token count in Omnigibson simulations, effectively detecting subtle 3D failures (e.g., object tilt angles).
- Showed robust real-world performance with **20.4%** higher success rates in "Simple Pick & Place" and up to **90%** success in complex "Reasoning Pick & Place" tasks, validating its generalization across diverse scenarios.

## Takeaways

> [!tip] Key Insights
> - Abstracting complex visual information into compact, trackable "constraint elements" enables precise geometric monitoring and reduces computational overhead.
> - Generating executable monitor code via VLMs for real-time evaluation of tracked elements bridges high-level VLM reasoning with fine-grained robotic control efficiency.
> - Integrating both reactive and proactive detection within a constraint-aware visual programming framework significantly enhances robotic system robustness and autonomy.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

**Challenges in Robotic Failure Detection:** As robots are increasingly expected to perform complex, long-horizon tasks in dynamic and unstructured environments, the occurrence of failures becomes inevitable. Traditional failure detection methods often rely on predefined failure modes, limiting their applicability in "open-set" scenarios where unexpected failures can occur. Furthermore, while reactive failure detection (identifying failures *after* they happen) is somewhat explored, proactive failure detection (preventing *foreseeable* failures) remains largely underdeveloped, especially for open-set problems requiring real-time, high-precision monitoring.

**Limitations of Prior VLM-based Approaches:** Recent advancements in Large Language Models (LLMs) and Vision-Language Models (VLMs) have enabled progress in open-set *reactive* failure detection, often by framing it as a visual question answering (VQA) task. However, these methods typically suffer from several drawbacks:
- **Compromised Execution Speed:** Frequent queries to computationally intensive VLMs lead to slow performance.
- **Coarse-grained Accuracy:** VLMs struggle with precise 3D spatio-temporal reasoning from single 2D images, leading to misjudgments or insufficient detail for fine-grained robotic control.
- **Lack of Proactive Capabilities:** Existing VLM-based methods are primarily reactive, lacking the ability to anticipate and prevent failures before they manifest.

**Positioning of Code-as-Monitor:** "Code-as-Monitor (CaM)" directly addresses these limitations by introducing a novel paradigm that unifies open-set reactive and proactive failure detection. It leverages the generalization power of VLMs while ensuring real-time efficiency and high precision, a gap not adequately filled by previous work. The paper positions itself at the intersection of visual programming, visual prompting, and robotic control. While prior visual programming efforts in robotics have shown promise for generalization, they often lose fine-grained details or rely on predefined primitive libraries. CaM distinguishes itself by:
- **Unified Detection:** Being the first attempt to integrate both reactive and proactive failure detection within a single framework.
- **Spatio-temporal Constraint Satisfaction:** Formulating failures as constraint satisfaction problems, which can be precisely translated into executable code.
- **Constraint Elements:** Introducing a novel concept of "constraint elements" that abstract relevant entities or parts into compact geometric forms (points, lines, surfaces). This simplifies tracking, enhances detection accuracy, and acts as a powerful visual prompt for code generation. This contrasts with methods like ReKep that use semantic keypoints, which may not be precise enough for specific constraints.

By generating executable code for real-time monitoring *once per subgoal* and tracking abstract geometric elements, CaM significantly reduces computational overhead and improves spatio-temporal precision compared to repetitive VLM queries on raw images.

### 2. Key Objectives and Motivation

The primary objectives of this research are to:
1. **Develop a unified framework for open-set reactive and proactive robotic failure detection:** The paper aims to create a system that can not only identify unexpected failures after they occur (reactive) but also foresee and prevent potential failures before they materialize (proactive), even in scenarios where failure modes are not predefined.
2. **Leverage Vision-Language Models (VLMs) for generalization while maintaining real-time efficiency and high precision:** The goal is to harness the powerful reasoning and generalization capabilities of VLMs to handle open-set scenarios, without succumbing to their typical limitations of slow execution speed and coarse-grained spatio-temporal understanding.
3. **Formulate failure detection as spatio-temporal constraint satisfaction problems:** By conceptualizing failures as violations of geometric and temporal constraints, the authors seek a more structured and programmable approach to detection.
4. **Introduce "constraint elements" to enhance monitoring accuracy and efficiency:** A key motivation is to abstract complex visual information into simpler, trackable geometric primitives that are directly relevant to constraint evaluation, thereby improving the precision and speed of the monitoring process.

The core motivation stems from the growing demand for autonomous robots to perform long-horizon tasks in complex, dynamic, and open-set environments. Failures are inevitable in such settings, making robust, real-time detection and prevention mechanisms crucial for achieving reliable closed-loop robotic systems.

### 3. Methodology and Approach

The "Code-as-Monitor (CaM)" framework consists of three main modules: the Constraint Generator, Constraint Painter, and Constraint Monitor.

#### 3.1. Overview of Code-as-Monitor (CaM)

CaM operates in a closed loop, where long-horizon tasks are broken down into subgoals. For each subgoal, textual and visual information is processed to generate and execute monitor code. If a failure is detected, the system re-plans; otherwise, it proceeds to the next subgoal.

#### 3.2. Constraint Generator

This module utilizes an off-the-shelf VLM (GPT-4o) to serve as a high-level planner. Given the global task instruction, multi-view RGB-D observations, the previous subgoal, and any failure feedback, the VLM generates:
- The **next subgoal (l_next)** to be executed.
- **Textual constraints (C)**: These are categorized into `C_d` (constraints to be maintained *during* subgoal execution, for proactive and reactive detection) and `C_u` (constraints to be met *upon* subgoal completion, for reactive detection). This VLM-driven decomposition unifies both detection modes within a constraint satisfaction paradigm.

#### 3.3. Constraint Painter

This is a crucial module for bridging VLM understanding with precise geometric monitoring. For each textual constraint, the Painter generates **constraint elements (E)** from the observed images.
- **Constraint Elements**: These are compact geometric representations (e.g., points, lines, surfaces) that abstract the constraint-related entities or their parts. For example, for a "pan should remain horizontal" constraint, the element might be a surface representing the pan's base. This abstraction eliminates irrelevant visual details, simplifying tracking and generalization.
- **ConSeg (Constraint-aware Segmentation)**: At the core of element generation is ConSeg, a fine-tuned VLM-based model (built upon LISA, using LLaVA and SAM components). ConSeg takes a textual constraint and an image as input. It performs two inference steps:
 1. Generates instance-level masks (M_i) for constraint-related entities.
 2. Generates fine-grained part-level masks (M_p) and corresponding element type descriptions (l_e).
 The VLM and vision encoder parts are frozen, while LoRA parameters and a decoder are optimized end-to-end.
- **Element Pipeline**: The 2D masks from all views are projected into 3D space using depth data. This point cloud is then refined through voxelization (size determined by `l_e`), clustering, and filtering to extract the final 3D points that form the constraint element. Points for end-effectors are obtained directly via forward kinematics. The final elements are numerically annotated onto multi-view images (O_E) to serve as visual prompts.
- **Dataset and Collection**: ConSeg is trained on a custom multi-granularity dataset derived from BridgeData V2. This dataset involves decomposing trajectory instructions into subgoals, constraints, and object-part associations, and then using Grounded SAM and Semantic SAM for automated instance and part-level segmentation, followed by manual refinement. Fine-tuning on simulator-specific data (ConSeg-ft) is performed to mitigate sim-to-real gaps, though the base ConSeg model is used for real-world tests to evaluate generalization.

#### 3.4. Constraint Monitor

This module is responsible for real-time failure detection.
- **Monitor Code Generation**: Given the next subgoal (`l_next`), textual constraints (`C`), and the annotated multi-view images with constraint elements (`O_E`), GPT-4o generates executable Python code, referred to as "monitor code." This code takes the 3D positions and historical trajectories of the elements as input.
- **Real-time Evaluation**: During subgoal execution, an off-the-shelf tracker (CoTracker) tracks the 3D positions of the constraint elements in real-time. The generated monitor code performs arithmetic operations on these tracked element positions (e.g., calculating angles, distances, checking for changes over time).
- **Failure Feedback**: If the code evaluates a constraint violation (e.g., an angle exceeds a tolerance), it returns `False` and a string explaining the reason for failure. This immediately halts policy execution, and the feedback is used by the Constraint Generator for re-planning. If all constraints are satisfied, the subgoal is considered complete. This "code-as-monitor" approach minimizes VLM calls to once per subgoal, ensuring real-time performance and precision.

### 4. Main Findings and Results

The experiments demonstrate CaM's superiority in open-set reactive and proactive failure detection across various robotic platforms, tasks, and environments.

#### 4.1. Performance in Simulators

- **CLIPort**:
 - **"Stack in Order"**: Under severe disturbances (e.g., blocks dropping, placement noise), CaM achieved a 17.5% higher success rate and reduced execution time by 14.4% compared to DoReMi. This highlights CaM's better 3D spatial reasoning via code-based evaluation of element positions, preventing misjudgments common in VLM-based VQA.
 - **"Sweep Half the Blocks"**: CaM achieved a 4.5x higher success rate than DoReMi, demonstrating more accurate counting by evaluating block points in designated regions, leading to precise policy halting.
 - **"Use Rope to Close the Opening Square"**: CaM showed superior success rate (18.34% over DoReMi) and reduced execution time by 47.43%, by precisely calculating distances between rope ends and opening edges, enabling earlier and more accurate task termination.
- **Omnigibson**:
 - **"Slot Pen" (Point-level disturbances)**, **"Stow Book" (Line-level disturbances)**, **"Pour Tea" (Surface-level disturbances)**: CaM consistently outperformed DoReMi. For example, in "Pour Tea," only CaM could detect failures caused by surface-level disturbances (teapot tilt angles), leading to a 50% success rate while DoReMi achieved 0%. This underscores the limitation of VLM queries on single images for complex 3D relationships.
 - **Computational Efficiency**: CaM achieved a 34.8% reduction in execution time and a 52.2% decrease in token count compared to DoReMi, attributed to proactive detection, real-time element tracking, and single VLM call per subgoal.
- **RLBench**: CaM demonstrated strong generalization across diverse manipulation tasks (articulated objects, rotational manipulation, tool use). For instance, in "Open Drawer," CaM achieved a 98.1% success rate vs. DRM's 90.6%, highlighting the benefits of generalizable geometric abstraction through constraint elements and VLM's prior world knowledge, even without specific training data for these tasks.

#### 4.2. Performance in Real-World Setting

- **"Simple Pick & Place"**: Using a different end-effector (Leap Hand), CaM achieved success rates 20.4% higher than DoReMi across various object types (deformable, transparent, rigid), confirming the generality of element abstraction in real-world scenarios.
- **"Reasoning Pick & Place" (Cluttered Scenes)**: CaM successfully handled long-horizon tasks with ambiguous instructions (e.g., "Clear all objects on table except for animals," "Grasp animals according to distances to fruits"). All baselines failed, while CaM achieved up to 90% success. This demonstrates CaM's ability to integrate reactive and proactive detection with open-loop policies to form a closed-loop system, allowing dynamic target adjustments in response to human disturbances and environmental changes.

#### 4.3. Constraint-Aware Segmentation Performance

- ConSeg (CaM's segmentation model) performed comparably to LISA and PixelLM on the ReasonSeg benchmark but significantly surpassed them on the proposed ConstraintSeg benchmark (nearly 40% improvement at the part level). This validates ConSeg's capability for multi-granularity, constraint-aware segmentation, which is crucial for generating precise constraint elements. Visual comparisons further showed ConSeg's generalization to unseen objects, scenes, and tasks (from datasets like RoboFail, Open6DOR, RT-1).

#### 4.4. Ablation Studies

- **Multi-View (MV)**: Crucial for visual programming, as using only front-view images reduced average success rate from 65% to 40% due to occlusion and misinterpretation of 3D geometry.
- **Constraint-aware Segmentation (CS)**: Using DINOv2 for semantic points instead of ConSeg reduced success rate from 65% to 42.5%, underscoring the need for precisely formed, constraint-representative elements.
- **Connect Points (CP)**: Using unconnected 3D points reduced success rate from 65% to 55%, as pre-formed elements provide better visual cues for code generation.
- **Elements Simplify Computation**: Not transforming entities/parts into proposed elements decreased success rate from 60% to 20% in real-world tests, due to inaccurate tracking and difficulty in performing arithmetic operations on raw 3D poses.
- **Training Data**: Both instance-level and part-level data in the custom dataset contributed to improved performance in constraint-aware segmentation, highlighting their synergistic effects.
- **Failure Detection Modes**: Proactive-only detection had lower success due to inability to handle unforeseen failures. Reactive-only had slightly higher success but longer execution times. The combination of both in CaM yielded the best performance.

### 5. Significance and Potential Impact

The "Code-as-Monitor" framework represents a significant step forward for robust and autonomous robotic systems, particularly in tackling complex, open-set manipulation tasks.

- **Enabling Robust Closed-Loop Robotic Systems**: By unifying reactive and proactive failure detection through a constraint-aware visual programming paradigm, CaM allows robots to dynamically monitor and adapt to unexpected events and foresee potential problems. This transforms inherently open-loop control policies into more robust closed-loop systems, critical for real-world deployment.
- **Bridging VLM Generality with Robotic Precision**: The paper effectively addresses the trade-off between the high-level reasoning and generalization of VLMs and the need for real-time, high-precision control in robotics. The introduction of "constraint elements" is a key innovation, providing a structured, geometric abstraction that allows VLMs to generate executable code for precise spatio-temporal constraint checking without constant, computationally expensive queries.
- **Enhanced Efficiency and Reduced Computational Cost**: By generating monitor code once per subgoal and leveraging efficient object tracking, CaM drastically reduces the reliance on frequent VLM inferences during execution, leading to faster operation and lower token usage compared to prior VLM-based reactive methods.
- **Generalizability Across Diverse Scenarios**: Demonstrated across multiple simulators, real-world setups, various robot platforms, end-effectors, object types, and complex tasks, CaM exhibits strong generalization capabilities. This is crucial for expanding robotic autonomy beyond controlled laboratory settings to dynamic and unstructured environments.
- **Potential for Advanced Robotic Applications**: This framework could unlock new possibilities in areas like complex assembly, human-robot collaboration, dynamic environment navigation, and long-duration autonomous operation, where failures are common and adaptation is essential.

**Limitations and Future Work**: The authors acknowledge limitations, including potential VLM hallucinations in code generation and segmentation, and the current inability of constraint elements to detect force-direction-related failures without noticeable displacement. Future work aims to integrate more knowledge (e.g., via RAG) to mitigate hallucinations and explore richer multimodal representations to capture cues beyond explicit displacement, such as water flow or sounds, further enhancing the system's perception and detection capabilities. Despite these, CaM's innovative approach to unifying failure detection modes and leveraging visual programming for precise, real-time monitoring lays a strong foundation for the next generation of intelligent robots.
