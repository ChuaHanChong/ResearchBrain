# Causal Episodic Memory for Feedback-Driven Agent Repair

> [!summary] Summary
> MERIT is a training-free Text-to-SQL repair agent that turns finished repair episodes into reusable experience. It stores oracle-verified corrections as positive memory and failed directions as negative memory, tags each with a deterministic failure type, and retrieves precedents with a hybrid dense-BM25 ranker before a frozen Qwen2.5-7B-Instruct writes each revision. Execution accuracy rises from 66.34% to 69.79% on Spider and 47.35% to 48.44% on BIRD.

## Problem

- Iterative self-correction methods like Self-Debugging and Self-Refine treat each query as a fresh problem, discarding useful corrections once the episode ends.
- Retrieval-based Text-to-SQL prompting selects question-SQL demonstrations for initial generation from a pre-built pool, never reusing repair transformations discovered after a prediction fails.
- Cross-episode memory systems organize experience by semantic similarity alone, conflating unsuccessful attempts with verified corrections and ignoring which failure produced each entry.

## Method

- Online dual-polarity memory: each finalized episode contributes at most one entry, positive for an oracle-confirmed failed-to-correct transition, negative for the final direction of an unresolved episode.
- A deterministic error classifier maps DBMS status and error text to seven coarse types (result mismatch, schema linking, aggregation, filter/value, execution, syntax, unknown) via ordered first-match rules.
- Type-conditioned hybrid retrieval ranks precedents by 0.75 dense plus 0.25 BM25, restricted to the predicted type when three same-type entries exist; causal constraint blocks current-episode and future memories.

## Results

- MERIT lifts Spider execution accuracy 66.34% to 69.79% (paired 95% CI +1.97 to +4.96 points) and BIRD 47.35% to 48.44%, whose interval starts at zero.
- MERIT ties Dynamic RAG on Spider and leads it 0.28 points on BIRD; Reflexion-style wins BIRD at 51.24% but costs 22.4M tokens versus MERIT's 17.6M.
- Ablations: cross-database-only retrieval costs 0.93 points on Spider and 2.74 on BIRD; dropping negative memory costs only 0.13/0.09 points; classifier accuracy is ~48%, macro-F1 0.32-0.36.

## Takeaways

> [!tip] Key Insights
> - Schema-local experience is the most transferable signal: memories from the same database beat cross-database analogies, so scope retrieval to the environment before scoping by failure taxonomy.
> - A coarse failure taxonomy works as a retrieval prior, not a hard partition; with ~48% classifier accuracy, soft type bonuses and fallback pools stay competitive.
> - Verified successes carry most of the signal; negative memory adds little, and memory raises token cost even when it cuts model calls.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

The development of dependable language agents capable of continuous learning and adaptation from environmental feedback is a significant area of research in artificial intelligence. Traditional approaches for improving Large Language Model (LLM) agents, such as ReAct, Self-Refine, CRITIC, and Self-Debugging, often focus on enhancing an agent's output through iterative feedback, external tools, or execution signals within a single interaction episode. These methods have demonstrated the value of grounding correction in external evidence, contrasting with the potential unreliability of intrinsic self-correction.

In the domain of Text-to-SQL, specific techniques like DIN-SQL, CHASE-SQL, and SQL-PaLM have advanced semantic parsing through structured reasoning, candidate generation, and instruction tuning. Retrieval-based prompting methods, such as DAIL-SQL and ACT-SQL, further improve initial generation by selecting relevant question-SQL demonstrations. However, a common characteristic of many of these existing methods is that they primarily treat each new query as an independent problem. Consequently, successful corrections discovered during one episode are typically not retained or systematically reused when similar failures occur in subsequent tasks, leading to repetitive rediscovery of solutions.

This research addresses a gap in the current landscape by exploring how an agent can improve its repair capabilities over time by retaining and organizing "causal cross-query memory." While general agent memory architectures like Reflexion, ExpeL, MemGPT, and Generative Agents utilize memory to transfer information across episodes, they do not specifically organize repair memories by failure type and correction outcome. This omission can result in the retrieval of irrelevant episodes or the conflation of unsuccessful attempts with verified corrections. This paper investigates whether a structured, episodic memory, explicitly designed for repair and organized by failure types and outcomes, can facilitate learning from experience without requiring parameter updates to the underlying LLM. The work positions itself at the intersection of execution-guided LLM agent repair and advanced memory systems for continuous learning.

### 2. Key Objectives and Motivation

The primary objective of this research is to investigate whether finalized repair outcomes from earlier Text-to-SQL episodes can be effectively utilized to improve the repair performance of subsequent episodes, without requiring parameter updates to the underlying language model. The authors aim to introduce a framework that enables agents to learn from and retain successful corrections and observed unsuccessful directions, thereby overcoming the limitation where agents often discard valuable repair experience.

The motivation for this work stems from several observations within the field of LLM agent development:
1. **Redundant Solution Discovery:** Current LLM agents, when encountering failures in tasks like Text-to-SQL, often lack a mechanism to persistently store and reuse successful corrections. This stateless nature means that if a similar failure type (e.g., missing joins, invalid schema references, incorrect aggregations) recurs in a later query, the agent is compelled to rediscover the solution, leading to inefficiency and slower progress.
2. **Limitations of Existing Memory Approaches:** While some LLM agents incorporate cross-episode memory (e.g., Reflexion, ExpeL), these approaches often retain verbal reflections or general knowledge from past trajectories without specifically organizing repair memories by the *failure* that produced them and the *outcome* of the attempted *correction*. This can lead to less precise or even irrelevant retrieval, diminishing the utility of stored experience for targeted repair.
3. **Enhancing Agent Dependability:** To achieve dependable language agents, it is essential for them to not only respond to immediate environmental feedback but also to retain and generalize what they learn from these interactions. A system that can leverage prior repair experiences without retraining the base model would represent a step towards more adaptable and robust agents.

To address these motivations, the authors define three specific contributions:
- **Introduction of MERIT:** They propose MERIT (Memory-Augmented Error-Typed Retrieval for Iterative Text-to-SQL repair) and formulate Text-to-SQL correction as a process leveraging causal episodic memory. This formulation restricts memory availability to only outcomes from finalized earlier episodes, guiding the current query.
- **Error-Guided Hybrid Retrieval:** They develop a retrieval mechanism that organizes repair experience based on its outcome (positive for verified corrections, negative for observed failures) and a coarse failure type. This mechanism utilizes a hybrid lexical-dense ranking approach to select relevant precedents.
- **Controlled Evaluation:** They conduct a controlled evaluation using multiple stream orders to compare MERIT's accuracy, repair behavior, and inference cost against alternative cross-query memory strategies, aiming to clarify when causal cross-query memory offers benefits.

### 3. Methodology and Approach

MERIT (Memory-Augmented Error-Typed Retrieval for Iterative Text-to-SQL repair) is a training-free agent designed to accumulate and utilize structured repair experience online. The methodology integrates a deterministic failure classifier, an online dual-polarity memory, and a type-conditioned hybrid retriever within a causal online repair formulation.

#### 3.1. Causal Online Repair Formulation

At each stream position `t`, the agent processes a new query `q_t` with its schema `S_t`, optional dataset evidence `a_t`, an executable database `D_t`, and a shared initial SQL prediction `y_t^(0)`. This initial prediction is generated once with greedy decoding and remains fixed across all repair methods to isolate the effect of the repair strategy.

**Observable Feedback and Benchmark Correctness:** Experiments are conducted in a `denotation_confirmed` regime. After each repair attempt `k`, a benchmark evaluator returns `V(D_t, y_t^(k)) = (z_t^(k), ε_t^(k))`, where `z_t^(k)` indicates the status (CORRECT, DENOTATION MISMATCH, EXECUTION ERROR, or TIMEOUT) and `ε_t^(k)` provides any observable Database Management System (DBMS) error. The reference SQL and result rows are internal to the evaluator and not exposed to the model. The reported setting is characterized as "oracle-assisted benchmark repair" because the oracle decision dictates episode termination and memory polarity.

Each initially incorrect query initiates an "episode." The agent maintains a local history `H_t^(k)` of attempts for the current query. Crucially, `M_<t` contains memory entries *only* from finalized episodes at earlier stream positions (`sourcePos(x) < t`). The global memory is updated only upon episode termination. This "causal" constraint ensures that the current query cannot access its own unfinished trajectory or future experience. The objective is to achieve a `CORRECT` status within a budget of `K=7` repair generations.

#### 3.2. MERIT: Correction and Experience Accumulation

MERIT's core mechanism involves an iterative repair loop that activates when an initial SQL prediction fails.

**Initialization and Failure Diagnosis:**
If `y_t^(0)` is correct, the episode finalizes without memory creation. Otherwise, `H_t^(0)` is initialized with `y_t^(0)`, and the repair loop begins. At each step `k`, a deterministic classifier maps the unsuccessful query `y_t^(k-1)` to a coarse failure type `τ_t^(k-1)`. The classifier uses a predefined set of ordered rules based on execution status and observable DBMS error text. Categories include RESULT MISMATCH, SCHEMA LINKING, AGGREGATION, FILTER/VALUE, EXECUTION, SYNTAX, and UNKNOWN. It does not inspect the SQL AST or infer semantic errors like incorrect joins. This label is recomputed after each unsuccessful revision and acts as a retrieval prior.

**Online Dual-Polarity Memory:**
MERIT maintains a memory `M_<t` partitioned into positive (`M_+_<t`) and negative (`M_-_<t`) pools. Each memory entry `x` is structured as `⟨c, τ, ∆, o, ρ⟩`, comprising the source question/schema/unsuccessful SQL/status/feedback (`c`), source failure type (`τ`), observed SQL transformation (`∆`), polarity (`o` ∈ {+, -}), and provenance (`ρ`).
- **Positive entries:** Record an oracle-confirmed "failed-to-correct" transition (`y- → y+`).
- **Negative entries:** Record the final direction attempted in an unresolved episode, indicating only that it failed in its source context.

**Causal, Type-Conditioned Retrieval:**
Candidate retrieval is performed independently for positive and negative polarities. `L_t,p` denotes the pool of legal (causally available, same-polarity) memories. `T_t,p` is the subset of `L_t,p` with the same predicted failure type `τ_t^(k-1)`.
- **Candidate Selection:** If `T_t,p` has at least three entries, MERIT retrieves from `T_t,p`; otherwise, it falls back to the full `L_t,p`.
- **Hybrid Ranking:** Dense and BM25 scores are independently min-max normalized within their respective pools. The full MERIT ranks candidates using `r(x, u) = 0.75 * b_d(x, u) + 0.25 * b_b(x, u)`, where `b_d` and `b_b` are the normalized dense and BM25 scores. The retrieval query concatenates the current question, SQL, failure context, and error type. MERIT retrieves at most three positive and one negative entry. The dense encoder used is BAAI/bge-large-en-v1.5, and BM25 is a custom implementation.

**Repair Generation and Validation:**
The repair prompt is constructed from the question, schema, current SQL, attempt status, DBMS error, predicted failure type, local history `H_t`, and the retrieved memories. Positive entries are presented as "confirmed successful repair directions," and negative entries as "observed failed directions." The frozen `Qwen2.5-7B-Instruct` model generates one revision `y_t^(k)` using greedy decoding. This revision is appended to `H_t` and evaluated. If correct, the episode terminates. Otherwise, the failure is reclassified, and the loop continues until correctness or budget exhaustion.

**Episode Finalization and Memory Update:**
If repair succeeds at step `k*`, a positive entry is created from the `y_t^(k*-1) → y_t^(k*)` transition. If repair fails after `K` generations, a negative entry is created from the final `y_t^(K-1) → y_t^(K)` direction. This finalized entry `x_t` is then added to the global memory `M_<(t+1)`, making it visible only to subsequent queries (`t+1` and beyond).

#### 3.3. Type-Reliability-Aware Retrieval Variant

This variant explores a modification to how error types influence retrieval. It defines high-reliability types (`h(τ) = 1`) for SYNTAX, SCHEMA LINKING, and EXECUTION, and `h(τ) = 0` otherwise, based on their direct support from DBMS diagnostics.
- **Candidate Selection:** Hard filtering to `T_t,p` occurs only if `h(τ_t^(k-1)) = 1` and `|T_t,p| ≥ 3`; otherwise, it falls back to `L_t,p`.
- **Ranking:** The ranking function `r_rel(x, u)` adds a soft type-match bonus (`+0.10 * (1 - h(τ)) * 1[τ_x = τ]`) to the base hybrid score `r_base(x, u)`. This bonus is applied only to lower-reliability types and is disabled for high-reliability types and small-pool fallback cases.

### 4. Main Findings and Results

The experiments were conducted on the development sets of Spider (1,034 queries) and BIRD (1,534 queries) using the `Qwen2.5-7B-Instruct` backbone with a fixed initial SQL prediction and a repair budget of K=7. Results are averaged over three query stream orders.

#### 4.1. Impact of Cross-Query Memory on Repair

- **Spider Dataset:** All memory-based methods demonstrated an improvement over the stateless `ITERATIVE` repair. `MERIT` and `DYNAMIC RAG` achieved the highest execution accuracy at `69.79%`, compared to `REFLEXION-STYLE` at `68.38%` and `ITERATIVE` at `66.34%`. `MERIT`'s gain of `+3.45` percentage points over `ITERATIVE` had a paired 95% confidence interval of `[+1.97, +4.96]`, indicating clear evidence of benefit.
- **BIRD Dataset:** `REFLEXION-STYLE` performed best at `51.24%`, followed by `MERIT` at `48.44%`, `DYNAMIC RAG` at `48.15%`, and `ITERATIVE` at `47.35%`. `MERIT`'s gain of `+1.09` points over `ITERATIVE` had a confidence interval of `[0.00, +2.17]`, suggesting weaker evidence of benefit compared to Spider.

#### 4.2. Comparison with Alternative Memory Organizations

- `MERIT` and `DYNAMIC RAG` were not reliably separated in performance; they tied on Spider and `MERIT` showed a marginal `+0.28` point lead on BIRD, with confidence intervals crossing zero. This suggests that the aggregate benefit from `MERIT`'s polarity separation and hard type conditioning over untyped dynamic retrieval was not consistently established.
- On Spider, `MERIT` exceeded `REFLEXION-STYLE` by `+1.42` points, but the confidence interval `[-0.19, +3.03]` included zero, indicating no reliable difference. On BIRD, `REFLEXION-STYLE` outperformed `MERIT` by `+2.80` points, with `MERIT`-minus-`Reflexion` interval `[-4.15, -1.46]`, positioning `REFLEXION-STYLE` as the strongest method for BIRD.

#### 4.3. Robustness of Error-Type Conditioning

- The comparison between hard and type-reliability-aware filtering did not yield reliably distinguishable results. Hard filtering showed a `+0.39` point change on Spider and `-0.20` points on BIRD, with zero-crossing intervals. This suggests that error type serves as a coarse retrieval prior rather than a definitive partition, and neither policy was uniformly superior.

#### 4.4. Impact on Repair Behavior and Computational Cost

- **Repair Success:** Memory-based methods primarily increased the number of initially failed queries that were successfully repaired. On Spider, `MERIT` and `DYNAMIC RAG` repaired `112.7` failures (vs. `77.0` for `ITERATIVE`). On BIRD, `REFLEXION-STYLE` repaired `197.0` failures (highest), while `MERIT` repaired `154.0`.
- **Trajectory Characteristics:** `MERIT` exhibited slightly shorter trajectories and lower oscillation rates on Spider compared to baselines, although differences from `DYNAMIC RAG` were minimal. On BIRD, `REFLEXION-STYLE` produced the shortest and least oscillatory trajectories.
- **Computational Cost:** Higher repair success correlated with increased token usage. On Spider, `MERIT` used `5.274` million tokens (compared to `2.529` million for `ITERATIVE`), while `REFLEXION-STYLE` used `6.597` million tokens. On BIRD, `MERIT` used `17.569` million tokens (vs. `9.325` million for `ITERATIVE`), and `REFLEXION-STYLE` was the most expensive at `22.407` million tokens. While `MERIT` made slightly fewer model calls than `ITERATIVE`, the inclusion of retrieved memories in prompts led to substantially higher total token consumption.

#### 4.5. Ablation Analysis

- **Memory Polarity:** Removing negative memory resulted in modest accuracy changes (`-0.13` on Spider, `-0.09` on BIRD), suggesting that verified corrections provided the majority of the useful signal.
- **Error-Type Conditioning:** Type-conditioned retrieval was more beneficial on Spider (`-0.58` accuracy drop when removed), highlighting the value of narrowing the retrieval pool. On BIRD, the impact was less pronounced. Dense relevance remained important within the typed class on Spider (`-1.12` without dense reranking).
- **Lexical and Dense Ranking:** The relative value of lexical and dense channels was dataset-dependent. On Spider, removing dense reranking caused a `1.12` point drop, while removing BM25 sometimes raised accuracy. On BIRD, removing BM25 lowered accuracy by `0.40` points, indicating the importance of exact lexical overlap for larger, specialized schemas.
- **Schema Locality:** Restricting retrieval to only cross-database memories consistently lowered accuracy (`-0.93` on Spider, `-2.74` on BIRD). This indicates that schema-local experience, preserving recurring patterns and terminology within a database, is highly valuable and cannot be fully replaced by cross-database analogies, particularly in domain-specific contexts like BIRD.
- **Error Classifier Performance:** The deterministic classifier's population-weighted accuracy was approximately `48%` on both Spider and BIRD, with Macro-F1 scores of `0.317` and `0.355`, respectively. This confirms that the labels provide useful but imperfect routing information.

### 5. Significance and Potential Impact

This research introduces MERIT, a training-free framework that demonstrates the viability of learning from execution-guided Text-to-SQL repair through causal cross-query memory. The findings confirm that memory-based approaches can enhance agent performance without requiring parameter updates to the base LLM.

The work's significance lies in several areas:
- **Enhanced Agent Dependability:** By showing that agents can retain and reuse successful corrections, MERIT contributes to the development of more robust and adaptable LLM agents that improve over continuous interaction. This addresses a critical limitation of many current stateless repair mechanisms.
- **Reduced Redundancy:** The ability to store and retrieve past solutions for recurring failure types can reduce the need for agents to repeatedly rediscover similar corrections, leading to more efficient repair processes.
- **Insights into Memory Design:** The detailed ablation studies provide empirical evidence regarding the design choices for agent memory systems. Specifically, they highlight that while positive memories (verified corrections) contribute most of the useful signal, the optimal configuration for retrieval (e.g., the balance between lexical and dense signals, or the application of error-type conditioning) can be dataset-dependent. The consistent value of schema-local experience is a notable finding, indicating that context-specific memory is particularly impactful.
- **Foundation for Future Research:** This research clarifies the conditions under which causal cross-query memory improves repair and when broader memory representations might be preferable. It suggests avenues for further exploration into more sophisticated memory organizations, adaptive retrieval policies, and potentially more nuanced failure classification systems to further optimize cross-query learning.

While MERIT is not presented as a claim of state-of-the-art Text-to-SQL performance, its focus on refining the agent's ability to learn from repair experiences positions it as a relevant contribution to the field of LLM agent research and memory-augmented learning. The framework offers a practical method for improving agent performance on recurring tasks, with potential applicability beyond Text-to-SQL to other domains requiring feedback-driven iterative refinement.
