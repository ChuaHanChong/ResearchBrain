# WorldCoder-Bench: Benchmarking Physically Grounded 3D World Synthesis

> [!summary] Summary
> WorldCoder-Bench is a benchmark of 2,026 expert-curated tasks for generating executable Three.js 3D worlds from natural language. Its StateProbe protocol runs each program in a headless browser and checks hidden, mutation-hardened behavioral contracts over runtime state. Across nine frontier models, the best reaches only 27.8% verification coverage, and failures come mainly from state-schema drift and broken interaction chains.

## Problem

- Existing web-generation benchmarks score only pixels or DOM nodes, but Three.js worlds render into an opaque canvas, so geometry, physics and interaction logic stay invisible to evaluators.
- Prior benchmarks under-test three things executable 3D worlds need: physical correctness, asset integration, and synchronization between user-facing controls and hidden runtime state.
- Screenshot, VLM and agent-exploration judges are costly, noisy, or non-deterministic, and they can pass visually plausible but behaviorally broken programs, which misdirects model development.

## Method

- **StateProbe** execution protocol: runs generated HTML in sandboxed ==headless Chromium==, reads state through a ==window-level runtime interface==, applies scripted actions, and checks ==hidden assertions== on before/after ==snapshot deltas==.
- ==Mutation-hardened behavioral contracts==: expert-authored hidden specifications are admitted only if they reject ==injected defects== such as stale state updates, corrupted physical constants, swapped event targets and broken asset loading.
- Four-stage curation plus metrics: expert seeds, LLM expansion and filtering, ==runtime verification==, and ==randomized robustness variants==; scored by ==coverage metrics== plus ==Return on Automation== and ==Time Efficiency Multiplier== utility measures.

## Results

- On WorldCoder-Core, GPT-5.4 leads with **27.8%** verification coverage and no model exceeds **30%**; affordance coverage is **40.6-67.4%** but transition coverage only **15.8-26.3%**.
- On the perturbed WorldCoder-Robust split, GPT-5.4 falls to **19.9%**, and Qwen3.6-Plus drops from **25.3%** to **13.5%**. The proprietary-open gap widens from **2.5** to **6** points.
- External judges fail to match contract-based scores over **1,434** pairs: DOM Kendall tau **-0.021**, Screenshot+VLM **-0.068**, 8-step agent **+0.111** at **~400x** cost while passing **45.6%** of low-coverage outputs.

## Takeaways

> [!tip] Key Insights
> - Visual plausibility is a poor proxy for behavioral correctness in generated interactive worlds; evaluation must probe internal runtime state rather than pixels or DOM.
> - Hardening evaluation contracts with injected-defect mutation testing keeps a pass meaningful and prevents permissive thresholds from inflating scores, a transferable practice for any executable benchmark.
> - Models fail at exact, action-synchronous state contracts (schema drift and broken interaction chains made up 83.6% of failures), not at scene construction, so progress needs stronger state-consistency reasoning.

## Detailed Report

### 1. Overview

A model is asked to build an interactive browser-based 3D world, such as a physics simulation or game, from a natural-language brief. The promised shortcut is to turn that brief into an interactive world much faster than hand-authoring one. That shortcut only helps if the world works, not just if it renders. A browser-generated 3D world can look convincing and still be wrong in the ways that matter: its objects may not obey the requested physics, imported assets may fail, or controls may stop updating the world's actual state.

The authors therefore evaluate the running program from inside the browser. They drive it with actions, inspect its runtime state, and check that state against private, task-specific behavioral requirements. In the hard Core evaluation, tested transitions are substantially less successful than object/control presence or reaching intermediate states.

The authors' conceptual illustration of three failure types: a ball's bounce labelled "Energy Imbalance" and "Penetration," a .glb asset problem labelled "Assembly Error," and a HUD reading HP 100/100 beside hidden internal HP 50. The right-hand panel shows the proposed checks of physics, asset integration, and state synchronization. This is a motivation diagram, not a sample of scored model outputs.

### 2. Making hidden behavior testable

WorldCoder-Bench contains 2,026 expert-curated tasks across Simulation, Rendering, and Application, organized into 15 fine-grained domains. Each task gives the model a natural-language brief, a required interface schema, and sometimes `.glb` assets. The model returns one HTML page.

The model can see the required runtime-state interface. It cannot see the contract, the scripted action sequence, the thresholds, or the assertions.

The evaluator, StateProbe, runs each page in a sandboxed headless Chromium browser and checks that the page loads and runs. It then applies deterministic clicks, key presses, drags, or physics-step commands. It snapshots state before and after each action and tests the resulting changes against the hidden contract.

Contracts are admitted only after mutation tests show they reject injected defects such as stale state updates, corrupted physical constants, broken asset loading, or HUD mismatches. This hardens the specified tests. It is not evidence that every conceivable defect is caught.

Four approaches: screenshot plus VLM judging, DOM-only inspection, pure-agent exploration, and StateProbe's probe-first evaluation. The numbers printed in the diagram are illustrative, not experimental results.

### 3. What the score reveals

Verification Coverage (V-Cov) is the share of hidden assertions passed. It is not the percentage of tasks that work completely. Three diagnostic scores break it down:

- A-Cov covers required objects and controls.
- S-Cov covers required intermediate states.
- T-Cov covers action-triggered transitions.

On WorldCoder-Core, the paper's 205-task hidden hard subset, GPT-5.4 has the highest reported V-Cov, at 27.8%. Its diagnostic coverages are 66.2% (A-Cov), 46.1% (S-Cov), and 26.3% (T-Cov). The measured shortfall is especially pronounced in behavior after actions, not simply in whether a scene starts.

The decisive comparison tests whether other evaluators reproduce this ranking. It covers seven models with complete reports across the 205 Core tasks, or 1,434 model-task pairs. The strongest external baseline is an agent allowed eight inspection steps. It has only a weak positive Kendall correlation with V-Cov (τb = +0.111), a measure of agreement in ordering. It costs about 400 times as much as DOM-only inspection. It also calls 45.6% of outputs with V-Cov below 30% "passing."

This supports the authors' case that visual/DOM inspection and agent exploration do not reproduce the contract-based model ranking. It does not show that StateProbe detects every possible defect.

### 4. Closing

For these generated worlds, visible plausibility is not a substitute for correct runtime behavior. StateProbe changes the question from "does the scene look right?" to "does the world respond as specified?" These results are for the paper's evaluation and contracts. They do not establish how every model, task, or real-world deployment would perform. The benchmark is available on the [WorldCoder-Bench project and release page](https://anonymous.4open.science/r/WorldCoder-Bench/).
