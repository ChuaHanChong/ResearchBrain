# FaSTA$^*$: Fast-Slow Toolpath Agent with Subroutine Mining for Efficient Multi-turn Image Editing

> [!summary] Summary
> FaSTA* is a neurosymbolic agent for multi-turn image editing that pairs fast LLM subtask planning with slow A* toolpath search. An LLM mines reusable symbolic subroutines from past successful toolpaths. Subroutines are tried first, and A* runs only when a VLM quality check fails. It cuts execution cost by about 49% versus CoSTA* with about 3% lower accuracy.

## Problem

- CoSTA*, the prior state of the art, combines LLM subtask planning with A* tool search, but the A* search stays a computational bottleneck for every new task.
- Prior test-time-only agents cannot reuse exploration from earlier tasks, so knowledge from explored toolpaths never accelerates future planning, unlike humans who learn reusable actions.
- LLM planners alone misestimate tool cost and quality and hallucinate choices, such as picking an expensive diffusion model when a simple filter suffices, so they cannot replace search.

## Method

- ==Inductive subroutine mining==: an LLM reads recent ==execution traces== and proposes or refines ==symbolic rules==, such as YOLO, SAM and SD Inpaint under area and mask-ratio conditions, stored in a ==subroutine rule table==.
- ==Subroutine verification==: each proposed subroutine or refinement must pass validation and retry checks before it is added to the rule table, so only reliable subroutines are inducted.
- ==Adaptive fast-slow planning==: the LLM plans subtasks and picks a subroutine for each one. A ==VLM quality check== gates the result, and ==A* search== on the subtask's ==tool subgraph== runs only on failure or when no subroutine applies.

## Results

- On the CoSTA* benchmark, FaSTA* cuts average execution cost from **78.27s** to **55.12s**, a **49.3%** reduction, while average accuracy drops only from **0.89** to **0.87**, about **3.2%** lower.
- On the independent Complex-Edit benchmark, FaSTA* gives about **30%** lower cost with comparable quality. Fast-only planning scores **0.84** quality at **27.5s**, slow-only scores **0.93** at **46.8s**, and FaSTA* scores **0.91** at **29.5s**.
- Subroutine verification cuts low-level A* fallbacks from **28%** to **9%**. A 3B Qwen2.5-VL selector picks the wrong subroutine about **40%** of the time, raising total cost by about **20%**.

## Takeaways

> [!tip] Key Insights
> - Distilling successful search traces into symbolic, condition-guarded rules turns expensive search into cheap reuse. The agent gets faster as experience accumulates, without any weight updates.
> - Keep the slow, accurate planner as a verified fallback. Pure fast planning is brittle, and quality checks decide when to escalate, which preserves near-optimal quality at roughly half the cost.
> - Gate learned rules with validation before adding them to memory, and use a capable selector model. Unverified rules and weak selectors trigger fallbacks that erase the efficiency gains.

## Detailed Report

### 1. Overview

1: A single request can bundle several edits: detect a bench, recolor it pink, remove a cat, and recolor a wall yellow. A request like this can require several different tools, and exploring possible tool sequences can itself be slow and expensive. FaSTA* addresses this by remembering reusable, condition-specific sequences from past work and trying those first. When a shortcut is absent or fails, it falls back to local A* search. The authors' central result is lower elapsed execution time than CoSTA* on their benchmark, with a small reduction in human-rated quality.

### 2. From experience to shortcuts

7: The closest prior work, [[2503.10613|CoSTA*]], already uses an LLM to break an editing request into subtasks, narrows the relevant tool graph, and then searches that graph with A*. The authors identify CoSTA*'s repeated, test-time-only search as the bottleneck FaSTA* aims to reduce.

9: FaSTA*'s addition is the *subroutine*: an ordered sequence of tool calls associated with a subtask and conditions under which it is intended to apply. The system logs traces, including paths, context, outcomes, costs, and quality. An LLM then proposes or refines compact symbolic rules from recent traces. Refinement happens every 20 tasks. Before a proposed change is accepted, it is verified on specialized test datasets against a baseline. The contextual rules use semantic categories, not just raw numerical thresholds.

11:

Schematic in two tiers. Top: recent execution traces go to an LLM, which proposes or refines rules; a validation pass updates the rule table, and a failure loops to retry. Bottom: an instruction is decomposed into a subtask chain, candidate rules are selected, and a VLM quality check can send a failed or unavailable subroutine to localized A* search.

### 3. A shortcut with a backstop

15: At run time, an LLM creates a subtask chain and selects a condition-matching subroutine. Its tools run in order, with VLM checks after tool executions. If no subroutine applies or a check fails, FaSTA* constructs a tool graph for that subtask and invokes A* search there. The paper reports that 91% of subtasks succeeded via the high-level subroutine path, and 9% required low-level fallback.

The ablation tests whether the fallback earns its place. In a fast-plan-only variant, a missing or failed subroutine caused failure instead of invoking the fallback. This variant scored 0.84 at 27.5 seconds, while the full system scored 0.91 at 29.5 seconds. This supports keeping the fallback in that setting. It does not isolate the fallback as the only cause of every quality difference.

19:

A single failure illustration. The input shows a cat beside a dog. In the failed subroutine result, the cat remains. After recovery via low-level A* search, FaSTA* replaces the cat with a rabbit and keeps the dog.

### 4. What the time comparison means

23: The main CoSTA* dataset has 121 image-prompt pairs and 550 total manipulations.

The two measures work as follows:

- **Quality:** Human evaluators score each subtask as 0, partial, or 1. Scores are averaged over a task's subtasks, then over tasks.
- **Cost:** Execution cost is elapsed seconds per inference, including necessary retries.

30: At α=1, FaSTA* averages 29.5 seconds per image and 0.91 quality, while CoSTA* averages 58.2 seconds and 0.94. The paper summarizes this as 49.3% cost savings for 3.2% quality degradation. This is a trade of time for a small quality drop. It is not evidence about token counts or a measured count of search attempts.

32: 32: The savings are learned rather than immediate. In the cold-start setting, before any tasks have been explored, FaSTA* matches its CoSTA* comparison, and savings emerge as useful rules are learned. The authors also acknowledge inductive-reasoning overhead and estimate it amortized over deployment.

### 5. Shortcuts, not guarantees

Reuse lets the agent avoid searching anew for every familiar subtask, and the fallback leaves it a route for unfamiliar or failed cases. On this benchmark, the result is roughly half the elapsed time at a 0.03 lower human score. Those savings appear only after cold start, as useful rules are learned.
