# EmbodiedSWE: Coding Agents for Long Horizon Dexterous Robotics

> [!summary] Summary
> EmbodiedSWE uses frontier coding agents as both solvers and demonstration teachers for long-horizon dexterous robotics. Agents write solve(env) programs against a simulator across 28 contact-rich, deformable, liquid and cutting tasks on five embodiments, iterating from execution feedback. A hierarchical data engine then expands one verified solution into thousands of diverse trajectories for VLA finetuning; the best agent solves 82%, and a sim-only policy transfers to a real lamp disassembly.

## Problem

- VLA policies need demonstrations at scale, but teleoperation needs many operators, human video mismatches robot embodiments, and precise insertion or threading data stays prohibitively hard to collect.
- Prior coding-agent robotics work stays on navigation and pick-and-place, relying on human-designed object-pose queries or macro primitives that constrain the reachable task space.
- Simulation benchmarks rarely combine long horizons with demanding physical interaction, while real-hardware iteration is expensive, so progress of coding agents on dexterous tasks is hard to measure.

## Method

- **EmbodiedSWE-Bench**: 28 Isaac Lab tasks over five embodiments, Dockerized runs, agent submits a ==solve(env)== program, graded offline by task graders plus VLM rubrics with state-writing disabled.
- Long-horizon agent tools: a ==checkpoint tree== storing simulator states with programs and logs, ==CMA-ES== evolutionary parameter search, a scene viewer, a parallel sweep tool, and structured assessment logs.
- **EmbodiedSWE-Gen** data engine: the agent diversifies scene, strategy, and phase entry states and writes ==DART-style phase-specific action noise==; scripts randomize mass, friction, lighting and camera; grader plus replay filtering.

## Results

- Frontier agents span **11%** (GPT-5.6 Terra) to **82%** (GPT-6 Astra) of tasks solved in a 4-hour budget; PPO with expert-tuned rewards reaches **0.06** mean score versus **1.00**.
- SmolVLA mean success rises from **18%** at 10 demonstrations per task to **69%** at 400; on held-out variations agent-aided data scores **0.233** overall versus **0.066** for script-only.
- A policy finetuned only on **500** generated simulation trajectories reaches **100/80/30/20%** real-robot stage success across the four lamp-disassembly stages, while the pretrained baseline scores **0%** at every stage.

## Takeaways

> [!tip] Key Insights
> - Writing and debugging programs beats tabula-rasa RL in equal wall-clock on tasks that are easy to specify but hard to explore.
> - Verified solutions are reusable assets: hints from a similar task or another arm raise both solving speed and final score, carrying decomposition and control knowledge.
> - Diversity of supervision, not volume alone, drives generalization; script-only randomization saturates near the original task distribution and barely transfers to novel objects.
> - Grade offline with state-writing disabled: agents hack scorers by teleporting objects or applying external forces, and often ignore renders for printed state.

## Detailed Report

### 1. Overview

Human demonstrations are costly to collect, and precise, multi-step actions such as threading a screw or inserting a part can be especially hard to record reliably. This paper instead lets a coding agent iteratively write, run, inspect, and revise a robot-control program in simulation. A verified program is then turned into many training trajectories for a separate learned robot policy. The agent does not control the physical robot; it supplies supervision for that policy. In one real-world test, a policy trained only on simulated, agent-generated demonstrations completed a lamp-disassembly rollout.

One successful real-robot lamp-disassembly rollout from the simulation-data-finetuned policy. The robot grasps and removes the lamp shade/cap, then grasps and unscrews the bulb until it is removed. Each step has an external-camera view above and a wrist-camera view below.

### 2. From program to teacher

The agents work on EMBODIEDSWE-BENCH, which contains 28 long-horizon simulation tasks, including threading, assembly, cutting, and carrying. Agents have full simulator-state access, along with generic inspection tools and controllers. They produce a Python `solve(env)` program. Grading is offline and task-specific. The benchmark therefore tests program discovery in simulation. It does not test agents acting from ordinary robot-camera observations in the physical world.

The teacher step is EMBODIEDSWE-GEN. It starts with a verified solution and systematically expands it into trajectories. Each trajectory is retained only if it passes the task grader and an open-loop replay check. The pipeline uses five types of variation:

- **Scene** changes task objects and layout.
- **Strategy** changes step order, grasps, plans, or recovery.
- **Phase** starts from valid intermediate task states.
- **Dynamics** adds agent-designed, phase-specific action noise and samples physical parameters.
- **Visual** changes lighting, background, and camera.

Scene, strategy, phase, and noise schedules are agent-aided. Physical and visual randomization are scripted from ranges the agent specifies.

Five bands, labeled Scene, Strategy, Phase, Dynamics, and Visual, connect a base example to variants. The dynamics band's chart shows stronger transport disturbance than insertion. This is an illustration of the proposed pipeline, not a measured result.

### 3. More varied data, better held-out performance

The authors finetune SmolVLA on generated trajectories for six tasks. In simulation, in the same scene and initial-state distribution as the generated data, the mean across the six tasks rises with more data. With 10 demonstrations per task, success is 18% and the rubric score is 0.32. With 400 demonstrations, success is 69% and the rubric score is 0.76.

The decisive test compares agent-aided data with a script-only diversification baseline. The baseline uses standard domain randomization, noise, and small initial-state perturbations. Both policies train on 1,000 demonstrations per task. Both are evaluated on the same held-out set of 256 configurations, which includes semantically novel task instances and unseen geometries. Results are mean rubric scores aggregated over three training seeds. Agent-aided data scores higher on all six held-out tasks. Its overall mean rubric score is 0.233 ± 0.016, compared with 0.066 ± 0.008 for script-only data. This result supports the agent-aided pipeline as a bundle. It does not isolate which diversification dimension caused the gains.

Rubric scores with uncertainty, script-only versus agent-aided (ours), for six tasks and overall. Slicing goes from 0 to 0.220 ± 0.017, and the overall score from 0.066 ± 0.008 to 0.233 ± 0.016.

### 4. A bridge, not a finished generalist

In the real-robot test, an Opus 5-written simulated lamp solution is diversified into 500 successful simulated trajectories. A pretrained π⁰·⁵-DROID policy is then finetuned only on these simulated demonstrations, with no real-robot demonstrations.

The policy was evaluated over 10 trials on a Franka Panda with a Robotiq gripper. Each milestone rate is the fraction of trials that completed all stages up to that milestone. The sim-trained policy reached:

- 100% for grasping the shade
- 80% for placing and releasing the shade
- 30% for grasping the bulb
- 20% for unscrewing and extracting the bulb

The pretrained baseline scored 0% at each milestone. This is nontrivial zero-shot sim-to-real transfer in one reconstructed lamp setup, not broad real-world generalization.

### 5. The teacher's handoff

The coding agent does not replace a deployed robot policy. Instead, a verified program becomes diverse training experience for one. The authors frame this as a potential path. They also report substantial iteration costs and task-specific solutions.
