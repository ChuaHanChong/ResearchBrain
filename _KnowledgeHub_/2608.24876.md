# Recursive Experiential-Working Memory Evolution for Long-Horizon Agent Harnesses

> [!summary] Summary
> Recuris is an agent-harness memory architecture where Working Memory tracks verified goal states and grounds skill retrieval from Experiential Memory at execution events, while a fixed Meta-Agent reads structured traces to patch the implicated memory component behind a validation gate. It improves task success in 35 of 37 model-benchmark pairs, taking Claude Opus 5 to 87.9% on retail tool-use.

## Problem

- Experiential-memory methods retrieve skills from the initial instruction or full history, which grows noisy with completed steps, stale goals, and execution noise.
- Agents left to invoke skills themselves misjudge relevance; injecting the whole library adds context and cost yet scores below carrying no skills at all.
- Self-improving agents learn from final success or failure only, a signal too coarse to say which mechanism failed, so memory rewrites are untargeted.

## Method

- ==Experiential-Working Memory coupling==: a compact goal state with pending/done/blocked entries drives ==state-grounded skill invocation== at execution events such as a drafted state-changing tool call.
- ==Evidence-grounded state update==: a ==checker set== evaluates proposed transitions against actual tool receipts, and a fixed ==commit kernel== admits only observation-supported changes, blocking hallucinated completion.
- ==Bounded recursive evolution==: a fixed ==Meta-Agent== localizes failures in ==structured traces== to one of skills, state spec, invocation policy, or checkers, patches those, and a ==held-out validation gate== admits.

## Results

- Adds **17.8 points** to GPT-5.6 Sol and **15.6** to Claude Opus 5 on retail tool-use, **16.6/13.5** on two open-weight models on SkillFlow; gains reach **+32.2** on longest tasks.
- Ablations: verified working state alone gives **+23.9 points** versus **+2.0** for experiential memory alone; state-grounded invocation beats model-controlled injection by **18.0 points** at lower token cost.
- Component-fault localization reaches **64.8%** macro accuracy from structured traces versus **37.0%** from raw trajectories and **13.0%** from outcomes; gated patches regressed anchor tasks less than rerun noise.

## Takeaways

> [!tip] Key Insights
> - Skill value is invocation-conditional: what a memory contains matters less than whether something knows the moment the skill is needed.
> - Verification must precede irreversible action; the post-hoc audit rejected 172 false completion claims yet changed no outcome, since executed writes cannot be undone.
> - Structured traces are what make scoped self-repair possible, and the critical mechanism varies by domain, so component effort cannot be fixed at design time.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

The work addresses a central challenge in the field of large language model (LLM) agents: achieving effective recursive self-improvement (RSI) for tasks that span long interaction horizons. LLM agents have demonstrated capabilities in reasoning, tool use, and autonomous execution, often mediated by an external agent harness that manages memory, skill invocation, and task-state tracking.

Existing approaches to enhance agent capabilities include the use of experiential memory (EM) to store reusable skills and working memory (WM) to track the current task state. However, the paper identifies limitations in these existing paradigms. Experiential memory methods often retrieve skills based on the initial instruction or the full interaction history, which can become unreliable as tasks evolve and histories grow, leading to the retrieval of irrelevant or outdated information. Working memory, while tracking task state, often relies on state updates that are either fixed by rules or self-reported by the model, lacking external verification and thus being susceptible to omissions or hallucinations. This lack of verified, compact, and continuously aligned task state impedes reliable skill invocation and makes it difficult to convert execution failures into precise, actionable improvements.

Recursive self-improvement efforts in LLM agents typically involve modifying various layers, such as the agent's runtime logic, workflow graphs, tool sets, or even the model's weights. Memory-centric RSI methods often involve adding, updating, or deleting experiences based on task outcomes. However, a common challenge across these methods is the difficulty in localizing the root cause of failure within the agent's complex architecture. Without a clear attribution, updates tend to be coarse or weakly targeted, potentially introducing regressions or failing to address the actual problem.

This work positions itself within this landscape by proposing a novel architecture, Recuris, that addresses these limitations through a verified coupling of experiential and working memory. It aims to provide a reliable mechanism for state-grounded skill invocation and, crucially, to generate structured diagnostic evidence from execution traces. This evidence then enables component-level failure localization and targeted, validation-gated evolution of the external memory-control layer, rather than modifying the underlying LLM or the entire agent program. This approach seeks to provide a more stable, interpretable, and scalable foundation for RSI in long-horizon tasks.

### 2. Key Objectives and Motivation

The primary objective of this research is to develop a method for recursive self-improvement in LLM agents that is effective for long-horizon tasks, where evolving goals and extensive interaction histories typically pose significant challenges.

The key motivations and more specific objectives are:

1. **Enhance Skill Invocation Reliability in Long-Horizon Tasks**: Current methods struggle with long-horizon tasks because growing interaction histories can obscure the true task state, leading to misaligned or irrelevant skill invocation. The paper aims to develop a mechanism where skill selection is continuously grounded in the agent's current progress and unresolved goals, rather than relying on the initial instruction or an unmanaged full history.
2. **Establish a Verified and Compact Task State Representation**: A central limitation identified is the lack of a compact and reliable task state. The research aims to implement a Working Memory (WM) that accurately tracks task progress, and critically, ensures that state updates are verified by environmental feedback or tool execution results, preventing the agent from operating on incorrect or hallucinated states.
3. **Transform Execution into Structured Diagnostic Evidence**: Traditional RSI often learns from final success/failure signals, which are insufficient to pinpoint the exact cause of an error. A key motivation is to design an architecture where agent harness execution itself generates structured evidence (linking task states, invoked skills, actions, and outcomes). This evidence is intended to allow for precise diagnosis of failures.
4. **Enable Targeted and Localized Memory Evolution**: With structured diagnostic evidence, the objective is to localize failures to specific components of the memory-control layer (e.g., experiential memory, working memory specification, invocation policy, or checkers). This allows for component-specific patching and updates, moving beyond coarse, whole-memory rewrites, and promoting more efficient and less disruptive self-improvement.
5. **Develop a Bounded and Stable Recursive Evolution Loop**: The authors aim to establish a recursive self-improvement process where the memory-control layer evolves, but the underlying LLM and the outer improvement procedure remain fixed. This bounded recursion, coupled with a validation-gated admission process, is intended to ensure that updates are beneficial, prevent regressions, and maintain the stability of the agent's abilities over time.
6. **Demonstrate Scalability and Transferability**: A core motivation is to show that memory evolved on one model and task set can transfer effectively to different tasks and models, including frontier LLMs, without requiring further model-specific tuning. This would establish the memory-control layer as a portable and trainable surface for frozen LLMs.
7. **Address Common Long-Horizon Failure Modes**: Specifically, the work seeks to reduce common issues such as hallucinated completions, omitted writes, wrong initial tool calls, and error cascades, by providing better state awareness and verified execution.

In essence, the research is motivated by the need for more robust, interpretable, and continuously improving LLM agents, particularly in complex, multi-step environments, by focusing on a dynamically evolving and externally verified memory-control layer.

### 3. Methodology and Approach

Recuris operates through an architecture designed around a recursive Experiential–Working Memory evolution for LLM agent harnesses. The methodology involves two interdependent loops: a within-task execution loop and a cross-task skill memory evolution loop. The core principle is to keep the underlying LLM fixed while recursively evolving an external memory-control layer.

#### 3.1. Problem Setup and Skill Memory Architecture

The agent harness mediates interactions for a frozen LLM ($\pi_\theta$) and a tool set ($\mathcal{T}$). During task execution, the agent maintains an interaction history ($h_t$) and a working state ($w_t$). An invocation policy selects experiential skills ($E_t$), the LLM produces an action ($a_t$), and the environment returns an observation ($o_t$). The goal is to update the external memory-control mechanisms that condition this process, rather than $\pi_\theta$.

The evolving Skill Memory at round $k$ is denoted $M_k = (E_k, W_k, \rho_k, C_k)$:
- **Experiential Memory ($E_k$)**: Stores reusable skills in an agent-skill format.
- **Working Memory Specification ($W_k$)**: Defines the schema and update proposal for the task-specific working state ($w_t$).
- **Invocation Policy ($\rho_k$)**: Determines when skills are retrieved and which entries from $E_k$ enter the LLM's context.
- **Checker Set ($C_k$)**: Contains predicates that verify if observations support proposed state changes.

Only these four components of $M_k$ are subject to evolution; the base LLM, Meta-Agent, localization/patching procedures, validation gate, and other harness mechanisms remain fixed. This defines a constrained patch space.

#### 3.2. Within-Task Verified EM–WM Coupling

This loop governs how the agent executes a single task. It emphasizes state-grounded skill invocation and evidence-grounded state updates.

- **Structured Working State**: $w_t$ is initialized from the task under $W_k$. Each goal within $w_t$ tracks its content, status (pending, done, blocked), and supporting evidence. This compact state guides the harness on current needs.
- **State-Grounded Skill Invocation**: Instead of retrieving skills once or from the full history, $\rho_k$ selects $E_t \subseteq E_k$ at specific execution events ($e_t$), such as drafting a state-changing tool call or a turn boundary. The selection is conditioned on the task ($x$), the current verified working state ($w_t$), and the event ($e_t$). This ensures skills are invoked when relevant to the *current* task stage.
 - **Call-time invocation**: Triggered when the agent drafts a state-changing tool call, using the tool name as a retrieval key. The skill is injected before the tool call is executed.
 - **Boundary invocation**: Triggered at a turn boundary based on a predicate over the working state, supplying skills without tool conditioning.
- **Evidence-Grounded State Update**: After receiving an observation $o_t$, $W_k$ proposes a next state ($ew_{t+1}$). The checker set $C_k$ evaluates this proposal against $o_t$, and a fixed kernel $K$ commits *only the changes supported by evidence*. A goal moves to "done" only if its explicit completion predicate in $C_k$ is satisfied by the tool/environment result, not by the model's claim. This prevents false progress.
- **Structured Execution Trace ($\Gamma_k$)**: The coupling of verified states, invoked skills, actions, and observations results in a detailed trace $\Gamma_k = \{x_k, \{w_t, E_t, a_t, o_t, ew_{t+1}, c_t, w_{t+1}\}_{t=1}^{L_k}, y_k\}$, which explicitly links how the memory-control layer influenced behavior. This trace is critical for the cross-task evolution loop.

#### 3.3. Bounded Cross-Task Skill Memory Evolution

This loop uses the structured execution traces from failed runs to recursively improve $M_k$.

- **Trace-Based Failure Localization**: For failed runs, a fixed Meta-Agent ($A_{fixed}$) analyzes $\Gamma_k$ to produce a diagnosis $D_k = \{(f_j, z_j)\}$, where $f_j$ is a diagnosed failure and $z_j \in \{E, W, \rho, C\}$ is the memory component identified as the most effective repair target. This is a repair decision, not necessarily a causal identification, and allows for attributing failures to missing skills (E), flawed state schema (W), incorrect invocation ( $\rho$), or faulty verification (C).
- **Component-Specific Patching**: A fixed patching stage ($P_{fixed}$) proposes one edit ($\Delta m_z$) for each implicated component $z \in Z_k$ (the set of implicated components). These edits are then applied together to form a candidate memory $M^+_k = M_k \oplus_{Z_k} \{\Delta m_z\}_{z \in Z_k}$. This operator ensures that only implicated components are revised, enforcing scoped repairs.
- **Validation-Gated Patch Admission**: A fixed gate ($G_{fixed}$) evaluates $M^+_k$ against $M_k$ on the failed source task ($x_k$) and a held-out development set ($D_{dev}$) containing anchor tasks. The candidate is admitted to become $M_{k+1}$ only if it repairs the target failure and meets a preset regression criterion on $D_{dev}$. If rejected, $M_k$ remains unchanged. This gate provides an external acceptance boundary, ensuring stability.
- **Bounded Recursive Evolution**: The complete loop is $M_k \to \Gamma_k \xrightarrow{A_{fixed}} D_k \xrightarrow{P_{fixed}, \oplus_{Z_k}} M^+_k \xrightarrow{G_{fixed}} M_{k+1} \to \Gamma_{k+1}$. This process ensures that memory changes behavior, behavior produces diagnostic evidence, and evidence evolves memory, all within a fixed outer harness and without modifying the base LLM.

#### 3.4. Test-Time Adaptation Mode

In a separate mode, Recuris supports adaptation on isolated tasks. Given a single task and an attempt budget, if an agent fails, the Meta-Agent receives the task instruction and failed trajectory (without verifier details) to propose a localized update to experiential memory. The agent then retries the task with the updated memory. This mode is evaluated against a control that retries with frozen memory.

### 4. Main Findings and Results

The research paper presents empirical results across various benchmarks and models, highlighting the efficacy of Recuris.

#### 4.1. Overall Performance

- Recuris improved task success in 35 out of 37 completed model–benchmark pairs.
- On $\tau^2$-Retail, it improved GPT-5.6 Sol by +17.8 points (from 58.3% to 76.1%) and Claude Opus 5 by +15.6 points (from 72.4% to 87.9%). On SkillFlow, it improved Qwen3.6-27B by +16.6 points (from 42.2% to 58.7%) and Qwen3.6-35B by +13.5 points (from 35.3% to 48.8%). These gains often position frontier models at "State-of-the-Art" (SOTA)-level task success compared to their baseline performance.
- The gains are attributed to the evolved memory, as the initial memory ($M_0$) contributed negligible improvements over the base agent across multiple models.
- The improvements were not due to increased context or compute; additional context sometimes led to worse performance and higher costs.

#### 4.2. Analysis of EM–WM Coupling in Long Horizon Tasks

- **Reliability over Longer Interaction Horizons**: Recuris's advantage increased with task length, reaching +32.2 points on the longest tasks, demonstrating its effectiveness in long-horizon scenarios (Figure 1, Figure 4). Analysis on $\tau^2$-Retail showed that long-horizon failures were primarily execution problems (unexecuted writes), rather than retrieval problems (read-action recall remained high across variants).
- **Impact of EM–WM Coupling**: The working state (WM only) contributed significantly more to task success (+23.9 points on $\tau^2$-Retail) than experiential memory alone (EM only, +2.0 points). The full EM+WM coupling achieved the highest task success, indicating that the verified working state is critical for effective long-horizon execution (Table 2, Figure 5).
- **Invocation Control vs. Skill Content**: State-grounded skill invocation (Recuris) outperformed a model-controlled approach (which injected all skills every turn) on $\tau^2$-Retail, leading to higher required-write recall (82.4% vs. 61.1%) and better task success (83.6% vs. 65.6%). This indicates that *when* a skill is invoked, guided by the task state, is more critical than merely its availability (Table 3, Figure 7). State-grounded invocation also reduced error compounding within episodes.
- **Domain-Specific Critical Mechanisms**: Ablation studies revealed that the specific working memory mechanism critical for success varied by domain. For $\tau^2$-Airline, "write review" (pre-execution check) was critical, while for $\tau^2$-Retail, the "status board" (state presentation) was critical. Mechanisms acting *after* the fact (e.g., "truth guard") consistently showed no measurable impact. This justifies the need for localized repair decisions based on execution traces (Figure 6).

#### 4.3. Analysis of Recursive Skill Memory Evolution

- **Structured Traces Improve Failure Localization**: Using structured traces ($\Gamma$) significantly improved the accuracy of component-level failure localization (64.8% macro accuracy) compared to using only the task outcome (13.0%) or raw trajectory (37.0%). This enhanced observability is crucial for enabling targeted, component-specific repairs (Table 4).
- **Consistent Held-Out Gains**: The evolution loop consistently yielded gains on held-out tasks (not seen during evolution), with task success deltas against $M_0$ ranging from +9.01 to +17.44 points, with intervals excluding zero. These gains compounded over iterations. The improvements were strongly correlated with increased required-write recall (Table 5, Figure 9a).
- **Meta-Agent Implementations Converge**: Two distinct Meta-Agent implementations (Claude Code and DeepSeek Harness), built independently, converged on statistically similar gains and learned the same critical components (e.g., service-request authorization tracking, execution-gate checks, anti-escalation skills). This suggests the evolution process is driven by the diagnostic evidence, rather than specific Meta-Agent heuristics (Table 6).
- **Gated Updates Preserve Abilities**: The validation gate effectively preserved existing abilities; accepted updates broke only 9.5% of tasks already solved, significantly lower than the baseline noise. The gate tended to err on the side of caution, rejecting candidates that later showed held-out gains, indicating its conservative nature but affirming its role in maintaining memory stability.
- **Cross-Task Transfer**: Memory evolved from a small set of training tasks successfully transferred to a larger set of held-out tasks, yielding 9-17 point gains where relevant failures were present. This transfer was not observed where the held-out tasks did not present the type of failures the memory was designed to repair.
- **Cross-Model Transfer**: Memory evolved on a mid-sized model (doubao-seed-2-0-pro) effectively transferred to frontier models it had not been trained on. It added +17.8 points to GPT-5.6 Sol and +15.6 points to Claude Opus 5 on $\tau^2$-Retail. The improvements were observed across various models, suggesting the evolved memory is not a crutch for weaker models but a general enhancement (Table 7).

#### 4.4. Test-Time Adaptation on Isolated Tasks

- On Terminal-Bench 2.1, a benchmark of isolated tasks, the primary driver of success was the budget for retries (+26.4 points over a single attempt). Test-time adaptation (memory rebuilt for a single task) provided a modest additional gain of +2.3 points over mere retrying at a matched budget, with some tasks solved only under adaptation. This suggests test-time adaptation complements cross-task evolution by improving per-attempt reliability on specific hard tasks (Table 8, Table 9).

### 5. Significance and Potential Impact

The research introduces Recuris, an architecture that redefines recursive self-improvement for LLM agents by focusing on an externalized, evolving memory-control layer. This approach has several significant implications and potential impacts:

- **Scalable and Stable Recursive Self-Improvement**: By confining recursion to an external memory-control layer and keeping the base LLM fixed, Recuris offers a scalable foundation for RSI. This modular approach can mitigate the risks associated with directly modifying the complex internal weights or entire codebase of LLMs, potentially leading to more stable and predictable agent evolution.
- **Enhanced Performance in Long-Horizon Tasks**: The consistent and substantial improvements in task success across diverse long-horizon benchmarks and models demonstrate Recuris's capability to address a critical limitation of current LLM agents. The architecture's ability to maintain reliability over longer interaction horizons and reduce common failure modes contributes to more robust agent behavior in complex, multi-step environments.
- **Interpretable and Targeted Evolution**: The introduction of structured execution traces and component-level failure localization represents a methodological advancement. This allows for specific diagnosis and targeted patching of memory components (Experiential Memory, Working Memory, Invocation Policy, Checkers), making the evolution process more interpretable, efficient, and less prone to unintended side effects compared to holistic updates.
- **Increased Agent Reliability through Verified State**: The verifiable Experiential–Working Memory coupling, where state updates are grounded in environmental evidence rather than model assertions, addresses the issue of hallucinated or incorrect internal states. This mechanism can lead to more dependable decision-making and action execution in LLM agents.
- **Portability and Generalization of Evolved Memory**: The demonstrated transferability of memory evolved on one model to different models, including frontier LLMs, and across various tasks, suggests that these evolved memory components capture generalizable strategies and disciplines. This could reduce the need for extensive model-specific fine-tuning or re-evolution, making agent development more efficient.
- **A New "Trainable Surface" for Frozen LLMs**: Recuris proposes the memory-control layer as a distinct "trainable surface" for frozen LLM agents. This paradigm could open new avenues for improving LLM capabilities without requiring access to or modification of the base model's parameters, which is particularly relevant for proprietary or very large models.
- **Inspiration for Future Research**: The work encourages further exploration into the design of external memory systems, validation mechanisms, and structured diagnostic approaches for LLM agents. It also highlights the potential for developing pruning operators for redundant memory and investigating how different memory components contribute to agent performance in various domains.
