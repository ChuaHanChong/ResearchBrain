# SceneCraft: An LLM Agent for Synthesizing 3D Scene as Blender Code

> [!summary] Summary
> SceneCraft is an LLM agent that turns a text description into a Blender Python script that renders scenes with up to a hundred 3D assets. It plans a relational scene graph, writes numerical layout constraints, and refines the script using a vision-language model's critique of renders. A library-learning outer loop distills reusable constraint functions. It scores 88.9 on constraint satisfaction versus 5.6 for BlenderGPT.

## Problem

- Text-to-3D generators such as DreamFusion and Magic3D produce single objects and cannot compose entire multi-asset scenes, because of dataset scale limits and domain specificity.
- Earlier rule-based systems like WordsEye and SceneSeer extract spatial constraints from language using predefined templates, so they need heavy human input whenever a new domain brings new relationship patterns.
- Directly predicting every asset's layout matrix from a text description is hard even for strong LLMs, given the combinatorial layout space and the subtle spatial relations, so existing LLM assistants such as BlenderGPT fail at complex spatial planning.

## Method

- A ==scene decomposer== splits the query into sub-scenes, and a ==CLIP-based retriever== fetches assets. An **LLM-Planner** then builds a ==relational bipartite scene graph== linking assets to relation nodes such as proximity, alignment and parallelism.
- An **LLM-Coder** turns the graph into Blender code and ==per-relation scoring functions== returning values in 0 to 1. A solver searches for the layout maximizing summed scores. A ==GPT-4V reviewer== critiques renders and revises the script in an ==inner loop==.
- An ==outer-loop== **Library-Learner** compiles the function edits made across many scenes' inner loops into a shared, reusable ==spatial skill library==. It needs no ground-truth scenes, no human input and no LLM parameter tuning.

## Results

- On 20 held-out synthetic queries, SceneCraft reaches CLIP similarity **69.8** and constraint score **88.9**, versus BlenderGPT's 24.7 and 5.6. Human raters prefer it **76.8%** (text fidelity), **83.6%** (composition) and **74.5%** (aesthetics).
- Ablations on constraint score: removing the learned library gives **64.5**, removing the inner loop **26.1**, and removing the relation graph **3.2**. Inner-loop feedback matters most, and every component contributes.
- On the Sintel movie, SceneCraft's layout similarity is **69.3** versus 27.5 for BlenderGPT. As video-model conditioning, its scenes give FVD **317**, against 574 for BlenderGPT scenes and 531 for text-to-video with finetuning.

## Takeaways

> [!tip] Key Insights
> - An intermediate symbolic abstraction, here a relational scene graph, that turns fuzzy language into checkable numeric constraints makes complex spatial planning tractable for LLMs. Removing it collapsed the constraint score to 3.2.
> - Vision-language critique of rendered outputs can serve as a reward signal, letting an agent self-improve non-parametrically by editing code. This avoids backpropagation through the LLM and needs no ground-truth labels.
> - Library learning that distills consensus edits across many tasks acts like a meta-learned initialization for later runs. It is sample-efficient, using only 20 seed queries, and transfers the skills to unseen queries.

## Detailed Report

### 1. Introduction

The ability to transform natural language descriptions into complex 3D scenes represents a significant challenge in artificial intelligence and computer graphics. While recent advances in text-to-3D generation have shown remarkable progress in creating individual objects, the task of composing entire scenes with multiple assets and intricate spatial relationships remains largely unsolved. SceneCraft, developed by researchers from Caltech, Google Research, and Google DeepMind, addresses this gap by introducing a Large Language Model (LLM) agent that can synthesize detailed 3D scenes directly as executable Blender code.

Unlike traditional approaches that rely on neural 3D generation models or rule-based systems, SceneCraft leverages the reasoning capabilities of LLMs to understand spatial relationships, generate executable code, and continuously improve through a feedback-driven learning process. The system can handle scenes with up to a hundred assets, managing complex spatial arrangements that would challenge even experienced 3D artists.

### 2. The Challenge of 3D Scene Generation

Creating 3D scenes from text descriptions involves several fundamental challenges that previous approaches have struggled to address comprehensively. Traditional text-to-3D systems like WordsEye and SceneSere relied heavily on predefined templates and symbolic rules, making them rigid and difficult to generalize. More recent neural approaches, while impressive for single objects, face significant limitations when dealing with multi-asset scene composition.

The core challenges include:

- **Combinatorial Complexity**: As the number of assets increases, the possible spatial arrangements grow exponentially, making it difficult to explore the solution space effectively
- **Spatial Reasoning**: Understanding and implementing complex spatial relationships (proximity, alignment, hierarchy) requires sophisticated reasoning capabilities
- **Asset Integration**: Combining multiple 3D objects while maintaining realistic proportions, physics, and aesthetic coherence
- **Constraint Satisfaction**: Ensuring that multiple, potentially conflicting spatial constraints are satisfied simultaneously

SceneCraft addresses these challenges by treating 3D scene generation as a constraint satisfaction problem, where natural language descriptions are translated into executable code that defines spatial relationships between assets.

### 3. Core Methodology

SceneCraft's approach centers on transforming text descriptions into structured representations that can be systematically converted into Blender Python scripts. The process begins with **asset retrieval and scene decomposition**, where an LLM analyzes the input text to identify required assets and break complex scenes into manageable sub-scenes.

For asset retrieval, the system uses a CLIP-based approach that matches textual descriptions to 3D assets in large repositories like Turbosquid. This involves rendering candidate assets and comparing them to text descriptions using vision-language similarity metrics. For complex scenes requiring many assets, an LLM-powered decomposer breaks the main query into a sequence of sub-scenes, each with its own title, asset list, and description.

The key innovation lies in the **scene graph construction** phase, where instead of directly predicting asset positions and orientations, SceneCraft creates an intermediate relational bipartite graph G(s) = (A, R, E). In this representation:
- A represents the assets in the scene
- R represents spatial and contextual relations (proximity, alignment, parallelism, hierarchy, rotation, repetition)
- E denotes edges connecting assets to specific relation nodes

This graph serves as a high-level plan that abstracts complex spatial relationships into a structured format, significantly reducing the combinatorial complexity for subsequent code generation.

### 4. The Dual-Loop Architecture

SceneCraft's most distinctive feature is its dual-loop self-improving pipeline, which enables both per-scene refinement and continuous skill learning without human annotation or parameter tuning.

#### 4.1. Inner Loop: Scene Layout Optimization

The inner loop focuses on iteratively refining individual scenes through a feedback-driven process:

1. **LLM-Coder**: Generates Blender Python scripts by reusing functions from a dynamic "spatial skill library." The coder translates the scene graph into numerical constraints, such as specific distances for proximity relationships or angles for alignment constraints.

2. **Constraint-based Search**: A specialized solver optimizes asset layouts (positions, scales, orientations) to maximize a global score representing the satisfaction of all spatial constraints. Each relation r in the scene graph contributes a score F_r based on how well the current layout satisfies that constraint.

3. **Blender Rendering**: The optimized layout is rendered into an image using Blender's rendering engine.

4. **LLM+V-Reviewer**: A multimodal LLM (such as GPT-4V) acts as a critic, comparing the rendered image to the original text description. It identifies misalignments, missing constraints, or incorrectly satisfied relationships, providing specific feedback for improvement.

5. **Iterative Refinement**: Based on the critic's feedback, the system revises the Blender script by modifying scene graph edges, updating constraint functions, or adjusting their parameters. This process continues until the scene adequately matches the text description.

#### 4.2. Outer Loop: Library Learning

The outer loop operates across multiple scenes to extract and generalize spatial skills:

After processing batches of queries through the inner loop, a **Library-Learner** component analyzes the patterns of successful modifications and distills them into reusable functions. For example, if many "on top of" scenarios initially fail because objects don't properly ground on surfaces, the system might learn to automatically add grounding constraints.

This learning process updates the global spatial skill library without requiring human intervention, ground-truth scenes, or explicit reward functions. The learning signal comes entirely from the multimodal LLM's visual feedback, making the system highly sample-efficient for acquiring generalizable skills.

### 5. Spatial Skill Learning

A crucial aspect of SceneCraft's effectiveness lies in its dynamic spatial skill library, which contains parameterized functions for implementing various spatial relationships. These functions translate high-level spatial concepts into precise numerical constraints that can be optimized.

For example, a "parallelism" constraint function might calculate directional vectors between consecutive assets and evaluate how parallel they are using dot products:

```python
def parallelism_score(assets: List[Layout]) -> float:
    """Evaluates and returns a score indicating the degree of parallelism in a list of assets"""

    # Calculate directional vectors between consecutive assets
    vectors = [
        calculate_vector(assets[i].location, assets[i + 1].location)
        for i in range(len(assets) - 1)
    ]

    # Normalize vectors to compare directions regardless of distance
    normalized_vectors = [normalize_vector(v) for v in vectors]

    # Calculate dot products between consecutive normalized vectors to evaluate parallelism
    dot_products = [
        np.dot(normalized_vectors[i], normalized_vectors[i + 1])
        for i in range(len(normalized_vectors) - 1)
    ]

    final_score = np.mean([0.5 * (dot + 1) for dot in dot_products])
    return final_score
```

The system learns to enhance these functions based on failures and successes encountered during scene generation. If a particular spatial relationship consistently fails to be satisfied, the system can modify the constraint function or add complementary constraints to improve success rates.

### 6. Experimental Results

SceneCraft was evaluated on both synthetic datasets with ground-truth constraints and real-world movie scenes from the Sintel dataset. The results demonstrate significant improvements over existing baselines across multiple metrics.

#### 6.1. Quantitative Performance

On synthetic queries with ground-truth constraints, SceneCraft achieved:
- **CLIP Similarity**: 69.8 vs. BlenderGPT's 24.7 (45.1% improvement)
- **Constraint Score**: 88.9 vs. BlenderGPT's 5.6 (demonstrating superior spatial relationship satisfaction)

#### 6.2. Human Evaluation

Human annotators judged SceneCraft against BlenderGPT across three dimensions:
- **Text Fidelity**: 83.6% win rate
- **Composition & Constraint Agreement**: 74.5% win rate
- **Aesthetics**: 74.5% win rate
- **Overall**: 76.8% win rate

#### 6.3. Real-World Application

When tested on the Sintel movie dataset for scene-guided video generation:
- **Layout Matrix Similarity**: 69.3 vs. BlenderGPT's 27.5
- **Scene CLIP Similarity**: 82.7 vs. BlenderGPT's 41.8
- **FVD (video quality)**: 317 vs. BlenderGPT's 574 (lower is better)

#### 6.4. Ablation Study Results

The importance of each component was validated through ablation studies:
- Removing the **Learned Library** dropped CLIP score to 48.3 and constraint score to 64.5
- Removing the **Inner-Loop** optimization reduced performance to 32.8 CLIP score and 26.1 constraint score
- Removing the **Relation Graph** abstraction resulted in the poorest performance: 19.4 CLIP score and 3.2 constraint score

These results confirm that each component of the dual-loop architecture contributes significantly to the system's overall performance.

### 7. Applications and Impact

SceneCraft's capabilities extend far beyond academic research, with significant implications for multiple industries:

#### 7.1. Creative Industries

- **Game Development**: Rapid prototyping of game environments and levels from conceptual descriptions
- **Film and Animation**: Streamlining pre-visualization and scene layout for animated productions
- **Architecture and Design**: Converting conceptual descriptions into detailed 3D visualizations for client presentations

#### 7.2. Content Creation Pipeline

SceneCraft can serve as an intermediary tool in content creation workflows, where designers provide high-level descriptions that are automatically converted into detailed 3D scenes. These scenes can then be further refined by human artists, significantly accelerating the initial design phase.

#### 7.3. Video Generation Enhancement

The research demonstrates SceneCraft's potential as a control mechanism for video generation models. By providing explicit 3D scene information, video generators can produce more coherent, structured, and controllable outputs compared to text-only conditioning.

### 8. Limitations and Future Directions

While SceneCraft represents a significant advancement in text-to-3D scene generation, several limitations and opportunities for future work remain:

#### 8.1. Current Limitations

- **Asset Dependency**: The system's output quality is constrained by the available 3D asset repository
- **Rendering Constraints**: Complex lighting, materials, and advanced visual effects are not directly addressed
- **Scale Limitations**: While capable of handling up to 100 assets, extremely large scenes may still pose computational challenges

#### 8.2. Future Research Directions

- **Integration with Neural 3D Generation**: Combining SceneCraft's spatial reasoning with neural object generation could enable creation of custom assets within scenes
- **Dynamic Scene Generation**: Extending the system to handle temporal relationships and scene animations
- **Multi-modal Input**: Incorporating reference images or sketches alongside text descriptions for more precise scene specification
- **Real-time Interaction**: Developing interactive interfaces where users can iteratively refine scenes through natural language dialogue

The work establishes a foundation for AI-driven 3D content creation that could eventually democratize complex scene design, making sophisticated 3D modeling accessible to users without extensive technical expertise. As the underlying LLMs and multimodal models continue to improve, SceneCraft's capabilities are likely to expand correspondingly, potentially revolutionizing how we approach 3D content creation in digital media production.
