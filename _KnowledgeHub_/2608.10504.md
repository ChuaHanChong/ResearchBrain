# MEGA: Self-Evolving Agent Optimization Infrastructure via Wisdom Graph

> [!summary] Summary
> MEGA is a three-layer infrastructure for self-evolving agent optimization. Layer 1 distills agent sessions into wisdom assets via BIRCH behavioral clustering and A/B validation; Layer 2 decomposes them into atomic Primary-Context-Resultant triplets in a typed Wisdom Graph, infers implicit relations, and assembles plans by Prize-Collecting Steiner Tree retrieval; Layer 3 optimizes heterogeneous workflows under fixed-seed attribution, scoring 46.5% on SkillsBench and 76.55 aggregate on four workflow benchmarks.

## Problem

- Prompt and workflow optimizers improve a system within one project but leave the rationale for successful strategies unstructured, so strategy search restarts from scratch elsewhere.
- Skill libraries and skill graphs compose at whole-skill granularity, never decomposing skills into atomic sub-units nor inferring dependency relations that were never explicitly recorded.
- Stored knowledge is rarely verified against execution outcomes, so stale and invalid entries accumulate beside valid ones and retrieval quality gradually degrades.

## Method

- Layer 1 distills sessions through domain pre-clustering plus single-pass ==BIRCH== behavioral clustering, then gates candidates by hash and embedding deduplication, conflict resolution, and ==behavioral A/B validation== of accuracy lift and token cost.
- Layer 2's **Wisdom Graph** stores atomic ==Primary-Context-Resultant== triplets with Pearl-inspired sufficiency/necessity edge scores, expands them by deduction, abduction, and induction, then assembles role-differentiated plans via ==Prize-Collecting Steiner Tree== retrieval that surfaces bridging nodes.
- Layer 3 optimizes heterogeneous workflows of code nodes, LLM calls, and tool-using agents with specialized agents under ==Seed-Epoch== fixed-seed evaluation, coverage-driven data augmentation, and a meta-learning agent feeding verdicts back.

## Results

- On SkillsBench (84 tasks, Gemini 3 Flash), MEGA passes **46.5%** versus SkillNet **41.7%**, AgentSkillOS **41.1%**, and **31.5%** with no skills, while using only **822k** tokens per task.
- Curation efficiency reaches **0.566** score per megatoken against **0.424** and **0.345**, with **11.8s** curation latency per task versus **37.8s** for SkillNet and **403.4s** for AgentSkillOS.
- On GPT-4.1 Mini, aggregate score **76.55** beats GEPA **69.52** and Feedback Descent **66.56**; the largest gain is HoVer **74.67** versus **56.67**, using smaller validation splits.

## Takeaways

> [!tip] Key Insights
> - Supplying skills is not enough: how they are decomposed, selected, and assigned execution roles dominates both downstream pass rate and context cost.
> - Retrieval over a pre-indexed graph needs no LLM calls, so richer compositional reasoning can lower latency and tokens rather than raising them.
> - Holding the evaluation sample fixed across iterations isolates strategy effects from data variance; without it, recorded successes blend genuine gains with easier draws.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

The field of agent-based software development is characterized by a shift where coding agents increasingly handle implementation tasks, while human roles transition to defining optimization objectives, designing evaluation data, and interpreting results. Within this landscape, research efforts are focused on developing infrastructure that systematically improves agent systems.

Current approaches to agent development automation include several categories:
- **Stateless automation loops**, such as the Ralph Loop, automate execution but do not accumulate knowledge from prior cycles.
- **Prompt optimizers** (e.g., DSPy, GEPA) and **workflow optimizers** (e.g., AFlow, Flow) enhance agent systems within specific projects. However, the underlying rationale for successful optimization—which strategies are effective under particular conditions—often remains unstructured and non-transferable between projects.
- **Skill libraries** (e.g., Voyager, Memento-Skills) store reusable procedures.
- **Adaptive memory systems** (e.g., Reflexion, ACE, ReasoningBank) distill reasoning strategies and insights from past attempts.

While these advancements address various aspects of agent development, the paper identifies three limitations that persist when these approaches operate independently:
1. **Optimization without knowledge accumulation**: Existing optimizers improve performance but typically do not structure the "why" behind successful strategies as transferable knowledge. Memory layers, while present, often lack the capability for compositional reasoning over stored items.
2. **Lack of compositional reasoning over stored knowledge**: Skill libraries, for instance, store entire procedural units but often do not facilitate reasoning about how to decompose these skills into atomic sub-units, compose them effectively, or infer implicit relations between them. This is described as a "compositionality gap," where models solve sub-problems but struggle to integrate solutions.
3. **Absence of knowledge self-evolution through operational evidence**: Knowledge that is not validated against actual execution outcomes risks becoming ungrounded or outdated. Without a feedback loop where optimization evidence verifies the effectiveness of knowledge, unverified information can accumulate, potentially degrading retrieval quality.

MEGA (Meta Evaluation-Grounded Adaptation) is presented as an infrastructure designed to address these limitations by unifying these capabilities. It aims to integrate a self-evolving cycle where agent sessions are distilled into verified knowledge, compositional reasoning guides optimization, and optimization evidence refines both the knowledge and the reasoning processes themselves. The work introduces a typed Wisdom Graph with logical reasoning and evidence-driven self-evolution as a central architectural element to bridge these identified gaps.

### 2. Key Objectives and Motivation

The primary motivation for MEGA stems from the observation that as coding agents become more proficient in implementation, the critical challenge shifts from building individual, capable agents to establishing an infrastructure that can systematically and repeatedly improve agent systems based on empirical data. This paradigm shift highlights an "infrastructure bottleneck" in current agent development.

The key objectives of MEGA are directly informed by the three limitations identified in existing agent development automation:

1. **Systematic Accumulation of Transferable Knowledge from Optimization**: Current systems often optimize without retaining the underlying rationale for why particular strategies succeeded under specific conditions. This means optimization strategies frequently restart from scratch for new projects. MEGA aims to transform each optimization process into a durable asset by distilling reusable wisdom from agent sessions. This wisdom is intended to be structured and transferable, enabling subsequent projects to leverage past optimization insights.
2. **Enabling Compositional Reasoning over Accumulated Knowledge**: Existing knowledge storage mechanisms, such as skill libraries, typically store procedural knowledge as monolithic units, lacking the ability to decompose them into atomic sub-units or infer complex logical relationships (e.g., prerequisites, mutual exclusions) among them. MEGA's objective is to develop a reasoning substrate, a typed Wisdom Graph, that allows for the decomposition of wisdom into atomic Primary-Context-Resultant (PCR) units. This structure facilitates deductive, abductive, and inductive reasoning to expand implicit relations and guide the compositional assembly of context-specific execution plans.
3. **Facilitating Self-Evolution of Knowledge through Operational Evidence**: Knowledge that is not empirically validated can become stale or erroneous, leading to degradation in system performance over time. A core objective of MEGA is to establish a robust feedback loop where operational evidence from optimization cycles continuously refines both the accumulated wisdom and the reasoning mechanisms that govern its use. This mechanism is intended to ensure that knowledge evolves based on its demonstrated effectiveness in real-world agent operations.

In summary, MEGA's motivation is to create a unified, self-evolving infrastructure where the process of optimizing an agent system is inextricably linked with the process of evolving the knowledge that guides that optimization. The ultimate goal is for this infrastructure to enable the Wisdom Graph to mature over time, providing effective optimization guidance from initial queries by leveraging accumulated experience across multiple projects.

### 3. Methodology and Approach

MEGA is structured as a three-layer, self-reinforcing architecture where optimization produces evidence, evidence refines a Wisdom Graph, and the refined graph guides subsequent optimization. This cycle is formally represented by equations indicating how wisdom (W), execution plans (Π), and evidence (E) evolve over time.

**Overall Architecture (Three Layers):**

- **Layer 1 (Session-based Wisdom Generation)**: Responsible for distilling raw agent session traces into reusable, structured wisdom assets.
- **Layer 2 (Wisdom Reasoning and Curation)**: Focuses on processing these wisdom assets within a typed Wisdom Graph, performing logical reasoning, and assembling context-specific execution plans.
- **Layer 3 (Evaluation-Driven Optimization)**: Executes multi-agent optimization, attributes performance improvements, and feeds back operational evidence to Layer 2 and session traces to Layer 1.

**Inter-Layer Artifact Contract:** Each layer has specified inputs, outputs, and core transformations to ensure clear system boundaries and interactions.

**Four Types of Wisdom:** MEGA categorizes wisdom into four types, each representing a causal judgment and sharing PCR semantics within the Wisdom Graph:
1. **Skill**: Reusable procedural knowledge.
2. **Strategy**: Decision rules and judgment criteria.
3. **Curation Pattern**: Effective combinations of skills and strategies under specific conditions.
4. **Optimization Trajectory**: Records of successful or failed optimization paths.

**Wisdom Graph (WG-DB) as a Reasoning Substrate:**
The WG-DB is a directed typed multi-graph where nodes are PCR components and edges carry Sufficiency/Necessity scores. It employs a "Role-Fluid node pool," allowing a concept to act as a Primary, Context, or Resultant in different triplets, facilitating richer relational networks.

**Layer 1: Session-based Wisdom Generation:**
This layer distills raw conversation sessions into verified wisdom assets through a multi-stage pipeline:
- **Privacy-Preserving Filtering**: Applies client-side masking and anonymization to session traces before processing.
- **Two-Stage Clustering**:
 - **Domain Pre-Clustering**: Classifies sessions by domain using embedding similarity, narrowing the scope for subsequent clustering.
 - **Behavioral Pattern Discovery**: Applies the BIRCH algorithm within each domain cluster. BIRCH's Clustering Feature (CF) tree structure enables single-pass O(n) processing and adaptively discovers behavioral patterns without requiring a predefined number of clusters (k). It separates sessions that are semantically similar but behaviorally distinct.
- **Synthesis and Structural Filtering**: An LLM synthesizes extracted behavioral patterns into structured wisdom. This involves hash-based exact deduplication, LLM-based conflict detection, and cross-run embedding-similarity deduplication to prevent knowledge-base contamination.
- **Behavioral A/B Validation**: This is a core quality gate. Test cases are generated, and wisdom candidates are empirically validated by comparing agent performance with (treatment) and without (control) the injected wisdom. Metrics include performance lift (accuracy) and token efficiency (cost). This ensures only empirically verified wisdom enters the system.

**Layer 2: Wisdom Reasoning and Curation:**
Layer 2 is responsible for processing wisdom assets, reasoning over them, and generating execution plans.
- **Security Screening Gate**: Inspects incoming wisdom assets (instructions, prompts, scripts) for potential threats like prompt injection or destructive commands.
- **PCR Atomic Decomposition and Role-Fluid Graph**: Each wisdom asset is decomposed into atomic PCR triplets (Primary-Context-Resultant), capturing internal logical dependencies (prerequisite, exclusion, conditional branching) as typed edges. Edges are scored with Sufficiency/Necessity values, indicating causal strength.
- **PCR Reasoning**: The directional P→C→R structure supports three modes of logical inference:
 - **Deduction**: Infers transitive causal relations (P→C and C→R implies P→R), applying multiplicative score decay for longer chains.
 - **Abduction**: Infers reverse causal relations (P→R and C→R implies P→C) by back-tracing shared results, requiring a high Necessity score for C→R.
 - **Induction**: Discovers statistical patterns (multiple P nodes connected to the same C and R implies C→R) verified by a hypergeometric test.
 These reasoning types are applied iteratively, monotonically expanding the graph's edge set until a fixed point is reached.
- **PCST-Based Compositional Retrieval**: For query-time plan assembly, the problem is formalized as a Prize-Collecting Steiner Tree (PCST) problem over the Wisdom Graph. This mechanism identifies "bridging knowledge"—nodes that may have low direct similarity to a query but are essential for connecting highly relevant nodes—enabling the assembly of mixed-type subgraphs (skills, strategies, patterns, trajectories).
- **From Subgraph to Execution**: The retrieved PCST subgraph is transformed into a linearized execution plan, assigning roles (execution candidate, gating rule, fallback path) to retrieved wisdom artifacts.
- **ROI-Based Wisdom Curation (Self-Evolution)**: This mechanism continuously refines wisdom effectiveness predictions based on historical performance. It uses predicted utility estimation, step-level aggregation, adaptive gating (cold-start vs. warm gate), and a four-axis composite scoring system. A Correction Factor (CF) calibrates the system's "self-awareness" of prediction accuracy.
- **Wisdom Self-Evolution Feedback Loop**: Operational outcomes from Layer 3 update individual-level wisdom calibration (transfer function τ), promote compositional patterns to curation strategies, and flag wisdom for content-level evolution if revision suggestions accumulate. Offline pattern consolidation prevents pattern proliferation.
- **Wisdom Maintenance (Auto Graph Hygiene)**: Layer 2 performs ongoing maintenance:
 - **PCR-Based Deduplication**: Merges semantically equivalent PCR triplets, consolidating evidence.
 - **Contradiction Resolution**: Detects and resolves conflicting wisdom by retaining stronger evidence or adding exclusion conditions.
 - **Evidence-Triggered Content Update**: Applies targeted patches to outdated wisdom based on accumulated feedback.

**Layer 3: Evaluation-Driven Multi-Agent Optimization:**
Layer 3 is an optimization engine for heterogeneous agent workflows, which include code nodes, LLM calls, and tool-using agent nodes. It extends optimization beyond prompt tuning to include tool configuration, code logic, and orchestration structure.
- **The Adapt Pipeline**: An end-to-end pipeline for system optimization:
 1. **Asset Scan**: Inventories existing system assets.
 2. **Adaptive Entry**: Selects starting point based on available assets.
 3. **Research Agents (conditional)**: If evaluation data or code is missing, specialized agents gather state-of-the-art information and datasets.
 4. **Reverse PRD / Data Synthesis**: A Reverse Engineer agent reconstructs a Pipeline Requirement Document (PRD) and, if needed, a Data Agent synthesizes evaluation datasets (stratified by difficulty, with human approval gates).
 5. **Shared Optimization Loop**: Executes iterative optimization based on Seed-Epoch.
 6. **Meta-learning Agent**: Extracts optimization trajectories as structured wisdom for Layer 2, closing the feedback loop.
- **Multi-Agent Collaboration**: Over a dozen specialized agents (e.g., Scientist, Code Reviewer, Redesign Agent) are coordinated by a central optimization agent.
 - **Baseline Analysis**: In Iteration 0, the system is evaluated, and the scientist agent performs diagnostics (error classification, root-cause analysis, ROI-based prioritization) and assesses the need for architectural redesign.
 - **Delta Mode**: In subsequent iterations, the optimization agent applies targeted fixes (prompt, code, parameter tuning), validated by the code reviewer (static analysis, dry-run), and measures results.
- **Data-Aware Optimization**: Before the optimization loop, the system analyzes whether failures stem from workflow limitations or data coverage gaps. It conditionally generates targeted synthetic data to augment training sets for missing dimensions.
- **Seed-Epoch: Overfitting Regulation**: To ensure attributable performance gains, all iterations within an "epoch" are evaluated on a fixed dataset (Seed-Epoch, ξ_e). This eliminates data variance, attributing deltas primarily to strategy changes. The epoch advances to new data upon saturation or plateauing.
- **Optimization Safeguards**:
 - **Anti-Heuristic Enforcement**: Code reviewer prohibits content-aware patterns (e.g., specific regex) to prevent overfitting.
 - **Overfitting Detection**: Monitors train/validation gap and restricts optimization to prompt improvements if the gap exceeds a threshold.
 - **Fixability-Based Goal Calibration**: Sets realistic accuracy targets based on error classification (prompt-fixable, code-fixable, architecture-required).
- **Cross-Layer Compounding Cycle**: Every "verdict" (tuple of accuracy, latency, token deltas) from Layer 3 updates the evidence confidence (η) and historical transfer rate (τ) in Layer 2. The meta-learning agent also extracts and registers optimization trajectories as structured wisdom, allowing the system to learn and improve its own optimization process across projects.

### 4. Main Findings and Results

The evaluation of MEGA was conducted along two primary axes: the quality of wisdom curation and the performance of its optimization capabilities, comparing against existing baselines.

### 5. Wisdom Curation Quality (SkillsBench)

- **Setup**: The evaluation utilized SkillsBench, a benchmark comprising 84 tasks across 11 domains, with deterministic pytest assertions in isolated Docker containers for binary pass/fail verdicts. The agent used was Gemini 3 Flash. The skill pool consisted of 4,207 assets.
- **Conditions**: Four conditions were compared, differing only in their skill discovery and orchestration methods: "No Skills" (baseline), "SkillNet", "AgentSkillOS", and "MEGA (WG)".
- **Metrics**: Pass rate (primary), average token consumption per task, curation latency (time to discover and orchestrate skills), and curation ROI (pass-rate improvement per additional megatoken consumed).
- **Results**:
 - **No Skills**: Achieved a 31.5% pass rate with 894k tokens consumed.
 - **AgentSkillOS**: Achieved a 41.1% pass rate, but with higher token consumption (1189k) and the longest curation latency (403.4 sec/task). Its efficiency was 0.345 score/Mtok.
 - **SkillNet**: Achieved a 41.7% pass rate with 983k tokens and 37.8 sec/task curation latency. Its efficiency was 0.424 score/Mtok.
 - **MEGA (WG)**: Demonstrated the highest pass rate at 46.5%. It also exhibited the best efficiency (0.566 score/Mtok) and the lowest curation latency (11.8 sec/task), while consuming fewer tokens per task (822k) compared to other skill curation methods.
- **Observations**: The results indicate that the method of skill curation significantly impacts performance and efficiency. MEGA's compositional retrieval over a typed Wisdom Graph, where skills are decomposed into atomic PCR units and assembled through graph reasoning, led to higher task performance, lower token consumption, and reduced curation latency compared to flat metadata matching and hierarchical tree search approaches.

### 6. Optimization Performance (LM-centric Optimizers)

- **Setup**: MEGA's optimization performance was compared against established LM-centric optimizers: MIPROv2, TextGrad, GEPA, and Feedback Descent. All methods were evaluated on GPT-4.1 Mini using four benchmarks from GEPA’s suite (HotpotQA, IFBench, HoVer, PUPA) with identical ground-truth evaluation data, train/test splits, and seeds. MEGA utilized smaller validation sets for its optimization process.
- **Metrics**: Aggregate score across benchmarks and individual benchmark scores.
- **Results**:
 - **Baseline**: Achieved an aggregate score of 52.67.
 - **MIPROv2**: Achieved an aggregate score of 59.71.
 - **TextGrad**: Achieved an aggregate score of 61.08.
 - **Feedback Descent**: Achieved an aggregate score of 66.56.
 - **GEPA (best)**: Achieved an aggregate score of 69.52.
 - **MEGA**: Attained the highest aggregate score of 76.55.
- **Observations**: MEGA's optimization system consistently outperformed the strongest baselines across all four benchmarks. It surpassed GEPA by +7.03 points and Feedback Descent by +9.99 points in aggregate score. The most substantial absolute gain was observed on HoVer (+18.00 over GEPA). These improvements were achieved despite MEGA using smaller validation sets, suggesting efficiency in convergence. The paper attributes these gains to the integrated infrastructure, including the curated Wisdom Graph for compositional context and the evaluation-driven optimization with disciplined attribution (Seed-Epoch regime).

### 7. Significance and Potential Impact

The development of MEGA represents an architectural approach to agent development infrastructure by integrating optimization with knowledge management and self-evolution. This work contributes to the field by addressing limitations in current agent automation concerning knowledge accumulation, compositional reasoning, and evidence-driven knowledge refinement.

The primary significance of MEGA lies in its introduction of a self-evolving feedback cycle. In this cycle, session distillation generates verified knowledge, logical reasoning guides the composition of execution plans, and multi-agent optimization produces empirical evidence that continuously refines both the Wisdom Graph and the underlying curation logic. This "meta-optimization" process allows the optimization method itself to improve over time.

Potential impacts of this infrastructure include:
- **Systematic and Repeatable Agent System Improvement**: By transforming each optimization process into durable assets and accumulating transferable knowledge, MEGA offers a pathway for systematically enhancing agent performance across various projects and tasks, reducing the need to restart strategy searches from scratch.
- **Enhanced Agent Capabilities through Compositional Wisdom**: The decomposition of wisdom into atomic PCR units and the application of logical inference (deduction, abduction, induction) enable the discovery and utilization of implicit relations, which may not be accessible through similarity-based retrieval alone. This can lead to more robust and contextually appropriate agent behaviors.
- **Increased Efficiency and Reliability in Agent Development**: The empirical validation of wisdom assets through behavioral A/B testing, combined with mechanisms like Seed-Epoch for attributable performance measurement and various optimization safeguards, aims to ensure that accumulated knowledge is effective and that performance gains are genuine, mitigating issues like overfitting and knowledge contamination. The observed reductions in token consumption and curation latency also point to operational efficiencies.
- **Foundation for Collective Agent Intelligence**: By accumulating skills, strategies, curation patterns, and optimization trajectories across multiple projects, the Wisdom Graph is intended to serve as a collective intelligence substrate. This may mitigate the cold-start problem for new agent development initiatives, allowing them to benefit from previously validated structures and knowledge.
- **Shifting Development Paradigm**: MEGA proposes a shift from focusing on individual agent capabilities to developing an infrastructure that systematically improves agent systems, suggesting a more scalable and sustainable approach to agent-based software development.

The empirical results, demonstrating improved pass rates, efficiency, and optimization performance against established baselines, support the integrated design of MEGA. These gains are presented as a consequence of the entire closed-loop architecture, where each layer contributes to the compounding effect of the system's self-improvement.
