# Coding Agents for Generalized Task and Motion Planning Problems

> [!summary] Summary
> AgenticGenPlan studies off-the-shelf coding agents as generalized task-and-motion planners: given only a task description, sandboxed simulator access and a fixed budget, an agent probes the environment, writes and revises a programmatic policy, which is then frozen and evaluated without any model in the loop. Across 28 environments and 98,000 episodes, agent programs reach 56-95% mean success versus 47% for hand-engineered planners, with an order of magnitude less compute per instance.

## Problem

- Task and motion planning stays hard even with full observability because discrete choices are tightly coupled to geometric, kinematic and dynamic feasibility constraints.
- Existing generalized-TAMP methods that learn samplers, feasibility predictors, heuristics or abstractions all demand heavy TAMP-specific engineering and hand-designed scaffolding per domain.
- Language models asked to make geometric or physical decisions inside planners perform poorly, so it was unclear whether coding progress transfers to physical reasoning.

## Method

- **AgenticGenPlan** gives each coding agent a task description plus a client exposing reset and step, a bare NumPy/SciPy sandbox, and a fixed budget to synthesize one frozen programmatic policy class.
- ==Interactive synthesis loop==: the agent picks its own experiments, writes probing scripts and custom tests, renders states as images, and git-commits each revision so program evolution is replayable.
- A + source variant exposes environment code inside the container, letting programs read goal checks and reuse inverse kinematics, motion planners and collision checks; baselines are planners, one-shot generation and **LLMGenPlan**.

## Results

- On the 16 planner-equipped environments, agents average **82%** and **95%** success versus **47%** for planners; per-instance compute is **2.1 s** and **0.5 s** versus **29 s**.
- Agentic synthesis beats static prompting sharply: LLMGenPlan with the same model, source code and budget reaches **28%** mean success, while the source-access agent wins **27 of 28** environments.
- Interaction pays measurably: kinematic self-calibration cuts predicted-position RMSE from **38.9 mm** to **1.8 mm**, and single revisions lift runs from **6%** to **64%** and **15%** to **56%**.

## Takeaways

> [!tip] Key Insights
> - Frozen synthesized programs can beat search-based planners on both success and runtime, since synthesis amortizes the reasoning that per-instance planning repeats.
> - Withholding source code forces agents to distill knowledge into self-contained code, giving faster policies; source access raises success but slows decisions by invoking the simulator.
> - Agents invent strategies absent from published solutions, including non-prehensile pushing and regrasping, yet dynamic 3D tasks needing sweeping or pouring many objects remain largely unsolved.

## Detailed Report

### 1. Overview

Consider a robot that must retrieve a target while the number and placement of obstacles surrounding it change. A fixed action sequence will not work across those cases. Often, the practical bottleneck is the engineering and computation needed to build a new plan for each case. This paper takes a different approach. A coding agent experiments through a simulator interface and writes one program for the task. At evaluation time, that program is frozen and tested on unseen instances. Across a large suite, these programs often solve more cases than the provided planners.

Coding agents for generalized TAMP. Top: conventional planner engineering compared with an agent that uses an environment API in a sandbox to produce a policy shared across tasks. Bottom: success rate and computation time per instance, plotted against problem size and averaged over environments with a planner and multiple object counts. The paper reports that the agentic method has higher success while maintaining efficiency.

### 2. From simulator probes to a reusable program

In task-and-motion planning (TAMP), a robot must choose what to manipulate and how. Its discrete choices remain coupled to geometric and physical constraints. Generalized TAMP seeks one reusable solution across instances of the same task whose object counts, configurations, or geometry vary.

In the main setting, the agent receives a task description and simulator reset, step, and render access. It has no environment source code and no supplied predicates, operators, samplers, or skills. It works in a bare Python/NumPy/SciPy environment. Within a $20 model-usage budget, it can choose experiments, inspect results, write custom tests, and revise its code. It then returns one program. That program is frozen and evaluated with no LLM call on 100 held-out instances under a 60-second instance timeout. The study covers 25 KinDER environments and three PDDLStream domains.

Left: in StickButton, custom tests reveal an edge case with a high button and a stick near a wall. A bottom grasp fails, a side grasp moves the stick, a side grasp is too short, and the robot releases and regrasps before pressing the button. Right: a Shelf arm is probed while holding a cube. Observed cube positions are used to fit the robot's geometry, and the fitted model is then used for calibrated inverse kinematics. The initial model mismatch is exaggerated for visibility.

In one run, the agent fitted six parameters. The RMSE on calibration observations fell from 38.9 to 1.8 mm.

### 3. Two decisive comparisons

Success is the share of held-out episodes in which a frozen program reached the goal within the task horizon and the 60-second per-instance wall-clock limit.

**Against hand-engineered planners.** Across the 16 environments with planner baselines, GPT-6 Astra averaged 95% success, compared with 47% for the planner. Both figures are equal-environment averages. All three main-setting configurations exceed the planner's mean on this subset. However, Astra beats the planner in 15 of 16 environments, Opus in 12, and Sol in 9.

**Against a non-agentic LLM pipeline.** LLMGenPlan uses Opus 5, receives environment source code, and has the same $20 synthesis budget. It cannot choose its own tests or run code; instead, a fixed pipeline returns predefined feedback. Over all 28 environments, Opus + source averaged 84% success, while LLMGenPlan averaged 28%. Opus + source scored higher in 27 of the 28 environments. This supports the authors' interpretation that the agentic synthesis setup matters. It does not isolate interaction as the sole cause, because tool use, custom testing, and the way code is revised differ together.

The method's reach is uneven. Astra's reported mean success in Dynamic3D is 65%. Some tasks, particularly sweeping or pouring many small objects, remain largely unsolved in the main setting.

### 4. A baseline, not a verdict

The authors conclude that coding agents are strong and should serve as an important baseline for future generalized TAMP research. The evidence has clear limits. It comes from simulated, simplified tasks with fully observed object-centric states and simulator access during synthesis. It does not establish performance under perception uncertainty or on real robots. Because the models' training data are undisclosed, prior exposure to benchmark code cannot be ruled out.
