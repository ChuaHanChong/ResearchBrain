# HELIOS: An LLM-Driven Autonomous Indirect Trajectory Optimization Agent

> [!summary] Summary
> HELIOS, an LLM-driven autonomous agent developed by the State Key Laboratory of Astronautic Dynamics, automates indirect low-thrust trajectory optimization, translating natural language problem descriptions into symbolic derivations and C++ shooting code. It successfully generates optimal solutions for complex scenarios with up to 48 variables, demonstrating an end-to-end autonomous approach.

## Problem

- Deriving transversality conditions for diverse mission constraint types is a labor-intensive and error-prone manual process.
- Different dynamics models (e.g., chemical propulsion, solar sails) necessitate repeated manual code rewriting for Hamiltonian, costate equations, and optimal control laws.
- Numerical convergence of highly nonlinear shooting equations is challenging and sensitive to initial guesses, especially for problems exceeding 20 variables.

## Method

- A ==five-stage pipeline== uses an LLM for autonomous ==PMP symbolic derivation==, incorporating ==symbolic verification== and a ==compilation repair loop==.
- A ==unified constraint framework== processes all constraint types uniformly, automatically identifying free parameters and generating corresponding stationarity conditions.
- A ==modular code generation architecture== (==DYNAMICS==, ==SWITCH==, ==RESIDUAL==, ==SOLVE==) allows the LLM to adapt to varying dynamics models by generating custom code modules.

## Results

- The DeepSeek-V4-Pro LLM backend achieved the highest overall score (**905/1100**) across **11** diverse scenarios, successfully handling complex problems with up to **48** variables.
- The compilation repair loop increased compilation success rates for some LLMs, such as DeepSeek-V4-Flash, from **4** to **11** scenarios.
- For a complex **48**-variable scenario involving multiple stay constraints, HELIOS autonomously converged with a final shooting residual of **6.18 × 10^-14** on the first random restart.

## Takeaways

> [!tip] Key Insights
> - Large Language Models (LLMs) can effectively perform complex symbolic reasoning for optimal control theory, automating PMP derivation from natural language.
> - Embedding a general set of PMP-derived rules (e.g., for lambda_0 handling, control direction, geometric derivatives, and constraint parameters) into LLM prompts improves derivation correctness and robustness.
> - A compilation repair loop that feeds compiler error messages back to the LLM significantly enhances the success rate of generated C++ shooting code.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

Low-thrust trajectory optimization is a fundamental aspect of deep-space mission design, offering advantages in propellant economy compared to impulsive chemical propulsion, albeit with increased complexity. Within this field, optimal control problems are typically tackled using either direct or indirect methods. Direct methods discretize the problem and solve a large-scale nonlinear programming problem, while indirect methods, based on Pontryagin's Minimum Principle (PMP), transform the optimal control problem into a two-point boundary value problem (TPBVP) solvable by shooting methods. Indirect methods are recognized for providing optimality guarantees and transparent solution structures, but their practical application has traditionally been limited by several challenges.

The paper situates its work within the context of these challenges, specifically addressing the labor-intensive nature of deriving transversality conditions for diverse constraint types, the need for repeated code rewriting for different dynamics models, and the numerical convergence difficulties associated with shooting equations. Concurrently, the rise of large language models (LLMs) with capabilities in symbolic reasoning and code generation has opened new avenues for automating complex scientific tasks. This research leverages LLMs to address the traditional bottlenecks in indirect trajectory optimization, aiming to automate the entire process from problem description to numerical solution, thereby bridging the gap between theoretical optimality and practical implementation. It distinguishes itself from prior work on LLM-assisted aerospace dynamics by proposing an end-to-end LLM-driven system for PMP symbolic derivation and shooting code generation.

### 2. Key Objectives and Motivation

The primary objective of this research is to develop an autonomous agent, HELIOS (Heuristic Engine for Low-thrust Interplanetary Optimization System), capable of performing indirect low-thrust trajectory optimization from a natural language problem description, without human intervention in the derivation or code generation process. This objective is motivated by three significant bottlenecks in the traditional application of indirect methods:

1. **Derivation Burden Due to Constraint Diversity:** Missions frequently involve a variety of constraint types, such as terminal rendezvous, interior-point flybys, stay arcs, gravity assists, and inequality path constraints. Each constraint type necessitates a specific derivation of its transversality conditions, which is a tedious and error-prone manual process. The paper notes that a gravity-assist constraint, for instance, requires complex derivations involving costate jump conditions, Hamiltonian continuity, and partial derivatives with respect to state variables and free parameters. The motivation is to automate this derivation to eliminate manual effort and reduce errors.
2. **Code Rewriting Due to Dynamics Diversity:** Different spacecraft and mission profiles entail distinct dynamics models (e.g., chemical propulsion, solar sails, J2 perturbation). These models lead to substantially different Hamiltonian structures, costate equations, and optimal control laws, which in turn require separate numerical code implementations and validations. The motivation is to create a system that can adapt to various dynamics models without requiring repeated manual code rewrites.
3. **Numerical Convergence of Shooting Equations:** The shooting system derived from indirect methods is highly nonlinear, making its numerical solution sensitive to initial guesses. As the number of variables increases, the probability of a random initial guess converging to a solution diminishes exponentially, often leading to failures for problems with more than 20 variables. While HELIOS does not directly aim to solve the intrinsic nonlinearity of the shooting problem itself, it intends to automate the preparation of the problem for numerical solvers, ensuring correctness in the formulation that feeds into established numerical techniques.

To address these motivations, HELIOS aims to achieve the following key innovations:

- **Constraint-Adaptive Derivation Framework:** To unify the treatment of diverse constraints, identifying free parameters within constraints and automatically generating corresponding stationarity conditions, thereby breaking the traditional limitation of case-by-case transversality condition derivation.
- **Dynamics-Adaptive Code Generation:** To develop a modular code generation architecture that supports complete code generation for non-standard dynamics models (e.g., solar sails, J2 perturbation) without requiring modifications to a fixed underlying template.
- **General Derivation Rule Set:** To distill and embed a set of general rules (Rules G1-G4, B2) from PMP theory into the LLM's prompt. These rules are designed to cover common error-prone points in derivations, such as lambda_0 handling, control-direction verification, geometric-derivative completeness, and state-dimension consistency, making the derivation process more robust.

### 3. Methodology and Approach

HELIOS employs a five-stage pipeline architecture designed to autonomously convert a natural language problem description into a converged trajectory solution. The system leverages a large language model (LLM) at its core for symbolic reasoning and code generation.

#### 3.1. Overall Design (Five-Stage Pipeline)

The pipeline consists of the following sequential stages:
1. **Constraint Parsing (ConstraintParser):** This initial stage transforms the natural-language problem description (specifying central body, constraints, dynamics, spacecraft parameters, and optimization objective) into a structured JSON object (`problem_spec`). A key design choice is that the parser does not differentiate between constraint types; instead, all are represented uniformly, leaving the LLM to interpret and handle them during PMP derivation.
2. **PMP Derivation (PMPDeriver):** This is the core intelligent module, where the LLM, guided by the `problem_spec` and a PMP derivation prompt (`pmp_derive.txt`), generates the complete indirect shooting formulation. This output includes the Hamiltonian, costate differential equations, optimal control law, all transversality conditions, and lists of shooting variables and equations. This stage incorporates a refinement loop with symbolic verification.
3. **SymPy Symbolic Verification (SymPyVerifier):** The derived costate ODEs are verified by executing them as a Python symbolic script, computing `-∂H/∂x` symbolically, and comparing it against the LLM's derivation. If verification fails, the error message is fed back to the PMPDeriver for up to three refinement rounds. For complex dynamics where SymPy might time out, verification is skipped.
4. **Code Generation (CodeGenerator):** The PMP derivation results and `problem_spec` are translated into C++ shooting code. This stage utilizes a fixed framework template complemented by LLM-generated modules.
5. **Compilation and Solving (SolverRunner):** The generated C++ code is compiled using g++ and linked against the cminpack library. The numerical solution is obtained using an adaptive ε-homotopy strategy with multiple random restarts and the `hybrd1` solver.

#### 3.2. Key Methodological Innovations

- **Unified Constraint Framework:** HELIOS unifies all constraints into the form `ψ(x, p1, p2, ...) = 0`, where `x` are state variables and `p` are free parameters embedded in the constraint. The system scans and classifies variables within each constraint into state variables, multipliers, and free parameters. Each interior-point constraint's multiplier `ν` becomes a shooting variable (Rule B), and each free parameter `p` also becomes a shooting variable (Rule B2). Each constraint `ψ = 0` forms a shooting equation, and each free parameter `p` generates a stationarity equation (`Σk νk ∂ψk/∂p = 0`). This framework allows for automatic handling of parameterized constraints like gravity assists without manual, per-constraint derivations.
- **Dynamics Model Adaptation (Four-Module Code Generation):** The CodeGenerator employs a modular architecture for C++ shooting code, divided into DYNAMICS, SWITCH, RESIDUAL, and SOLVE modules. For standard low-thrust problems (e.g., chemical propulsion), default template implementations are used for DYNAMICS and SWITCH, while RESIDUAL and SOLVE are LLM-generated. For non-standard dynamics (e.g., solar sail, J2 perturbation), the LLM generates custom code for all four modules, including the right-hand-side function for dynamics, the optimal control law, and propagation logic. This enables adaptability to varying state dimensions, control parameterizations, and Hamiltonian structures.
- **General Derivation Rule Set:** The LLM's prompt incorporates a set of general rules derived from PMP theory to guide the derivation process and mitigate common errors:
 - **Rule 0 (constraints are equations):** Ensures all stated constraints are included in the shooting system.
 - **Rule B (interior-point constraints):** Defines costate jumps and multiplier treatment for interior constraints.
 - **Rule B2 (constraint parameters):** Identifies and handles free parameters within constraints.
 - **Rule G1 (λ0 handling):** Specifies how the abnormal multiplier λ0 is treated in cost functionals and normalization.
 - **Rule G2 (control-direction verification):** Ensures correct maximization/minimization of H.
 - **Rule G3 (geometric derivatives):** Requires inclusion of ∂n/∂x terms when optimal control direction depends on state.
 - **Rule G4 (state dimension):** Excludes non-state variables from dynamics equations.
 - **Rules G5-G6:** Address issues like avoiding placeholders and requiring full Jacobian for J2 costate gradients.

#### 3.3. Numerical Stability Strategies

The system incorporates several strategies to enhance numerical stability:
- **Normalization:** Physical quantities are converted to normalized units (AU, year, AU/year) to keep variables in a manageable O(1)–O(10) range.
- **Time-fraction Parameterization:** Free time variables are represented as fractions `τ ∈` to avoid large magnitude discrepancies.
- **Target-Epoch Evaluation:** Target body states are evaluated at the actual arrival epoch, not fixed epochs.
- **Dimensionless Residuals:** Residual vector `fvec` uses raw normalized differences without arbitrary scaling.
- **Explicit Sign Convention:** The min or max principle convention for the Hamiltonian is explicitly declared to avoid sign errors.

#### 3.4. Experimental Design

The system was tested on 11 progressive scenarios, ranging from 8 to 48 variables. These scenarios covered a spectrum of constraint types (rendezvous, flyby, stay, gravity assist, inequality), dynamics models (two-body, J2 perturbation, solar sail), and optimization objectives (minimum fuel, minimum time, minimum initial mass).

#### 3.5. Evaluation Metrics

A five-dimension scoring system (total 1100 points) was used:
- **d1 Parsing (30 points):** Correct extraction of constraints, dynamics, and parameters.
- **d2 Derivation (20 points):** Correctness of Hamiltonian, costate ODEs, control law, and variable/equation counts.
- **d3 Compilation (20 points):** Successful compilation of C++ code.
- **d4 Convergence (20 points):** Shooting residual below 10^-5.
- **d5 Accuracy (10 points):** Deviation from reference solution.

#### 3.6. Multi-Model Baselines

Eight LLM backends (DeepSeek, Qwen, GLM, MiniMax) of different scales (large, medium, small) were evaluated using identical prompts, temperature, and pipeline configurations to assess the system's model-agnostic nature and the correlation between model scale and capability.

### 4. Main Findings and Results

#### 4.1. Multi-Model Comparison

The evaluation across 11 scenarios with 8 LLM backends yielded total scores ranging from 250 to 905 out of 1100.
- **Top Performers:** DeepSeek-V4-Pro achieved the highest total score (905/1100), demonstrating capability in complex scenarios like S07 (48-variable STAY) and S09 (inequality constraints). Qwen3.7-Max converged on the most scenarios (6/11) and performed well on S10 (Mars gravity assist) and S11 (solar sail). DeepSeek-V4-Flash achieved the highest compilation rate (11/11).
- **Model Scale Correlation:** A positive correlation was observed between model scale and derivation capability. Large models averaged 868 points, medium models 698, and the small model (GLM-4-9B, 9B) scored 250, failing to complete tasks, suggesting a minimum capability threshold.

#### 4.2. Token Consumption

Total token consumption (input + output) ranged from 465k to 836k across models. Input token consumption was consistent (∼530k) due to identical prompt templates. Differences in output tokens were primarily attributed to the number of refinement rounds.

#### 4.3. Derivation Quality Analysis

The agent demonstrated correct handling of several critical derivation points:
- **Transversality Conditions:** Correct sign of H-jump conditions.
- **λ0 Handling:** Correct inclusion of λ0 in spherical normalization for both min-time and min-fuel problems.
- **State Dimension:** Correct exclusion of mass state for solar-sail scenarios (Rule G4).
- **Constraint-Parameter Identification:** Correct identification of gravity assist parameters (δ, ϕ) as shooting variables (Rule B2).
- **Geometric Derivatives:** Correct inclusion of geometric derivative terms for solar sail control (Rule G3).
- **STAY Multiple Shooting:** Correct implementation of costate separation and H-jump terms for S07 (48 variables).
- **J2 Costate Gradient:** Correct derivation of the full 3x3 Jacobian for J2 acceleration.
- **Solar-Sail Control Law:** Correct use of the cubic equation for optimal cone angle.

#### 4.4. Compilation Repair Loop Effectiveness

The compilation repair loop, allowing up to 3 rounds of feedback to the LLM based on compiler error messages, significantly improved compilation success rates. For instance, DeepSeek-V4-Flash's success rate increased from 4 to 11 scenarios (+7), and MiniMax-M3's from 1 to 7 (+6). Repairs addressed code quality issues like duplicated variable definitions and function-signature mismatches without altering mathematical logic.

#### 4.5. Case Study: S07 Stay Constraints + t0 Sliding (48 Variables)

The end-to-end autonomous derivation was demonstrated on scenario S07, a complex problem involving 3 interior rendezvous, 3 stay arcs, and a free departure epoch (48 variables).
- **Constraint Parsing:** Correctly extracted 6 interior constraints and identified `t0_prior` and `total_dt`.
- **PMP Derivation:** The LLM correctly generated the Hamiltonian, switching function, 48-dimensional variable structure (including λ0, initial costates, 3 STAY multiplier groups, and t0 offset), and 48 shooting equations. It specifically recognized 6 arrival and 6 departure multipliers for each STAY constraint and correctly formulated the H-jump equation with both endpoint terms.
- **SymPy Verification:** The symbolic verification passed in 13 seconds.
- **Code Generation:** Produced 21,511 characters of C++ code, correctly implementing time conversions, state resetting for multiple shooting, propagating stay arcs with zero thrust, and evaluating H(t0).
- **Compilation and Solving:** The code compiled without errors. The solver converged on the first random restart, with a final residual of 6.18 × 10^-14 after 46 ε-homotopy steps. The final mass was 1522.46 kg (Δv = 8026.4 m/s), with terminal position error of 73.3 m and velocity error of 1.07 × 10^-5 m/s. All 48 residual components were below 10^-13. The trajectory visualization showed bang-bang control and mononically decreasing mass.

### 5. Significance and Potential Impact

HELIOS represents an advancement in the automation of indirect low-thrust trajectory optimization, leveraging large language models to address long-standing challenges in the field. Its significance lies in demonstrating the feasibility of an autonomous agent that can perform PMP symbolic derivation and C++ shooting code generation from a natural language problem description, a process traditionally requiring specialized human expertise and considerable manual effort.

The system's **constraint adaptability**, achieved through a unified framework for handling diverse constraints and automatically identifying free parameters (Rule B2), has the potential to substantially reduce the manual derivation burden for complex missions involving various boundary conditions and interior-point events. Similarly, its **dynamics adaptability**, facilitated by the four-module code generation architecture, allows for the efficient development of solutions for different spacecraft types (e.g., chemical propulsion, solar sails, perturbed dynamics) by simply modifying the problem description, rather than requiring extensive code rewriting. The **objective adaptability** further extends its utility by automatically handling both minimum-fuel and minimum-time problems through the same derivation framework.

The general derivation rule set embedded in the LLM's prompt, derived from PMP theory rather than specific problem instances, enhances the robustness and correctness of the autonomous derivations. The experimental results, particularly the successful resolution of complex, high-dimensional problems like the 48-variable STAY scenario, provide evidence for the system's capability to correctly interpret, derive, and implement optimal control problems. The multi-model evaluation also demonstrates the system's model-agnostic architecture and offers insights into the performance correlation with LLM scale, which can guide future backend selections.

Potential impacts include:
- **Reduced Development Time and Cost:** By automating the symbolic derivation and code generation, HELIOS could shorten the design cycle for low-thrust missions from days to minutes, allowing mission designers to explore a wider range of mission concepts and parameters more efficiently.
- **Increased Accessibility:** The natural language interface could lower the barrier to entry for researchers and engineers who are not specialized in optimal control theory or C++ programming, making indirect methods more accessible.
- **Improved Reliability:** Automating error-prone manual derivation steps, coupled with symbolic verification and compilation repair loops, could lead to more reliable and correct optimal control formulations.

While limitations such as numerical convergence for very high-dimensional problems and SymPy verification timeouts for extremely complex dynamics exist, the work lays a foundation for future advancements. Potential future directions, including physics-informed initial guess construction, global search algorithms, and more efficient verification strategies, suggest avenues for further enhancing the system's robustness and applicability. Overall, HELIOS demonstrates the transformative potential of LLMs in automating intricate scientific computing tasks within astrodynamics.
