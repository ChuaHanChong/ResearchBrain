# ReWOO: Decoupling Reasoning from Observations for Efficient Augmented Language Models

> [!summary] Summary
> ReWOO (Reasoning WithOut Observation) is a modular framework for tool-augmented language models that splits work into a Planner, a Worker and a Solver. The Planner writes the full multi-step plan before any tool runs, so observations never re-enter the reasoning loop. This cuts redundant prompt tokens. On HotpotQA it uses about 5x fewer tokens with 4% higher accuracy than ReAct.

## Problem

- Interleaved thought-action-observation systems like ReAct halt the LLM at every tool call, then resend the whole history through stateless APIs, causing heavy prompt redundancy and high token cost.
- Prompt tokens grow quadratically with the number of reasoning steps because context, exemplars and past observations are repeated at every call, hitting token limits and inflating expense.
- Prior fine-tuning for tool use either samples tools independently (Toolformer) or trains on full trajectories with observations, which is unproven on unseen tasks or tools and tangles parametric and tool components.

## Method

- ==Plan-Work-Solve paradigm==: the ==Planner== emits linked (Plan, #E) tuples in one pass, using ==placeholder evidence variables== that later steps can reference, without seeing any real tool output.
- ==Worker== and ==Solver== modules: the Worker calls the designated tools and fills each #E with real evidence, then the Solver reads all plan-evidence pairs and answers, prompted to use them with caution.
- Specialization: GPT-3.5 bootstraps about 2000 correct ==plan blueprints==, which are used to instruction-tune Alpaca 7B (LLaMA 7B) with ==LoRA== into a **Planner 7B** that does ==foresight reasoning==.

## Results

- Averaged over six public benchmarks with gpt-3.5-turbo, ReWOO cuts token usage by **64%** and gains **4.4%** absolute accuracy over ReAct. On HotpotQA it uses **1986** tokens versus **9795**, with accuracy **42.4** versus **40.8**.
- When all tools return 'No evidence found', ReAct loses **40.8** accuracy points on HotpotQA, while ReWOO loses **29.2**. On curated SOTUQA, ReWOO beats ReAct by **8%** accuracy with **43%** fewer tokens.
- Planner 7B and Alpaca 7B, plugged in as Planner, match the roughly **25x** larger GPT-3.5 on HotpotQA, TriviaQA and StrategyQA. Adding extraneous tools lowered accuracy, and **17 of 20** inspected failures involved tool misuse.

## Takeaways

> [!tip] Key Insights
> - Separating planning from observation removes the prompt redundancy of interleaved loops, and the savings grow with the number of steps. Foreseeable reasoning works when a task's structure can be predicted upfront.
> - Decoupling reasoning from tool responses makes the planner trainable on its own, so its ability can be distilled into small models and can transfer to unseen tools without end-to-end tool-in-the-loop training.
> - Caution: planning without observation fails when the environment is unknown, as in AlfWorld, where the planner must enumerate every possibility. Adding unneeded tools also degrades performance, so keep tool sets minimal.

## Detailed Report

### 1. Broader Research Landscape

The field of Large Language Models (LLMs) has seen rapid advancements, leading to the development of powerful models capable of complex reasoning and text generation. A significant trend is the augmentation of LLMs with external tools or plugins, giving rise to what are termed Augmented Language Models (ALMs). This paradigm allows LLMs to overcome inherent limitations, such as outdated knowledge (hallucinations) or inability to perform precise calculations, by enabling them to interact with the environment, retrieve up-to-date information, and execute actions.

Existing ALM systems, notably those inspired by the **ReAct (Reasoning and Acting)** framework, operate by interleaving LLM "thoughts" with "actions" (tool calls) and subsequent "observations" (tool responses). In this common **Thought-Action-Observation (TAO)** paradigm, the LLM generates a thought, proposes an action, pauses for the tool's response, and then incorporates that observation into its context for the next reasoning step. This iterative process allows LLMs to adapt their reasoning based on real-time feedback from tools, mimicking a human-like problem-solving approach. Prominent applications like Auto-GPT have showcased the potential of such autonomous ALMs for complex task execution.

However, the prevailing TAO paradigm introduces significant practical challenges, particularly concerning computational efficiency and cost. Each interaction with an external tool requires the LLM to be halted, and for stateless LLM APIs (like ChatGPT), the entire historical context, including the initial prompt, exemplars, and all previous reasoning traces and observations, must be re-fed into the model for subsequent token generation. This creates substantial prompt redundancy. As multi-step tasks require numerous tool interactions, the token consumption grows quadratically with the number of reasoning steps, leading to exorbitant computational costs and time expenses, posing a major hurdle for scalable and affordable ALM deployment.

Prior work has explored tool integration (e.g., Toolformer) and fine-tuning for reasoning (e.g., ReAct's fine-tuning attempts), but none have specifically tackled the fundamental issue of prompt redundancy and the resulting inefficiencies in interleaved ALM operations. ReWOO addresses this critical gap by proposing a novel, decoupled approach to reasoning and observation, aiming to make ALMs significantly more efficient and scalable for real-world use cases.

### 2. Key Objectives and Motivation

The primary objective of ReWOO is to **decouple the reasoning process of LLMs from external observations**, thereby significantly reducing token consumption and enhancing the computational efficiency and cost-effectiveness of Augmented Language Models (ALMs). The authors aim to challenge the prevailing interleaved Thought-Action-Observation (TAO) paradigm, which they identify as a major source of prompt redundancy and escalating costs.

The key motivations driving this research are:

- **Addressing Prompt Redundancy and High Costs:** Current ALMs, especially those based on stateless LLM APIs, repeatedly feed the entire conversation history (context, exemplars, past thoughts, actions, and observations) into the LLM for each new step. This quadratic growth in token consumption leads to "ridiculously high computation and time expenses," making multi-step ALM applications economically unfeasible for average users (e.g., an Auto-GPT request easily exceeding $1). ReWOO seeks to mitigate this by designing a paradigm that avoids such repeated prompt feeding.
- **Enhancing Computational Efficiency:** By reducing token usage, ReWOO directly aims to lower the computational load on LLMs, making ALMs faster and more resource-efficient. This is crucial for deploying ALMs at scale.
- **Improving Performance and Robustness:** Beyond efficiency, the authors hypothesize that a decoupled approach might also lead to better task performance and increased robustness. They aim to demonstrate that "foreseeable reasoning" – the ability of LLMs to plan steps without immediate observation feedback – can be effectively harnessed to achieve comparable or even superior accuracy to observation-dependent methods. They also investigate robustness under tool-failure scenarios.
- **Facilitating Parameter Efficiency and Scalability:** A long-term motivation is to enable the offloading of reasoning capabilities from large, expensive black-box LLMs (like GPT-3.5) into smaller, more specialized, and locally deployable models. By decoupling parametric reasoning modules from non-parametric tool calls, ReWOO aims to simplify instruction fine-tuning, paving the way for truly efficient and scalable ALM systems that are less reliant on massive general-purpose models.

In essence, ReWOO seeks to build a more intelligent and economical ALM architecture that can perform complex multi-step reasoning while being significantly more practical for widespread adoption.

### 3. Methodology and Approach

ReWOO (Reasoning WithOut Observation) proposes a novel, modular prompting paradigm for ALMs, fundamentally departing from the interleaved Thought-Action-Observation (TAO) approach. It compartmentalizes the ALM workflow into three distinct, decoupled modules: Planner, Worker, and Solver, operating in a sequential "Plan-Work-Solve" paradigm.

#### 3.1. The ReWOO Plan-Work-Solve Paradigm

The core idea is to leverage the LLM's "foreseeable reasoning" ability, allowing it to compose a comprehensive solution blueprint upfront, before any external tool interactions.

- **Planner:** This module, typically powered by an LLM (e.g., GPT-3.5), is responsible for breaking down the initial task into a series of interdependent steps. Critically, the Planner formulates a complete "blueprint" of plans *prior to receiving any tool responses*. Each plan is defined by a descriptive message and allocates a special token, `#E_s`, to store presumably correct evidence from a designated Worker for step `s`. The Planner can refer to `E_s` from previous steps in subsequent plan instructions, enabling complex multi-step reasoning where later steps depend on earlier observations. This module essentially performs the entire reasoning trajectory in one go.
- **Worker:** Once the Planner generates the blueprint, the Worker module takes over. It acts as the interface to the environment, invoking external tools (e.g., Wikipedia, Google, Calculator, specialized APIs) according to the instructions embedded in the Planner's blueprint. The Worker's role is to retrieve the necessary external knowledge or execute actions, populating the `#E_s` variables with real evidence or observations. The Worker module is non-parametric and handles the interaction with the external world.
- **Solver:** The final module, also typically an LLM, synthesizes all the generated plans and the collected evidence to formulate the ultimate solution to the original task. The Solver is prompted to use the provided plans and evidence "with caution," allowing it to exercise its inherent reasoning ability to validate or partially compensate for any shortcomings in the Planner or Worker steps.

#### 3.2. Prompt Redundancy Reduction

The fundamental difference from observation-dependent ALMs lies in how context and exemplars are handled. In ReAct-like systems (Figure 2a), the context, exemplars, and all previous TAO steps are repeatedly fed into the LLM at each iteration. This leads to a quadratic increase in input tokens with the number of reasoning steps (`k`), making it computationally expensive.

In contrast, ReWOO (Figure 2b) avoids this interleaving and repetition. The Planner receives the initial context, exemplars, and question once to generate the full plan. The Worker operates independently to fetch evidence. Finally, the Solver receives the context, question, and the *complete set* of plans and collected evidence. This significantly linearizes the token consumption. The authors provide mathematical formulations (Equations 1 and 2 in the paper) to illustrate this difference:

- **ReAct-like Token Cost:** `k * (Θ(Q) + Θ(C) + Θ(S)) + Sum_{j=1 to k-1} (k-j) * Θ(T_j + A_j + O_j)` (where Θ is token count, Q=question, C=context, S=exemplars, T=thought, A=action, O=observation). This clearly shows the `k` factor multiplying context and exemplars, and the quadratic `(k-j)` factor for TAOs.
- **ReWOO Token Cost:** `Θ(C_planner + S + Q) + Θ(C_solver + Q + Sum_{j=1 to k} (P_j + E_j))` (where P=plan, E=evidence). This demonstrates that context and exemplars are fed only once to the Planner and once (as C_solver) to the Solver, leading to a much smaller, approximately linear, growth in token usage with task complexity.

This decoupled structure eliminates the need to repeatedly prompt the LLM with redundant historical context, leading to substantial savings in token usage, computation, and cost.

#### 3.3. Parameter Efficiency by Specialization

ReWOO's decoupled nature allows for an innovative approach to parameter efficiency. By separating reasoning (Planner/Solver) from tool calls (Worker), the generic "foreseeable reasoning" ability can be optimized independently. The authors demonstrate a pipeline to offload this ability from a large, general LLM (GPT-3.5) into a smaller, more specialized model (LLaMa 7B).

The process involves:
1. **Data Generation:** Using `text-davinci-003` (a GPT-3.5 variant) to infer 4000 (Plan, #E) blueprints on mixed training data (HotpotQA and TriviaQA).
2. **Bootstrapping and Filtering:** Sampling blueprints that lead to correct answers, yielding approximately 2000 high-quality Planner instruction data points.
3. **Instruction Fine-tuning (Alpaca):** A pre-trained LLaMa 7B model is instruction fine-tuned on the 52k self-instruct dataset, resulting in "Alpaca 7B," which approximates the general abilities of `text-davinci-003`.
4. **Specialization (Planner 7B):** Alpaca 7B is *further* fine-tuned on the 2000 Planner instruction data, creating "Planner 7B," a model specifically specialized in foreseeable reasoning.

This approach demonstrates the potential to distill complex reasoning capabilities from massive LLMs into much smaller models, making ALM deployment more lightweight, scalable, and accessible without compromising performance.

### 4. Main Findings and Results

The comprehensive evaluation of ReWOO across six public NLP benchmarks and a curated dataset revealed several significant findings regarding its performance, efficiency, and robustness.

#### 4.1. Comparison of Prompting Paradigms

- **Superior Efficiency:** ReWOO consistently demonstrated significant token efficiency over ReAct, the prevailing observation-dependent ALM paradigm. On average across six public benchmarks, ReWOO reduced token usage by **64%**. Specifically, on HotpotQA, a multi-step reasoning benchmark, ReWOO achieved a **5x token efficiency** improvement (1986.2 tokens vs. 9795.1 tokens for ReAct). This translates directly into substantial cost savings.
- **Improved or Comparable Accuracy:** Despite the dramatic reduction in token usage, ReWOO not only matched but often **outperformed ReAct in accuracy across all tasks**. It achieved a **4% absolute accuracy improvement on HotpotQA** and an average absolute accuracy gain of **4.4%** across the public benchmarks.
- **ALMs vs. Non-ALMs:** On "curated" tasks like SOTUQA (State of the Union Address QA), which require up-to-date external knowledge, both ReWOO and ReAct (ALMs) clearly outperformed non-ALM baselines (Direct Prompting and Chain-of-Thought, CoT). ReWOO, in particular, excelled on SOTUQA, achieving **70.2% accuracy** against ReAct's 64.8%, while consuming 43% fewer tokens. This highlights the value of external tools for real-world, dynamic knowledge tasks.
- **Prompt Decomposition Analysis:** An additional observation from token decomposition (Appendix A.1) showed that ReAct consumes significantly more tokens in exemplars due to repetitive prompting at each step, including lengthy observations, whereas ReWOO avoids this redundancy.

#### 4.2. Robustness and Tool Impact

- **Robustness to Tool Failure:** ReWOO exhibited greater robustness when external tools malfunctioned and returned errors (e.g., "No evidence found"). In a simulated tool-failure scenario on HotpotQA, ReAct's performance significantly degraded, while ReWOO was "less compromised at a smaller cost." This suggests that ReWOO's pre-planned reasoning trajectory is less susceptible to cascading failures caused by unexpected tool responses.
- **Impact of Extraneous Tools:** A crucial ablation study revealed that incrementally adding "extraneous" (unnecessary) tools in-context can **compromise ALM performance**. While a powerful tool like Google might initially boost accuracy, adding too many tools generally led to a performance drop for both ReWOO and ReAct. Qualitative analysis showed that this degradation was often due to tool misuse (e.g., using Yelp to search for a celebrity), indicating that unnecessary tools introduce noise and confusion for the LLM.
- **RLHF Effects:** Replacing `gpt-3.5-turbo` with `text-davinci-003` (which uses conversation-aligning RLHF) for LLM-based tools in HotpotQA surprisingly showed that `text-davinci-003` performed better with fewer tokens. This implied that conversation-aligned RLHF might slightly harm the commonsense reasoning ability of ALMs in some contexts.

#### 4.3. Fine-tuning and Specialization of LLMs

The most impactful finding in terms of long-term scalability was the successful demonstration of "Specialization":

- **Offloading Reasoning:** The authors successfully fine-tuned a **7B LLaMa model (Planner 7B)** to specialize in foreseeable reasoning. This smaller model, when plugged into the Planner module of ReWOO, was able to **match the performance of the 25x larger GPT-3.5** on HotpotQA, TriviaQA, and StrategyQA.
- **Effectiveness of Specialization:** The general accuracy gain observed from Alpaca 7B (a general-purpose LLaMa instruction-tuned model) to Planner 7B (Alpaca further specialized for planning) underscored the effectiveness of the specialization process.
- **Generalizability of Specialized Models:** Despite being trained on blueprints involving only Wikipedia and LLM tools, Planner 7B showed an increasing capability to reason with Google and Calculator tools when paired with in-context descriptions. This hints at the potential for specialized small models to generalize to unseen tools.

These results highlight ReWOO's significant potential for enabling lightweight, parameter-efficient, and scalable ALM deployment, moving away from exclusive reliance on massive, general-purpose LLMs.

### 5. Significance and Potential Impact

The ReWOO framework presents a substantial leap forward in the design and deployment of Augmented Language Models (ALMs), offering significant implications for both research and practical applications.

**1. Revolutionizing ALM Efficiency and Cost-Effectiveness:**
The most immediate and impactful contribution is ReWOO's ability to drastically reduce token consumption and, consequently, the computational cost of ALMs. By decoupling reasoning from observations, ReWOO mitigates the quadratic growth in prompt tokens inherent in interleaved approaches like ReAct. This 5x token efficiency and 64% average token reduction mean that complex, multi-step tasks that were previously prohibitively expensive can now become economically feasible for wider adoption. This directly addresses one of the major barriers to the scalability and widespread commercial deployment of ALM systems, particularly those relying on pay-per-token black-box LLM APIs.

**2. Advancing "Foreseeable Reasoning":**
ReWOO successfully harnesses and validates the concept of "foreseeable reasoning" in LLMs – the ability to anticipate future steps and plan an entire trajectory without immediate, real-time feedback from tool observations. This demonstrates a more sophisticated form of reasoning beyond simple reactive decision-making, opening new avenues for exploring LLM cognitive capabilities and how they can be leveraged for complex problem-solving.

**3. Enabling Parameter-Efficient and Scalable ALMs:**
The demonstration that specialized smaller language models (like Planner 7B) can effectively offload the foreseeable reasoning ability from much larger LLMs (e.g., GPT-3.5) is groundbreaking. This opens the door for building highly efficient ALMs where the core reasoning component is a compact, locally deployable model, while large, expensive models are only used for specific, high-level guidance or fine-tuning data generation. This "distillation" approach significantly reduces the memory footprint and computational requirements, making ALMs more accessible and deployable on a wider range of hardware, moving towards truly scalable AGI architectures.

**4. Enhanced Robustness and Tool Management:**
ReWOO's improved robustness to tool failures is a critical practical advantage. In real-world scenarios, tools can malfunction or return irrelevant information. ReWOO's pre-planned approach makes it less susceptible to infinite loops or cascading errors caused by unexpected observations, leading to more reliable ALM behavior. Furthermore, the finding that extraneous tools can degrade performance highlights the importance of intelligent tool management and selection, encouraging future research into more sophisticated tool representation and utilization strategies.

**5. Foundation for Modular and Graph-Based ALM Architectures:**
The modular "Plan-Work-Solve" paradigm provides a robust foundation for future ALM system design. It suggests that ALMs can evolve beyond simple linear thought processes into more complex, directed acyclic graph (DAG) structures where different specialized LLMs and tools communicate and cooperate. This vision aligns with emerging trends in AI system design (e.g., LangChain) and encourages research into:
 - **Modular LLM Fine-tuning:** Training specialized sub-models for distinct roles (Planner, Solver).
 - **Tool Representation Learning:** Developing methods for LLMs to understand and select tools more effectively.
 - **Graph Optimization:** Applying graph theory and concurrency algorithms to optimize the execution flow within complex ALM systems.

In summary, ReWOO significantly advances the state-of-the-art in ALMs by providing a more efficient, cost-effective, robust, and scalable architecture. Its insights into "foreseeable reasoning" and parameter offloading are pivotal for the development of the next generation of intelligent, autonomous, and widely deployable AI systems.
