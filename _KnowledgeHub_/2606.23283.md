# Towards Root Memories: Benchmarking and Enhancing Implicit Logical Memory Retrieval for Personalized LLMs

> [!summary] Summary
> RootMem tackles implicit logical memory retrieval for personalized LLMs, where logically critical memories sit far from the query semantically. It distills long-term user histories offline into structured root memory units, each pairing execution rules with personalized logical evidence, then an LLM router activates relevant units to augment semantic retrieval. On the new IMLogic benchmark it reaches 55.23% accuracy, 27.23% relatively above the strongest baseline.

## Problem

- Existing memory retrieval ranks by semantic similarity alone, so memories linked to a query by constraints, motives, or conditions are missed despite being decision-critical.
- Prior benchmarks test locating explicit information inside noise or reasoning over implicit persona clues, never modeling the conflict between semantic similarity and logical relevance.
- Graph and hybrid memory systems reorganize raw entries but still match on surface overlap; the strongest existing memory agent reaches only 43.50% on such queries.

## Method

- IMLogic benchmark: an LLM cognitive miner extracts semantic/logical memory pairs from HaluMem dialogues, then a Generator-Judger-Refiner loop builds 2,216 QA pairs with preference, fabrication, and generic trap options.
- Root memory unit: structured pair of execution rules (activation conditions plus response-guiding logic) and personalized logical evidence, built offline by an LLM extractor that creates, enriches, and merges units per memory batch.
- Root memory router: an LLM boolean gate tests each unit's execution rules against the query, concatenating activated rule-evidence blocks with standard semantic retrieval into one logic-guided context.

## Results

- Memory-level MCQ: RootMem reaches 55.23% versus 43.41% for the best hybrid reranking baseline (+27.23% relative), 40.93% for the best embedding retriever, and 25.18% for cluster-tree graph retrieval.
- Plugged into MemOS, LightMem, and EverMemOS, every system clears 50% accuracy, averaging +26.36% relative; generic errors fall 20.06% and preference errors 14.04% on average.
- Ablations drop accuracy 8.51% without the router, 8.40% without execution rules, 3.54% without evidence, and to 33.98% semantic-only; total latency 654.53s versus 6143.10s for entity-linked graphs.

## Takeaways

> [!tip] Key Insights
> - Similarity-based retrieval has a structural blind spot: embedding distance cannot express constraint, motive, or condition links that actually decide the correct answer.
> - Storing how facts should constrain responses, not only the facts themselves, is the transferable idea; summaries and user profiles keep what without how.
> - Pushing logic consolidation offline and keeping inference to cheap boolean routing captures most of the gain without graph-scale construction cost.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

The development of personalized Large Language Models (LLMs) is a significant area within natural language processing, aiming to create AI systems that can tailor responses to individual user histories, preferences, and contexts. Memory systems are foundational to achieving this personalization, as they enable LLMs to accumulate and retrieve relevant user data over time.

Existing memory retrieval methods predominantly rely on semantic similarity to identify relevant information. This approach, while effective for surface-level context matching, exhibits limitations when dealing with implicit logical relationships. Logically critical memories may have limited semantic overlap with a user's current query, leading to their omission by similarity-based retrievers. Consequently, LLMs might generate responses that address superficial intent but fail to incorporate crucial underlying constraints, motivations, or conditions, potentially leading to inaccurate or inappropriate personalized interactions.

Current benchmarks for evaluating LLM memory systems primarily focus on aspects such as explicit preference adherence, long-context retention, persona extraction, or addressing memory hallucinations. They often fall short in explicitly modeling the divergence and potential conflict between semantic similarity and logical relevance. This leaves a gap in evaluating a system's ability to retrieve memories that are logically essential but semantically distant, or semantically similar but logically irrelevant. This research addresses this gap by proposing a new benchmark and a complementary retrieval framework.

### 2. Key Objectives and Motivation

The primary objective of this research is to address the limitations of existing memory systems for personalized LLMs, particularly their struggle with implicit logical memory retrieval. The motivation stems from several identified challenges:

1. **Over-reliance on Semantic Similarity:** Current retrieval methods in personalized LLMs predominantly depend on semantic similarity. This approach can lead to failures in recalling logically critical memories that have limited semantic overlap with a user's query. For instance, a memory about a user's pet cat might be logically crucial for advising on open-top fish tanks (due to safety concerns), even if "cat" and "fish tank" have low semantic similarity on their own. Conversely, semantically similar but logically irrelevant memories can mislead the LLM.
2. **Inadequacy of Existing Benchmarks:** Current memory benchmarks are insufficient for robustly evaluating implicit logical reasoning capabilities in retrieval. They often overlook scenarios where semantic similarity and logical relevance conflict, and do not adequately cover complex settings like long conversations with multiple memory entries containing subtle logical dependencies. This makes it difficult to assess how well LLMs can identify and utilize underlying constraints or unstated demands for personalized responses.
3. **Need for a Complementary Memory Representation:** To overcome the "semantic gap" and prevent LLMs from generating responses based solely on superficial intent, there is a recognized need for a memory representation that preserves reusable, decision-relevant logic distilled from long-term user histories. Such a representation would complement semantic matching by explicitly capturing the personalized logic that guides future response decisions.

To address these motivations, the paper sets forth three specific objectives:
- To construct a high-quality benchmark, IMLogic, specifically designed for evaluating implicit logical memory retrieval in long-dialogue scenarios, explicitly modeling the conflict between semantic and logical relevance.
- To introduce "root memory," a structured representation that distills and preserves reusable personalized decision logic from user histories.
- To propose RootMem, a plug-and-play framework that constructs and utilizes these root memories, enhancing conventional semantic retrieval with logically relevant information for more accurate and personalized LLM responses.

### 3. Methodology and Approach

This research introduces a novel benchmark, IMLogic, and a new retrieval framework, RootMem.

#### 3.1. The IMLogic Benchmark

IMLogic is designed to evaluate implicit logical memory retrieval by explicitly modeling conflicts between semantic and logical relevance.

**Problem Formulation:** The task involves a user query `q` and a memory bank `M`. The goal is to retrieve a *logical memory* (`m_l`) that is indispensable for a sound personalized response, even if it has negligible semantic similarity with `q`. Concurrently, a *semantic memory* (`m_s`) might align with `q` semantically but be insufficient or misleading on its own. The challenge is to prioritize `m_l` over `m_s` and integrate its logic.

**IMLogic Overview:**
- **Context Construction:** Two evaluation modes are supported: *Memory-level*, using pre-annotated memory entries, and *Conversation-level*, using raw long conversation histories.
- **Query Construction:** Three types of queries simulate real-world scenarios: *Recommendation*, *Advice*, and *Chatting*.
- **Response Construction:** For each query, a *Correct* response is provided, along with three error-inducing options:
 - **Preference Trap:** Based on `m_s` only, panders to user's explicit viewpoint, ignoring `m_l`.
 - **Fabrication Trap:** Based on `m_s` only, justifies user's viewpoint by fabricating details.
 - **Generic Trap:** Ignores both `m_s` and `m_l`, provides a standard, non-personalized response.
 This structure supports both multiple-choice and open-ended evaluations.

**Benchmark Construction Pipeline (3 phases):**
1. **Data Collection and Memory Tagging:** Reuses long conversations and memory entries from HaluMem (Chen et al., 2025) for authenticity. An LLM classifies memories into nine categories (e.g., personal background, assets, past experiences).
2. **Implicit Logical Memory Pair Mining:** Gemini-3-Pro (DeepMind, 2025) acts as a "cognitive miner." Guided by a meta-prompt, it autonomously identifies logical memory pairs (`m_s`, `m_l`) from user memories, where `m_s` and `m_l` have an implicit logical relationship (e.g., `m_l` imposes a constraint on `m_s`). A filtering mechanism prevents repetitive memories. The logical associations are classified into seven categories, including "State Constraint," "Motivational Orientation," and "Identity Shift."
3. **High-Quality QA Pair Construction:** A collaborative "Generator-Judger-Refiner" pipeline creates challenging QA pairs.
 - **Generator:** Creates a query `q` that semantically overlaps with `m_s` but requires `m_l` for a correct answer, and generates the four response options.
 - **Judger:** Reviews the QA pair based on five dimensions: logical rationality, semantic stealthiness (no `m_l` keywords in query), tone naturalness, option unbiasedness, and logical superiority of the correct answer.
 - **Refiner:** Rewrites the QA pair based on Judger feedback. This loop iterates until quality standards are met or the sample is discarded.

**Quality Control:** Includes manual verification of logical memory pairs by expert annotators, LLM-based QA refinement, and a final human review for appropriateness, relevance, and personalized response quality.

#### 3.2. The RootMem Framework

RootMem is a plug-and-play framework designed to extract and utilize root memories for implicit logical memory retrieval, complementing semantic retrieval. It operates in two stages:

1. **Root Memory Construction:**
 - **Root Memory Units:** Raw historical memories are distilled into structured `root memory units` (`U_i = ⟨R_i, E_i⟩`). Each unit consists of `Execution Rules` (`R_i`) that specify activation conditions and response-guiding logic, and `Personalized Logical Evidence` (`E_i`) that provides user-specific facts grounding these rules.
 - **Construction Process:** An LLM-based `extractor` (`Φ_C`) periodically aggregates new memory entries and updates existing root memory units. It enriches evidence, refines rules, creates new units for emerging logic, or merges overlapping units. The number of units is dynamically determined but capped.

2. **Root Memory Routing:**
 - **Activation:** During online inference, an LLM-based `Root Memory Router` (`Φ_R`) evaluates the `Execution Rules` (`R_i`) of each root memory unit against the current user query `q` to identify logically relevant units (`U_act`).
 - **Context Augmentation:** Activated root memory units, represented as `[R_i, E_i]` blocks, are concatenated with semantic memory entries (`M_sem`) retrieved by conventional semantic methods. This forms a `logic-guided context` (`C`) for the LLM's response generation. This process injects decision-guiding logic and supporting evidence, providing a more reliable basis for personalized responses.

### 4. Main Findings and Results

The experiments were conducted on the IMLogic benchmark, evaluating various retrieval methods and memory systems.

#### 4.1. Memory-Level Performance on Implicit Logical Memory Retrieval

- **Shared Challenge for Existing Paradigms:** Lexical, semantic, graph-based, and hybrid retrieval methods exhibited limited accuracy on implicit logical memory retrieval. The strongest baseline, "Query Reconstruction + Reranker," achieved 43.41% accuracy. This indicates that relying on surface-level similarity or memory restructuring alone is insufficient for recovering logically critical but semantically distant memories.
- **RootMem's Superior Performance:** RootMem achieved an accuracy of 55.23%, representing a 27.23% relative improvement over the strongest baseline. This suggests that explicitly modeling and routing personalized decision logic is effective for this task.
- **Error Analysis:** Existing methods largely failed due to "Preference Trap" and "Generic Trap" errors (36.28% and 20.17% respectively for the best baseline). RootMem reduced these errors significantly, with Preference errors at 28.84% and Generic errors at 15.79%. The consistently low "Fabrication Trap" rate across all methods indicated that failures primarily stemmed from retrieval rather than answer selection, confirming the importance of logical memory recovery.
- **Practical Overhead:** RootMem exhibited a favorable performance-overhead balance. Its offline consolidation cost (510.32s) and online retrieval cost (144.21s) were lower than the total costs of most graph-based and hybrid methods, making it a viable solution.

#### 4.2. Conversation-Level Performance on Implicit Logical Memory Retrieval

- **Persistent Challenge:** When memory systems processed raw dialogue streams, accuracy remained limited, ranging from approximately 30% to 43% for baselines. Graph-based methods did not consistently outperform semantic ones, reinforcing that complex memory organization alone does not guarantee implicit logical information recovery.
- **Consistent Gains with RootMem Integration:** RootMem was integrated as a compensatory component into the three best-performing baselines (MemOS, LightMem, EverMemOS). It consistently improved their accuracy, yielding an average relative gain of 26.36% and pushing all augmented systems above 50% accuracy.
- **Targeted Error Mitigation:** RootMem reduced Generic errors by an average of 20.06% and Preference errors by an average of 14.04% across augmented systems. The larger reduction in Generic errors suggests its effectiveness in providing missing logical grounding.

#### 4.3. Ablation Study

Ablation experiments confirmed the contribution of each RootMem component:
- Removing the `Root Memory Router` resulted in the largest performance degradation (50.90% accuracy, -8.51% drop from full RootMem), indicating its criticality in activating relevant units and preventing interference.
- Removing `Execution Rules` (50.95% accuracy, -8.40% drop) showed that explicit guidance on how logic should affect responses is important, even if evidence is available.
- Removing `Personalized Logical Evidence` (53.34% accuracy, -3.54% drop) suggested that user-specific factual support is necessary to ground high-level guidance.
- "Semantic Only" retrieval performed substantially worse (33.98% accuracy, -62.54% drop), highlighting that semantic retrieval cannot substitute for root memories' logical information.

#### 4.4. Performance on Open-Ended QA and Generalization Across LLM Backbones

- **Open-Ended QA Performance:** On open-ended generative QA, RootMem significantly improved baseline memory systems (e.g., LightMem + RootMem achieved 26.17% accuracy, a 57.56% relative improvement over LightMem's 16.61%). This indicates that RootMem's benefits extend to enabling more effective utilization of logical information during direct response generation.
- **Generalization Across LLM Backbones:** RootMem demonstrated consistent and substantial improvements across different LLM backbones (GPT-4o-mini, Qwen3-30B-A3B-Instruct-2507, GLM-4.6) in the conversation-level MCQ setting. For instance, LightMem combined with GLM-4.6 and RootMem achieved a 71.52% relative gain. This suggests that RootMem's effectiveness is not dependent on specific LLM architectures or pretraining distributions.

### 5. Significance and Potential Impact

This research contributes to the field of personalized LLMs by addressing a critical limitation in existing memory retrieval systems and evaluation methodologies.

The introduction of **IMLogic** is significant as it provides the first high-quality benchmark specifically targeting implicit logical memory retrieval in long-dialogue scenarios. By explicitly modeling the conflict between semantic similarity and logical relevance, IMLogic offers a more rigorous and realistic evaluation of LLM memory systems. This allows researchers to identify and analyze failures related to missing logical connections, which were previously overlooked by benchmarks primarily focused on explicit memory.

The proposed concept of **root memory** and the **RootMem framework** offer a novel approach to overcome the limitations of purely semantic retrieval. By distilling reusable personalized decision logic into structured units and actively routing them during inference, RootMem provides a mechanism to compensate for the "semantic gap." This enables LLMs to access and utilize logically essential information that might be semantically distant from the current query, leading to more accurate, safe, and contextually appropriate personalized responses.

The experimental results demonstrate that RootMem consistently and substantially improves the performance of various memory systems across different evaluation settings and LLM backbones. This indicates its broad applicability as a plug-and-play component. The ability to enhance logical grounding in LLM responses has implications for a range of user-centric applications, potentially leading to more trustworthy and effective personalized agents in areas such as recommendations, advice-giving, and general conversational AI.

While the paper acknowledges limitations such as its focus on text-based scenarios, the efficiency of offline construction, and the scope of query types, the fundamental contributions of a specialized benchmark and a logic-enhancing retrieval framework lay groundwork for future advancements in intelligent personalized systems.
