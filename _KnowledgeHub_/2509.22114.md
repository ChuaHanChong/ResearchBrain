# SK2Decompile: LLM-based Two-Phase Binary Decompilation from Skeleton to Skin

> [!summary] Summary
> SK2 Decompile, developed by a research team including Hanzhuo Tan and Yuqun Zhang, introduces a two-phase Large Language Model-based binary decompiler that overcomes the traditional trade-off between functional correctness and code readability. It achieves approximately 70% re-executability on HumanEval and 60% on MBPP, while also significantly improving structural and semantic readability compared to existing LLM-based decompilers.

## Problem

- Traditional decompilers (e.g., Ghidra, IDA Pro) generate low-level, obfuscated pseudocode lacking meaningful identifiers, which hinders human comprehension and further analysis.
- Existing LLM-based decompilers often struggle with functional correctness, frequently failing to produce re-compilable and executable code, limiting their practical utility.
- The complexity of simultaneously inferring intricate control-flow, data structures, and meaningful identifiers in a single decompilation process leads to inherent trade-offs between output correctness and readability.

## Method

- A two-phase LLM-based approach decomposes binary decompilation into '==Structure Recovery==' (reconstructing the program skeleton with generic identifiers) and 'Identifier Naming' (assigning meaningful names to the recovered structure).
- A novel Intermediate Representation (IR) is introduced as 'obfuscated source code,' which retains structural and functional information while abstracting identifier semantics, acting as a bridge between low-level pseudocode and high-level source.
- Reinforcement learning (RL) is applied to both phases: Structure Recovery uses compiler feedback for functional correctness rewards, and Identifier Naming uses semantic similarity rewards for generating human-centric, meaningful names.

## Results

- SK2 Decompile achieves unprecedented re-executability rates for LLM-based decompilers, reaching approximately **70%** on HumanEval and **60%** on MBPP.
- It surpasses commercial state-of-the-art GPT-5-mini by an average of **21.6%** on HumanEval and **26.3%** on MBPP in re-executability.
- The method demonstrates superior structural readability (e.g., **18.4%** R2I gain over Idioms on ExeBench) and high-quality identifier naming (4.24/5 on HumanEval via GPT-Judge), indicating both functionally correct and human-readable output.

## Takeaways

> [!tip] Key Insights
> - Decomposing the complex decompilation task into separate structural recovery and identifier naming phases enables LLMs to achieve significantly higher functional correctness and readability.
> - An intermediate representation designed as 'obfuscated source code' effectively preserves program structure while abstracting identifier specifics, serving as an optimal information bottleneck for multi-phase translation.
> - Phase-specific reinforcement learning rewards, such as compiler feedback for structural integrity and semantic similarity for identifier quality, are crucial for fine-tuning LLMs to meet distinct, high-level objectives in code generation.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

Binary decompilation, the process of converting compiled machine code back into high-level source code, has long been a cornerstone in software security (e.g., malware analysis, vulnerability discovery) and program understanding. Traditionally, tools like Ghidra and IDA Pro have been the industry standard, excelling in functional correctness by accurately recovering control flow and data structures. However, a persistent challenge with these tools is the generation of obfuscated, difficult-to-read pseudocode, often lacking original meaningful identifiers and high-level abstractions, which hinders human comprehension and further analysis.

The advent of Large Language Models (LLMs) has opened new avenues for code-related tasks, including decompilation. Recent research has explored leveraging LLMs to refine the low-level pseudocode produced by traditional decompilers into more human-readable source code. Early efforts, such as LLM4Decompile (Tan et al., 2024), demonstrated the potential of LLMs to translate pseudocode into higher-level representations. Subsequent studies, like Idioms (Dramko et al., 2025) and D-LIFT (Zou et al., 2025), focused on incorporating richer contextual information or reinforcement learning (RL) with novel reward functions to improve code accuracy and readability.

Despite these advancements, a fundamental trade-off has plagued LLM-based decompilers: while they generally produce more readable output than traditional tools, they often struggle to preserve the original program's functional correctness. Many existing LLM-based methods frequently fail to generate code that can be re-compiled and executed successfully, limiting their practical utility. This limitation stems from the inherent complexity of simultaneously inferring intricate control-flow structures, data layouts, and meaningful identifiers from low-level binary representations in a single, monolithic process.

SK2 Decompile directly addresses this core challenge by proposing a novel two-phase approach that explicitly decomposes the decompilation task. Instead of attempting a single-shot translation, it separates the recovery of program structure ("skeleton") from the assignment of meaningful identifiers ("skin"). This decomposition allows for independent optimization of functional correctness and readability, moving beyond the traditional trade-off. By achieving re-executability rates of approximately 70% on HumanEval and 60% on MBPP – a first for LLM-based decompilers – SK2 Decompile significantly pushes the boundaries of what is achievable, setting a new state of the art in generating *both* functionally correct and human-readable code from binaries. This work not only enhances the practical applicability of LLM-based decompilation but also introduces a methodological paradigm that could influence future research in complex code generation and translation tasks.

### 2. Key Objectives and Motivation

The primary objective of SK2 Decompile is to develop a novel LLM-based binary decompilation technique that effectively overcomes the long-standing trade-off between functional correctness and code readability, a limitation prevalent in both traditional and existing LLM-based decompilers. The authors are specifically motivated by the observation that simultaneously inferring complex control-flow structures, data layouts, and meaningful identifiers in a single decompilation phase is an intractable problem, leading to compromises in output quality.

To achieve this overarching goal, the key objectives are:

1. **Decompose the Decompilation Task:** To break down the complex binary decompilation problem into two more manageable, sequential phases: Structure Recovery (deriving the "skeleton") and Identifier Naming (deriving the "skin"). This decomposition aims to allow for independent and aggregated advancements in functional correctness and readability.
2. **Design a Novel Intermediate Representation (IR):** To create an IR that serves as an effective bridge between low-level pseudocode and high-level source code. This IR, conceptualized as "obfuscated source code" with generic placeholders, must preserve maximal structural and functional information while abstracting away identifier semantics, adhering to the Information Bottleneck principle.
3. **Enhance Structure Recovery with Compiler Feedback:** To train a model for the Structure Recovery phase using reinforcement learning, where rewards are directly tied to the compilability and structural integrity of the generated IR, thereby maximizing functional correctness.
4. **Improve Identifier Naming with Semantic Similarity:** To train a separate model for the Identifier Naming phase using reinforcement learning, employing a reward function based on the semantic similarity between predicted and reference identifiers. This approach aims to generate human-centric, meaningful names, enhancing readability beyond exact lexical matching.
5. **Achieve State-of-the-Art Performance:** To demonstrate that the two-phase SK2 Decompile framework, with its specialized IR and reinforcement learning objectives, can significantly outperform existing state-of-the-art LLM-based decompilers in terms of re-executability (functional correctness) and various readability metrics (R2I, GPT-Judge).

Ultimately, the motivation is to deliver a decompiler that not only understands the "what" (program logic) but also the "who" and "how" (meaningful names and types) of a binary, making the output genuinely useful for human analysts in real-world scenarios like security analysis and software maintenance.

### 3. Methodology and Approach

SK2 Decompile employs a novel two-phase LLM-based approach, decomposing binary decompilation into "Structure Recovery" and "Identifier Naming," connected by a custom Intermediate Representation (IR).

#### 3.1. Two-Phase Decompilation Process

The core idea is to break down the complex probabilistic mapping $P(s|u)$ (source code `s` given pseudocode `u`) into two simpler steps: $P(s|u) \approx \sum_i P(s|i) \cdot P(i|u)$.
- **Phase 1: Structure Recovery (P(i|u))**: This phase focuses on transforming low-level pseudocode (`u`) into an Intermediate Representation (`i`). It aims to reconstruct the program's "skeleton"—its fundamental control flow (loops, conditionals) and data structures—while using generic placeholders for all identifiers. For instance, `while(1)` with `goto LABEL_2` in pseudocode might become a structured `while` loop, and pointer arithmetic like `*(uint8_t *)(v5 + 1)` translates into structured access like `var3->field2->field3`.
- **Phase 2: Identifier Naming (P(s|i))**: This phase takes the recovered, structured IR (`i`) and infers meaningful names for functions, types, fields, and variables to generate the final, human-readable source code (`s`). A crucial simplification is made here: `P(s|i, u)` is approximated as `P(s|i)` (Markov assumption), implying that once the clean IR is generated, the original pseudocode offers little additional information for naming. This allows the naming task to be highly focused.

#### 3.2. Intermediate Representation (IR)

The design of the IR is critical. It must be simple enough to be reliably recovered from pseudocode (compression) yet rich enough to enable accurate source code reconstruction (relevance). This is framed as an Information Bottleneck (IB) optimization problem, minimizing `I(u; i)` (mutual information between pseudocode and IR) while maximizing `I(i; s)` (mutual information between IR and source code).
The chosen IR is **obfuscated source code**: the original source code with all identifiers (variable, function, type names) replaced by generic placeholders (e.g., `func1`, `type1`, `var1`). This naturally satisfies the IB objectives by retaining structural semantics while maximally compressing identifier-specific semantics.

#### 3.3. IR Generation Algorithm

Algorithm 1 outlines the process:
1. **Extract Preserved Names:** Analyze the pseudocode to identify and preserve standard names (e.g., `int`, `memcpy`).
2. **Parse Source Code:** Create an Abstract Syntax Tree (AST) from the original source code.
3. **Traverse and Rename:** Recursively traverse the AST. For each identifier not in the preserved list, generate a new generic name (e.g., `func1`, `var2`) and map the original name to this new name.
4. **Apply Replacements:** Sort the generated replacement entries (start offset, end offset, new name) in descending order of start position to correctly apply substitutions to the source code, producing the obfuscated IR.

#### 3.4. Enhancement with Reinforcement Learning (RL)

Both phases utilize supervised fine-tuning (SFT) as a baseline, minimizing cross-entropy (CE) loss. However, recognizing the limitations of token-level CE loss (e.g., equal penalty for compiler-breaking errors and semantically equivalent name choices), RL is applied to further refine the models with more meaningful, global rewards.

- **Structure Recovery RL:**
 - **Reward Function (`r_structure`)**: This is a composite reward.
 - **Compilability:** A base reward of 1.0 is granted *only if* the generated IR successfully compiles. This ensures functional correctness. Compiler feedback is obtained using Psyche-C to generate headers.
 - **Placeholder Recovery (`r_placeholder`)**: Additional reward based on the Jaccard similarity coefficient between the set of generated placeholder identifiers (`I_gen`) and the ground-truth IR placeholders (`I_IR`). This encourages accurate reconstruction of the program's data layout.
 - The model is trained to maximize `1.0 + r_placeholder` if compilable, and `0.0` otherwise.

- **Identifier Naming RL:**
 - **Reward Function (`r_identifier`)**: This reward focuses on semantic similarity.
 - **Semantic Similarity**: Measured as the cosine similarity between the embeddings of the generated code (`e_gen`) and the reference source code (`e_src`). Embeddings are generated using qwen-embedding-0.6B.
 - This encourages the model to produce identifiers that are semantically meaningful and reflective of human intent, rather than strictly enforcing an exact lexical match that CE loss would.

#### 3.5. Training Data and Evaluation

- **Data Corpus**: Collected from Exebench and Decompile-Bench C programs, compiled for x86 Linux with GCC/Clang (-O0 to -O3). Source code was normalized, and binaries were stripped. IDA Pro generated pseudocode. The dataset comprises ~5 million samples, totaling ~2B pseudocode tokens, and ~1.5B IR/source code tokens.
- **Baselines**: Compared against GPT-5-mini (commercial SOTA), LLM4Decompile, and Idioms (open-source SOTA).
- **Metrics**:
 - **Re-executability Rate**: Checks if the decompiled code re-compiles and passes original unit tests (for HumanEval and MBPP).
 - **R2I (Relative Readability Index)**: Quantitatively measures structural readability of C code (0-1 score) by analyzing AST features. Modified to assign 0 to unparsable outputs rather than discarding samples.
 - **GPT-Judge**: Uses GPT-5-mini as an automated evaluator (5-point scale) to assess the quality of recovered identifiers based on semantic meaningfulness and adherence to source-level abstractions.

Models were initialized from LLM4Decompile-6.7B, fine-tuned with LLaMA-Factory (SFT), and then further tuned with GRPO algorithm (RL) using the veRL library.

### 4. Main Findings and Results

SK2 Decompile consistently and significantly outperforms existing state-of-the-art LLM-based decompilers across all evaluation benchmarks and metrics, demonstrating its superior ability to generate functionally correct and human-readable code.

#### 4.1. Re-executability Rates (Functional Correctness)

- SK2 Decompile achieves unprecedented average re-executability rates for LLM-based decompilers: approximately **70% on HumanEval** and **60% on MBPP**. This is a critical breakthrough, as previous models struggled significantly with functional correctness.
- It surpasses **GPT-5-mini** by an average of **21.6% on HumanEval** and **26.3% on MBPP**.
- The performance gains are observed across all optimization levels (O0-O3), highlighting the robustness of the approach even under varying compilation complexities.

#### 4.2. R2I (Relative Readability Index - Structural Readability)

- SK2 Decompile demonstrates superior structural readability, consistently achieving the highest R2I scores across all benchmarks.
- Notably, it achieves performance gains of **18.4% over Idioms on ExeBench** and a remarkable **29.4% over Idioms on the GitHub2025 benchmark**. These results indicate that the Structure Recovery phase is highly effective at reconstructing clear and well-formed program structures.

#### 4.3. GPT-Judge (Identifier Naming Effectiveness - Semantic Readability)

- For identifier naming, SK2 Decompile produces high-quality, semantically meaningful names. It scores **4.24/5 on HumanEval** and **4.12/5 on MBPP**.
- When applied to real-world datasets, SK2 Decompile outperforms GPT-5-mini by **2.1% on ExeBench** and **6.7% on GitHub2025**, indicating its ability to infer accurate and intuitive names in more complex scenarios.

#### 4.4. Ablation Studies (Validation of Components)

The ablation studies provide strong evidence for the effectiveness of SK2 Decompile's core components:
- **Task Decomposition:** Comparing `pseudo-src` (direct decompilation with SFT) with `pseudo-ir-src` (decomposed SFT) reveals that decomposition significantly improves re-executability. For instance, on HumanEval, the average re-executability rate increased from 54.86% (`pseudo-src`) to 63.75% (`pseudo-ir-src`). This validates the hypothesis that tackling decompilation as two simpler sub-tasks is more effective.
- **Structure Recovery Importance:** Even the `pseudo-ir` model (SFT for structure recovery only) surpassed the `pseudo-src` baseline on HumanEval (62.56% vs. 54.86%), emphasizing the critical role of an independent phase for program structure recovery.
- **Reinforcement Learning:** The `pseudo-ir-rl` model (structure recovery with RL) achieved substantial performance gains (10.0% to 20.8%) over `pseudo-ir` (structure recovery with SFT only), underscoring the benefits of compiler feedback as an RL reward.
- **Synergistic Effect:** The full `pseudo-ir-src-rl` (SK2 Decompile) consistently achieved the best performance across all metrics, demonstrating that all proposed components—task decomposition, the novel IR, and the specialized reinforcement learning rewards for both phases—are critical and synergistically contribute to the overall superior performance.

#### 4.5. Case Study

A case study on a memory allocation function visually illustrates the advantages. While direct decompilation (e.g., `pseudo-src` or GPT-5-mini) struggles with data structure reconstruction and produces low-level pointer arithmetic or generic casts, SK2 Decompile's Structure Recovery accurately recovers the control flow and data structures. Building upon this clean structure, the Identifier Naming phase then assigns meaningful, semantically rich names (e.g., `arena_alloc`, `state->avail`, `state->limit`), resulting in human-readable and functionally accurate code.

### 5. Significance and Potential Impact

SK2 Decompile represents a significant advancement in the field of binary decompilation, addressing a long-standing challenge and setting new benchmarks for performance. Its potential impact spans several critical areas:

#### 5.1. Breakthrough in Decompilation Quality

By effectively mitigating the traditional trade-off between functional correctness and human readability, SK2 Decompile delivers a novel solution that can produce *both* re-executable and semantically meaningful source code from binaries. Achieving unprecedented re-executability rates (around 70% on HumanEval and 60% on MBPP) for LLM-based decompilers, coupled with superior structural and semantic readability, is a major breakthrough. This positions SK2 Decompile as a new state-of-the-art, significantly enhancing the utility of automated decompilation.

#### 5.2. Enhanced Software Security and Reverse Engineering

The ability to reliably decompile stripped binaries into human-readable and functionally verifiable source code has profound implications for software security.
- **Malware Analysis:** Security analysts can more quickly and accurately understand the intricate logic of malware, identify vulnerabilities, and develop countermeasures without needing to manually decipher low-level assembly or obfuscated pseudocode.
- **Vulnerability Discovery:** Automated analysis of decompiled code becomes more feasible and effective for identifying security flaws in compiled software.
- **Digital Forensics:** Understanding the behavior of unknown binaries or reverse-engineering proprietary systems (under ethical guidelines) becomes more accessible.

#### 5.3. Improved Software Maintenance and Program Understanding

- **Legacy Code Recovery:** For organizations with lost or poorly documented source code, SK2 Decompile offers a powerful tool for recovering high-level representations, facilitating maintenance, updates, and migration efforts.
- **Auditing and Compliance:** It enables easier auditing of compiled software for adherence to coding standards, security policies, or intellectual property concerns.
- **Cross-Architecture Analysis:** While not explicitly detailed, better semantic understanding could contribute to cross-architecture porting or analysis efforts.

#### 5.4. Methodological Contributions

- **Two-Phase Paradigm:** The "skeleton-to-skin" decomposition provides a robust methodological blueprint for tackling other complex code generation or translation tasks where multiple, often conflicting, objectives (e.g., correctness and style) are present. This separation of concerns simplifies learning for LLMs.
- **Information Bottleneck IR:** The principled design of the Intermediate Representation based on the Information Bottleneck principle offers a theoretical foundation for creating effective intermediate formats in code translation, balancing compression and relevance.
- **Targeted Reinforcement Learning Rewards:** The innovative use of phase-specific RL rewards (compiler feedback for structural correctness and semantic similarity for identifier quality) demonstrates how LLMs can be finely tuned to achieve specific, high-level objectives in code generation, going beyond mere lexical accuracy.

#### 5.5. Open Science and Reproducibility

The authors' commitment to releasing their code, training scripts, processed data, and pre-trained models fosters transparency and reproducibility. This open approach encourages further research, allows other researchers to build upon their work, and facilitates the integration of SK2 Decompile's advancements into practical applications.

#### 5.6. Ethical Considerations

The paper explicitly addresses the ethical implications, emphasizing the tool's intended use in legitimate scenarios (academic research, debugging, source code recovery with permission, open-source projects). It highlights that commercial software is typically protected by obfuscation, which limits the potential for misuse, fostering a responsible development approach.

In conclusion, SK2 Decompile represents a significant leap forward in automated binary decompilation, offering a robust, accurate, and highly readable solution that addresses long-standing challenges. Its impact is expected to be felt across software security, maintenance, and the broader field of program analysis, while also providing valuable methodological insights for future LLM-based code research.
