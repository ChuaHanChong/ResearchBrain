# InCoder-32B: Code Foundation Model for Industrial Scenarios

> [!summary] Summary
> InCoder-32B, a 32-billion-parameter code foundation model, unifies code intelligence across diverse industrial domains like chip design, GPU optimization, and 3D modeling. It establishes strong open-source baselines, outperforming other open-weight models across various industrial benchmarks and, in some cases, surpassing proprietary models like Claude-Sonnet-4.6.

## Problem

- General-purpose code LLMs exhibit significant performance degradation when applied to industrial software development due to complex hardware semantics, strict constraints, and specialized language constructs.
- A lack of comprehensive and specialized training data exists for industrial code, which is typically proprietary or underrepresented in public datasets, hindering LLMs from acquiring domain-specific knowledge.
- Previous efforts to address industrial code intelligence have resulted in fragmented, domain-specific models and benchmarks without a unified approach across areas like chip design, GPU kernel optimization, and embedded systems.

## Method

- Developed **InCoder-32B**, a 32-billion-parameter ==decoder-only Transformer== model, specifically designed to unify code intelligence across diverse industrial scenarios.
- Employed a three-stage training pipeline called ==Code-Flow==: ==Pre-training & Annealing== (broad code understanding with curated industrial data), ==Mid-training== (industrial-aware foundation with progressive context extension and synthetic data), and ==Post-training== (execution-grounded verification and feedback-driven repair).
- Systematically collected, cleaned, and synthesized industrial-specific code data from repositories, technical literature via OCR, and domain-specific web sources, complementing it with ==verifiable synthetic industrial code QA pairs== and agent trajectories.

## Results

- Achieved competitive performance on **14** mainstream general code benchmarks, including ranking first among all open-weight baselines on SWE-bench Verified (**74.8%**), Mind2Web, and τ₂-bench, demonstrating strong agentic coding and tool use capabilities.
- Established strong open-source baselines across **9** industrial benchmarks, often outperforming other open-weight models and, in some cases, proprietary models (e.g., CAD-Coder IoU of **53.5%** surpassed Claude-Sonnet-4.6's **32.4%**).
- Detailed error analysis on **1,882** failure cases revealed systematic patterns, including compilation/syntax errors (up to **71%** in Verilog), incomplete API knowledge, functional correctness issues (e.g., **79%** failures in VeriRepair after compilation), and optimization gaps, providing specific directions for future research.

## Takeaways

> [!tip] Key Insights
> - A multi-stage training approach combining broad code understanding, progressive context extension, and execution-grounded feedback with repair trajectories is effective for developing robust industrial code LLMs.
> - The systematic collection of scarce industrial data, augmented by synthetically generated and automatically verified reasoning data, is crucial for acquiring domain-specific knowledge and handling complex constraints.
> - A relatively compact 32B-parameter model can achieve competitive performance on general coding tasks and establish strong baselines on specialized industrial tasks when trained with targeted domain-specific methodologies.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

The field of code intelligence has seen substantial advancements with the development of large language models (LLMs). Models such as Qwen3.5, DeepSeek-V3.2, and Claude-4.6 have demonstrated capabilities across a range of programming tasks, including competitive programming, software task resolution, and tool use. This progress is largely attributed to the availability of extensive and diverse public code datasets from platforms like GitHub and StackOverflow, which predominantly cover mainstream programming languages, frameworks, and general development patterns.

However, a notable gap exists between the performance of these general-purpose code LLMs and the specific requirements of industrial software development. Industrial scenarios, exemplified by CUDA kernel optimization, Verilog hardware description, embedded firmware programming, and compiler optimization, introduce distinct challenges. These include reasoning about hardware semantics, adhering to strict timing and resource constraints, processing specialized language constructs, and employing rigorous verification methodologies. Existing benchmarks indicate that even advanced code LLMs exhibit performance degradation on such industrial tasks, achieving success rates as low as 28.80% for Triton operator generation and 33.3% for Verilog code passing formal equivalence checking.

Previous research has begun to address these industrial challenges, but primarily through domain-specific models and benchmarks. Examples include VeriGen and RTL-Coder for chip design, Kevin and ConCuR for GPU kernel generation, SuperCoder for compiler optimization, and CAD-Coder for 3D modeling. While these efforts have advanced individual sub-domains, they have resulted in fragmented coverage without a unified approach.

InCoder-32B positions itself within this landscape as the first large language model explicitly purpose-built for industrial code intelligence. Its objective is to bridge the identified gap by unifying code intelligence across multiple, previously fragmented industrial domains—chip design, GPU kernel optimization, embedded systems, compiler optimization, and 3D modeling—within a single foundation model. This work aims to extend the utility of code LLMs beyond general software engineering to address the specialized demands of hardware-aware and resource-constrained industrial programming.

### 2. Key Objectives and Motivation

The primary objective of this research is to develop **InCoder-32B**, a 32-billion-parameter code foundation model capable of unifying code intelligence across diverse industrial scenarios. This model is designed to perform effectively in domains such as chip design, GPU kernel optimization, embedded systems, compiler optimization, and 3D modeling.

The motivation behind InCoder-32B stems from several challenges observed with existing large language models (LLMs) in industrial contexts:

- **Performance Degradation in Industrial Scenarios:** Current code LLMs, despite their progress in general programming tasks, demonstrate significant performance limitations when applied to industrial code. These scenarios demand intricate reasoning about hardware semantics, specialized language constructs (e.g., Verilog, CUDA, specific C/C++ dialects for embedded systems), and strict resource constraints (e.g., timing, memory, power budgets). Existing models often treat these as "out-of-distribution" tasks, leading to subpar results.
- **Specialized Requirements of Industrial Domains:** Industrial software development often necessitates capabilities not central to general software engineering. This includes understanding and generating code that respects hardware-level constraints, predicting and optimizing for timing behavior, ensuring synthesizability for hardware, performing low-level performance optimizations, and adhering to rigorous verification methodologies grounded in physical execution environments.
- **Lack of Comprehensive Training Data:** The abundance of publicly available code data primarily covers mainstream programming languages and general software development patterns. This leaves a critical data gap for specialized industrial code, which is typically proprietary or underrepresented in public repositories. This data scarcity hinders the ability of LLMs to acquire the necessary domain-specific knowledge and reasoning abilities.
- **Fragmented Solutions Across Industrial Domains:** Prior efforts to address code intelligence in industrial settings have largely focused on individual domains. This results in a fragmented ecosystem where different models or benchmarks target specific sub-domains, such as a model for Verilog generation or another for CUDA kernel optimization. The motivation for InCoder-32B is to consolidate these capabilities into a single, unified foundation model, thereby reducing complexity and promoting cross-domain code intelligence.
- **Need for Robust Evaluation Baselines:** The absence of a strong, open-source baseline model capable of addressing multiple industrial code domains makes it challenging to benchmark progress and drive further research in this area. InCoder-32B aims to establish such a baseline.

By addressing these motivations, InCoder-32B seeks to bridge the gap between academic code benchmarks and the practical demands of real-world industrial engineering.

### 3. Methodology and Approach

InCoder-32B is developed using a 32-billion-parameter decoder-only Transformer architecture, which is specified with 64 layers, a hidden size of 5120, 40 attention heads, 8 KV heads (GQA), and a maximum context length of 131072 tokens. The model employs a SiLU activation function and RoPE positional encoding. The training process for InCoder-32B follows a three-stage pipeline referred to as "Code-Flow": Pre-training & Annealing, Mid-training, and Post-training.

#### 3.1. Stage 1: Pre-training & Annealing

This initial stage focuses on establishing a broad code understanding, enriched with curated industrial data.

- **Data Collection:** Industrial code is gathered from three sources:
 - **Repository-level recall:** A three-step strategy (rule-based filtering, FastText classifier, domain-adapted semantic encoder) identifies relevant code from public repositories across digital circuit design, high-performance computing, embedded systems, and CAD automation.
 - **Technical literature via OCR:** Code snippets and structured content from technical books and hardware reference manuals are extracted to capture domain-specific knowledge.
 - **Domain-specific web sources:** Technical forums, vendor documentation, and engineering reports provide practical code samples.
- **Data Cleaning and Refinement:**
 - **Cleaning:** Involves license filtering, removal of personally identifiable information (PII) and credentials, discarding invalid files, and multi-level deduplication (exact hash, token-level, repository-level fork consolidation, cross-source). Domain-specific checks (e.g., Verilog syntax parsing, C/C++ header consistency) are applied.
 - **Refinement:** Normalizes surface-level formatting and adds structured annotations, including cross-file dependency resolution, platform/constraint metadata, and natural-language descriptions. All refined samples are verified through AST comparison and re-compilation.
- **Training Strategy:** InCoder-32B is trained on 4,096 GPUs using autoregressive language modeling and fill-in-the-middle (FIM) completion. A constant learning rate of 3 × 10⁻⁴ is used over 15T tokens with a global batch size of 2,048. A curriculum schedule progresses from function-level to project-level data, maintaining a proportion of general-purpose code and text. Periodic evaluations on industrial benchmarks guide data sampling weights.

#### 3.2. Stage 2: Mid-training (Industrial-Aware Foundation)

This stage aims to build an industrial-grade, hardware-aware code foundation by continuing pre-training on industrial data with targeted objectives.

- **Progressive Context Extension:** The model's context length is progressively extended in two sub-stages:
 - **8K to 32K Extension:** Directly trains on sequences up to 32K tokens, emphasizing file-level tasks. Data mixture prioritizes reasoning QA (40%), agent trajectories (20%), commits (15%), industrial artifacts (15%), and FIM (10%).
 - **32K to 128K Extension:** Unlocks long-context capabilities for debugging and multi-file projects. Long-sequence samples (>32K) are introduced gradually, starting at 10% and linearly increasing to 50%. Data replay (5–10% from Stage 2.1) is used to preserve file-scale performance.
- **Industrial Data Synthesis and Curation:** Addresses the scarcity of industrial data.
 - **Synthetic Industrial Code QA:** A three-stage pipeline generates industrially grounded, factually correct reasoning data:
 1. **Industrial scenario specification:** Concrete contexts are identified through consultation with engineers and analysis of design verification reports (e.g., timing violations, GPU operator optimization, memory safety).
 2. **Seed code generation:** Representative code fragments reflecting realistic hardware design patterns (e.g., finite state machines, pipelined datapaths, SIMD vectorization) are generated or extracted.
 3. **QA pair synthesis with automated verification:** Question-answer pairs probing industrial reasoning competencies are generated, with step-by-step chain-of-thought (CoT) reasoning. Crucially, all reasoning traces undergo automated verification via code execution, static analysis, and logical consistency checks to ensure factual correctness.
 - **Curated Industrial Code Data:** Includes authentic data in four categories:
 - **Agent Trajectories:** Multi-step debugging and repair sequences, capturing closed-loop reasoning with feedback from hardware simulators, synthesis tools, and compilers.
 - **Code Commits:** Version-control commits pairing developer intent with code changes, augmented with hardware-characteristic samples.
 - **Industrial Code Artefacts:** Auxiliary files like hardware testbenches (SystemVerilog/UVM), timing constraints (SDC), synthesis scripts, GPU profiling traces, and memory sanitizer logs.
 - **File-Level Fill-in-the-Middle (FIM):** Structure-aware FIM samples targeting code blocks, with domain-specific masking strategies.

#### 3.3. Stage 3: Post-training (Execution-Grounded Verification)

This final stage refines the model's capabilities for real-life industrial coding tasks through supervised fine-tuning (SFT) based on execution-grounded verification.

- **Data Construction:** Approximately 2.5 million SFT samples are constructed directly from industrial coding tasks across hardware design, GPU kernel development, systems programming, and embedded firmware.
- **Task Extraction and Normalization:** Each industrial task is decomposed into a structured instruction format, including natural language requirements, interface constraints, target platform/toolchain, dependencies, and verification scripts.
- **Multi-Source Candidate Synthesis:** A diverse set of candidate solutions is generated through various channels: rewriting, template-based perturbation, cross-language migration, retrieval-augmented generation (RAG), and direct generation from frontier models.
- **Execution-Based Verification:** Candidates are rigorously validated in *real execution environments* (compilation, simulation, test execution, performance profiling, formal checking) rather than relying on heuristic or model-based scoring.
- **Feedback-Driven Repair:** When candidates fail verification, the full feedback context (e.g., compiler errors, runtime logs, waveform differences) is captured. This feedback is used to generate repaired solutions, creating closed-loop repair trajectories (original failed attempt + feedback + corrected solution) that are included in the SFT corpus.
- **Quality Filtering and Final Composition:** The verified samples undergo filtering for executability, stability, and information density. Samples are categorized into direct solutions, defect repairs, and performance/structural optimization samples to ensure a comprehensive learning signal.

### 4. Main Findings and Results

InCoder-32B was evaluated on 14 mainstream general code benchmarks and 9 industrial benchmarks spanning 4 specialized domains.

#### 4.1. Results on General Code Benchmarks

On general code intelligence tasks, InCoder-32B (a 32B dense model) demonstrated competitive performance when compared to significantly larger open-weight models, including those with Mixture-of-Experts (MoE) architectures.

- **Code Generation:** InCoder-32B achieved competitive results on benchmarks such as EvalPlus (HumanEval, MBPP), BigCodeBench, and FullStackBench. For instance, it achieved 94.5% on HumanEval, 89.6% on HumanEval+, 91.8% on MBPP, and 78.3% on MBPP+.
- **Code Reasoning, Efficiency, and Text-to-SQL:** The model also performed competently on CruxEval (code reasoning), LiveCodeBench (competitive programming), Mercury (code efficiency), and Text-to-SQL tasks (Bird, Spider).
- **Agentic Coding and Tool Use:** InCoder-32B ranked first among all open-weight baselines on SWE-bench Verified (74.8%), Mind2Web (70.0% Airline, 85.1% Retail, 86.8% Telecom), and $\tau_2$-bench (86.8%). This indicates strong capabilities in real-world software engineering tasks and multi-turn, tool-augmented workflows.
- **Overall Comparison:** While a performance gap remained on certain reasoning and efficiency benchmarks compared to the largest MoE models, InCoder-32B delivered strong overall performance given its relatively compact size (32B parameters).

#### 4.2. Results on Industrial Code Benchmarks

InCoder-32B demonstrated clear advantages and established strong open-source baselines across specialized industrial code tasks.

- **Chip Design:**
 - **VeriScope:** Achieved a score of 80.7.
 - **VeriRepair:** Achieved a fix rate of 80.0%.
 - **RealBench:** Demonstrated notable strength on module-level tasks with a Syn@1 of 74.8% and Syn@5 of 83.3%, surpassing other open-weight models by a wide margin. Func@1 and Func@5 were 62.7% and 70.5% respectively.
 - **ArchXBench:** Showed competitive performance with an average of 3.4 compilable candidates out of 5 and a 51.0% testbench pass rate for the best candidate.
- **3D Modeling:**
 - **CAD-Coder:** Achieved the highest open-weight results with an 82.0% compilation rate and 53.5% IoU. The IoU score even surpassed the proprietary Claude-Sonnet-4.6 (32.4%).
- **GPU Optimization:**
 - **KernelBench:** Led all open-weight baselines across all three levels (L1: 22.2%, L2: 36.0%, L3: 14.0%) and outperformed Claude-Sonnet-4.6 on L1, L2, and L3 performance.
 - **TritonBench:** Achieved a G-call of 18.5% and T-call of 19.3%, with 100% and 93.8% execution accuracy for G-exe and T-exe respectively when code called successfully.
- **Code Optimization:**
 - **EmbedCGen:** Achieved a main pass rate of 35.2%.
 - **SuperCoder:** Demonstrated an accuracy of 91.0% with a 1.3× speedup, indicating capability in generating functionally correct and optimized assembly code.
- **Overall Industrial Performance:** The results collectively confirm that InCoder-32B provides robust capabilities in industrial code domains, often outperforming other open-weight models and, in some cases, proprietary models.

#### 4.3. Ablation Studies and Error Analysis

- **Effect of SFT Data Scale:** Evaluation of checkpoints trained with 83M, 167M, and 250M industrial SFT tokens showed consistent performance improvements across the majority of benchmarks as data scaled. Minor regressions were observed in a few sub-metrics at the 250M stage, suggesting potential saturation for verification-related understanding with sufficiently high-quality data.
- **Error Analysis:** A manual inspection of 1,882 failure cases revealed systematic failure patterns:
 - **Compilation and Syntax Errors:** Predominant in Verilog generation tasks (71% of RealBench failures, 51% of ArchXBench failures), indicating incomplete internalization of precise syntactic rules and library constraints.
 - **Incomplete API Knowledge:** Significant linker errors (47%) on EmbedCGen for HAL/CMSIS functions and Name/TypeErrors (33% and 24%) on TritonBench for API usage.
 - **Functional Correctness Errors:** Dominated VeriRepair (79% compiled but failed tests), ArchXBench (49% simulated incorrectly), and CAD-Coder (93% geometric failures, often from misinterpreting Euler angle conventions), highlighting challenges in precise numerical or state machine semantics.
 - **Optimization Gaps:** KernelBench failures included 33% functionally correct but insufficiently fast kernels, and SuperCoder failures showed 83% cases where the model did not perform optimization. This indicates that generating correct code is not always synonymous with generating optimized code.

### 5. Significance and Potential Impact

The development of InCoder-32B represents a notable contribution to the field of code intelligence, particularly its application in specialized industrial domains.

- **Bridging the Gap in Code Intelligence:** InCoder-32B is presented as the first code LLM purpose-built to unify code intelligence across diverse industrial engineering domains. This addresses a recognized limitation where general-purpose code LLMs struggle with the unique demands of hardware semantics, strict constraints, and specialized verification in areas like chip design, GPU kernel optimization, embedded systems, compiler optimization, and 3D modeling. By consolidating these capabilities into a single model, the research offers a unified solution to a previously fragmented landscape.
- **Comprehensive Evaluation Framework:** The research introduces and utilizes a comprehensive evaluation suite, encompassing 14 general code benchmarks and 9 industrial benchmarks across 4 specialized domains. This rigorous and broad evaluation provides a more complete understanding of model capabilities and limitations in both general and highly specialized coding contexts, setting a new standard for assessing industrial code intelligence.
- **Establishment of Strong Open-Source Baselines:** InCoder-32B achieves competitive performance on general coding tasks while establishing strong open-source baselines across all evaluated industrial domains. In some instances, it surpasses proprietary models, particularly in 3D modeling (CAD-Coder IoU) and GPU optimization (KernelBench). This provides a foundational model for the open-source community to build upon, potentially accelerating innovation in these critical sectors.
- **Methodological Advancements in Training:** The three-stage Code-Flow training pipeline, comprising pre-training with curated industrial code annealing, mid-training with progressive context extension and synthetic industrial reasoning data, and post-training with execution-grounded verification, introduces several methodological contributions. These include the systematic collection and refinement of scarce industrial data, the generation of verifiable synthetic reasoning data, and the incorporation of feedback-driven repair trajectories. These strategies are shown to improve robustness, planning capabilities, and the ability to learn from execution feedback, which are critical for industrial applications.
- **Practical Implications for Industrial Engineering:** The capabilities demonstrated by InCoder-32B could significantly impact industrial workflows. By assisting engineers in tasks such as designing digital circuits, optimizing GPU kernels for performance, developing embedded firmware, and generating parametric CAD models, the model has the potential to enhance productivity, reduce development cycles, and mitigate errors in complex hardware and systems engineering projects.
- **Guidance for Future Research:** The detailed error analysis provides clear insights into the remaining challenges for industrial code intelligence, such as issues with precise syntactic rules, domain-specific API knowledge, subtle functional logic, and effective optimization. This analysis offers concrete directions for future research to further refine LLM capabilities in these demanding areas, moving towards more robust and industry-ready AI assistants.
