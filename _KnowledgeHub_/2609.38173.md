# In-context Robot Learning Made Simple: A Democratized Recipe for Manipulation Tasks

> [!summary] Summary
> SimpleICL is a minimalist robot in-context learning recipe in which a world action model, built on a Wan2.2 video backbone, conditions on a human demonstration video through a learnable query-token prompt encoder. It defines what a demonstration should convey (action, composition, object, affordance) and pairs this with semantic-discriminative, cross-group-paired data collection, reaching 0.68 real-world hard-level success versus 0.42 for Fast-WAM.

## Problem

- Concurrent robot in-context learning works such as HOST, Gen-1.5 and Zero-WAM leave the learning target undefined, so the intent behind a demonstration video remains ambiguous.
- A video simultaneously conveys trajectories, object identity, affordances, spatial relations and goals, leaving unclear whether the robot should copy the hand's motion or follow the task semantics.
- Task-centric datasets like RoboTwin place unrelated objects outside the action area, so they neither induce nor evaluate genuine prompt ambiguity, and prior ICL leans on massive pre-training.

## Method

- Robot ICL problem definition: four semantics the model must follow (action, composition, object, affordance) and three factors it must ignore (spatial mismatch, human action details, scene variations).
- ==Semantic-discriminative data protocol== with group-based collection and cross-group pairing, which pairs human videos with robot executions from perturbed scenes, yielding up to 3,000 human-robot pairs per robot per day.
- ==Unified visual prompt encoder==: ==128 learnable query tokens== ==cross-attend== to the conditioning video's latents, producing a fixed-size context injected into both the video and action DiTs of a ==Wan2.2-5B world action model==.

## Results

- On RoboTwin visual-ambiguity tests, ICL-oriented data lifts success from **37.6%** (Fast-WAM) to **72.1%**; on seven novel simulated tasks SimpleICL scores **65.9%** versus **24.6%**.
- On real-world Franka hard-level tasks, average success is **0.68** versus **0.42** for Fast-WAM and **0.31** for pi0.5; removing future prediction collapses simulation success from 72.1% to **20.2%**.
- Dropping cross-group pairing cuts success under spatial shift from **0.79** to **0.51**; without affordance-discriminative data, affordance intent-following falls to **0.40-0.60**, while composition stays at **0.93-0.97**.

## Takeaways

> [!tip] Key Insights
> - Video prompts beat language prompts only when training data forces discrimination; shared-scene, multi-intent data is what breaks the shortcut of binding task intent to scene layout.
> - Decoupling demonstration and execution scenes acts as an invariance constraint, not mere augmentation: it prevents trajectory copying and makes the policy ground its actions on objects.
> - Compositional order emerges spontaneously, but fine-grained affordance does not; it needs explicitly contrasted manipulation modes on the same object, making affordance the harder ICL dimension.

## Detailed Report

### 1. Overview

Robot in-context learning (ICL) means using a visual demonstration as an instruction for a robot, rather than requiring someone to teleoperate the robot through the task. A video, however, shows much more than the intended task: motion paths, objects, grasp choices, and scene details. If nobody specifies what the robot should learn from it, the model might copy the demonstrator's path instead of following the demonstrated intent. The authors' central move with SimpleICL is to define that learning target. They then test the resulting recipe in a real-robot evaluation on eight unseen tasks, including weighing, wiping a plate, serving tea, and pulling a drawer.

Execution of the eight real-world evaluation tasks.

### 2. A demonstration needs a target

The robot should follow the demonstrated action and its order, identify the intended object, and use the demonstrated way of manipulating it. The paper splits this into four dimensions:

- **Action category:** press, grasp, place.
- **Composition:** which actions, and in what order.
- **Object identity:** the intended object, even when its position changes.
- **Affordance:** an object's relevant way of being manipulated, such as grasping a mug handle rather than its body.

The robot should disregard irrelevant differences such as object position, hand appearance, and background clutter. These fall under three kinds of variation treated as irrelevant within the paper's scope: spatial mismatch, low-level human-action details, and scene variation. The authors explicitly allow two exceptions. Extreme positional differences may count as different semantics, and some applications might care about details such as speed.

Four data types, illustrating the distinctions the data are meant to teach: (a) action, "Press pump" versus "Grasp bottle" in the same scene; (b) object, correct versus wrong object; (c) compositional, "Pick A" then "Pick B"; (d) affordance, grasping a handle versus a rim. Each panel shows human and robot examples.

### 3. Make copying the scene a bad shortcut

The recipe turns each target into a data rule:

- Collect different actions in the same scene.
- Shift target-object positions and add distractors to test object grounding.
- Vary action order to test composition.
- Show different manipulation modes on the same object to test affordance.

Tasks are collected in groups of scenes. A robot trajectory is then paired with a human video from a changed scene, such as one with altered object positions, lighting, or distractors. This cross-group pairing breaks the exact scene match that could reward trajectory copying.

The authors report that a single platform can produce up to 3,000 valid human–robot pairs per working day. They also say minor scene changes enrich pairing at virtually no additional collection cost.

On the model side, a module encodes video frames and uses learnable tokens and cross-attention to query task-relevant cues. It then supplies compact prompt tokens to the video and action models. The system uses a pretrained Wan2.2-5B backbone.

### 4. Testing the distinctions

The first comparison uses the hardest real-world setting, where a task has multiple valid targets. For example, the robot must choose which of two adjacent plates to wipe. Here, the average of the eight task success rates is 68% for SimpleICL, compared with 42% for FAST-WAM and 31% for π₀.₅. This is a system comparison, not a clean test of video input alone. The baselines are language-conditioned, while SimpleICL is video ICL.

The second comparison isolates the data design. With affordance-discriminative data, the model follows the demonstrated grasp mode more often than without it. On tape measure, intent-following is 77% versus 40%. By contrast, composition results without targeted sampling remain 93%, 97%, and 93% for snack, cup, and bag tasks. The authors read this as evidence that, in their tested setup, fine-grained affordance is harder to learn spontaneously than action order.

Top (medium): when asked to pull open the yellow drawer, the language-conditioned WAM is distracted by a nearby scale, while SimpleICL points to the intended drawer. Bottom (hard): the baseline selects the round bowl instead of the elongated bowl, while SimpleICL reaches the demonstrated destination.

### 5. Intent, not trajectory

The contribution is a definition of which parts of a demonstration should guide action, plus a data recipe designed to test that distinction. The authors present clear definitions and reproducible data recipes as a way to study robot ICL systematically. The paper proposes and tests this recipe. It does not measure a comparative reduction in collection time or compute.
