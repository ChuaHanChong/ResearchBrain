# PurpCode: Reasoning for Safer Code Generation

> [!summary] Summary
> Researchers from the University of Illinois Urbana-Champaign developed PurpCode, an open-source alignment framework that enables large language models (LLMs) to perform explicit cybersafety reasoning for code generation. It achieves state-of-the-art secure code generation, surpassing baselines by 12-21% and frontier models against red-teaming attacks, while also significantly reducing over-refusal and preserving model utility.

## Problem

- Large Language Models (LLMs) frequently generate code containing security vulnerabilities, posing risks to software integrity.
- LLMs can be prompted to assist in malicious cyber activities by generating harmful code or instructions for attacks.
- Existing implicit safety methods for code LLMs struggle to generalize cybersafety across the vast number of specific security rules and vulnerability types, such as those cataloged in CWEs.

## Method

- **PurpCode** implements a two-stage ==post-training recipe==, combining Supervised Fine-Tuning (SFT) for explicit rule learning and Reinforcement Learning (RL) to generalize cybersafety reasoning.
- A comprehensive internal red-teaming pipeline generates a high-coverage dataset of adversarial cyber-safety prompts, including vulnerable code synthesized for 90 distinct CWEs and various advanced jailbreak techniques.
- Specialized oracles (e.g., CodeGuru for security, LLM judge for malicious assistance, Sandbox Fusion for correctness) are used for rigorous data verification and evaluation during training and testing.

## Results

- PurpCode-**32B** achieved state-of-the-art cybersafety, with **80.8%** secure code generation on CyberSecEval SCG (**12%** better) and **94.8%** on CodeLMSec (**21%** better), and demonstrated **77.6%** secure generation against university red-teaming attacks, outperforming Sonnet 4 by **35%**.
- The model exhibited strong defense against advanced jailbreaks (e.g., **95.7%** against LAA-Attack) and successfully reduced over-refusal rates (as low as **2%** in general scenarios) while maintaining model utility.
- Controlled experiments confirmed that both rule learning (SFT) and subsequent RL stages significantly improved code security and over-refusal mitigation, with the proposed dynamic sampling mechanism accelerating RL training by **12%**.

## Takeaways

> [!tip] Key Insights
> - Explicitly teaching LLMs a 'safety analysis first, then answer' reasoning trajectory, grounded in specific security rules, leads to more robust and generalizable secure code generation than implicit learning.
> - A multi-objective reward system in the RL stage, which incentivizes both refusal of malicious tasks and the generation of *secure* code, is critical for balancing safety and utility and preventing over-refusal.
> - Developing a diverse and adversarial red-teaming pipeline, including methods to synthesize vulnerable code for low-resource rules and adapt advanced jailbreaking techniques, is essential for creating effective safety training data.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

The emergence of Large Language Models (LLMs) has revolutionized various domains, with coding assistance quickly becoming one of their most prominent and impactful applications, exemplified by commercial models like Claude Sonnet. However, the increasing capability of LLMs in code generation introduces significant safety challenges that are critical to address for responsible deployment. This paper tackles two primary concerns: (i) the potential for LLMs to assist malicious cyber activities (e.g., generating malicious code or attack instructions), and (ii) their tendency to produce functional code that inadvertently contains security vulnerabilities.

The research landscape for LLM safety has traditionally focused on rejecting prompts with malicious intent. For code LLMs specifically, prior methods (e.g., SafeCoder, ProSec) have attempted to improve secure code generation implicitly, through techniques like contrastive samples and specialized loss functions. While these approaches show promise, this paper argues that implicit learning alone is insufficient for achieving generalizable cybersafety across diverse scenarios and the vast number of known code security rules. For instance, the MITRE Common Weakness Enumeration (CWE) catalog lists hundreds of vulnerabilities, and various static analysis tools like AWS CodeGuru and GitHub CodeQL implement extensive rules to detect them. Explicitly teaching models these detailed, fine-grained rules, and enabling them to *reason* about them, is a recognized gap.

PurpCode directly addresses this gap by specializing the high-level framework of "deliberative alignment" (as proposed by OpenAI for general safety) for the specific domain of cybersafety and code security. It distinguishes itself by being presented as the **first open-source alignment approach** designed to train models capable of performing *cybersafety reasoning*. This involves a departure from purely reactive safety mechanisms towards a proactive, rule-based reasoning capability. By open-sourcing its training recipe, including infrastructure, datasets, synthesizers, and evaluators, PurpCode also makes a significant contribution to fostering broader research and development in this critical area, accelerating the community's ability to build safer code LLMs.

### 2. Key Objectives and Motivation

The overarching objective of the PurpCode project is to develop and implement an alignment approach that enables generalizable cybersafety reasoning in coding LLMs *without compromising their utility*. This core goal breaks down into several specific motivations and objectives:

1. **Explicit Rule Learning for Cybersafety**: A primary motivation is to move beyond implicit learning in secure code generation. The authors argue that models need to be explicitly taught how to reference and apply a large number of known code security rules (like CWEs and static analysis rules) to generate vulnerability-free code and avoid facilitating malicious cyber activities. This objective aims to instill a deeper, more generalizable understanding of security principles.
2. **Defense Against Malicious Cyber Activities**: Directly motivate the model to refuse and defend against prompts that seek assistance for cyberattacks, whether through generating malicious code, providing instructions for attacks, or exploiting vulnerabilities.
3. **Generation of Vulnerability-Free Code**: Ensure that when asked for benign coding tasks, the model generates functional code that adheres to security best practices and is free from common vulnerabilities.
4. **Preservation of Model Utility**: A critical objective is to ensure that enhanced safety does not come at the cost of the model's core utility in generating correct code for benign problems or answering general security knowledge questions.
5. **Mitigation of Over-refusal**: Safety alignments can often lead to models becoming overly cautious and refusing benign or subtly-phrased legitimate requests. A key objective for PurpCode is to reduce such over-refusal rates in both general and cybersecurity-specific scenarios, maintaining a helpful user experience.
6. **Comprehensive Data Generation through Red-Teaming**: Motivated by the need for robust and diverse safety training data, the project aims to develop an internal red-teaming pipeline capable of synthesizing high-coverage, adversarial prompts. This includes prompts designed to induce vulnerable code and assist malicious events, as well as their jailbroken variants.
7. **Open-Source Contribution**: A significant motivation is to fully open-source the entire training recipe, including infrastructure, datasets, data synthesizers, and evaluators. This aims to democratize access to advanced safety alignment techniques and accelerate research in the broader community.

### 3. Methodology and Approach

PurpCode introduces a novel, two-stage post-training recipe for aligning code LLMs, complemented by a robust internal red-teaming pipeline for data generation. The approach is designed to teach models explicit cybersafety reasoning.

**A. Safety-Aware Code Reasoning Pipeline:**
This pipeline trains the reasoning model in two sequential stages:

1. **Rule Learning Stage (Supervised Fine-Tuning - SFT)**:
 - **Goal**: To explicitly teach models individual rules of general safety and secure coding practices.
 - **Process**:
 - **Rejection Sampling**: An initial "data synthesis model" (often the base LLM) generates responses to verifiable prompts (from both safety and utility categories). These responses are *contextualized* with safety guidelines and prompt-specific vulnerability information (e.g., citing CWEs).
 - **Oracle Verification**: The generated prompt-response pairs are then rigorously verified by a set of specialized oracles (described below). Only responses that pass the oracle checks are retained.
 - **SFT**: The model is fine-tuned on this high-quality, verified dataset. Each training conversation includes a system message reminding the model of safety guidelines, the user prompt, and the verified response which comprises a trajectory of safety reasoning *followed by* the certified answer. This explicitly teaches the model *how to think* about and apply security rules.
 - **Rules to Learn**: The prompts used for data generation are enriched with three categories of rules:
 - **Behavioral Guidelines**: Instruct the model to analyze user intent, run a checklist of reasoning steps, and decide between rejection or safe assistance.
 - **Safety Guidelines**: Define allowed and disallowed content, prohibiting insecure code or actionable malicious suggestions while allowing explanations of security concepts.
 - **Prompt-specific Coding Hints**: For code generation tasks, relevant CWEs and vulnerability specifics (with contrastive examples) are provided to guide the model away from known weaknesses.

2. **Reinforcement Learning (RL) Stage**:
 - **Goal**: To generalize the model's safety reasoning capability to a wider, more diverse set of scenarios, optimizing both safety and utility.
 - **Mechanism**: An outcome-driven RL approach (similar to DeepSeek-R1) is used. In each RL step, the policy model generates multiple responses (rollouts) for a mini-batch of prompts.
 - **Reward Mechanism**: A multi-objective reward system uses binary oracle signals (0 or 1). Crucially, to prevent "reward hacking" (where models might refuse all code generation to be "secure"), a partial reward (0.8) is given for refusing malicious coding tasks, while a full reward (1.0) is only granted if the response *includes code* AND that code is *secure*.
 - **Single-Step Dynamic Sampling**: An efficiency improvement over existing RL methods like DAPO. It adjusts the sampling size for the next batch based on the "learnability" (variance in rewards) of the current batch. This prevents restarting rollouts and avoids wasting valuable samples, leading to faster convergence.
 - **Batched Reward Calculation**: To address the bottleneck of concurrent code analyzer execution (due to high start-time overhead), a batched reward manager packs multiple code snippets for a single analysis request. This significantly accelerates the oracle evaluation process.

**B. Oracle Design:**
Central to both training stages and evaluation, various oracles are designed:

- **Safety Oracles**:
 - **Code Security**: Leverages CodeGuru v0.2.4 (configured for medium/high severity issues) as the primary static analyzer for Python, noting its superior detection capabilities compared to CodeQL (especially for critical vulnerabilities and fewer false positives).
 - **Malicious Event Assistance**: An LLM judge (Llama-3.3-70B for evaluation, Qwen2.5-32B for training) evaluates responses against detailed rubrics, checking for malicious code/scripts or instructions facilitating cyber activities. This judge is validated for high consistency with human annotations.
- **Utility Oracles**:
 - **Code Correctness**: Evaluates generated Python code by executing it against prompt-associated test cases (pytest, standard I/O) in a secure sandbox (Sandbox Fusion).
 - **Detecting Overrefusal**: An LLM judge categorizes responses to basic security questions (from CyberMetric) into refusal, irrelevant, unsafe, or appropriate, flagging over-refusal when not "appropriate."
- **Format Oracle**: Ensures responses adhere to a specified format (safety analysis first, then answer) and avoid repetitive patterns.

**C. Internal Red-Teaming Pipeline (Data Curation):**
This pipeline generates a high-coverage corpus of adversarial cyber-safety prompts:

1. **Synthesizing Prompts to Induce Vulnerable Code**:
 - **Curating Vulnerable Code**: Collects seed vulnerable code from (i) Open Source Vulnerabilities (OSV) database, (ii) existing open security datasets, and (iii) **RULE2CODE**, a novel method to synthesize vulnerable code for low-resource security rules (e.g., AWS-specific rules) by prompting helpful-only LLMs with documentation. This results in 7,288 certified vulnerable code snippets covering 90 distinct CWE identifiers.
 - **VUL2PROMPT**: A framework that prompts DeepSeek-R1 to generate vulnerability-inducing prompts based on these seed codes, coding rules, and three strategies: (i) Implicit/Explicit Vulnerability-inducing Instruction, (ii) Vulnerable Continuation of Benign Code, and (iii) Vulnerability Processing (code-editing to add/preserve vulnerabilities).
2. **Seed Prompts for Malicious Event Assistance**:
 - Curated from (i) real-world user-LLM conversations (Discord, Reddit, LMSYS) filtered for cybersecurity relevance, and (ii) expert-crafted/synthetic prompts from cybersecurity-focused datasets (e.g., HarmBench's cybercrime category).
3. **Jailbreaking**: Existing safety prompts are "jailbroken" to subtly elicit unsafe behaviors. For code security, modifications include target construction (vulnerability-aware objectives), sampling by CWE coverage, and attack model conditioning with domain knowledge. For malicious event assistance, various template-based (H4RM3L, ArtPrompt), search-based (AutoDAN, LAA-Attack), and multi-turn (ActorAttack) jailbreaking methods are adapted.

### 4. Main Findings and Results

The evaluation of PurpCode-32B (built on Qwen2.5-32B-Instruct) against various frontier models and alignment baselines reveals several key findings:

1. **State-of-the-Art Cybersafety**: PurpCode-32B consistently demonstrates superior cybersafety across multiple critical metrics.
 - **Code Security**: It achieved the highest secure code generation rates, outperforming the second-best baseline by **12% on CyberSecEval SCG (80.8% vs. Qwen3-235B's 72.3%)** and **21% on CodeLMSec (94.8% vs. Qwen3-32B's 78.1%)**. Crucially, against **university red-teaming prompts** specifically designed to attack PurpCode models, it maintained a **77.6% secure code generation rate, surpassing Sonnet 4 by 35% (57.3%)**, demonstrating exceptional robustness. The model also shows generalization across various programming languages, not just Python.
 - **Malicious Event Assistance**: PurpCode-32B nearly saturates performance on CyberSecEval MITRE (99.2%) and university red-teaming (98.2%). Furthermore, it exhibits the **strongest overall defense against advanced jailbreaks**, outperforming other models across template-based, search-based, and multi-turn attacks (e.g., 95.7% defense rate against LAA-Attack where Qwen3-235B achieved 63.9%).
2. **Reduced Overrefusal**: PurpCode-32B effectively mitigates over-refusal without compromising safety.
 - On cybersecurity benchmarks, it answers most prompts (over 90%), ranking #1 in XSCode (93.5%, 7% better than o4-mini) and #3 in CyberSecEval FRR (92.7%).
 - In general scenarios (XSTest, PHTest), PurpCode-32B is the least over-refusing model, with rates as low as 2%, suggesting its safety is not a result of excessive caution.
3. **Preserved Model Utility**: The alignment process incurs minimal impact on the model's core utility.
 - Code generation utility (measured by pass@1 on HumanEval+ and MBPP+) shows only slight variations, with a 3% improvement on HumanEval+ and a 3% degradation on MBPP+ in controlled 14B experiments. The 32B model confirms minimal impact.
 - Basic security knowledge (Security QA) also shows no degradation, maintaining high non-deflation rates.
4. **Effectiveness of Training Stages**: Controlled experiments (on Qwen2.5-14B-Instruct-1M) confirm that each alignment stage (rule learning and subsequent RL) significantly improves code security and mitigates over-refusal, reinforcing the efficacy of the proposed multi-stage pipeline.
5. **Efficiency of Dynamic Sampling**: The proposed single-step dynamic sampling mechanism accelerates end-to-end RL training by **12%** and leads to higher-quality models compared to DAPO's dynamic sampler, demonstrating improved efficiency and performance.
6. **Comparison with Baseline Alignment Methods**: PurpCode significantly outperforms existing open-source secure code generation methods like SafeCoder (which often achieves safety through over-refusal) and ProSec (which struggles with malicious event assistance).

### 5. Significance and Potential Impact

The "PurpCode: Reasoning for Safer Code Generation" paper makes several significant contributions with far-reaching potential impacts on AI safety, software development, and the broader cybersecurity landscape.

1. **Pioneering Cybersafety Reasoning in LLMs**: PurpCode is the first open-source approach to explicitly teach LLMs detailed code safety rules and enable them to perform *cybersafety reasoning*. This shifts the paradigm from implicit, pattern-based safety to a more robust, generalizable, and transparent understanding of security principles. This innovation holds the potential to significantly enhance the reliability and trustworthiness of AI-assisted code generation.
2. **Substantial Improvement in Code LLM Security Posture**: By demonstrating state-of-the-art performance against various benchmarks, including highly adversarial red-teaming data, PurpCode offers a robust solution to the critical problem of LLMs generating vulnerable code or assisting malicious cyber activities. This directly reduces the attack surface in software developed with AI assistance and minimizes the risk of LLMs being weaponized.
3. **Addresses the Over-refusal Challenge**: A common hurdle in developing safe LLMs is the tendency towards over-refusal, which can make models unhelpful for legitimate tasks. PurpCode's success in achieving high safety without significant over-refusal rates (often outperforming frontier models) is a crucial step towards more balanced and practically deployable AI systems, enhancing user acceptance and utility.
4. **Comprehensive Adversarial Data and Benchmarking**: The extensive internal red-teaming pipeline, including the curation of vulnerable code covering 90 distinct CWEs and advanced jailbreaking techniques, contributes valuable datasets and methodologies to the community. This provides more challenging and high-coverage evaluation frameworks, fostering more rigorous future research in LLM security.
5. **Catalyst for Open-Source AI Safety Research**: The decision to fully open-source the training recipe – including infrastructure, datasets, data synthesizers, and evaluators – is a major contribution. It democratizes access to advanced techniques, lowers the barrier for entry into LLM safety research, and will likely accelerate the development of more secure and reliable AI systems across the globe.
6. **Practical Implications for Software Development**: As LLMs become integral to software development workflows, PurpCode's ability to generate safer code has direct, tangible benefits for developers and organizations. It can lead to more secure software by design, potentially reducing the time and resources spent on vulnerability detection and patching post-development.
7. **Broader Impact on AI Alignment and Safety**: By successfully specializing deliberative alignment for a complex domain like cybersafety, PurpCode offers a blueprint for applying similar reasoning-based approaches to other challenging AI alignment problems. This could inspire new directions in ensuring AI systems behave as intended across diverse, critical applications.

In conclusion, PurpCode represents a significant advancement in the field of LLM safety for code generation. Its focus on explicit reasoning, coupled with a robust methodology and open-source contribution, positions it as a pivotal work that will likely influence the development of more secure, reliable, and helpful AI coding assistants.
