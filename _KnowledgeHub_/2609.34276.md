# NavHarness: Towards Lifelong Embodied Navigation

> [!summary] Summary
> NavHarness is a training-free harness for lifelong embodied navigation that builds memory handling into the navigation loop. Multi-round frontier-model sessions consult and revise SLAM maps, task records and house notes. They pass structured handovers to fresh conversations, an independent judge verifies outcomes, and run-end consolidation writes house notes. With GPT-6 Astra it reaches state-of-the-art 83.7 s-SR on GOAT-Bench and 85.9 on IR2R-CE.

## Problem

- Frontier-model navigation harnesses handle single tasks well, but successive tasks require reusing an evolving map and earlier search records that may be incomplete or contradict new observations.
- Prior long-horizon methods retain scene representations or train retrieval policies, but do not study how general-purpose reasoning sessions consult, check and revise memory without navigation-specific training.
- One long conversation accumulates outdated goals and observations, while restarting loses search evidence, and unverified completion claims can become accepted but misleading experience for later tasks.

## Method

- ==Three-tier memory==: active context, working memory pairing ==SLAM==-built ==occupancy maps==, named places and photos with a ==task journal==, and long-term ==house notes== on rooms, routes, failed searches and skills.
- Structured recovery ==handovers==: before a fresh conversation replaces a stuck session, the outgoing session records searched places, evidence-supported exclusions, a reliable landmark, untried options and uncertainty, within the shared task budget.
- A tool-less judge session performs pre-stop verification and post-stop certification from stop views, sampled frames and the map, while a run-end consolidation session rewrites house notes from the journal.

## Results

- On GOAT-Bench, NavHarness raises s-SR over same-backbone independent sessions by **30.3** points for Qwen3.8-27B, **34.8** for GPT-4o, **22.6** for Opus **5** and **18.6** for GPT-6 Astra.
- With GPT-6 Astra and SLAM-estimated poses it reaches **83.7** s-SR, **62.3** SPL and **36.9** e-SR on GOAT-Bench, against a prior best of **72.8** s-SR, and **85.9** s-SR on IR2R-CE.
- Opus **5** ablations: structured handovers beat matched-length summaries by **8.3** s-SR, removing cross-task memory costs **14.7**, and consolidation raises continuous-deployment s-SR from **72.8** to **80.5**.

## Takeaways

> [!tip] Key Insights
> - What crosses a session boundary matters more than how much: handovers that separate visited places from evidence-backed exclusions beat generic summaries of equal length.
> - One ever-growing conversation underperforms fresh per-task sessions, so keeping memory in external files and restarting context stops stale goals from competing with the current task.
> - Memory that agents write needs independent checking, because unverified completion claims spread errors into long-term notes, so keeping claims separate from judged verdicts protects later reuse.

## Detailed Report

### 1. Overview

A household robot has finished one search and must begin another from where it stopped. It is still in the same home, but its next reasoning session is new. The practical risk is that a note saying “not found in this room” does not prove every relevant spot was inspected, and stored descriptions can conflict with the current view. NavHarness keeps the robot's accumulated evidence and replaces only the conversation. The next session then checks that evidence against the scene. It is a training-free harness, not a newly trained navigation policy.

An illustration of memory reuse across tasks. Left: a floor plan with routes and numbered task markers, where a “Task 1 memory” card links saved information to later navigation. Right: a navigation session, working memory, and long-term memory, with arrows for recall, writing, updating, and consolidation.

### 2. Keep the evidence, reset the conversation

A new task opens a fresh multimodal reasoning conversation. Before the robot moves, the session is pointed to relevant records. During navigation, it can consult several sources:

- a SLAM-built occupancy map
- named places with saved views
- task handovers
- house notes

The session compares this retrieved information with its observations and can correct its account.

Recovery follows the same pattern. The outgoing session writes a note that distinguishes places visited from places ruled out by evidence, and it lists untried options. A fresh attempt then resumes at the same physical location. It keeps the map, the records, and the remaining task budget, but not the old conversation.

A separate stage guards against false completions. Before a stop, an independent judge checks the completion claim against views and execution evidence. A definite contradiction can send the session evidence and one chance to continue.

### 3. What the comparisons establish

Two metrics matter here:

- **s-SR** is the fraction of individual subtasks completed.
- **e-SR** is the fraction of episodes in which every subtask succeeds.

Memory carries between tasks within an episode, but each episode begins with empty memory.

The first comparison uses GPT-6 Astra on GOAT-Bench. It covers validation-unseen results over all 2,669 subtasks in 360 episodes across 36 scenes. The navigator uses SLAM-estimated poses, not simulator ground-truth poses.

- **Individual tasks:** s-SR is 83.7% (±0.4) with NavHarness versus 65.1% (±0.6) for same-model independent sessions, an 18.6-point gain.
- **Whole sequences:** e-SR is 36.9% (±0.9) versus 13.6% (±0.7).

The control has a fresh context-only session per task and no external memory. This comparison is therefore for the full harness, not memory alone.

GOAT-Bench comparison. Published baselines occupy the upper rows, and same-backbone independent-session and NavHarness pairs occupy the lower rows. NavHarness's entries use SLAM rather than simulator pose. The dagger marks a 278-subtask evaluation. The paper's own scores are mean ± standard deviation over three seeds.

The second comparison tests the handover mechanism with Opus 5, using matched budgets and three seeds on all 2,669 subtasks. It asks whether restarting with any compact summary is enough, and it keeps recovery triggers and budgets unchanged. The full harness scores 81.5% s-SR. An ordinary summary matched in length to the structured recovery handover scores 73.2%. That is a difference of 8.3 points, with a paired 95% CI for summary relative to full of −11.0 to −5.7.

The structured note is designed to keep a distinction the ordinary summary may lose: “visited” is different from “ruled out by evidence.” The note also retains untried options. This result supports the value of the handover's information selection and organization together. It does not establish that formatting alone caused the gain.

The task budget is shared across attempts, so a restart does not grant a new search budget.

### 4. Scope

NavHarness shows that a fresh conversation can inherit evidence that remains open to checking and revision. These experiments are in simulation, not real homes. The extended comparison uses finite sequences in static simulated houses. The authors note that SLAM drift and map misalignment can persist, and an incorrect completion accepted by the judge can propagate into house notes. The work is progress toward lifelong navigation, not a demonstration of reliable real-world, indefinite operation.
