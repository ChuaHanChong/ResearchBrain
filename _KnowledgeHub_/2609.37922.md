# WayFinder: Hierarchical Visual-Language-Action for Zero-Shot Waypoint Generation and Low-Level Kinematic Control

> [!summary] Summary
> WayFinder is a hierarchical zero-shot navigation framework for drones that pairs a lightweight onboard DQN kinematic controller with an offboard Gemma 3 multimodal LLM queried only when a progress-based stall trigger fires. The MLLM reads a ray-traced occupancy state map plus coordinate-grounded text and outputs recovery waypoints, raising AirSim navigation success by up to 27.45% without any fine-tuning.

## Problem

- VLA models such as RT-2 and OpenVLA demand continuous heavy inference, clashing with the compute and power limits of onboard edge hardware on mobile robots.
- Mapping pretrained VLAs to specific embodiments needs costly fine-tuning or distillation, yet demonstration data for niche domains like aerial navigation is virtually nonexistent.
- End-to-end DRL navigation controllers generalize poorly out of distribution and lack common-sense reasoning to escape dead-ends and infinite loops, requiring human intervention.

## Method

- Low-level ==DQN== controller: CNN over a three-frame depth-map queue fused with relative GPS and IMU history in an MLP, trained with A*-graded curriculum, cached discretized states, and deterministic collision halting.
- Sparse ==stall trigger==: measures maximum progress toward the goal over a rolling window of N steps and invokes the offboard MLLM only when progress falls below a threshold, then resets the window.
- Coordinate-grounded visual state map: ==ray-traced ternary occupancy grid== rendered with high-contrast color-coded markers for robot, trajectory, past waypoints, start, and target, paired with a text prompt listing explicit coordinates.

## Results

- With fully observed maps, Gemma 3 27B lifts navigation accuracy over the DQN-only baseline from **44.55%** to **70.73%** on CityEnviron and **63.73%** to **77.73%** on Coastline.
- Using partially observed ray-traced maps, the 27B model recovers **50.82-80.72%** of episodes the low-level policy failed, versus **25.08-54.82%** for the 4B model.
- Ablation: removing explicit coordinates from the prompt collapses aggregate recovery from **56.79%** to **12.26%**, while dropping the visual map only reduces it to **55.62%**; ground-truth maps score **53.45%**.

## Takeaways

> [!tip] Key Insights
> - Querying a large model only on detected failure, rather than every step, preserves fast reactive control while capturing common-sense recovery at minimal inference cost.
> - For MLLM spatial reasoning, explicit textual coordinates matter far more than images; dynamic image rescaling breaks pixel-to-coordinate mappings, so the map is largely auxiliary.
> - Memory of failed recovery attempts prevents repeated identical suggestions, and egocentric partial maps can beat perfect global maps, though only consistently for the largest model.

## Detailed Report

### 1. Overview

WayFinder addresses a practical navigation bottleneck. A robot's fast reactive controller can get stuck, while asking a large multimodal model to decide every movement is costly and ill-suited to real-time control. WayFinder keeps a trained, onboard controller in charge of ordinary motion. It calls a zero-shot, offboard multimodal large language model (MLLM) only when a progress monitor detects a stall. The MLLM proposes a waypoint, and the onboard controller then resumes navigating toward it. In AirSim simulations, this setup improves navigation over a controller-only baseline.

The two control levels and their feedback loop. The upper path takes depth-map and GPS/IMU inputs through a FIFO history, CNN/MLP and DRL policy to produce motion actions. The lower path builds a state map and checks progress at a "Progress Stalled?" decision. When the robot is stalled, it sends map/context to the MLLM, which returns a new waypoint before the low-level controller resumes.

### 2. A fast controller, a sparse supervisor

The low-level controller is a deep-reinforcement-learning (DRL) policy trained in AirSim. It uses depth, GPS, and heading feedback for local movement and collision avoidance. During deployment, a rolling history checks progress toward the current target. If the distance reduction over the window falls below a threshold, the system marks the robot stalled, pauses the low-level policy, and queries the MLLM. This is a stagnation signal rather than a perfect failure detector: the authors note false positives, and a longer detection window delays the trigger.

Depth observations are projected into a global occupancy map with free, occupied, and unknown space. The MLLM receives a 2D map plus language that describes coordinates and symbols. The map marks the traveled path, prior waypoints, the start, the robot, and the target. The MLLM returns a new intermediate waypoint. After the robot reaches it, the controller resumes toward the original goal.

### 3. The result and what the ablation isolates

Navigation accuracy is the percentage of test episodes that reach within the target radius before the maximum step limit. The test set comprised 4,000 valid A*-checked paths. The low-level DQN was trained only in AirSimNH.

In this baseline experiment, the MLLM receives AirSim's ground-truth occupancy grid with a fully observed map. That makes it an upper-bound setup, not the partially observed deployment-style condition. Under this condition, Gemma 3 27B on CityEnviron reached 70.73% accuracy, versus 44.55% for the low-level-only baseline, a difference of 26.18 percentage points. Accuracy does not rise with model size in every environment: on Blocks, 12B (88.71%) is slightly below 4B (89.57%).

Ablation study: recovery rate and relative length per configuration. Default WayFinder has 56.79% recovery and relative length 1.00. With no language coordinates, recovery is 12.26% and relative length is 1.46.

The prompt ablation is the strongest mechanism test. Recovery rate is the percentage of episodes that first failed with only the low-level controller and then reached the target after MLLM intervention. Relative path length is the average ratio of total steps on successful episodes to the default setup.

Across the AirSim environments, removing explicit spatial coordinates from the language prompt drops recovery from 56.79% to 12.26% and raises relative path length to 1.46. The "no coordinates" arm still supplies a visual map with labeled axes and tick marks. It therefore tests language-coordinate grounding, not the removal of all spatial information. In the reverse case, removing the visual map while retaining linguistic coordinates gives 55.62% recovery, a modest change from default.

These ablations support the importance of explicit coordinate-to-map grounding in this setup. They do not prove that language coordinates are the only useful input or that the finding generalizes to other spatial tasks.

### 4. Ground the waypoint

WayFinder uses the MLLM as an occasional strategist and leaves the movement job to the fast controller. The ablation suggests that explicitly tying language coordinates to map features is central to recovery in this setup. The tests were in AirSim, not on a physical robot. The headline accuracy comparison used a fully observed ground-truth map, while the partial-map evaluation reported recovery rates rather than full navigation accuracy.
