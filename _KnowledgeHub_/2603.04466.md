# Act-Observe-Rewrite: Multimodal Coding Agents as In-Context Policy Learners for Robot Manipulation

> [!summary] Summary
> Act-Observe-Rewrite (AOR) lets a multimodal coding agent improve a robot manipulation policy without gradient updates, demonstrations, or reward engineering. Between trials, the agent reads key-frame images and structured episode outcomes, diagnoses the failure, and rewrites the whole Python controller. In robosuite, it reaches 100% on Lift and PickPlaceCan and 91% on Stack.

## Problem

- VLA models often fail on a specific deployment configuration, and diagnosing why and adapting without expensive retraining remains largely unsolved.
- Reflexion-style self-reflection works in symbolic, text-based environments with discrete actions. It has not been shown to handle continuous kinematics, noisy vision, and physical geometry in manipulation.
- Code-as-policies methods generate controller code once with no closed-loop feedback. Reward-code methods like Eureka need thousands of RL updates per LLM call, so neither can cheaply fix low-level implementation errors.

## Method

- ==Two-timescale loop==: a Python controller runs each episode at control frequency, and the multimodal LLM reasons only between episodes, keeping real-time control deterministic.
- ==Full controller rewrite==: the LLM sees ==key-frame images==, ==phase logs==, and current source, answers three ==structured diagnosis questions==, then outputs a new controller class. The vision pipeline and controller are separate, so each can be rewritten independently.
- Safety mechanisms: a ==compilation sandbox==, fallback to the last working controller, ==action clamping== of Cartesian deltas to [-2, 2] and gripper to [-1, 1], and bounded targeted rewrites instead of holistic ones.

## Results

- Lift reached **100%** in **3 LLM calls**, and PickPlaceCan reached **100%** in **2 calls**. PickPlaceCan passed **20/20** randomised repeats, using only camera input and no ground-truth object positions.
- Stack rose from **0%** over v0-v6 to **33%** after the y-flip fix, **45%** after the extrinsic fix, **70%** at v10, and **91%** at v20. Fixing the two vision bugs cut localisation error from **5-8 cm** to **1.4-1.9 cm**.
- Residual Stack failures are gripper contact with cubeB, which the agent diagnosed correctly but never fixed. Swapping in OpenAI Codex (GPT 5.3) solved none of the three tasks in the same iteration budget.

## Takeaways

> [!tip] Key Insights
> - In-context improvement works best when the LLM operates at the same abstraction level as the failures. Code-level rewriting can fix a back-projection sign error that parameter tuning or skill selection cannot.
> - Giving the LLM both images and source code lets it trace a symptom to a specific code line. Such reasoning can debug vision pipelines even for systems that use learned policies.
> - The agent diagnosed correctly but stalled in a local optimum, introduced side-effect bugs, and had miscalibrated confidence. The loop needs diversity pressure or restarts, and results depend on the coding agent's capability.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

The "Act–Observe–Rewrite" (AOR) framework by Kumar occupies a distinct and innovative position within the rapidly evolving landscape of robot learning, particularly at the intersection of large language models (LLMs) and physical manipulation. It bridges several prominent research traditions while offering unique contributions.

**Distinction from Foundation Models and VLAs:** The dominant paradigm for generalized robot manipulation involves training Vision-Language-Action (VLA) models (e.g., RT-2, PaLM-E, OpenVLA, Octo, GR00T N1) on internet-scale data and vast robot trajectories. These models excel at breadth and zero-shot generalization across hundreds of tasks. AOR, however, adopts a fundamentally different approach. Instead of optimizing for breadth, it prioritizes **depth and interpretability**, aiming for high performance on individual tasks through targeted reasoning. Crucially, AOR achieves this *without any gradient updates, demonstrations, or reward engineering*, making it a cost-effective and transparent alternative to data-hungry VLA models. The paper frames AOR as complementary, suggesting it could provide targeted debugging and adaptation when a VLA model fails in a specific deployment.

**Advancement over Language Agent Research:** AOR builds upon the "language agent" tradition, drawing inspiration from works like Reflexion, ReAct, and Voyager. Reflexion introduced the concept of verbal self-reflection for improving performance, primarily in text-based environments. ReAct demonstrated interleaving reasoning with actions. Voyager built a lifelong agent whose skill library grows from LLM-generated code. AOR extends these concepts significantly by applying them to **continuous physical manipulation**, where observations are raw RGB-D images, policies are executable motor-control code, and failure modes involve complex kinematics and sensor geometry. Unlike Reflexion, which modifies natural language strategies, AOR directly rewrites *low-level motor-control code*, enabling far more precise and fundamental policy changes.

**Novelty in Code Generation for Robot Control:** Previous work has explored using LLMs to generate robot control code (e.g., Code as Policies, ProgPrompt, SayPlan, ReKep). However, a critical distinction is that these approaches are often **one-shot** or focus on high-level task planning. Code as Policies generates code once; ReKep generates constraint code once. AOR introduces a **closed-loop, iterative refinement** mechanism. It observes visual and structured evidence of failure from episode rollouts and then *iteratively rewrites* the entire controller implementation, allowing for continuous self-improvement and systematic correction of errors that are invisible in a single observation. This feedback loop is the core innovation over prior code generation efforts.

**Alternative to LLM-Generated Reward Functions:** Research such as Eureka, DrEureka, and Language to Rewards uses LLMs to generate reward functions for reinforcement learning (RL). While powerful, these methods typically require many full RL training runs as an inner loop, involving thousands of gradient updates. AOR offers a **substantially cheaper and faster** alternative for rapid task adaptation. Each LLM call in AOR is followed by a single trial execution, making it more agile for situations where interpretability and quick adaptation are paramount over peak performance achieved through extensive RL training.

**Refinement of LLM-Based Optimization:** AOR can be viewed as an instance of LLM-based optimization (e.g., OPRO, FunSearch, EvoPrompting) where the LLM proposes better solutions based on past performance. However, AOR differentiates itself by utilizing **richer multimodal and causal feedback**. Instead of just a scalar score, the LLM in AOR receives key-frame images, reward traces, and phase-transition logs, allowing it to "see" where the arm failed and reason about the physical cause. This enables targeted, single-step improvements that pure score-based optimization would struggle to discover efficiently.

**Depth of Diagnosis in Grounded Planning:** Works like SayCan and Inner Monologue use LLMs for high-level planning and replanning, often selecting from a fixed library of pre-trained skills or incorporating high-level feedback. AOR's key contribution over these is the **depth of diagnosis**. By reasoning over images and controller code simultaneously, AOR can pinpoint root causes at the level of individual lines of code, addressing "how to do it" (motor-control implementation) rather than just "what to do" (task planning or skill selection).

In essence, AOR carves out a niche where LLMs are not just planning agents or code generators, but **reflexive policy learners that deeply understand and debug their own executable motor control code** based on multimodal feedback from physical interaction.

### 2. Key Objectives and Motivation

The primary objective of the Act–Observe–Rewrite (AOR) framework is to enable a multimodal language model agent to **learn to manipulate physical objects by reasoning about its own failures**, critically doing so *without gradient updates, demonstrations, or reward engineering*. This ambitious goal is motivated by two significant challenges persisting in the field of robot manipulation, particularly with the rise of foundation models:

1. **Diagnosing and Adapting Failures Without Retraining:** Current vision-language-action models, while capable of zero-shot generalization, struggle when they fail on a specific deployment configuration. Diagnosing the precise reasons for failure and adapting the policy without the prohibitively expensive process of full retraining remains largely an unsolved problem. AOR aims to provide a mechanism for in-context adaptation and systematic debugging.
2. **Cost of Pretraining Data and Compute:** The sheer scale and cost associated with collecting pretraining data and computational resources required for large foundation models place them out of reach for many researchers and practitioners who need to rapidly iterate on novel manipulation tasks. AOR seeks to offer an accessible and efficient alternative for task-specific learning and adaptation.

To address these challenges, AOR posits a central architectural claim: that making the **full low-level motor control implementation the unit of LLM reasoning**—represented as interpretable Python code—creates a qualitatively different kind of in-context learning compared to opaque neural policies. This approach is motivated by the following core beliefs:

- **Enabling Root Cause Diagnosis:** By having the LLM reason over explicit code, it can diagnose the *cause* of a failure in terms of code logic (e.g., "the y-coordinate is negated in the back-projection, which is wrong for OpenGL convention"), rather than merely observing that a failure occurred or inferring it from abstract parameters.
- **Facilitating Architectural Changes:** Code as a policy representation allows the LLM to make fundamental architectural changes, such as adding new phases to a control sequence, altering target computations, or introducing geometric corrections. This goes far beyond the limitations of parameter tuning or selecting from a predefined skill library.
- **Reasoning About Physical Constraints:** The LLM can leverage its world knowledge about geometry, physics, and programming to reason about physical constraints (e.g., workspace limits, sensor biases, grip geometry) and directly encode these as executable corrections in the policy code.
- **Interpretability and Efficiency:** The appeal of this "write a policy and rewrite it when it fails" paradigm is clear: it promises no data collection, no lengthy training loops, full interpretability of the robot's actions, and direct application of the LLM's vast knowledge base to practical robotics problems.

In essence, AOR's key objective is to demonstrate the viability and advantages of a paradigm where an LLM functions as an intelligent robot programmer, iteratively improving manipulation policies through a cycle of execution, observation of multimodal failure evidence, and programmatic self-correction.

### 3. Methodology and Approach

The Act–Observe–Rewrite (AOR) framework implements a novel **two-timescale learning loop** designed to enable multimodal LLM agents to iteratively improve robot manipulation policies. This design separates the real-time constraints of robot control from the computational demands of LLM reasoning.

#### 3.1. The AOR Two-Timescale Loop

1. **Fast Loop (Within Episode):** At the control frequency, the robot executes an episode under the guidance of a Python controller. Sensor observations (RGB-D images and proprioceptive state) pass through a vision pipeline, generating a feature dictionary. This feature dictionary is then fed to the current Python Controller class, which produces actions (e.g., Cartesian deltas, gripper commands) that the robot executes.
2. **Slow Loop (Between Episodes):** Upon episode termination, the accumulated outcomes and key-frame images are stored in an episodic memory. A multimodal LLM agent then reasons over this comprehensive feedback. Based on its diagnosis of failure modes, the LLM synthesizes an entirely new Python controller class. This new controller is dynamically compiled, validated, and loaded for the next trial, allowing the robot to execute the refined policy. No model weights are updated at any point; all learning occurs in-context through code synthesis.

This two-timescale decomposition is motivated by separating concerns (deterministic control vs. slow, non-deterministic LLM inference), abstracting noisy single-timestep observations into episode-level summaries for robust reasoning, and using interpretable code as the natural interface between the LLM and robot execution.

#### 3.2. The Four Components of AOR

1. **Vision Pipeline:** This component processes raw RGB-D images from the robot's camera feed into a structured feature dictionary (e.g., `{object_pos, eef_pos, detected}`). It is deliberately separated from the controller to allow the LLM to reason about and rewrite vision logic independently from control logic.
2. **Controller:** The core of the robot's immediate behavior, implemented as an executable Python class with `reset()` and `get_action(features)` methods. This representation allows for maximal expressiveness, supporting arbitrary algorithmic changes such as phase-based state machines, PID loops, waypoint sequences, and complex geometric computations, which is a key advantage over parameter-tuning or skill-selection methods.
3. **Episodic Memory:** A persistent storage mechanism that accumulates structured data from each episode. This includes scalar reward, step count, a detailed phase-transition log, minimum end-effector-to-object distance, an oscillation flag, and a small set of visual key-frame images captured at critical moments (e.g., phase transitions, regular intervals). This rich, multimodal feedback is crucial for the LLM's diagnostic capabilities.
4. **Multimodal LLM Agent:** This is the brain of the AOR framework. It receives the full context from episodic memory (including current controller source code) and generates an improved controller class. The LLM is guided by a structured prompt, requiring it to answer three diagnostic questions before producing code: (1) What was the dominant failure mode? (2) Was the root cause in vision, controller logic, or parameters? (3) What is the single most impactful change? This structured reflection, inspired by Reflexion, facilitates targeted and effective code rewrites.

#### 3.3. Safety and Stability Mechanisms

To mitigate the risks associated with LLM-generated code, AOR incorporates several safeguards:

- **Compilation Sandbox:** All newly generated code is compiled and validated in an isolated environment. If the code fails to compile, lacks the required interface, or raises exceptions during instantiation, the system automatically reverts to the previous working controller, ensuring operational stability.
- **Action Clamping:** All actions output by the controller are constrained within predefined safe bounds (e.g., `[-2, 2]` for Cartesian deltas, `[-1, 1]` for gripper commands). Runtime exceptions during a step trigger a zero (safe-stop) action.
- **Bounded Rewrites:** The LLM is explicitly instructed to make targeted changes that address diagnosed failure modes while preserving the overall structure of the existing controller. This prevents radical, ungrounded rewrites and encourages incremental improvement.

#### 3.4. Instantiation for Robot Manipulation

The AOR framework was instantiated using the **robosuite v1.5.1 simulation platform** with a UR5e arm and OSC POSE Cartesian delta controller. **Claude Code (claude-sonnet-4-x family)** served as the multimodal coding agent. Key design choices, notably the vision pipeline (HSV color-based segmentation) and the phase-based controller structure, were not predefined by the authors but *emerged autonomously* through the agent's iterative diagnosis and rewriting process, showcasing its self-adaptive capabilities. This included the agent discovering and correcting subtle, undocumented camera convention issues in robosuite for accurate pinhole back-projection, and developing principles like "stationary grasp" and "EMA smoothing" for robust control.

### 4. Main Findings and Results

The experimental validation of the AOR framework demonstrates its capability to autonomously improve robot manipulation policies across tasks of varying complexity, achieving high success rates without demonstrations, reward engineering, or gradient updates.

#### 4.1. Setup and Agent Comparison

Experiments were conducted on three `robosuite` tasks: Lift, PickPlaceCan, and Stack, using a UR5e arm and observations from a single 256x256 RGB-D camera. The primary coding agent was **Claude Code (claude-sonnet-4-x family)**. A crucial comparative finding was that **OpenAI’s Codex agent (GPT 5.3)**, when tested under the same conditions, was unable to solve any of the three tasks within the allocated iteration budget, highlighting the significant role of the underlying LLM's reasoning capabilities in AOR's effectiveness.

#### 4.2. Task-Specific Performance and Discoveries

The experiments revealed a consistent pattern where AOR's behavior directly addressed the nature of the underlying failure mode.

- **Lift Task (Pick up a red cube):**
 - **Success Rate:** 100%
 - **LLM Calls:** 3
 - **Key Discoveries:** The agent rapidly converged to a solution.
 - **Episode 0:** Failed to descend. The LLM diagnosed a **2.5 cm vision depth bias** and introduced a `z-offset` correction, demonstrating systematic error correction.
 - **Episode 1:** Reached but failed to grasp. The LLM diagnosed **downward pressing during gripper closure** destabilizing the object and changed the policy to implement a "stationary grasp."
 - **Episode 2:** Succeeded, and subsequent randomized repeats also passed.

- **PickPlaceCan Task (Pick up can, place in bin):**
 - **Success Rate:** 100%
 - **LLM Calls:** 2
 - **Key Discoveries:** AOR successfully resolved compounding perception bugs.
 - **Call 1 (Episode 0):** Arm stalled in `reach` phase. The LLM diagnosed a **total detection failure**; the can rendered red in the agentview camera, not silver as initially assumed. The vision pipeline was rewritten to use a red-hue segmentor.
 - **Call 2 (Episode 1):** Arm descended towards a bin marker instead of the can. The LLM diagnosed **bin indicator contamination** (red pixels from a bin marker biased the centroid). The fix was to switch to `largest-connected-component filtering`, isolating the can.
 - **Episode 2:** Succeeded, and all 20 randomized repeats passed, without using ground-truth object positions.

- **Stack Task (Stack red cube on green cube):**
 - **Success Rate:** 91%
 - **LLM Calls:** 20
 - **Key Discoveries (Table 2 progression):** This task, requiring ∼2 cm placement tolerance, exposed profound vision pipeline bugs and stochastic grasp dynamics.
 - **v0–v6:** Initial controller tuning attempts failed due to **5–8 cm systematic vision errors**.
 - **v7–v9:** The LLM diagnosed **vision inaccuracy** as the root cause. It identified and corrected two critical, subtle bugs: (i) **incorrect back-projection** using `-y_p` instead of `+y_p` (wrong for OpenGL convention), and (ii) an **extrinsic matrix convention mismatch** with `robosuite`'s OpenGL rendering. Correcting these reduced localization errors significantly.
 - **v10:** Vision calibrated, leading to 70% success.
 - **v11–v20:** Further iterations involved refining retract ramps, descend tuning, adding **grasp retries** (v17), fixing a bug where a single offset parameter was shared across grasp and place (v18-v19), and "freezing" the target cube at place entry (v20), reaching 91% success.

#### 4.3. Observed Shortcoming: Unresolved Placement Strategy

Despite achieving 91% on Stack, the remaining 9% failures were not stochastic. The LLM accurately diagnosed the consistent cause from episode images: the **gripper fingers contacted `cubeB` during descent to place `cubeA`, physically displacing it** before release. However, even after identifying this root cause, the agent **failed to discover a placement strategy** (e.g., steeper descent angle, compliant release, lateral nudge) that would avoid this contact within its iteration budget. This highlights a limitation in the current reflexion search, where the agent converged to a local optimum in controller space, unable to construct a suitable variant for this specific geometric challenge.

#### 4.4. Overall Performance Summary

| Task | Success | LLM Calls | Residual Failure |
| :---------- | :------ | :-------- | :------------------------------ |
| Lift | 100% | 3 | None |
| PickPlaceCan| 100% | 2 | None |

These results confirm AOR's ability to achieve high task-specific performance and systematically debug complex robotic manipulation tasks solely through in-context learning, multimodal feedback, and code rewriting.

### 5. Significance and Potential Impact

The Act–Observe–Rewrite (AOR) framework presents a significant advancement in robot learning, offering a distinct and practically impactful approach that complements existing paradigms. Its core contributions lie in demonstrating the power of interpretable code as a policy representation for autonomous robotic agents.

#### 5.1. Code as the Right Representation for Reflective Learning

AOR's most profound significance is its validation of the architectural claim: making the full controller implementation the unit of LLM reasoning qualitatively transforms in-context learning in physical manipulation. This approach enables:

- **Deep Causal Diagnosis:** Unlike parameter-tuning or skill-selection frameworks that are limited to high-level adjustments or choices, AOR allows the LLM to diagnose failures at the level of specific code logic (e.g., "the y-coordinate in the back-projection has the wrong sign"). This capability to attribute symptoms to specific lines of code is a fundamental advantage, leading to precise and effective corrections.
- **Architectural Flexibility:** The LLM can introduce architectural changes—such as new phases, entirely different geometric computations, or novel control strategies—that are impossible with fixed policy architectures or skill libraries. This expands the agent's problem-solving space significantly.
- **Leveraging LLM World Knowledge:** The LLM can directly apply its vast knowledge of geometry, physics, and programming to reason about physical constraints and encode these insights into executable corrections, bridging symbolic reasoning with low-level control.

#### 5.2. Autonomous Perception Debugging

A particularly impactful finding is AOR's ability to autonomously discover and fix subtle vision pipeline bugs, such as camera convention errors in robosuite. In traditional robot learning, vision bugs often manifest as ambiguous performance plateaus, making root cause attribution difficult. AOR's LLM, by having access to both visual observation data (images showing where the arm went) and the actual implementation code (e.g., the back-projection formula), can generate diagnoses like "placement is consistently wrong by 5–8 cm... this is consistent with a systematic back-projection error." This level of **automated debugging**, from symptom to specific code module and line, suggests that AOR-style reflexive agents could be invaluable not just for policy learning but as diagnostic tools for *any* vision-based robot system, even those using learned policies.

#### 5.3. Complementary Position in Robot Learning

AOR occupies a unique and valuable space:

- **Complement to VLA Models:** While VLA models prioritize breadth and generalization, AOR optimizes for depth and interpretability on specific tasks. This complementarity suggests AOR could serve as a targeted debugging and adaptation layer for VLA models when they encounter specific, challenging deployment configurations without requiring costly retraining.
- **Advancement of Reflexion-style Agents:** AOR extends the principles of verbal reflection to a much lower level of abstraction—motor-control implementation—making it effective for failures that occur at the kinematic and sensor geometry level, beyond high-level strategy or sub-goal planning.

#### 5.4. Potential Broader Impact

The framework's ability to achieve high task-specific performance without demonstrations, reward engineering, or gradient updates offers several practical benefits:

- **Reduced Development Cost and Time:** Eliminating data collection and training loops dramatically accelerates the iteration cycle for novel manipulation tasks.
- **Enhanced Interpretability and Auditability:** The policy is human-readable Python code, making the robot's decisions transparent and auditable, which is crucial for safety-critical applications.
- **Accessibility:** Lowering the barriers to entry by reducing data and compute requirements makes advanced robot learning more accessible to a wider range of researchers and smaller labs.

#### 5.5. Limitations and Future Directions

Despite its successes, the paper honestly outlines several limitations, which also point to promising future work:

- **Simulation Only:** Current results are in simulation, requiring further validation and robustness enhancements for real-robot deployment (e.g., handling sensing noise, actuation imprecision, lighting variation).
- **Sequential Iteration:** The one-trial-at-a-time hypothesis testing is inefficient. Parallel evaluation of candidate controllers could significantly reduce wall-clock time.
- **LLM Dependence and Search Incompleteness:** The agent's performance is directly tied to the underlying LLM's capabilities. The "Stack" task's unresolved placement issue highlights that the search for solutions can get stuck in local optima, suggesting the need for mechanisms like diversity pressure, restarts, or structured exploration strategies.
- **Classical Controller Bias:** The agent currently converges on classical control techniques (HSV, state machines, PID) due to their prevalence in training data. Future work could explore prompting the agent to adopt modern perception (e.g., learned keypoint detectors, foundation-model visual features) or control methods.

In conclusion, AOR establishes a powerful new paradigm for robot learning, leveraging the reasoning and code-generation capabilities of multimodal LLMs to enable autonomous self-improvement in physical manipulation. As LLMs continue to advance, this combination of verbal diagnosis and direct code synthesis promises to become an increasingly vital tool for developing and deploying robust, interpretable, and adaptable physical AI systems in the real world.
