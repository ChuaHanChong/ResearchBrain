# CoAct-1: Computer-using Agents with Coding as Actions

> [!summary] Summary
> CoAct-1 presents a multi-agent framework that integrates both Graphical User Interface interactions and direct programmatic execution through coding for computer-using agents. This hybrid methodology achieves a 60.76% success rate and completes tasks in an average of 10.15 steps on the OSWorld benchmark, establishing improved performance and efficiency over purely GUI-driven approaches.

## Problem

- Existing computer-using agents relying solely on Graphical User Interfaces (GUIs) are brittle and inefficient for complex, long-horizon tasks.
- GUI-only actions are prone to visual grounding ambiguities, planning errors, and accumulated failures across numerous sequential manipulations.
- Many common computer operations can be executed more rapidly and reliably via direct programmatic commands (Python/Bash) than through lengthy GUI interactions.

## Method

- CoAct-1 employs a novel multi-agent system comprising an ==Orchestrator==, a ==Programmer==, and a ==GUI Operator==.
- It introduces a ==hybrid action space==, allowing the Orchestrator to dynamically delegate subtasks to either the Programmer (for Python/Bash script execution) or the GUI Operator (for visual interactions).
- The Programmer agent writes and executes code to interact directly with the operating system, while the GUI Operator uses a vision-language action model for screen-based tasks.

## Results

- CoAct-1 achieved an overall success rate of **60.76%** in the 100+ steps category on the OSWorld benchmark, outperforming previous leading methods.
- It demonstrated dramatic efficiency improvements, solving tasks with an average of just **10.15 steps**, a substantial reduction compared to around **15 steps** for other high-performing agents like GTA-1.
- The system showed superior performance across various task categories, including LibreOffice Calc (**70.21%**), VS Code (**78.26%**), and multi-application workflows (**47.88%**), benefiting significantly from programmatic control.

## Takeaways

> [!tip] Key Insights
> - Integrating coding as a fundamental action alongside GUI manipulation provides a more robust and efficient paradigm for autonomous computer agents.
> - Dynamically delegating tasks to the most appropriate modality (GUI or code) significantly reduces the total number of steps and opportunities for error.
> - Leveraging powerful, specialized backbone models for each agent type (VLM for GUI, LLM for coding and orchestration) is crucial for maximizing the hybrid system's overall performance.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

The development of autonomous agents capable of operating computers through Graphical User Interfaces (GUIs) has been a significant area of focus in recent artificial intelligence research. Current advancements in this domain primarily revolve around vision-language models (VLMs) that perceive and interact with digital interfaces. While these GUI-centric agents demonstrate proficiency in various tasks, they frequently encounter limitations when dealing with complex, long-horizon operations. These challenges include visual grounding ambiguities, the high potential for cumulative errors across long sequences of actions, and inherent inefficiencies in tasks that could be more directly resolved through programmatic means.

To mitigate some of these issues, a line of research has emerged that augments GUI agents with high-level planners. These modular systems, exemplified by approaches like GTA-1 and Agent S/S2, utilize powerful language models to decompose complex user goals into a series of manageable subtasks. This hierarchical planning aims to improve performance and robustness by structuring the problem-solving process. However, these planning augmentations do not fundamentally address the core inefficiency and brittleness that stem from an exclusive reliance on low-level GUI manipulation for all execution steps. Tasks such as file system management, data processing within spreadsheets, or environment configuration still necessitate lengthy and often precise sequences of clicks, drags, and typing, even when a high-level plan is in place. This leaves the agents susceptible to planning uncertainties, visual perception errors, and difficulties in integrating high-level plans with low-level GUI actions.

Within this landscape, the present work introduces a hybrid approach that integrates programmatic execution as a primary action modality. Prior work has explored different aspects of computer-using agents, categorized as:
- **Screen parsing and visual grounding**: Focuses on perceiving and mapping language instructions to actionable GUI elements from pixel data, without relying on underlying structural information (e.g., OmniParser, SeeClick, OS-Atlas).
- **Native end-to-end GUI agents**: Aims to unify perception, reasoning, and action within a single model for mouse/keyboard operations across various applications (e.g., UI-TARS, OpenCUA, AGUVIS).
- **Modular planner-grounder agents**: Explicitly separates high-level planning from low-level visual action grounding, with a language model proposing subgoals and a visual model executing them (e.g., GTA-1, Agent S2.5).
- **Hybrid agentic frameworks**: Systems that compose tools and APIs dynamically to extend capabilities beyond GUI interaction (e.g., UFO-2, PyVision, ALITA). While these integrate tools, they often do not specifically focus on embedding direct operating system-level coding actions as a core, first-class alternative to GUI interactions within a unified multi-agent framework for general computer use.

This work differentiates itself by explicitly proposing and implementing a multi-agent system where a central orchestrator dynamically chooses between GUI-based interaction and direct code execution (Python or Bash) for subtask resolution. By providing agents with the ability to "code as an action," the system addresses the fundamental limitations of GUI-only agents for tasks where programmatic control offers superior precision, reliability, and efficiency. This integration positions CoAct-1 as a novel contribution that expands the action space for computer-using agents, aiming for a more robust and scalable form of generalized computer automation.

### 2. Key Objectives and Motivation

The primary objective of this research is to enhance the efficiency, robustness, and flexibility of autonomous computer-using agents, particularly for complex and long-horizon tasks. The motivation for this work stems from the identified limitations of existing GUI-centric automation paradigms.

The key motivations and specific objectives are detailed as follows:

- **Addressing Inefficiency of GUI-only Automation:** Current computer-using agents predominantly operate through Graphical User Interfaces. While effective for simple interactions, complex tasks often require long, intricate sequences of low-level GUI operations (e.g., clicking menus, typing in fields, dragging elements). For instance, tasks in office productivity software, such as filtering data in a spreadsheet and saving it as a new file, or file management operations like finding and resizing images across nested directories, are inherently inefficient when performed solely via GUI actions. These GUI-only sequences consume many steps and are prone to errors. The objective is to introduce a mechanism to bypass these inefficient sequences.

- **Mitigating Brittleness and Error Propagation:** Relying solely on visual interaction makes agents susceptible to visual grounding ambiguities (e.g., misinterpreting visually similar icons or menu items). A single mis-click or a misunderstanding of a UI element can cascade into task failure, leading to a "brittle" system. The motivation is to introduce a more reliable action modality that is less susceptible to visual perception errors and cumulative interaction failures.

- **Enhancing Task Decomposition beyond GUI Execution:** While augmenting agents with high-level planners improves task decomposition, these systems (like GTA-1) still funnel all low-level execution through GUI manipulation. This means that even if a plan is sound, its execution remains constrained by the GUI's limitations. The objective is to enable agents to choose the most appropriate execution modality—GUI for visual interactions and programmatic for backend operations—to fundamentally improve execution.

- **Introducing Direct Programmatic Control as an Action:** The core motivation is to move beyond the exclusive paradigm of GUI manipulation by integrating direct system interaction through code (e.g., Python or Bash scripts) as an enhanced action. This allows for precise, robust, and often single-shot execution of tasks like file operations, data processing, and environment configuration that are ill-suited for GUI-only approaches.

- **Developing a Hybrid Multi-Agent Architecture:** The research aims to instantiate this hybrid approach within a multi-agent system, where an intelligent Orchestrator can dynamically delegate subtasks to either a conventional GUI Operator for visual interactions or a specialized Programmer agent for code-based execution. This architectural design is intended to synergistically combine the intuitive strengths of GUI interaction with the precision and reliability of programmatic control.

- **Establishing New Performance and Efficiency Benchmarks:** A crucial objective is to empirically demonstrate the advantages of this hybrid design on challenging, real-world computer operation benchmarks like OSWorld and WindowsAgentArena, showing improvements in both task success rates and operational efficiency (fewer steps).

By pursuing these objectives, the researchers aim to pave a more robust, efficient, and scalable path toward generalized computer automation that can handle a broader spectrum of complex user tasks with higher reliability.

### 3. Methodology and Approach

The methodology centers on CoAct-1, a novel multi-agent system designed to address the limitations of GUI-exclusive computer-using agents by integrating programmatic execution capabilities. The core approach involves a hybrid action space, A = A_GUI ∪ A_Code, which allows for both traditional GUI manipulation and direct operating system interaction through code.

#### 3.1. Multi-Agent System Design

CoAct-1 comprises three specialized agents that collaboratively work towards a user's high-level goal (G), generating an action trajectory (τ). Each agent manages its own dedicated conversational context.

- **Orchestrator:**
 - **Role:** Serves as the high-level meta-policy (π_Orch), responsible for task decomposition, dynamic planning, and delegation. It does not directly interact with the operating system (OS).
 - **Inputs:** Receives the full history of observations (H_t), including past subtask summaries and screenshots, and the overall user goal (G).
 - **Decision-making:** Analyzes the current subtask and determines whether it should be assigned to the Programmer (implementing π_Code) or the GUI Operator (implementing π_GUI).
 - **Feedback Loop:** Upon subtask completion by an executor agent, the Orchestrator receives a condensed summary of the execution process and a new screenshot (o_t+1) reflecting the updated system state, which informs its next decision.
 - **Termination:** Outputs a termination signal when the overall goal G is deemed met.
 - **Backbone Model:** Implemented using OpenAI o3 for its reasoning capabilities.

- **Programmer:**
 - **Role:** Implements the specialized policy (π_Code) for generating and executing programmatic actions (a_t ∈ A_Code).
 - **Interaction:** Engages in a multi-round conversation with a remote code interpreter. It generates Python or Bash scripts, which are executed, and receives execution results as feedback. This allows for iterative code refinement until the subtask is resolved.
 - **Capabilities:** Handles backend OS operations such as file management, data processing, and environment configuration, bypassing GUI sequences.
 - **Context:** Provided with necessary context from the Orchestrator, such as file paths or window information inferred from H_t.
 - **Backbone Model:** Implemented using OpenAI o4-mini, chosen for its strong ability to write Python and Bash scripts.

- **GUI Operator:**
 - **Role:** Implements the GUI-based policy (π_GUI) for generating visual interface actions (a_t ∈ A_GUI).
 - **Interaction:** Operates in a multi-round "perception-action" loop. It takes the current screenshot and subtask instruction as input, generates a single GUI action (e.g., mouse click, keyboard input), which is then executed by a GUI action interpreter on the OS. A new screenshot serves as observational feedback for subsequent actions.
 - **Capabilities:** Performs frontend actions like clicking buttons, navigating visual interfaces, typing, and using hotkeys.
 - **Backbone Model:** Utilizes OpenAI computer-use-preview, a vision-language action model specifically fine-tuned for computer use.

#### 3.2. Workflow and Memory Design

The system employs a structured workflow and hierarchical, isolated memory system to manage information flow.

- **Workflow:**
 1. The Orchestrator delegates a subtask to either the Programmer or the GUI Operator.
 2. The selected executor agent enters its own multi-round interactive loop to complete the subtask, generating a detailed conversational history of its actions and system responses.
 3. Upon subtask completion, a dedicated summarizer model (OpenAI o4-mini) condenses this detailed interaction history into a concise summary, capturing key actions and outcomes.
 4. This summary, along with the final screenshot (reflecting the new environment state), is returned to the Orchestrator, updating its overall task history (H_t).

- **Memory Design:**
 - **Orchestrator Memory:** Maintains the long-term, primary memory (H_t), comprising the initial user goal (G) and the sequence of high-level summaries and screenshots received from the executor agents after each subtask. This provides context for high-level planning.
 - **Executor Memory:** The Programmer and GUI Operator each maintain a short-term, working memory that holds the "instance conversation history" for their currently assigned subtask. This memory is active only for the duration of that subtask and is cleared upon completion. This isolation ensures agents focus on the current subtask without interference from prior, irrelevant interactions.

#### 3.3. Implementation Details

- **Environment:** Experiments are conducted on a Linux environment augmented with a RESTful server from OSWorld. A remote code interpreter processes Python and Bash scripts.
- **Task Initialization:** Each task in the OSWorld and WindowsAgentArena benchmarks involves an initial system state (e.g., specific applications open, files downloaded), followed by an initial screenshot and user task provided to CoAct-1.
- **Step Limits:** Maximum rounds for the Programmer are 20, for the GUI Operator 25 steps per subtask, and for the Orchestrator 15 rounds of delegation. This sets an upper bound on system interactions, though tasks typically resolve much faster.
- **Prompt Design:** Specific prompt engineering techniques are employed for each agent, including chain-of-thought, verification rules, and mechanisms to mitigate common LLM limitations like hallucination and misinterpretation of changes (e.g., Orchestrator independently checks results, reloads files modified by Programmer).

#### 3.4. Evaluation Protocol

The system is evaluated using rule-based evaluators provided by the OSWorld and WindowsAgentArena benchmarks. These evaluators use Boolean expressions built from 134 atomic, execution-based evaluators to determine task success.

### 4. Main Findings and Results

The experimental evaluation of CoAct-1 on the OSWorld and WindowsAgentArena benchmarks demonstrates that the proposed hybrid multi-agent system establishes new state-of-the-art performance, outperforming previous GUI-only and modular planner-grounder methods.

#### 4.1. Performance on OSWorld

On the comprehensive OSWorld benchmark, CoAct-1 exhibits superior task completion rates and efficiency:
- **Overall Success Rate:** CoAct-1 achieves a success rate of **60.76%** within the 150-step limit, surpassing leading agentic frameworks such as Agent S2.5 w/ o3 (55.98%) and GTA-1 w/ o3 (53.07%).
- **Early Task Completion:** At the 100-step mark, CoAct-1 already achieves a 59.93% success rate, exceeding the final success rates of all compared baselines.
- **Category-Specific Performance:** The advantages are notable in domains where programmatic control is highly effective:
 - Office: 64.80%
 - OS: 75.00%
 - Multiple Apps: 47.87%
 - VS Code: 78.26%
 This performance in areas involving complex data manipulation, file system interactions, and cross-application workflows highlights the efficacy of delegating backend operations to the Programmer agent.

#### 4.2. Performance on WindowsAgentArena

CoAct-1's capabilities successfully transfer to the WindowsAgentArena benchmark, demonstrating cross-OS generalization:
- **Overall Success Rate:** The system achieves an overall success rate of **52.5%** at 100 steps, a notable improvement over prior methods like Agent S2 (29.8%) and NAVI (19.5%).
- **System-Level and Utility Tasks:** CoAct-1 shows strong performance in tasks related to system settings and utilities:
 - Windows System: 83.3%
 - Windows Utils: 77.7%
These categories, which often involve interacting with file explorers, system configurations, and native applications, are well-suited for the script-based actions of the Programmer.
- **Scalability with Step Budget:** Performance consistently improves with an increased step budget, rising from 21.4% at 15 steps to 52.5% at 100 steps, indicating its capacity to solve more complex, long-horizon problems.

#### 4.3. Efficiency Analysis

The hybrid approach significantly enhances operational efficiency:
- **Average Steps:** CoAct-1 solves tasks in an average of **10.15 steps** on OSWorld (for passed tasks within a 100-step budget), a reduction compared to GTA-1 (15.22 steps) and UI-TARS (14.90 steps). While OpenAI CUA 4o shows fewer average steps (6.14), its overall success rate is substantially lower (31.40% vs. 59.93% for CoAct-1 at 100 steps), indicating CoAct-1's efficiency is coupled with higher effectiveness.
- **Role of Coding Actions:** Strategic use of coding actions contributes to the lower total steps per task. Coding is particularly beneficial in complex domains like LibreOffice Calc, Multi-apps, and direct OS interactions, where a single script can replace extended GUI sequences, thus minimizing error opportunities.
- **Failure Correlation:** Analysis indicates a positive correlation between the number of required actions and the task failure rate. By reducing the total number of steps, CoAct-1's hybrid approach not only accelerates task completion but also inherently reduces the opportunities for error.

#### 4.4. Impact of Backbone Models

The choice of backbone models for each agent component influences overall performance:
- **Orchestrator and Programmer Importance:** Performance is sensitive to the reasoning and instruction-following capabilities of the models selected for the Orchestrator and Programmer roles. Using OpenAI o3 for both roles yielded 58.72% success, compared to 43.43% with o4-mini for both.
- **Optimal Configuration:** The highest performance (60.76%) was achieved with OpenAI o3 for the Orchestrator, o4-mini for the Programmer, and OpenAI CUA 4o for the GUI Operator. This suggests that a powerful high-level planner (Orchestrator) is critical for task decomposition and delegation, complemented by a capable code generator (Programmer).

#### 4.5. Ablation Study (Pure GUI vs. Pure Coding)

An ablation study isolating the agent modalities confirms the synergy of the hybrid design:
- **Programmer-Only (Pure Coding):** Achieved 35.73% success with an average of 1.14 steps per task. This indicates high efficiency but limited scope, as many tasks still require GUI interaction.
- **GUI Operator-Only (Pure GUI):** Achieved 50.68% success with an average of 11.20 steps per task. This demonstrated broader task coverage but lower efficiency.
- **Full CoAct-1 (Hybrid):** Achieved 60.76% success with 10.15 average steps. This outcome demonstrates that the Orchestrator's ability to dynamically leverage the Programmer's efficiency for backend tasks and the GUI Operator's versatility for visual navigation yields a more robust and capable overall system.

### 5. Significance and Potential Impact

The introduction of CoAct-1 represents an advancement in the field of autonomous computer-using agents, particularly by challenging the exclusive reliance on Graphical User Interface (GUI) manipulation. The significance and potential impact of this work are multi-faceted:

#### 5.1. Enhanced Robustness and Efficiency in Computer Automation

The primary significance lies in demonstrating that integrating direct programmatic execution (coding) as a core action modality, alongside traditional GUI control, leads to substantial improvements in agent robustness and efficiency. By strategically allowing agents to bypass lengthy, error-prone GUI sequences for tasks like file management and data processing, CoAct-1 significantly reduces the average number of steps required to complete complex tasks. This reduction in interaction steps directly correlates with a lower probability of error, leading to higher success rates on challenging benchmarks. This capability is critical for developing automation solutions that can reliably handle long-horizon, multi-step tasks in real-world computing environments.

#### 5.2. A More Flexible and Scalable Paradigm for Agent Design

CoAct-1 introduces a hybrid action space that offers greater flexibility than previous GUI-only or even planner-grounder systems. The dynamic delegation mechanism by the Orchestrator enables agents to adapt their interaction strategy based on the nature of the subtask, choosing the most appropriate and efficient modality. This architectural paradigm suggests a more scalable path toward generalized computer automation, as it allows for the handling of a wider array of task types, from visually intensive UI navigation to precise, backend system operations that are difficult or impossible through GUI alone. This shift could influence future agent architectures to incorporate diverse action modalities beyond visual-motor control.

#### 5.3. Broadening the Scope of Automated Tasks

The significant performance gains in categories such as Office (especially spreadsheets), OS-level interactions, and multi-application workflows highlight the system's ability to automate tasks previously considered highly brittle or intractable for GUI-only agents. The Programmer agent's capability to write and execute Python or Bash scripts unlocks new possibilities for automating complex data transformations, system configurations, and cross-application data flows that often require programmatic precision. This expansion of automate-able tasks has implications for productivity tools, software development environments, and system administration.

#### 5.4. Insights for Future Research in Multi-Agent Systems and LLM Capabilities

The research provides valuable insights into the design of multi-agent systems, particularly regarding task decomposition, dynamic role assignment, and inter-agent communication (via summarized context). The ablation studies underscore the complementary strengths of coding and GUI modalities, validating the hybrid approach. Furthermore, the analysis of failure cases (high-level/ambiguous queries, reflection errors, and hallucinations) points toward critical areas for future research, including:
- **Improving intent inference and contextual reasoning** in large language models to better handle abstract or underspecified user goals.
- **Developing more robust reflection and verification mechanisms** within agents, especially for intermediate state changes that may not be visually apparent.
- **Mitigating hallucinations** in complex planning and action generation processes across all agent components.
- **Exploring integration with application-specific APIs/SDKs** to further enhance the Programmer's capabilities beyond general OS-level scripting.

In summary, CoAct-1 represents a methodological advancement by demonstrating the practical benefits of augmenting computer-using agents with coding actions. It offers a more robust, efficient, and flexible framework for generalized computer automation, with the potential to influence the design of future intelligent agents operating in digital environments and expand the range of tasks amenable to automation.
