# OxyGen: Unified KV Cache Management for VLA Inference under Multi-Task Parallelism

> [!summary] Summary
> OxyGen is an inference system for Mixture-of-Transformers vision-language-action models that treats the KV cache as one resource shared across tasks and control frames. Cross-task KV sharing prefills each observation once for both the action and language experts. Cross-frame continuous batching advances language requests by a calibrated per-frame budget. On pi0.5 it reaches up to 3.7x speedup, over 200 tokens/s alongside 70 Hz actions.

## Problem

- Existing MoT VLA inference stacks run each task in a separate forward pass, re-encoding the same observation per task and producing identical, redundant KV caches.
- Even with a shared cache, action and language tasks compete for a single on-robot GPU, and long language decoding blocks the hard per-frame action deadline.
- LLM serving techniques such as prefix caching and continuous batching assume identical autoregressive readers and run-to-completion requests, which break under read-only action denoising and frame-bounded decoding.

## Method

- ==Unified KV cache manager==: stores a ==resumable state== for each request (KV cache, token buffer, termination flag) with Store/Retrieve/Update/Remove, so language generation pauses and resumes across frames without recomputation.
- ==Cross-task KV sharing==: runs VLM ==prefill== once per observation and hands the cache out as separate ==per-expert views==, read-only for ==flow-matching== action denoising and appendable for language decoding.
- ==Cross-frame continuous batching==: stacks in-flight language requests from different frames into one decoding batch and advances each by an ==offline-calibrated k tokens per frame== after action denoising finishes.

## Results

- Up to **3.7x** speedup on RTX 4090 and **3.3x** on Jetson AGX Thor; action frequency rises from **19.1** to **70.5 Hz** and language throughput from **57.2** to **212.9 tokens/s**.
- Ablation: KV sharing alone gives **1.4x** for short decoding. Continuous batching holds about **60 Hz** on RTX 4090 at long decoding lengths, while the baseline falls from **49.9** to **19.1 Hz**.
- LIBERO success rates stay within **0.8%** of openpi. Power drops up to **47%** and energy per request up to **78%**, for **15%** extra memory. On the humanoid, language generation falls from **822** to **195 ms**.

## Takeaways

> [!tip] Key Insights
> - A model that can do several tasks does not run them faster on its own; how the inference system schedules shared state decides whether one unified model beats separate models.
> - In a physical control loop, treat language as soft-deadline background work spread across frames, so the hard action deadline stays protected while throughput scales with batch size.
> - LLM serving techniques transfer to robots only if they respect each expert's cache semantics; letting language appends into the action expert's read-only context would break correctness.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

The development of embodied artificial intelligence (AI) agents capable of complex interactions in real-world environments necessitates the ability to execute multiple tasks in parallel. Examples include robots manipulating objects while conversing with users or constructing environmental memories. This operational mode, termed multi-task parallelism, requires concurrent execution of temporally independent tasks from shared inputs, each potentially under distinct time constraints.

Recent advancements in Vision-Language-Action Models (VLAs), particularly those based on Mixture-of-Transformers (MoT) architectures, represent a step towards this goal. Unlike conventional VLAs that are often restricted to action generation and require running multiple models for diverse tasks (e.g., a VLA for actions and a Vision-Language Model (VLM) for language), MoT-VLAs incorporate modality-specific experts within a single model. This design allows for shared VLM backbones to produce heterogeneous outputs, such as actions and language, from a common observation. Architecturally, MoT-VLAs offer the potential for multi-tasking.

However, existing inference systems designed for VLAs, such as `openpi`, often fail to translate this architectural capability into efficient on-device multi-task parallelism. These systems typically employ an "isolated execution" paradigm, where each task (e.g., action generation, language generation) performs a separate forward pass of the same model, even when processing identical input observations. This approach leads to two primary inefficiencies: redundant computation, where shared observations are repeatedly encoded, and resource contention, as different tasks compete for limited hardware resources (e.g., a single GPU on a robot) despite having disparate deadlines (e.g., hard real-time deadlines for actions versus softer deadlines for language generation).

While Key-Value (KV) cache management is a well-established area in Large Language Model (LLM) serving, with techniques like prefix caching and continuous batching improving throughput in multi-tenant cloud environments, these methods are not directly applicable to MoT VLA inference. The paper identifies two MoT-specific challenges:
1. **Heterogeneous expert KV semantics:** In LLM serving, prefix sharing assumes homogeneous autoregressive readers. For MoT VLAs, an action expert might consume the prefill KV cache as read-only context across multiple denoising steps, while a language expert continuously appends new KV entries. Naive sharing of a mutable cache could lead to data inconsistencies.
2. **Frame-bounded language decoding:** Traditional continuous batching in LLM serving allows requests to run uninterrupted to completion. However, robotic control loops demand that language decoding advances by a calibrated step budget per frame and resumes across frames without recomputation, a pattern not natively supported by existing serving systems.

This work addresses these identified gaps by proposing a novel inference design centered on unified KV cache management. It aims to bridge the architectural multitasking potential of MoT-VLAs with efficient inference system design for resource-constrained robotic platforms, thereby moving beyond the limitations of isolated execution and unadapted LLM serving techniques.

### 2. Key Objectives and Motivation

The primary objective of this research is to enable efficient multi-task parallelism for Vision-Language-Action (VLA) inference in embodied AI agents, particularly for Mixture-of-Transformers (MoT) VLAs deployed on resource-constrained robotic platforms.

The motivation stems from the observed inefficiencies in current VLA inference systems when supporting concurrent tasks. Embodied AI agents frequently need to perform multiple cognitive and physical tasks simultaneously, such as object manipulation, environment narration for users, memory construction, and future planning. These tasks often operate on shared sensory observations but have diverse temporal requirements; for instance, robot actions demand strict real-time deadlines, while language-based tasks may have more flexible completion windows.

The paper identifies the root cause of these inefficiencies as **isolated KV cache management**. This approach, commonly found in existing systems like `openpi`, treats each task's KV cache independently, even when tasks share the same initial input observation. This isolation leads to two critical problems:

1. **Redundant Computation:** When multiple tasks are executed, the shared observation (e.g., visual input, language instruction) is encoded repeatedly by the model's backbone for each task. This redundant "prefill" computation generates identical KV cache entries for each task, leading to wasted computational resources and increased latency. The paper quantifies this, noting a 1.4x slowdown attributable to redundant prefill.

2. **Resource Contention:** Even if KV caches were somehow shared, different tasks compete for the finite computational resources (typically a single GPU on a robot). This contention results in tasks blocking each other, increasing overall latency and making it challenging to meet asymmetric deadlines. For example, language decoding, if run sequentially, can significantly delay action generation, violating the hard per-frame deadlines required for smooth robot control. The paper reports a 2.6x slowdown due to resource contention when language decoding steps increase.

Furthermore, applying existing KV cache optimization techniques from Large Language Model (LLM) serving directly to MoT VLA inference is insufficient due to specific architectural and operational differences:
- **Heterogeneous Expert KV Semantics:** Unlike LLM serving where prefix sharing often assumes homogeneous autoregressive decoding, MoT VLAs involve diverse expert consumers. An action expert might perform multiple denoising steps, treating the KV cache as read-only context, while a language expert appends new tokens autoregressively, modifying the cache. A simple mutable shared cache risks mixing these distinct access patterns.
- **Frame-Bounded Language Decoding:** Cloud LLM serving typically aims to run requests to completion in an uninterrupted manner (continuous batching). In robotic systems, language decoding must align with a physical control loop, advancing by a specific token budget per robot frame and resuming across frames without recomputation, a pattern that existing systems do not inherently support.

To address these challenges, the research proposes the following key objectives:
- To formulate multi-task parallelism as a target inference scenario for MoT VLAs and precisely identify the root cause of inefficiency in existing systems as isolated KV cache management.
- To design and implement a unified KV cache management system, named OxyGen, that treats the KV cache as a shared resource across tasks and over time.
- To develop two specific optimizations within this framework:
 - **Cross-task KV sharing** to eliminate redundant prefill computation of shared observations.
 - **Cross-frame continuous batching** to decouple variable-length language decoding from fixed-rate action generation, thereby enabling higher language throughput while respecting hard action deadlines.
- To validate the effectiveness of OxyGen by implementing it for a popular MoT VLA (𝜋0.5) and evaluating its performance on representative on-device robotic platforms, demonstrating significant speedups in both action frequency and language throughput without degrading action quality, and proving its real-world applicability on a humanoid robot.

### 3. Methodology and Approach

The core methodology of this research involves introducing **unified KV cache management** to enable efficient multi-task parallelism for Mixture-of-Transformers (MoT) Vision-Language-Action (VLA) models. The proposed system, named OxyGen, treats the KV cache as a shared resource, managed across tasks and over time, building upon the insight that the KV cache, derived from a shared VLM backbone and common observation, is a natural point for computational reuse and execution coordination.

#### 3.1. Preliminaries and Problem Formulation

The paper models MoT VLA inference in a multi-task embodied agent. At each control cycle (frame) *t*, the agent receives an observation *o<sub>t</sub>*. The inference process is divided into a prefill phase and a generation phase:
- **Prefill:** The VLM backbone (Θ<sub>VLM</sub>) processes *o<sub>t</sub>* to produce hidden states, keys (K<sub>t,l</sub>), and values (V<sub>t,l</sub>) for each of its *L* layers. The aggregated KV cache, K<sub>t</sub>, is modality-agnostic, representing the encoded observation.
- **Generation:** Modality-specific experts consume K<sub>t</sub>. The action expert (Θ<sub>Act</sub>) generates an action chunk A<sub>t</sub> via *S* denoising steps. The language expert (Θ<sub>Lang</sub>) generates text tokens y<sub>t</sub> autoregressively.
The problem is formulated to maximize language throughput (τ) while ensuring a minimum action frequency (f ≥ f<sub>min</sub>), recognizing the asymmetric deadlines of these tasks.

#### 3.2. Unified KV Cache Manager (M)

OxyGen centralizes KV cache management through a unified manager M, which supports two primary optimizations:

1. **Cross-task KV Sharing:** Within a single frame *t*, the observation *o<sub>t</sub>* is encoded only once to produce K<sub>t</sub>. This single K<sub>t</sub> is then "fanned out" to both the action expert and the language expert. This eliminates the redundant prefill computation that occurs in isolated execution paradigms. The action expert consumes K<sub>t</sub> as read-only context, while the language expert uses it as a prefix for autoregressive generation.

2. **Cross-frame Continuous Batching:** To manage language generation efficiently across frames, OxyGen introduces "resumable generation states" (σ<sub>t</sub> = {K<sub>t</sub>, y<sub>t</sub>, δ<sub>t</sub>}). Each state stores the KV cache (K<sub>t</sub>) for a specific language request (extended as generation progresses), its decoded tokens (y<sub>t</sub>), and a termination flag (δ<sub>t</sub>). This allows language generation to be interrupted at the end of a frame and resumed in a subsequent frame without recomputing prior tokens.
 The manager M maintains a set of active requests (R). For parallel decoding, it stacks the individual states of these active requests into a "batched state" (ˆσ). This batched state allows the VLM to process multiple language requests simultaneously in a single forward pass, amortizing computation costs.
 The per-frame budget *k* (number of tokens decoded per request per frame) is calibrated to ensure that batched language decoding fits within the remaining time after action denoising, thus preserving the hard action deadline while scaling language throughput with the active batch size.

#### 3.3. Per-Frame Execution Flow (Algorithm 1)

The combined optimizations result in a two-stage per-frame execution:
- **Stage 1 (New Request Processing):**
 - The system performs a single `Prefill` operation on the new observation *o<sub>t</sub>* to obtain K<sub>t</sub>.
 - The `ActionDenoise` expert uses K<sub>t</sub> to generate actions A<sub>t</sub>.
 - A new language generation state (σ<sub>t</sub>) is initialized with K<sub>t</sub> and stored in the manager.
- **Stage 2 (Batched Language Decoding):**
 - The newly created language request joins the set of active requests R.
 - The manager retrieves and batches all *m* active states into ˆσ.
 - `BatchedLanguageDecode` advances all *m* requests by *k* tokens in parallel.
 - The batched state ˆσ is then unbatched, and individual requests are either removed (if terminated) or updated and persisted for the next frame.

#### 3.4. Implementation and Evaluation Setup

- **Model:** OxyGen is implemented for 𝜋0.5, a popular MoT VLA, built on `openpi`, its official inference framework.
- **Hardware Platforms:** Evaluated on NVIDIA GeForce RTX 4090 (high-end desktop GPU) and Jetson AGX Thor (edge AI platform for on-device deployment), representing typical robotic compute environments.
- **Configurations:** Three robotic task configurations (LIBERO, DROID, ALOHA) are used, matching their input observation and control dimensionality.
- **Baselines:**
 - **Sequential isolated execution ("Baseline"):** Standard approach where action and language generation run sequentially within each frame, each with its own forward pass.
 - **Parallel isolated execution ("Parallel"):** Tasks run on individual processes in parallel, sharing a single GPU via CUDA Multi-Process Service (MPS), but without unified KV cache management.
- **Metrics:** Action frequency (Hz), language throughput (tokens/s), average batch size, memory consumption (GB), power consumption (W), energy per request (mJ), and action quality (task success rate).

#### 3.5. Generalization to Richer Settings (Discussion)

The paper discusses the extensibility of OxyGen:
- **More Experts:** The manager interface is designed to treat experts as opaque consumers of K<sub>t</sub>, allowing straightforward extension to more than two experts.
- **Parallel Decoding Schemes:** The resumable state (σ<sub>t</sub>) is compatible with advanced parallel or speculative decoding schemes beyond vanilla token-by-token generation.

### 4. Main Findings and Results

The evaluation of OxyGen demonstrates improvements in multi-task VLA inference efficiency across various scenarios and hardware platforms.

#### 4.1. End-to-End Performance

- **Overall Speedup:** OxyGen consistently accelerates parallel multi-task inference by up to **3.7x** compared to sequential isolated execution (Baseline). This speedup is observed on both the NVIDIA GeForce RTX 4090 and Jetson AGX Thor platforms across LIBERO, DROID, and ALOHA configurations.
- **Pareto Frontier Extension:** Unlike baselines, which exhibit a trade-off between action frequency and language throughput as language workload increases, OxyGen simultaneously improves both metrics. For instance, on RTX 4090, it achieves over 200 tokens/s language throughput and 60 Hz action frequency. On Jetson AGX Thor, it sustains over 27 Hz action frequency at comparable throughputs.
- **Impact of Language Workload:** Higher total decoding steps (N) and smaller decoding steps per frame (k)—implying a larger average batch size (B = N/k)—lead to greater speedups. This indicates that cross-frame continuous batching effectively leverages hardware parallelism.
- **Naive Parallelization:** The "Parallel" baseline, using CUDA MPS for isolated parallel execution, provided only modest improvements over the sequential baseline, confirming that simply running tasks in parallel without addressing redundant computation and coordinated scheduling is insufficient.

#### 4.2. Ablation Study

An ablation study isolates the contributions of the two core optimizations:
- **Cross-task KV Sharing:** This optimization alone (OxyGen w/o Batching) provides an initial speedup, estimated at 1.4x for shorter decoding steps on the RTX 4090. This gain is attributed to eliminating redundant prefill computation of the shared observation for different tasks.
- **Cross-frame Continuous Batching:** This optimization is crucial for scenarios with longer language decoding sequences (≥ 10 tokens). It enables OxyGen to maintain a nearly constant high action frequency (around 60 Hz on RTX 4090 and 27 Hz on Jetson AGX Thor), whereas baselines without batching experience significant degradation (e.g., the baseline's action frequency on RTX 4090 drops by 2.6x, from 49.9 Hz to 19.1 Hz, as language decoding steps increase). The overhead introduced by OxyGen's cross-frame scheduling remains modest.

#### 4.3. Workload Generalization

OxyGen demonstrates robustness across various request arrival patterns:
- **Uniform and Poisson Arrivals:** It maintains higher action frequency than the baseline. While a higher arrival rate increases the average batch size and total language throughput, it may decrease the action frequency *per request* if prefill costs become dominant. However, overall hardware utilization and total actions per second increase significantly (e.g., 4.4x in uniform arrivals).
- **Random Length Requests:** OxyGen maintains a consistent action frequency per request while dynamically handling varying numbers of concurrent requests of different lengths.

#### 4.4. Action Quality and Resource Efficiency

- **Action Quality:** OxyGen does not degrade the action quality of the 𝜋0.5 model. Task success rates on LIBERO test suites (e.g., LIBERO-Spatial, LIBERO-Long) are reproduced within ±0.8% of the officially reported `openpi` performance, indicating that the inference optimizations do not compromise robotic control.
- **Resource Efficiency:**
 - **Memory:** OxyGen introduces a modest memory overhead of approximately 15% compared to the baseline. In contrast, naive parallelization nearly doubles peak memory consumption.
 - **Power and Energy:** OxyGen substantially reduces average power consumption by up to 47% and energy per request by up to 78%. This efficiency gain is attributed to fewer memory accesses to VLM weights due to batched decoding, which optimizes data movement and computation. The naive parallel baseline, due to redundant computation and memory bandwidth contention, actually increases energy per request by 3%.

#### 4.5. Real-Robot Deployment

The benefits of OxyGen were validated on a real humanoid robot equipped with a Jetson AGX Thor module:
- The baseline inference (1030 ms) significantly exceeded the 333 ms action-execution window, blocking subsequent control cycles.
- OxyGen reduced total inference latency to 393 ms. Crucially, the action-critical prefill and denoising stage completed in 198 ms, fitting within the robot's action-execution window. The remaining 195 ms for language generation occurred after the action was produced, with its latency largely hidden behind the physical action execution. This demonstrates OxyGen's capability to enable real-time, multi-task control on constrained hardware.

### 5. Significance and Potential Impact

This research presents OxyGen, a system designed to improve the efficiency of multi-task Vision-Language-Action (VLA) inference, particularly for Mixture-of-Transformers (MoT) VLA models deployed on robotic platforms. The work's significance lies in its systematic approach to addressing bottlenecks in the practical deployment of sophisticated embodied AI agents.

**Key contributions and significance:**
1. **Enabling Efficient Multi-Task Parallelism:** The paper highlights and resolves the inefficiency of isolated execution in current MoT VLA inference systems. By introducing unified KV cache management, OxyGen moves beyond the architectural capability of MoT-VLAs to architecturally *and* inferentially support parallel tasks. This allows embodied agents to coordinate multiple tasks (e.g., manipulation, conversation, memory) concurrently from shared observations, a crucial step towards more human-like, versatile robotic intelligence.
2. **Addressing Core Bottlenecks:** The identification of isolated KV cache management as the root cause of redundant computation and resource contention in existing systems is a key insight. OxyGen directly tackles these issues through cross-task KV sharing and cross-frame continuous batching, leading to substantial performance gains.
3. **Tailored for Robotic Constraints:** The optimizations are specifically designed for the unique constraints of robotic platforms, such as limited hardware resources (e.g., a single GPU) and asymmetric task deadlines (hard real-time for actions, softer for language). This contrasts with cloud-based LLM serving techniques which operate under different assumptions.
4. **Significant Performance Improvements:** The reported speedups of up to 3.7x in both action frequency and language throughput on representative robotic hardware (NVIDIA GeForce RTX 4090 and Jetson AGX Thor) demonstrate a tangible improvement in inference capabilities. The ability to achieve over 200 tokens/s language throughput and 70 Hz action frequency simultaneously is a notable advancement for real-time embodied control and continuous cognitive functions.
5. **Resource Efficiency:** Beyond speed, OxyGen's reduction in power consumption (up to 47%) and energy per request (up to 78%) is significant for on-device deployment, where battery life and thermal management are critical. This improved energy efficiency contributes to the sustainability and operational longevity of robotic systems.
6. **Validated on Real Hardware:** The successful deployment and validation on a real humanoid robot using an on-board Jetson AGX Thor module confirm the practical applicability and effectiveness of OxyGen in real-world scenarios, ensuring that theoretical gains translate to tangible benefits for robotic control and responsiveness.

**Potential Impact:**
- **Advancement of Embodied AI:** OxyGen can facilitate the development and deployment of more capable, responsive, and autonomous embodied agents. By enabling simultaneous high-frequency control and complex language-based reasoning, it broadens the scope of tasks robots can perform in real-time.
- **Accessibility and Cost Reduction:** Lowering the computational and energy requirements for multi-task VLA inference makes advanced robotic research and deployment more accessible. This could reduce the entry barrier for researchers and developers, fostering innovation in the field.
- **Environmental Benefits:** Reduced energy consumption directly contributes to a smaller carbon footprint for robotic operations, aligning with broader sustainability goals in technology.
- **Foundation for Future Work:** The unified KV cache management framework is presented as generalizable, potentially serving as a foundation for optimizing other MoT backbones, integrating more diverse experts, and supporting advanced decoding schemes in future VLA systems.

**Limitations (as stated by the authors):** The empirical evaluation primarily focuses on one specific MoT VLA (𝜋0.5) with two experts (action and language). While the generalized nature of the manager interface is discussed, its performance and applicability to other MoT backbones and richer multi-expert configurations are left for future research.
