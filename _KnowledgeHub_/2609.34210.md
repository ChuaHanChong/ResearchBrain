# RLE-Bench: A Qualifying Exam for Coding Agents as Robot Learning Engineers

> [!summary] Summary
> RLE-Bench is a benchmark testing whether general coding agents can work as robot learning engineers. It has 51 simulated tasks in four workflows: interactive control, policy development, perception and estimation, and mechanical design. Hidden verifiers score each task, and the scores are aggregated into an RLE Index. Across 11 model-harness pairs the top agent scores 73.4, and all models struggle with physical consequences in design.

## Problem

- Existing robotics benchmarks such as LIBERO and RoboTwin evaluate individual artifacts like VLA policies or controllers, not the broader engineering capabilities coding agents exercise across the robot development process.
- Software and ML engineering benchmarks like SWE-bench and MLE-bench are purely digital, lacking physics-grounded feedback, so they cannot reveal whether agents reason about physical consequences of their code.
- CaP-X, the closest prior work, only evaluates code-as-policy controllers for manipulation, omitting policy training, perception and estimation, and mechanical design that real robotics development requires.

## Method

- Nine task families and 51 tasks across four workflows, each defined as instruction, dev environment, budget, ==artifact contract==, and ==verifier-controlled evaluation== with hidden scenes, dynamics, embodiments, and seeds.
- Diverse submitted artifacts: agent context, reusable ==harness code== plus manual, ==whole-body tracking== and ==nanoVLA== checkpoints, pose estimators, bin-clearing controllers, and ==MJCF mechanical designs== with controllers, each with a task-specific metric.
- **RLE Index**: ==equal-weight macro-average== of task, family, then workflow scores, plus per-workflow ==capability profiles==, cost accounting, and ==Harbor==-packaged ==sandboxed verifiers==, with three ==harness scaffolding levels== in RoboCasa control.

## Results

- GPT-6 Astra tops the leaderboard with an RLE Index of **73.4**, ahead of Claude Fable 5.1 at **64.0** and Claude Opus 5 at **53.4**; the weakest of **11** combinations scores **16.3**.
- Evaluation feedback helps within its scope: in **29 of 36** sessions the submitted policy beat the first dev evaluation, yet robustness subtasks fall **19** points on LIBERO and **41** on RoboTwin below dev scores.
- In mobile-base design all nine models get **zero** worst-arm static-stability credit despite passing structural validity checks; in pose estimation only flagship models build reliable occlusion handling.

## Takeaways

> [!tip] Key Insights
> - Richer external scaffolding helps most models but can stop helping, or interfere, once a model's own perception is strong enough, as seen with GPT-6 Astra at the base level.
> - Agent improvement is bounded by what feedback can measure: rehearsable objectives transfer to held-out evaluation, unseen perturbations do not, so hidden-robustness signals are needed to train robust agents.
> - Satisfying stated objectives is not physical understanding: agents pass structural checks yet miss coupled, delayed consequences such as stability under load, so physics-grounded verification exposes gaps text benchmarks hide.

## Detailed Report

### 1. Overview

Picture a robot facing a sealed box. Hidden ballast sits in one of four marked quadrants, and the robot has to work out which one. It cannot inspect the box. It has to probe it and reason from the physical response. The answer depends on what happens when the robot acts, not just on what it can see. In the benchmark's version of this task, there are three boxes, and the agent gives one irreversible answer per box, with no correctness feedback. RLE-Bench tests agents on many kinds of robotics development work like this, not on a single controller.

The hidden-center-of-mass task: the agent probes a sealed box to identify which marked quadrant contains the ballast. Source: [author project page](https://rle-bench.github.io/blog/).

### 2. A broader kind of robotics exam

Robotics engineering is broader than writing a controller. Agents must build and revise different kinds of artifacts and interpret feedback from physical interactions. They must also work within time, interaction, and compute limits. Existing robotics evaluations often judge an individual policy or controller, not this wider engineering process.

RLE-Bench has 51 tasks in nine families across four workflows. A workflow is one of four broad capability areas: interactive control, policy development, perception and estimation, and mechanical design. A family groups related tasks within a workflow.

In each task, the agent works in a development environment with limited resources. There it can observe, act, and build an artifact. Once development ends, a verifier checks the submitted artifact in a verifier-controlled environment with hidden conditions.

The results are summarized in the RLE Index, which is not a simple average over all tasks. Native task scores are averaged within families, family scores within workflows, and then the four workflow scores are averaged equally. The scores are normalized verifier rewards, not all success percentages.

Paper Figure 2: the four workflows, Interactive Control (35 tasks), Policy Development (9), Perception & Estimation (5), and Mechanical Design (2), with task counts and scope markers for the nine families. These are task-family counts, not performance results.

### 3. What the scores reveal

The paper reports results for 11 model–harness combinations. GPT-6 Astra scores 73.4 on the RLE Index and ranks first. Claude Fable 5.1 scores 64.0 and ranks second. This shows that the benchmark differentiates the tested systems across its chosen workflows. It does not show that either system is generally qualified to engineer real robots.

The pattern is uneven. The authors say the leading systems' advantage is most pronounced in interactive control and perception/estimation. Policy-development performance is more closely matched, and mechanical-design scores show smaller gaps.

Paper Figure 3: panels (a–d) show scores from 0–100 for model ranks 1–11 in each workflow. Panel (e) plots RLE Index against API cost in dollars on a logarithmic cost axis.

A plausible alternative is that success comes mainly from tool support. Family 01 tests this directly. The same five RoboCasa kitchen tasks run at three harness levels, which set how much help the agent gets:

- **L1:** basic robot and sensor APIs
- **L2:** adds reusable perception and grasp-planning utilities
- **L3:** adds privileged object and fixture positions

Richer scaffolding generally improves scores and reduces API costs for many models. GPT-6 Astra, however, already performs strongly at L1 and gains little or sometimes loses performance with added support. The authors interpret this as suggesting that external modules may sometimes interfere with a stronger model's own perception and reasoning. So the effect is not uniformly "more tools are better." The comparison does not establish that tool interference is the sole cause of any decline.

### 4. A test, not a license

RLE-Bench evaluates agents' work across a wider robot-learning engineering process. It checks the submitted artifacts under hidden conditions instead of judging a single policy. Its evaluation is exclusively in simulation, however. The paper says this does not establish real-world reliability or safety, and that the tested workflows cover only part of robot-learning engineering.
