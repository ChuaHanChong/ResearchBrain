# frax: Fast Robot Kinematics and Dynamics in JAX

> [!summary] Summary
> Researchers from Stanford University developed `frax`, a JAX-based library for robot kinematics and dynamics. It delivers low-microsecond computation times on CPU for real-time control and scales to over 100 million dynamics evaluations per second on GPU for parallel workloads, all while natively supporting automatic differentiation.

## Problem

- Existing rigid-body dynamics libraries, often C++-based, lack seamless and efficient integration with modern Python automatic differentiation tools like JAX.
- A unified framework for robot dynamics that performs efficiently across diverse computing architectures (CPU, GPU, TPU) without compromising on performance or ease of use is largely absent.
- Current solutions typically specialize in either low-latency CPU execution or high-throughput GPU workloads, requiring separate implementations or introducing overhead when bridging architectures.

## Method

- Introduced `**frax**`, a pure-Python library built on the JAX framework, specifically designed for high-performance robot kinematics and dynamics computations across multiple devices.
- Utilized a fully-vectorized formulation of rigid-body dynamics algorithms, employing an ancestor mask to enable fine-grained parallelism suitable for JAX's XLA compiler.
- Leveraged JAX's Just-In-Time (JIT) compilation, native automatic differentiation capabilities, and multi-device compatibility to create a cohesive and performant single codebase.

## Results

- Achieved low-microsecond CPU computation times (e.g., 4.09 µs for Franka Panda differential inverse kinematics), enabling kilohertz-rate control and demonstrating a 2-**5x** speedup over Python APIs of Pinocchio and MuJoCo.
- Showcased strong GPU scaling for parallel workloads, exceeding 100 million dynamics evaluations per second for batch sizes of 4096, performing comparably to or slightly faster than other JAX-backend libraries like MJX and BRAX.
- Exhibited significantly faster JIT compilation times of 1-2 seconds, compared to 6-12 seconds for competing JAX-based libraries, thereby improving the iterative development process.

## Takeaways

> [!tip] Key Insights
> - The vectorized dynamics approach, while theoretically increasing algorithmic complexity (O(n) to O(n^2)), translates to practical performance gains on accelerators due to XLA's ability to exploit fine-grained parallelism.
> - A pure-Python JAX-native library can offer competitive real-time performance for single-robot CPU control tasks compared to optimized C++ libraries, while providing superior scalability and automatic differentiation support for parallel GPU workloads.
> - Efficient JIT compilation and automatic differentiation within JAX simplify the development and deployment of complex, gradient-reliant control and planning algorithms in robotics.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

The field of robotics research, particularly in control, planning, and learning, relies heavily on efficient computation of rigid-body dynamics. This computational demand has led to the development of numerous libraries and frameworks, each often specializing in certain aspects or platforms.

Existing rigid-body dynamics libraries, such as Pinocchio, RBDL, RobCoGen, and RigidBodyDynamics.jl, provide implementations of algorithms like the Recursive Newton-Euler Algorithm (RNEA) and the Composite Rigid Body Algorithm (CRBA). Pinocchio is frequently cited for its performance among these. Concurrently, physics engines and simulators, including MuJoCo, Drake, and PyBullet for CPU, and more recently Isaac Lab, Newton, Genesis, BRAX, and MJX for GPU, are utilized to extract dynamic properties and simulate robot behavior.

Beyond core dynamics, there is also a parallel development of fast libraries for motion planning and inverse kinematics. These often incorporate GPU acceleration (e.g., curobo), Single Instruction/Multiple Data (SIMD) operations, or native JAX implementations (e.g., Pyroki). Differential inverse kinematics solutions with Python interfaces to compiled libraries (e.g., Pink, Mink) represent another category.

A significant recent focus in the field has been on the analytical and accelerated computation of gradients for rigid-body dynamics algorithms. This is critical for advanced applications such as nonlinear trajectory optimization, Model Predictive Control (MPC), and broader optimal control strategies.

Despite the existence of these various tools, the current landscape presents several limitations. A majority of the leading dynamics libraries are developed in C++, often providing Python bindings. While these bindings enable Python-based workflows, they can introduce development complexities and computational overhead. A major challenge lies in the lack of a unified framework that seamlessly operates across diverse computing architectures. Libraries optimized for low-latency CPU execution (e.g., Pinocchio, MuJoCo in C++) are generally not directly compatible with GPUs, and vice-versa for GPU-centric libraries (e.g., MJX, BRAX). Furthermore, integrating these C++-based libraries with modern automatic differentiation (AD) tools in Python, such as JAX, for machine learning or optimization-based control, frequently poses difficulties. The paper identifies a gap for a library that combines high performance, ease of use, multi-device compatibility (CPU, GPU, TPU), and robust automatic differentiation support within a single, integrated framework.

### 2. Key Objectives and Motivation

The primary motivation for this work stems from the identified need for rigid-body dynamics libraries that exhibit high performance, ease of use, and compatibility across various computing architectures, specifically CPUs and accelerators (GPUs, TPUs). While existing libraries often excel in either low-latency CPU execution or high-throughput GPU workloads, few provide a cohesive framework that addresses both without compromising on performance or user experience. The difficulties associated with integrating C++-based libraries into Python-centric workflows, particularly when leveraging automatic differentiation for optimization and learning, further underscore this necessity.

To address these limitations, the central objective of this research is to introduce `frax`, a JAX-based library specifically designed for robot kinematics and dynamics computations. The authors outline several key goals for `frax`:

1. **Unified High-Performance Interface:** To provide a single, pure-Python interface for robot kinematics and dynamics that delivers high performance across CPU, GPU, and TPU. This aims to bridge the gap between CPU-optimized and GPU-optimized solutions.
2. **Efficient Real-time Control and Parallelization:** To enable efficient real-time control for single-robot applications on CPUs and to facilitate massive parallelization for multi-instance workloads on GPUs and TPUs. This is pursued through a fully-vectorized approach to rigid-body dynamics.
3. **Automatic Differentiation Support:** To natively support automatic differentiation, leveraging JAX’s capabilities, thereby simplifying the implementation of optimization-based methods, machine learning, and advanced control strategies that require gradients of robot dynamics.
4. **Competitive Performance Metrics:** To achieve low-microsecond computation times on CPU, making it suitable for kilohertz-rate control, and to demonstrate scalability on GPU to millions of dynamics evaluations per second for large-scale simulations or learning environments.
5. **Ease of Use and Development:** To offer a user-friendly, pure-Python environment that simplifies prototyping, development, and deployment of robot control and planning algorithms.
6. **Open-Source Contribution:** To release `frax` as an open-source library, fostering its adoption and further development within the robotics community.

By achieving these objectives, `frax` aims to provide a versatile and performant tool for the evolving demands of robot control, planning, and learning research, offering a balance of speed, flexibility, and architectural compatibility.

### 3. Methodology and Approach

The `frax` library is developed as a pure-Python library built on the JAX framework, which underpins its core capabilities for high performance and multi-device compatibility.

**JAX-Based Implementation:**
The selection of JAX as the foundational technology is central to `frax`'s approach. JAX provides several key advantages:
- **Just-In-Time (JIT) Compilation:** JAX functions are compiled to optimized machine code using XLA (Accelerated Linear Algebra), which significantly reduces runtime overhead and allows for aggressive compiler optimizations.
- **Device Compatibility:** JAX natively supports execution on CPUs, GPUs, and TPUs using the same Python code, eliminating the need for separate implementations for different hardware.
- **Automatic Differentiation (AD):** JAX provides built-in, efficient automatic differentiation capabilities, allowing gradients of arbitrary numerical functions to be computed directly.

**Vectorized Rigid-Body Dynamics:**
A distinguishing feature of `frax` is its fully-vectorized formulation of rigid-body dynamics algorithms, departing from the traditional recursive traversal methods (e.g., Featherstone's algorithms).
- **Ancestor Mask and Parallelization Strategy:** Instead of recursive loops, `frax` employs an ancestor mask, `U ∈ {0, 1} ^ {n×n}`, to encode the kinematic tree structure. `U_ij = 1` if joint `j` is an ancestor of joint `i` (including `i` itself). This matrix allows summations across the tree to be performed using matrix multiplication, assuming spatial quantities (velocities, accelerations, forces) are expressed in a common reference frame. This approach, while appearing in older literature, is less common in modern libraries. The use of this mask enables matrix operations to replace recursive loops for algorithms like RNEA and CRBA, fostering fine-grained parallelism.
- **Computational Complexity Considerations:** The vectorized approach intentionally increases the theoretical algorithmic complexity for single evaluations. Specifically, RNEA's complexity transitions from O(n) to O(n^2), and CRBA's from O(nd) to O(n^2), where `n` is the number of degrees of freedom (DOFs) and `d` is the maximum tree depth. This complexity trade-off is justified by the performance gains achieved through the XLA compiler. XLA can exploit the fine-grained parallelism inherent in the vectorized matrix operations on CPUs, GPUs, and TPUs. GPUs, in particular, are optimized for operations with fewer sequential dependencies, making the vectorized form more suitable than recursive tree traversals. Additionally, for automatic differentiation, this structure avoids the computational cost of tracing gradients through extensively unrolled loops, contributing to faster evaluation and compilation of derivative computations.
- **Loop-Free Dynamics:** The design minimizes explicit Python loops. All dynamics terms are evaluated using array broadcasting. While forward kinematics still requires a loop, for serial kinematic chains (e.g., Franka Panda), this loop can also be replaced with an `associative_scan`, rendering both kinematics and dynamics computations entirely loop-free within the compiled graph.

**Batched Performance Design:**
The vectorized dynamics methods are engineered to exhibit high throughput across varying batch sizes, specifically leveraging GPU capabilities for large parallel workloads. Performance trends show that while CPU is faster for single instances due to GPU overhead, GPU performance surpasses CPU at batch sizes greater than 4, and scales effectively to thousands of instances.

**Library Features and Automatic Differentiation:**
- `frax` supports robot models loaded via URDF (Unified Robot Description Format) and provides specialized classes (`Manipulator`, `Humanoid`) for common kinematic structures. It includes native support and pre-tuned collision models for robots like the Franka Panda and Unitree G1.
- A core benefit of JAX integration is the efficient computation of gradients. `frax` leverages `jax.jvp` (Jacobian-vector product), which can often replace full Jacobian computations. This is particularly advantageous for high-DOF systems and for forming complex constraints (e.g., Lie derivatives for Control Barrier Functions, CBFs), where only the product of the Jacobian with a vector is needed, rather than the full Jacobian matrix. The library also includes analytical Jacobians for frequently used kinematic functions where direct computation is faster.

**Benchmarking Strategy:**
The performance of `frax` is evaluated by benchmarking its application in common robot control tasks, specifically differential inverse kinematics (IK-based) and operational space control (ID-based). Comparisons are made against:
- Compiled C++ libraries (Pinocchio, MuJoCo).
- Python APIs of these libraries, using NumPy for intermediate computations.
- Other JIT-compiled JAX libraries (MJX, BRAX).
Timing measurements were conducted on a desktop PC with an i9-14900KF CPU and RTX 4090 GPU. Python methods used `time.perf_counter` with `jax.block_until_ready` for JAX functions, while C++ methods used `clock_gettime` with `CLOCK_MONOTONIC`. Specific JAX configuration flags for optimal CPU performance are documented. The benchmark design emphasizes scenarios where multiple kinematic and dynamic terms are evaluated within a single JIT compilation region, representing a typical control loop workflow.

### 4. Main Findings and Results

The evaluation of `frax`'s performance across various computing environments and against established libraries yielded several findings regarding its capabilities for robot kinematics and dynamics.

**CPU Performance for Single-Robot Control:**
`frax` demonstrates performance on CPU that is competitive for real-time, single-robot control applications. For a Franka Panda manipulator, differential inverse kinematics computations were completed in 4.09 microseconds, and inverse dynamics (operational space control) in 7.03 microseconds. For a Unitree G1 humanoid, these times were 6.71 microseconds and 24.6 microseconds, respectively. These low-microsecond computation times indicate suitability for kilohertz-rate control loops.
In comparison to the Python APIs of Pinocchio and MuJoCo, `frax` achieved a 2-5x speedup. This performance gain is attributed to JAX's just-in-time (JIT) compilation, which enables reduced overhead, compiler fusions, and multi-threaded linear algebra operations. While highly optimized C++ implementations of Pinocchio and MuJoCo generally outperform `frax` for raw CPU speed, the performance gap was observed to be narrow, particularly for complex tasks like Unitree G1 operational space control. Other JAX-based libraries, such as MJX and BRAX, were found to be less efficient for single-robot control on CPU, exhibiting significantly longer computation times (e.g., approximately 1 millisecond for G1 inverse dynamics compared to `frax`'s 25 microseconds).

**GPU Performance for Parallel Workloads:**
When deployed on a GPU, `frax` exhibited strong scaling capabilities for parallel workloads. The same codebase used for CPU execution could scale to thousands of robot instances, achieving throughput rates exceeding 100 million dynamics evaluations per second for batch sizes of 4096. This performance positions `frax` as a viable option for massively parallelized applications in areas like reinforcement learning or large-scale planning.
Its GPU performance was observed to be comparable to, or slightly faster than, other JAX-backend libraries specifically designed for GPU compatibility, such as MJX and BRAX. This parity is expected given the shared underlying JAX framework.

**Automatic Differentiation Efficiency:**
The integration with JAX enables efficient automatic differentiation through complex functions of robot kinematics and dynamics. The library leverages Jacobian-vector products (JVPs) (`jax.jvp`) where feasible, which can be computationally more efficient than explicitly computing full Jacobian matrices, particularly for high-DOF systems or when deriving complex constraint terms for optimization-based control. This approach simplifies the derivation and implementation of advanced control and planning algorithms.

**JIT Compilation Times:**
A practical advantage noted for `frax` is its significantly reduced JIT compilation times. For the tested scenarios, `frax` compiled within 1-2 seconds, in contrast to MJX and BRAX, which required 6-12 seconds. While not impacting the "hot" loop execution speed, faster compilation times contribute to a more efficient and less frictional iterative development process for researchers.

**Validation and Open-Source Release:**
The performance and functionality of `frax` were validated on representative robotic systems, including a Franka Panda manipulator and a Unitree G1 humanoid. The library has been released as an open-source resource, providing access to its codebase and capabilities.

### 5. Significance and Potential Impact

The introduction of `frax` contributes to the field of robotics by addressing several long-standing challenges in rigid-body dynamics computation. Its primary significance lies in providing a unified, high-performance, and flexible framework that is compatible across multiple computing architectures (CPU, GPU, TPU) while integrating seamlessly with modern automatic differentiation (AD) tools.

**Contributions to Robot Control and Planning:**
- **Real-time Performance on CPU:** By achieving low-microsecond computation times, `frax` enables real-time, kilohertz-rate control for single robots on standard CPUs. This is crucial for hardware-in-the-loop applications where low-latency feedback is essential.
- **Scalability for Parallel Applications:** The demonstrated capability to scale to thousands of robot instances and achieve millions of dynamics evaluations per second on GPUs makes `frax` suitable for massively parallelized applications. This includes large-scale reinforcement learning (RL), population-based optimization, and complex trajectory optimization problems, which often require numerous parallel dynamics evaluations.
- **Enhanced Optimization-Based Methods:** The native and efficient support for automatic differentiation via JAX facilitates the development and deployment of optimization-based controllers, model predictive control (MPC), and other nonlinear optimization techniques that rely on gradient information of the robot dynamics. This capability simplifies the implementation of complex objective functions and constraints.

**Development Workflow and Flexibility:**
- **Pure-Python Interface:** The pure-Python implementation, combined with JAX, offers a more streamlined and flexible development experience compared to C++ libraries with Python bindings. This reduces development overhead and allows for faster prototyping.
- **Unified Codebase:** Researchers can write a single codebase that runs efficiently across CPUs, GPUs, and TPUs, eliminating the need for architecture-specific implementations. This simplifies code maintenance and portability.
- **Reduced Development Friction:** Faster JIT compilation times (1-2 seconds compared to 6-12 seconds for competing JAX-based libraries) can significantly improve the iterative development and tuning process, allowing researchers to quickly test and refine algorithms.

**Limitations and Future Directions:**
The paper acknowledges that `frax` is designed to be a more minimal library compared to comprehensive environments like Pinocchio or MJX, prioritizing performance within a focused scope. While C++ implementations may offer marginally faster control rates in certain contexts, `frax` provides a more flexible, AD-compatible Python interface that is sufficiently fast for many practical applications. It currently does not provide a full simulation environment like MJX, nor does it focus on solving global inverse kinematics problems.

Future development plans for `frax` include:
- Expanding support for additional collision geometries (e.g., capsules, boxes, ellipsoids).
- Implementing the Articulated Body Algorithm (ABA), analytical derivatives of RNEA, and direct inversion methods for the mass matrix.
- Improving support for other robot classes, such as quadrupeds, and integrating more built-in collision models for common robots.

In summary, `frax` represents a significant step towards a unified, performant, and user-friendly library for robot kinematics and dynamics. Its design fosters both real-time single-robot control and large-scale parallel computations, with robust support for automatic differentiation, thereby potentially impacting a broad range of future research and applications in robotics.
