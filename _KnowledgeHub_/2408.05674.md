# PS-TTL: Prototype-based Soft-labels and Test-Time Learning for Few-shot Object Detection

> [!summary] Summary
> PS-TTL enhances few-shot object detection by enabling detectors to adapt to novel classes during the testing phase without additional human annotation. The framework leverages a test-time learning module for pseudo-labeling and a prototype-based soft-label strategy for utilizing low-confidence predictions, achieving state-of-the-art results on PASCAL VOC and MS COCO benchmarks.

## Problem

- Few-shot object detection (FSOD) struggles to accurately model the data distribution of novel classes due to extremely limited labeled examples.
- Current fine-tuning based FSOD methods often overfit due to insufficient novel class samples, leading to poor generalization.
- Existing approaches either generate synthetic data that differs from real distributions or rely on unrealistic assumptions about novel instances in base data.

## Method

- Introduces ==PS-TTL==, a framework that employs ==Test-Time Learning (TTL)== using a ==mean-teacher network== to generate pseudo-labels for unlabeled test data.
- Implements a ==Prototype-based Soft-labels (PS)== strategy that leverages low-confidence detector predictions by assigning soft-labels based on cosine similarity to category prototypes.
- Continuously adapts the detector to novel class distributions during the testing phase by training a student network on both few-shot labeled data and pseudo-labeled test data.

## Results

- PS-TTL achieves state-of-the-art performance on the PASCAL VOC dataset across various few-shot settings (**1**, **2**, **3**, **5**, and **10** shots).
- The framework outperforms existing methods on the more challenging MS COCO dataset, demonstrating its effectiveness.
- Performance consistently improves with increasing training iterations, showing particular gains in extremely low-shot scenarios (**1-shot** and **2-shot**).

## Takeaways

> [!tip] Key Insights
> - Adapting the object detector during the testing phase using unlabeled test data can effectively address the data scarcity challenge for novel classes.
> - Leveraging low-confidence predictions by assigning them soft-labels based on similarity to category prototypes improves learning from limited data.
> - Dynamically updating category prototypes during test-time learning allows the model to better capture evolving understandings of novel classes.

## Detailed Report

### 1. Introduction

Few-shot object detection (FSOD) addresses a critical challenge in computer vision: how to detect objects in images when only a limited number of labeled examples are available. While conventional object detection methods require large amounts of labeled data for each object category, FSOD aims to leverage knowledge from abundantly-labeled "base" classes to detect "novel" classes with just a few examples.

Current fine-tuning based FSOD methods struggle to accurately model the data distribution of novel classes due to the scarcity of labeled examples. This paper introduces PS-TTL (Prototype-based Soft-labels and Test-Time Learning), a framework that addresses this challenge by learning from both the limited labeled examples and the unlabeled test data itself. This represents a paradigm shift in how few-shot object detection is approached, moving toward a more realistic scenario where the detector can adapt to novel data distributions during the testing phase.

### 2. Current Approaches and Limitations

The dominant paradigm in FSOD involves pre-training a detector on base classes with abundant data and then fine-tuning it on novel classes with limited examples. However, this approach faces significant challenges:

1. **Limited Samples**: Few-shot examples are insufficient to accurately model the data distribution of novel classes, leading to overfitting and poor generalization.

2. **Distribution Gap**: Methods that generate synthetic data often create samples that differ significantly from real-world data distributions.

3. **Unrealistic Assumptions**: Semi-supervised approaches assume that unlabeled novel instances are widely present in base data, which is often not the case in real-world scenarios.

These limitations motivate the development of more adaptive approaches that can leverage information available during the testing phase itself.

### 3. PS-TTL Framework

The PS-TTL framework consists of two main components:

1. **Test-Time Learning (TTL)**: This module employs a mean-teacher network to generate pseudo-labels for test data, allowing the detector to adapt to novel classes during the testing phase.

2. **Prototype-based Soft-labels (PS)**: This strategy leverages low-confidence detector predictions by assigning "soft-labels" based on their similarity to category prototypes.

The framework uses the available test data to continuously improve detection performance on novel classes, without requiring additional labeled data beyond the few-shot examples.

### 4. Test-Time Learning Module

The TTL module adapts the detector to the distribution of novel classes in test data through self-training. The process works as follows:

1. A teacher network, initialized from a detector fine-tuned on the few-shot examples, generates pseudo-labels for unlabeled test samples.

2. A student network is trained using both the original few-shot labeled data and the pseudo-labeled test data.

3. The teacher network is updated via Exponential Moving Average (EMA) of the student network's weights:

 ```
   θ_t = α * θ_t + (1-α) * θ_s
   ```

 where θ_t and θ_s are the parameters of the teacher and student networks, respectively, and α is the EMA coefficient.

4. This process is repeated as new test samples arrive, allowing the detector to continuously improve its performance on novel classes.

The primary advantage of this approach is that it enables the detector to learn from test data without requiring additional human annotation, making it particularly suitable for real-world deployment scenarios.

### 5. Prototype-based Soft-labels Strategy

The PS strategy addresses a key observation: many low-confidence detector predictions still correctly identify foreground regions but may misclassify the object category. Rather than discarding these predictions, PS-TTL leverages them through a prototype-based approach:

1. **Dual Threshold Mechanism**: The framework uses two confidence thresholds:
 - An upper threshold (δ_upper) for high-confidence predictions used as standard pseudo-labels
 - A lower threshold (δ_lower) to identify low-confidence predictions that still correspond to foreground objects

2. **Category Prototypes**: For each novel class, a prototype feature vector is maintained, initialized using the few-shot examples and updated during test-time learning.

3. **Soft-label Assignment**: Low-confidence predictions (between δ_lower and δ_upper) are assigned soft-labels based on their similarity to category prototypes:

 ```
   s_i = cos(f_i, p_c)
   ```

 where f_i is the feature of prediction i, p_c is the prototype of category c, and cos denotes cosine similarity.

4. **Knowledge Distillation Loss**: The soft-labels are used in a knowledge distillation framework, where the student network learns to match the soft distribution:

 ```
   L_KL = KL(q_i || p_i)
   ```

 where q_i is the predicted distribution and p_i is the soft-label distribution.

This strategy makes effective use of uncertain predictions that would otherwise be discarded, significantly improving the model's ability to learn from limited data.

### 6. Implementation Details

The implementation of PS-TTL builds upon standard object detection architectures:

1. **Backbone Network**: ResNet-50 or ResNet-101 with Feature Pyramid Network (FPN) is used as the feature extractor.

2. **Detection Head**: A standard Faster R-CNN detection head is employed with:
 - Region Proposal Network (RPN) for generating object proposals
 - ROI Head for classification and bounding box refinement

3. **Training Procedure**:
 - First, the detector is pre-trained on base classes with abundant data
 - Then, it is fine-tuned on the few-shot examples of novel classes
 - During testing, the TTL module is activated to adapt to test data distribution

4. **Prototype Updating**: Category prototypes are dynamically updated using a momentum mechanism:
 ```
   p_c = β * p_c + (1-β) * f_new
   ```
 where f_new is the feature of a new high-confidence prediction and β is the momentum coefficient.

The dynamic nature of prototype updating allows the model to better capture the evolving understanding of novel classes as more test data is processed.

### 7. Experimental Results

PS-TTL was evaluated on two standard FSOD benchmarks:

1. **PASCAL VOC**: The model achieves state-of-the-art performance in various few-shot settings (1, 2, 3, 5, and 10 shots).

2. **MS COCO**: Similarly, PS-TTL outperforms existing methods on this more challenging dataset.

The results demonstrate several key findings:

- PS-TTL shows consistent improvement across different shot settings, with the most significant gains in the extremely low-shot scenarios (1-shot and 2-shot).

- The performance improves with the number of training iterations, demonstrating the effectiveness of the continuous learning approach.

- The approach is particularly effective for challenging classes with high intra-class variation or classes that are prone to confusion with visually similar categories.

### 8. Ablation Studies

Several ablation studies confirm the effectiveness of the proposed components:

1. **Impact of TTL**: The TTL module alone provides significant improvement over the baseline fine-tuned detector, demonstrating the value of learning from test data.

2. **Contribution of PS Strategy**: Adding the prototype-based soft-labels further improves performance, especially in cases where high-confidence pseudo-labels are scarce.

3. **Threshold Selection**: The choice of confidence thresholds (δ_upper and δ_lower) affects performance, with the optimal values depending on the dataset and shot setting.

4. **Dynamic vs. Static Prototypes**: Dynamically updating prototypes during test-time learning yields better results than using static prototypes initialized only from few-shot examples.

5. **EMA Coefficient**: The choice of EMA coefficient (α) for updating the teacher network affects the stability and effectiveness of self-training, with values around 0.9-0.95 typically performing best.

These studies provide valuable insights into the design choices that maximize the effectiveness of the PS-TTL framework.

### 9. Conclusion

PS-TTL introduces a novel approach to few-shot object detection that addresses the fundamental challenge of limited data by leveraging test-time learning and prototype-based soft-labeling. The framework represents a significant advancement in making object detectors more adaptable to novel categories with minimal annotation effort.

Key contributions include:

1. A test-time learning paradigm that enables FSOD models to adapt to the distribution of novel classes during testing, without requiring additional labeled data.

2. A prototype-based soft-label strategy that leverages low-confidence predictions to improve learning from limited data.

3. State-of-the-art performance on standard FSOD benchmarks, demonstrating the effectiveness of the approach.

The PS-TTL framework has broad implications for practical applications of object detection in scenarios where collecting large labeled datasets is impractical, such as robotics, medical imaging, autonomous driving, and industrial inspection systems.
