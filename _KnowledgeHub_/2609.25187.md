# X-Planner: Event-Structured Task Planning for Embodied Intelligence

> [!summary] Summary
> X-Planner is a VLM-based planning front-end that turns instructions and multi-view observations into event-structured plans that condition a frozen world-action model. It outputs either discrete event states (initial plan, progress, current and next event, error recognition) or parallel latent CoT states via Staircase Decoding, anchored by frozen latent-to-text reconstruction. The event-mode system achieves the highest real-robot Task Progress on reasoning and generalization suites.

## Problem

- Embodied planners train on coarse task-level captions or fixed sub-goal lists that hide event boundaries, regrasps, retries and failures, while policy-collected failures overrepresent one policy's mistakes.
- Reasoning-based VLA planners commit to one externally imposed granularity, such as fixed-level text or sub-goal images and flow, and fixed-length chunks split or merge distinct behaviors.
- Explicit chain-of-thought decodes token by token, creating a serial critical path and error propagation, while most latent-CoT methods still keep autoregressive dependencies between latent steps.

## Method

- ==Multisource hierarchical planning data==: Ego, UMI and teleoperation demonstrations annotated on an ==L3 Task, L2 Subtask, L1 Action, L0 Segment hierarchy==, plus ==takeover-time labels== and ==human-designed failures== for error recognition.
- **Staircase Decoding**: a lightweight ==Mixture-of-Transformers== branch shares lower-layer visual-language computation up to a ==relay depth==, then updates multiple ==continuous CoT latents in parallel== through the upper layers.
- ==Frozen latent-to-text reconstruction== maps latents through a ==soft prefix== into a frozen small language model that must reconstruct the textual plan, plus ==L2 feature alignment== into the world-action model's text-embedding space.

## Results

- Offline two-step planning: BERTScore-F1 **0.9011** and Doubao Judge Overall **1.411**, above Qwen (**0.8878**, **1.367**) and Doubao (**0.8846**, **1.366**) but below kimi3 (**0.9108**, **1.434**).
- Real-robot Reasoning Manipulation: event-mode X-Planner averages **71.6** Task Progress versus **59.5** U-Scratch, **56.4** pi0.5, **32.7** DreamZero and **31.6** LingBot-VA; ordered button pressing reaches **64%** versus **31%** for the best baseline.
- Cluttered Generalization suite: **53.75** Task Progress versus **28.5** DreamZero, **24.0** pi0.5 and **18.5** U-Scratch; no ablations isolate the plan forms, staircase schedule or failure data.

## Takeaways

> [!tip] Key Insights
> - Action-grounded semantic events, with boundaries that follow behavior changes, make a plan unit that is readable in language, observable in video and executable by a downstream controller.
> - Adding an explicit planner front-end to a frozen world-action model gives the largest gains on ordered and instruction-conditioned tasks, where identifying task structure matters more than motor skill.
> - Caution: only the discrete event mode was tested on robots, with no ablations, variance or timing, so latent staircase decoding's benefits remain unproven.

## Detailed Report

### 1. Overview

Long-horizon robot manipulation requires more than choosing the next motion. A robot must identify and order the meaningful stages of a task, then pass them to a controller that can execute them. Take the instruction “Put the laundry into basket.” An illustrative plan breaks it into three steps: approaching the bed, grasping and lifting the garment, and placing it in the basket. X-Planner makes such stages explicit as action-grounded events and uses them as a handoff between an instruction and a downstream world-action model. On the reported reasoning and generalization suites, the event-mode system records the highest average Task Progress.

An instruction and multi-view observations enter the Qwen3.5 VLM. In event mode (upper branch), natural-language event descriptions pass through a text encoder/embedding route to a world-action model. In unified mode (lower branch), a Staircase Decoder produces parallel continuous CoT latents, which condition the world-action pathway. Along the bottom, the laundry example pairs three event captions with observation frames: approach the bed holding the blue laundry item; grasp and lift the garment; place it in the basket. This is the paper’s illustrative event-level rollout.

### 2. Events as a handoff

An event is a temporally coherent span of executable behavior, such as reaching, grasping, lifting, or placing. Its boundary follows a behavioral change, rather than being a fixed-length action chunk or one coarse task caption. The practical idea is to give a controller useful structure without requiring it to execute an entire task from an implicit instruction-to-action mapping.

Prior work frames embodied reasoning differently. [[2407.08693|Embodied Chain-of-Thought Reasoning]] generates textual plans alongside grounded details such as object boxes and gripper position. [[2503.22020|CoT-VLA]] first predicts future subgoal images. X-Planner instead centers the interface on semantic events. These events are meaningful in language, visible in demonstrations, and realizable through control. The paper reports no direct comparison against either method.

The planner also tracks execution as it unfolds. In intervention episodes, takeover times mark when error recognition is needed. Human-performed, deliberately designed failure demonstrations supplement errors from the collecting policy. Ongoing states include:

- current and next events
- normalized progress
- whether execution should continue
- error recognition

The episode-end marker denotes the last available media frame. It does not prove semantic task success.

### 3. What the robot tests show

Task Progress is a task-rubric score from 0 to 100. It credits partial completion, so it is not binary success. The tabletop bimanual-robot evaluation tests the complete event-mode, planner-conditioned system.

In the five-task Reasoning Manipulation suite, X-Planner’s reported mean is 71.60, versus 59.50 for U-Scratch, the strongest reported baseline there. In Generalization, the reported mean is 53.75, versus 28.50 for DreamZero, the strongest available baseline. LingBot-VA has no result for this suite.

X-Planner does not win every task. It ties U-Scratch on headphone sorting, U-Scratch scores higher on shape classification, and π0.5 scores highest on item pairing. Trial-level results and uncertainty estimates are unavailable, so these are comparisons of reported means, not a significance analysis.

Task Progress (0–100; higher is better). A, Reasoning Manipulation: π0.5 56.4, LingBot-VA 31.6, DreamZero 32.7, U-Scratch 59.5, X-Planner (event) 71.6. B, Generalization: π0.5 24.0, LingBot-VA N/A (no available result, not zero), DreamZero 28.5, U-Scratch 18.5, X-Planner (event) 53.8, rounded from the reported 53.75. There are no error bars because uncertainty estimates were not provided.

### 4. Events connect intent to action

Per-event textual plans give the controller an intermediate unit that is more informative than an implicit instruction. Realizing that plan physically is still left to the action model.

The measurements support the complete event-mode system on these tests. They do not establish the causal contribution of event plans, error supervision, or any individual model component. The U-Scratch baseline is a system-level reference, not an intervention that isolates X-Planner’s contribution. The latent interface and Staircase Decoding are proposed ways to reduce serial computation inside the planner. The paper does not establish lower end-to-end control latency.
