# ECoMEM: Explicit Concept Memory for Memory-Dependent Robot Control

> [!summary] Summary
> ECoMEM gives a VLA an explicit memory channel. A fixed, evidence-based Writer selects task-relevant concepts from a shared compositional library, recognizes them using OWLv2, SAM2 and robot state, and maintains typed records. A learned Reader turns those records into memory tokens that condition pi0.5. ECoMEM averages 82.42% on 16 RoboMME tasks, leading on 15, and reaches 86.1% versus 8.6% on two real-robot tasks.

## Problem

- Implicit-memory VLAs, such as long-context, recurrent, memory-bank and test-time-training policies, learn what to retain only through action supervision, which never specifies which past facts should persist or be revised.
- Policies trained only on control objectives can exploit shortcuts in current observations, previous actions or trajectory correlations, so accurate action prediction does not prove the relevant history is represented reliably.
- Existing explicit memories fall short: keyframes force the controller to recover facts from images, VLM summaries struggle with spatio-temporal reasoning, and text or scene-graph memories mostly feed high-level planners.

## Method

- **Shared Concept Library**: agent-coded concepts in four families (entity and spatial grounding, state and relation, event and progress, temporal and procedure), each with a perception-plus-robot-state recognizer and an explicit update rule.
- **Evidence-based Writer**: an instruction parser with ==dependency closure== activates only the needed concepts, grounds entity phrases via ==OWLv2== and ==SAM2==, and merges noisy detections using rules for confirmation, persistence through occlusion, deduplication and counting.
- **Learned Reader**: per-field ==embedding tables== are summed into one vector per record, and a small ==position-free Transformer== emits one ==memory token== per record into the pi0.5 prefix, trained by ==flow matching== with the Writer frozen.

## Results

- On 16 RoboMME tasks ECoMEM averages **82.42%**, **37.91 points** above FrameSamp+Modul (**44.51%**) and well above MemER (**42.38%**). It leads on **15** tasks and comes within **8.08 points** of human performance.
- Ablating spatial grounding, event and progress, or temporal order drops success from **84%** to **18%**, **62%** to **14%** and **60%** to **12%**. Generic entity queries cut PatternLock from **72%** to **2%**.
- On the real robot ECoMEM succeeds in **68 of 79** trials (**86.1%**) versus **5 of 58** (**8.6%**) for no-memory pi0.5. On ordered-sequence extraction the Writer scores **100%** versus **11.8%** for a fine-tuned Qwen3-VL-8B.

## Takeaways

> [!tip] Key Insights
> - Separate what to remember from how to act: building memory from fixed evidence rules avoids the shortcut learning that action-only supervision invites in history-conditioned policies.
> - More memory is not better: irrelevant records actively distract the policy, so choosing what to track for each task matters as much as how much the memory can hold.
> - Direct VLM video extraction handles current state well but collapses on temporal composition, so composing grounded events symbolically is a more reliable way to remember order and counts.

## Detailed Report

### 1. Overview

A robot is asked to scoop beans from a tray onto a plate for a set number of cycles. Each time, it faces a small but consequential question: did that scoop actually carry beans? If an empty attempt is mistaken for a completed cycle, the robot's progress record will be wrong, and so will its next action. ECoMEM keeps an evidence-grounded record of what happened separate from the policy that decides what to do next. In the authors' illustration, an empty scoop leaves the count unchanged, which prompts a retry rather than falsely advancing progress.

Paper Figure 1. Two task instructions show cup round trips and scoop-and-pour cycles. In the scoop sequence, successful events advance the count. A low-payload attempt leaves the count at 2/3, and a retry follows before eventual completion. The figure shows the proposed record-and-retry logic. It does not establish a success rate.

### 2. From observations to records

A task is memory-dependent when two histories can call for different actions despite the same instruction and current observation.

ECoMEM's memory is built from two parts:

- **Concept:** a reusable type of task-relevant fact.
- **Record:** one grounded instance of that fact.

The concepts fall into four families:

- **Entity and spatial grounding** says what object is where.
- **State and relation** says what condition or relation holds.
- **Event and progress** says what has happened and how much of the goal is complete.
- **Temporal and procedure** says in what order events occurred and what step comes next.

The first two describe the world; the last two describe the past.

The Writer selects the concepts the instruction requires and grounds them to the named entities. Recognizers then combine visual evidence with robot state, such as gripper state and end-effector motion, to assess spatial relations and interaction events.

Explicit updates turn these noisy outputs into stable records:

- They accumulate evidence before confirming a state.
- They preserve an occluded object's last supported location rather than treating a missed detection as evidence against it.
- They record a confirmed event once and count distinct events.
- They advance ordered progress only when prerequisites are met.

An instruction can specify the goal count, but only observed completion events advance the observed count.

The Reader converts the structured records into memory tokens. These join the image and language tokens for the vision-language-action (VLA) model. Writer recognition and memory writing stay fixed during policy training. The Reader and policy are trained to use the records.

Paper Figure 2. In the Writer, instruction, frame, and proprioception feed entity tracking, concept activation, and evidence filtering. The Writer consults a shared Concept Library and sends records to the Reader. The VLA receives visual, language, and memory tokens and produces actions.

### 3. What the tests establish

**Benchmark.** RoboMME covers 16 memory-dependent tasks. Success is reported per task as a percentage. The summary score, AVG, is the task-equal mean of those 16 rates.

On this benchmark, ECoMEM reaches 82.42% success. That is 37.91 percentage points above the strongest evaluated baseline, FrameSamp+Modul at 44.51%. ECoMEM also leads the evaluated policies on 15 of 16 tasks.

The authors evaluated ECoMEM on 50 validation episodes per task with three policy sampling seeds. The baseline results are the ones reported by RoboMME.

ECoMEM does not lead on PickHighlight, where MemER is 8 points higher. The authors interpret this as consistent with a transient visual cue being preserved in a retrieved keyframe. On InsertPeg, ECoMEM scores 40.67%, well below human performance. Remembering the insertion side and endpoint does not itself ensure precise execution.

**Real robot.** The authors built two new real-robot tasks:

- **CupSwitch** reuses the existing grounding, persistence, pick-and-place, counting, and goal concepts, without a new recognizer or update rule.
- **ScoopPour** adds one concept, `SCOOP(tool, material)`, to recognize a scoop carrying beans. A cycle counts only when the scoop-and-pour succeeds. An empty attempt leaves progress unchanged so the robot can retry.

Across the two tasks, ECoMEM succeeds in 68/79 trials (86.1%). The comparison is a no-memory π₀.₅ policy fine-tuned on the same demonstrations, which succeeds in 5/58 trials (8.6%). Success requires exactly the requested number of cycles. The trials are unpaired and unequal in number, so this is evidence from these tested settings rather than a matched-trial estimate.

### 4. Takeaway

The instruction supplies the desired count, but the evidence-grounded memory records what has actually been completed. That separation lets the same counting machinery distinguish a failed scoop from a completed cycle. The paper's central boundary is that memory cannot replace control skill.
