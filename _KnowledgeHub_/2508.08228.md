# LL3M: Large Language 3D Modelers

> [!summary] Summary
> LL3M is a multi-agent system that reformulates 3D shape generation as writing Blender Python code with pretrained LLMs, no training data or finetuning. Planner, retrieval, coding, critic, verification, and user agents share code context and use a Blender documentation RAG. It produces detailed, editable assets with materials and supports fast iterative user edits.

## Problem

- Representation-centric generative 3D models need large 3D shape collections or costly 2D-prior optimization, and yield outputs that lack control, interoperability with graphics pipelines, and interpretability.
- Direct LLM mesh generation outputs low-level vertices and faces, which miss high-level structure shared across shapes and give no interpretable, tunable parameters for editing.
- Prior Blender-code LLM work is narrow: primitives only, materials only, predefined procedural scenes, or asset placement. Single-LLM BlenderMCP yields less detailed assets and limited iterative refinement.

## Method

- ==Three-phase pipeline==: initial creation, ==automatic refinement==, and ==user-guided refinement==, driven by an ==external controller== that orders agents and shares full conversation and ==code context== across all of them.
- Six ==specialized agents==: planner splits the prompt into subtasks, retrieval supplies documentation, coding writes and executes ==Blender code==, critic reviews renders, verification checks fixes, user agent processes edits.
- **BlenderRAG**: a ==retrieval database== built from ==Blender API documentation== gives the coding agent examples, types, and functions for advanced operations like ==B-meshes==, ==geometry modifiers==, and ==shader nodes==, improving correctness.

## Results

- BlenderRAG raises the average count of unique complex function calls from **1.20** to **5.86** (about **5x**) and cuts total execution errors by **26%** (**3.29** to **2.43**), tested on 17 objects.
- Runtime averages about **4 minutes** for initial creation and **6** for auto-refinement, but each user edit takes only about **38 seconds** versus about **10 minutes** to regenerate from scratch.
- About **59%** of shown edit examples needed a single instruction, others needed **3 to 4** follow-ups. Ablations show each agent and shared code context improve quality; LL3M beats BlenderMCP qualitatively.

## Takeaways

> [!tip] Key Insights
> - Code is a strong 3D representation: shared structure such as loops, modifiers, and node setups across categories lets pretrained LLMs generate diverse, editable assets without any 3D training data.
> - Retrieval of API documentation both enables more sophisticated operations and lowers error rates, so grounding code agents in version-specific docs helps capability and reliability together.
> - Persisting code as shared state makes edits localized and cheap, preserving asset identity. Remaining limits are VLM critics missing spatial errors, so spatial edits need multiple human follow-ups.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

The field of 3D content generation has seen rapid advancements, largely driven by deep learning models. Traditionally, these approaches have focused on designing bespoke geometric representations (e.g., implicit functions like Neural Radiance Fields (NeRFs), Gaussian splatting, or explicit forms like point clouds, voxels, and meshes) and training generative models on vast collections of 3D data. While these "representation-centric" methods excel at producing high-fidelity visuals, they often suffer from several limitations: lack of fine-grained control, poor interoperability with existing graphics pipelines, limited interpretability for artists, and a requirement for extensive datasets or costly optimization processes.

A distinct line of research involves "program-based generation," where 3D objects are described using domain-specific languages (DSLs) or procedural frameworks. Projects like GeoCode, PyTorchGeoNodes, and ShapeAssembly aim for high-level abstraction and interpretability. However, these often impose category-specific constraints or restrictive assumptions on the types of geometric primitives, limiting their generalizability.

More recently, the success of Large Language Models (LLMs) in code generation has inspired efforts to apply them to 3D tasks. Initial attempts included direct mesh token prediction, which often resulted in low-level, uninterpretable representations lacking high-level structure. Other LLM-based approaches for Blender focused on specific subtasks, such as retrieving and placing existing assets (SceneCraft), generating materials for existing geometry (BlenderAlchemy), generating parameters for predefined procedural scenes (3D-GPT), or creating simple primitive shapes (L3GO). These methods, while innovative, remained constrained in their scope and the completeness of the generated 3D assets.

LL3M distinguishes itself significantly by **breaking away from conventional representation-centric generative modeling** and instead **reformulating 3D shape generation as a comprehensive code-writing task** within Blender. Unlike previous LLM-based systems, LL3M aims to generate *complete, open-vocabulary 3D assets*—including detailed geometry and appearance attributes—by writing *interpretable, modular Python code*. This unique approach eliminates the need for specialized 3D datasets or finetuning, leveraging the inherent code generation capabilities of pre-trained LLMs. By producing human-readable Blender Python scripts, LL3M directly addresses the shortcomings of existing methods by offering enhanced control, interoperability, and interpretability, thereby seamlessly integrating AI-driven generation with traditional artist workflows. The paper also positions itself in direct comparison with BlenderMCP, which is highlighted as the most relevant baseline, claiming superior asset quality and iterative refinement capabilities.

### 2. Key Objectives and Motivation

The primary objective of LL3M is to **enable the scalable generation of editable 3D geometry from natural language text prompts** by harnessing the power of pre-trained Large Language Models to write high-level, interpretable Python code for Blender.

This ambitious goal is driven by several key motivations:
- **Addressing Limitations of Current 3D Generative Models:** Existing methods often produce 3D assets that are difficult to control, modify, or integrate into professional graphics pipelines due to their black-box nature or low-level representations. LL3M seeks to overcome this by generating structured, human-readable code.
- **Leveraging LLMs for Procedural Generation:** Recognizing the impressive code generation capabilities of modern LLMs, the authors hypothesize that these models can be effectively utilized to write procedural Blender scripts, inherently offering abstraction, reusability, and modularity that other 3D representations lack.
- **Enhancing Modularity and Editability:** Code serves as an excellent medium for representing 3D assets because it naturally supports modularity. This allows for precise, localized edits and iterative refinements by adjusting parameters or modifying specific code blocks, contrasting with the often "all-or-nothing" regeneration required by other text-to-3D systems.
- **Seamless Integration with Artist Workflows:** By generating native Blender Python code, LL3M ensures that the output is fully compatible with existing 3D software and artistic pipelines. This empowers artists to easily inspect, understand, and further refine AI-generated assets, fostering a collaborative, co-creative design process.
- **Open-Vocabulary and Comprehensive Asset Creation:** The system aims to move beyond generating specific object categories or limited procedural programs. LL3M is motivated to create diverse, detailed 3D assets, complete with intricate geometry and rich appearance attributes, from open-ended text descriptions.
- **Efficiency and Accessibility:** By relying on pre-trained LLMs augmented with a knowledge base (RAG), LL3M bypasses the need for large, specialized 3D datasets for training, or computationally expensive neural optimizations typically found in many generative 3D models. This makes the process more efficient and potentially accessible.

### 3. Methodology and Approach

LL3M employs a novel **multi-agent system** that coordinates various specialized Large Language Models (LLMs) to generate and refine 3D assets by writing Python code in Blender. The core concept is to treat 3D asset creation as a code-writing and debugging task, facilitated by a **Retrieval-Augmented Generation (RAG)** knowledge base specific to Blender.

**Core Components:**
- **Multi-Agent Framework:** Orchestrated by an external controller, a team of six specialized LLM agents communicate through a shared context, allowing awareness of previous attempts and iterative refinement. This framework is implemented using the AutoGen framework.
 - **Planner Agent (GPT-4o):** Decomposes the initial user prompt into a series of manageable 3D modeling subtasks.
 - **Retrieval Agent (GPT-4o):** Queries **BlenderRAG** (a RAG database built from 1,729 official Blender 4.4 documentation HTML files using RAGFlow) to retrieve relevant Blender API documentation, code examples, and solutions to potential errors. This agent acts as the system's "Blender expert."
 - **Coding Agent (Claude 3.7 Sonnet):** The primary code generator. It takes subtasks and retrieval agent feedback to write, execute, and incrementally refine Blender Python scripts.
 - **Critic Agent (Gemini 2.0 Flash, orchestrated by GPT-4o):** Incorporates visual awareness. It renders 5 views of the current 3D asset in Blender, then uses an external Vision-Language Model (VLM) to analyze these renders, identify visual discrepancies or flaws (e.g., disconnected parts), and propose concrete fixes as text.
 - **Verification Agent (Gemini 2.0 Flash, orchestrated by GPT-4o):** Follows the Critic. After the Coding Agent attempts fixes, this agent re-renders the scene and uses the VLM to compare the new renders against the previous critiques and renders, verifying if the proposed solutions were successfully applied.
 - **User Proxy Agent (Human):** This is a non-LLM interface that allows direct user input for iterative refinement instructions, providing an intuitive co-creative loop.

**Three-Phase Process:**
1. **Initial Creation Phase:**
 - The user provides an initial text prompt.
 - The Planner Agent breaks it down into subtasks.
 - For each subtask, the Retrieval Agent fetches relevant Blender documentation from BlenderRAG.
 - The Coding Agent then writes and executes Blender Python code, incorporating prior subtask code.
 - An internal loop handles compilation/execution errors: if an error occurs, the Retrieval Agent is invoked to find solutions from BlenderRAG, and the Coding Agent attempts to fix the script.
 - This phase outputs an error-free Blender script that generates a preliminary version of the 3D asset.

2. **Automatic Refinement Phase:**
 - This phase aims to automatically improve the asset's quality and alignment with the prompt by integrating visual feedback.
 - The Critic Agent renders the current asset and uses a VLM to identify visual issues (e.g., "legs aren’t attached to the seat") and suggest textual solutions.
 - The Coding Agent receives these critiques and modifies the *existing* Blender code (crucially, operating on the previous script rather than rewriting from scratch) to address the issues.
 - The Verification Agent then checks if the proposed fixes were successfully implemented by comparing new renders with the pre-fix state and the critiques.
 - If issues persist, the loop between the Critic, Coding, and Verification Agents continues until the asset meets the visual criteria.
 - This phase outputs a visually improved 3D asset script.

3. **User-Guided Refinement Phase:**
 - This final phase enables human-in-the-loop co-creation.
 - Users can provide additional natural language prompts (e.g., "add lemons to the tree," "change the style to steampunk") to further refine the 3D model.
 - The Coding Agent receives these instructions and makes localized edits to the existing Blender script.
 - The Verification Agent confirms the successful application of user-requested changes.
 - This iterative cycle continues until the user is satisfied, allowing for highly customized and precise modifications without regenerating the entire asset. Users can also directly tweak parameters exposed in the generated Blender nodes or code.

### 4. Main Findings and Results

LL3M demonstrates remarkable capabilities in generating and refining 3D assets through its code-writing paradigm, showcasing several key findings:

- **Generality and Versatility:** LL3M can generate a wide array of 3D assets across diverse categories, including vehicles, musical instruments, animals, and intricate scenes, without explicit class constraints. Figures 4, 8, 9, and 14 illustrate its ability to produce objects with complex geometry, varied textures, materials, and hierarchical part arrangements. The system can also generate plausible, distinct variations from generic prompts, as shown with different "tree" outputs (Figure 7).
- **High Fidelity and Contextual Understanding:** The multi-phase refinement process, especially the auto-refinement phase, significantly enhances the fidelity of the generated assets to the input text. Figure 6 demonstrates how an initial "red bucket" cylinder is refined into a realistic tapering bucket with reflective plastic material. The system also exhibits contextual understanding, generating a fire blast at the base of a "blasting off" rocket (Figure 4). It supports multi-modal inputs, accurately translating visual details from images into 3D models (Figure 8), and generating complex scenes with appropriate spatial relationships (Figure 9).
- **Structured, Interpretable, and Editable Code:** A central finding is the production of human-readable, well-documented, and modular Blender Python code (Figure 13). This code uses clear variable names and logical structures, making it highly interpretable. This interpretability is crucial for enabling precise, localized edits, either by modifying code parameters (e.g., adjusting a fish's size in Figure 1) or by adding new code without altering existing structures (e.g., adding a candle to a lantern).
- **Effective User-Guided Refinement:** LL3M excels in iterative co-creation. Users can modify materials (Figure 11), apply high-level stylistic changes (e.g., "steampunk" to hats, Figure 12), and make fine-grained parameter adjustments directly in Blender (Figure 10). The system supports complex, sequential edits, maintaining asset coherence and even interpreting semantic actions like a character "eating ice cream" by adjusting pose and gaze (Figure 3).
- **Qualitative Superiority over Baselines:** Compared to the most relevant baseline, BlenderMCP, LL3M consistently produces higher-quality 3D models with richer details and greater plausibility (e.g., accurate cat whiskers, strawberry seeds), attributed to its sophisticated multi-agent architecture (Figure 14).
- **Quantitative Impact of BlenderRAG:** An ablation study quantitatively demonstrates the critical role of BlenderRAG. Incorporating this knowledge base led to a **5-fold increase in the use of complex Blender operations** (from an average of 1.20 to 5.86 unique complex calls per script). Surprisingly, BlenderRAG also **reduced the total code execution error rate by 26%** (from 3.29 to 2.43 errors), indicating that providing accurate, version-specific documentation enhances code sophistication while improving correctness (Table 1, Figure 15).
- **Importance of Multi-Agent Collaboration and Context Sharing:** Ablation studies confirm that each agent (Planner, Retrieval, Critic) progressively improves the quality and fidelity of the generated shapes (Figure 16). The shared code context across agents is vital for enabling consistent editing and incremental refinement, preventing the system from regenerating assets from scratch with each modification (Figure 17).
- **Runtime Efficiency for Iterative Edits:** While initial creation and auto-refinement take about 4 and 6 minutes respectively, subsequent user-guided edits average only 38 seconds per instruction. This rapid iteration capability is a significant advantage for practical design workflows.

**Limitations:** The paper acknowledges that the auto-refinement phase, reliant on VLMs, might not perfectly correct all spatial artifacts (e.g., disconnected handles in Figure 18). However, these remaining flaws are typically easily rectifiable through further user-guided instructions, highlighting the strength of the system's iterative editing capabilities.

### 5. Significance and Potential Impact

LL3M represents a significant advancement in the field of 3D content creation, offering a compelling new paradigm with broad implications:

- **Redefining 3D Generation:** By framing 3D asset creation as a code-writing task, LL3M shifts away from purely data-driven, black-box generative models. This approach leverages the logical and procedural reasoning capabilities of LLMs, opening new avenues for controllable and interpretable 3D design.
- **Bridging AI and Artistic Workflows:** A key impact is the creation of AI-generated assets that are not just visually appealing but also fully integrated into professional 3D pipelines. The output—human-readable Python code—empowers artists to understand, modify, and build upon AI-generated designs, fostering a true co-creative environment. This addresses a major pain point of current generative models, which often produce outputs difficult to edit or adapt.
- **Democratization of 3D Modeling:** LL3M lowers the barrier to entry for 3D content creation. Users can generate and edit complex 3D models using natural language, democratizing a skill traditionally requiring extensive technical expertise and software proficiency. This could lead to a surge in user-generated 3D content across various applications.
- **Enhanced Control and Iterative Design:** The system's multi-agent architecture, combined with RAG and visual feedback, enables unprecedented levels of control over 3D asset properties. The iterative refinement loop, especially the user-guided phase, allows for precise, localized edits and stylistic transformations through natural language, making the design process highly flexible and responsive to user intent.
- **Advanced LLM Applications:** LL3M showcases the power of multi-agent LLM systems, particularly when augmented with domain-specific knowledge bases (like BlenderRAG) and multi-modal capabilities (VLM for visual critique). It demonstrates how LLMs can be orchestrated to solve complex, multi-step, and multi-modal tasks involving spatial reasoning, procedural generation, and error correction.
- **Future Directions in Procedural Content Generation:** The work highlights the potential for more sophisticated procedural modeling tools that are guided by natural language. This could lead to AI assistants capable of designing entire virtual environments, interactive objects, and characters with high levels of detail and artistic control. The ability for BlenderRAG to be updated for future Blender versions also ensures the system's longevity and adaptability.

In conclusion, LL3M pushes the boundaries of AI-driven 3D content creation by prioritizing interpretability, editability, and seamless integration with human workflows. Its novel multi-agent, code-generating approach positions it as a significant step towards truly intelligent and collaborative 3D modeling systems.
