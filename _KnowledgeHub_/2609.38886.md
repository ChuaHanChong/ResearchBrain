# Benchmarking and Enhancing Skill-Level Memory for Partially Observable Robotic Manipulation

> [!summary] Summary
> HIDE is a 15-task RLBench benchmark for manipulation under partial observability, spanning repetition counting, historical-state recall, and execution-progress tracking. SEEK adds three memories to a SAM2Act coarse-to-fine policy: a sliding window of recent interactions, a persistent anchor retrieved by visual similarity, and a stage counter. SEEK reaches 62.9% average success on HIDE, 11.7 points above SAM2Act+, and 89% on real robots.

## Problem

- Manipulation policies, including large VLAs, act mainly on current observations or short context, so they fail when visually identical scenes require different actions depending on prior events.
- Existing memory-based policies retain history via recurrent states, memory banks, or retrieval, but retaining history does not guarantee recovering the specific hidden state a decision requires.
- Standard benchmarks measure task completion and generalization, and memory benchmarks scale length or occlusion, rather than explicitly building decision points where history causally determines the correct action.

## Method

- **HIDE** benchmark: 15 RLBench tasks with randomized configurations, scripted demonstrations, and automatic ==keypoint-based stage annotations==, grouped by hidden variable: repetition count, historical scene state, execution progress.
- **SEEK**'s ==Windowed Context Memory== keeps the latest K interaction memories, while ==Persistent Anchor Memory== retrieves one older entry from outside the window by ==cosine similarity== of pooled visual descriptors.
- ==Stage-Counter Memory== advances a discrete counter with a learned embedding at predicted stage boundaries; all three memories feed ==SAM2-style memory attention== in the coarse branch, trained with action plus ==stage-boundary loss==.

## Results

- On HIDE, SEEK averages **62.9%** versus **51.2%** for SAM2Act+, **26.4%** for GR00T-N1.7 and **22.1%** for pi0, leading all three categories at **61.6%**, **59.2%** and **68.0%**.
- Ablations: storing visual features instead of proprioception lifts average success from **42.5%** to **62.9%**; memory length **6** beats length **0** (**62.9%** vs **46.7%**); SCM, PAM and WCM each lead one category.
- Real-robot average success is **89%** versus **47%** for SAM2Act+ and **13%** for pi0.5, while standard RLBench performance holds at **84.7%** versus **84.1%** for SAM2Act.

## Takeaways

> [!tip] Key Insights
> - Memory demands are heterogeneous: counting, recall and progress tracking favor different mechanisms, and a single memory type can help one hidden-state requirement while degrading another.
> - An explicit discrete progress counter resolves repetition ambiguity that visual history alone cannot, because repeated actions return the scene to nearly identical appearances.
> - Memory dependence should be defined causally, as aliased observations requiring different actions, not by horizon length or occlusion; large VLAs score poorly once defined this way.

## Detailed Report

### 1. Overview

A robot told to press a colored button a specified number of times faces a bookkeeping problem. After individual presses, the current view may not reveal whether to repeat or stop. The authors frame this as information hidden from the current observation but recoverable from interaction history. Their policy, SEEK, gets three kinds of memory:

- recent interaction context,
- a way to retrieve an older visual clue,
- an explicit estimate of execution progress.

They test button counting alongside two other kinds of hidden task state. The combined memory design achieves better task success.

"Push Button Times," front view, from the project page section "How many times? Remember the repetition count." This is a scripted expert demonstration, not an evaluated SEEK rollout.

### 2. A view is not the whole state

The central challenge is that two histories can produce visually similar current observations but call for different next actions. The authors' benchmark, HIDE, comprises 15 RLBench-based tasks: five each for repetition counting, historical-state recall, and execution-progress tracking. Tasks are grouped by their primary memory requirement:

- **Repetition counting:** knowing how many operations are complete.
- **Historical-state recall:** using information seen earlier but now unavailable.
- **Execution-progress tracking:** knowing which substeps are done and what comes next.

The categories can overlap within an individual task. The criterion is stronger than "long horizon" or "occlusion": history must determine the correct subsequent behavior.

SEEK's memory has three pieces:

- **Windowed Context Memory (WCM)** keeps the latest *K* interaction memories in order and replaces the oldest when full.
- **Persistent Anchor Memory (PAM)** searches the older episode archive for a relevant visual reference, excluding entries already in WCM.
- **Stage-Counter Memory (SCM)** holds a discrete progress count and a learned stage representation. Its count advances when the policy predicts a stage boundary, rather than at every control step.

In the reported HIDE setup, the memory budget is six entries. The read is bounded by recent entries, at most one older anchor, and one stage representation per view, regardless of archive length.

The coarse branch uses memory-conditioned features to select a workspace target, while the fine branch refines the action from local geometry. The policy writes an interaction memory after predicting the action. Memory resets between episodes.

Right: the coarse-to-fine policy pipeline, with memory attention conditioning the coarse branch and a memory encoder writing entries.

### 3. The combination matters

The metric is task success. HIDE's overall score is the unweighted average across 15 task success rates, with category averages computed over five tasks each. Evaluation used 25 held-out episodes per task. SEEK was jointly trained on all 15 tasks with 100 demonstrations per task.

SEEK's overall success rate is **62.9%**, versus **51.2%** for SAM2Act+, the strongest average baseline reported on HIDE. That is a difference of 11.7 percentage points. SAM2Act+ already uses a memory bank, so the contrast is not "memory versus no memory."

SEEK leads the reported baselines in all three categories, but the strongest baseline varies by category. SAM2Act+ leads on repetition counting and execution-progress tracking, while GR00T-N1.7 leads on historical-state recall.

The component ablation tests the mechanism:

- Adding SCM gives the largest reported stepwise gain on repetition counting (+14.0 points).
- Adding WCM gives the largest stepwise gain on execution-progress tracking (+12.0 points).
- Adding PAM gives the largest stepwise gain on historical-state recall (+11.6 points).

The combined model leads all three categories. This supports complementarity in these experiments, not the claim that each mechanism is the sole cause of its category's gains.

### 4. Closing

On four real-world tasks under randomized initial configurations, SEEK's average success is **89%**, versus **47%** for SAM2Act+ and **13%** for π₀.₅. Each method had a separately trained real-robot policy, and each task was evaluated over 25 test trials.

Across these experiments, pairing recent context, a retrieved past reference, and explicit progress gives the best average among the evaluated configurations. The authors limit HIDE to controlled, interpretable forms of hidden state and identify richer real-world settings as future work.
