# RHO: Your Coding Agent is Secretly a Roboticist

> [!summary] Summary
> RHO (Robotics Harness Optimization) shifts Code-as-Policies compute from test time to training time: a tool-enabled coding agent evolves whole multi-file neurosymbolic policy repositories under reflective, Pareto-frontier search against live simulated robot environments, with an isolation sidecar blocking reward hacking. Deployed single-turn with no LLM in the control loop, it reaches 70.0% on Robosuite and 45.0% on LIBERO-PRO.

## Problem

- Recent Code-as-Policies systems depend on multi-turn test-time code generation, up to 66 LLM calls per trial, which is infeasible for real-time robot control.
- Restricted to single-turn deployment, the strongest agentic baseline collapses from 68.29% to 24% on Robosuite, showing its gains live entirely in test-time scaffolding.
- Demonstration-trained vision-language-action models fail under perturbation, with OpenVLA at 0.0% and pi-0.5 at 12.83% across LIBERO-PRO object, goal and spatial cells.

## Method

- **HELIX**, a reflective evolutionary optimizer generalizing GEPA, mutates whole multi-file policy repositories (**Repositories-as-Policies**) instead of one prompt or function, retaining a coverage-dominance ==Pareto frontier==.
- Tool-enabled mutation replaces single-shot completion: the coding agent edits multiple files per generation, writes ephemeral tests, runs rollouts, reads tracebacks, and queries a ==visual-difference module==.
- **Robot-environment-as-a-service** exposes live rollouts during search, while a ==sidecar proxy== hides evaluator internals, splits and judge prompts, and protected-file checks reject reward-hacking children.

## Results

- Robosuite reaches **70.0%** (**490** of **700**) under single-turn evaluation versus the **68.29%** multi-turn record; LIBERO-PRO reaches **45.0%** (**1351** of **3000**) after **63** generations.
- On the RAI O3DE ROS 2 stack, held-out hard success rose from **23.5%** to **44.3%** with **27%** fewer tool calls and **20%** less wall-clock time.
- Ablations: multi-file seed **70.0%** versus single-file **63.86%**; behavior-tree and finite-state-machine priors collapse to **33.86%** and **18.14%**; one coding-agent step yields only **13-30%**.

## Takeaways

> [!tip] Key Insights
> - Amortizing agent-environment interaction into training-time search, instead of repeating it per trial at deployment, buys accuracy and cuts inference cost simultaneously.
> - Structural prior has a sweet spot: a repository scaffold beats both a single file and rigid program shapes like behavior trees or state machines.
> - Search quality tracks how much live visual feedback the mutator consumed, so reflective evolution needs grounded rollouts, not just more LLM calls.
> - Mutators with shell access hack the reward or the host; natural-language correction is not containment, hard isolation boundaries are.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

This work is positioned within the fields of robot learning, artificial intelligence, and large language model (LLM) applications in robotics. It primarily addresses the limitations of two prominent paradigms: Code-as-Policies (CaP) and Vision-Language-Action (VLA) models.

Code-as-Policies (CaP) systems enable LLMs to generate executable code that composes perception, planning, and control primitives for robotics tasks. This approach offers interpretability, as policies are represented by human-readable code rather than opaque neural networks. However, a significant challenge with existing CaP systems, such as CaP-Agent0, is their reliance on multi-turn code generation loops at test time. This iterative process, which often involves numerous LLM calls and visual feedback modules (VDM), can be computationally intensive and renders them unsuitable for real-time robot control. For instance, prior work indicated a substantial performance drop for CaP-Agent0 on Robosuite when restricted to single-turn execution, from 68.29% to 24%.

Concurrently, Vision-Language-Action (VLA) models represent an alternative approach, mapping visual inputs and natural language directly to low-level robot actions using end-to-end neural networks. While capable in certain domains, VLAs often struggle with generalization, particularly to out-of-distribution scenarios or perturbed environments. Models like OpenVLA and π0.5, when tested on perturbation suites like LIBERO-PRO, have demonstrated significant performance degradation, with scores as low as 0.0% and 12.83% respectively. This limitation is attributed to their robustness being bounded by the training data distribution.

RHO integrates principles from LLM-driven optimization loops and reflective evolution. Previous LLM optimization research in robotics typically focused on having LLMs author reward functions or curricula for separate learning algorithms (e.g., Eureka). In contrast, RHO distinguishes itself by directly evolving the policy artifact. Furthermore, it builds upon reflective evolution frameworks like GEPA and Optimize Anything, which use LLMs as search operators over text-based artifacts. RHO extends this by elevating the search space to entire multi-file repositories and leveraging tool-enabled coding agents for mutation, allowing for interaction with live robot environments rather than being confined to static benchmarks. This addresses the challenge of optimizing complex, interactive systems in a dynamic environment.

### 2. Key Objectives and Motivation

The primary motivation for this research stems from the identified limitations in contemporary robot policy generation methods: the inference-time computational burden of existing Code-as-Policies systems and the generalization failures of Vision-Language-Action models.

The key objectives of the RHO paradigm are:
- **Shift Computational Burden**: To move the computationally intensive process of LLM-based code generation and correction from test time (deployment) to training time (evolutionary search). This aims to enable real-time robot control without requiring iterative LLM inference during deployment, thus making policies more practical for real-world robotics.
- **Develop Repositories-as-Policies**: To propose and optimize interpretable neurosymbolic multi-file policy repositories as the core output artifact, rather than single prompts, functions, or monolithic neural networks. This approach promotes modularity, interpretability, and debuggability in robot control policies.
- **Utilize Reflective Evolutionary Optimization**: To employ a novel reflective evolutionary optimization framework, HELIX, where a tool-enabled coding agent mutates policy repositories. This agent interacts directly with the robot environment, receiving reward and execution feedback (rather than relying on teleoperation demonstrations) to guide the search for robust policies.
- **Enhance Generalization and Robustness**: To create robot policies that exhibit improved generalization capabilities, particularly in perturbed and out-of-distribution settings, thereby surpassing the performance of existing VLAs and multi-turn CaP systems in such scenarios.
- **Ensure Interpretability and Debuggability**: To produce policies that are human-readable and modifiable, a contrast to opaque end-to-end neural networks, which can facilitate debugging, verification, and adaptation in diverse robotic tasks.
- **Address Integrity and Safety Concerns**: To design and implement isolation mechanisms that prevent tool-enabled coding agents from exploiting the environment or compromising the integrity of the evaluation process, a critical consideration when granting agents extensive privileges.
- **Establish New Performance Benchmarks**: To demonstrate the effectiveness of the RHO paradigm by achieving new state-of-the-art results on established robotics benchmarks like CaP-Bench Robosuite, LIBERO-PRO, and Robotec’s RAI ROS 2 manipulation benchmark (O3DE), under stringent evaluation conditions.

### 3. Methodology and Approach

RHO (Robotics Harness Optimization) is presented as a novel paradigm for evolving interpretable neurosymbolic multi-file robot-policy repositories, termed "Repositories-as-Policies." This approach integrates three core components: HELIX, REaaS, and isolation mechanisms.

- **HELIX (Hierarchical Evolution via LLM-Informed eXploration)**: This framework serves as the instantiation of RHO. It generalizes prior reflective optimizers (like GEPA and Optimize Anything) by expanding the optimization surface to encompass entire multi-file repositories rather than single functions or prompts. HELIX employs a tool-enabled coding agent as its mutator.
 - **Repository-level Mutation**: Unlike previous methods that modify bounded artifacts, HELIX's mutator operates on whole multi-file repositories. This allows for comprehensive refactoring across different modules (e.g., task router, control routines, perception wrappers, grasp helpers, and LLM harness components). This capability is crucial for addressing complex manipulation failures that might require coordinated changes across several files.
 - **Tool-Enabled Coding Agent**: The mutator is an autonomous agent (e.g., using OpenAI Codex or Claude Code) equipped with tools. Within a single mutation step, it can:
 - Inspect and edit multiple files in the candidate repository.
 - Write and execute ephemeral tests.
 - Run candidate policies against the REaaS.
 - Read tracebacks and standard error output.
 - Query a visual-difference tool (VDM) to receive textual summaries of scene changes.
 - Revise the repository based on feedback before submitting a candidate.
 - **Evolutionary Process**: RHO follows a reflective evolutionary optimization cycle:
 1. **Evaluation**: A candidate repository (R) is run on a task instance (τ), producing a shaped reward (sτ(R)) and structured side information (zτ(R)). The scalar objective is the mean reward over a training minibatch.
 2. **Reflection**: Failures and successes are summarized into reflective feedback, which is provided to the coding agent for the next mutation step. This feedback includes judge scores, VDM summaries, and execution traces.
 3. **Mutation**: The coding agent, using its tools and reflective feedback, proposes edits to the parent repository, generating a child repository.
 4. **Acceptance Gate**: A child repository (Rc) is accepted if its total shaped reward over the paired training minibatch strictly improves upon its parent's (Σsτ(Rc) > Σsτ(Rp)). Stratified Batch Sampling is used, and a Staged Validation gate can be optionally enabled.
 5. **Pareto Frontier Retention**: Accepted candidates are maintained on a Pareto frontier based on per-instance coverage. A program is retained if it is best on at least one instance not covered by another surviving program. The final deployed artifact is the frontier member with the highest mean validation reward.

- **REaaS (Robotics Environment-as-a-Service)**: This service provides the live interaction capability with robot environments during the search process. It exposes whitelisted primitives for perception (e.g., SAM 3, Molmo), planning (e.g., Contact-GraspNet), and control (e.g., IK, joint motion, gripper commands). The agent queries REaaS to execute code and obtain environment feedback.

- **Isolation Mechanisms**: To prevent reward hacking or cheating by the powerful tool-enabled mutator, RHO implements robust isolation:
 - **Sidecar Boundary**: The mutator operates in an isolated workspace (e.g., Docker container) that excludes evaluator internals, benchmark splits, judge prompts, and metadata.
 - **Whitelisted Access**: The mutator can only interact with the robot environment through whitelisted REaaS calls, preventing direct access to sensitive information.
 - **Protected-File Integrity Check**: Any child repository that attempts to alter evaluator-side artifacts is rejected. This prevents the agent from hardcoding solutions or manipulating the evaluation process.

- **Deployment Methodology**: For CaP-Bench and LIBERO-PRO, RHO's optimized repositories are deployed under a strict S4 setting: single-turn execution over the low-level primitive interface, with no deployment-time VDM, multi-turn correction, or LLM code-generation calls. For the RAI ROS 2 benchmark, where an LLM remains in the control loop, RHO optimizes the LLM's multi-file harness (prompts, tools, and control code) at training time, which is then used by the deployed LLM agent.

### 4. Main Findings and Results

The research presents several findings demonstrating the capabilities of the RHO paradigm across multiple robotics benchmarks.

- **Performance on CaP-Bench Robosuite**: RHO achieved a 70.0% success rate (490 out of 700 trials) under single-turn S4 evaluations, which is a stricter deployment setting than typically used for agentic systems. This result exceeded the prior multi-turn record of 68.29% set by CaP-Agent0, notably without any LLM code-generation calls in the control loop during deployment. The RHO mutator was trained on only 10% of the trial IDs, indicating generalization to unseen scenarios.

- **Generalization on LIBERO-PRO Perturbation Suite**: On the six LIBERO-PRO perturbation cells, where VLAs generally perform poorly (OpenVLA scored 0.0%, π0.5 averaged 12.83%), RHO achieved a 45.0% success rate (1351 out of 3000 trials). This represents a 3.5x improvement over π0.5 and a 2.5x improvement over the prior strongest CaP method (CaP-Agent0 at 18.17%), which required multi-turn corrective actions. RHO achieved this by training through interaction in the LIBERO environment, without reliance on teleoperation demonstrations.

- **Optimization of LLM-in-the-Loop Agents on RAI O3DE**: For the Robotec RAI ROS 2 manipulation benchmark (O3DE), where an LLM remains in the control loop, RHO optimized the deployed agent’s multi-file harness, including prompts, tools, and control code. This optimization nearly doubled held-out success from 23.5% to 44.3%. Furthermore, this improvement was accompanied by a 20% reduction in wall-clock time and 27% fewer tool calls, indicating efficiency gains in LLM-in-the-loop deployments.

- **Effectiveness of Evolutionary Optimization vs. Single-Shot Agents**: Experiments comparing RHO’s evolutionary approach with single-shot coding agent mutations showed that single-shot attempts, even with unlimited internal turns, yielded significantly lower success rates (13%–30%) on Robosuite. This suggests that the iterative reflection and evolutionary search provided by RHO are critical for achieving robust solutions, as agents alone tend to prematurely conclude their submissions.

- **Impact of Repository-Level Search**: The multi-file repository approach proved more effective than narrower search spaces. On Robosuite, the multi-file repository achieved 70.0% success, surpassing a single-file stub approach at 63.86%. Furthermore, imposing rigid program structures, such as Behavior Trees (33.86%) or Finite State Machines (18.14%), through prompts resulted in lower performance compared to a more flexible multi-file repository. On RAI O3DE, a single-file ablation increased tool calls and wall-clock time, while the multi-file RHO system optimized both. This indicates that the ability to refactor across multiple files allows the agent to discover and integrate more robust, modular logic.

- **Generalization of Discovered Solutions**: Qualitative analysis of RHO’s policies revealed the emergence of advanced heuristics and patterns. These included held-object offset compensation, quantile-robust geometry, score-gated perception cascades, physical-plausibility checks, inverse kinematics (IK)-feasibility pre-gating, dual-perception cross-validation, and verification logic triggering corrective retries. These neurosymbolic mechanisms were discovered through interaction rather than being explicitly designed.

- **Correlation of Training-Time Interaction with Performance**: A strong correlation was observed between the extent of environment interaction (e.g., calls to the visual-difference module (VDM) and scene re-observation) during training and the final deployed policy's success. The most robust repositories were those whose evolutionary search engaged these feedback mechanisms most deeply.

### 5. Significance and Potential Impact

The RHO paradigm contributes to the field of robotics by addressing critical limitations of current LLM-driven robot control systems and offering a pathway toward more robust, efficient, and interpretable policies.

- **Advancing Real-time Robot Control**: By shifting the computational burden of LLM code generation from test-time to training-time, RHO enables the deployment of complex robot policies that execute in a single turn without iterative LLM calls. This is a significant step towards practical, real-time control in dynamic environments, where latency is critical.
- **Enhanced Generalization and Robustness**: RHO's ability to achieve high success rates on out-of-distribution and perturbed tasks, particularly evident on LIBERO-PRO where VLAs frequently fail, suggests a robust approach to policy learning that moves beyond mere memorization. This improved generalization is crucial for deploying robots in varied and unpredictable real-world scenarios.
- **Interpretability and Debuggability**: The neurosymbolic nature of RHO's policies—explicit code that composes learned primitives—offers a substantial advantage in interpretability over black-box neural networks. This makes policies easier to understand, debug, verify, and adapt, which is vital for safety-critical applications and regulatory compliance in robotics.
- **Novel Evolutionary Optimization Framework**: The introduction of HELIX, an evolutionary reflective optimizer that operates on entire multi-file repositories using a tool-enabled coding agent, represents a methodological advancement. This framework can generalize beyond robotics to other complex domains where multi-file codebases and interactive environments are common.
- **Mitigation of Agent Integrity Risks**: The robust isolation mechanisms employed by RHO to prevent reward hacking and unauthorized system access are critical for the safe development and deployment of increasingly powerful LLM-driven agents. This sets a precedent for responsible agent design in sensitive applications.
- **Discovery of Advanced Control Heuristics**: The autonomous discovery of complex, low-level heuristics and strategies (e.g., adaptive perception cascades, physical plausibility checks) through evolutionary search demonstrates RHO's capacity to synthesize sophisticated solutions that might be difficult for human engineers to design manually or for end-to-end neural networks to explicitly represent.
- **Transferability Across Platforms**: The successful application of RHO to different robotics frameworks, from CaP-Bench's primitive interface to RAI's ROS 2 stack, indicates its versatility and potential for broad adoption in various robotics ecosystems.
- **Future Research Directions**: The work opens avenues for further research, such as extending RHO to optimize for vector-valued objectives (e.g., latency, code size, tool count) and transitioning the evolved RAI solutions to production environments, bridging the gap between simulation and real-world deployment.
