# Afterburner: Reinforcement Learning Facilitates Self-Improving Code Efficiency Optimization

> [!summary] Summary
> An iterative optimization framework named Afterburner leverages reinforcement learning with empirical execution feedback to continuously improve the computational efficiency of code generated by large language models. This approach, particularly using Group Relative Policy Optimization, led to sustained efficiency gains and generated solutions more performant than human-written code in a notable percentage of cases.

## Problem

- Large Language Models (LLMs) often generate functionally correct code but frequently produce computationally inefficient solutions, creating a gap for real-world deployment.
- Existing code optimization methods, such as prompt engineering or fine-tuning, have limited success in fostering adaptive and sustained improvements in code efficiency.
- Reinforcement Learning (RL) applications in code generation primarily focus on functional correctness, largely overlooking computational efficiency as a direct optimization target.

## Method

- The research introduces an ==Iterative Optimization Framework== (IOF) that pairs **Afterburner** (an LLM-based code optimizer) with Monolith (a high-fidelity execution sandbox) to create a closed-loop system for continuous code refinement.
- Afterburner employs Group Relative Policy Optimization (GRPO), an online reinforcement learning strategy, which learns from empirical execution feedback to adaptively improve code efficiency over multiple iterations.
- Monolith provides precise, real-world performance metrics (time, memory, integral score) by executing code in isolated Docker containers, serving as consistent and discriminative feedback for the LLM.

## Results

- Afterburner-GRPO demonstrated sustained improvements in code quality, increasing PASS@1 from **37.33%** to **61.67%** and runtime efficiency (BEYOND-T) from **31.22%** to **45.17%** over nine iterations.
- Afterburner-GRPO generated solutions that surpassed the efficiency of all human-written code in up to **8.00%** of cases for runtime, **7.00%** for memory, and **5.33%** for integral score after eight iterations.
- In comparative studies, Afterburner-GRPO significantly outperformed Afterburner models trained with SFT and DPO, which exhibited performance saturation, reaching BEYOND-T scores of **26.78%** and **30.92%** respectively.

## Takeaways

> [!tip] Key Insights
> - While vanilla LLMs excel at functional correctness, their code consistently exhibits suboptimal computational efficiency across various benchmarks compared to human solutions.
> - Online reinforcement learning, specifically the GRPO approach, is crucial for achieving continuous, adaptive self-improvement in code efficiency, significantly outperforming offline methods like SFT and DPO that tend to saturate.
> - Integrating empirical performance feedback from a controlled execution environment is essential for LLMs to learn genuinely efficient code, enabling them to move beyond theoretical complexity to practical performance optimization.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

The integration of Large Language Models (LLMs) into software engineering has led to significant advancements in automated code generation. Contemporary LLMs and agent frameworks are increasingly capable of producing functionally correct code, with some models approaching human performance in certain coding tasks. This progress is evident in various applications, including code completion, program repair, and unit test generation. However, a consistent observation across numerous benchmarks, such as HumanEval, LiveCodeBench, and BigCodeBench, is that while LLMs excel at functional correctness, they often generate code with suboptimal computational efficiency.

This efficiency deficit poses a challenge for the real-world deployment of LLM-generated code, particularly in systems where latency, memory usage, and computing costs are critical performance indicators. The research landscape has recognized this gap, leading to the development of specialized benchmarks for code efficiency, including EffiBench, PIE4PERF, Mercury, EVALPERF, and ENAMEL. These benchmarks consistently indicate that current LLMs struggle to achieve expert-level computational efficiency.

Previous efforts to address this efficiency gap have involved prompt engineering techniques like Chain-of-Thought, self-optimization strategies, and fine-tuning LLMs on efficiency-oriented datasets. However, these methods have generally yielded limited success in instilling adaptive knowledge for robust and sustained efficiency improvements. Reinforcement Learning (RL) has emerged as a promising paradigm for preference alignment in code generation, with methods like CodeRL, StepCoder, RLEF, and Focused-DPO primarily focusing on enhancing functional correctness through execution feedback. However, these RL approaches have largely not prioritized computational efficiency as a primary optimization target.

This paper addresses this specific challenge by proposing an iterative optimization framework that integrates LLMs with empirical performance feedback to facilitate continuous self-improvement in code efficiency. By exploring different training strategies, the work aims to determine which approaches are most effective in developing an adaptive proficiency for code efficiency optimization during test-time inference.

### 2. Key Objectives and Motivation

The central objective of this research is to introduce and evaluate a novel test-time iterative optimization framework (IOF) designed to enhance the computational efficiency of code generated by Large Language Models. This overarching goal is motivated by several specific considerations:

- **Addressing the Efficiency Gap:** LLMs have demonstrated proficiency in generating functionally correct code, but this often comes at the expense of computational efficiency. In real-world applications, inefficient code can lead to significant performance bottlenecks, increased operational costs, and degraded user experience due to high latency and memory consumption. The primary motivation is to bridge this critical gap between functional correctness and practical efficiency.
- **Enabling Continuous Self-Improvement:** Existing methods for improving code efficiency, such as supervised fine-tuning (SFT) or direct preference optimization (DPO), tend to rely on static datasets and often exhibit saturation in performance gains. The research aims to develop a system that allows LLMs to iteratively refine their generated code based on empirical performance feedback, mimicking human development cycles of trial and error. This closed-loop system is intended to enable continuous self-improvement during inference time.
- **Investigating Training Strategy Effectiveness:** The paper seeks to comparatively analyze the learning dynamics and effectiveness of different LLM training strategies—specifically Supervised Fine-Tuning (SFT), Direct Preference Optimization (DPO), and Group Relative Policy Optimization (GRPO)—within the proposed iterative optimization framework. This comparative analysis is motivated by the need to understand which methods are best suited for cultivating adaptive knowledge for code efficiency optimization.
- **Leveraging Empirical Performance Feedback:** Traditional code optimization often relies on theoretical complexity analysis (e.g., Big O notation), which can overlook practical performance factors such as constant factors, implementation details, language runtime, and hardware interactions. The motivation is to integrate a high-fidelity execution sandbox (Monolith) to provide real-world, empirical performance metrics (time, memory, integral score) as a consistent and discriminative feedback signal, thereby enabling LLMs to learn genuinely efficient code generation.
- **Developing Robust Benchmarking Resources:** To facilitate rigorous evaluation of code efficiency, the research is motivated to introduce a new dataset, Venus, which expands upon existing benchmarks by offering a larger collection of tasks and human solutions, enabling more stable percentile rank calculations for holistic efficiency assessment. This aims to provide a reliable platform for evaluating models' performance against a diverse distribution of reference solutions.

In summary, the core motivation is to move beyond merely functionally correct code to truly performant code, utilizing an adaptive, feedback-driven approach, and to identify the most effective learning paradigms for this complex task.

### 3. Methodology and Approach

The research introduces an Iterative Optimization Framework (IOF) designed to enhance the efficiency of LLM-generated code through a closed-loop system of generation and evaluation. This framework comprises two primary components: Afterburner and Monolith, working synergistically over multiple iterations.

**Iterative Optimization Framework (IOF) Workflow:**
The IOF operates in an iterative cycle (Algorithm 1). It begins with an initial code version (either pre-provided or generated by Afterburner) and its baseline performance, measured by Monolith. In each iteration, Afterburner generates an improved code solution based on the current code and its performance metrics. This new code is then evaluated by Monolith. If the improved code demonstrates superior performance according to a specified efficiency objective, it replaces the current best code for the next iteration; otherwise, the previous best code is retained. This process continues for a predetermined number of iterations.

**Afterburner: Code Efficiency Optimization Models:**
Afterburner is a suite of LLM-based models responsible for proposing targeted efficiency improvements. It takes as input a problem description (P), an efficiency instruction (I) (e.g., 'time-efficient', 'memory-efficient', 'integral-efficient'), the current input code ($C_{in_i}$), and its corresponding performance metrics ($M_{in_i}$). Afterburner then generates a refined candidate code ($C_{out_i}$) along with its reasoning. The iterative refinement is guided by a greedy selection mechanism (Equation 2) that chooses the best-performing code for the subsequent iteration.

**Monolith: Code Execution Sandbox:**
Monolith serves as the evaluation backbone of the IOF, providing empirical performance feedback. Unlike theoretical complexity analysis, Monolith executes the generated code in a controlled environment to measure real-world performance. It returns a tuple: `{passed, time, memory, integral}` (Equation 3), indicating functional correctness (passed all test cases), absolute execution time, peak memory usage, and an integral score (combining time and instantaneous memory footprint). Monolith prioritizes consistent measurement by using dedicated Docker containers with isolated resources for each execution, minimizing variability from hardware and system-level factors.

**Code Efficiency Optimization Strategies:**
The study investigates three distinct strategies for training the Afterburner models:

1. **Data Preparation:** The authors introduce **Venus**, a new dataset for rigorous code efficiency assessment. Venus expands upon existing benchmarks by providing a substantially larger set of human solutions per task (averaging 106.6 in Python), enabling more stable percentile rank calculations against diverse reference solutions, and offering holistic assessment of time, memory, and integral scores. It includes 2,181 training and 300 test tasks for Python, with multilingual support. The APPS benchmark is used as an auxiliary evaluation.
 - **DS_SFT:** Pairs of functionally correct solutions from Venus_train, with inferior code ($C^-$) and superior code ($C^+$) for SFT.
 - **DS_DPO:** Prompt (P, I, C, M) with a preferred ($C^+$) and dis-preferred ($C^-$) response for DPO, sampled from Venus_train solutions.
 - **DS_COLD:** Designed to rapidly adapt Afterburner models to a specific response format (`<thinking><solution>`), constructed from Gemini 2.5 Pro responses to Venus_train tasks. Used for initial SFT of GRPO models.
 - **DS_GRPO:** Prompts structured as (P, I, C, M), where Afterburner_GRPO learns from online execution feedback without ground-truth responses.

2. **Supervised Fine-Tuning (SFT):** Afterburner_SFT is trained to learn patterns that transform suboptimal solutions into more performant ones. The training objective minimizes cross-entropy loss to generate the optimized code ($C^+$) given a prompt (P, I, $C^-$, $M^-$) (Equation 4).

3. **Direct Preference Optimization (DPO):** Afterburner_DPO aligns LLMs with efficiency preferences offline. It directly increases the likelihood of preferred responses ($C^+$) and decreases that of dis-preferred responses ($C^-$). The DPO loss function (Equation 5) uses a reference model (Afterburner_SFT) and a logistic function to optimize for the preference objective.

4. **Group Relative Policy Optimization (GRPO):** Afterburner_GRPO extends DPO to an online, group-wise ranking scenario using reinforcement learning. It first undergoes SFT on DS_COLD to align with the response format, then learns from code execution feedback.
 - **Reward Functions:** The final reward ($R_{final}$, Equation 9) is a composite of three components:
 - **Format Control Reward ($R_{Format}$):** A binary reward (+1/-1) for adhering to the specified output format (`<thinking>...</thinking><solution>...</solution>`) (Equation 6).
 - **Functional Correctness Reward ($R_{correct}$):** A nuanced reward that assesses changes in passing status (upgrade, maintained passing, maintained failing, downgrade) between the input and output code (Equation 7).
 - **Efficiency Improvement Reward ($R_{efficiency}$):** Measures the relative improvement in a clipped performance metric (time, memory, or integral score) using a hyperbolic tangent function to bound and smooth the signal (Equation 8). This component leverages the inherent stochasticity of empirical measurements to encourage exploration.
 - **Objective:** GRPO employs a policy gradient approach (Equation 10) that encourages the policy to favor generated candidates that show superior performance relative to other candidates within the same generation group. It uses a policy ratio ($W_i$) and an advantage term ($A_i$) that normalizes rewards within the rollout group (Equation 11).

**Experiment Setup:**
- **Functional Correctness:** Assessed by PASS@1 (percentage of solutions passing all test cases).
- **Computational Efficiency:** Measured by global metrics BEYOND-T, BEYOND-M, and BEYOND-I. These represent the average percentile ranks of generated code's execution time, peak memory, and integral score, respectively, relative to distributions of human solutions. Higher scores indicate greater efficiency.
- **Implementation:** Models were trained on H100 GPUs using Llama-Factory, Verl, and vLLM for inference acceleration. Monolith runs on GCP instances with Docker containers, precisely measuring `time -v` and `VmRSS` for metrics. Bootstrapping (128 replicates, 4 solutions sampled per problem) was used to quantify statistical uncertainty.

### 4. Main Findings and Results

The research presents several findings regarding the efficiency optimization capabilities of LLMs under different training paradigms within the Iterative Optimization Framework (IOF).

#### 4.1. Code Efficiency Performance of Vanilla LLMs

Initial evaluations of various open-source and closed-source LLMs on the Venus and APPS benchmarks (Tables 1 and 9) indicate a consistent pattern: while vanilla LLMs achieve high functional correctness (PASS@1), their computational efficiency is notably inferior compared to human-written solutions. For example, OpenAI o4 mini, despite an 89.11% PASS@1 on Venus, achieved BEYOND-T (runtime efficiency) of only 56.85% (40.07% on APPS), meaning its solutions surpassed approximately 57% of human solutions in runtime efficiency. Similar disparities were observed for other leading models across all efficiency metrics (BEYOND-T, BEYOND-M, BEYOND-I). While larger models show marginally better efficiency, this improvement is insufficient to close the substantial gap, underscoring the necessity for dedicated optimization frameworks.

#### 4.2. Effectiveness of the Iterative Improvement Framework

The core hypothesis that iterative refinement can progressively enhance code efficiency was investigated by comparing the performance dynamics of Afterburner models trained with SFT, DPO, and GRPO over successive iterations (Figure 5).
- **SFT (Afterburner_SFT):** This approach exhibited initial gains in efficiency but quickly saturated. For example, PASS@1 rose from 46.00% to 48.67% and BEYOND-T from 25.04% to 26.78% by iteration 7, with negligible improvements thereafter. This behavior is attributed to SFT's tendency to memorize superficial patterns from its training data, limiting its ability to generalize to novel inefficiencies or explore fundamentally different algorithmic solutions beyond learned examples.
- **DPO (Afterburner_DPO):** DPO models consistently performed better than SFT, demonstrating more nuanced judgments guided by learned preferences. For instance, BEYOND-T increased from 24.61% to 30.92% by iteration 9. However, similar to SFT, DPO's performance also tended to plateau. This is explained by DPO being an offline method that internalizes static preferences; without retraining, its exploration capabilities are bounded by the diversity of its initial preference dataset.
- **GRPO (Afterburner_GRPO):** In stark contrast to SFT and DPO, Afterburner_GRPO continuously refined code performance over multiple iterations. PASS@1 steadily increased from 37.33% to 61.67% by iteration 9, and BEYOND-T rose from 31.22% to 45.17%. Significant improvements were also observed for BEYOND-M (from 25.14% to 48.05%) and BEYOND-I (from 16.24% to 38.96%). This sustained improvement is attributed to GRPO's online reinforcement learning approach, which actively explores the solution space and receives direct, empirical execution feedback, cultivating an adaptive proficiency in code optimization.

#### 4.3. Reasons for GRPO's Iterative Efficiency Enhancement

The superior performance of GRPO is attributed to its inherent generation diversity and continuous learning from execution feedback. By allowing for greater KL divergence during training, Afterburner_GRPO explores multiple optimization pathways without being confined by ground-truth examples or static preferences. The iterative refinement loop allows the model to gain experience from its own generated code, learning from both successes and failures. Ablation studies (Table 2) further supported this, showing that removing either the execution feedback mechanism or the original code context significantly diminished Afterburner_GRPO's performance (e.g., BEYOND-T dropped by 6.66% without feedback, and 8.64% without original code context). This effect was less pronounced for SFT and DPO, underscoring the critical role of online feedback and context for GRPO's adaptive learning.

#### 4.4. Ability to Surpass Human Efficiency

The study investigated whether Afterburner can generate solutions that exceed the efficiency of the best human-written code. As shown in Table 3, Afterburner_GRPO achieved the highest "Better than all human" (B%) scores across all evaluated metrics after 8 iterations: 8.00% for Time, 7.00% for Memory, and 5.33% for Integral score. This indicates that Afterburner_GRPO can move beyond merely replicating human patterns, discovering highly optimized implementations that may differ structurally from canonical human approaches. However, this enhanced exploration came with a trade-off, as Afterburner_GRPO also generated a larger fraction of solutions that were less efficient than the human baseline (higher W% compared to top vanilla models).

### 5. Significance and Potential Impact

This research introduces an Iterative Optimization Framework (IOF) that demonstrates a method for enhancing the computational efficiency of code generated by Large Language Models. The framework's core components, Afterburner and Monolith, establish a closed-loop system where LLMs can iteratively refine code based on empirical performance feedback.

The comparative analysis of Supervised Fine-Tuning (SFT), Direct Preference Optimization (DPO), and Group Relative Policy Optimization (GRPO) reveals distinct learning dynamics. The findings suggest that while SFT and DPO provide initial gains or internalize static preferences, they tend to saturate. In contrast, GRPO, by leveraging online Reinforcement Learning (RL) with direct execution feedback, is shown to facilitate continuous and substantial improvements in code efficiency. This distinction highlights the adaptive proficiency that RL can cultivate in LLMs, enabling them to "self-improve" their code efficiency during test-time inference. The demonstrated increase in PASS@1 and efficiency metrics, as well as the ability of Afterburner-GRPO to generate solutions more efficient than all human references in a notable percentage of cases, indicates a step towards overcoming a known limitation of current LLMs in real-world software deployment.

The introduction of the **Venus dataset** and the **Monolith code execution sandbox** provides valuable resources for the research community. Venus offers a robust, multi-language benchmark with extensive human solutions for fine-grained efficiency assessment, addressing limitations of prior benchmarks. Monolith provides a high-fidelity, consistent environment for empirical performance measurement, crucial for generating reliable feedback signals for RL-based optimization.

The potential impact of this work is significant for the deployment of LLM-generated code in performance-critical applications. By enabling LLMs to produce not just functionally correct but also computationally efficient code, the framework could alleviate bottlenecks related to latency, memory usage, and computing costs. This has implications for various domains, including cloud computing, edge devices, and competitive programming, where resource optimization is paramount.

The research also opens avenues for future investigations. While the framework demonstrates effectiveness for competition-level programming tasks, its scalability to larger, more complex real-world software engineering projects, with diverse efficiency criteria and sophisticated task decomposition requirements, warrants further exploration. Additionally, the inherent increase in inference time for iterative optimization, while potentially offset by long-term runtime savings in production, represents a trade-off that requires careful consideration based on specific application requirements. The findings suggest that future research could focus on mitigating this trade-off, extending the framework to more programming languages, and further refining RL techniques to enhance exploration robustness while minimizing the generation of less efficient solutions.
