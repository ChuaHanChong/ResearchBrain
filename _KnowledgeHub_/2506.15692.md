# MLE-STAR: Machine Learning Engineering Agent via Search and Targeted Refinement

> [!summary] Summary
> MLE-STAR is an LLM-based agent that automates machine learning engineering tasks by leveraging web search for up-to-date models and implementing a targeted, ablation-guided code refinement process. This framework achieves state-of-the-art performance on a benchmark of 22 Kaggle competitions, outperforming existing LLM agents and specialized AutoML tools.

## Problem

- Existing LLM-based ML agents often propose familiar or outdated ML methods due to their training data, and face scalability/generalizability issues from reliance on manually curated knowledge bases or case banks.
- Current agents perform coarse, broad modifications to code, hindering deep and iterative optimization of specific ML pipeline components.
- LLM-generated code can exhibit 'misbehaviors' like data leakage or incomplete data utilization, compromising solution robustness.

## Method

- A ==multi-agent framework== that uses a retriever agent with ==web search== to identify state-of-the-art ML models and example code relevant to a given task.
- A ==targeted code block refinement== mechanism where an extractor agent, guided by ablation studies, identifies and iteratively refines high-impact ML components.
- A novel, ==LLM-guided ensemble strategy== that proposes and evaluates ensemble plans to combine candidate solutions, plus auxiliary modules for debugging, data leakage checking, and data usage checking to ensure robustness.

## Results

- Achieved a **63.6%** medal rate (**36.4%** gold medals) on 22 Kaggle competitions within the MLE-bench Lite benchmark using Gemini-2.5-Pro.
- Outperformed the leading LLM agent AIDE by **18.1** percentage points in 'Any Medal' rate (**43.9%** vs **25.8%**), with the proposed ensembling method driving 'Any Medal' from **37.9%** to **43.9%** and 'Gold Medal' from **25.8%** to **30.3%**.
- Demonstrated superior performance against DS-Agent and AutoGluon on most tabular tasks, without relying on manually curated case banks.

## Takeaways

> [!tip] Key Insights
> - Integrating external web search allows LLM agents to overcome knowledge biases and dynamically incorporate up-to-date, task-specific ML models and practices.
> - Focusing refinement on specific, high-impact code blocks via ablation studies, and proactively detecting and correcting misbehaviors like data leakage, are both critical for robust, effective ML solutions.
> - Intelligent, LLM-guided ensembling can further boost model performance by effectively combining diverse candidate solutions.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

This research sits at the intersection of several rapidly evolving fields: large language models (LLMs), autonomous agents, and automated machine learning (AutoML).

**LLM Agents:** The paper positions MLE-STAR within the broader trend of developing autonomous agents powered by LLMs. Recent advancements in LLMs have enabled agents like ReAct, HuggingGPT, Voyager, and AlphaCode to perform complex tasks by synergizing reasoning and acting, often utilizing external tools or execution feedback. MLE-STAR extends this paradigm by specializing an LLM agent for the intricate domain of machine learning engineering.

**Automated Machine Learning (AutoML):** AutoML aims to automate various stages of the ML pipeline, reducing the need for human experts. Traditional AutoML systems (ee.g., Auto-WEKA, TPOT, AutoGluon) typically operate within predefined search spaces for models, hyperparameters, or neural architectures (Neural Architecture Search - NAS). While effective, these methods often require domain expertise to define these search spaces and can struggle with novel task types.

**LLM-based MLE Agents:** More recently, research has focused on leveraging the inherent coding and reasoning capabilities of LLMs to create "MLE agents" that can generate executable code solutions directly, thereby eliminating the need for manually curated search spaces. Prior efforts in this area include systems like MLAB, OpenHands, AIDE, and DS-Agent. However, the authors identify several critical limitations in these existing LLM-based MLE agents:
1. **Reliance on Inherent LLM Knowledge:** Many agents heavily depend on the LLM's internal knowledge base, which can lead to a bias towards familiar, potentially outdated, or overly simplistic ML methods (e.g., favoring scikit-learn or older models like ResNet even for tasks where more advanced models exist). This limits their ability to select truly task-specific, state-of-the-art approaches.
2. **Coarse Exploration Strategies:** Existing agents often modify the entire code structure at once, hindering deep and iterative exploration within specific ML pipeline components. This means they might prematurely switch between stages (e.g., model selection to hyperparameter tuning) without fully optimizing a particular component like feature engineering.
3. **Scalability and Generalizability Issues:** Some agents, like DS-Agent, rely on manually curated "case banks" (e.g., from Kaggle solutions), which are difficult to scale, prone to overfitting to past patterns, and may not generalize well to novel or multi-modal tasks.

MLE-STAR directly addresses these limitations. It bridges the gap between the powerful code generation capabilities of LLMs and the need for up-to-date external knowledge and targeted optimization. By integrating a web search engine and a fine-grained, ablation-guided refinement mechanism, MLE-STAR aims to build a more intelligent, adaptable, and high-performing MLE agent that can select effective models, perform deep exploration within components, and generalize across diverse ML tasks without extensive human curation.

### 2. Key Objectives and Motivation

The primary objective of MLE-STAR is to **streamline the labor-intensive and iterative process of developing high-performance machine learning models** by introducing a novel, highly effective LLM-based Machine Learning Engineering (MLE) agent. The authors are motivated by the challenges data scientists face in tasks ranging from data engineering to extensive model experimentation.

The key motivations and specific objectives of MLE-STAR are to overcome the inherent limitations observed in existing LLM-based MLE agents:

1. **Mitigate LLM's Bias Towards Familiar/Outdated Methods:** Current LLM agents often suggest common or older ML models due to their training data, neglecting more effective, task-specific, or recently developed approaches. MLE-STAR aims to counter this by leveraging **external knowledge retrieval via web search** to identify and incorporate state-of-the-art models relevant to the given task.
2. **Enable Deep, Targeted Exploration of ML Pipeline Components:** Existing agents tend to modify the entire code solution broadly, preventing focused optimization of specific parts of the ML pipeline (e.g., feature engineering, data preprocessing, ensemble building). MLE-STAR's objective is to implement a **targeted code block refinement strategy**, where an agent iteratively focuses on improving individual, high-impact ML components, guided by **ablation studies**.
3. **Enhance Scalability and Generalizability Beyond Fixed Knowledge Bases:** Agents relying on manually curated case banks suffer from scalability issues, potential overfitting, and limited applicability to new or complex multi-modal tasks. MLE-STAR aims for a more flexible and scalable approach by dynamically retrieving information and exploring code space directly, making it adaptable to a wider array of ML problems.
4. **Introduce Novel Ensemble Strategies:** To further boost model performance, a specific objective is to develop a novel **ensembling method** that intelligently combines multiple candidate solutions, moving beyond simple voting or best-of-N selections.
5. **Improve Robustness and Reliability:** LLM-generated code can sometimes exhibit "misbehaviors" like data leakage or incomplete data utilization. A critical objective is to integrate **auxiliary modules (debugging, data leakage checker, data usage checker)** to ensure the generated solutions are robust, fair, and make optimal use of all provided data.

In essence, MLE-STAR aims to build a more intelligent, adaptive, and high-performing MLE agent by combining external search capabilities with a structured, iterative, and component-wise refinement process, all while ensuring the robustness of the generated code.

### 3. Methodology and Approach

MLE-STAR proposes a multi-agent framework designed to automatically generate high-performance ML solutions. The core methodology integrates web search for initial solution generation and a multi-stage, targeted refinement process. The system operates on a given task description (`T_task`) and datasets (`D`) to produce an optimal Python script.

The methodology can be broken down into three main phases, augmented by robustness modules:

1. **Generating an Initial Solution using Web Search as a Tool:**
 - **Candidate Model Search:** To overcome LLM biases towards outdated models, MLE-STAR first employs a `retriever` agent (`A_retriever`). This agent utilizes Google Search to identify and retrieve `M` effective, state-of-the-art ML models relevant to the `T_task`. For each retrieved model, a description (`T_model`) and an example code snippet (`T_code`) are obtained.
 - **Candidate Evaluation:** A `candidate evaluation` agent (`A_init`) then generates an initial Python script (`s_i_init`) for each of the `M` retrieved models, incorporating the `T_model` and `T_code`. These scripts are evaluated for performance (`h(s_i_init)`) on a validation set.
 - **Merging Candidate Models:** The top-performing `s_i_init` scripts are then iteratively merged to form a consolidated initial solution (`s_0`). This process starts with the highest-scoring script, and a `merger` agent (`A_merger`) attempts to integrate subsequent higher-ranked scripts (guided to use simple averaging ensembles) until no further performance improvement is observed on the validation set.

2. **Refining a Code Block for Solution Improvement:**
 This is an iterative process over `T` "outer loops," where the current solution (`s_t`) is refined.
 - **Targeted Code Block Extraction:** To focus refinement efforts, an `ablation study` agent (`A_abl`) generates a script (`a_t`) designed to perform an ablation study on `s_t`. This script creates variations of `s_t` by modifying or disabling 2-3 specific ML components (e.g., feature engineering, data preprocessing, model selection). Previous ablation summaries are fed back to `A_abl` to encourage diversity in explored components. The execution of `a_t` yields results (`r_t`), which are summarized by `A_summarize` into `T_t_abl`. Finally, an `extractor` agent (`A_extractor`) analyzes `T_t_abl` and `s_t` to identify the specific `code block` (`c_t`) that had the most significant impact on performance, prioritizing blocks not yet refined. It also generates an initial refinement plan (`p_0`) for `c_t`.
 - **Code Block Refinement (Inner Loop):** Once `c_t` and `p_0` are identified, an "inner loop" explores `K` potential refinement strategies for `c_t`. A `coder` agent (`A_coder`) implements `p_0` to produce a refined block (`c_0_t`), which replaces `c_t` in `s_t` to form a candidate solution (`s_0_t`). This is evaluated. For subsequent iterations (`k = 1..., K-1`), a `planner` agent (`A_planner`) proposes new plans (`p_k`) for `c_t`, leveraging the outcomes of previous attempts as feedback. `A_coder` implements these plans, and `s_k_t` solutions are generated and evaluated. After `K` refinements, the best-performing `s_k_t` (if it improves `s_t`) becomes the solution for the next outer loop (`s_{t+1}`).

3. **Further Improvement by Exploring Ensemble Strategies:**
 To enhance the final solution, MLE-STAR introduces a novel ensembling procedure.
 - Given `L` distinct solutions (e.g., from parallel runs of the refinement process), an `ensemble planner` agent (`A_ens_planner`) iteratively proposes various ensemble plans (`e_r`). These plans can range from simple averaging of predictions to more complex stacking methods, with feedback from previous attempts.
 - An `ensembler` agent (`A_ensembler`) implements `e_r` to merge the `L` solutions into an ensembled solution (`s_r_ens`). The best-performing `s_r_ens` after `R` iterations is selected as the final output.

4. **Additional Modules for Robust MLE Agents:**
 To ensure the quality and reliability of the generated code, MLE-STAR integrates specialized checker agents:
 - **Debugging Agent (`A_debugger`):** If a script execution results in an error (`T_bug`), `A_debugger` attempts to correct the script iteratively.
 - **Data Leakage Checker (`A_leakage`):** This module analyzes preprocessing code blocks to detect and prevent data leakage (e.g., using test set statistics for imputation). If detected, it generates a corrected version.
 - **Data Usage Checker (`A_data`):** Before refinement, this agent checks if the initial solution utilizes all relevant provided data sources from the `T_task` and revises the script if necessary.

The entire system is orchestrated with specific prompts and algorithms for each agent, detailed in the appendix, showcasing a comprehensive and modular approach to ML engineering automation.

### 4. Main Findings and Results

MLE-STAR's effectiveness was rigorously evaluated on 22 Kaggle competitions from the **MLE-bench Lite** benchmark, demonstrating significant performance improvements over existing state-of-the-art LLM-based MLE agents. Experiments were typically run with three random seeds, with baselines often using more seeds for robustness.

**Quantitative Performance on MLE-bench Lite (Table 1):**
- **Overall Superiority:** MLE-STAR, particularly with Gemini-2.5-Pro, achieved medals in **63.6%** of the competitions, with **36.4%** being gold medals. With Gemini-2.0-Flash, it achieved 43.9% any medal and 30.3% gold.
- **Outperforming Baselines:** When compared to AIDE (the leading alternative) using the same Gemini-2.0-Flash model, MLE-STAR substantially improved:
 - "Any Medal" achievement rate from 25.8% to **43.9%** (an 18.1 percentage point gain).
 - "Above Median" performance from 39.4% to **63.6%**.
 - Notably, MLE-STAR with Gemini-2.0-Flash even surpassed AIDE running on a more powerful reasoning model (o1-preview) in gold medal achievement (30.3% vs 20.7%).
- **LLM Scaling:** The results clearly indicated that MLE-STAR's performance scaled with the capability of the underlying LLM, with Gemini-2.5-Pro yielding better results than Gemini-2.0-Flash (e.g., higher medal rates across all categories).

**Comparison to DS-Agent (Table 2 & 9):**
- Despite DS-Agent's reliance on a manually curated Kaggle case bank (which limits direct comparison across diverse modalities), MLE-STAR was evaluated on four tabular tasks previously used in DS-Agent's development.
- MLE-STAR (Gemini-2.0-Flash) significantly **outperformed DS-Agent** (across various LLMs including GPT-3.5, GPT-4, and Gemini-2.0-Flash) on metrics like MAE (wild-blueberry-yield), Accuracy (spaceship-titanic), and AUROC (enzyme-substrate), and showed comparable performance on RMLSE (media-campaign-cost). This highlights MLE-STAR's efficiency even without human-intensive case bank construction.
- Furthermore, MLE-STAR also **outperformed AutoGluon**, a specialized AutoML tool for tabular data, on three out of four tasks, demonstrating its competitive edge even against domain-specific automated solutions.

**Ablation Studies:**
- **Performance with Reasoning Models (Table 3):** Experiments with Claude-Sonnet-4 further demonstrated the framework's compatibility and generalizability across different LLM types, showing promising results on diverse tasks (image-to-image, image classification, text classification, audio classification). This reinforces the idea that MLE-STAR can harness advancements in various reasoning-based LLMs.
- **Effectiveness of Proposed Ensemble Method (Table 4):** The novel ensembling strategy of MLE-STAR provided substantial gains:
 - It consistently improved the "Any Medal" rate (from 37.9% without ensemble to 43.9% with ensemble) and specifically the "Gold Medal" rate (from 25.8% to 30.3%).
 - It also performed better than simpler ensemble strategies like "Best-of-N" or "Average ensemble," indicating the value of LLM-guided ensemble plan generation.

**Qualitative Observations:**
- **Model Usage:** MLE-STAR actively leverages web search to identify and use more recent and competitive models (e.g., EfficientNet, ViT for image tasks) compared to baselines (e.g., AIDE using older ResNet architectures), directly contributing to performance gains.
- **Human Intervention:** The framework allows for minimal human intervention, such as manually introducing a model description, which MLE-STAR can then integrate into its solution generation.
- **Correction of LLM Misbehavior:**
 - The **data leakage checker** successfully identified and corrected instances where LLMs incorrectly used test data statistics for preprocessing (e.g., on spaceship-titanic), preventing significant drops in test accuracy (Table 5).
 - The **data usage checker** ensured that LLM-generated scripts fully utilized all provided data sources (e.g., `geometry.xyz` files in nomad2018-predicting), leading to notable performance improvements (Table 6).
- **Progressive Improvement:** Analysis of refinement trajectories (Figure 8) showed consistent performance improvement across the iterative refinement steps, with the ablation study module effectively targeting high-impact code blocks for earlier optimization.
- **Novelty of Solutions:** An LLM-as-a-judge evaluation (Appendix H) determined that MLE-STAR's final solutions were sufficiently novel compared to top Kaggle discussions, mitigating concerns about data contamination.

In summary, MLE-STAR demonstrably achieves state-of-the-art performance for LLM-based MLE agents, largely due to its innovative integration of external knowledge, targeted refinement, intelligent ensembling, and robust error/leakage handling mechanisms.

### 5. Significance and Potential Impact

MLE-STAR represents a significant advancement in the field of automated machine learning and LLM-powered agents, with substantial implications for how machine learning models are developed and deployed.

**Key Contributions and Significance:**
1. **Addressing Core LLM Agent Limitations:** MLE-STAR effectively tackles the critical shortcomings of previous LLM-based MLE agents: the reliance on potentially outdated internal LLM knowledge, coarse exploration strategies, and the scalability issues of manually curated case banks. By doing so, it pushes the frontier of what LLMs can autonomously achieve in complex engineering domains.
2. **State-of-the-Art Performance:** The experimental results on MLE-bench Lite are compelling, showcasing that MLE-STAR significantly outperforms leading baselines, achieving a remarkable 64% medal rate (including 36% gold medals) on Kaggle competitions. This demonstrates not just a theoretical improvement but practical, competitive performance that rivals human experts in many scenarios.
3. **Intelligent Knowledge Integration:** The novel approach of using a search engine to retrieve up-to-date, task-specific models and example code is a powerful mechanism for overcoming LLM knowledge "stale-ness." This allows MLE-STAR to adapt to evolving best practices and new model architectures dynamically.
4. **Targeted and Efficient Refinement:** The core idea of "Search and Targeted Refinement," guided by ablation studies, enables a more efficient and profound exploration of the solution space. By focusing on high-impact code blocks, MLE-STAR optimizes the development process and achieves greater performance gains within reasonable computational constraints.
5. **Robustness and Reliability:** The inclusion of dedicated debugging, data leakage checking, and data usage checking modules is crucial. These modules proactively address common misbehaviors of LLMs in code generation, ensuring that the generated solutions are not only high-performing but also safe, fair, and scientifically sound. This enhances trust and practical applicability.
6. **Generalizability and Adaptability:** MLE-STAR is designed to be applicable across diverse ML tasks and data modalities (tabular, text, image, audio), making it a versatile tool. Its ability to leverage new LLMs (e.g., Gemini-2.5-Pro, Claude-Sonnet-4) and incorporate novel models with minimal human intervention further underscores its adaptability and future-proofing.

**Potential Impact:**
- **Democratization of ML:** By automating complex ML engineering tasks, MLE-STAR could significantly lower the barrier to entry for individuals and organizations without extensive data science expertise. This could enable wider adoption of ML across various sectors and foster innovation.
- **Accelerated ML Development:** Data scientists and ML engineers can leverage MLE-STAR to rapidly prototype, optimize, and deploy models, freeing up human experts to focus on more strategic and creative aspects of ML projects. This could dramatically reduce development cycles and time-to-market for ML-powered solutions.
- **Enhanced Performance:** The consistent ability to achieve competitive results on challenging Kaggle tasks suggests that MLE-STAR can generate high-quality, production-ready solutions, automatically integrating best practices and advanced techniques.
- **Catalyst for LLM Agent Research:** This work provides a robust framework and strong empirical evidence for the efficacy of specialized LLM agents, likely inspiring further research into more intelligent and autonomous systems for scientific and engineering tasks.
- **Self-Improving Systems:** The framework's reliance on web search and continuous refinement suggests a path towards self-improving ML systems that automatically adapt to new data, models, and best practices as they emerge online.

**Limitations (as acknowledged by authors):**
The primary limitation noted is the potential for data contamination, given that Kaggle competitions are publicly accessible and LLMs might have been trained on relevant discussions. However, the authors address this by demonstrating that MLE-STAR's solutions are judged as "sufficiently novel" by another LLM, suggesting that it's not simply memorizing and reproducing existing solutions but synthesizing new ones. This ongoing challenge in LLM research needs continued attention.

Overall, MLE-STAR represents a significant step towards truly autonomous and intelligent machine learning engineering, promising to make the development of high-performance ML models more accessible, efficient, and robust.
