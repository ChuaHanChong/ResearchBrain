# Communication-Aware Robot Execution for Cloud Inference under Spatially Heterogeneous Connectivity

> [!summary] Summary
> Researchers at The University of Osaka developed a communication and motion co-design framework for cloud-powered robots operating in environments with varying wireless connectivity. This framework enables robots to proactively select communication-favorable points for cloud inference, achieving 100% task success in simulation while drastically reducing cloud request failures and redundant interactions.

## Problem

- Autonomous robots relying on cloud-hosted foundation models face execution fragility due to spatially heterogeneous wireless connectivity.
- The temporal need for subsequent cloud inference results often conflicts with the spatially varying opportunities for reliable communication.
- Existing methods, like latency mitigation or communication-aware motion planning, do not proactively select optimal locations for cloud requests to ensure continuous task progression.

## Method

- A **communication and motion co-design** framework integrates high-level task scheduling with low-level robot navigation in a ==cloud-local architecture==.
- The system estimates a ==request-response window== to predict the full duration of a cloud interaction, encompassing inference latency and network transmission times.
- It actively selects an optimal ==request point== based on communication quality, task progress, and a feasible downstream window for response retrieval, guided by a communication-aware ==Model Predictive Path Integral (MPPI)== local planner.

## Results

- The proposed framework achieved **100%** task success rates in simulation for certain observation ranges, demonstrating superior reliability compared to baseline methods.
- It significantly reduced cloud request failures (**0.0%** at best), redundant requests, and robot waiting times, indicating higher efficiency in resource utilization.
- Robot trajectories actively adapted to seek communication-favorable 'request points' before submitting cloud queries, without significantly increasing total task execution time compared to asynchronous baselines.

## Takeaways

> [!tip] Key Insights
> - Actively transforming the selection of cloud request submission points into a proactive motion planning decision is crucial for robust cloud robotics in heterogeneous wireless environments.
> - Precisely predicting the full request-response interaction time, including inference and transmission, provides a necessary temporal constraint for local robot planning.
> - Integrating communication quality and expected response availability into the robot's local path planning enables trajectories that opportunistically leverage strong connectivity for continuous task execution.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

The integration of large foundation models (e.g., large language models, vision-language models) is fundamentally reshaping the capabilities of autonomous robots, allowing them to perform complex semantic reasoning that far exceeds the computational limits of onboard processors. This paradigm, often referred to as cloud robotics, involves offloading computationally intensive tasks to remote servers. Within this landscape, the robot typically executes a high-level "primitive" or instruction generated by a cloud-hosted model, with continuous task progression dependent on receiving the next primitive before the current one is fully consumed.

A significant challenge in this setup arises from the interaction between robot motion and wireless communication in real-world environments, which often exhibit spatially heterogeneous connectivity. While the robot's task execution dictates the *timing* of when the next cloud result is needed, the spatially varying wireless environment dictates the *location* where a cloud request can be reliably submitted and its response retrieved.

Previous research has explored two main avenues related to this challenge:
1. **Latency Mitigation through Computation and Offloading:** This area focuses on system-level optimizations such as deploying services closer to the edge, replicating cloud resources, or using asynchronous execution patterns (e.g., in Vision-Language-Action (VLA) systems) to reduce or mask the latency of remote inference. These methods primarily address *how* cloud services are managed or invoked to reduce delay, but they generally treat the robot's request submission location as a passive outcome of its current state rather than an active decision variable.
2. **Communication-Aware Motion Planning:** This field incorporates wireless communication quality into robot motion planning, enabling robots to design trajectories that maintain connectivity or select specific transmission points based on signal strength or radio maps. While these methods optimize for communication, they are not typically designed to account for the specific characteristics of delayed foundation model inference, where a high-level semantic result is needed for *continued* task execution.

This paper addresses a critical gap by explicitly coupling robot motion with spatially varying connectivity and the requirements of delayed cloud inference. It moves beyond simply reducing latency or maintaining a continuous link, focusing on the proactive selection of communication-favorable *request points* to ensure the continuity of semantic execution derived from cloud-hosted foundation models. By doing so, it contributes to bridging the system-level concerns of cloud robotics with the spatial and temporal considerations of robot autonomy in dynamic environments.

### 2. Key Objectives and Motivation

The primary objective of this research is to enable uninterrupted robot task execution that relies on cloud-hosted foundation models, particularly in wireless environments characterized by spatially heterogeneous connectivity. The authors identify a core problem: the temporal dependency of task progress on subsequent cloud inference results is often at odds with the spatial variability of reliable communication opportunities.

The specific motivations and objectives are detailed as follows:

- **Addressing Fragile Execution under Heterogeneous Connectivity:** Robots executing a finite primitive from the cloud must receive the next primitive before the current one is exhausted. This becomes fragile when the robot's location, and thus its wireless connectivity, changes during execution. Existing methods that reduce latency or improve individual transmissions (e.g., redundant paths, resource allocation) do not resolve the fundamental problem of determining *where* the robot should be to reliably submit a request and retrieve a response. A robot might still fail if it attempts communication in a weak-connectivity region, regardless of average latency improvements.
- **Introducing the Request–Response Window:** To systematically quantify the timing requirements for a complete cloud interaction, the paper proposes the "request–response window." This concept characterizes the total estimated duration from the moment a cloud request is submitted to the moment the corresponding response is retrieved. This window encompasses uplink transmission time (often dominant due to large observation data), cloud inference latency (which can fluctuate and needs online prediction), downlink retrieval time (for the typically compact primitive), and an uncertainty margin for inference variability. The motivation is to provide a holistic temporal constraint that the robot's local planner must respect.
- **Treating Request Point as a Motion Decision:** The central motivation is to transform the selection of the next cloud request submission point from a passive consequence of the robot's current trajectory into an active motion planning decision. Instead of submitting a request from the robot's current location, which might be in a poor communication zone, the robot should proactively move to an optimized "request point." This point must offer sufficient communication quality for submission, preserve progress toward the current task target, and crucially, leave a feasible downstream opportunity for response retrieval within the estimated request–response window.
- **Developing a Communication-Aware Local Planner:** Once a request point is selected, the robot needs to be guided towards it. After submitting the request, the robot continues its primary task. The motivation is to ensure that during this period (between submission and response retrieval), the robot maintains sufficient connectivity for the response and does not exhaust its current primitive prematurely. This necessitates integrating communication-aware costs and objectives into the local motion planner to shape trajectories that are robust to communication outages.
- **Validating in a Realistic Wireless Scenario:** The ultimate motivation is to demonstrate that by co-designing communication and motion, task success rates can be improved, while minimizing inefficiencies such as excessive waiting, failed requests, or redundant cloud interactions. This validation must occur in a scenario that captures the spatial variability of real-world wireless environments.

### 3. Methodology and Approach

The proposed framework, termed communication and motion co-design, integrates high-level task scheduling with low-level robot navigation to coordinate local execution with remote cloud reasoning. It operates under a hierarchical cloud-local architecture.

**A. Cloud–Local Architecture**
The system adopts a strict functional partitioning:
- **Cloud Foundation Model:** Responsible for cognitive reasoning, interpreting user intents from high-dimensional multimodal inputs, and generating abstract, high-level semantic primitives (e.g., a target coordinate for navigation, a manipulation policy). It does not account for real-time local dynamics or precise geometric constraints.
- **Local Controller:** Operates onboard, handling real-time geometric grounding, safety-critical execution, mapping cloud-derived semantic intents to the robot's physical constraints, and generating feasible trajectories (e.g., path planning, calculating manipulator base placement).

The robot's planar position is denoted `r(t)`. Each cloud primitive `p(k)` (from the k-th request) induces a 2D base waypoint `w`. The robot is assumed to have access to an environmental communication map `M(r)` (e.g., RSSI, RSRP), which indicates expected communication quality at any location.

**B. Request–Response Window Estimation**
To enable seamless autonomy, the robot must obtain the next primitive `p(k+1)` before the current one `p(k)` is exhausted. This requires predicting the duration of a full cloud interaction cycle, called the request–response window (`b_T_window`).
1. **Cloud Inference Latency:** `b_T_infer(k+1)` and its variance `σ_infer^2(k+1)` are estimated using an Exponential Weighted Moving Average (EWMA) based on past observations (`T_obs_infer(k)`) and a smoothing factor `α` (Equations 1, 2).
2. **Network Transmission Times (Uplink/Downlink):**
 - Uplink throughput `R_up(r)` at a location `r` is estimated from an effective uplink SNR.
 - `SNR_up(r)` is calculated from `M(r)` (signal level from communication map), adjusted by an uplink asymmetry term `ΔP_tx` and noise floor `N_noise` (Equation 3).
 - Packet Error Rate (PER) `ρ(r)` is modeled by a logistic waterfall curve, sharply degrading near a sensitivity threshold `SNR_th` (Equation 4).
 - Expected goodput `R_up(r)` incorporates `ρ(r)` and a congestion penalty `γ` with baseline link rate `R_link(r)` (Equation 5).
 - Uplink transmission latency `T_up(r)` is `D_up / R_up(r)`, where `D_up` is uplink payload size (Equation 6). Downlink latency `T_down(r)` is computed similarly for `D_down`.
3. **Total Request–Response Window:** `b_T_window(k+1, r) = T_up(r) + T_down(r) + b_T_infer(k+1) + β * σ_infer(k+1)` (Equation 7), where `β * σ_infer(k+1)` acts as a dynamic safety buffer for uncertainty. A single-location approximation is used for `b_T_window` calculation, simplifying online tractability and justified by uplink/inference dominance in duration.

**C. Request Point Optimization**
This component selects an optimal request point `p*` for the next cloud request, ensuring reliable submission and downstream response retrieval while maintaining task progress.
1. **Forward Region (`R_fwd_t`):** Candidate points `p` are filtered to be ahead of the robot towards the current waypoint `w` and to incur a bounded detour `ε_det` (Equation 8).
2. **Downstream Retrieval Margin (`Δ_t_ret(p)`):** For each `p` in `R_fwd_t`, this margin calculates the largest time slack between travel from `p` to a downstream communication-feasible point `q` (where `M(q) >= S_ret`) and the `b_T_window` (Equation 9). A positive margin indicates a feasible retrieval opportunity.
3. **Robust Request Region (`R_req_t`):** Defined as points `p` in `R_fwd_t` that satisfy sufficient communication quality for submission (`M(p) >= S_sub`) and have a positive retrieval margin greater than a safety margin `ε_safe` (Equation 10).
4. **Request Point Selection (`p*`):** `p*` is chosen from `R_req_t` to minimize the combined travel time `τ_move(r(t), p) + τ_move(p, w)` (Equation 11), ensuring the least additional motion cost to the current waypoint.
5. **Fallback Mechanism:** If `R_req_t` remains empty after three consecutive recomputations, the robot falls back to submitting the request at the next communication-favorable position encountered along its current path.

**D. Communication-Aware Local Path Planning**
A Model Predictive Path Integral (MPPI) local planner generates robot motion, integrating dynamics, collision avoidance, and communication requirements.
1. **Objective Function:** The planner minimizes a cost function comprising navigation (`J_nav`), control regularization (`J_ctrl`), and a communication-aware auxiliary cost (`J_ca`) (Equation 13).
2. **Active Goal `g(t)`:** Before request submission, `g(t)` is `p*`. After submission (and until response buffering), `g(t)` reverts to the current waypoint `w`.
3. **Auxiliary Cost Gate `α_t`:** `J_ca` is only active (i.e., `α_t = 1`) after a request is issued and until its response is buffered locally.
4. **Cost Terms:**
 - **Navigation (`J_nav`):** Penalizes deviation from `g(t)` over the prediction horizon `H`, with increasing weights for later steps (Equation 14).
 - **Control Regularization (`J_ctrl`):** Encourages smooth control sequences (Equation 15).
 - **Communication-Aware Auxiliary Cost (`J_ca`):**
 - **Communication Penalty (`J_comm`):** Penalizes predicted trajectories entering weak-coverage regions where `M(r_l)` falls below the retrieval threshold `S_ret` (Equation 17).
 - **Arrival Time Penalty (`J_arr`):** Discourages the robot from reaching the current waypoint `w` before the cloud response is estimated to be ready (`b_T_window`) (Equation 18). This prevents premature primitive exhaustion and "stop-and-wait" behavior.
5. **MPPI Solution:** MPPI generates trajectories by sampling control sequences. Rollouts are scored based on the objective function (`S(ξ_i)`, Equation 19). Infeasible rollouts (collision, control bounds) are discarded. The nominal control sequence is updated using importance-weighted averaging (Equation 20).

This methodology systematically integrates communication predictions and requirements into active motion planning, aiming to ensure continuous robot operation with cloud intelligence.

### 4. Main Findings and Results

The evaluation was conducted in a ROS-integrated Gazebo simulation using a TurtleBot3 Burger model. The wireless environment was derived from the SYL scenario of the SODIndoorLoc dataset, providing a realistic, measurement-based indoor communication map with spatially degraded connectivity (e.g., strong coverage in office areas, weak in corridors). Cloud-generated primitives were emulated as waypoints sampled from a global path, with a mock VLM introducing a sampled request-response delay. All methods shared the same robot model, task route, communication map, and cloud delay model. Experiments were run from 11 different start positions to assess robustness to varying connectivity along the path.

**A. Baselines:** The proposed method was compared against three baselines:
- **Stop-and-wait execution:** Robot completes current primitive, then stops and waits for the next cloud response.
- **Fixed-period asynchronous requests:** Robot issues requests at a fixed interval (5s, 10s, or 15s) while executing, without communication awareness.
- **Inference-only asynchronous requests:** Robot issues requests early based on estimated inference time, but does not use the communication map to select the submission location.

**B. Metrics:** Key metrics included task success rate (`R_succ`), request-response window (`T_window`), number of cloud requests (`N_req`), waiting time (`T_wait`), request failure rate (`R_fail`), and overlap rate (`R_ovl`).

**C. Quantitative Results:**
- **Overall Performance (Table II, Figures 5 & 6):**
 - The proposed method consistently achieved the **highest or tied-highest task success rate** across all tested observation ranges (`D_obs` = 5.0 m, 5.5 m, 6.0 m). For `D_obs` = 5.5 m and 6.0 m, it achieved 100% success.
 - This high success was accomplished with **significantly fewer cloud requests (`N_req`)** compared to the fixed-period asynchronous baselines, especially the shorter-period ones (e.g., at `D_obs` = 6.0 m, proposed: 15.3 ± 1.6 requests vs. fixed-period 5s: 50.5 ± 3.4 requests for 100% success). This indicates that the improvement is not merely due to increased request frequency.
 - The proposed method exhibited **substantially lower waiting time (`T_wait`), request failure rate (`R_fail`), and overlap rate (`R_ovl`)**. For `D_obs` = 5.5 m and 6.0 m, its `R_fail` and `R_ovl` were 0.0%, demonstrating highly reliable and non-redundant cloud interactions. In contrast, baselines, particularly fixed-period 5s, showed high `R_fail` (e.g., 56.9% at 6.0m) and `R_ovl` (e.g., 51.5% at 6.0m).
 - The estimated `T_window` remained comparable across all methods (mean values between 6.4 and 6.9 seconds), suggesting that the performance differences are attributed to the communication strategy rather than intrinsic cloud latency.
- **Execution Behavior (Figure 4):** A representative trace illustrated the proposed method's active relocation strategy. Unlike baselines that follow the nominal path, the proposed method computes and guides the robot towards communication-favorable request points, resulting in trajectories that opportunistically bend towards stronger connectivity regions before request submission.
- **Execution Time Overhead (Figure 7):** For successful task completions, the proposed method's total execution time was comparable to that of the asynchronous baselines. This suggests that the gains in reliability and efficiency (reduced waiting and failures) were not achieved by significantly slowing down the robot or incurring large detours.
- **Boundary Behavior of Submissions (Figure 8):** The RSSI measurements at request submission events for the proposed method indicated that most requests were submitted from locations above the communication feasibility threshold. Residual failures, particularly at the shortest observation range (`D_obs` = 5.0 m), occurred close to this threshold. This highlights a robustness-feasibility trade-off, where limited primitive support or steep RSSI gradients can challenge point-based request placement.

**D. Synthesis of Findings:** The results collectively demonstrate that actively selecting communication-favorable request points for cloud inference significantly improves task success and operational efficiency in spatially heterogeneous wireless environments. The proposed method's ability to reduce request failures and redundant submissions, while maintaining competitive task completion times, supports the hypothesis that co-designing motion and communication is crucial for robust cloud robotics.

### 5. Significance and Potential Impact

This research presents a significant advancement in the field of cloud robotics and robot autonomy, particularly for systems relying on powerful, remotely hosted foundation models. Its significance and potential impact can be summarized as follows:

- **Enabling Robust Cloud Robotics:** The work directly addresses a critical vulnerability of cloud-driven robots: the fragility of execution under spatially heterogeneous wireless connectivity. By proactively managing communication opportunities, it enhances the robustness and reliability of robot operations in real-world environments where Wi-Fi or 5G signal quality is rarely uniform.
- **Optimized Resource Utilization:** The proposed method substantially reduces the number of unnecessary cloud requests, request failures, and redundant (overlapped) interactions. This leads to more efficient use of cloud computing resources, reduced network bandwidth consumption, and lower operational costs for cloud-robot systems.
- **Improved Execution Continuity and Efficiency:** By minimizing robot waiting time for cloud responses and preventing premature primitive exhaustion, the framework promotes smoother and more continuous task execution. This directly translates to higher operational efficiency and potentially faster task completion in complex scenarios.
- **Bridging Key Research Areas:** The paper effectively integrates insights from network communication, robot motion planning, and distributed computing (cloud/edge robotics). It highlights that for advanced robotic systems, these domains cannot be treated in isolation; their co-design is essential for realizing their full potential.
- **Foundation for Future Autonomous Systems:** As foundation models become more central to robot intelligence, the ability to reliably interact with them from dynamic, mobile platforms is paramount. This research lays a foundation for more intelligent and resilient autonomous systems capable of leveraging remote AI capabilities in diverse and unpredictable settings.
- **Guidance for Practical Deployments:** The findings provide practical guidance for deploying cloud-enabled robots. Instead of solely focusing on network infrastructure improvements or reactive latency compensation, developers should consider active communication-aware motion planning to optimize the timing and location of cloud interactions.

**Potential Future Work and Impact:**
The authors themselves identify several avenues for future research that underscore the broader impact:
- **Dynamic and Incomplete Communication Maps:** Extending the framework to handle communication maps that are incomplete, learned online, or dynamically changing (due to human movement, occlusion, or network load) would significantly enhance real-world applicability. This would make the system robust to real-time environmental variability.
- **Real-World Closed-Loop Experiments:** Validating the framework with actual cloud inference over deployed Wi-Fi or 5G networks, rather than solely in simulation, is crucial for assessing its effectiveness and limitations in practical systems, accounting for real-world network stack behaviors and hardware constraints.
- **Degraded Execution and Fallback Strategies:** Investigating how robots can maintain basic task progress through degraded execution, local fallback mechanisms, or task replanning when communication-favorable regions are scarce for extended periods is vital. This would address scenarios where ideal communication is simply not available, enabling graceful degradation rather than complete task failure.

In conclusion, this research significantly contributes to making cloud-powered robots more reliable and effective in the face of real-world wireless communication challenges, paving the way for more capable and robust autonomous systems.
