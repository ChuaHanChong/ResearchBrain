# TrackEverything: Long Horizon Dense Tracking via De-Duplicating 3D Scene Representations

> [!summary] Summary
> TrackEverything is a 3D point tracker that represents video as persistent world-coordinate scene tracks. It voxel-de-duplicates co-located tracks at sliding-window boundaries, splits tracking into an endpoint refiner with static/dynamic classification and a trajectory refiner run only on dynamic points, and replaces 4D correlation volumes with 3D WAFT feature sampling. It tracks all points across 1000+ frame videos within 40 GB, beating open-source all-frame dense 3D trackers by over 20% APD.

## Problem

- Sparse trackers span long horizons but only for user-specified query points, leaving the rest of the scene unmodeled; their 4D correlation volumes scale with query count.
- Dense trackers operate in frame-local pixel space, so compute and memory grow linearly with video duration, exhausting GPU memory beyond roughly 96 frames.
- Existing dense methods compromise: they either track only first-frame-visible points, ignoring newly disoccluded surfaces, or track all points but only within 48-64 frame clips.

## Method

- ==Voxelization-based de-duplication== merges co-located tracks at window boundaries via mean-pooling, so representation size grows with unique scene geometry rather than with frame count.
- **Endpoints-before-trajectories** decomposition: an endpoint refiner predicts each point's window-boundary position plus a static/dynamic label, and a trajectory refiner decodes dense paths only for dynamic points.
- **3D WAFT** samples source and target image features at projected positions as a template-matching signal for self-attention, replacing memory-prohibitive ==4D correlation volumes== with cheap feature lookups.

## Results

- On 48-frame TAPVid-3D clips it averages **34.7** APD-P versus **10.9** for all-frame dense VDPM, and on full-length video **31.2** versus **29.7-29.8** for sparse trackers.
- On PointOdyssey peak memory stays under **30 GB** at 900 frames, while Any4D exceeds memory at 96 frames and SpatialTracker-v2 and DeltaV2-dense at roughly 200.
- Ablations: dropping iterative trajectory refinement moves APD-P from **31.2** to **26.4** and dropping 3D WAFT to **29.3**; the static/dynamic split cuts latency **4.8x** and memory **2.5x** at identical accuracy.

## Takeaways

> [!tip] Key Insights
> - Scale a video representation with unique 3D scene content rather than frame count; repeated re-observation of already-seen surfaces is the real long-video cost.
> - Predicting only window-boundary endpoints suffices to advance a sliding window, so expensive dense trajectory decoding can be reserved for the small moving subset.
> - Keeping geometry external lets a tracker inherit sensor and reconstruction advances without retraining, but irreversible voxel merges can permanently collapse distinct surfaces into one track.

## Detailed Report

### 1. Overview

A long video keeps showing surfaces that were already seen. Frame-by-frame processing represents that old scene content again each time, so its cost scales linearly with video duration. Long-horizon sparse tracking avoids this cost, but it follows only selected points and leaves most of the scene untracked. TrackEverything instead keeps surface tracks in a shared 3D world coordinate system, so repeated views of the same geometry can be merged. The authors report all-visible-point tracking on videos exceeding 1,000 frames within 40 GB of GPU memory.

TrackEverything tracks all points. Input RGB video appears above the corresponding dense 3D tracks. Dynamic points have trails, and static content is rendered as a point cloud. In the plot of active tokens against frames processed, the comparison at about 400 frames is labeled 4.86M versus 13.4k tokens.

### 2. A scene that remembers

The video is processed in short, non-overlapping 16-frame windows. Geometry and camera poses lift frame features into a shared world-coordinate 3D cloud. At each window boundary, the model quantizes predicted track positions into voxels, which are small cells of space, and mean-pools the tracks that land in the same voxel. The next window combines this compact carried-over scene state with newly observed points.

Tracking inside a window happens in two stages. An endpoint refiner first estimates where each point ends up at the boundary and whether it is static or moving. Static points keep their world positions. A trajectory refiner then decodes full within-window paths only for dynamic points.

To find correspondences, a component called 3D WAFT samples image features at projected source and target positions. This avoids constructing a costly 4D correlation volume.

Window *i*'s dense tracks are voxelized at their endpoints. The merged scene memory plus new geometry then enters Window *i+1*. In this example, 46k points become 16k after voxelization and mean-pooling.

### 3. What the tests establish

The evaluation uses APD-P, the fraction of queried points predicted within a distance threshold of ground truth, averaged over thresholds. Its thresholds are depth-relative and are obtained by unprojecting pixel thresholds into 3D. TAPVid-3D has sparse query-point annotations, so the score measures tracking fidelity on sampled points. It does not provide dense ground truth for every scene surface.

The first comparison uses the first 48 frames of TAPVid-3D. On the reported three-dataset average, TrackEverything scores 34.7 APD-P, and the open-source all-frame dense baseline VDPM scores 10.9, a gap of 23.8 points. Geometry differs between the two methods: TrackEverything uses VGGT-Ω geometry, while VDPM uses its native geometry.

One method does better on these short clips. D4RT reports a higher 48-frame average, with higher scores on DriveTrack and PStudio but a lower score on ADT. It is closed-source, uses roughly 20 times TrackEverything's parameter count, and trains on more data, including private data. It is evaluated only on 48-frame clips.

The second comparison is a set of ablations that test the mechanism itself. On the reported PointOdyssey test, removing voxelization leads to running out of memory, while the default voxel size is feasible. Removing static/dynamic classification leaves APD-P at 31.2. It raises latency from 0.05 to 0.24 seconds per frame and peak memory from 9.1 to 22.4 GB. These results support the claim that both de-duplication and selective trajectory decoding matter for efficiency. They do not establish that either is the only source of the system's gains.

### 4. Geometry sets the horizon

TrackEverything shifts computation toward unique 3D scene content and away from video duration. That shift lets dense coverage extend beyond short clips.

Its limits come from the same design. The representation grows with newly encountered scene geometry, so the paper does not show constant memory for indefinite open-world exploration. Tracking depends on input geometry, and poor pointmaps can affect it. Because boundary merging uses irreversible mean-pooling, it can collapse distinct surfaces if tracking errors bring them together.
