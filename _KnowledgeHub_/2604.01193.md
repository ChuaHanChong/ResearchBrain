# Embarrassingly Simple Self-Distillation Improves Code Generation

> [!summary] Summary
> A method called Simple Self-Distillation (SSD) enables large language models to enhance their code generation performance by training exclusively on self-generated, unverified solutions. This approach improved the Qwen3-30B-Instruct model's pass@1 score on LiveCodeBench v6 from 42.4% to 55.3%, demonstrating its efficacy without external supervision or complex verification.

## Problem

- High cost and difficulty of obtaining high-quality supervised training signals for LLM code generation, limiting scalability.
- Limitations of existing self-improvement methods, including performance ceilings for teacher-based distillation and operational complexities or instabilities in RL and unsupervised intrinsic reward systems.
- An inherent "precision-exploration conflict" in LLM decoding for code, where a single global temperature setting struggles to balance precise token generation at constrained points with necessary exploration for diverse algorithmic choices.

## Method

- Introduce ==Simple Self-Distillation (SSD)==, where a frozen base LLM generates a single candidate solution for each problem prompt using specific training-time decoding configurations, without any external verification.
- Fine-tune the base LLM on this self-generated, unverified dataset using standard ==supervised fine-tuning== with a ==cross-entropy loss== function.
- Deploy the resulting fine-tuned model with optimized evaluation-time decoding settings, designed to leverage the reshaped ==token distributions== for improved performance.

## Results

- SSD consistently increased pass@1 scores across five evaluated models, with **Qwen3-30B-Instruct** improving by **12.9pp** (from **42.4%** to **55.3%**) on LiveCodeBench v6.
- Performance gains were disproportionately higher for more challenging problems, showing pass@1 gains of up to **15.3pp** and pass@5 gains of **23.0pp** on hard problems for **Qwen3-30B-Instruct**.
- The SSD-trained model substantially outperformed the best-tuned base model configuration by **11.8pp** for **Qwen3-30B-Instruct** pass@1, indicating that SSD's changes are not achievable through decoding parameter adjustments alone.

## Takeaways

> [!tip] Key Insights
> - Simple Self-Distillation (SSD) alleviates the "precision-exploration conflict" by context-dependently reshaping the model's token distributions, suppressing distractors at "locks" while maintaining useful diversity at "forks."
> - SSD induces fundamental changes within the model's learned distributions that cannot be replicated by merely adjusting inference-time decoding parameters on the original model.
> - The method's benefits stem from distributional reshaping (support compression and within-support smoothing) rather than the superficial correctness of individual self-generated training samples, as improvements persist even with intentionally degraded training data.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

The development of large language models (LLMs) has advanced capabilities in various domains, including code generation. However, a significant challenge in improving these models, particularly for complex coding tasks, lies in the scarcity and high cost of acquiring high-quality supervised training data. Existing approaches to enhance LLMs for code generation face several limitations:

- **Human-labeled data:** Producing human-written solutions for intricate coding problems is resource-intensive and expensive.
- **Teacher-based distillation:** Methods that rely on stronger "teacher" models for synthetic data generation inherit the performance ceiling of the teacher model and require the availability of such a teacher.
- **Execution-based verification and Reinforcement Learning (RL):** Pipelines that use code execution to verify correctness or reinforcement learning with verifiable rewards are operationally complex, can be unstable, and necessitate an external verification mechanism.
- **Unsupervised intrinsic reward methods:** Alternatives utilizing intrinsic rewards, such as majority voting or entropy minimization, have shown promise but are susceptible to issues like reward hacking and potential model collapse under prolonged training.

This research introduces Simple Self-Distillation (SSD) as a method that addresses these limitations by enabling an LLM to improve its code generation capabilities using only its own raw, unverified outputs. Unlike many contemporary techniques, SSD operates without relying on external human-labeled data, a stronger teacher model, an external verifier, a reward model, an execution environment, or reinforcement learning. This positions SSD as a distinct and complementary direction in post-training optimization for LLMs, particularly in contexts where external resources are constrained or unavailable. It aims to demonstrate that a model can extract sufficient learning signals from its own self-generated, unverified samples to achieve performance improvements, thereby exploring an overlooked avenue in self-improvement mechanisms for LLMs.

### 2. Key Objectives and Motivation

The primary objective of this research is to investigate whether a large language model can enhance its code generation performance by training exclusively on its own raw, unverified outputs. This central question is motivated by the recognized challenges and limitations inherent in conventional LLM training and refinement paradigms, especially for complex tasks like code generation.

The motivations driving this inquiry include:

- **Addressing data scarcity and cost:** The increasing difficulty of coding tasks for LLMs has led to a binding constraint on the supply of high-quality supervised signals. Generating human-written solutions is costly, and synthetic data pipelines often require either a more capable teacher model or execution-based verification, adding layers of complexity and resource demands. SSD seeks to circumvent these dependencies by creating a self-sufficient improvement loop.
- **Overcoming limitations of existing self-improvement techniques:** While other self-training and distillation methods exist, many still incorporate elements of privileged information, feedback from human or model judges, or external reward signals. Reinforcement learning, despite its advancements, can be complex and unstable. Unsupervised methods, relying on intrinsic rewards, risk reward hacking or collapse. SSD aims for a simpler, more robust approach by removing these external or complex components entirely.
- **Exploring intrinsic model capabilities:** The researchers hypothesize that existing code models may possess untapped capabilities that are not fully realized under standard, fixed decoding policies. The objective is to determine if self-distillation can unlock this latent potential by intrinsically reshaping the model's output distributions.
- **Investigating the "precision-exploration conflict":** A core motivation is to understand the underlying mechanism by which such a simple self-distillation process could be effective. The paper introduces the concept of a "precision-exploration conflict" in LLM decoding for code generation. This conflict arises because some token positions ("locks") demand high precision (e.g., specific syntax), where a sharply peaked probability distribution is desirable, while others ("forks") require exploration and diversity (e.g., choice of algorithm), benefiting from a flatter distribution over plausible options. A single, global decoding temperature (T_eval) must compromise between these conflicting demands, potentially suboptimally. The research aims to demonstrate that SSD resolves this conflict by adaptively reshaping token distributions.

In summary, the key objectives are to demonstrate the efficacy of SSD for code generation improvement, identify the precision-exploration conflict as a core mechanism, and provide empirical and theoretical evidence to support this mechanistic explanation.

### 3. Methodology and Approach

The methodology revolves around Simple Self-Distillation (SSD), a two-stage process: data synthesis and fine-tuning, followed by standard inference. The approach systematically evaluates SSD's performance across various LLMs and provides a multi-faceted analysis of its underlying mechanisms.

#### 3.1. Simple Self-Distillation (SSD) Process

1. **Data Synthesis:**
 - A frozen, pre-trained LLM ($p_\theta$) is given a set of problem prompts ($X$).
 - The model samples $N$ candidate solutions per problem. This sampling is performed using specific training-time decoding configurations, including a temperature ($T_{train}$) and a truncation configuration ($\rho_{train}$, encompassing top-k and top-p sampling).
 - A critical aspect is that these sampled solutions are *not* verified for correctness through execution, test cases, or any filtering mechanism. They represent the raw outputs of the base model.
 - In practice, a single sample per prompt ($N=1$) was found to be sufficient.
 - The collection of these raw, unverified outputs forms the $D_{SSD}$ dataset.

2. **Training:**
 - A new instance of the model (or the original model) is fine-tuned on the $D_{SSD}$ dataset.
 - This fine-tuning uses standard supervised fine-tuning (SFT) with a cross-entropy loss function.

3. **Inference:**
 - The fine-tuned model ($p_{\theta^*}$) is then used for inference with its own evaluation-time decoding configuration ($T_{eval}$, $\rho_{eval}$).

#### 3.2. Experimental Setup

- **Models:** The study evaluated SSD on six distinct models: Llama-3.1-8B-Instruct, Qwen3-4B-Instruct-2507, Qwen3-4B-Thinking-2507, Qwen3-30B-A3B-Instruct-2507, Qwen3-30B-A3B-Thinking-2507, and GPT-OSS-20B. These models span three families (Llama, Qwen, GPT-OSS), scales from 4B to 30B parameters, and represent both "instruct" and "thinking" reasoning styles.
- **Data Synthesis Details:**
 - The prompts for self-sampling were drawn from the seed subset of the rSTARcoder dataset, de-duplicated to yield approximately 10,000 unique competitive programming problems.
 - A single solution was sampled per prompt from the base model, using model-specific decoding configurations for $T_{train}$, top-k, and top-p (details provided in Table 3 of the paper).
 - Only minimal syntactic filtering (e.g., removal of empty responses or single-line stubs) was applied; no correctness signal was utilized.
 - vLLM (v0.11.0) was used for generation with a maximum sequence length of 128K.
- **Training Details:**
 - Fine-tuning was performed using Megatron-LM on 8 NVIDIA B200 GPUs.
 - AdamW optimizer (β1=0.9, β2=0.95, weight decay 0.1) was used with a cosine learning rate decay schedule (peak LR 5 × 10⁻⁶, final LR 1 × 10⁻⁶).
 - A global batch size of 32 and sequence length of 65,536 were employed.
 - Instruct models were trained for 2,500 iterations (250 warmup iterations), and thinking models for 300 iterations (50 warmup iterations).
- **Evaluation:**
 - The primary benchmark was LiveCodeBench v6 (LCB v6; 131 problems, from Feb–May 2025), categorized by easy, medium, and hard difficulty levels.
 - LiveCodeBench v5 (LCB v5; 374 problems, from Aug 2024–Feb 2025) served as a secondary confirmation.
 - The main performance metric was pass@1, with pass@5 and per-difficulty breakdowns also reported.
 - For comparison, base models were evaluated with their officially recommended sampling parameters (Table 4), while SSD-trained models used optimized $T_{eval}$ settings (Table 3).
- **Hyperparameter Interaction Analysis:** A grid search over $T_{train}$ and $T_{eval}$ was conducted for Qwen3-30B-Instruct on LCB v6, comparing regimes with and without truncation, to understand the interplay of these parameters.

#### 3.3. Mechanism Analysis

The research employed a multi-pronged approach to understand *why* SSD works:
- **Precision-Exploration Conflict Hypothesis:** This hypothesis posits that code generation involves "lock positions" (syntactically constrained, demanding precision) and "fork positions" (multiple plausible continuations, demanding exploration). A single global decoding temperature ($T_{eval}$) cannot optimally satisfy both.
- **Controlled Toy Simulation:** A minimal finite-state machine (FSM) environment (16-token vocabulary, 1 fork state, 3 lock states) was designed. This allowed for exact computation of success probabilities under various decoding settings, making the lock/fork conflict explicit and demonstrating how SSD reshapes these states differently.
- **Real-Model Analysis:**
 - Comparison of cumulative probability mass curves between base and SSD-trained Qwen3-30B-Instruct models to identify changes in head concentration and tail suppression.
 - Analysis of how the number of "surviving tokens" and entropy of the truncated distribution changed with $T_{eval}$ for both base and SSD models, demonstrating SSD's effect on useful exploration.
- **Theoretical View (Appendix B):** Formal mathematical derivations decomposed the SSD loss function. This established how SSD induces "support compression" (removing diffuse tail mass) and "within-support reshaping" (redistributing probability within the retained head), explaining the context-dependent effects at locks and forks, and why total entropy can decrease while conditional head entropy for exploration is maintained. It also theoretically explains why decode-only tuning cannot replicate SSD's effects.
- **High-Temperature Stress Test:** An experiment was conducted with Qwen3-30B-Instruct using high $T_{train}$ (2.0) and *no* truncation during data synthesis, resulting in largely "gibberish" training data. This pathological setting aimed to isolate the contribution of distributional reshaping from the quality of the self-generated samples.

### 4. Main Findings and Results

The research yielded several findings regarding the efficacy and underlying mechanisms of Simple Self-Distillation (SSD) for code generation.

- **Consistent Performance Improvement:** SSD consistently improved code generation performance across all six evaluated models, spanning various families (Llama, Qwen, GPT-OSS), scales (4B to 30B parameters), and reasoning styles (instruct and thinking).
 - For Qwen3-30B-Instruct, pass@1 on LiveCodeBench v6 (LCB v6) increased from 42.4% to 55.3%, representing a 12.9 percentage point (pp) absolute gain or a 30.4% relative improvement.
 - Other models also showed substantial pass@1 gains on LCB v6: Llama-3.1-8B-Instruct (+3.5pp), Qwen3-4B-Instruct (+7.5pp), Qwen3-4B-Thinking (+3.3pp), Qwen3-30B-Thinking (+2.1pp), and GPT-OSS-20B (+5.3pp). Similar improvements were observed on LCB v5.
- **Gains Concentrated on Harder Problems:** The performance improvements were more pronounced on medium and hard problems. For Qwen3-30B-Instruct on LCB v6, pass@1 gains were +6.5pp on easy, +14.2pp on medium, and +15.3pp on hard problems. This pattern also held for pass@5 and across other Qwen models.
- **Preservation of Generation Diversity:** SSD did not lead to a collapse of generation diversity. Pass@5 gains frequently exceeded pass@1 gains, indicating that the method either preserved or improved the variety of generated solutions. For example, Qwen3-30B-Instruct on LCB v6 showed a +18.1pp gain at pass@5 compared to +12.9pp at pass@1.
- **Superiority Over Global Decoding Policies:** Tuning evaluation-time decoding parameters (temperature and truncation) on the original base models yielded only modest pass@1 improvements (1.5-3.0pp spread). SSD-trained models consistently outperformed the best-tuned base models, especially on hard problems and at pass@5. This suggests that SSD induces intrinsic changes in the model's distributions that cannot be replicated by merely adjusting inference parameters.
- **Hyperparameter Interaction:**
 - In the absence of truncation during training, performance was largely organized by an "effective temperature" ($T_{eff} = T_{train} \times T_{eval}$), with a peak near $T_{eff} \approx 1.2$.
 - The inclusion of training-time truncation ($\rho_{train}$) raised the achievable performance ceiling, indicating that support compression during data synthesis provides an additional channel for improvement beyond temperature scaling alone.
- **Mechanism Validation: Precision-Exploration Conflict:**
 - **Controlled Simulation:** The toy FSM demonstrated that the base model faced the precision-exploration dilemma. After SSD training, lock-like states exhibited stripped low-probability tails, making them more resilient to high temperatures, while fork-like states retained multiple viable options that became more evenly weighted. The optimal evaluation temperature for the SSD model shifted significantly higher, allowing for increased exploration at forks without destabilizing locks.
 - **Real-Model Analysis:** Qwen3-30B-Instruct after SSD exhibited faster accumulation of cumulative mass in its top ranks, indicating a cleaner head and weaker distractor tails. Furthermore, as evaluation temperature increased, SSD models showed a greater increase in the number of surviving tokens and their entropy after truncation, suggesting that $T_{eval}$ became more effective at diversifying useful alternatives within the refined head.
 - **Theoretical Framework:** The mathematical analysis of the SSD objective function confirmed that it promotes both "support compression" (concentrating probability mass on a smaller, relevant set of tokens) and "within-support reshaping" (redistributing probabilities among those retained tokens). This dual action allows the model to become globally sharper (reduced total entropy) while preserving useful local diversity at fork-like contexts.
- **Robustness to Pathological Training Data:** A stress test involving data synthesis with high $T_{train}$ (2.0) and *no* truncation resulted in a training corpus where approximately 62% of outputs contained no extractable code and many were multilingual gibberish. Despite this severely degraded training data, the fine-tuned Qwen3-30B-Instruct model still achieved a material improvement (48.1% pass@1, 64.0% pass@5), with gains concentrating on hard problems. This finding suggests that SSD's benefits are primarily derived from the distributional reshaping process itself, rather than from the intrinsic "correctness" of the self-generated samples.
- **Out-of-Domain Transfer:** For 30B-parameter models, SSD training on competitive programming data largely preserved performance on other benchmarks, including math reasoning (AIME), general code generation (HumanEval), code understanding (CruxEval), and general knowledge (MMLU), with changes typically within ±2pp. Smaller models, however, exhibited more varied, benchmark-dependent tradeoffs.

### 5. Significance and Potential Impact

The research on Simple Self-Distillation (SSD) presents implications for the development and enhancement of large language models, particularly in the domain of code generation.

- **Reduced Resource Dependency:** SSD offers a method for improving LLM code generation capabilities without requiring high-quality human-labeled data, a more powerful teacher model, a verifier, a reward model, or a code execution environment. This significantly lowers the resource barriers to model improvement, making advanced LLM tuning more accessible and less costly.
- **Unlocking Latent Model Capabilities:** The findings suggest that existing powerful code models contain intrinsic capabilities that are not fully realized under conventional decoding strategies. SSD acts as a mechanism to unlock this latent potential by adaptively reshaping token distributions, leading to more effective inference.
- **Deeper Understanding of LLM Behavior:** The identification and validation of the "precision-exploration conflict" and its resolution through support compression and within-support reshaping contribute to a more nuanced understanding of how LLMs generate code. This theoretical framework provides insights into token-level decision-making and how intrinsic model properties can be manipulated for performance gains.
- **Complementary Post-Training Strategy:** SSD represents a novel and complementary post-training direction. Its simplicity and effectiveness indicate that it could be integrated with, or serve as an alternative to, more complex fine-tuning methods, potentially offering a valuable tool in the LLM development lifecycle.
- **Implications for Self-Supervised Learning:** The robust performance of SSD even with low-quality, self-generated "gibberish" data is notable. This suggests that the learning signal extracted by SSD is more about the structural properties of token probabilities and distribution reshaping than about the superficial correctness of the generated sequences. This insight could inform future research into robust self-supervised learning paradigms that are less sensitive to the explicit quality of synthetic data.
- **Scalability for Continuous Improvement:** By allowing models to learn from their own outputs, SSD enables a potential pathway for continuous self-improvement in situations where external data acquisition is impractical or finite. This could be particularly impactful for specialized or evolving domains where up-to-date, high-quality labeled data is persistently scarce.
