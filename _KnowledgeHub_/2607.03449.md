# HiMe: Hierarchical Embodied Memory for Long-Horizon Vision-Language-Action Control

> [!summary] Summary
> HiMe decouples embodied control into three tiers, a high-frequency Executor for actions, a lightweight Sentry that gates when replanning is needed, and a slow-thinking Planner that maintains cross-modal episodic memory with Add/Update/Delete operations. This resolves the frequency-competence paradox, hitting 90% average success on long-horizon manipulation vs 65% for flat-memory baselines.

## Problem

- Markov-policy VLAs condition only on the current observation, so they cannot track state or preferences that persist beyond the visible frame.
- Training native memory into VLAs is bottlenecked by short context windows and hard long-range causal credit assignment over hundreds of steps.
- LVLM-as-memory approaches force a real-time latency ceiling on model scale, weakening reasoning, and passive FIFO storage cannot revise outdated or conflicting facts.

## Method

- Hierarchical Embodied Memory splits state into Transient (Executor), Working (Sentry sliding window), and Episodic (Planner) memory tiers with distinct temporal resolutions.
- Sentry gating function triggers the Planner only at detected subtask completions or deviations, amortizing costly VLM reasoning over long execution windows instead of every step.
- Active memory management gives the Planner explicit Add/Update/Delete CRUD operations over a cross-modal (image+text) key-value episodic store to keep beliefs consistent and current.

## Results

- HiMe reaches 90% average task progress across Object Search, Counting, and Rearrangement, versus 68% for HiMe w/o Sentry and 65% for Flat Memory (MemER-style FIFO).
- Sentry gating alone lifts Transient Memory from 14% to 26% progress by curbing erratic subtask switching from frame-by-frame replanning noise.
- HiMe cuts Planner API calls about 3x versus Flat Memory (e.g. 5.4 to 1.8 in Object Search) and raises memory hit rate from 68% to 94%.

## Takeaways

> [!tip] Key Insights
> - Decoupling reasoning frequency from execution frequency via an explicit gating signal, not just a bigger context window, is what resolves the slow-planner/fast-controller conflict.
> - Passive accumulation (FIFO or unbounded logging) is not enough; active consolidation with delete/update prevents stale or redundant memory from degrading retrieval quality.
> - Cross-modal memory beats single-modality: images preserve spatial/recognition fidelity while text carries semantics and logical constraints text alone or vision alone lose.

## Detailed Report

### 1. How this Work Fits into the Broader Research Landscape

Vision-Language-Action (VLA) models have gained prominence in robotic manipulation, often leveraging large-scale pretraining to map observations to control signals. However, a significant limitation of many existing VLA architectures is their reliance on the Markov assumption, where actions are predicted solely based on immediate observations and language instructions. This limits their effectiveness in non-Markovian, long-horizon tasks that require tracking temporal dependencies, recalling past events, or maintaining latent environmental information no longer visually present.

Previous efforts to address these memory limitations include:
- **Training-based methods:** Augmenting VLA models with native memory capabilities through specialized training or auxiliary losses. These methods often face constraints such as limited context windows and difficulties in optimizing long-range causal dependencies over extended task horizons.
- **Large Vision-Language Models (LVLMs) as memory containers:** Using LVLMs to store and retrieve historical trajectories. This approach encounters a "frequency-competence paradox" in real-time robotics, where powerful LVLMs are too computationally intensive and slow for high-frequency control, while faster, smaller models lack sufficient reasoning and generalization capabilities for complex memory tasks.

This work contributes to the field by proposing an architectural solution to this paradox, drawing inspiration from hierarchical planning paradigms and human cognition. It extends the concept of robotic memory, which has been explored at the policy level for local action generation and short-range consistency, and at higher levels for planning and reflection (e.g., MemER). Unlike many existing memory management frameworks for agents that predominantly focus on text-based representations for Large Language Models (LLMs), HiMe specifically addresses the integration of multimodal information for Vision-Language Models (VLMs) within a structured and actively managed memory system designed for real-world robotic interaction. The paper situates itself within the evolving landscape of hierarchical robot foundation models by introducing a novel hierarchical memory architecture that aims to enhance high-level VLM planning with context-aware instructions for low-level controllers, while maintaining real-time execution.

### 2. Key Objectives and Motivation

The primary objectives and motivations behind the development of HiMe are:

- **Addressing Limitations in Long-Horizon Tasks:** Current VLA models struggle with complex, non-Markovian tasks requiring long-term memory and reasoning. These tasks involve dependencies on past events or non-visible information, which immediate observations cannot fully capture. The objective is to enable robots to perform such tasks effectively.
- **Resolving the "Frequency-Competence Paradox":** A core challenge is the architectural misalignment between the computational demands of powerful reasoning models and the real-time, low-latency requirements of robotic control. Stronger reasoning models are typically slow, while faster models often lack sufficient reasoning capabilities. The motivation is to create a framework that balances "slow thinking" planning with "fast execution."
- **Decoupling Embodied Intelligence:** To manage the computational and temporal mismatch, the work aims to decouple embodied intelligence into specialized components, each operating at a distinct temporal resolution and with specific responsibilities, mirroring a multi-store structure of human cognition. This separation intends to amortize the cost of complex planning over extended execution windows.
- **Developing a Dynamic Multimodal Knowledge System:** Existing memory solutions often involve passive accumulation of data, leading to knowledge stagnation or cognitive dissonance when facing outdated or conflicting information in dynamic, multimodal human-robot interaction scenarios. The objective is to establish a memory system that:
 - **Captures Multimodal Richness:** Represents episodic memory as an object-centric system, deeply anchoring visual experiences with high-density textual descriptions. This allows for storing and retrieving not only visual features but also underlying logical constraints, ownerships, procedural rules, and human preferences that are often implicit or invisible in raw pixel data.
 - **Supports Knowledge Plasticity:** Moves beyond passive storage by introducing explicit "Add, Update, and Delete" operations for memory entries. This active management mechanism is designed to enable the robot to proactively refine its knowledge base in response to significant state transitions or revisions in user intent, thereby maintaining a consistent and concise memory aligned with the evolving environment.
- **Improving Robustness and Efficiency:** The ultimate motivation is to achieve higher success rates and robustness in complex human-robot collaborative scenarios that demand multi-step reasoning and adaptation, while simultaneously reducing the computational overhead typically associated with large VLM inferences.
- **Enabling Self-Correction:** A specific goal is to demonstrate the robot's ability to self-correct its internal knowledge based on new information or conflicting human preferences, a capability often absent in prior retrieval-based memory methods.

### 3. Methodology and Approach

HiMe (Hierarchical Embodied Memory) is a framework designed to manage the contradictory requirements of long-horizon manipulation: maintaining global consistency over extended history and reacting responsively to immediate dynamics. It achieves this through a three-tiered hierarchical policy and a structured memory system.

#### 3.1. Hierarchical Embodied Memory Structure

The framework explicitly represents information required for immediate control, temporal monitoring, and long-term planning through three distinct memory components:

- **Transient Memory ($\mathcal{T}_t$):** This memory, managed by the **Executor**, holds the instantaneous observation ($o_t$). Its purpose is to provide the minimal sufficient state for reactive sensory-motor coordination, ensuring physical stability.
- **Working Memory ($\mathcal{W}_t$):** Managed by the **Sentry**, this is a sliding window of recent observations ($\{o_{t-h_s}, \dots, o_t\}$). It is transient and raw, designed for high-frequency monitoring to capture immediate dynamics, verify subgoal status, or detect sudden failures.
- **Episodic Memory ($\mathcal{E}_t$):** This persistent, long-term store is managed by the **Planner** and consists of two sub-components:
 - **Contextual Memory ($\mathcal{E}^c_t$):** A multimodal key-value store that accumulates compact, task-relevant information over time, including visual imagery and textual descriptions (e.g., object state changes, spatial constraints, human preferences). It supports retrieval via textual keys.
 - **Procedural Memory ($\mathcal{E}^p_t$):** A structured plan represented as an ordered list of language subgoals ($\{\tau_i\}^N_{i=1}$). Each active subgoal ($\tau_t^{(i)}$) carries status labels ('active', 'pending', 'done') to synchronize the control loop.

#### 3.2. Hierarchical Policy Decomposition

The hierarchical policy $\pi(a_t | o_{0:t}, l)$ is decomposed into three layers, progressively trading off frequency for context capacity:

- **Base-level Executor ($\pi_e$):** This is a high-frequency, reactive policy. Given an active language subgoal ($\tau_t \in \mathcal{E}^p_t$), it maps the current observation ($o_t$) to an action ($a_t$). It assumes a local Markov property and is designed to be stateless and computationally efficient, enabling real-time responsiveness to physical dynamics.
- **Agile Sentry ($\pi_s$):** The Sentry acts as a gating function, $u_t \in \{0, 1\}$, invoked at regular intervals ($n_m$) to amortize the computational cost of high-level reasoning. It operates on the working memory ($\mathcal{W}_t$) to evaluate subgoal completion or environmental deviations. If $u_t = 1$, it signals a "handover" event, indicating that the current subgoal $\tau_t$ is either completed or invalidated, thereby triggering the Planner. If $u_t=0$, high-level reasoning is bypassed.
- **Reasoning Planner ($\pi_p$):** When the Sentry's trigger is activated ($u_t=1$), the Planner is invoked. Its role is to update the episodic memory and realign the agent's internal belief with the current environment. This process involves two stages:
 1. **Context Retrieval:** The Planner encodes the user instruction ($l$) and recent observations from working memory ($\mathcal{W}_t$) into a query ($q_t$). It then retrieves the most relevant contextual entries ($\mathcal{M}_{ret}$) from the contextual memory ($\mathcal{E}^c_t$).
 2. **Memory Update and Re-planning:** Conditioned on $l$, $\mathcal{W}_t$, $\mathcal{M}_{ret}$, and the current procedural plan ($\mathcal{E}^p_t$), the Planner jointly updates both components of episodic memory. The contextual memory ($\mathcal{E}^c$) is updated through explicit **Add, Update, and Delete** operations to manage new facts, revise outdated entries, or remove stale/conflicting information. Concurrently, the Planner synthesizes an updated procedural plan ($\mathcal{E}^p_{t+1}$), from which the next active subgoal is selected for execution.

#### 3.3. Implementation Details

- **Model Instantiation:** The Planner is instantiated with GPT-4o for main experiments (and Qwen3-VL-30B for supplementary evaluations) due to its strong multimodal reasoning. The Sentry utilizes Qwen3-VL-8B for its balance of speed and grounding accuracy.
- **Memory Backend:** A vector database is used for semantic retrieval. OpenAI's text-embedding-3 model encodes text queries, and multimodal memory entries are stored alongside their caption embeddings for cosine similarity retrieval.
- **Parameters:** The working memory buffer size ($h_s$) is set to 8 frames, and the Sentry monitoring interval ($n_m$) is 5 execution steps.
- **Training and Operation:** Only the low-level Executor ($\pi_e$), based on $\pi_{0.5}$, requires domain-specific training. The Sentry and Planner operate in a zero-shot or few-shot manner, leveraging pre-trained generalization to handle long-horizon logic without extensive data collection.
- **Hardware and Control:** Experiments use a WidowX-250s arm with a parallel gripper and dual-camera visual input (third-person and wrist view). The Executor runs at 2 Hz, predicting action chunks (10 actions, 10 Hz), with 5 actions executed open-loop. The Sentry is queried after every 10 Executor steps.

#### 3.4. Task Setting

Three tabletop manipulation tasks are designed to evaluate various capabilities:

- **Object Search:** Domestic maintenance task involving inspection of opaque boxes, organizing items, dynamic memory updates when new items are introduced, and retrieving objects based on memorized user preferences.
- **Counting:** Interpreting a visual recipe, planning ingredient preparation for multiple servings, and adapting to new user preferences by synthesizing current constraints with memorized recipes.
- **Rearrangement:** A two-stage "clear and restore" operation, requiring the robot to collect scattered toys, remember their original locations, and restore them according to pre-established user placement preferences and visual memory.

These tasks challenge different aspects of memory: active perception and belief updating (Object Search), persistent semantic memory and progress tracking (Counting), and long-term spatial memory and consistency (Rearrangement). All tasks also incorporate user preference constraints, demanding integration of memory with high-level reasoning.

#### 3.5. Evaluation Metrics

Performance is evaluated across 20 trials per method using:
- **Task Progress:** Proportion of completed subtasks, reflecting overall task completion.
- **API Calls:** Average number of Planner invocations per subtask, serving as a proxy for computational cost and efficiency.
- **Memory Hit Rate:** Probability of successfully retrieving required information from memory when the Planner is invoked.

### 4. Main Findings and Results

The experiments demonstrate that HiMe addresses the "frequency-competence paradox" and improves performance in long-horizon Vision-Language-Action control.

#### 4.1. Overall Performance

HiMe achieves an average success rate of 90% across the three challenging long-horizon tasks (Object Search, Counting, Rearrangement), significantly outperforming existing flat-memory baselines. This performance effectively bridges the gap between typical robotic agent capabilities and a Human High-level oracle, which serves as an upper bound.

#### 4.2. Analysis of Sentry Mechanism

The Sentry module plays a role in enhancing execution consistency and observation quality.
- **Consistency via Reduced Task Switching:** Comparing "Transient Memory" (14% average progress) with "Transient Memory w/ Sentry" (26% average progress) reveals a performance boost. The Sentry prevents the Planner from high-frequency, frame-by-frame re-evaluation, which would make the robot hypersensitive to visual noise and lead to erratic subtask switching. By intervening only upon subgoal completion, the Sentry promotes coherent action execution.
- **Quality via Consolidated Working Memory:** The Sentry's ability to consolidate observations into structured working memory improves task progress from 68% ("HiMe w/o Sentry") to 90% ("HiMe"). Instead of relying on a narrow window of recent frames, the Sentry aggregates the history of the active subtask, providing a more comprehensive perspective for verification and reducing hallucinations or redundant replanning by the Planner.
- **Sentry's Termination Behavior:** Analysis of Sentry's decision-making shows that increasing its working memory context (from 1 to 8 frames) improves both precision (from $\sim$76% to $\sim$82%) and recall (from $\sim$22% to $\sim$35%) for subtask completion detection. The Sentry exhibits a "conservative" nature, prioritizing precision over recall, meaning it prefers to continue execution unless highly confident of completion. This minimizes premature stops but can lead to missed "Done" events, necessitating a fixed-interval Planner fallback to prevent infinite loops.

#### 4.3. Analysis of Planner Memory Management

The hierarchical memory design, particularly active management, contributes to HiMe's performance.
- **Necessity of Persistent Memory:** Memory-less baselines, such as "Transient Memory w/ Sentry," still struggle with long-horizon tasks (e.g., 23% in Counting). Without explicit memory, they cannot retain object states or counted progress once information leaves the immediate observation window.
- **Inefficiency of Flat Memory:** "Flat Memory" (65% average progress), which uses a FIFO queue, performs significantly worse than HiMe (90%). Its limitation lies in the lack of consolidation; the fixed context window quickly fills with noisy frames, leading to the eviction of critical early information needed for later reasoning.
- **Necessity of Active Management:** HiMe's active memory curation through "Add, Update, and Delete" operations contributes to its superior performance. "No Management" (append-only) achieves 86% average progress, but is inferior to HiMe due to redundancy and inconsistencies from obsolete states. "FIFO" (68% average progress) performs worst due to active forgetting of crucial early context. HiMe maintains a concise and consistent memory by updating outdated entries and removing redundant or erroneous data.

#### 4.4. Memory Modality Effectiveness (Q1)

The study investigated the impact of memory modality:
- **Spatial and Recognition Demands:** For tasks requiring detailed spatial localization and fine-grained recognition, "Only image" memory (86% in Object Search) substantially outperformed "Only text" (74%). Text as a lossy compression can miss details or prevent re-grounding.
- **Semantic and Logical Reasoning:** Conversely, for tasks demanding non-spatial reasoning, semantic summarization, logical dependencies, and user preferences, "Only text" memory (91% in Counting) outperformed "Only image" (78%).
- **Superiority of Cross-Modal Memory:** HiMe's cross-modal approach, combining images for spatial fidelity with text for semantic and logical structure, achieves the best average performance (90%), enabling both precise grounding and effective reasoning.

#### 4.5. Efficiency and Latency (Q3)

HiMe demonstrates a clear efficiency advantage:
- **Reduced API Calls:** HiMe reduces Planner API calls by approximately 3x (e.g., from 5.4 for "Flat Memory" to 1.8 for "HiMe" in Object Search). Since VLM inference is computationally expensive, fewer calls translate to faster execution.
- **Sentry's Role in Reducing Invocation Frequency:** The Sentry manages dense subtask completion checking, invoking the Planner only when necessary (sparse, subtask-level calls) instead of step-by-step interpretation of the visual buffer.
- **Infinite Memory vs. FIFO Forgetting:** HiMe's structured, "infinite" memory ensures a high memory hit rate (94% vs. 68% for "Flat Memory"), avoiding the need for redundant physical re-exploration when context has been evicted.
- **Latency:** While GPT-4o API calls have a P50 latency of 38.59 seconds, local deployment of open-source VLMs significantly reduces this (e.g., Qwen3-VL-30B at 6.83 seconds P50). This reasoning latency is decoupled from the high-frequency low-level control loop.

#### 4.6. Additional Findings

- **Controlled Memory Ablation:** Under a fixed memory budget, "Limited Active Management" (80% task progress) still significantly outperforms "FIFO (Limited)" (64%), indicating that the benefit of active management is not solely due to larger memory capacity but also the explicit "Update/Delete" operations.
- **Open-Source Planner Evaluation:** Experiments using Qwen3-VL-30B as the Planner demonstrate consistent trends, confirming the robustness of HiMe's benefits regardless of the specific VLM used for planning.
- **Memory Scalability:** In extended multi-round Object Search tasks, while memory size grows with the number of subtasks, task performance declines. This suggests that maintaining correct and up-to-date memory in an evolving environment becomes increasingly challenging over very long horizons.

### 5. Significance and Potential Impact

The HiMe framework presents an advancement in the field of robotic manipulation and embodied AI, particularly for tasks requiring long-horizon reasoning and interaction with dynamic environments.

- **Resolution of the Frequency-Competence Paradox:** By hierarchically decoupling fast execution from memory-driven, slow reasoning, HiMe provides a practical architecture that balances the real-time demands of robotic control with the complex processing capabilities of large vision-language models. This addresses a fundamental architectural misalignment in current VLA systems.
- **Enhanced Performance in Long-Horizon Tasks:** The framework significantly improves success rates in complex, multi-step manipulation tasks that necessitate persistent state tracking, dynamic belief updating, and adaptation to user preferences. The achievement of a 90% average success rate demonstrates a substantial leap over existing flat-memory and transient-memory baselines.
- **Dynamic and Self-Evolving Knowledge System:** The introduction of cross-modal semantic schemata and active "Add, Update, Delete" memory management transforms robotic memory from a passive buffer into a dynamic, adaptable knowledge system. This enables robots to maintain knowledge plasticity, remain consistent with evolving environments, and self-correct based on new information or conflicting instructions, a capability less common in prior retrieval-based methods.
- **Reduced Computational Overhead:** The Sentry module's dynamic triggering mechanism reduces the frequency of invoking the computationally expensive Planner, leading to more efficient resource utilization without compromising performance. This makes advanced reasoning more viable for real-world robotic deployment.
- **Foundation for Autonomous and Adaptive Agents:** HiMe's approach to structured, hierarchical, and actively managed memory is presented as a vital step towards developing more truly autonomous and adaptive robotic agents capable of robustly operating in complex, open-ended environments and human-robot collaborative scenarios.

While the work shows promise, the authors acknowledge limitations, including evaluation primarily on real-robot tasks without a matched standard simulation benchmark (limiting reproducibility for some), reliance on relatively simple manipulation primitives, and the need for further characterization of performance under very long horizons or larger, more complex environments. Despite these, the proposed hierarchical memory framework represents a significant contribution to building intelligent robotic systems with advanced cognitive capabilities.
