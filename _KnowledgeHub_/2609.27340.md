# Spatial and Semantic Reasoning for LLM-Driven Robot Navigation via MCP

> [!summary] Summary
> This paper presents a non-invasive framework that links LLM reasoning to an unmodified ROS navigation stack through a navigation-oriented representation layer exposed as Model Context Protocol tools. Visual map modules render occupancy grids as metric, pose-aware images, while semantic annotation modules log waypoint-level observations with robot poses. Two LLM backends reached over 97% map coverage and selected spatial and semantic navigation goals from plain-language instructions.

## Problem

- ROS navigation data such as occupancy grids arrive as raw per-cell numerical arrays, which language models cannot interpret directly as spatial or semantic context.
- Existing LLM-ROS interfaces expose robot topics, services and actions generically, but define no navigation-specific representation for map, pose or perception data.
- LLM navigation methods rely on pre-built topological graphs, frontier maps or memory retrieval that are coupled to method-specific pipelines rather than reusable tools.

## Method

- ==subscribe_map_as_image==, ==draw_map_axis== and ==draw_robot_pose== convert occupancy grids into grayscale images, overlay an adaptive metric grid near 15 divisions, and project the robot pose as an arrow marker.
- A ==waypoint-centric semantic specification== stores each record as name, place description, observation pose, plus safety landmarks, functional landmarks and geometric features, written and read by ==write_semantic_data== and ==get_semantic_data==.
- A ==prompt-defined semantic filtering policy== retains only stable, recognizable observations; the representation layer is registered as **MCP** tools via ==@mcp.tool()== decorators atop the generic **ROS-MCP Server** substrate.

## Results

- Autonomous mapping reached **97.83%** free-space coverage with Claude Sonnet 4.6 and **99.78%** with GPT-5.5, against a teleoperated ground-truth map in an Isaac Sim warehouse.
- Spatial reasoning navigation to the smallest room succeeded in **26 of 30** trials (**86.67%**) for Claude and **28 of 30** (**93.33%**) for GPT-5.5.
- Semantic navigation to the fire extinguisher succeeded **30 of 30** times (**100%**) on both backends, with nearest-waypoint selection when several stored entries matched the request.

## Takeaways

> [!tip] Key Insights
> - Rendering geometric robot data as annotated images, rather than serialized numbers, converts a token-heavy array into spatial context a multimodal model can reason over.
> - Standardized tool protocols let reasoning be added around a robot stack, keeping SLAM and planning untouched and reusable across different robots.
> - Waypoint-level semantic anchoring only looks solved because annotations were complete; estimating room size from map images is the fragile step, corridors read as rooms.

## Detailed Report

### 1. Overview

A user gives a robot in a simulated indoor warehouse a deliberately indirect request: “Fire detected nearby. Navigate to the tool used for it.” To act on it, the robot needs context that links what it has seen to places it can navigate to. In this paper's approach, the LLM uses an earlier waypoint annotation that identifies a fire extinguisher. It then sends that waypoint's pose as an approximate goal through the existing navigation stack. This is a waypoint-level anchor, not a calculation of the extinguisher's exact coordinates. The authors' contribution is to expose such navigation-oriented representations as reusable MCP tools, without replacing the robot's existing ROS navigation stack.

Representative Claude Sonnet 4.6 executions of Tasks 2 and 3. Left: a top-down warehouse view with routes and destination camera images; the Task 3 destination is the fire extinguisher. Right: text excerpts showing the LLM tool-call sequence and reasoning for each task.

### 2. From cells and camera views to places

The authors identify two practical bottlenecks. Occupancy grids arrive as numerical cells that are hard for an LLM to interpret. Adding LLM features can require robot-specific wrappers.

MCP is a standardized client–server interface through which an LLM application accesses tools and data. ROS-MCP Server ([GitHub repository](https://github.com/robotmcp/ros-mcp-server)) supplies the generic communication substrate. The paper adds navigation-specific tools that expose map, pose, and camera information in forms intended for reasoning.

The mechanism has two linked steps. First, the map tools reshape occupancy values into an image. Unknown cells are gray, free cells white, and occupied cells darker as occupancy probability rises. An axis/grid overlay supplies metric references, and a robot-pose tool adds the robot's position and heading as an arrow.

Second, at exploration waypoints the LLM considers a camera image together with the annotated map. It filters observations using qualitative instructions and stores descriptions and the observation pose in a YAML-based semantic record. During navigation, it retrieves matching records and uses the associated pose as an approximate goal, not the object's exact coordinates. The authors state that the filtering policy is not confidence calibration or a quantitative reliability estimate.

### 3. What the trials establish

The evaluation used NVIDIA Isaac Sim, a Nova Carter robot, ROS 2, Cartographer SLAM, and Nav2 in one indoor warehouse simulation. Task 1 first generated a separate annotated map and semantic data for each backend, which were then used in Tasks 2 and 3. Tasks 2 and 3 each had 30 trials per backend.

Mapping coverage is the ratio of free-space pixels in the generated map to those in a ground-truth map built by manual teleoperation. GPT-5.5 reached 99.78% coverage. A navigation success is a trial in which the robot reaches the specified goal or associated waypoint. On “Go to the smallest room,” GPT-5.5 succeeded in 28 of 30 trials. Failures included mistaking a corridor for a room or estimating room sizes incorrectly. For the fire-extinguisher waypoint, it succeeded in 30 of 30 trials. That result depended on the target object being present in the semantic records. The discussion cautions that this is waypoint-level navigation under complete annotations, not exact object-coordinate navigation.

These results show feasibility in this simulation, not an improvement over a competing navigation method. The paper reports no baseline or ablation that isolates the benefit of the new representations, such as raw occupancy data or removing the semantic waypoint records.

### 4. Context becomes a goal

The framework turns raw map and camera data into spatial and semantic context that an LLM can use to select a goal, while the existing navigation stack handles motion. The authors present it as non-invasive, working without modifying the existing ROS infrastructure. Its evaluation covers Claude Sonnet 4.6 and GPT-5.5 in a single simulated warehouse.
