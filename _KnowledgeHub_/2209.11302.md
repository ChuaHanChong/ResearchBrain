# ProgPrompt: Generating Situated Robot Task Plans using Large Language Models

> [!summary] Summary
> ProgPrompt prompts a large language model with Python-style programs to generate executable robot task plans. The prompt imports the robot's available actions, lists the objects in the scene, and gives example plans with comments and assertions that check preconditions and trigger recovery actions. It beats a prior LLM planner on VirtualHome and transfers to a real Franka arm.

## Problem

- Scoring-based LLM planners must enumerate every possible next action and argument, which becomes impractical when the action space is combinatorial in household environments.
- Free-form text-generation planners produce steps that may name actions the robot cannot perform or objects absent from the scene, so plans need fragile text-to-action matching.
- Earlier LLM planners generated plans open-loop or lacked situated state feedback, so they could not check preconditions or recover when the environment differed from assumptions.

## Method

- ==Pythonic prompt structure==: import statements list the robot's ==action primitives==, and a variable lists the scene's objects. This restricts the LLM to executable functions and available objects, and swapping agents only needs a new import list.
- ==Example task programs== pair a function name with a body of action calls, so the LLM completes a new function for the target task and directly outputs an ==executable plan==.
- Natural language ==comments== summarize upcoming sub-tasks, while ==assertions== verify preconditions using environment state with ==else-branch recovery actions== such as find or open. Assertions are checked in ==closed loop== during execution.

## Results

- On VirtualHome with a GPT-3 backbone, ProgPrompt reaches **0.34** success rate, **0.84** executability and **0.65** goal-condition recall, against **0.00**, **0.45** and **0.21** for the language-model baseline. Codex raises these to **0.40**, **0.90** and **0.72**.
- Ablations show both features help: removing comments drops success from **0.34** to **0.30** and goal recall from **0.65** to **0.58**, and removing assertion feedback drops success to **0.28**. Removing both gives **0.18**.
- In two extra VirtualHome scenes the average success rate is **0.48** and executability **0.85**. On a Franka arm, tabletop plans always executed (**Exec=1**) and succeeded in **7 of 8** runs, with distractor objects added in half of them.

## Takeaways

> [!tip] Key Insights
> - Expressing plans as code lets the prompt encode robot capabilities and scene objects, constraining LLM outputs to executable actions without any fine-tuning.
> - Natural language comments inside code act like chain-of-thought, and their removal hurt more than removing assertions here. Combining natural language reasoning with program structure beats either alone.
> - Inline assertions with recovery branches give cheap closed-loop error correction, but a plan can only recover from failures its assertions anticipate. Real-robot noise, ambiguous goals, and long tasks (success 0.00 for plans of 11 or more actions) remain limits.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

The field of robotic task planning has traditionally relied on pre-defined domain knowledge and symbolic search methods, often using formalisms like PDDL (Planning Domain Definition Language). While effective for well-defined environments, these methods struggle with scalability and the effort required to define myriad domain knowledge in complex, open-world settings. More recently, learning-based approaches, including representation learning, hierarchical learning, and learning compositional skills, have sought to overcome these limitations.

The advent of Large Language Models (LLMs) has introduced a new paradigm to robotics. LLMs, trained on vast text corpora, exhibit remarkable commonsense reasoning and multi-task generalization abilities. Researchers have begun to leverage LLMs to generate plausible action plans, either by scoring potential next actions or by directly generating action sequences in natural language. Previous works such as Huang et al. and INNERMONOLOGUE have demonstrated the potential of LLMs for open-domain planning, but often suffer from two key shortcomings:
1. **Lack of Situated Awareness:** Generated plans might involve objects or actions not present or feasible in the robot's current environment. For instance, an LLM might propose "pick up the jar of pickles" when no pickles are available.
2. **Executability Challenges:** The free-form text generated by LLMs requires a robust mapping to executable robot actions, which can be ambiguous or lead to actions inadmissible in the current situation. INNERMONOLOGUE introduced environment feedback but still faced issues with non-existent objects. SAYCAN addressed action admissibility by scoring a predefined set of feasible actions, but this approach can be challenging in environments with combinatorially large action spaces. Concurrent work like Socratic Models also uses code-completion for robot plans.

PROGPROMPT directly addresses these critical gaps by integrating LLMs' understanding of programming languages. It moves beyond purely natural language prompting by presenting LLMs with a structured, Pythonic representation of available robot actions and environmental objects. By doing so, PROGPROMPT offers a method to generate plans that are not only imbued with commonsense reasoning but are also inherently situated within the robot's capabilities and environment, leading to directly executable programs. This work advances the field by demonstrating a practical and robust way to ground LLM-generated plans in physical and virtual robot systems, making them more reliable and deployable. It bridges the gap between high-level natural language instructions and low-level executable robot commands by leveraging the LLM's capacity for code understanding, thereby making LLM-based planning more practical and robust for real-world robotics.

### 2. Key Objectives and Motivation

The central objective of this research is to develop a programmatic LLM prompting scheme that enables the generation of robot task plans that are functionally robust across various situated environments, robot capabilities, and tasks. The authors aim to overcome the limitations of existing LLM-based planning methods, specifically their lack of situated awareness and guaranteed executability.

The key motivations driving this work are:
1. **Reduce Domain Knowledge Definition Effort:** Traditional task planning demands extensive and meticulous definition of domain knowledge about the world and robot actions. The authors seek to ameliorate this effort by leveraging LLMs' vast pre-trained commonsense understanding.
2. **Enhance Situated Awareness:** Current LLM planners often generate actions that are not possible or relevant in the robot's specific environment. A core motivation is to provide the LLM with real-time, situated information about available objects and their states, ensuring generated plans are contextually appropriate.
3. **Ensure Plan Executability:** Free-form natural language plan generation often requires complex mapping to executable robot actions, which can introduce ambiguity and errors. The authors are motivated to enable LLMs to generate plans directly in a format that is immediately executable by a robot, akin to a program.
4. **Leverage LLMs' Code Understanding:** Recognizing that LLMs are trained on vast web corpora including programming tutorials and code documentation, the authors aim to tap into this underutilized capability. By structuring prompts as programs, they hypothesize LLMs can generate more coherent, logical, and executable action sequences.
5. **Incorporate Closed-Loop Environment Feedback:** To handle dynamic environments and potential execution failures, the method aims to integrate mechanisms for checking preconditions and performing recovery actions, making the planning process more robust.

In essence, PROGPROMPT is motivated by the desire to merge the powerful commonsense reasoning of LLMs with the precise, structured requirements of robot control, thereby creating a more intuitive, flexible, and reliable system for autonomous task execution.

### 3. Methodology and Approach

PROGPROMPT's core methodology involves representing robot plans as Pythonic programs and structuring LLM prompts to elicit the generation of these executable code sequences. This approach leverages the LLM's capacity for both world knowledge and programming language understanding.

The method can be broken down into three main components:

**A. Representing Robot Plans as Pythonic Functions:**
Robot plans are defined as Python functions, consisting of:
- **API Calls to Action Primitives:** Robot capabilities are exposed as function calls (e.g., `grab('salmon')`, `putin('salmon', 'microwave')`). Objects in the environment serve as arguments to these functions.
- **Natural Language Comments:** These are embedded within the Python code (e.g., `# 5: put salmon in microwave`). They serve to break down high-level tasks into logical sub-tasks, provide natural language summaries for action sequences, and guide the LLM's commonsense reasoning, thereby reducing the likelihood of incoherent or repetitive outputs. This builds upon concepts like "chain of thought" prompting.
- **Assertions for Execution Tracking and Error Recovery:** Pythonic `assert` statements are used to check preconditions before executing an action (e.g., `assert('close' to 'salmon')`). If an assertion fails, an `else` clause specifies a recovery action (e.g., `else: find('salmon')`). This provides a crucial closed-loop feedback mechanism, enabling the robot to respond to unexpected environment states or execution failures.

**B. Constructing Programming Language Prompts (PROGPROMPT):**
The LLM prompt is carefully constructed as a Pythonic code snippet, providing all necessary context for plan generation:
- **Action Primitive Definitions:** Robot capabilities are explicitly listed as Python `import` statements (e.g., `from actions import grab <obj>, switchon <obj>, ...`). This informs the LLM about the available functions and their expected parameters, constraining its output to valid actions.
- **Available Object List:** A list of all interactable objects currently present in the environment is provided as a Python list of strings (e.g., `objects=['banana', 'bottle', 'box', 'plate', ...]`). This grounds the LLM's planning to the situated reality of the robot's workspace.
- **Few-shot Example Tasks:** The prompt includes several fully executable program plans for sample tasks. These examples demonstrate the desired structure, the relationship between natural language task descriptions (function names) and action sequences, and the proper use of action primitives, objects, comments, and assertions.
- **Next Task Prompt:** Finally, a natural language description of the target task is provided as the definition of a new, incomplete Python function, which the LLM is tasked to complete.

**C. Task Plan Generation and Execution:**
- **LLM Inference:** The constructed Pythonic prompt is fed to a large language model (e.g., GPT-3, CODEX). The LLM then autocompletes the incomplete Python function, generating an entire executable plan program based on the provided context, examples, and the new task description.
- **Environment Interaction:** The generated plan is executed by an interpreter in a closed-loop manner.
 - **VirtualHome (VH):** In the simulation environment, VH provides a state graph with object properties and relations. A separate LLM query is used to check assertions against this state graph, and if an assertion fails, the specified recovery action is executed before proceeding.
 - **Physical Robot (Franka-Emika Panda):** For real-world deployment, the action `grab_and_putin(obj1, obj2)` is provided as the primitive. Object detection is performed using ViLD (Vision-Language Detection) to identify and segment objects from point clouds, which are then mapped to the text strings in the generated plan. Due to real-world uncertainty, assertions were simplified or not fully implemented in the physical setup for reliable state tracking.

By meticulously structuring the prompt and integrating environmental feedback through assertions, PROGPROMPT ensures that the generated plans are not just syntactically correct Python, but also semantically grounded and executable in the robot's operational context.

### 4. Main Findings and Results

The research presents compelling results from both virtual simulation and physical robot experiments, demonstrating the efficacy of the PROGPROMPT approach.

**A. Virtual Experiment Results (VirtualHome)**
- **Superior Performance:** PROGPROMPT significantly outperforms prior work, specifically "Language models as zero-shot planners" by Huang et al. and a natural language-based baseline (LANGPROMPT), across all evaluation metrics: Success Rate (SR), Goal Conditions Recall (GCR), and Executability (Exec). For instance, PROGPROMPT with a GPT-3 backbone achieved an SR of 0.34 compared to 0.00 for both baselines, and Exec of 0.84 compared to 0.45 and 0.36, respectively.
- **LLM Backbone Comparison:** While GPT-3 demonstrated strong performance, the CODEX model (a GPT-3 variant explicitly trained on programming language data) achieved the highest success (SR 0.40, Exec 0.90, GCR 0.72), suggesting that LLMs fine-tuned on code are particularly well-suited for this task. DAVINCI, another GPT-3 variant, performed slightly worse than base GPT-3, potentially due to prompt length constraints.
- **Ablation Studies:**
 - **FEEDBACK (Assertions and Recovery Actions):** The inclusion of `assert` statements and recovery actions demonstrably improved performance across most metrics (SR, GCR), highlighting the value of closed-loop environment interaction for robust planning.
 - **COMMENTS (Natural Language Guidance):** Removing comments from the prompt code substantially reduced performance across all metrics, underscoring the importance of natural language guidance within the programming structure for eliciting commonsense reasoning and guiding the LLM.
- **Task-by-Task Performance:** Performance varied by task difficulty and similarity to prompt examples. Tasks similar to those in the prompt or with shorter action sequences generally yielded higher success rates. The strict final state checking sometimes penalizes plans that achieve the core goal but also perform additional, non-critical actions.
- **Generalization to New Scenes:** PROGPROMPT successfully generalized to two additional VirtualHome environments by simply updating the list of available objects. This shows the adaptability of the method to new environmental configurations. For instance, it correctly inferred "cutlery" to refer to spoons and forks in new scenes, even if examples primarily featured knives.

**B. Physical Robot Results**
- **Qualitative Demonstration:** The physical robot experiments, using a Franka-Emika Panda manipulator, served as a qualitative demonstration of PROGPROMPT's ability to generate executable plans for real-world tasks. While quantitative comparison was challenging due to real-world uncertainties (e.g., gripper failures), the system showed high Plan SR (success assuming perfect pick-and-place) and Exec (always 1).
- **Successful Task Execution:** PROGPROMPT successfully generated plans for tasks like "put the banana in the bowl," "put the pear on the plate," and "sort the fruits on the plate and bottles in the box," even with distractor objects present.
- **Limitations:** Real-world challenges included occasional physical failures (e.g., gripper slips) and object misidentification by the visual system (e.g., a soup can mistaken for a bottle). Assertions were not fully implemented due to complexities in reliable state tracking in the real world.

**C. Qualitative Analysis and Limitations**
The authors identified several common failure modes:
- **Environment Artifacts:** Limitations of the simulation (e.g., agent inability to interact with objects while sitting) or specific affordance definitions not available in VH.
- **Environment Complexities:** Assertions not always sufficient for complex scenarios, such as planning to open a cabinet before grabbing an object inside.
- **Lack of Action Success Feedback:** The agent doesn't receive explicit feedback on action success, which can lead to cascading failures if an action implicitly fails.
- **Incomplete Generation:** LLM API caps occasionally cut plans short.
- **Strict Evaluation Metrics:** The binary nature of SR and GCR can be overly strict for ambiguous tasks or when the robot performs additional, non-critical but valid actions.

Overall, the results demonstrate that PROGPROMPT significantly enhances the practical utility of LLMs for robot task planning by ensuring situated awareness and direct executability through a clever programmatic prompting strategy.

### 5. Significance and Potential Impact

PROGPROMPT represents a significant step forward in the field of robot task planning, particularly in its novel integration of Large Language Models. Its primary significance lies in effectively bridging the gap between high-level natural language instructions and low-level executable robot actions by leveraging LLMs' understanding of programming language structures.

**Key Contributions and Impact:**

1. **Enhanced Situated-Awareness and Executability:** By explicitly providing robot action primitives and environmental object lists in a programmatic format, PROGPROMPT enables LLMs to generate plans that are inherently grounded in the robot's capabilities and current scene. This directly addresses the critical limitations of prior LLM-based planning methods, which often produced generic or ungrounded plans. The result is a substantial improvement in plan executability and task success rates.

2. **Reduced Domain Engineering Effort:** PROGPROMPT drastically reduces the need for manual, laborious definition of domain-specific knowledge, which has long been a bottleneck in traditional symbolic planning. The LLM's pre-trained commonsense reasoning takes over much of this burden, making robot task deployment faster and more scalable.

3. **Robustness through Closed-Loop Feedback:** The integration of Pythonic `assert` statements and recovery actions within the generated plans introduces a crucial closed-loop feedback mechanism. This allows the robot to monitor its state, verify preconditions, and autonomously recover from unexpected environmental conditions or minor execution failures, leading to more robust and reliable task completion.

4. **Leveraging LLMs' Multi-Modal Understanding:** This work highlights the power of LLMs' ability to process and generate not only natural language but also code. By tapping into this "code understanding" capability, PROGPROMPT unlocks new avenues for human-robot interaction and robot autonomy, moving beyond simple natural language command following.

5. **Generalizability and Flexibility:** The method demonstrates strong generalization across different virtual environments by simply updating the object list. Its deployment on a physical robot also showcases its practical adaptability to real-world scenarios with minimal changes to the core prompting mechanism, illustrating its potential for broad application.

**Potential Impact:**
PROGPROMPT lays a foundation for future intelligent robotic systems that can interpret complex, high-level natural language commands and translate them into robust, situated, and executable plans with minimal human intervention. This could revolutionize various applications, from household robots assisting with daily chores to industrial manipulators performing complex assembly tasks, and even autonomous agents navigating dynamic and uncertain environments.

**Future Directions:**
The authors propose exciting future work, including exploring more advanced programming language features within prompts. This could involve using real-valued numbers for measurements, nested dictionaries for richer scene graph representations, and more complex control flow structures (e.g., loops, conditionals beyond `assert/else`). Such advancements could enable LLMs to generate even more sophisticated and adaptive robot behaviors, further blurring the lines between high-level human intent and low-level robot execution. The work serves as an inspiration for the robotics and NLP communities to further explore the uncharted potential of LLMs in generating and completing robot plans with deeper reasoning and control capabilities.
