# Reinforcement Learning from Intermediate Renders for Image-to-Code Generation

> [!summary] Summary
> IR4RL is a reinforcement-learning post-training method for image-to-code vision-language models. It renders the partial program after each drawing command, scores each render against the target image, and turns the score change between consecutive renders into token-level process rewards. These are combined with the usual final-image reward. On Image-to-SVG and Image-to-TikZ it beats supervised fine-tuning and outcome-only GRPO, sets open-source state of the art and writes shorter programs.

## Problem

- Rendering-based RL for image-to-code gives one reward to the whole program at the end, so every token gets the same credit whether it helped or hurt the image.
- Supervised fine-tuning copies reference programs without seeing how code errors become visual errors, and it penalizes programs that look correct but differ from the reference code.
- Existing process-reward methods need human step labels, learned verifiers or sampling-based estimates, and earlier image-to-code work used intermediate renders only for refinement or search at inference time.

## Method

- ==Render-progress reward==: after every completed drawing command, a ==closure operator== adds the missing closing syntax so the prefix runs, and the change in visual similarity between consecutive renders scores that segment.
- ==Backward propagation== in the style of ==GAE==: each token's process advantage sums the score changes of later renders, discounted exponentially by token distance, so tokens inside a segment get credit for the next render.
- Combined advantage inside on-policy ==GRPO==: the ==group-normalized outcome advantage== plus an alpha-weighted per-token process advantage replaces the outcome-only term, keeping pressure on final quality while localizing credit. Inference cost is unchanged.

## Results

- On MMSVGBench-Illustrations the 4B model reaches DINO **97.48** and LPIPS **9.79**, against **92.85** and **16.89** for outcome-only GRPO, beating 8B SVG models and Gemini 3 Flash.
- On DaTikZ-v3, DreamSim rises from **80.3** for the DeTikZify-v2 SFT model and **83.9** for outcome-only RL to **86.9**. It surpasses VinciCoder-8B and DeTikZify-v2.5 with **0.6k-token** programs.
- Ablations: the process reward alone recovers most of the gain (DINO **95.89**). Best settings are alpha **10**, lambda **0.9** and a render after every command. Humans prefer it over outcome-only RL **74.0%** of the time.

## Takeaways

> [!tip] Key Insights
> - When partial outputs can be executed and drawn elements persist, the renderer itself acts as a free step-by-step verifier, giving dense credit without human labels or a learned reward model.
> - Rewarding the change each segment causes isolates its contribution better than absolute scores, but the final-outcome reward is still needed because a run of good steps can stop short of the target.
> - Denser, more local feedback helped at every tested setting, but full undiscounted propagation hurt. The RL gains mostly make existing good samples more likely, so they shrink at large best-of-K budgets.

## Detailed Report

### 1. Position in the Broader Research Landscape

Image-to-code generation seeks to convert a raster image into an executable, structured program. Examples include generating SVG code for illustrations and icons, TikZ code for scientific diagrams, HTML for web interfaces, and CAD programs for three-dimensional objects. Unlike raster image generation, code-based representations can be edited, rescaled, reused, and integrated into existing design or scientific-document workflows.

Existing image-to-code systems generally begin with supervised fine-tuning (SFT) on image–program pairs. This approach teaches a vision-language model (VLM) to reproduce a reference program, but it does not directly evaluate whether the generated program visually matches the input image. It may also penalize valid programs that use a different but visually equivalent structure from the reference code.

A subsequent line of work has introduced reinforcement learning (RL) based on rendering feedback. In these methods, a generated program is rendered, compared with the target image, and assigned a final outcome reward. This provides visual grounding without requiring the model to reproduce the exact reference program. However, the reward is usually assigned to the whole sequence. If a program contains both accurate and inaccurate drawing operations, every token may receive essentially the same training signal.

The paper addresses this credit-assignment problem through **IR4RL**, or “Intermediate Renders for Reinforcement Learning.” Its central premise is that many partial program prefixes can be made executable and rendered during generation. The visual change between successive partial renders can therefore indicate whether newly generated code improves or harms the reconstruction. This places the work at the intersection of image-to-code generation, rendering-aware RL, and process-level supervision.

The approach differs from prior methods that use intermediate renders during inference for iterative refinement or search. IR4RL uses intermediate states during training to assign localized rewards, while leaving the inference procedure unchanged. It is also related to process-supervised reasoning and compiler-feedback methods, but the feedback source here is visual similarity rather than human labels, a learned verifier, or program execution success alone.

### 2. Objectives and Motivation

The primary objective is to improve RL post-training for image-to-code VLMs by providing more informative feedback about individual generation decisions.

The motivation has several components:

1. **Terminal rewards are sparse.** A final image similarity score is available only after the full program has been generated. It does not identify which commands contributed to the result.

2. **Programs can contain mixed-quality decisions.** One part of a generated SVG or TikZ program may accurately reproduce a shape, color, or annotation, while a later part may introduce an incorrect element. Outcome-only RL treats both portions according to the same final score.

3. **Intermediate prefixes can expose progress.** In SVG and TikZ, drawing commands are often additive: once an element is created, it remains in the rendered program as subsequent elements are added. A partial program can therefore provide a meaningful visual snapshot of the current reconstruction.

4. **The method should not require additional annotation.** Intermediate visual scores can be computed automatically by rendering prefixes and comparing them with the target image. This avoids collecting human step-level labels or training a separate process reward model.

5. **The method should generalize across representations.** The authors test the approach on SVG and TikZ, which have different syntax and rendering pipelines but both support incremental construction and evaluation.

The paper also investigates how reward granularity and propagation affect learning, whether process and outcome rewards are complementary, and whether the method changes the probability of obtaining high-quality samples during test-time sampling.

### 3. Methodology and Approach

#### 3.1. Base RL formulation

For an input image \(x\), a VLM policy generates a program \(y=(y_1,\ldots,y_T)\). The completed program is rendered as \(R(y)\), and a visual similarity function \(S\) compares the rendering with \(x\). Standard outcome-based RL assigns the final reward

\[
R(y,x)=S(R(y),x).
\]

The paper uses Group Relative Policy Optimization (GRPO). For each input, the model samples a group of candidate programs and normalizes their rewards relative to the group mean and standard deviation. The resulting advantage is applied to every token in a candidate sequence, which creates the credit-assignment limitation that IR4RL is designed to address.

#### 3.2. Intermediate rendering and prefix closure

The generated program is divided into segments at boundaries corresponding to completed drawing operations. In SVG, boundaries are placed after completed path commands such as moves, lines, curves, arcs, or closes. In TikZ, boundaries occur after semicolon-terminated drawing statements such as `\draw` or `\fill`.

A raw prefix may not be syntactically complete. The authors therefore define a closure operator \(C\), which appends the missing syntax needed to produce an executable program. For SVG, this may involve adding container tags and path wrappers. For TikZ, the procedure tracks and closes open braces, option blocks, and environments.

For each boundary \(b_j\), the closed prefix \(P_j=C(y_{1:b_j})\) is rendered and assigned a visual score:

\[
F_j=S(R(P_j),x).
\]

The empty canvas provides \(F_0\), and the complete program provides \(F_M\).

#### 3.3. Render-progress reward

Rather than using the absolute score of each prefix, the method computes the change between successive prefixes:

\[
\Delta_j=F_j-F_{j-1}.
\]

A positive \(\Delta_j\) means that the newly completed segment improved image similarity, while a negative value indicates that the segment reduced similarity. This difference is intended to represent the marginal visual contribution of the newly generated code.

#### 3.4. Token-level propagation

The render-progress reward is initially defined at segment boundaries, whereas the policy is updated at the token level. IR4RL propagates future progress rewards backward through the tokens:

\[
A^{\text{Process}}_t =
\sum_{j:b_j\geq t}\lambda^{b_j-t}\Delta_j.
\]

The parameter \(\lambda\) controls the distance over which a reward is propagated. With \(\lambda=0\), only boundary tokens receive the reward. Higher values assign diminishing credit to earlier tokens. The authors describe this as analogous to the locality-control function of generalized advantage estimation.

#### 3.5. Combining process and outcome supervision

The process advantage is combined with the normalized outcome advantage:

\[
A_{i,t}=A^{\text{Outcome}}_i+\alpha A^{\text{Process}}_{i,t},
\]

where \(\alpha\) determines the process reward’s contribution. This preserves global feedback about final quality while adding localized feedback about visual progress.

#### 3.6. Experimental settings

For **Image-to-SVG**, the authors use OmniSVG-4B as the SFT base model and train on the svg-stack dataset. They use a scale-invariant normalized \(L_2\) image score. Training uses LoRA adapters, a group size of 16, 128 rollouts per update, and 300 training steps on one B200 GPU. The main experiment uses 700 training samples.

For **Image-to-TikZ**, they use DeTikZify-v2, train on DaTikZ-v3, and use the DeTikZify SelfSim metric, which compares patch-level visual features using Earth Mover’s Distance. Training uses a group size of 32, 128 rollouts per update, approximately 25,000 training samples, and 900 steps.

The baselines include the original SFT models, outcome-only GRPO, RAFT rejection-sampling fine-tuning, task-specific models, general-purpose VLMs, and optimization-based SVG systems such as DiffVG and LIVE.

### 4. Main Findings and Results

#### 4.1. Image-to-SVG

On MMSVGBench, IR4RL improves the OmniSVG-4B SFT model across reconstruction, perceptual, semantic, aesthetic, and length metrics.

On the Illustrations split, the proposed model achieves:

- DINO: **97.48**, compared with **85.48** for SFT and **92.85** for outcome-only RL.
- LPIPS: **9.79**, compared with **22.26** for SFT and **16.89** for outcome-only RL.
- MSE: **1.17**, compared with **5.11** for SFT.
- SSIM: **94.22**, compared with **89.70** for SFT.
- CLIP: **96.05**, compared with **82.03** for SFT.
- Aesthetic score: **5.09**, compared with **4.55** for SFT.
- Program length: **2.5k tokens**, compared with **11.3k** for SFT.

On the Icons split, it obtains a DINO score of **98.26**, LPIPS of **8.67**, SSIM of **93.88**, and an average length of **2.1k tokens**. The results are higher than the corresponding outcome-only RL and RAFT variants.

The model also compares favorably with several larger general-purpose VLMs and with task-specific SVG systems. Qualitative examples indicate fewer omissions and less distortion of structure, geometry, color, and fine details.

A human study involving 50 images and 30 participants found that participants preferred the proposed model over Gemini 3 Flash in **60.6%** of comparisons, over InternSVG-8B in **76.3%**, over RAFT in **74.9%**, and over outcome-only RL in **74.0%**. A VLM judge showed a similar preference pattern, with reported human–VLM agreement of 88%.

#### 4.2. Image-to-TikZ

On DaTikZ-v3, IR4RL improves visual reconstruction over the DeTikZify-v2 SFT model and outcome-only RL. It achieves:

- DreamSim: **86.9**, compared with **80.3** for SFT and **83.9** for outcome-only RL.
- SigLIP: **94.0**, compared with **90.0** for SFT.
- CLIP: **92.8**, compared with **88.9** for SFT.
- LPIPS: **32.8**, compared with **38.3** for SFT.
- KID: **0.20**, compared with **0.72** for SFT.
- Token length: **0.6k**, compared with **1.3k** for SFT.

Reference-based code metrics decline somewhat relative to SFT and RAFT. This is consistent with the training objective: RL optimizes visual equivalence rather than matching a particular reference implementation. The authors interpret this trade-off as evidence that code similarity and visual fidelity measure different objectives.

#### 4.3. Ablations and further analysis

Process reward alone accounts for most of the improvement over outcome-only RL, but combining process and outcome rewards produces the best results. Performance improves as the process coefficient increases up to approximately \(\alpha=10\).

Reward propagation is also important. The best reported setting is \(\lambda=0.9\), while undiscounted propagation at \(\lambda=1\) performs worse, indicating that retaining locality is useful.

Rendering after every available drawing command produces the strongest performance. Rendering less frequently causes a consistent decline, supporting the use of fine-grained intermediate supervision.

In best-of-\(K\) sampling experiments, IR4RL produces the highest average reward across sampling budgets, with the largest differences at small \(K\). This suggests that training increases the probability of high-quality outputs rather than only improving the model’s performance when many candidates are sampled.

### 5. Significance and Potential Impact

The paper provides a general technique for converting executable intermediate states into process supervision for image-to-code models. Its main significance lies in addressing token-level credit assignment without human annotations or a learned verifier. The method also retains the final outcome objective, which helps prevent a model from accumulating locally positive steps while ending with an incomplete or globally inaccurate program.

If applicable beyond SVG and TikZ, the approach could support post-training for Lottie animations, HTML interfaces, diagram languages, and 3D scene programs. The main requirement is that partial programs must be renderable, comparable with the target, and incrementally additive enough for changes in visual score to be meaningful.

The primary limitations are computational and structural. Rendering many intermediate prefixes increases training-time cost, and the method may not transfer to representations whose partial states are invalid, visually ambiguous, or frequently overwritten by later operations. The reported evaluations also focus on two datasets and rely partly on automated similarity measures, although the SVG experiments include human judgments. Finally, optimizing visual similarity may produce code that is less similar to reference programs or may not satisfy broader criteria such as semantic correctness, editability, or maintainability.

Overall, the work frames intermediate rendering as a practical source of process-level feedback for multimodal program generation. Its results indicate that localized visual progress can complement terminal rewards and improve both reconstruction quality and generation efficiency.
