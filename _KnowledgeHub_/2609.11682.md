# COBRA-Skills: Contextual Bandit-Guided Evolution for Agent Skill Optimization

> [!summary] Summary
> COBRA-Skills optimizes reusable LLM-agent skills under a tight evaluation budget by treating each candidate skill as a contextual-bandit arm: a neural reward predictor over skill embeddings plus a LinearUCB bonus decides which skill the target agent executes next, while regeneration, rollout-mutation and crossover operators periodically evolve the population from execution evidence. It posts the highest average across six benchmarks and three target models, cutting optimization cost 55-58% versus SkillOpt.

## Problem

- Existing skill-optimization methods assess candidate utility only through execution-based generate-evaluate-refine loops, so much of the budget is spent running low-quality candidates on tasks.
- Prior methods repeatedly invoke LLMs to re-analyze trajectories, diagnose failures and rewrite skills every round, making teacher-side token cost a second bottleneck.
- Hand-authored skills need domain expertise, while skills from an LLM's parametric knowledge are plausible but ungrounded, and trajectory-grounded baselines still demand large optimization pools.

## Method

- ==Bandit-guided prioritization==: a two-layer MLP predicts reward from a fixed Qwen3-Embedding-4B skill embedding, and a ==LinearUCB== confidence bonus adds exploration; their sum ranks candidates for evaluation and pruning.
- Evidence-grounded ==evolution== with three operators: regeneration from no-skill trajectories, rollout mutation revising the just-evaluated skill from its successful and failed rollouts, and evidence-based crossover over strong and weak skill groups.
- Scheduled population update: evolution fires only when round-gap and log-ratio conditions hold, pruning the 3 lowest-priority of 10 skills and replacing them with newly evolved candidates.

## Results

- Average accuracy over six benchmarks reaches **73.5**, **56.9** and **68.9%** on Qwen3.6-35B-A3B, GPT-5.4-Nano and Gemma-4-26B-A4B-it, beating SkillOpt by **3.9**, **3.2** and **1.3** points.
- Total optimization cost drops **55-58%** and cost per point of gain **60-69%** versus SkillOpt, using **67-80%** fewer teacher tokens and only 50 optimization examples per benchmark.
- Ablations lose **2.2** points without the bandit, **2.4** without evolution, **2.5** for Best-of-30; self-teaching drops only **73.5** to **72.5**, and **34 of 36** cross-model transfers improve.

## Takeaways

> [!tip] Key Insights
> - Choosing which candidate to evaluate matters as much as generating better ones: simply enlarging the candidate pool and picking the best does not close the gap.
> - Cost in skill optimization is dominated by teacher-side trajectory re-analysis, not agent execution; invoking refinement on a schedule buys most of the savings.
> - Optimized skills carry task-level strategy rather than model-specific quirks, transferring across target models and agent harnesses, and surviving without a stronger external teacher.

## Detailed Report

### 1. Position Within the Broader Research Landscape

COBRA-Skills addresses the growing use of external, reusable “skills” to improve large language model (LLM) agents. LLM agents increasingly perform tasks involving tool use, multi-step reasoning, files, interactive environments, and domain-specific procedures. A skill is typically a textual artifact—often a system-prompt-style document—that records reusable strategies, error-avoidance rules, or tool-use instructions. It can be injected into an agent without modifying the underlying model parameters.

Existing research has explored several approaches to skill construction. Some methods manually author skills, while others generate them directly from an LLM’s prior knowledge. More recent systems derive skills from agent execution trajectories, using successful and failed interactions as evidence for identifying reusable procedures. Methods such as Trace2Skill and SkillOpt further apply iterative refinement, in which skills are generated, evaluated through agent execution, and revised based on observed outcomes.

The paper identifies two limitations in this research direction. First, candidate skill evaluation is expensive because utility is generally unknown until the target agent executes the skill on task instances. Exhaustively evaluating many candidates can consume substantial inference resources. Second, repeated trajectory analysis and skill rewriting can be costly, particularly when a powerful teaching model is used to interpret failures and generate revisions.

COBRA-Skills combines two established ideas to address these limitations. It treats candidate selection as a contextual bandit problem, allowing the system to prioritize candidates according to predicted performance and uncertainty. It also uses evolutionary operators to generate and refine new skills from execution evidence. The resulting framework lies at the intersection of LLM agent memory and skill learning, prompt or instruction optimization, contextual bandits, and evolutionary search.

### 2. Objectives and Motivation

#### 2.1. Central Objective

The central objective is to optimize reusable agent skills under a limited budget of task examples, target-agent executions, and teaching-model calls. The authors formulate skill optimization as sequential decision-making over a changing candidate population. Each candidate skill has an unknown downstream utility, which can be estimated only by running the target agent with that skill.

The optimization goal is to identify a skill that performs well not only on the small optimization set but also on unseen examples from the same task distribution. The target agent remains frozen; only the textual skill is generated or modified.

#### 2.2. Motivation for Selective Evaluation

The authors argue that a fixed generate-and-evaluate loop allocates resources inefficiently. A candidate that appears weak may be evaluated repeatedly before being discarded, while a promising but underexplored candidate may not receive sufficient attention. Since skills can be represented by semantic embeddings, outcomes from previously evaluated skills may provide information about similar candidates.

This motivates a contextual bandit formulation. The system must balance exploitation—evaluating skills predicted to have high utility—with exploration—evaluating skills located in insufficiently explored regions of the skill-embedding space. The approach is intended to reduce the number of costly evaluations required to discover effective skills.

#### 2.3. Motivation for Dynamic Evolution

A purely fixed candidate pool cannot introduce new strategies after optimization begins. Conversely, continuously generating and rewriting skills may lead to high teaching-model costs. COBRA-Skills therefore evolves the population periodically rather than after every evaluation. It retains candidates with high predicted utility or exploration value and replaces low-priority candidates with new skills grounded in observed trajectories.

### 3. Methodology and Approach

#### 3.1. Overall Optimization Loop

For each benchmark, the method uses a 50-example optimization set and collects initial no-skill trajectories from the target agent. Ten initial skills are generated independently from these trajectories. The optimization then runs for 30 rounds with a population of 10 candidates.

At each round, every current skill is embedded and assigned a priority score. The highest-priority candidate is evaluated by the target agent on all 50 optimization examples. Its reward and execution trajectories are recorded. The reward predictor is then retrained using all evaluated candidates, and the population is periodically evolved.

The final output is the evaluated skill with the highest mean observed optimization reward.

#### 3.2. Contextual-Bandit Prioritization

Each skill \(s\) is represented by a fixed semantic embedding \(z_s=\phi(s)\), produced using Qwen3-Embedding-4B. The embeddings are L2-normalized and have dimension 2,560.

A two-layer multilayer perceptron predicts the reward of a skill from its embedding. The architecture is 2,560 input units, a 64-unit ReLU hidden layer, and one scalar output. After each evaluation, the model is refitted on the complete accumulated history using mean-squared error with L2 regularization.

To represent uncertainty, COBRA-Skills adds a LinearUCB-style bonus:

\[
b_t(z_s)=\nu\sqrt{z_s^\top A_{t-1}^{-1}z_s},
\]

where \(A_{t-1}\) is a regularized design matrix formed from embeddings of previously evaluated skills, and \(\nu\) controls exploration. The total priority score is the sum of predicted reward and uncertainty bonus. The default exploration coefficient is 0.1.

This score serves two purposes. It determines which candidate is evaluated next and which candidates are retained during population updates. Thus, exploration value affects both short-term evaluation allocation and long-term population composition.

#### 3.3. Evidence-Grounded Evolution

Population evolution occurs according to a schedule with minimum interval three rounds and a logarithmic timing condition. At each update, the three candidates with the lowest updated priority scores are removed and replaced.

The replacement candidates are produced through three operators:

1. **Regeneration:** A new skill is generated directly from the original no-skill trajectories. Because it has no parent skill, regeneration introduces independent search directions and helps maintain diversity.

2. **Rollout mutation:** The skill selected in the current round is revised using a sample of successful and failed trajectories generated with that skill. The mutation is intended to make local, evidence-supported corrections rather than rewrite the skill completely.

3. **Crossover:** Once more than eight distinct skills have been evaluated, the method forms pools of high- and low-performing skills. One strong skill serves as the backbone, another strong skill supplies positive evidence, and two weak skills supply negative evidence. The teaching model produces a child skill by making conservative changes to the backbone. The parents are not simply concatenated.

Before crossover is activated, the operator ratio for regeneration, mutation, and crossover is 2:1:0. Afterwards, the ratio is 1:1:1. The teaching model used in the main experiments is GPT-5.5 with medium reasoning effort. Importantly, candidate scores are based on target-agent execution feedback rather than the teaching model’s subjective assessment.

#### 3.4. Experimental Design

The evaluation covers six heterogeneous benchmarks: SearchQA, SpreadsheetBench, DocVQA, LiveMathematicianBench, SocialMaze’s Hidden Role Deduction task, and ALFWorld. These include question answering, spreadsheet manipulation, visual document understanding, mathematical reasoning, social reasoning, and embodied decision-making. SpreadsheetBench and ALFWorld involve multi-turn interaction, while the other tasks are evaluated primarily in single-turn settings.

The target models are Qwen3.6-35B-A3B, GPT-5.4-Nano, and Gemma-4-26B-A4B-it. The main comparisons are against no skill, a one-time evidence-grounded LLM-generated skill, Trace2Skill, and SkillOpt. All methods use a held-out test set of 100 examples. COBRA-Skills uses 50 optimization examples, whereas Trace2Skill and SkillOpt use benchmark-specific pools ranging from 53 to 170 examples.

### 4. Main Findings and Results

#### 4.1. Overall Performance

COBRA-Skills obtains the highest average test performance among the compared methods for all three target models:

- **Qwen3.6-35B-A3B:** 73.5%, compared with 60.4% for the no-skill baseline and 69.6% for SkillOpt.
- **GPT-5.4-Nano:** 56.9%, compared with 30.0% for the baseline and 53.7% for SkillOpt.
- **Gemma-4-26B-A4B-it:** 68.9%, compared with 46.4% for the baseline and 67.6% for SkillOpt.

The corresponding improvements over no-skill agents are 13.1, 26.9, and 22.5 percentage points. The gains are not uniform across tasks. For example, COBRA-Skills improves substantially on SpreadsheetBench, LiveMath, and SocialMaze for Qwen, while SkillOpt remains competitive or slightly better on some individual tasks, including Qwen SearchQA and ALFWorld. The result is therefore primarily an average performance advantage across heterogeneous benchmarks rather than universal dominance on every task.

#### 4.2. Optimization Cost and Sample Efficiency

COBRA-Skills reports lower total optimization costs than SkillOpt:

- $54.10 versus $121.02 for Qwen.
- $58.46 versus $133.59 for GPT-5.4-Nano.
- $38.98 versus $92.14 for Gemma.

These correspond to cost reductions of approximately 55–58%. Cost per point of improvement is also lower, falling from 13.15 to 4.13 for Qwen, from 5.64 to 2.17 for GPT-5.4-Nano, and from 4.35 to 1.73 for Gemma.

The main source of savings is lower teaching-model usage. COBRA-Skills uses 67–80% fewer teaching-model tokens than SkillOpt. Target-model usage is not always lower; in some settings, COBRA-Skills uses more target-model tokens but allocates them through selective prioritization. The method also uses only 50 unique optimization examples per benchmark.

#### 4.3. Ablation Results

Ablation experiments indicate that both main components contribute. On Qwen, the full method reaches an average of 73.5%. Removing evolution reduces performance to 71.1%, while removing bandit prioritization reduces it to 71.3%. A Best-of-30 fixed-pool comparison reaches 71.0%.

These results suggest that the method’s gains are not explained solely by generating more candidates. Adaptive evaluation and dynamic candidate evolution provide separate, complementary benefits.

#### 4.4. Robustness and Transfer

Under external agent harnesses, COBRA-Skills achieves average scores of 68.2% with Claude Code and 72.4% with Codex, exceeding SkillOpt’s 64.0% and 71.1%, respectively.

In a self-teaching experiment, Qwen generates and refines its own skills rather than relying on GPT-5.5. Average performance declines modestly from 73.5% to 72.5%, while optimization cost is approximately halved. Cross-model transfer is also favorable: 34 of 36 transfers improve on the receiving model’s no-skill baseline.

### 5. Significance and Potential Impact

COBRA-Skills contributes a budget-aware formulation for optimizing textual skills in LLM agents. Its main conceptual contribution is to treat skills as contextual arms whose value must be inferred through expensive execution, while allowing the arm set itself to evolve. This provides a structured alternative to exhaustive candidate evaluation and continuous, costly skill rewriting.

If the reported behavior generalizes, the framework could reduce the cost of building task-specific agent capabilities, particularly when target-agent executions are expensive or when only limited task data are available. Its self-teaching results also suggest that skill optimization need not always depend on a substantially stronger external model.

Several limitations require consideration. The study is a preprint and uses three independent runs per condition, so uncertainty remains about performance across broader datasets and random seeds. Optimization data are not equalized across methods: COBRA-Skills uses 50 examples, while the baselines generally use larger pools. This supports the paper’s sample-efficiency claim but complicates strictly budget-matched comparisons. The method also relies on a fixed embedding model and a heuristic LinearUCB bonus, without formal guarantees for the nonstationary candidate space created by evolution. Finally, skills may overfit recurring patterns in the optimization trajectories or fail under substantial distribution shift. Further evaluation on larger task collections, equalized compute budgets, and evolving real-world agent environments would clarify the framework’s broader applicability.
