# Agent-Editing World Model: Rethinking World Modeling for LLM Agents

> [!summary] Summary
> AEWM (Agent-Editing World Model) rethinks language world modeling: instead of predicting tool responses, it predicts how a proposed reasoning-action pair shapes future task progress. An Action Judge labels decisions critical, exploratory, or noisy; State Revision rewrites noisy ones; EditAct executes the kept or revised action in the real environment. It reaches 70.5% macro-F1 on action judgment and lifts agent scores by 3.2-6.7 points.

## Problem

- Existing language world models predict environment observations, but tool responses are high-entropy and execution-dependent, so reconstructing them adds little value when real feedback is already available.
- Simulated observations risk introducing fabricated evidence without improving how an agent interprets grounded feedback or selects its next decision.
- Long-horizon agents suffer task-state contamination: unsupported assumptions, outdated plans, and partial progress mistaken for completion persist in history and distort later decisions.

## Method

- **Action Judge** classifies a pre-execution state (history plus the proposed reasoning-action pair) as critical, exploratory, or noisy, predicting downstream contribution from retrospectively annotated yet forward-looking labels.
- **State Revision** regenerates reasoning and action from the same history for noisy proposals; **EditAct** commits the retained or revised pair and executes it in the real environment.
- ==Two-stage training==: 52B-token mid-training over Search, Terminal and SWE trajectories, then SFT on 120K synthesized examples; **AEWM-RFT** distills verified EditAct trajectories back into the agent.

## Results

- AEWM scores **70.5%** macro-F1 on a 3,000-decision Action Judge benchmark, beating the strongest frontier baseline by **10.6** points, with **60.9**/**72.1**/**77.8** on Search, Terminal and SWE.
- EditAct beats the strongest baseline by **6.7**, **5.2** and **3.2** average points on 4B, 9B and 35B-A3B backbones; 9B with EditAct beats 35B with ReAct (**44.1** vs **42.2**).
- AEWM-RFT exceeds Self-RFT by **2.2-2.6** points without online guidance; full training beats SFT-only by up to **6.4** points, and direct editing beats resampling and critique hints.

## Takeaways

> [!tip] Key Insights
> - When real execution is available, a world model pays off more by judging and rewriting the agent's own decisions than by simulating observations.
> - Direct replacement of a reasoning-action continuation outperforms critique hints or resampling, suggesting the contaminated state itself, not only the action, must be edited.
> - Guidance gains shrink as the agent outgrows the world model's capacity, so a smaller editor caps how much it can correct a stronger agent.

## Detailed Report

### 1. Overview

A Search agent is asked for a headteacher's birth surname. It sees conflicting name histories, starts treating one source's answer as settled, and issues a query that confirms its favored name. Before that query runs, a separate model revises both the reasoning and the tool call so the agent investigates how the names relate. The recorded feedback gives a chronology, and the agent later submits the benchmark-accepted answer. That feedback is the trajectory's recorded reader output, not independent verification of live webpages.

Search 1: Resolving Conflicting Name Evidence. The original step seeks to confirm "Prevett"; the revised step asks how "Prevett" and "Robertson" relate. The agent later submits Prevett and the benchmark accepts it. The tool feedback is recorded in the case, not independent verification of the live pages.

The model making this correction is AEWM. Its core claim is that a long-horizon agent may need help correcting its own interpretation and plan. On this view, the agent does not need a model that invents what a search engine, terminal, or code tool might return.

### 2. When the agent's history goes wrong

The authors call the failure *task-state contamination*. Unsupported assumptions, outdated plans, or partial progress treated as completion persist in the interaction history and distort later decisions. The authors argue that this can happen even when the agent receives grounded observations.

Existing world models predict environment observations. AEWM instead judges the likely contribution of the next reasoning-and-action pair. When that pair is judged noisy, AEWM replaces both parts before execution. The real environment then provides feedback. The authors frame this as a shift from predicting environment observations to modeling decision effects and editing agent states. This framing does not establish that observation-predictive world models are universally unhelpful.

AEWM is also not the first system to judge or refine agent steps. SRR-Judge ([paper](https://www.alphaxiv.org/abs/2602.07773)) already rates and refines thought–action steps in deep search.

### 3. Judge, replace, execute

At each step, the agent proposes its next reasoning and tool action. Action Judge assesses that proposal from the task and history available before execution, and assigns it to one of three categories:

- **Critical** decisions make necessary progress.
- **Exploratory** decisions can be useful because they reduce uncertainty or test a plausible branch.
- **Noisy** decisions are unproductive or misdirected.

Critical and Exploratory proposals are kept. Only a Noisy proposal triggers State Revision, which supplies replacement reasoning and an action from the same observed history. The chosen action, not a predicted tool response, is executed in the real environment.

### 4. Does direct editing matter?

The paper calls this inference procedure EditAct. It was tested with Qwen3.5-35B-A3B across six benchmarks. EditAct's six-benchmark mean is **48.8%**, compared with **45.6%** for trajectory-level Best@3, the strongest baseline by that average. The mean is the unweighted average of six benchmark scores with different task metrics, so it is not one pooled measure of success. EditAct beats ReAct and both Best@3 baselines on all six benchmarks and three backbones. The reported gains over the strongest baseline range from 3.2 to 6.7 points. The results are means of three evaluation runs, and no significance test is reported. DeepSearchQA and SWE-Bench Pro are out-of-distribution relative to training.

A more skeptical test asks whether direct replacement adds value beyond another generation or critique-like guidance. The comparison used Qwen3.5-35B-A3B on Terminal-Bench 2.0, with the same agent, scaffold, tasks, environment settings, and evaluation protocol for every variant. EditAct scores **48.3%**, versus **40.4%** with Agent Resampling and **39.3%** with AEWM Hint. Resampling gives the agent another generation from the same history. Hint gives AEWM's revised reasoning to the agent and asks it to regenerate. This supports the direct-editing interpretation in that comparison. It does not show that direct editing is the sole source of every gain.

Table 3: ablations on BrowseComp, Terminal-Bench 2.0, and Doc2Repo (percentages). Full AEWM scores 48.1/48.3/48.9, versus 36.2/40.4/42.8 for Agent Resampling and 41.8/39.3/43.2 for AEWM Hint. Full AEWM is highest in each row. The table also contains other ablations.

EditAct adds Action Judge calls and, on noisy proposals, State Revision calls. The paper does not establish fewer generated tokens or less elapsed time overall.

### 5. What the results show

AEWM targets a contaminated reasoning-and-action state rather than a guess about what a tool might say. Real execution then supplies the next evidence. The findings support this mechanism in the tested setups. They do not support a general claim that agent-state editing is the only cause of improvement.
