# Divide-and-Remember: Recursive Action-Relevant Memory for Long-Horizon VLA Policies

> [!summary] Summary
> Divide-and-Remember (D&R) is a memory method for VLA policies that learns which history tokens to keep by maximising the conditional mutual information between action and memory given the current observation. A single shared lightweight selector recursively keeps the top-K of every 2K pretrained-space tokens, trained only by the flow-matching action loss. On RoboMME with a 64-token budget it reaches 38.6% average success, versus 32.2% for the best baseline.

## Problem

- Perceptual memories pick frames with hand-designed rules such as largest pixel change or VLM event labels, which track a loose entropy bound and are not optimised for control.
- Latent memories compress history into newly learned states that track counts well but sit outside the VLA's pretrained token space and lose spatial detail such as object locations.
- Recurrent belief-state memories grow compute linearly with episode length and cannot parallelise training over time, while test-time-training memories write facts slowly and read them back inexactly.

## Method

- ==Conditional mutual information objective==: a POMDP analysis shows the optimal memory maximises I(action; memory | observation), a ==policy-sufficient statistic== optimised through the action-likelihood variational lower bound.
- ==Recursive divide-and-remember selection==: history tokens are split into 2K-token slices, a selector keeps K per slice, then neighbouring survivors merge and are reselected, covering unbounded history at fixed cost.
- Shared transformer selector with ==M-RoPE== over time, height and width, trained end-to-end through ==straight-through sigmoid gates== and ==Gumbel-Top-K exploration==, using only the ==flow-matching action loss== on a π0.5 backbone.

## Results

- On RoboMME's **16** tasks at a **64**-token budget, D&R averages **38.6%** success, versus **32.2%** for HAMLET, **27.9%** for FrameSamp and **17.9%** for memoryless π0.5.
- Gains are largest on frame-like facts: **47.5%** on Motion-Centric versus **31.0%** for FrameSamp. On a real Franka arm D&R succeeds in **35**/**40** trials, versus **22** for FrameSamp and 3 for π0.5.
- Adding a world-model prediction loss lowers the average from **36.9%** to **33.6%**, and adding instruction text tokens costs **6.6** points. Training takes about **20** hours, versus about **10** days for RB-VLA.

## Takeaways

> [!tip] Key Insights
> - Memory should be selected for action relevance rather than visual novelty, because pixel change is a loose upper bound that wastes budget on visual changes irrelevant to control.
> - Keeping memory as verbatim pretrained tokens preserves spatial facts, but snapshot memories still trail per-step latent states on running quantities such as elapsed time or event counts.
> - Richer predictive objectives can hurt: asking memory to forecast the future spends capacity the action never repays, and past actions in memory invite causal-confusion shortcuts.

## Detailed Report

### 1. Overview

When a robot is asked to repeat an action it saw earlier, the scene in front of it may not say which action to take. Two demonstrations can lead to the same current view but call for different behavior. The authors' example is a cube that must be moved in the same manner as before: either picked up and placed, or pushed with a peg. A policy that sees only the present cannot recover a relevant fact that has disappeared from view. Divide-and-Remember (D&R) learns to keep a small selection of past visual tokens that helps choose the next action, rather than keeping frames according to a fixed rule. In the authors' tests, it improves average task success on a benchmark and on tested real-robot tasks.

(a) A video phase shows two different ways to move a cube, pick up and place or push using a peg, followed by the same current observation. (b) History passes to a "Divide and Remember" selector, a memory holds selected visual patches, and the current observation goes to the robot policy. The highlighted key fact is a grasp pose at $t-3$. This is an explanatory schematic, not a measured experimental outcome.

### 2. A memory judged by the action

In a history-dependent task, the same present view can require different actions depending on what happened earlier. The desired memory therefore preserves details from history that help determine the action and are missing from the present view.

Formally, this is conditional mutual information, $I(a_{t};m_{t}\mid o_{t})$. It measures the action-relevant information in memory $m_{t}$ that is not already in the current observation $o_{t}$. The authors derive this as an ideal objective. Maximizing it is equivalent to minimizing action-relevant information discarded from history, and an ideal memory would preserve the expert's action distribution.

Perceptual heuristics work differently: they keep frames with large pixel changes. Visual change can come from lighting or other factors irrelevant to control, so it is only a rough proxy for useful memory.

D&R approximates the ideal objective and does not calculate mutual information directly. It keeps original pretrained visual-token representations and trains the selector with the policy's action loss. In the π0.5 implementation, the flow-matching loss is a surrogate for the action log-likelihood, not itself a proven likelihood lower bound.

The selector works in stages:

1. A candidate slice of $2K$ tokens is scored and reduced to its top $K$.
1. Selected tokens from neighboring slices are combined and selected again.
1. This repeats until the root produces the bounded memory for the policy.

The selector is shared across recursion blocks, so the input size of each selection stays fixed even as history grows. Tokens remain in temporal order. The same tree is constructed for a given history prefix in training and deployment, so the method avoids an offline–online mismatch.

(a) History tokens run along a time axis from leaf level toward root. Repeated selector boxes score and prune tokens, and kept tokens merge into the next selection level. At the root, the selected memory tokens go to the policy. (b) Image and language features enter a vision-language model, then an action expert that receives memory through adaptive LayerNorm and cross-attention.

### 3. Does action-relevant selection pay off?

**Benchmark results.** RoboMME has 16 long-horizon manipulation tasks in four suites: Counting, Permanence, Reference, and Imitation. Each task is evaluated over 50 episodes. The overall score is the mean success rate across the 16 tasks, with task rates weighted equally. All memory methods use the π0.5 backbone and the same 64-token budget, and results average the last three checkpoints and three seeds.

Under this setup, D&R's average success rate is **38.58%**. HAMLET, the best baseline on the overall average, reaches **32.22%**, and memoryless π0.5 reaches **17.93%**. HAMLET is a learned latent-memory approach. It compresses each timestep into moment tokens and aggregates them for action prediction ([HAMLET: Switch Your Vision-Language-Action Model into a History-Aware Policy](https://openreview.net/forum?id=KcJ9U0x6kO)). D&R instead selects existing pretrained visual tokens. This result does not establish that preserving original tokens is the only cause of the gain.

The advantage is also uneven across memory demands. D&R gains the most on frame-like facts. Latent memory is competitive on state-like facts and does better on some individual tasks, and HAMLET leads on Time-Sensitive.

**Real-robot results.** The tests covered four tasks (PutBottles, TrackCube, RepickCube, and DrawPattern) with 10 trials each. D&R succeeds in **35 of 40 trials**, against **22 of 40 for FrameSamp** and **3 of 40 for memoryless π0.5**. This is evidence on those tested tasks, not proof of broad real-world reliability.

### 4. What the result shows

D&R defines useful memory by what it contributes to action beyond the current observation. It trains a recursive, fixed-size selector through the policy's action objective as a practical approximation to that target. Under a shared 64-token, π0.5 setup, it achieves the highest average success rate on RoboMME, and it succeeds in more trials on the tested real-robot tasks. Its advantage is strongest on frame-like facts, and latent memory remains competitive on state-like ones.
