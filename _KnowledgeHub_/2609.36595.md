# Simple Agentic Memory for Generalist Robot Policies

> [!summary] Summary
> SimpleARM is a training-free memory layer for frozen hierarchical robot policies. It treats memory as task-relevant state instead of retained frames. A VLM reads the instruction and specifies which entity relations, progress counts and procedures to track. Frozen perception tools update that state online. Structured retrieval feeds the state only to subgoals that depend on history, re-grounded in the current view. It reaches 67.17% mean success on RoboMME versus 44.51% for the strongest baseline.

## Problem

- Long-video and streaming memory methods store history as retained or compressed observations, but control-relevant state like identity bindings, counts or procedures may appear in no single frame.
- Memory-augmented VLAs pass compressed visual tokens, retrieved keyframes or text to the policy, and RoboMME shows diminishing returns from giving more tokens to perceptual history.
- Video-QA memories return historical evidence as an answer and ignore that actions change the scene, so recalled entities are never re-grounded in the current view before control.

## Method

- ==Task-conditioned state specification==: a frozen Qwen3-VL-4B planner reads the instruction once and proposes ==entity-relation, progress and trajectory variables== plus compatible retrieval operations, without assigning any values.
- ==Tool-grounded gated updates==: frozen perception and event tools, including ==identity feature anchors== and ==optical-flow continuity checks==, extract evidence and commit a state change only when an ==evidence gate== accepts it.
- ==Structured selective retrieval== with ==current-view grounding==: memory is read only when the frozen subgoal predictor's proposal has a history-dependent argument, and recalled entities are re-localized before the pi0.5 VLA executes.

## Results

- **67.17%** mean success across all **16** RoboMME tasks and three seeds, versus **32.70%** with no memory, **42.37%** MemER, **44.51%** FrameSamp and **31.50%** Recent32, against an **84.08%** oracle ceiling.
- Largest gains over FrameSamp are on Permanence (**+53.56** points) and Reference (**+42.17** points); Counting drops **8.22** points, mostly because StopCube scores **0%** and needs dense local visual history.
- Ablation losses stay localized: removing route state costs **68.0** points and progress counting **62.0** points on tasks that retrieve them, near zero elsewhere; VLM-decided retrieval at every subgoal loses **11.9** points.

## Takeaways

> [!tip] Key Insights
> - Effective robot memory is compact state derived from interaction, such as identity, progress and procedure, not more retained frames; adding perceptual history tokens gives diminishing returns.
> - Maintained state helps only when it is retrieved for a decision, so deciding when memory should influence control is a separate design problem from deciding what to store.
> - A track can stay internally coherent and still hold a wrong binding: success falls from 74/75 to 2/27 as candidate bindings grow, so identity ambiguity remains a bottleneck.

## Detailed Report

### 1. Overview

A robot sees colored cubes, and then covers hide them. The covers move. Later, the robot must pick the cover hiding the green cube, and then the one hiding the red cube. Its current camera view cannot show which cube is under which cover.

In one recorded ButtonUnmaskSwap episode, the system retains cube-to-cover bindings and updates them as the covers slide. At both history-dependent reads, the frozen composer proposes the wrong container. Each time, memory retrieves the binding and supplies a coordinate grounded in the current view. The episode succeeds at environment step 596. This system is SimpleARM. The episode is an illustrative trace of how its mechanism operates. It does not measure overall accuracy.

### 2. A memory that can reach the action

SimpleARM's central move is to remember compact, task-relevant state derived from the interaction, rather than only selected past images. It brings that state into control only when the current subgoal needs it. The authors frame this as a move from preserving visual evidence to maintaining policy-relevant state.

The process has four steps:

1. Before the task starts, a frozen vision-language model proposes what to track, based on the instruction.
1. As the scene and task evolve, frozen perception and event tools maintain verified records of three kinds:

- Entity/relation state records relationships, such as which cover hides which cube.
- Progress state records counts or task stage.
- Trajectory/procedure state records an ordered route or sequence.

1. When a proposed subgoal depends on history, structured access retrieves the compatible record.
1. For a recalled object, current-view perception locates it again before the frozen robot policy acts.

Memory is reset between episodes. If no compatible record or safe grounding is available, the system abstains rather than changing the proposal.

In the green-cube episode, this division of labor is concrete. Memory supplies the cube's identity and history, and current perception supplies where the cover is now.

### 3. The benchmark gain, and its unevenness

The benchmark is RoboMME, a set of 16 memory-dependent robot-manipulation tasks grouped into Counting, Permanence, Reference, and Imitation. Success rate is the percentage of episodes solved. Each task has 50 episodes per policy seed, three seeds are evaluated, and the overall score is the mean of the per-task success rates.

On this metric, SimpleARM reaches 67.17% mean success. The strongest non-oracle baseline, FrameSamp-ModuL, reaches 44.51%, a difference of 22.66 percentage points. FrameSamp retains sampled visual history, while SimpleARM builds and selectively reads typed state. This is a system-level comparison and does not by itself prove that memory alone caused the full gap.

The gains vary by task. SimpleARM's largest gains are in Permanence and Reference. In Counting, it trails FrameSamp, including 0% on StopCube. [[2603.04639|RoboMME]] also found that no single representation dominates across all tasks.

### 4. State helps when it is read

Matched ablations remove one component at a time from the full method. Each uses 50 matched episodes per task at one policy seed. They are therefore matched effects, not multi-seed replications.

Two results stand out:

- **Route state.** Removing route state reduces success by 68.0 points across the two tasks that require it, PatternLock and RouteStick. The remaining tasks change by −3.4 points on average.
- **Structured access.** Replacing structured access with a VLM decision at every proposed subgoal reduces success by 17.2 points on the ten tasks with retrievable historical state. On the remaining tasks, it reduces success by 3.0 points.

These results are evidence of mechanism specificity, not universal causal proof.

### 5. State, then action

SimpleARM is a training-free layer that keeps the subgoal predictor and the low-level policy frozen. It maintains typed, episode-level state and reads it only when a subgoal depends on history. The moving-cover episode illustrates this mechanism, and the ablations tie the gains to state being retrieved for control.

The evaluation covers simulated benchmark tasks, not real-world deployment. The measured benefit is success rate. The system is also not computation-free: it makes ten text-only language-model calls before the first action and averages 2.02 seconds of perception-tool time per episode.
