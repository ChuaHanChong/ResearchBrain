# Learning to Generate Unit Test via Adversarial Reinforcement Learning

> [!summary] Summary
> Researchers at KAIST and Microsoft Research developed UTRL, an adversarial reinforcement learning framework for training large language models to generate unit tests using only instruction-code solution pairs. This framework iteratively co-evolves a unit test generator and a code generator, producing unit tests that significantly improve code evaluation accuracy and fidelity compared to supervised methods and frontier models like GPT-4o.

## Problem

- Generating comprehensive, high-quality unit tests, especially for challenging edge cases, is a complex and resource-intensive task for human developers and LLMs.
- Existing LLM-based approaches, predominantly supervised fine-tuning, rely on costly and difficult-to-scale explicit unit test labels for training.
- Designing reliable reward functions for unit test generation in reinforcement learning without requiring ground-truth unit test annotations is an open challenge.

## Method

- **UTRL** (Unit Test Reinforcement Learning) employs an ==adversarial RL== framework that iteratively trains two LLMs: a unit test generator (MUTM_{UT}MUT) and a code generator (McodeM_{code}Mcode).
- MUTM_{UT}MUT is trained to generate unit tests that maximize a combined reward for discriminating faulty code (from McodeM_{code}Mcode) from ground-truth solutions and ensuring the functional validity of individual test cases.
- McodeM_{code}Mcode is trained to produce robust code solutions that achieve a high pass rate against the increasingly challenging unit tests generated by its adversary, MUTM_{UT}MUT, using only instruction-code solution pairs for training.

## Results

- UTRL-generated unit tests achieved superior 'Best-of-N improvement,' yielding code accuracies up to **17.3%** for Qwen3-**14B** code generation, surpassing proprietary models like GPT-4o.
- The framework significantly improved 'Unit test fidelity,' with UTRL-trained Qwen3-**14B** achieving a Spearman's correlation of **0.827** with ground-truth evaluations, outperforming supervised methods and GPT-4.1.
- The adversarially trained code generator within UTRL reached a pass@1 accuracy of **15.3%**, significantly outperforming code trained with GPT-4o-generated tests and supervised fine-tuning.

## Takeaways

> [!tip] Key Insights
> - An adversarial learning paradigm, where a unit test generator and a code generator co-evolve, can effectively train LLMs for unit test generation without requiring explicit human-annotated unit test labels.
> - A reward function combining 'discrimination' (ability to expose faults in generated code) and 'validity' (functional correctness against ground-truth code) is critical for guiding the unit test generator's learning.
> - Iterative training significantly improves unit test quality, as a more robust code generator compels the unit test generator to create more sophisticated and discriminative tests.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

Unit testing is an integral practice in software development, serving as a mechanism for evaluating and verifying the functional correctness of programs. This applies to code developed by human programmers as well as solutions generated by large language models (LLMs). The utility of unit tests extends to providing verifiable reward functions in reinforcement learning (RL) or for test-time scaling in LLM-driven code generation. However, the process of creating comprehensive and high-quality unit tests is resource-intensive and challenging. Effective unit tests require not only functional validity but also the ability to cover challenging edge cases that can discriminate between correct and subtly faulty code implementations. This demands considerable code reasoning capabilities and a deep understanding of the programming task.

Recent advancements in LLMs have demonstrated their proficiency in code understanding and generation, leading to explorations of their application in automating unit test generation. A common approach involves supervised fine-tuning (SFT) of LLMs on instruction–unit test pairs. Efforts to scale the annotation of high-quality unit tests for SFT have included leveraging capable teacher models (e.g., CodeRM), employing code perturbation techniques to create faulty variants for test case generation (e.g., UTGEN), or utilizing generator–validator frameworks. While these SFT-based methods have shown promise, their inherent reliance on explicit unit test labels for every training example limits their scalability across diverse programming domains due to the high cost of obtaining such annotations.

Reinforcement learning presents an alternative paradigm by directly optimizing models against reward signals, thereby potentially removing the need for explicit unit test labels and offering a more scalable approach to training LLMs for unit test generation. The primary challenge in this context is the design of a reward function that can reliably assess the quality of generated unit tests without requiring ground-truth annotations. Prior work in RL for LLMs has focused on aligning models with human preferences (RLHF) or improving reasoning capabilities in domains with verifiable rewards, such as mathematics and code generation. However, defining verifiable rewards for unit test generation, which is a non-trivial task, remains less explored.

Adversarial learning and self-play frameworks, where models improve through competition with an adaptive opponent (often derived from the model itself), have demonstrated success in various domains, including strategic decision-making and curriculum generation. More recently, these paradigms have been extended to LLM-based systems for tasks like task generation and solving (e.g., AZR), alignment (e.g., SPIN), and code/test generation (e.g., Sol-Ver, CURE, STP). CURE, in particular, explores the co-evolution of code generation and test case generation via RL but assumes access to ground-truth unit test datasets.

This work, UTRL, positions itself within this landscape by proposing a novel adversarial RL framework for training an LLM to generate unit tests. A distinguishing feature of UTRL is its ability to train an LLM for unit test generation using only instruction-code solution pairs, thereby circumventing the need for ground-truth unit test annotations. It also focuses on generating an optimal set of test cases rather than a single test case, addressing a limitation of some prior co-evolutionary approaches. By designing a discrimination reward derived from ground-truth code solutions and LLM-generated faulty code, UTRL aims to overcome the scalability issues of SFT-based methods and the data requirements of some existing RL approaches for unit test generation.

### 2. Key Objectives and Motivation

The central objective of this research is to develop a robust and scalable method for training large language models (LLMs) to generate high-quality unit tests. The authors identify several motivations driving this objective:

1. **Challenge in comprehensive unit test generation:** Writing unit tests that are both functionally valid and capable of identifying subtle faults, especially those related to challenging edge cases, is a labor-intensive and complex task for human developers. This difficulty persists even with the aid of powerful LLMs.
2. **Limitations of existing LLM-based approaches:** While LLMs have demonstrated strong capabilities in code understanding and generation, methods for training them specifically to produce high-quality unit tests are underexplored. Current supervised fine-tuning (SFT) approaches rely on instruction–unit test pairs, which are costly and difficult to obtain at scale across diverse programming domains. The open-ended nature of unit test implementation, with no single correct solution and subjective quality evaluation, further complicates dataset curation for SFT.
3. **Need for scalable training without ground-truth unit tests:** To overcome the data annotation bottleneck of SFT, there is a motivation to develop a training paradigm that does not require explicit ground-truth unit test labels. The widely available instruction–code solution pairs offer a potential alternative data source.
4. **Enhancing code evaluation and verification:** High-quality unit tests are critical for robust program evaluation and verification, whether the code is human-written or LLM-generated. Improving automated unit test generation capabilities can contribute to more reliable and safe LLM-based code generation and advanced software engineering practices.

To address these motivations, the authors propose UTRL (Unit Test Reinforcement Learning), an adversarial reinforcement learning framework. The key objective is to iteratively train two LLMs—a unit test generator and a code generator—in a competitive manner. Specifically:
- The **unit test generator** is motivated to produce tests that are highly discriminative, meaning they can effectively expose faults in code solutions, particularly those that are "near-correct" but still contain subtle errors. It should also generate functionally valid test cases.
- The **code generator** is motivated to produce robust code solutions that pass the increasingly challenging unit tests generated by its adversary, the unit test generator.

Through this adversarial interaction, the framework aims to progressively improve both the code generation and unit test generation capabilities, ultimately enabling the unit test generator to create comprehensive test suites that detect even subtle faults without direct supervision from human-annotated unit tests.

### 3. Methodology and Approach

UTRL is an adversarial reinforcement learning framework designed to train a unit test generator LLM ($M_{UT}$) and a code generator LLM ($M_{code}$) iteratively. The core idea is to foster a competitive learning environment where each LLM's improvement drives the other's development.

#### 3.1. Overview of UTRL Framework

The framework operates by alternating between two main training steps:

- **Step 1: Training the Unit Test Generator ($M_{UT}$):** Given a programming instruction, $M_{UT}$ is trained to generate a unit test $T$ that maximizes a reward signal. This reward encourages $T$ to discriminate faulty code solutions (produced by $M_{code}$) from ground-truth code solutions and to contain functionally valid test cases.
- **Step 2: Training the Code Generator ($M_{code}$):** For the same instruction, $M_{code}$ is trained to generate code solutions $C$ that maximize their pass rate against the unit tests $T$ generated by $M_{UT}$.

This iterative process leads $M_{code}$ to produce more functionally correct solutions, which in turn compels $M_{UT}$ to generate increasingly discriminative and high-quality unit tests capable of identifying subtle flaws in near-correct code. The framework leverages instruction–code solution pairs, which are more readily available than instruction–unit test pairs.

#### 3.2. Training the Unit Test Generator ($M_{UT}$)

To guide $M_{UT}$ to generate both effective and functionally valid unit tests, two reward components are introduced:

- **Discrimination Reward ($R_{disc}$):** This reward evaluates how effectively the generated unit test $T$ can distinguish between code solutions produced by $M_{code}$ and the ground-truth code solution ($C^*$).
 - **Computation:** For a given instruction $I$, $M_{UT}$ generates a unit test $T$. A set of code solutions $C$ is sampled from $M_{code}$. The reward is calculated as the fraction of sampled code solutions in $C$ that are "detected" by at least one valid test case in $T$. A test case is considered functionally valid if it passes under the ground-truth code solution $C^*$.
 - **Formula:** $R_{disc}(T, C, C^*) = \frac{1}{|C|} \sum_{C \in C} \left[ 1 - \prod_{T' \in T, \text{Pass}(C^*, T')=1} (1 - \text{Pass}(C, T')) \right]$
 - `Pass(Code, Test Case)` is an indicator function returning 1 if `Code` passes `Test Case`, and 0 otherwise.

- **Validity Reward ($R_{valid}$):** This component ensures that the individual test cases within the generated unit test $T$ are functionally correct (i.e., they correctly map inputs to expected outputs for the given instruction).
 - **Computation:** It is defined as the proportion of test cases in $T$ that pass the ground-truth code solution $C^*$.
 - **Clipping Mechanism:** To prevent $M_{UT}$ from receiving high rewards for generating only a few trivial valid test cases, a hyperparameter $\tau$ is used. The denominator in the validity reward formula is $\max(|T|, \tau)$, where $|T|$ is the number of test cases in $T$. This ensures that unit tests with fewer than $\tau$ test cases receive a reward proportional to the absolute number of valid test cases, discouraging sparse unit tests.
 - **Formula:** $R_{valid}(T, C^*, \tau) = \frac{\sum_{T' \in T} \text{Pass}(C^*, T')}{\max(|T|, \tau)}$

- **Combined Training Reward for $M_{UT}$:** The total reward $r_{UT}$ for $M_{UT}$ is a weighted sum of the discrimination reward and the validity reward: $r_{UT} = \lambda R_{disc}(T, C, C^*) + (1 - \lambda)R_{valid}(T, C^*, \tau)$, where $\lambda$ is a weighting hyperparameter. $M_{UT}$ is updated via an RL algorithm (GRPO) to maximize this combined reward.

#### 3.3. Training the Code Generator ($M_{code}$)

After $M_{UT}$ is updated, $M_{code}$ is trained.

- **Reward for $M_{code}$ ($R_{code}$):** Given a code solution $C$ generated by $M_{code}$ and a unit test $T$ generated by $M_{UT}$, the reward for $C$ is defined as its pass rate over the *functionally valid* test cases in $T$. Invalid test cases (those that fail $C^*$) are filtered out to ensure fair evaluation.
 - **Formula:** $R_{code}(C, T, C^*) = \frac{\sum_{T' \in T} \text{Pass}(C, T') \cdot \text{Pass}(C^*, T')}{\sum_{T' \in T} \text{Pass}(C^*, T')}$
 - $M_{code}$ is updated via an RL algorithm (GRPO) to maximize this reward, learning to produce solutions that pass the unit tests generated by its adversary.

#### 3.4. Reinforcement Learning Algorithm

The authors employ **Grouped Relative Policy Optimization (GRPO)**, a variant of PPO, for RL training. GRPO addresses the computational and memory costs of learning a separate value function in standard PPO by sampling a group of outputs from the LLM policy, computing scalar rewards for each, and then normalizing these rewards to derive an advantage score. This shared advantage is broadcast to all tokens in an output, weighting token-level policy gradients without requiring a dedicated value function.

#### 3.5. Experimental Setup

- **Base Model:** Qwen3-4B (Yang et al., 2025) is used as the base LLM for both the unit test and code generators.
- **Dataset:** The TACO dataset (Li et al., 2023), comprising 15,249 programming instruction-code solution pairs, is used for training.
- **Hyperparameters:** Specific values for $\lambda$, $\tau$, number of code samples, and GRPO parameters are provided in the appendix.
- **Evaluation:** The quality of generated unit tests is assessed using "Best-of-N improvement" (how well unit tests select high-quality code from candidates) and "Unit test fidelity" (Spearman's correlation between evaluations induced by generated tests and ground-truth tests). Code generation performance is measured by pass@1 accuracy. Evaluation is performed on the TACO evaluation set and LiveCodeBench-v2.

### 4. Main Findings and Results

The experiments conducted investigate the effectiveness of UTRL in training LLMs for unit test generation, comparing it against supervised learning approaches and frontier models.

#### 4.1. Effectiveness of UTRL in Generating High-Quality Unit Tests (RQ1)

- **Best-of-N Improvement:** Unit tests generated by Qwen3-4B trained with UTRL demonstrated superior performance in selecting high-quality code solutions. When used as evaluators for best-of-32 sampling with Qwen3-8B and Qwen3-14B code generators, UTRL-generated unit tests yielded code accuracies of 14.9% and 17.3%, respectively. This represents a substantial gain (e.g., +6.9% for Qwen3-8B) compared to the base Qwen3-4B (9.8% accuracy). Notably, UTRL-trained Qwen3-4B also surpassed the performance of unit tests generated by frontier proprietary models such as GPT-4.1 and GPT-4o. A larger model, Qwen3-14B trained with UTRL, achieved even higher accuracies (15.0% and 17.7%).
- **Unit Test Fidelity:** UTRL significantly improved the fidelity of generated unit tests. Qwen3-4B trained with UTRL achieved a Spearman's correlation of 0.794, and Qwen3-14B with UTRL reached 0.827. These values indicate that UTRL-generated unit tests induce code evaluations that closely align with those from ground-truth unit tests, with UTRL-trained Qwen3-14B outperforming GPT-4.1 (0.800).
- **Comparison to CURE:** When comparing UTRL (specifically, UTRL$^\dagger$ trained on Qwen2.5-7B-Instruct with CodeContests dataset) against CURE, UTRL showed superior best-of-N improvement (e.g., 14.1% vs. 9.7% code accuracy for Qwen3-8B code generator) and higher unit test fidelity (0.593 vs. 0.576). This indicates UTRL's advantage even without requiring ground-truth unit test annotations, unlike CURE.
- **Generalization to LiveCodeBench:** Experiments on the LiveCodeBench-v2 dataset further confirmed UTRL's generalization capabilities, with UTRL-trained models outperforming CURE and GPT-4.1 in best-of-N improvement.

#### 4.2. Superiority of UTRL Over Supervised Learning Approaches (RQ2)

- UTRL consistently outperformed supervised fine-tuning (SFT) baselines. SFT on ground-truth unit tests (D$_{UT}$) provided gains over the base model but was inferior to UTRL in both best-of-N improvement and unit test fidelity.
- SFT with reasoning-augmented synthetic data (D$_{reason+UT}$) achieved a slightly better unit test fidelity (0.604) than SFT with D$_{UT}$ (0.566) but still lagged behind UTRL (0.794). Moreover, SFT with D$_{reason+UT}$ showed inferior best-of-N improvement compared to SFT with D$_{UT}$. This suggests that while reasoning can aid fidelity, the quality of synthetic labels can limit overall performance, and SFT may struggle with generalization compared to RL.

#### 4.3. Effectiveness of UTRL in Training Code Generator (RQ3)

- The code generator ($M_{code}$) adversarially trained within UTRL achieved a pass@1 code accuracy of 15.3% on the TACO evaluation tasks. This performance was significantly higher than training with GPT-4o-generated unit tests (under 12%) and SFT using ground-truth code solutions (3.6%).
- The UTRL-trained code generator's performance was comparable to the upper bound of 15.9% achieved by a code generator trained to maximize pass rate over ground-truth unit tests. This indicates that the unit tests generated by $M_{UT}$ in UTRL are effective in guiding the code generator towards functionally correct solutions, especially when ground-truth unit tests are unavailable.

#### 4.4. Effect of Iterative Training (RQ4)

- **Discrimination Reward Dynamics:** In the first iteration, the discrimination reward for $M_{UT}$ saturated after approximately 50 steps. After updating $M_{code}$, the discrimination reward for $M_{UT}$ dropped significantly from 0.626 to 0.375 at the beginning of iteration 2. This indicated that the updated $M_{code}$ was generating more robust solutions that were harder to distinguish from ground-truth, thus presenting a more challenging task for $M_{UT}$.
- **Subsequent Improvement:** As training continued in iteration 2, $M_{UT}$ improved, and the discrimination reward increased from 0.375 to 0.447. Correspondingly, the unit tests generated by $M_{UT}$ in iteration 2 yielded superior best-of-N performance compared to iteration 1, even surpassing GPT-4.1.
- **Sustained Improvement:** While a third iteration did not show notable improvement with Qwen3-4B, the results suggest that the adversarial process enables continuous improvement of test generation capabilities as the code generator becomes more proficient.

#### 4.5. Ablation Studies (Appendix)

- **Weighting Term (λ):** Ablation on the $\lambda$ hyperparameter for balancing discrimination and validity rewards showed that an appropriate balance (e.g., $\lambda=0.85$) is crucial. Too little discrimination reward ($\lambda=0$) led to higher validity but lower discriminativeness, while too much ($\lambda=1$) resulted in many invalid test cases.
- **Validity Reward Design:** Ablating the validity reward term confirmed its importance and the effectiveness of the clipping mechanism (`max(|T|, τ)`). Without it, the model either produced unit tests with many invalid cases or collapsed to generate a very small number of trivial test cases to maximize the validity ratio, hindering comprehensive test generation.

### 5. Significance and Potential Impact

This research presents UTRL, a novel adversarial reinforcement learning framework that contributes to the field of automated unit test generation by addressing several key limitations of existing approaches.

#### 5.1. Advancement in Unit Test Generation

UTRL demonstrates that an LLM can be effectively trained to generate high-quality, discriminative, and functionally valid unit tests without relying on costly human-annotated unit test labels. This capability is crucial, as the manual creation of comprehensive test suites, especially for complex or novel programming tasks, is a significant bottleneck in software development and LLM-driven code generation.

#### 5.2. Scalability and Data Efficiency

By leveraging readily available instruction–code solution pairs instead of instruction–unit test pairs, UTRL offers a more scalable training paradigm. This reduces the dependency on labor-intensive data annotation, enabling broader application across diverse programming domains where high-quality unit test datasets are scarce.

#### 5.3. Superior Performance

The empirical results indicate that UTRL-trained LLMs generate unit tests that yield higher best-of-N code generation improvement and unit test fidelity compared to conventional supervised fine-tuning methods and even surpass the performance of unit tests generated by frontier models such as GPT-4.1 and GPT-4o. This suggests UTRL's effectiveness in teaching LLMs to identify subtle faults and generate robust test cases.

#### 5.4. Mutual Improvement of Code and Test Generation

The adversarial nature of UTRL leads to the co-evolution of both the unit test generator and the code generator. As the code generator becomes more robust, it implicitly forces the unit test generator to create more sophisticated and discriminative tests, which in turn further refines the code generator. This synergistic learning process has the potential to advance both aspects of LLM programming capabilities.

#### 5.5. Enhanced Reliability and Trustworthiness of LLM-Generated Code

The ability to automatically generate high-quality unit tests provides a verifiable mechanism for evaluating and ensuring the functional correctness of code produced by LLMs. This is particularly relevant for the development of reliable LLM-based code generation systems and agentic software engineering, where automated verification is paramount for deploying safe and functional applications.

#### 5.6. Future Research Directions

UTRL paves the way for future research into more advanced RL algorithms for test generation, exploration of larger-capacity models within the adversarial framework, and adaptation of the framework to broader software engineering domains beyond competitive programming. Considerations for generating variable-length unit tests dynamically based on task complexity also represent a promising avenue.

In summary, UTRL presents a significant step towards fully automating the generation of high-quality unit tests, a critical component for the robust development and verification of both human-written and LLM-generated software.
