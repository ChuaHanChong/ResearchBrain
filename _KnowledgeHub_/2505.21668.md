# R1-Code-Interpreter: LLMs Reason with Code via Supervised and Multi-stage Reinforcement Learning

> [!summary] Summary
> Researchers from MIT, Harvard, University of Illinois Urbana-Champaign, and other institutions developed R1-Code-Interpreter, a framework that augments open-source Large Language Models (LLMs) with autonomous code execution capabilities through multi-turn supervised fine-tuning and a novel multi-stage reinforcement learning curriculum. The R1-CI-14B model achieved 72.4% accuracy on 37 diverse test tasks, outperforming text-only GPT-4o and GPT-4o with its native Code Interpreter, while reducing RL training time by 39%.

## Problem

- Text-only LLMs struggle with tasks requiring precise computation, symbolic manipulation, and algorithmic processing, where external tools like Code Interpreters are beneficial.
- Existing LLM integrations with Code Interpreters often underutilize symbolic capabilities due to difficulties in autonomously determining when and how to switch between textual reasoning and programmatic solutions.
- Prior research on training LLMs to use Code Interpreters typically focused on narrow domains or simple tool use, lacking a comprehensive framework for general-purpose application across diverse reasoning and planning tasks.

## Method

- The **R1-Code-Interpreter** framework extends text-only LLMs using ==multi-turn== Supervised Fine-Tuning (SFT) based on GPT-4o synthesized trajectories, followed by Group Relative Policy Optimization (GRPO).
- A novel multi-stage curriculum learning approach, guided by an 'improvement potential' metric, prioritizes training samples that offer the strongest learning signals, mitigating issues of task heterogeneity and sparse rewards.
- A specialized Code Execution Sandbox was developed to decouple code execution from GPU-based gradient computation, significantly reducing reinforcement learning training time by executing code in parallel on CPU nodes.

## Results

- R1-Code-Interpreter models demonstrated an average success rate improvement of **36.4%** on training tasks and **31.5%** on unseen testing tasks across Qwen-2.5 model sizes (**3B**, **7B**, **14B**).
- The R1-CI-**14B** model achieved an average accuracy of **72.4%** on 37 test tasks, surpassing text-only GPT-4o (**58.6%**) and GPT-4o with its native Code Interpreter (**70.9%**).
- The multi-stage curriculum learning approach enhanced average RL performance gains from +**3.4%** (vanilla GRPO) to +**9.3%** across Qwen-2.5 models and demonstrated emergent self-checking behavior and out-of-distribution generalization.

## Takeaways

> [!tip] Key Insights
> - Direct application of vanilla GRPO to a diverse, heterogeneous set of tasks yields only marginal improvements due to vanishing policy signals (gradients) when tasks are either too easy or too difficult.
> - Curriculum learning, by focusing on samples with balanced success and failure rates (high improvement potential), is crucial for effective and efficient reinforcement learning in diverse task environments.
> - Effective integration of code execution and textual reasoning requires a warm start via SFT, which instills initial reasoning capabilities before RL further optimizes autonomous code invocation and self-checking behavior.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

Large Language Models (LLMs) have demonstrated progress in reasoning and planning through reinforcement learning (RL)-based fine-tuning. However, they continue to encounter difficulties with tasks requiring precise computation, symbolic manipulation, optimization, and algorithmic processing. Textual reasoning, while effective for semantics and commonsense, often lacks the rigor for these specific types of problems. Integrating code generation and execution as an external tool has been shown to enhance LLM performance on such tasks compared to purely textual reasoning.

Existing efforts to integrate LLMs with Code Interpreters, such as OpenAI's GPT models, allow for iterative code generation and reasoning. However, current implementations have demonstrated limitations in effectively mediating between textual reasoning and programmatic solutions, leading to underutilization of symbolic capabilities. Research such as ToRL and ReTool has explored training reasoning models to incorporate Code Interpreters, but their scope has typically been confined to specific domains like mathematics. ToolRL has focused on tool selection, where the Code Interpreter's role is limited to generating relatively simple code. These approaches have not fully addressed the challenge of fine-tuning LLMs for robust, generalizable performance across a broad spectrum of reasoning and planning tasks.

This work positions itself within this landscape by addressing the identified gap: the absence of a comprehensive understanding and a published framework for training *general-purpose* Code Interpreters within open-source LLMs to achieve robust and generalizable performance across a wide array of reasoning and planning challenges. It aims to develop a training methodology that enables LLMs to autonomously decide when and how to integrate code execution with textual reasoning, overcoming limitations related to task heterogeneity and the scarcity of effective training samples in diverse environments.

### 2. Key Objectives and Motivation

The primary objective of this research is to develop and evaluate R1-Code-Interpreter, a framework for extending text-only LLMs to leverage a Code Interpreter autonomously across a diverse range of reasoning and planning tasks. This involves training the LLM to generate multiple code queries during a step-by-step reasoning process.

The motivation for pursuing this objective stems from several identified challenges and limitations in current LLM capabilities:

- **Limitations of Textual Reasoning:** LLMs, despite advances, exhibit inherent weaknesses in tasks requiring precise computation, symbolic manipulation, optimization, and algorithmic processing when relying solely on textual reasoning. External symbolic tools like Code Interpreters are recognized as beneficial for these areas.
- **Suboptimal Code Interpreter Utilization:** Existing Code Interpreter implementations in prominent LLMs often struggle to effectively determine when to switch between textual reasoning and programmatic solutions. This leads to underutilization of the symbolic capabilities offered by code execution, even when such capabilities would be advantageous. Most input questions lack explicit cues to guide this decision, and the combined text/code solution space is extensive.
- **Narrow Scope of Prior Research:** Previous efforts in training LLMs to integrate with Code Interpreters or other tools (e.g., ToRL, ReTool, ToolRL) have largely focused on narrow domains like specific math problems or simple code generation. There has been a lack of comprehensive research and practical guidance on training a *general-purpose* Code Interpreter that can perform effectively across hundreds of diverse reasoning and planning tasks.
- **Challenges of General-Purpose RL Training:** The authors observe that applying traditional reinforcement learning (RL) training, specifically DeepSeek-style GRPO, to a general Code Interpreter across a large and heterogeneous set of tasks yields only marginal improvements. This is attributed to the significant task heterogeneity, where different tasks require varied reasoning skills, and the scarcity of effective samples that provide a clear learning signal for the model. Tasks that are either too easy or too difficult offer limited gradient information, hindering effective optimization.
- **Computational Efficiency:** Training LLMs with integrated Code Interpreters is computationally intensive due to the multiple sampled rollouts required for RL and the time-consuming nature of code execution. This impacts GPU utilization and overall training efficiency, necessitating methods to mitigate these costs.

In summary, the motivation is to bridge the gap between LLMs' reasoning potential and their practical application in complex, diverse domains by developing a scalable, effective, and generalizable training methodology for Code Interpreter integration, while also addressing the practical challenges of training efficiency and signal sparsity in heterogeneous task environments.

### 3. Methodology and Approach

The R1-Code-Interpreter framework involves extending a text-only LLM through multi-turn supervised fine-tuning (SFT) followed by reinforcement learning (RL), specifically Group Relative Policy Optimization (GRPO), to autonomously integrate code execution with textual reasoning.

**Task Curation and Standardization:**
The researchers curated 144 diverse reasoning and planning tasks from three benchmarks: SymBench (33 tasks), Big-Bench-Hard (27 tasks), and Reasoning-Gym (84 tasks). Duplicate samples were removed, ensuring over 200 samples per task. All tasks were standardized into a unified format and evaluated using rule-based criteria (e.g., exact match, constraint checks) to facilitate efficient rollout and automated correctness assessment. These tasks cover diverse capabilities including mathematical, spatial, logical, ordinal, optimization, and search-based reasoning. For training, 107 tasks were selected, with the remaining 37 used for testing, ensuring no sample overlap.

**Response Format and Code Interpreter Interaction:**
A simple head prompt guides the LLM to structure its output into iterative parts: reasoning, optional Code Interpreter invocation, and a final answer. The model relies on natural language markers, enclosing code between '```python' and '```' for execution, and the final answer between '<<<' and '>>>'. The system executes detected code blocks and appends 'Code Execution Results:' to the generation. This loop continues for a maximum of 8 code calls or until a final answer is produced. Content-specific constraints, like explicit section tags, were avoided to preserve natural learning dynamics.

**Supervised Fine-Tuning (SFT):**
The SFT stage utilized 6.5k multi-turn text/code trajectories synthesized by GPT-4o. Only trajectories yielding correct answers were retained. To enhance diversity and adaptability, varied prompt formats were used, some allowing free-form reasoning while others encouraged transitions between text and code. An emphasis was placed on increasing the proportion of multi-turn trajectories with adaptive solving strategies. Each task contributed at most 70 valid trajectories. Qwen-2.5 models (3B, 7B, 14B) were used as base models, with SFT trained for 3 epochs.

**Reinforcement Learning with GRPO:**
The SFT-trained model was further optimized using Group Relative Policy Optimization (GRPO). The RL objective integrates the Code Interpreter, maximizing reward while regularizing the policy towards a reference model using KL divergence. GRPO samples a group of responses, calculates an advantage based on relative rewards within the group, and updates the policy. The reward function assigns +1.0 for correctness, +0.1 for format compliance, and -0.1 if generation turns exceed six. Policy gradients are calculated only over LLM-generated tokens, masking code execution tokens.

**Code Execution Sandbox:**
To mitigate the computational cost and GPU underutilization caused by time-consuming code execution, a specialized Code Execution Sandbox was designed. This sandbox was deployed on five 64-core CPU nodes, decoupling code execution from GPU-based gradient computation. This allowed generated code to be executed in parallel during batch inference, reportedly reducing overall RL training time by approximately 39%.

**Bottlenecks in Vanilla GRPO and Multi-Stage Curriculum Learning:**
The researchers observed that direct GRPO training on the 144 diverse tasks yielded marginal gains due to task heterogeneity and the scarcity of effective samples. They theoretically analyzed that the policy signal (gradient magnitude) in GRPO, which depends on `p(1-p)` (where `p` is the success probability), vanishes when `p` is near 0 (too hard) or 1 (too easy). This leads to the KL regularizer dominating updates and contracting the policy towards the reference model without significant learning.

To address this, a novel **multi-stage curriculum learning approach guided by measured improvement potential** was introduced:
1. **Improvement Potential Estimation:** Starting from the SFT-initialized model, four agent variants (All Text, All Code, Code Agent, CodeSteer) were used to generate 5 samples each (total N=20 answers) per training question at different temperatures. The empirical correctness rate `p_i` for each sample `x_i` was calculated, and the improvement potential `Π_i` was defined as `4 * p_i * (1 - p_i)`. This metric is maximized when `p_i = 0.5`, indicating samples with mixed outcomes that offer the strongest learning signal.
2. **Multi-Stage Training:** All training samples were sorted by their `Π_i` score and partitioned into four equally sized groups, from highest to lowest potential. GRPO training commenced with the highest-potential group. Progressively, lower-potential groups were incorporated in subsequent stages. Each stage ran for 150 steps, gradually expanding the training distribution.

**Training Parameters:**
SFT was trained for 3 epochs. GRPO used a learning rate of 1e-6, 5 sampled responses per prompt, and a KL penalty of 0.001. Training and inference temperatures were set to 1.0 and 0.6, respectively. Batch sizes were 32 for SFT and 128 for GRPO. Full-parameter fine-tuning was performed on 16 H100 GPUs.

### 4. Main Findings and Results

The research produced several findings related to the R1-Code-Interpreter framework's performance, training dynamics, and characteristics:

**Overall Performance:**
- R1-Code-Interpreter (R1-CI) demonstrated substantial improvements in reasoning and planning abilities. Across Qwen-2.5 models (3B, 7B, 14B), it achieved an average success rate improvement of 36.4% on 107 training tasks and 31.5% on 37 testing tasks.
- The R1-CI-14B model achieved a 72.4% average accuracy on the 37 test tasks. This result surpassed text-only GPT-4o (58.6%) and GPT-4o with its native Code Interpreter (70.9%).
- These improvements were consistent across all tested model sizes (3B, 7B, 14B), indicating the generalizability and effectiveness of the proposed method.

**Effectiveness of Multi-Stage Curriculum Learning:**
- Vanilla GRPO training without curriculum learning yielded only marginal gains (+3.4% average RL gains across Qwen-2.5 models), attributed to task heterogeneity and sparse effective samples.
- The multi-stage curriculum learning approach, guided by improvement potential, increased average RL performance gains to +9.3% across Qwen-2.5 models.
- Compared to variants without curriculum learning (R1-CI wo CL) or without improvement potential-based calibration (R1-CI wo IP), R1-CI consistently showed enhanced training performance across all model sizes. Training rewards and test scores showed apparent increases, particularly in the first two stages, with plateaus observed when low-potential samples were introduced in later stages.

**Cost Efficiency:**
- The specialized Code Execution Sandbox, which decouples code execution from GPU-based gradient computation, reduced overall RL training time by 39%, decreasing from approximately 4500 to 1845 GPU hours for R1-CI-14B.

**Out-of-Distribution (OOD) Generalization:**
- R1-CI-7B and R1-CI-14B models demonstrated improved performance on unseen OOD tasks, including Graduate-Level Google-Proof Q&A (GPQA, Diamond) and the American Invitational Mathematics Examination (AIME 24&25), outperforming their untrained counterparts.
- Further evaluation on an OOD benchmark (BBH), when trained on different datasets (SymBench and Reasoning-Gym), showed comparable performance to the originally trained R1-CI-14B, suggesting generalizability to unseen task distributions.

**Response Characteristics:**
- **Emergent Self-Checking:** During GRPO training, the model exhibited emergent self-checking behavior, integrating textual reasoning with code execution to verify proposed solutions. The proportion of answer trajectories containing code-based self-checking increased substantially after GRPO training.
- **Code Usage Turn Number:** Most problems were solved within fewer than four code interactions, balancing the utility of multi-turn code reasoning with maintaining a reasonable reasoning cost.
- **Response Length:** No significant increase in average response length per generation turn was observed during RL training, in contrast to some prior work. This was attributed to SFT already instilling long-chain reasoning, multi-turn interactions spreading reasoning across turns, and code-augmented reasoning reducing reliance on lengthy textual Chain-of-Thought (CoT) chains.

**Ablation Studies:**
- **Multi-turn Code Interpreter Framework:** The multi-turn Code Interpreter framework proved more generalizable and effective than single-turn All Text or All Code generation frameworks.
- **SFT Dataset Design:** Including incorrect answers degraded performance, while varied prompts, diverse strategies, and emphasis on multi-turn interactive trajectories were crucial for enhancing dataset diversity and overall performance.
- **Warm Start vs. Cold Start:** Warm-starting with SFT was identified as crucial for enabling the model to effectively reason with the Code Interpreter, leading to significant performance gains, unlike prior findings in other contexts.
- **RL Algorithms:** GRPO, PPO, and Reinforce++ showed comparable performance within the R1-CI framework.
- **Offline vs. Online RL:** Offline multi-stage training achieved comparable performance to more computationally costly online repartitioning variants in later stages.
- **RL Training Rounds:** A single round of multi-stage RL training was deemed sufficient, as continued training did not yield further improvements and could lead to overfitting on limited data.
- **Impact of Improvement Potential:** Training on samples with higher improvement potential (closer to `p=0.5`) resulted in more pronounced increases in training rewards and test scores, supporting the theoretical analysis.
- **Base Models:** Qwen-2.5 models consistently outperformed DeepSeek R1-distilled reasoning models of the same size, particularly in code generation tasks.

**Training and Inference Cost:**
- GRPO training for the Code Interpreter was computationally intensive, requiring approximately 1845 GPU hours for R1-CI-14B, even with the optimized Code Execution Sandbox. Inference generally solved most questions with fewer than four code executions and within two minutes.

### 5. Significance and Potential Impact

The R1-Code-Interpreter research contributes to the field of Large Language Models by addressing a gap in the effective training of general-purpose Code Interpreters for broad and diverse reasoning and planning tasks. Its significance and potential impact can be summarized as follows:

- **Advancement in General-Purpose Code Interpreters:** This work represents an early published effort to train a general Code Interpreter across a wide range of reasoning and planning tasks and domains. Unlike prior research focused on narrow domains or simple tool use, R1-Code-Interpreter demonstrates the feasibility of equipping LLMs with robust symbolic computation capabilities for heterogeneous problems.
- **Novel Curriculum Learning Strategy:** The introduction of a multi-stage curriculum learning approach guided by "improvement potential" is a methodological contribution. This strategy effectively mitigates the challenges of task heterogeneity and sparse reward signals in diverse RL environments, a common bottleneck in training complex agentic behaviors in LLMs. By prioritizing samples with balanced success and failure rates, the training process is made more efficient and effective.
- **Enhanced LLM Capabilities:** R1-CI-14B's performance, which exceeds that of both text-only GPT-4o and GPT-4o with its inherent Code Interpreter on the tested benchmarks, indicates that targeted fine-tuning with the proposed methodology can elevate the problem-solving abilities of open-source LLMs to levels comparable to or exceeding large proprietary models. This performance improvement spans mathematical, logical, spatial, and planning tasks.
- **Emergent Self-Checking Behavior:** The observation of emergent self-checking behavior, where the model learns to generate code to verify its own answers, suggests an improvement in the model's internal reasoning and reliability. This capability could lead to more trustworthy and robust AI systems.
- **Improved Training Efficiency:** The practical innovation of the Code Execution Sandbox, decoupling code execution from GPU-based gradient computation, significantly reduces training time. This makes the computationally intensive process of training Code Interpreter-augmented LLMs more accessible and resource-efficient.
- **Foundation for Future Research and Development:** By releasing datasets, code, and models, the authors provide resources for the research community. This open-source contribution facilitates further exploration, replication, and extension of Code Interpreter-augmented LLMs, potentially accelerating advancements in agentic AI and complex problem-solving.
- **Broader Applicability:** The demonstrated ability of R1-Code-Interpreter to combine robust code execution with textual reasoning for diverse, challenging tasks has potential implications across various domains, including scientific research, engineering, and advanced AI applications requiring precise, verifiable, and adaptive problem-solving.
