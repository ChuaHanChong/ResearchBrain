# FutureWorlds: Learning Robotic World Models from Alternative Futures

> [!summary] Summary
> FutureWorlds post-trains a discrete autoregressive robotic world model by learning from its own alternative futures. Diverse beam search builds distinct candidate rollouts. Candidate-specific bounded memory gives each branch the same history for generation and scoring. MemSPO turns video rewards into GRPO-style group-relative advantages. It cuts 32-frame LPIPS by 9-21% versus the strongest baseline on RT-1, BridgeV2, and RoboCasa.

## Problem

- Supervised autoregressive world models train on ground-truth histories but roll out on self-generated ones, so errors accumulate, and token likelihood never optimizes whole generated sequences.
- RL post-training such as RLVR-World samples candidates independently or via ordinary beam search, yielding near-identical futures that give weak, uninformative group-relative comparisons.
- Diverging candidate branches each need their own persistent history, yet prior methods neither bound this memory for long horizons nor match histories between generation and policy scoring.

## Method

- ==Diverse beam search== during RL: groups of beams score tokens by old-policy log-likelihood minus a cross-group token-frequency penalty, producing confident yet distinct candidate futures under identical conditions.
- ==Candidate-specific persistent memory==: each branch keeps the initial scene context, a state anchor, and a rolling window of recent frame and action tokens within a fixed token budget.
- **MemSPO**: a ==GRPO-style clipped surrogate== with ==dual clipping== and reference regularization, using within-group normalized MAE plus LPIPS rewards, scoring each candidate under the exact memory that generated it.

## Results

- Leads all 12 baselines on 32-frame prediction, with LPIPS **0.1551**, **0.1409**, and **0.1833** on RT-1, BridgeV2, and RoboCasa, **14.78%**, **20.84%**, and **9.12%** below the runner-up.
- With only 200 updates, MemSPO beats plain GRPO at 32 frames, reducing LPIPS by **9.98%** on RT-1, **1.58%** on BridgeV2, and **2.17%** on RoboCasa.
- Full memory cuts 32-frame MSE by **29-58%** versus no history; optical-flow error drops **4.6-16.7%** versus SFT, using 0.257B parameters but **26.76 s** beam decoding per rollout.

## Takeaways

> [!tip] Key Insights
> - For group-relative RL, how candidates are constructed matters as much as how many: enforced diversity yields informative advantages that independent sampling or plain beam search squanders.
> - When rollouts branch, each sample must be scored under the exact context that produced it; mismatched histories between generation and scoring silently corrupt the policy-gradient signal.
> - Recent context carries most long-horizon gains over distant anchors, and pixel-quality RL rewards can improve motion fidelity, though benefits for closed-loop robot control remain unvalidated.

## Detailed Report

### 1. Overview

A robot is asked to move a can, and its world model must predict how the can and gripper will move over the next 32 frames. Predicting many steps into the future is useful for anticipating action outcomes, planning, and evaluating policies. However, small errors can accumulate when a model must condition on its own predictions rather than recorded histories. FutureWorlds compares multiple predicted futures rather than relying only on a single supervised prediction. Its reported predictions more closely match recorded futures on three datasets.

RT-1 example “Move 7up can near pepsi can”: Ground truth, SFT, and MemSPO side by side for 32 frames. This is a selected open-loop prediction, not task-success evidence.

### 2. Comparing futures under their own histories

A world model predicts future observations conditioned on a scene and actions. A candidate future is one such possible rollout under shared conditions.

FutureWorlds starts from the same scene, actions, and instruction. It searches for several plausible but distinct futures and remembers each branch's recent scene history. It then compares each completed prediction with the recorded future. MemSPO uses those relative quality comparisons to update the predictor. Unlike ordinary beam search, its candidate search penalizes overlap across groups. Unlike scoring a prediction under a generic context, it scores each prediction with the same candidate-specific history that generated it.

The decoder renders candidates as videos, and a reward compares each video to the recorded future. The future frames are used for reward computation only, never to condition candidate generation or fill candidate memory.

Memory retains the initial scene/state anchors and a bounded rolling window of recent predicted states and their actions. When beams branch or reorder, their memories travel with them. MemSPO is a clipped, GRPO-style policy update with a reference-policy regularizer. Because search changes which candidates are seen, the authors do not claim an unbiased on-policy gradient.

Inputs include video observations, actions, and text. The world model makes candidate branches, each with a separate memory and rolling history. Candidate futures are decoded to video and compared with ground truth for reward, and generation and policy scoring use matching histories. This is a workflow schematic, not experimental evidence.

### 3. Does diverse search help the final model?

A skeptic might suspect that ordinary high-likelihood candidates would train just as well. The paper tests this by comparing the two methods from the same SFT checkpoint. Both use the same base reward, optimizer settings, reference policy, memory, and history-matched scoring.

Results are reported in LPIPS, a perceptual distance between predicted and reference images, averaged across frames and trajectories, where lower is better. At 32 frames, matched RT-1 LPIPS is 0.1690 for ordinary-beam post-training and 0.1565 for MemSPO after 200 updates, a 7.37% reduction. Across all three datasets and all three tested horizons, MemSPO improves PSNR and LPIPS over ordinary-beam post-training.

Several qualifications apply:

- **Beam allocation differs.** Ordinary beam keeps eight global paths and returns four, while MemSPO uses four groups of two and returns one per group. The comparison therefore does not isolate the diversity penalty.
- **The benefit depends on the metric.** On BridgeV2, the 32-frame LPIPS gain is only 0.20%, and ordinary beam has lower BridgeV2 MAE at 32 frames (0.042731 versus 0.042887).
- **Significance is not established.**

Matched post-training comparison on RT-1, BridgeV2, and RoboCasa at 10, 20, and 32 frames. At 32 frames on RT-1, LPIPS is 0.1690 for ordinary beam versus 0.1565 for MemSPO, a 7.37% reduction.

The broader benchmark covers 32-frame prediction on 128 held-out trajectories per dataset. There, FutureWorlds reports lower LPIPS than the strongest baseline on RT-1, BridgeV2, and RoboCasa, with reductions of 14.78%, 20.84%, and 9.12%. On RT-1, FutureWorlds scores 0.1551 against 0.1820 for RLVR-World.

These checkpoints use 500, 200, and 400 MemSPO updates on RT-1, BridgeV2, and RoboCasa, respectively. Models share recorded actions, trajectories, and targets but retain native interfaces and decoding. For example, Cosmos-Predict2.5-2B uses one initial observation, while FutureWorlds uses two.

### 4. Prediction needs history

FutureWorlds makes alternative futures usable as learning signals by comparing them under the histories that generated them. This yields better measured prediction on three manipulation datasets.

These are prediction metrics and selected open-loop examples. They are not evidence of physical robot task success or validated closed-loop control, which the paper identifies as future work. Autoregressive beam decoding also costs latency. In a native-configuration BridgeV2 comparison, FutureWorlds takes 26.76 seconds per 32-frame rollout versus iVideoGPT's 4.14 seconds. That timing comes from three cases on one H20 at batch size one, so it is not a general speed guarantee.
