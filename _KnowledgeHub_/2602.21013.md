# Notes-to-Self: Scratchpad Augmented VLAs for Memory Dependent Manipulation Tasks

> [!summary] Summary
> Notes-to-Self augments VLA policies with an explicit language scratchpad: the model predicts a description alongside each action, appends it to a stored context (grounding, plan, act sections) via a done-token trigger, giving stateless and recurrent VLAs spatial and temporal memory. Scratchpad boosts memory-dependent task success 48.8% non-recurrent, 11% recurrent.

## Problem

- Existing VLAs are stateless, mapping current observation to action independent of past states, failing on non-Markovian long-horizon manipulation tasks.
- Recurrent policies (RoboMamba, RoboFlamingo, ClevrSkills backbones) are used mainly as transformer substitutes, not explicit long-horizon memory solutions, and still lose task-relevant info as horizons lengthen.
- No robotics benchmark rigorously isolates spatial versus temporal memory requirements, since most simulators assume Markovian tasks with sufficient current-state information.

## Method

- **Scratchpad**-augmented VLA: model jointly predicts action and description conditioned on observation, instruction, and accumulated scratchpad, forming distribution over action and description given state and memory.
- ==Special-token update logic== (Algorithm 1): a done token triggers appending the current description into the scratchpad for grounding, plan, and act sections, else scratchpad stays unchanged across steps.
- Recurrent extension: interleaved text sequences of instruction, description, observation, and action trained via ==next-token prediction== on ==Mamba backbone== with an MLP action head for continuous outputs.

## Results

- On ClevrSkills-Mem (5 tasks), scratchpad improves transformer VLA success by **68%**, **72%**, **68%**, and **30%** on four tasks, averaging **48.8%** gain overall.
- Scratchpad-equipped transformer VLA matches or surpasses recurrent VLA performance on average, while recurrent VLA with scratchpad still gains **11%** further.
- On MemoryBench Put-Block-Back, scratchpad raises RGB-only transformer VLA from **0%** to **40%** (**100%** under relaxed sim-eval); real-world pick-place-restore task rises from **0%** to **65%** success with OpenVLA.

## Takeaways

> [!tip] Key Insights
> - Explicit language memory can substitute for architectural recurrence, since a scratchpad-augmented feedforward VLA rivals or beats a genuinely recurrent backbone on memory tasks.
> - Even models with inherent memory benefit from an external symbolic trace, suggesting recurrence alone does not reliably retain long-horizon task-relevant state.
> - Language-based memory is limited to coarse temporal or spatial recall and fails on tasks needing fine-grained continuous tracking, such as cumulative rotation amount.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

The field of robotics has experienced a notable advancement with the emergence of Vision-Language-Action (VLA) models, which integrate large-scale language and vision models to enable robots to understand semantic instructions and execute actions. These VLAs, exemplified by models such as Gato, RT-1, RT-2, OpenVLA, and π0, leverage internet-scale data for improved generalization across various tasks, robot morphologies, objects, and lighting conditions. However, a significant limitation of current VLA paradigms is their predominantly "stateless" or "reactive" nature. These models typically map a visual input at a given timestep to an action without retaining memory of past observations or actions, operating under a Markovian assumption where the current state is sufficient for decision-making.

This architectural characteristic restricts their performance on non-Markovian, memory-dependent tasks that are common in real-world scenarios. Such tasks require robots to track object positions over time, remember prior actions, or recall sub-task completion status to formulate subsequent actions. While prior research in robotics has explored various forms of memory—including explicit spatial mapping (e.g., SLAM, attention-based memory modules, 3D representations like voxel-maps and Gaussian splats) and recurrent policies (e.g., RoboMamba, RoboFlamingo, ClevrSkills for efficient processing)—these approaches have not comprehensively addressed the integration of both spatial and temporal memory into the VLA framework through a flexible, language-based mechanism. Recurrent networks, despite their inherent memory capabilities, can struggle with long-horizon tasks due to training challenges, such as GPU memory limitations and vanishing gradients, often requiring training on sub-sampled trajectories that limit long-term information retention.

This work positions itself to address the gap in memory capabilities for VLAs. It aims to endow VLAs with both spatial and temporal memory by introducing a language scratchpad. This approach distinguishes itself by leveraging the inherent language capabilities of the underlying Vision-Language Model (VLM) to create an explicit, evolving memory trace of the robot's own behavior, encompassing both environmental state changes and task progress. By doing so, the research contributes to making VLAs more robust and capable of handling complex, multi-stage, and long-horizon manipulation tasks that necessitate sequential reasoning and information retention beyond immediate observations.

### 2. Key Objectives and Motivation

The primary objective of this research is to enhance the capabilities of Vision-Language-Action (VLA) models by enabling them to effectively solve memory-dependent, non-Markovian manipulation tasks. The existing VLA paradigm, while successful in leveraging internet-scale semantic understanding for robotics, primarily operates in a "stateless" or "reactive" manner. This means that current VLAs predict actions based solely on the immediate visual input and high-level language instruction, largely disregarding past observations, previous actions, or the evolving state of the environment over a long time horizon.

The motivation for this work stems from the observation that many real-world dexterous manipulation tasks are inherently non-Markovian. Solving these tasks requires a robot to maintain memory of various types:
- **Spatial Memory:** The ability to remember the initial positions of objects, their changing locations during a task, or specific target locations. For instance, in a "swap" task, the robot must recall the original positions of two objects to correctly interchange them.
- **Temporal Memory:** The capacity to keep track of its own plan, recognize which sub-tasks have been completed, and determine the next step in a multi-stage process. An example is a "touch-reset-pick" task, where the robot needs to remember that it has already touched an object and reset its position before proceeding to pick another object. Without this temporal memory, the robot might repeatedly perform an already completed sub-task or fail to sequence actions correctly.

Contemporary VLAs fail on such tasks because they lack explicit mechanisms to store and retrieve this crucial information. The absence of memory leads to policies that are unable to:
1. **Remember Object Positions:** They cannot retain knowledge of where objects were initially placed or how their positions might have changed, which is critical for tasks requiring restoration or precise placement relative to an initial state.
2. **Track Sub-task Progress:** They cannot distinguish which parts of a multi-stage task have been completed and what actions are required next, leading to repetitive or incomplete task execution.

Therefore, the key motivation is to overcome these limitations by investigating a simple yet effective strategy: incorporating a language scratchpad into VLAs. This scratchpad is designed to serve as an explicit, evolving memory trace, leveraging the innate language capabilities of the underlying VLM. By allowing the VLA to predict and store textual descriptions of its intentions ("thoughts"), environmental states (like object positions), and task progress, the model can condition future actions not just on current visual input and the original instruction, but also on a rich, semantic history of its own behavior. This is hypothesized to impart both spatial and temporal memory, thereby enabling VLAs to successfully execute complex, long-horizon, memory-dependent manipulation tasks that are currently beyond their capabilities.

### 3. Methodology and Approach

The core methodology involves augmenting existing Vision-Language-Action (VLA) models with a language scratchpad to impart spatial and temporal memory.

#### 3.1. Scratchpad-Augmented VLAs

The fundamental idea is to extend standard VLA models, which typically predict an action ($a_t$) and potentially a language description ($d_t$) given an observation ($o_t$) and instruction ($l$), to incorporate a history-dependent context. The proposed scratchpad-augmented VLA models the conditional distribution $p(a_t, d_t | o_t, S_t, l)$, where $S_t$ is the language scratchpad at timestep $t$.

- **Scratchpad Structure:** The scratchpad is a collection of language descriptions, $S_t = \{d_1, d_2, \ldots, d_n\}$. It is designed with three main sections:
 - **Grounding:** Contains initial conditions and spatial memory, such as object positions and the end-effector's starting pose.
 - **Plan:** Outlines the sequence of sub-tasks required to complete the overall task.
 - **Act:** Records the current progress by listing sub-tasks that have already been completed by the policy, serving as temporal memory.
- **Scratchpad Update Mechanism:** The VLA itself is responsible for updating the scratchpad. During execution, the model predicts an action and a description ($d_t$). If $d_t$ contains a special "update token" (e.g., `<done>`), it signifies the successful completion of a sub-task. Upon detection of this token, $d_t$ is added to the scratchpad, $S_{t+1} = S_t \cup d_t$. If no update token is predicted, the scratchpad remains unchanged, $S_{t+1} = S_t$. This autoregressive update mechanism ensures that future actions are conditioned on an explicit, evolving memory trace of the robot's past interactions and the environment's state changes.

#### 3.2. Generating Scratchpad Data

To train models with a language scratchpad, ground truth data is generated that includes detailed descriptions for the scratchpad content. This involves:
- **Leveraging Oracle Solvers:** For simulated environments, oracle solvers are used to generate complete trajectories, including actions, precise object positions, and sub-task segmentations.
- **Creating Descriptions:** Based on these traces, natural language descriptions are formulated for the "grounding," "plan," and "act" sections of the scratchpad. These descriptions capture both spatial information (e.g., "Cyan cube is at [-34, 17, 2]") and temporal information (e.g., "Touching cyan cube at [-34, 17, 2]; Done;"). The design allows for flexibility in the type of coordinates (3D, 2D) and semantic labels used.

#### 3.3. Extending Scratchpad to Recurrent VLAs

The framework is also applied to recurrent VLA (R-VLA) models, which possess inherent memory capabilities but can struggle with very long trajectories.
- **Interleaved Sequences:** For R-VLAs, ground truth trajectories are converted into interleaved sequences of language instructions ($l$), observations ($o$), actions ($a$), and descriptions ($d$). This sequence format, e.g., $[l, d_1, o_1, a_1, o_2, a_2, \ldots, d_k, o_n, a_n]$, allows the scratchpad to be naturally integrated into the input context.
- **Training Objective:** R-VLAs are trained on a simple next-token prediction task. Image observations are represented by special `<image>` tokens, which are replaced by image embeddings from a vision head after tokenization.
- **Action Head:** A key difference for R-VLAs is the use of a simple Multi-Layer Perceptron (MLP) as an action head, which takes embeddings from an `<action>` token to produce 7-dimensional real-valued vectors for actions, as opposed to the discretized actions used by the Transformer-based VLA (T-VLA).

#### 3.4. Model Architectures and Training

- **Transformer-based VLA (T-VLA):**
 - **Base Model:** PaliGemma-2 VLM (3B parameters), built on Gemma-2 LLM and SigLIP vision encoder.
 - **Scratchpad Integration:** The linearized scratchpad is appended to the prompt. Special tokens (e.g., `<plan>`, `</plan>`, `<think>`, `<act>`, `<done>`) are used to delineate different parts of the scratchpad and control its updates.
 - **Training:** Full finetuning with a batch size of 8, learning rate of $2 \times 10^{-5}$ using Adam optimizer.
- **Recurrent VLA (R-VLA):**
 - **Base Model:** Mamba language model (130M parameters) with a ViT as an image backbone.
 - **Training:** Full finetuning with a batch size of 4, learning rate of $10^{-5}$ using Adam optimizer.

#### 3.5. Evaluation Environments and Tasks

The approach is evaluated across three distinct settings:
- **ClevrSkills-Mem Benchmark:** A novel split of memory-dependent tasks from the ClevrSkills environment (based on ManiSkill2). This benchmark includes five tasks:
 1. **Touch-reset-pick:** Requires temporal memory to sequence touching, resetting, and picking.
 2. **Place-next-to and restore:** Evaluates spatial memory for restoring objects to initial positions.
 3. **Stack-and-topple:** Long-horizon task requiring temporal memory for complex sequencing.
 4. **Swap:** Combines spatial (remembering initial positions) and temporal (tracking task phase) memory.
 5. **Rotate-restore:** Requires fine-grained temporal memory to track rotation relative to the initial orientation.
- **MemoryBench:** Focusing on the "Put-Block-Back" task, which tests both temporal (button press status) and spatial (initial object position) memory, alongside precise manipulation.
- **Real-world Task:** "Pick-Place-Restore" using a UFACTORY xArm 6 robot. This task requires picking an object, placing it in a bowl, and then restoring it to its original position, testing both spatial and temporal memory in a physical environment.

Actions are generally 7-dimensional end-effector pose deltas (6DoF pose + 1D gripper state), discretized for T-VLA and real-valued for R-VLA. Training data for the real-world task comprised 200 tele-operated trajectories.

### 4. Main Findings and Results

The experiments demonstrate that incorporating a language scratchpad significantly enhances the performance of VLAs on memory-dependent tasks across various settings, for both non-recurrent and recurrent architectures.

#### 4.1. ClevrSkills-Mem Benchmark

On the ClevrSkills-Mem benchmark, which features a suite of challenging memory-dependent tasks, the scratchpad consistently improved success rates:
- **T-VLA (Transformer-based VLA):** The baseline T-VLA, operating without a scratchpad, struggled on all tasks, exhibiting low success rates.
- **T-VLA w/ Scratchpad:** The integration of the language scratchpad led to substantial performance gains:
 - **Touch-reset-pick:** 68% improvement.
 - **Swap:** 72% improvement.
 - **Place-next-to-restore:** 68% improvement.
 - **Stack-and-topple:** 30% improvement.
 - **Overall Average:** An average performance gain of 48.8% across these tasks.
- **Rotate-restore:** Neither T-VLA nor T-VLA w/ Scratchpad achieved significant success on this task, indicating that fine-grained, low-level temporal memory requirements for precise rotation adjustments may not be fully addressed by the current scratchpad design.
- **R-VLA (Recurrent VLA):** R-VLA, with its inherent memory capabilities, generally outperformed the stateless T-VLA. However, the T-VLA w/ Scratchpad was able to match or even surpass the R-VLA's performance on average, highlighting the effectiveness of explicit language-defined memory.
- **R-VLA w/ Scratchpad:** Even with inherent recurrence, R-VLAs showed an average improvement of 11% when augmented with the scratchpad. This suggests that for tasks with longer average trajectory lengths, explicit memory augmentation can complement implicit recurrent memory, aiding in information retention over extended horizons and overcoming challenges like vanishing gradients in long sequences.

#### 4.2. MemoryBench (Put-Block-Back Task)

The evaluation on MemoryBench's "Put-Block-Back" task, which demands both temporal and spatial memory alongside precise manipulation:
- **T-VLA (Baseline):** Achieved 0% success.
- **T-VLA w/ Scratchpad:** Achieved a 40% success rate, a significant improvement.
- **Relaxed Evaluation ("sim-eval"):** When a relaxed criterion was applied (ground truth action executed if the VLA reached close to the button, acknowledging the challenge of precise manipulation from RGB inputs), the T-VLA w/ Scratchpad achieved 100% success. This indicates that the model successfully performed the necessary temporal and spatial recall for the task steps, with manipulation precision being a separate challenge not directly related to memory. The models used RGB images as input, in contrast to some prior works that used 3D point clouds for enhanced manipulation precision.

#### 4.3. Real-World Task (Pick-Place-Restore)

On the real-world "Pick-Place-Restore" task, involving picking an object, placing it in a bowl, and restoring it to its initial position, thus requiring both spatial and temporal memory:
- **OpenVLA (Baseline without scratchpad):** Achieved 0% success with a sub-task completion rate (CR) of 0.9. Qualitatively, this model often picked the object but failed to sequence the placing and restoring steps correctly due to temporal ambiguity (the initial and final states being visually similar in terms of object position relative to the robot).
- **OpenVLA w/ Scratchpad:** Demonstrated significant improvement, achieving a 65% average success rate and a sub-task completion rate of 2.4 (out of 3 subtasks). This highlights the scratchpad's ability to disambiguate task phases and recall spatial information in a real-world setting.
- **Restoration Accuracy:** The average distance between the initial and restored object position was 10.62cm for the scratchpad-augmented model, compared to 3.2cm for human demonstrations. This disparity was attributed to the limited training data (200 trajectories) available for the real-world experiments.

In summary, the results consistently demonstrate that the language scratchpad mechanism effectively endows VLAs with robust memory capabilities, enabling them to tackle complex, memory-dependent manipulation tasks in both simulated and real-world environments.

### 5. Significance and Potential Impact

This research presents a simple yet effective mechanism for addressing a fundamental limitation of current Vision-Language-Action (VLA) models: their inability to retain and leverage memory over extended task horizons. By introducing a language scratchpad, this work offers a method to impart both spatial and temporal memory, which is crucial for handling non-Markovian, multi-stage, and complex manipulation tasks prevalent in real-world robotics.

The significance of this contribution lies in several areas:

1. **Bridging the Memory Gap in VLAs:** The work directly addresses the "stateless" nature of many contemporary VLAs, which primarily operate on immediate observations. By providing an explicit, language-defined memory, it expands the applicability of VLAs to a broader spectrum of robotic tasks that require sequential reasoning, plan tracking, and recall of past environmental states.
2. **Flexibility and Generalizability:** The language scratchpad mechanism is shown to be highly flexible. It is compatible with different VLA architectures (both transformer-based and recurrent models) and can integrate diverse types of information, from object coordinates to semantic action labels. This flexibility suggests that the approach could be adapted to various robotic platforms and task domains.
3. **Enhanced Task Performance:** The demonstrated significant performance improvements across multiple memory-dependent tasks in diverse environments (ClevrSkills-Mem, MemoryBench, and a real-world pick-and-place task) validate the efficacy of the scratchpad. The ability of a stateless VLA augmented with a scratchpad to match or even surpass the performance of inherently recurrent models in some cases underscores its power.
4. **Support for Recurrent Models:** The finding that even recurrent VLAs benefit from explicit scratchpad augmentation for long-horizon tasks is noteworthy. It suggests that while recurrence provides implicit memory, an explicit, semantically rich scratchpad can complement it, especially when facing challenges like vanishing gradients or limited context windows in training long trajectories.
5. **New Benchmarking Resources:** The introduction of the ClevrSkills-Mem benchmark split directly addresses the scarcity of specialized environments for evaluating long-range memory in robotics. This contribution provides a valuable tool for the research community to develop and test new methods for memory-augmented robotic policies.
6. **Potential for More Autonomous Robots:** By enabling robots to remember object locations, track progress on sub-tasks, and follow complex plans, this research moves towards developing more autonomous and intelligent robotic systems. Such systems would be less prone to repetitive actions or getting stuck in loops, and more capable of handling intricate, multi-step tasks in unstructured and dynamic environments.
7. **Integration with Language Models:** Leveraging the innate language capabilities of VLMs to generate and update the scratchpad aligns with the growing trend of using large language models for reasoning and planning in robotics. This approach is compatible with current state-of-the-art reasoning models, suggesting potential for further integration and more sophisticated cognitive abilities in robots.

In conclusion, this research presents a practical and impactful solution for equipping VLAs with essential memory capabilities, contributing to the development of more robust, intelligent, and versatile robots capable of performing complex, sequential tasks in both simulated and real-world settings.
