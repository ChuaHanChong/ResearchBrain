# Generating Code World Models with Large Language Models Guided by Monte Carlo Tree Search

> [!summary] Summary
> The paper has an LLM write a Python simulator of an environment, called a Code World Model, for model-based reinforcement learning. GIF-MCTS searches over programs with Monte Carlo Tree Search, using generate, improve and fix actions and feedback from unit tests on offline trajectories. It beats baselines on the new 18-environment benchmark, on APPS and on RTFM. The resulting planners are far faster than querying an LLM.

## Problem

- Video and LLM-based world models are slow, costly and unreliable inside a planning loop, so they cannot be called repeatedly for model-based RL planning.
- Existing code-world-model and code-generation methods, such as WorldCoder with Thompson sampling, generate few diverse programs, offer no dedicated bug-fixing action, and were tested only on simple grid-worlds.
- Writing a full world model in code needs exact dynamics and reward logic, long-program self-debugging, and language grounding. No benchmark existed to test this across discrete and continuous environments.

## Method

- **GIF-MCTS**: a ==Monte Carlo Tree Search== over whole programs whose tree actions are ==Generate== new code, ==Improve== a working program, and ==Fix== a buggy one, guided by environment feedback.
- Validation and feedback loop: each candidate is scored by the fraction of ==offline transitions== it predicts correctly, and failed predictions are fed back into the prompt, with ==self-reflection== folded into the generation prompt.
- **Code World Models Benchmark (CWMB)**: 18 Gymnasium environments with discrete and continuous control, each with a text description and about 10 curated trajectories, plus planning with the synthesized ==code model==.

## Results

- On the APPS competition split, GIF-MCTS with Llama 3 70B reaches **28.3%** strict accuracy at pass@20. That beats WorldCoder at **25.1%**, zero-shot CoT at **23.2%** and Parsel at **25.5%**.
- On CWMB with Llama 3 70B, discrete-action normalized return is **0.76** versus **0.60** for WorldCoder. GPT-4 Turbo with 10 calls scores **0.81** versus **0.79** discrete and **0.26** versus **0.20** continuous.
- Ablation removing Fix drops discrete return from **0.83** to **0.55**. Removing Generate or Improve also hurts. Code models run **four to seven orders of magnitude** faster than querying an LLM.

## Takeaways

> [!tip] Key Insights
> - Writing world models as executable code gives fast, interpretable, exact simulators. Once the code is accurate, planning matches an oracle planner with far lower inference cost.
> - Tree search over whole programs, with separate actions for generating, refining and repairing, works better than refining a single program, because it keeps candidates diverse and targets bugs directly.
> - Continuous-control environments stay hard, with accuracy around 0.35 to 0.40. Deterministic, fully observed dynamics are assumed, and text descriptions plus small offline data are enough for discrete tasks.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

This research sits at the intersection of several rapidly evolving fields: Reinforcement Learning (RL), Large Language Models (LLMs), and program synthesis.

**World Models in Reinforcement Learning**: The ability to accurately model an environment (i.e., predict future states and rewards given actions) is fundamental for goal-oriented intelligent agents, particularly in model-based RL. World models enable planning, improve sample efficiency, and facilitate understanding of environment mechanics. Traditional world models often rely on specialized architectures trained on observed data, which can be data-hungry and lack generalizability.

**Leveraging LLMs for World Modeling**: Large Language Models have demonstrated impressive capabilities in language understanding, reasoning, and instruction following due to their vast pre-training on internet-scale data. This has opened new avenues for their application in RL, including directly using LLMs as world models. However, directly querying LLMs for every step in a planning loop is prohibitively slow, computationally expensive, and their outputs can be unreliable or restricted to textual formats, limiting their applicability in diverse RL environments with continuous state/action spaces. Multi-modal LLMs (e.g., text-to-video models) offer high fidelity but suffer from similar inference speed issues.

**Code Generation and Programmatic RL**: Separately, the field of code generation has seen significant advancements with LLMs, moving from simple code completion to generating complex programs from natural language descriptions. Programmatic RL, where policies or world models are represented as executable code, offers benefits such as interpretability, precision, and efficiency, making them potentially safer and more reliable for critical applications. Previous work in programmatic RL often involved custom Domain Specific Languages (DSLs) or traditional program synthesis methods, which can be less flexible or require expert-designed grammars. More recent efforts have explored LLMs for generating Python policies or skill libraries.

**The Contribution of Code World Models**: This paper bridges these areas by proposing "Code World Models" (CWMs) – world models generated *as Python code* by an LLM. This approach aims to combine the strengths of LLMs (understanding complex instructions, reasoning) with the inherent advantages of code (precision, reliability, speed, interpretability). Instead of an LLM directly predicting future states, it *writes a program* that can then efficiently and deterministically simulate future states. This sidesteps the inference cost and reliability issues of direct LLM prediction while retaining LLM's high-level reasoning.

**Relation to Concurrent Work**: The authors acknowledge the contemporaneous proposal of "WorldCoder" (Tang et al., 2024b) which also uses LLMs to generate Python-based world models. However, they highlight key technical distinctions: their method, GIF-MCTS, scales to more complex world models, considers a broader selection of environments, learns from offline data, and handles continuous state/action spaces, distinguishing it from WorldCoder's focus on online interactions and specific grid-world tasks. The rigorous benchmarking of their code generation method also sets this work apart.

**MCTS for Code Generation**: The proposed GIF-MCTS method builds on existing MCTS-based code generation strategies (e.g., LATS by Zhou et al., 2023, or Zhang et al., 2023). However, it introduces novel framing of MCTS nodes and actions specifically tailored for long-form code generation in the presence of unit tests, with specialized action types (Generate, Improve, Fix) and heuristics for exploration-exploitation balance, making it particularly effective for the CWM problem.

### 2. Key Objectives and Motivation

The central motivation for this work stems from the limitations of existing approaches to world modeling in RL, particularly when integrating Large Language Models.

**Limitations of Direct LLM-based World Models**: The authors identify that while LLMs offer impressive reasoning and language understanding, their direct use as world models for planning in RL is problematic. They are:
- **Slow for inference**: Repeated calls within a planning loop are computationally expensive and time-consuming.
- **Costly**: High inference costs for powerful LLMs make them impractical for many RL applications.
- **Unreliable**: LLM outputs can still contain factual errors or "hallucinations," which are detrimental for precise environment simulation.
- **Restricted**: Often limited to textual inputs/outputs, hindering their applicability in diverse RL environments with continuous or complex observation/action spaces.

**Limitations of Traditional Language-Conditioned RL**: Conversely, language-conditioned model-based RL agents, while fast at planning, typically use specialized architectures that possess poor language understanding and generalization capabilities compared to LLMs. They struggle to leverage additional descriptive information effectively.

**The Proposed Solution and its Benefits**: To overcome these limitations, the paper proposes to **model the world with code**, specifically Python code, generated by an LLM. The core hypothesis is that code, unlike direct LLM predictions, is:
- **Precise and Reliable**: Code executes deterministically according to its logic.
- **Fast**: Once generated, executing Python code for a step is orders of magnitude faster than querying an LLM.
- **Interpretable**: Python code provides a transparent, human-readable representation of the environment dynamics, crucial for understanding and debugging.

**Key Objectives**:
1. **Introduce and validate the Code World Models (CWMs) framework**: Establish a novel paradigm where LLMs generate executable Python code to serve as world models for model-based RL.
2. **Develop an effective code generation strategy**: Create a robust method, GIF-MCTS, that can guide LLMs to iteratively generate, refine, and debug complex Python programs for environment dynamics and reward functions.
3. **Establish a comprehensive benchmark**: Create the "Code World Models Benchmark" (CWMB) to evaluate the effectiveness of CWM generation and planning across a diverse set of RL environments, including discrete and continuous action/observation spaces.
4. **Demonstrate practical utility for RL planning**: Show that CWMs synthesized with GIF-MCTS can be successfully employed by planning algorithms, leading to model-based RL agents with improved sample efficiency and inference speed.
5. **Address challenges in code generation**: Tackle the complexities of instruction understanding, exact code generation, and self-debugging of long programs using feedback from unit tests and environment trajectories.

### 3. Methodology and Approach

The methodology revolves around the concept of Code World Models (CWMs) and a novel Monte Carlo Tree Search (MCTS)-based code generation strategy called GIF-MCTS, applied within an offline RL setting.

#### 3.1. Code World Models (CWMs) Framework

- **Problem Formulation**: The task is to synthesize a Python `Environment` class that accurately implements a deterministic transition function `s' = f(s, a)` and a reward function `R(s, a, s')`.
- **Assumptions**:
 1. **Deterministic and Fully Observable Environments**: The method currently assumes environments where the next state is uniquely determined by the current state and action, and all relevant information is observable.
 2. **Natural Language Description**: A detailed natural language description of the environment, sufficient to infer observation space, transition logic, and reward function, is provided. This mimics a human learning a task from a tutorial.
- **Offline RL Setting**: The approach operates in an offline RL scenario, meaning a dataset `D` of `n` single-timestep transitions `{(s, a, r, s', d)}` is available. This dataset is *not* for training the world model directly but for **validating** the correctness of the generated code, acting as unit tests. The authors emphasize that this assumption can be relaxed for online RL.
- **CWM Accuracy Metric**: The accuracy `A` of a CWM is defined as the fraction of correctly predicted transitions from the dataset `D`, considering next state, reward, and done signals uniformly.

#### 3.2. Code World Models Benchmark (CWMB)

To thoroughly evaluate CWMs and the generation method, the authors introduce a new benchmark:
- **Environments**: 18 diverse RL environments from classical control, PyGame-based physics, and MuJoCo tasks, featuring both continuous and discrete action/observation spaces (e.g., CartPole-v1, HalfCheetah-v4, Humanoid-v4, Taxi-v3).
- **Descriptions**: Each environment is paired with a natural language description derived from Gymnasium documentation, cleaned to remove irrelevant details.
- **Datasets**: For each environment, a training dataset `D` of past trajectories is collected. This dataset is curated to include both low-scoring and relatively high-scoring behaviors (typically 5 random + 5 suboptimal trajectories), aiming for low annotation effort. Each transition acts as an input-output sample for validating the generated CWM.

#### 3.3. Generate, Improve and Fix with Monte Carlo Tree Search (GIF-MCTS)

GIF-MCTS is the core code generation strategy designed to leverage LLMs for synthesizing CWMs by iteratively refining candidate programs based on feedback.

- **MCTS Framework**: It adapts the standard MCTS algorithm (selection, expansion, evaluation, backpropagation) to the domain of long-form code generation.
- **Node and Edge Formulation**:
 - **Nodes**: Represent programs. A node's "state" stores a partial program in blocks of `L` lines (e.g., L=2), while a "rollout" is the remaining part of the program, used for evaluation. This differs from prior work that stored full programs or single tokens.
 - **Edges/Actions**: Correspond to prompting the LLM to modify the program.
- **Three Specialized Action Types**:
 1. **Generate new lines**: Explores divergent paths by asking the LLM to generate a full program from the current node's state (partial program). This leverages the LLM's stochastic sampling to explore the solution space.
 2. **Improve predictions**: When a CWM produces incorrect predictions on specific test cases, this action prompts the LLM with the full program, the incorrect input-output example, and the ground-truth output. The LLM is guided to perform Chain-of-Thought (CoT) reasoning to explain the error, locate the faulty logic, suggest a fix, and then produce the corrected code.
 3. **Fix bugs**: Addresses programs that fail due to syntax or runtime errors. The LLM is given the buggy code and the error message, then prompted to explain the error, suggest a fix, and provide the corrected code, again using CoT.
- **Modified UCT Formula and Heuristics**:
 - The standard Upper Confidence Bound for Trees (UCT) formula is modified to balance exploration of new actions/nodes with exploitation of promising ones, including a term `n_a=a_i` to prevent horizontal saturation of a single action type.
 - **Value Estimation for Unexplored Nodes**: A simple linear model, trained during search, estimates the value of unvisited nodes based on global and local averages for each action type.
 - **Value Estimation for Buggy Nodes**: Buggy nodes are assigned a temporary high value (e.g., 0.99) to encourage the "fix" action, which linearly decreases over a set number of attempts (`f=3`). If `f` attempts fail, the value becomes 0, discouraging further exploration. This ensures bug-ridden branches are not prematurely discarded but also not endlessly pursued.

#### 3.4. Planning with CWMs

- After a CWM is synthesized and validated, it replaces the true environment model for planning.
- **Planning Algorithms**:
 - **Monte Carlo Tree Search (MCTS)**: Used for environments with discrete action spaces.
 - **Cross-Entropy Method (CEM)**: Used for environments with continuous action spaces.
- **Normalized Return Metric**: `R(CWM) = (R(π_CWM) - R(π_rand)) / (R(π_true) - R(π_rand))`. This metric measures how close the CWM-based planner's performance is to an oracle planner (with access to the true environment) relative to a random policy.

### 4. Main Findings and Results

The research provides strong empirical evidence for the effectiveness of GIF-MCTS in generating Code World Models and their utility in model-based reinforcement learning.

#### 4.1. APPS Benchmark (General Code Synthesis)

- GIF-MCTS, using Llama 3 70B, achieved a strict accuracy of **28.3%** on the challenging Competition split (pass@20), outperforming strong baselines like Zero-shot CoT (23.2%) and their re-implementation of WorldCoder (25.1%). This demonstrates that GIF-MCTS is a state-of-the-art method for general code synthesis, not just specific to CWMs.
- The method showed competitive sample efficiency, achieving superior accuracy while evaluating significantly fewer solutions compared to methods like Parsel.

#### 4.2. Code World Models Benchmark (CWMB)

- **Superior Performance**: GIF-MCTS consistently outperformed WorldCoder across all environment splits (discrete/continuous action spaces) and backbone LLMs (Llama 3 70B, GPT-4 Turbo).
 - For Llama 3 70B, GIF-MCTS achieved an average accuracy of 0.84 and normalized return (R) of 0.76 on discrete action spaces, and 0.35 accuracy / 0.22 R on continuous action spaces.
 - For GPT-4 Turbo, GIF-MCTS showed even better performance: 0.91 accuracy / 0.81 R on discrete, and 0.40 accuracy / 0.26 R on continuous. GPT-4 with GIF-MCTS was able to generate models for the hardest environments (Humanoid-v4, HumanoidStandup-v4), which Llama 3 struggled with.
- **Successful Planning**: The CWMs synthesized with GIF-MCTS were successfully used for planning, demonstrating that the generated code is sufficiently accurate to guide agents effectively. When CWMs were highly accurate, they could match the performance of an oracle planner.

#### 4.3. Read to Fight Monsters (RTFM)

- On a simplified version of the RTFM grid-world, GIF-MCTS again significantly surpassed WorldCoder in accuracy.
- Notably, GPT-4 with GIF-MCTS and a higher budget (50 LLM calls) achieved **1.00 accuracy and 1.00 normalized return**, meaning it generated a perfect CWM that allowed the agent to achieve optimal performance. This highlights the potential for accurate CWMs to enable optimal planning and provides empirical evidence against data contamination concerns, as this modified environment lacked online solutions.

#### 4.4. Ablation Study

- The ablation study confirmed the importance of all three action types (Generate, Improve, Fix). Removing any one action led to a drop in performance, particularly for "Fix" actions and in harder continuous environments. This indicates that the iterative refinement and debugging capabilities provided by these distinct actions are crucial for robust code generation.

#### 4.5. Efficiency and Interpretability

- **Inference Speed**: CWMs demonstrated exceptional inference speed, being **four to seven orders of magnitude faster** than directly querying an LLM (GPT-4 Turbo) for environment predictions. This is a critical advantage for real-time planning.
- **Sample Efficiency**: Generating a CWM required very little interaction with the environment (small, curated datasets of ~10 trajectories for validation), offering significantly higher sample efficiency compared to traditional model-based or offline RL methods that often require vast amounts of data.
- **Interpretability**: As CWMs are executable Python code, they offer inherent interpretability, allowing human experts to inspect and understand the environment dynamics, a key advantage for safety-critical applications.

#### 4.6. Limitations Observed

- **Accuracy-Return Gap**: CWM accuracy often exceeded normalized return, especially when the model failed to predict rare terminal states correctly. This indicates that flawless CWMs are essential for optimal planning, and slight imperfections can significantly impact an agent's performance.
- **Comparison with Offline RL (CQL)**: While CWMs performed well on discrete tasks with limited data, a SOTA offline RL method (CQL) sometimes outperformed CWMs on complex continuous physics tasks, possibly due to CWMs struggling to model such environments purely with code without external simulators, and CQL being better at extracting signal from data in some contexts, albeit overfitting with scarce data.

### 5. Significance and Potential Impact

This research marks a significant step forward in integrating the capabilities of Large Language Models with the efficiency and interpretability requirements of Reinforcement Learning.

- **Paradigm Shift in World Modeling**: The introduction of "Code World Models" offers a compelling alternative to direct LLM-based world models or purely data-driven approaches. It effectively leverages LLM's reasoning and language understanding to *program* the world, rather than just *predicting* it, yielding models that are precise, fast, and transparent.
- **Advancement in Code Synthesis**: GIF-MCTS is a novel and powerful code generation strategy. Its ability to iteratively generate, improve, and fix long-form code, guided by unit tests and MCTS, pushes the state of the art in programming by LLMs, particularly for complex, multi-component problems like environment modeling.
- **Highly Efficient and Sample-Efficient RL Agents**: By decoupling the slow and costly LLM generation phase from the fast inference phase (code execution), CWMs enable model-based RL agents with unparalleled inference speed. Furthermore, using trajectories solely for *validation* rather than extensive training allows for remarkably high sample efficiency, making RL applicable in data-scarce scenarios.
- **Enhanced Interpretability and Safety**: The generated world models are human-readable Python code, offering a high degree of interpretability. This transparency is invaluable for debugging, auditing, and ensuring safety in critical applications where opaque deep learning models might be unacceptable. It allows human experts to vet the generated logic.
- **Broader Applicability of Model-Based RL**: By simplifying the process of obtaining accurate world models, this framework could democratize model-based RL, making it more accessible for a wider range of tasks and environments where a good natural language description is available.
- **Foundation for Future Research**: The paper opens numerous avenues for future work, including:
 - Extending CWMs to handle stochastic and partially observable environments.
 - Integrating image-to-text models to create CWMs from visual observations.
 - Enabling LLMs to generate code that leverages external tools and physics simulators for more complex tasks (e.g., MuJoCo environments).
 - Developing methods for self-generating unit tests to broaden GIF-MCTS applicability beyond environments with pre-defined validation data.
 - Exploring techniques to bridge the accuracy-return gap, potentially by focusing on critical error types or combining multiple CWMs.

In conclusion, this work presents a robust framework and method for harnessing LLMs to create highly efficient, interpretable, and sample-efficient world models in the form of code. This innovation has the potential to significantly impact the development of more capable, understandable, and trustworthy AI agents in reinforcement learning.
