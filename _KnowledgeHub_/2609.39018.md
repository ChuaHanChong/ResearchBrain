# Make Code as Policy Great Again: Frontier Agents Write, Call, and Evolve Robot Tools

> [!summary] Summary
> URAI (Universal Robot-Agent Interface) brings back code as policy. A programming agent writes, validates and revises reusable and task-specific robot tools. A frozen execution agent picks and fills in one tool per decision, and each call runs a complete timed multi-phase motion before the agent decides again from feedback. Over five RoboDojo tasks and four frontier agents, success rises from 18.0% to 53.0% over direct fingertip control.

## Problem

- Frontier models used as step-by-step policies choose every end-effector target, so each observation-reasoning-action cycle adds waiting time and tokens, which makes manipulation slow and costly.
- Code as Policies hands later decisions to a program written in advance, which handles only the conditions its code checks and removes model-level judgment between motions.
- VLA and world action model policies generalize poorly to new layouts, keeping a median of only 12-16% of their success when RoboDojo scene layouts are randomized.

## Method

- ==Programming/execution agent split==: a ==programming agent== writes tools from intent and execution feedback, while a frozen ==execution agent== selects and parameterizes one tool per decision from current observations.
- ==Timed motion representation==: each call specifies a metric path, an ==SO(3) orientation==, a ==speed profile== and progress-tied gripper events, which the backend grounds from depth, checks and executes locally at 50 Hz.
- ==Weight-free tool evolution==: the tool collection, tool code and execution strategy are revised across episodes, unit-tested and frozen, with one ==tool contract== shared by a human GUI and an agent API in **URAI**.

## Results

- Over **five** RoboDojo tasks, **four** frozen agents go from **18.0%** to **53.0%** success through URAI; Claude Opus 5.5 reaches **60.0%**, close to the best learned leaderboard policy at **58.1%**.
- Deciding after each call beats a program written in advance over the same tools, **28/50** against **12/50** episodes; three agents also finish **1.3-1.5x** faster with **1.5-1.7x** fewer tokens.
- On AgileX dual-arm hardware, tic-tac-toe finishes **2.7x** faster than GPT-Policy at the same **3/3** success, and block-into-bowl runs **2.4x** faster with **4.7x** fewer output tokens.

## Takeaways

> [!tip] Key Insights
> - How much motion one model decision covers is a primary design lever: bundling multi-phase motions into one call reduces decisions per episode instead of making each decision cheaper.
> - Keeping the model in the loop between coarse tool calls adds value beyond the tool library itself; a program written in advance over identical tools loses much of the gain.
> - Coarser calls do not guarantee savings: an agent that over-observes and probes can spend more time deciding, so efficiency also depends on how the execution agent behaves.

## Detailed Report

### 1. Overview

Robot manipulation by a vision-language agent can require a fresh model decision for each small movement. That repeated observation–reasoning–action cycle is the practical bottleneck. It adds waiting and generated output, and it asks the model to manage motion details. An alternative is to let one tool run a multi-phase motion, return feedback, and let the model decide the next call. A pick-and-place tool, for example, can bundle approach, grasp, transfer, placement, and retreat into one call. This is the approach URAI takes. The model stays in the decision loop between motions, so the robot is not acting autonomously from a generated script.

### 2. Where the decision happens

URAI splits the work between two agents that act at different times. Between episodes, a programming agent proposes tool-collection, tool-code, or execution-strategy revisions from task intent and development feedback. Candidates are validated and frozen for evaluation, and foundation-model weights remain fixed.

Within an episode, the execution agent uses current observations and execution history to select and parameterize one available tool. The backend grounds the request, checks the planned motion, and executes its timed path locally. After completion or interruption, the agent receives feedback and chooses again.

Native fingertip control already uses inverse kinematics and local control, so URAI's contribution lies elsewhere: the model does not have to reason separately about every motion phase.

This also differs from earlier code-based systems. [Code as Policies](https://doi.org/10.1109/ICRA48891.2023.10160591) showed that a language model can generate robot programs with perception calls and feedback logic. At run time, however, the generated code decides what happens next. [[2603.22435|CaP-X]] adds multi-turn interaction and structured execution feedback. URAI's emphasis is a different handoff boundary: each call runs one complete timed tool motion, and then the frozen execution agent decides again.

### 3. Two decisive comparisons

The sharper test holds the tools constant. In the program condition, an agent has a one-time planning session and then writes a program that runs without the model. That program has the same tools, observations, depth probes, and ability to branch on tool returns.

For GPT-6 Astra and Claude Opus 5.5, an agent that chooses the next call after each execution succeeds in 28/50 episodes (56%). The advance-written program succeeds in 12/50 (24%), with 17 versus 1 discordant episodes (McNemar p = 1.4 × 10⁻⁴). Without Swap Blocks, the results are 19/40 versus 11/40 (8 versus 0, p = 0.0078).

This supports the authors' view that continuing to decide between tool calls contributes beyond the tools themselves. It does not show that this is the only source of URAI's gains. The comparison covers two agents and seeds 0–4, and no prompt- or memory-only revision control was run.

The broader comparison is against native fingertip control. It spans five RoboDojo tasks: pour liquid into a cup, pour balls into a vase, fold clothes, swap blocks, and stack blocks. Across these tasks, the four frozen execution agents average 53.0% success through URAI versus 18.0% under native control. Average success is the equally weighted mean of the five task success rates. Each agent-task condition had five episodes.

The paired test finds 40 cases where only URAI succeeds and 5 where only native control succeeds (p = 7.9 × 10⁻⁸). Without Swap Blocks, the averages are 42.5% versus 22.5% (p = 0.0025).

This aggregate is not a pure test of call granularity. Swap Blocks accounts for the largest gap, and its URAI tool bundles a task-level place-on-pad procedure with button pressing, unlike native fingertip commands.

Efficiency gains are also conditional. Three of four agents use less execution-phase time and output. DeepSeek-V4-Flash is the exception: its time falls about 5% and its output tokens about 9%.

### 4. Keeping the model in the loop

URAI moves repeated motion details into local tools, and the agent still makes the next task decision after each motion. The same-tools program comparison is the clearest evidence that this boundary matters. The main limits are scope and cost accounting. The measurements cover five simulated tasks under this tool collection, and tool-authoring and author-steering costs were not measured.
