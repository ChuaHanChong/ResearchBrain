# CommitFlow: Semantic Commitment Verification and Local Correction for Long-Horizon Robot Manipulation VLA Execution

> [!summary] Summary
> CommitFlow is a closed-loop execution wrapper for frozen VLA policies that verifies stage-level physical preconditions (semantic commitments) before long-horizon tasks advance. A monitor holds dependent actions when conditions are unmet, a learned low-rank residual head corrects the base action locally, and a calibration step picks the smallest sufficient correction gain. On RoboTwin 2.0 it lifts π0.5 from 53.2% to 75.9% mean success.

## Problem

- Long-horizon VLA policies advance to the next stage before the required physical effect is established, so local deviations propagate and cause downstream task failure.
- Existing failure detectors and recovery methods intervene only after clear failure signs emerge, facing a harder failure state that replanning or retries must untangle.
- Subtask backtracking, skill resets, and action-quality steering either roll back still-valid progress like established grasps or never check whether stage-transition prerequisites actually hold.

## Method

- **Semantic Commitment Monitor (SCM)**: a ==GRU== state estimator over RGB-D features, metric relations and joint states verifies stage conditions, assigning Keep/Correct/Hold permissions per action-chunk element to withhold dependent actions until re-verified.
- **BoundaryFlow**: a trainable residual head conditioned on state and the frozen base chunk, predicting tanh-bounded coefficients on a rank-12 ==SVD== basis of expert-minus-base residuals, merged into ==flow sampling== via velocity remapping.
- **Relation and Gain Calibration (RGC)**: fits per-stage success reference regions with 95th-percentile coverage from successful executions, then selects the smallest correction gain whose ==forward-kinematics==-predicted endpoint lands inside the region margin.

## Results

- On ten RoboTwin 2.0 tasks, π0.5+CommitFlow reaches **75.9%** mean success versus **53.2%** base, **58.7%** TACO and **61.5%** CAPS; Handover Block rises from **24%** to **66%**.
- Across 11 tasks, gains hold for three frozen base policies: π0 **36.5%** to **52.9%**, π0.5 **49.4%** to **72.8%**, LingBot-VLA **81.4%** to **86.6%**, though LingBot drops on Object Scale (**96%** to **93%**).
- With base re-querying held fixed, BoundaryFlow correction beats IK and no correction (**80.0%** vs **69.0%** vs **66.8%**, six tasks); real-robot eraser placement rises **50%** to **63%**, bowl stacking **40%** to **50%**.

## Takeaways

> [!tip] Key Insights
> - Gate stage transitions on verified physical preconditions from fresh observations; an action command alone does not prove its effect, so pre-transition checks beat post-failure recovery.
> - Pure geometric fixes like IK can hurt: corrections must stay compatible with what the frozen policy does next, so condition residuals on the base action itself.
> - Local correction cannot add skills the base policy lacks; successful local grasp recovery often fails later stages, and larger correction gains cause overshoot, so minimal intervention matters.

## Detailed Report

### 1. Overview

In a real-robot bowl-stacking task, the base policy releases a bowl while it is still offset, and the bowl strikes the target rim. The robot has moved on to the next step before the current one has produced the physical state that step requires. An instruction or action command is not proof that the object is actually grasped, aligned, or placed. CommitFlow checks the physical condition before letting the next dependent action proceed. With CommitFlow, the bowl's position is corrected before release and it enters the target.

In eraser placement (right), a misaligned gripper leads to a failed grasp; CommitFlow corrects the gripper pose, grasps, and places the eraser in the container.

### 2. A task step needs a physical receipt

A vision-language-action (VLA) model is a policy that maps visual observations, language instructions, and robot state to robot actions. Tasks such as grasp, lift, hand over, or release happen in sequence, and a policy may continue even when the required physical result has not occurred. An early transition can then propagate a local deviation. CommitFlow calls a physical condition that a stage must establish or maintain a *semantic commitment*. In a handover, for example, the sender retains the object while the receiver aligns, and release should wait for a verified receiver grasp.

The mechanism works in four steps:

- The Semantic Commitment Monitor (SCM) checks the active stage's required conditions against visual and state evidence and history. It can KEEP unaffected motion or CORRECT a locally adjustable action. It can also HOLD a critical action and its dependents when a required condition is unsupported or violated.
- BoundaryFlow generates a local correction conditioned on the current state and the frozen base action.
- Relation and Gain Calibration (RGC) checks candidate correction strengths against stage reference ranges and action constraints, then chooses the smallest feasible strength. If no strength is feasible, the affected actions stay held while evidence or correction is refreshed.
- After execution, fresh observations let SCM re-check the condition before held actions resume.

The base policy remains frozen throughout.

### 3. Evidence beyond retrying

On the RoboTwin 2.0 simulation benchmark, each task is evaluated over 100 randomized trials, and the metric is success rate. The reported average covers the ten common tasks and excludes Hang Mug. On this average, CommitFlow reaches 75.9%, compared with 53.2% for frozen π0.5, a difference of 22.7 percentage points. The other comparisons are 58.7% for π0.5+TACO and 61.5% for π0.5+CAPS.

CAPS uses adaptive inference-time MCMC search to refine candidate trajectories when uncertainty is high. CommitFlow instead asks whether the stage's physical prerequisites have been met, so the two methods are complementary ([[2605.09537|CAPS, “Drift Is a Sampling Error”]]).

The gains are not uniform. In the separate cross-policy results, LingBot-VLA falls from 96% to 93% on Object Scale and stays at 83% on Place A2B Left.

A six-task ablation tests whether simply querying the base policy again explains the gains. Every variant re-queries the base policy. The six-task mean is 66.8% for Fresh Base, 69.0% for Fresh + IK (inverse kinematics), and 80.0% for Fresh + Ours. This supports an advantage over these alternatives under that setup. It does not isolate every component. The authors suggest that IK's drop on Object Cabinet (61% to 57%) reflects a limitation of geometric alignment alone, which may not remain compatible with subsequent base-policy actions.

### 4. What the approach changes

CommitFlow treats a physical prerequisite as something to verify rather than infer from an issued action. Local correction restores that condition while keeping valid progress. Fresh evidence, not the correction command itself, then authorizes the next dependent action.

The approach depends on RGB-D perception, temporal state estimation, and task-specific definitions of events and preconditions. Occlusion, bad depth, estimation errors, or timing mismatches can undermine verification. The authors also report that corrections cannot supply skills absent from the base policy.
