# AIOS: LLM Agent Operating System

> [!summary] Summary
> AIOS is an operating-system-style architecture for serving LLM agents. It separates agent applications from an AIOS kernel that turns agent queries into system calls. A central scheduler dispatches them to LLM core, context, memory, storage, tool and access managers. An SDK adapts existing agent frameworks. AIOS keeps or improves benchmark accuracy and gives up to 2.1x higher throughput.

## Problem

- Agent frameworks give agents direct, unrestricted access to LLMs and tools, so resources are used inefficiently and unsafely, and no isolation or access control exists.
- Without scheduling, concurrent agents monopolize the LLM and flood it with requests while other agents wait, which limits overall system efficiency.
- Existing frameworks handle concurrent LLM calls by trial and error: prompts load into GPU memory until CUDA limits raise exceptions, forcing deallocation and retries that hurt throughput.

## Method

- A ==three-layer design== (application, kernel, hardware) puts agent queries through an **AIOS SDK**, with the ==AIOS kernel== decomposing them into thread-bound ==system calls== for LLM, memory, storage and tool operations.
- A ==centralized scheduler== holds all module queues and supports ==FIFO== and ==Round Robin==. LLM instances are wrapped as ==LLM cores==, and a ==context manager== snapshots and restores generation state (text-based or logits-based) for interruption.
- Memory, storage, tool and access managers add ==LRU-K eviction== from RAM to disk at an 80% limit, and tool-conflict hashmaps. ==Privilege-group access control== and user confirmation for destructive actions complete them, alongside SDK adapters for existing frameworks.

## Results

- On HumanEval, MINT, GAIA and SWE-Bench-Lite, AIOS holds or slightly raises success rates across **five** frameworks. ReAct on GAIA rises from **5.5%** to **7.3%** and on HumanEval from **48.8%** to **50.6%**.
- With Llama-3.1-8b and Mistral-7b on HumanEval, AIOS raises throughput across all five frameworks, up to **2.1x** for Reflexion agents on Llama-3.1-8b, and also reduces average agent waiting time.
- Scaling from **250** to **2000** concurrent agents, AIOS keeps execution time and waiting time roughly linear in agent count. The gap over the no-AIOS baseline widens as agent count grows.

## Takeaways

> [!tip] Key Insights
> - Treating LLM agents as processes and the LLM as a shared core lets classic OS mechanisms (scheduling, context switching, memory paging, access control) carry over to agent serving.
> - Centralized scheduling avoids wasteful trial-and-error GPU loading. Systems-level resource management can raise throughput and lower latency with no change to agent logic.
> - Kernel-level services can improve accuracy as well as speed, since parameter validation and conflict resolution helped tool-calling tasks. Framework adapters make such gains usable without rewriting agents.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

The development of LLM-based intelligent agents has seen rapid growth, building upon decades of research in autonomous agents and leveraging the unprecedented capabilities of modern Large Language Models (LLMs). Contemporary LLMs have demonstrated remarkable prowess in instruction understanding, reasoning, problem-solving, and interaction with users and environments, enabling agents to tackle complex tasks from virtual assistance to sophisticated problem-solving.

However, the proliferation of LLM agents has exposed significant infrastructural limitations within existing agent frameworks (e.g., Autogen, Langchain). These frameworks often grant agents direct, unrestricted access to critical system resources such as LLM inference capabilities and external tools. This direct access leads to several challenges:
1. **Inefficient Resource Allocation:** Agents can monopolize resources, leading to situations like an LLM being flooded with requests while other agents are stalled.
2. **Lack of Concurrency and Scheduling:** The absence of proper scheduling mechanisms hinders concurrent processing, resulting in suboptimal system efficiency. For instance, current frameworks often resort to a trial-and-error approach for LLM calls, repeatedly attempting to load prompts into GPU memory until exceptions are hit, requiring deallocation and retries—a highly inefficient process under concurrent loads.
3. **Vulnerabilities and Security Risks:** Direct access to system-level resources can introduce security vulnerabilities and compromise resource optimization.

AIOS addresses these critical issues by drawing a profound analogy to traditional operating systems. As detailed in the "Related Work" section, operating systems evolved from rudimentary batch processing to sophisticated multi-tasking systems with specialized components for process scheduling, memory management, and file system operations. AIOS posits that AI models, particularly LLMs, are undergoing a similar migration from being mere applications to becoming foundational system-level components. This work positions itself as a foundational step in this paradigm shift, envisioning an "LLM-based AI Agent Operating System" that provides standardized services and robust resource management for LLM agents.

By introducing a dedicated kernel and SDK for LLM agents, AIOS aims to abstract away the complexities of resource management, scheduling, and security, much like a traditional OS abstracts hardware. This approach moves beyond the scope of individual agent design or multi-agent communication protocols to tackle the underlying system-level infrastructure. It fills a crucial gap by providing a systematic, efficient, and secure environment for deploying and managing complex LLM-based agent ecosystems, thus enabling the scalable and reliable application of these agents in real-world scenarios.

### 2. Key Objectives and Motivation

The primary motivation behind AIOS stems from the pressing challenges in deploying and managing LLM-based intelligent agents, particularly concerning resource management, efficiency, and security in concurrent environments. The authors identify several critical pain points with existing agent frameworks:

- **Unrestricted Resource Access:** Current designs allow agents unmediated access to LLM and tool resources. This lack of control can lead to suboptimal or even harmful allocation and utilization, compromising system stability and performance.
- **Inefficient Concurrent Processing:** The absence of sophisticated scheduling and resource management mechanisms severely hampers concurrent task execution. This is particularly problematic in scenarios where multiple agents compete for limited LLM resources, leading to inefficient "trial-and-error" GPU memory management and significant degradation in throughput.
- **Lack of Isolation and Vulnerabilities:** Direct access to system resources by agents introduces potential security vulnerabilities and makes it difficult to ensure systematic resource management and safety.

To mitigate these limitations, the key objectives of the AIOS project are:

1. **Develop a Novel Agent-Serving Architecture:** Introduce AIOS as a layered architecture that clearly separates agent applications from the core resources (LLMs, tools) into distinct application and kernel layers, promoting systematic management and optimization.
2. **Design and Implement an AIOS Kernel:** Create a robust kernel to encapsulate fundamental resource management abstractions, including scheduling, context management, memory management, storage management, and access control. This kernel is designed to decompose agent queries into parallelizable execution units (syscalls).
3. **Develop a Comprehensive AIOS SDK:** Provide a higher-level abstraction via an SDK with a suite of APIs, allowing developers to focus on agent application logic without being burdened by the intricate details of kernel functionalities and resource management.
4. **Enhance System Efficiency and Scalability:** Significantly improve the execution speed, throughput, and responsiveness of serving LLM agents, especially under concurrent workloads, while ensuring the system scales effectively with an increasing number of agents.
5. **Maintain or Enhance Agent Performance:** Ensure that the introduction of AIOS does not degrade, and ideally improves, the performance of agents on standard benchmarks, particularly in tasks involving tool calling and complex reasoning.

In essence, the motivation is to build a foundational operating system layer for LLM agents that can handle the complexity of resource management, scheduling, and security, transforming LLM agents from isolated applications into a cohesive, efficiently managed ecosystem.

### 3. Methodology and Approach

AIOS introduces a novel, layered architecture designed to bring operating system principles to the management and deployment of LLM-based agents. The methodology centers on isolating agent applications from core resources and services through a dedicated kernel and providing a developer-friendly SDK.

The AIOS architecture is structured into three distinct layers:
1. **Application Layer:** This layer houses various agent applications (e.g., Travel Agent, Coding Agent) that interact with the AIOS kernel through the AIOS SDK. The SDK supports both native agent development and the adaptation of agents built using popular existing frameworks like ReAct, Reflexion, Autogen, Open-Interpreter, and MetaGPT, abstracting away kernel complexities.
2. **Kernel Layer:** This is the core innovation, integrating a traditional OS kernel (for non-LLM tasks) with an **AIOS kernel**. The AIOS kernel is a collection of specialized modules designed to manage LLM-specific resources and services.
3. **Hardware Layer:** Consists of physical computing resources (CPU, GPU, memory, disk), which the AIOS kernel accesses indirectly via the traditional OS kernel.

The design and implementation of the **AIOS Kernel** are central to the methodology:
- **Query Decomposition and Syscalls:** Agent queries are first decomposed into granular, thread-bound "AIOS syscalls." These syscalls represent fundamental operations (LLM processing, memory access, storage operations, tool usage) and are dispatched by a central scheduler for concurrent processing.
- **Modular Kernel Components:**
 - **LLM Core:** Encapsulates diverse LLM instances (local or cloud, different inference frameworks) as standardized "cores," similar to CPU cores. It provides a unified interface for LLM inference and supports structured output and function calling.
 - **Scheduler:** A centralized module that manages queues for all types of syscalls. It dispatches calls to appropriate processing modules and implements classic scheduling algorithms like First-In-First-Out (FIFO) and Round Robin (RR) to manage concurrent requests efficiently.
 - **Context Manager:** Crucially addresses LLM inference bottlenecks by enabling context interruption and resumption. It supports two snapshot/restoration methods: text-based (for closed-source LLMs) and a more granular logits-based method (for open-source LLMs) that preserves intermediate search tree states, preventing redundant computation upon task resumption.
 - **Memory Manager:** Manages transient agent interaction histories (conversation logs, tool results) in RAM. It employs an LRU-K eviction policy to swap less frequently accessed data to disk (via the Storage Manager) when memory limits are approached, balancing efficiency and data retrievability.
 - **Storage Manager:** Handles persistent data for agents, including files, knowledge bases, and evicted agent memories. It offers versioned file management, thread-safe access, and semantic search capabilities, often implemented using local files and vector databases (e.g., Chromadb).
 - **Tool Manager:** Standardizes the loading and execution of a wide array of API tools. It includes pre-execution parameter validation to prevent tool crashes and a conflict resolution mechanism (using hashmaps) to manage parallel access constraints for tools.
 - **Access Manager:** Provides access control through privilege groups, regulating cross-agent data operations. It also implements a user intervention protocol, requiring explicit user confirmation for potentially irreversible operations.

The **AIOS SDK** complements the kernel by offering a high-level API for developers. It simplifies tool integration, provides functions to interact with kernel services, and includes "Agent Framework Adapters" to seamlessly integrate existing agents from frameworks like Autogen, Open-Interpreter, and MetaGPT into the AIOS environment without requiring code modifications.

This comprehensive methodology aims to create a robust, efficient, and scalable foundation for the next generation of LLM agent development and deployment.

### 4. Main Findings and Results

The evaluation of AIOS focused on three key research questions (RQ1-RQ3), demonstrating its effectiveness in performance, efficiency, and scalability for LLM-based agents.

**RQ1: Agent Performance on Standard Benchmarks**
The study assessed AIOS's impact on agent performance across four standard benchmarks: HumanEval (code generation), MINT (code subset, multi-turn interaction), GAIA (general AI assistant tasks with tools), and SWE-Bench-Lite (real-world GitHub issues). Using GPT-4o-mini as the LLM core, results showed:
- **Performance Maintenance and Enhancement:** AIOS consistently maintained or slightly improved agent performance across all benchmarks compared to running agents without AIOS.
- **Specific Improvements:**
 - In code generation benchmarks (HumanEval, MINT, SWE-Bench-Lite), AIOS boosted performance through "prompt enhancement," embedding more structural input/output within the LLM wrapper to guide response generation.
 - In tool-calling benchmarks (GAIA), performance gains were attributed to two mechanisms: (1) pre-execution parameter validation using structural regex to check tool call formats, and (2) conflict resolution hashmaps to mitigate concurrent access issues for tools.

**RQ2: Efficiency Analysis (Throughput and Latency)**
Evaluations on locally hosted Llama-3.1-8b and Mistral-7b models, using HumanEval, MINT, GAIA, and SWE-Bench-Lite benchmarks under concurrent conditions, revealed significant efficiency improvements:
- **Throughput Increase:** AIOS achieved substantially higher throughput across various agent frameworks. For instance, it demonstrated up to a **2.1× increase in throughput** for Reflexion-based agents on Llama-3.1-8b. This improvement is primarily due to the AIOS kernel's intelligent scheduling, which prevents inefficient trial-and-error attempts to load prompts onto the GPU, avoiding unnecessary computations and retries.
- **Reduced Latency:** The average waiting time for agents was significantly reduced, highlighting AIOS's responsiveness in serving LLM-based agents.
- **Impact of Scheduling Strategies:** An ablation study showed that while FIFO offered the shortest overall execution time, Round Robin (RR) provided a fairer distribution of waiting times (better p90 metric), albeit with slightly higher overall execution due to context switching overhead.
- **Correctness of Context Switch:** Using BLEU and BERT scores, the context manager's text-based and logits-based context switch mechanisms achieved a perfect score of 1.0, indicating that context interruption and resumption do not introduce discrepancies in output quality, thereby confirming the reliability of this feature.

**RQ3: Scalability Analysis**
The scalability of AIOS was tested by incrementally increasing the number of concurrently running agents from 250 to 2000, using Llama-3.1-8b and Mistral-7b on the HumanEval benchmark.
- **Linear Scalability:** AIOS demonstrated approximately linear relationships between both overall execution time and average agent waiting time relative to the increasing agent count. This indicates that AIOS can efficiently manage workloads even under high demand without disproportionate performance degradation.
- **Widening Performance Gap:** Crucially, the performance differential (in execution and waiting times) between systems running with and without AIOS *widened significantly* as the number of agents increased. This underscores AIOS's robust scalability advantage in handling high concurrent workloads, where traditional approaches quickly become bottlenecks.

In summary, the findings robustly confirm that AIOS not only maintains or enhances agent performance but also drastically improves system efficiency and scalability, making it a powerful solution for managing complex LLM agent deployments.

### 5. Significance and Potential Impact

The introduction of AIOS represents a significant leap forward in the practical deployment and management of LLM-based intelligent agents, with far-reaching implications for the future of AI systems.

**1. Foundational System Infrastructure:** AIOS establishes a crucial foundational layer for LLM agents, akin to how traditional operating systems manage computer hardware and processes. By treating LLMs and their associated resources (tools, memory, storage) as core system components, AIOS shifts the paradigm from individual agent design to a more integrated, system-level approach. This vision of "LLM as OS, Agents as Apps" is transformative, providing a standardized, robust, and scalable environment for developing and deploying complex agent ecosystems.

**2. Enhanced Efficiency and Scalability for Concurrent Operations:** The empirical results demonstrate AIOS's ability to dramatically improve system throughput (up to 2.1x faster execution) and reduce latency for concurrent agent tasks. This is critical for real-world applications where multiple agents need to operate simultaneously and efficiently, preventing resource monopolization and the inefficient "trial-and-error" approaches common in existing frameworks. Its linear scalability under increasing agent loads underscores its readiness for large-scale deployments.

**3. Improved Reliability and Robustness:** Features like the Context Manager's ability to interrupt and resume LLM inference tasks without loss of fidelity, the Memory Manager's intelligent swapping, and the Tool Manager's conflict resolution mechanisms contribute significantly to the overall stability and reliability of agent operations. This allows for more complex, long-running agent tasks to be managed effectively.

**4. Streamlined Agent Development:** The AIOS SDK provides a higher level of abstraction, shielding developers from the complexities of underlying resource management, scheduling, and security protocols. This allows agent developers to focus primarily on agent logic and application-specific functionalities, accelerating innovation and making agent development more accessible. The framework adapters further ensure backward compatibility and ease of migration for existing agent solutions.

**5. Stronger Security and Resource Governance:** The Access Manager's privilege-based access control and user intervention features are vital for managing cross-agent interactions and preventing unintended or harmful operations. This brings a much-needed layer of governance and safety to LLM agent systems, which are increasingly entrusted with sensitive tasks.

**6. Catalyst for Future Research:** AIOS lays robust groundwork for numerous future research directions, including advanced semantic scheduling algorithms, more efficient context management techniques (e.g., compression), optimized memory and storage architectures (e.g., shared memory for collaborative agents), and comprehensive safety and privacy enhancements (e.g., protection against jailbreaking, advanced encryption, watermarking). Its open-source availability encourages community engagement and accelerates collective progress in this critical area.

**Ethical Considerations:** The authors proactively discuss both the positive societal impacts (enhanced efficiency, improved user experience, innovation ecosystem) and potential negative impacts (privacy concerns, security risks, system failures). This responsible approach highlights the importance of incorporating robust design, ethical rules, standards, and public engagement in the development and deployment of such foundational AI systems, ensuring that AIOS contributes to an equitable and prosperous future while mitigating its inherent risks.

In conclusion, AIOS is a pivotal contribution that addresses fundamental infrastructural bottlenecks in LLM agent deployment. By providing an operating system layer, it not only enhances the performance, efficiency, and reliability of current agent systems but also paves the way for a more integrated, scalable, and secure future for intelligent agents across various domains.
