# HarnessPAI: An Evolving Harness for Physical AI

> [!summary] Summary
> HarnessPAI is a model- and embodiment-agnostic harness that treats executable code as the interface organizing a frozen action model. Within a rollout, a fixed program grounds objects, reasons geometrically, invokes the VLA or WAM, and verifies each step; across rollouts, execution feedback revises the program and distills node-keyed repair skills. It reaches 96.5% on LIBERO-PRO and lifts WorldDreamer by 27.2 points.

## Problem

- Post-training a VLA narrows its action distribution and erodes perception and language grounding, so policies above 90% on standard LIBERO collapse under scene perturbations.
- Code-as-policy systems replace learned manipulation with hand-designed control APIs, sacrificing contact-rich robustness; a pure code agent reaches only 18.3% overall success on LIBERO.
- Prior harnesses re-deliberate online at every action step, putting a large reasoning model on the critical path at roughly 1135 seconds and $168 per fifty rollouts.

## Method

- ==Open-loop execution== compiles one fixed program per task that calls ==SAM3== perception primitives, geometric control primitives, and the frozen action model, gating each phase behind an explicit success check.
- ==Closed-loop evolution== splits writer and diagnoser: a coding agent edits candidates under a success contract with pre-flight and probe gates, while a separate VLM scores rollout videos node by node.
- A ==node-centric structured skill memory== mounts failure-to-repair notes onto workflow-graph nodes such as grasp or transport, each referencing maintained code, so repairs transfer to new tasks sharing those nodes.

## Results

- LIBERO-PRO reaches **96.5%**, **8.8** points over the strongest Harness VLA variant and **24.8** over ASPIRE; standard LIBERO hits **98.1%** and robosuite averages **96.3%**.
- Wrapping WorldDreamer lifts RoboCasa Atomic-Seen from **65.0%** to **92.2%**, and the harness transfers zero-shot to DreamZero, raising Swap success from **0.6%** to **73.4%**.
- Fine-tuning on harness-collected trajectories lifts LIBERO-PRO from **34.9%** to **73.7%**, while rollouts run over **18x** faster than Harness VLA at zero online LLM API cost.

## Takeaways

> [!tip] Key Insights
> - Storing adaptation as inspectable code rather than weights or transient online reasoning lets the same scaffold wrap a different action backend untouched.
> - Harness gains scale with whatever atomic competence the base model retains; code can re-ground and verify actions but cannot manufacture missing dexterity.
> - A converged program doubles as a cheap demonstration generator, so system-level corrections can be distilled back into weights where human demonstrations do not exist.

## Detailed Report

### 1. Overview

A robot arm is asked to choose a black bowl by its relation to a plate and ramekin, then put it on the plate. Add the word “not,” and the intended bowl changes. In the paper’s illustrative comparison, π0.5 still grasps the bowl from the original instruction. HarnessPAI uses code to re-ground the instruction and grasps the other bowl.

The authors argue that a physical agent need not put every useful capability into one action model. Instead, executable code can ground a task in the current scene, organize perception and geometric reasoning, call a learned model for contact-rich actions, and check whether each step succeeded. On LIBERO-PRO, HarnessPAI wrapped around frozen π0.5 reaches 96.5% overall success, versus 34.9% for π0.5 alone.

### 2. A task is more than an action

A VLA maps images and instructions to actions. A successful action sequence on a familiar setup does not guarantee correct grounding when the instruction or scene changes. The paper’s illustrated failures show what happened. They do not show whether the source was language understanding, visual grounding, or the mapping from instruction to action.

The authors’ broader motivation is practical. Physical actions can leave persistent or hard-to-reverse scene changes, so a system should check important steps before committing to the next one. They call execution “open-loop” at the program level. This means the code remains fixed during one rollout, while live observations and predefined checks can still guide execution. Changes to the program happen between rollouts.

### 3. Compile, execute, and learn

HarnessPAI first creates a task program that coordinates perception, geometric reasoning, control, action-model calls, and success checks. In a manipulation example, code may locate an object and approach it, the VLA may perform the grasp, and code may transport it. A check gates each next phase.

Across rollouts, the system runs a candidate on multiple environments and inspects execution diagnostics and rollout video. It then revises failures and promotes code only after it passes the success contract.

Failures can also become reusable repair skills. A skill is a record of a failure and a repair, indexed by the workflow stage where it occurred and linked to maintained implementation code. A later program can therefore retrieve a relevant repair without searching a flat pile of notes. The library’s structure provides a transfer mechanism. The reported ablation, however, covers only three representative development tasks.

Development success rate over evolution rounds for LIBERO-Object Tasks 0, 1, and 5. The comparison is between the no-skill version (dashed blue) and the with-skill version (solid orange). These are development trajectories over seeds 0–14 in Swap and Task conditions, not held-out generalization results.

With skills, the program reaches 100% development-batch success within the first two rounds in these tasks. Without skills, the paths differ:

- Task 0 stays near zero before a late jump.
- Task 1 oscillates.
- Task 5 improves gradually.

This is suggestive evidence that stored repairs can speed these examples’ evolution. It is not a held-out, cross-task transfer test or a controlled measure of total cost.

### 4. Robustness under perturbation

LIBERO-PRO tests position swaps (“Swap”) and changed instructions (“Task”) across Object, Goal, and Spatial suites. Its overall score averages success across the six suite-by-perturbation groups. Each group averages ten tasks, and each task is evaluated on 50 layout seeds. The same task program is evolved on seeds 0–14 and then run unchanged across all 50.

Under these conditions, HarnessPAI reaches 96.5% overall success, versus 34.9% for π0.5 alone. That is a 61.6-percentage-point gain. The result supports the value of the complete harnessed system in this setting. It does not isolate which component causes the gain.

Success rate on LIBERO-PRO’s Object, Goal, and Spatial suites under Swap and Task perturbations. The orange HarnessPAI bars are high in all six suite-condition groups (93.8%–99.2%). π0.5 is substantially lower on the perturbations.

Two neighboring harness approaches also appear in the comparison:

- [[2607.08448|Harness VLA]] wraps a frozen VLA with a memory-guided agent that makes online planning decisions. Its CC variant reports 87.7% overall.
- [[2607.00272|ASPIRE]], a code-as-policy agent without a learned manipulation primitive, reports 71.7%.

Harness VLA’s reported evaluation uses 10 seeds per task versus HarnessPAI’s 50, so this is not a strictly controlled comparison.

### 5. Competence still matters

HarnessPAI makes a validated executable task program the unit that persists and evolves, while retaining the learned action model. It organizes and verifies capabilities. It does not create physical competence the underlying action primitive lacks.
