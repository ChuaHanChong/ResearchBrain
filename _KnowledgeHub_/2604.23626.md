# GraphPlanner: Graph Memory-Augmented Agentic Routing for Multi-Agent LLMs

> [!summary] Summary
> GraphPlanner introduces a graph memory-augmented agentic router for multi-agent large language models, dynamically generating query-specific workflows by selecting heterogeneous LLM backbones and specialized agent roles. This system demonstrated superior performance and efficiency across diverse tasks, achieving state-of-the-art accuracy with significant gains while reducing computational costs and exhibiting robust generalization capabilities.

## Problem

- Existing single-round LLM routers lack multi-step reasoning, task decomposition, and explicit coordination for complex, real-world tasks.
- Multi-round routing systems treat LLM calls as independent events, leading to redundant computations, semantic inconsistencies, and underutilization of heterogeneous LLM strengths.
- Current agentic LLM research often assumes homogeneous LLM backbones for agents and rarely systematically leverages abundant historical interaction memories to improve future coordination.

## Method

- **GraphPlanner** frames agentic routing as a ==Markov Decision Process== (MDP) to enable sequential decision-making for generating adaptive, query-specific workflows.
- It introduces GARNet, a heterogeneous graph neural network, to parameterize the routing policy, which captures and integrates current workflow memory and historical interaction memories through shared 'role hub nodes'.
- The entire routing pipeline is optimized using Proximal Policy Optimization (PPO), a reinforcement learning algorithm, to jointly maximize task-specific performance and minimize computational costs.

## Results

- GraphPlanner achieved state-of-the-art accuracy in 8 out of 10 tasks across two evaluation phases, with an average accuracy gain of +**9.3%** over the best baseline in workflow generation, consistently forming the Pareto frontier for accuracy-cost trade-offs.
- It demonstrated strong zero-shot generalization with **78%** average accuracy on unseen datasets, significantly outperforming baselines, and maintained superior performance with unseen LLM backbones and novel agentic roles.
- The system exhibited efficient training, requiring the smallest GPU compute (1.04 GiB) and total training time (120 minutes) among compared methods, alongside a low inference time of 1.2 seconds per query.

## Takeaways

> [!tip] Key Insights
> - Modeling agentic routing as an MDP allows for dynamic selection of both heterogeneous LLM backbones and specialized agent roles (Planner, Executor, Summarizer), enabling adaptive workflow generation.
> - A heterogeneous graph-based memory structure (GARNet) effectively integrates evolving workflow context and accumulated historical interactions, facilitating more informed and adaptive routing decisions.
> - Reinforcement learning, specifically PPO, successfully addresses the deferred reward problem in multi-step agentic routing, optimizing for long-term task performance and cost-efficiency simultaneously.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

The field of large language model (LLM) routing is focused on efficiently allocating queries to diverse LLM backbones to balance performance and computational cost. Existing routing methodologies can be broadly categorized into single-round and multi-round approaches.

Single-round routers (e.g., Shnitzer et al., 2023; Hu et al., 2024a; Chen et al., 2024a; Feng et al., 2024) perform a one-shot assignment of a query to a specific LLM based on static features or embeddings. While these methods offer simplicity and efficiency, they lack the capacity for multi-step reasoning, task decomposition, or explicit coordination among different models. Consequently, their applicability to complex, real-world tasks that require iterative problem-solving is limited.

Multi-round routers (e.g., Zhang et al., 2025; Shao et al., 2025) introduce flexibility by allowing sequential routing decisions that incorporate historical context. This enables more informed choices over multiple steps. However, these systems typically treat each LLM call as an independent event rather than a component of a cooperative workflow. This can lead to redundant computations, semantic inconsistencies from accumulated context, and an inability to fully exploit the complementary strengths of heterogeneous LLMs through structured collaboration.

A parallel development in LLM research is the emergence of agentic LLMs and multi-agent systems (MAS) (e.g., Wang et al., 2024a; Qian et al., 2024; Guo et al., 2024; Wu et al., 2024). These systems demonstrate that explicit collaboration among specialized agents can significantly enhance planning, reasoning, and overall performance on intricate tasks. However, much of the current MAS research often assumes homogeneous LLM backbones for all agents, which constrains the exploration of diverse agent capabilities and limits truly complementary collaboration. While some recent work has focused on automating multi-agent workflow generation (e.g., Hu et al., 2024b; Zhang et al., 2024a; Shang et al., 2024), these systems often still assume largely homogeneous agent capabilities. Additionally, the increasing integration of LLM agents with external tools and APIs (e.g., Schick et al., 2023; Patil et al., 2024; Yao et al., 2022) highlights the importance of real-world functionality, yet these systems often rely on static or manually designed workflows.

GraphPlanner addresses a significant gap by extending LLM routing into the domain of agentic multi-LLM settings. It aims to integrate the benefits of dynamic routing with the collaborative and specialized capabilities of multi-agent systems. Unlike prior routing methods, GraphPlanner explicitly models agent roles and heterogeneous LLM backbones within structured workflows, while also systematically leveraging historical interactions through a graph-based memory mechanism. This positions the work as a contribution to developing more adaptive, efficient, and capable LLM systems that can handle complex, multi-faceted tasks through intelligent coordination.

### 2. Key Objectives and Motivation

The primary objective of this research is to extend LLM routing mechanisms to agentic LLM settings, a domain where task planning, multi-round cooperation among heterogeneous agents, and systematic memory utilization are critical. The authors motivate this work by identifying several challenges inherent in current routing paradigms when applied to complex, real-world applications.

First, **the relations among queries, responses, and LLM candidates become highly diverse and complex in agentic settings.** Unlike single-step assignments, agentic workflows require reasoning over evolving contexts where initial queries may lead to branching sub-queries, intermediate responses interact, and different models contribute complementary or potentially conflicting information. Designing a router capable of capturing and leveraging these heterogeneous dependencies is a non-trivial challenge. Existing routers, confined to simpler or static settings, are not equipped to manage this complexity.

Second, **agentic routing involves deferred rewards and presents a challenging credit assignment problem.** Early decisions in a multi-step workflow can have long-term consequences on the final outcome. An inefficient or incorrect allocation by the router at an early stage may cascade into redundant subsequent calls or degrade the quality of downstream reasoning. This means that immediate feedback is insufficient for optimizing the overall workflow, requiring the router to balance short-term computational efficiency with long-term task performance.

Third, **there is an unaddressed potential to fully exploit abundant historical memories from agentic LLM systems.** Rich traces of past multi-agent workflows contain valuable insights regarding successful collaboration patterns, common error modes, and effective divisions of labor among agents. However, existing routers rarely make systematic use of this accumulated historical information to improve future coordination and decision-making, leaving a significant opportunity untapped.

To address these challenges, GraphPlanner sets out with several key objectives:
- To propose a heterogeneous graph memory-augmented agentic router for multi-agent LLMs.
- To generate adaptive, query-specific routing workflows that involve selecting both an LLM backbone and an agent role at each step.
- To formulate this workflow generation as a Markov Decision Process (MDP) to enable sequential decision-making and reinforcement learning optimization.
- To incorporate a novel heterogeneous graph structure, GARNet, to effectively capture and integrate current workflow memory and historical interaction memories, thereby constructing richer state representations.
- To optimize the entire routing pipeline using reinforcement learning (specifically PPO), with the goal of jointly improving task-specific performance of the final answers and minimizing associated computational costs.
- To develop a system that supports both inductive (generalizing to new queries without prior history) and transductive (leveraging similar past interactions) inference, enhancing adaptability and robustness.

### 3. Methodology and Approach

GraphPlanner frames the problem of LLM routing as a sequential decision-making process for generating agentic workflows. This process is modeled as a Markov Decision Process (MDP), and the routing policy is parameterized by a heterogeneous graph neural network called GARNet.

#### 3.1. Agentic Routing Workflow Generation as Markov Decision Process (MDP)

GraphPlanner models the generation of an agentic routing workflow as an MDP defined by (S, A, T, r, γ), representing state, action, transition dynamics, reward, and discount factor, respectively.

- **State (S):** At any step *t*, the state *s_t* is the current query under resolution, denoted as *q_t*. The evolving workflow structure implicitly captures contextual signals.
- **Action (A):** An action *a_t* is a pair (*α_t*, *m_t*), where *α_t* is the selected agent role and *m_t* is the chosen LLM backbone from a pool of *K* candidates. The paper defines three core agent roles:
 - **Planner:** Decomposes complex queries into atomic sub-queries.
 - **Executor:** Generates responses for queries or sub-queries, with or without contextual grounding.
 - **Summarizer:** Condenses multiple outputs into a coherent answer.
 The total action space is 3*K*. To ensure semantic validity, a dynamic mask *M_t* restricts available actions: summarizer actions are prohibited at the first step, termination must occur via an executor action, and the number of planner actions is limited by a hyperparameter *P_max*.
- **Transition (T):** The transition dynamics *T(s_t, a_t)* determine the next query *s_{t+1}* and the observable response *o_t*.
 - If a Planner is selected, the current query is decomposed, *o_t* is the set of new sub-queries, and *s_{t+1}* becomes the first child query.
 - If an Executor is selected, the current query is resolved, *o_t* is the answer, and *s_{t+1}* moves to the next pending query or terminates the episode.
 - If a Summarizer is selected, completed responses are aggregated, *o_t* is the summary, and *s_{t+1}* is set to the summary query.
- **Reward (r):** The reward function balances task utility *U(ŷ, y*)* and computational cost *C(a_t)*. At terminal steps (*t=T*), the reward is *U(ŷ, y*) - α C(a_t)*; otherwise, for intermediate steps (*t<T*), it is * -α C(a_t)*. *α* is a cost-utility trade-off coefficient.
- **Episode and Objective:** An episode concludes when the root query is resolved. The router's objective is to find a policy *π* that maximizes the expected discounted return *E_{q~Q}[Σ_t γ^t r(s_t, a_t)]*.

#### 3.2. Heterogeneous Graph-Based Policy Network (GARNet)

The policy *π(a_t | s_t)* is parameterized by GARNet, a heterogeneous graph neural network. At each step *t*, the environment is represented as a union of the current workflow memory graph *G_workflow* and a historical memory graph *G_history*, denoted as *G_t = G_workflow ∪ G_history*.

- **Node Initialization:**
 - **Workflow Memory Graph (G_workflow):** Contains query nodes (*x_q*), response nodes (*x_r*), and LLM-role nodes (*x_m*). *x_q* is represented by a Longformer embedding of the current query. *x_r* is an embedding of the response. *x_m* is a composite node embedding concatenating an LLM-role textual embedding with task utility (*U*) and cost (*C*).
 - **Historical Memory Graph (G_history):** Includes historical query nodes (*x_hq*) and historical response nodes (*x_hr*). Crucially, the same LLM-role nodes (*x_m*) from *G_workflow* are reused as "role hub nodes" in *G_history*. These shared nodes provide a mechanism for information exchange between the current workflow and historical experiences.
- **Graph Construction:**
 - In *G_workflow*, edges *e_q–m* connect queries to roles, incorporating task performance and cost. Responses are linked to the roles that generated them, and query-response edges maintain semantic alignment.
 - In *G_history*, historical queries (*x_hq*) and responses (*x_hr*) are connected to the shared role hub nodes (*x_m*). These edges encode accumulated experience regarding how specific roles performed in past interactions. This shared-node mechanism enables GARNet to integrate multi-round contextual information without explicit temporal edges, allowing reuse of knowledge across routing steps.
- **Message Passing:** Node embeddings are first projected into a hidden space. Messages are then aggregated from neighboring nodes, and node states are updated via a residual connection.
- **Nested Dual-Graph Encoding:** This involves a two-stage encoding process:
 1. The historical memory graph is encoded by *GARNet_θ_his(G_history)*, generating updated embeddings for the role hub nodes that summarize past interactions.
 2. These historical embeddings are then injected into the workflow memory graph encoder, *GARNet_θ_loc(G_workflow; H^(his))*, which yields local-contextualized representations of queries, roles, and responses. This ensures that role hub nodes encode both historical patterns and the evolving workflow state.
- **State Fusion and Action Scoring:** The global state representation *z_t* is obtained by fusing the current query embedding. Each candidate action corresponds to an LLM-role node embedding. Compatibility scores are computed by a dot product between *z_t* and the action embedding, masked by *M_t*, and then normalized into a probability distribution *π(a_t | s_t)*.

#### 3.3. GraphPlanner Training

GraphPlanner is optimized using Proximal Policy Optimization (PPO), an actor–critic reinforcement learning algorithm. Both the policy and value functions are parameterized by GARNet. The PPO objective is used to maximize the expected return, incorporating a clipping mechanism to ensure stable updates. Hyperparameters for PPO include a discount factor *γ* of 0.99 and a clipping threshold *ϵ* of 0.2. The training process utilizes a multi-threaded rollout design to enhance data collection efficiency, parallelizing query processing and interaction generation.

### 4. Main Findings and Results

GraphPlanner was evaluated across 14 diverse LLM tasks spanning 6 domains and compared against a range of single-round and multi-round router baselines. The evaluation was structured in two phases and measured performance using accuracy (task-specific metrics) and computational cost (GPU cost based on token usage and LLM pricing).

#### 4.1. Superior Performance and Efficiency

- **Outperformance across Phases:** GraphPlanner consistently demonstrated superior performance. In Phase 1 (optimizing LLM backbones within existing workflows), it achieved state-of-the-art (SOTA) results in four out of five tasks and the highest overall average accuracy, with a minimum improvement of +3.8% over the strongest baseline. In Phase 2 (generating optimal workflows by jointly selecting agents and LLM backbones), GraphPlanner again achieved SOTA in four out of five tasks, with an overall average accuracy gain of +9.3% over the best baseline.
- **Amplified Advantage in Workflow Generation:** Phase 2 results showed a more pronounced advantage for GraphPlanner, with an average accuracy about 5% higher than its best Phase 1 performance. This indicates that dynamically constructing query-specific agentic workflows is more effective than optimizing within fixed workflow structures, particularly for reasoning-intensive tasks like Math and Code (gains of 5.0% and 4.0%, respectively).
- **Pareto Frontier for Accuracy-Cost Trade-off:** GraphPlanner consistently formed the Pareto frontier in accuracy-cost plots, surpassing both single-round and multi-round routers. This implies that it can achieve higher accuracy at the same cost, or lower cost at the same accuracy, demonstrating more efficient and controllable trade-offs by adjusting its cost-utility coefficient *α*.
- **Reduced Training Overhead:** GraphPlanner exhibited the smallest GPU compute requirements during Phase 2 training (1.04 GiB), significantly lower than some multi-round routers (e.g., Router-R1 at 186.26 GiB). While consuming slightly more tokens than Router-R1, this was attributed to more extensive multi-step planning during training, which correlated with improved routing performance. Furthermore, GraphPlanner achieved the lowest total training time (120 minutes) among all methods, benefiting from its multi-threaded rollout design for data collection, and the lowest inference time per query (1.2 seconds).

#### 4.2. Robust Generalization Capabilities

- **Zero-shot Generalization to Unseen Tasks:** GraphPlanner demonstrated strong zero-shot generalization on unseen datasets (LogicGrid, MGSM, CommonGen), achieving an average accuracy of 78%. This significantly surpassed single-round routers (GraphRouter 46%, RouterDC 58%) and the multi-round router Router-R1 (38%), performing highest on each individual unseen dataset. This suggests its routing strategy is robust and adaptable to novel task domains.
- **Adaptability to Unseen LLMs:** The router maintained superior performance across all task domains when evaluated with LLM backbones that were not part of its training set. This indicates that GraphPlanner's learned routing strategy generalizes effectively to new underlying models without requiring additional fine-tuning.
- **Performance on Complex Unseen Datasets:** On the challenging, unseen AIME dataset, GraphPlanner achieved an accuracy of 14.7%, which was nearly double that of the best baseline (7.56%). This highlights its superior transferability to complex mathematical reasoning problems.

#### 4.3. Validation through Ablation Studies

- **Importance of Historical Memories (GARNet):** Ablation studies confirmed the critical role of GARNet's historical memory modeling.
 - Removing historical states entirely ("w/o History") led to a substantial performance drop, emphasizing the necessity of accumulated interaction context.
 - Replacing GARNet with homogeneous or simpler heterogeneous graph neural networks ("Homo-Graph", "Hetero-Graph") showed progressively better results than "w/o History," but neither matched the full GARNet design. This confirmed that both structural relations and agent role heterogeneity are important, but GARNet's ability to model workflow dynamics and integrate historical and current memory through shared role hub nodes provided superior contextual awareness.
 - Comparative ablations against LLM-based historical processing strategies (e.g., "History-summary," "History-retrieval" variants of Router-R1) further demonstrated GARNet's effectiveness. These LLM-based methods showed limited improvements over Router-R1, indicating that directly injecting unstructured historical text is less effective than GARNet's principled graph-based approach for modeling complex, heterogeneous interaction histories.
- **Inductive vs. Transductive Inference:** GraphPlanner supports both inference modes:
 - **Transductive:** Leveraging preserved historical interactions during inference yielded slightly better overall performance, demonstrating the value of richer context.
 - **Inductive:** Directly generating decisions without external historical context maintained strong performance and was more resource-efficient, consistently outperforming the best multi-round router baseline. This flexibility allows adaptation to different operational priorities.
- **Adaptability to New Agentic Roles:** Experiments introducing additional agent roles (Thinker, Verifier) demonstrated GraphPlanner's adaptability. When trained with these new roles, performance consistently improved. Furthermore, GraphPlanner showed strong zero-shot and few-shot generalization to unseen agentic roles, indicating its capacity to quickly integrate and leverage expanded agent configurations.
- **GARNet Design vs. Other GNNs:** Ablations replacing GARNet with standard GAT or GraphTransformer encoders showed that GARNet consistently achieved stronger performance while being a lightweight alternative.

### 5. Significance and Potential Impact

GraphPlanner contributes to the field of large language model deployment and multi-agent systems by introducing a novel framework for agentic LLM routing. Its significance and potential impact are multifaceted:

- **Advancement in LLM Routing:** This work moves beyond traditional, static LLM routing paradigms by integrating dynamic workflow generation and explicit agent collaboration. This shift is critical for enabling LLMs to tackle more complex, multi-stage problems that require structured reasoning and coordinated action.
- **Enabling Heterogeneous Multi-Agent Collaboration:** GraphPlanner's core contribution lies in its ability to jointly select heterogeneous LLM backbones and specialized agent roles. This allows for the creation of truly complementary multi-agent systems where different LLMs, with varying capabilities and costs, can be intelligently orchestrated according to the demands of each sub-task. This explicit modeling of specialization and cooperation has the potential to unlock new levels of performance and efficiency in complex AI systems.
- **Effective Utilization of Historical and Workflow Memory:** The introduction of GARNet, a heterogeneous graph-based memory system, provides a principled mechanism for integrating both the evolving state of the current workflow and accumulated historical interactions. This systematic leverage of memory leads to more informed, adaptive, and robust routing decisions, addressing a critical limitation of previous approaches.
- **Robust Generalization:** The demonstrated strong zero-shot generalization capabilities to both unseen tasks and novel LLM backbones indicate that GraphPlanner learns fundamental principles of effective routing and agentic coordination rather than merely memorizing training patterns. This robustness is crucial for real-world deployments where task distributions and available models may change dynamically.
- **Improved Efficiency and Performance Trade-offs:** By consistently forming the Pareto frontier for accuracy and computational cost, GraphPlanner offers practical benefits for system designers. It enables flexible optimization towards either maximum performance or maximum cost-efficiency, depending on application requirements, while simultaneously achieving state-of-the-art accuracy and significantly reducing GPU compute and total time costs.
- **Foundation for Scalable Agentic Systems:** GraphPlanner provides a foundational framework for developing more scalable and cooperative multi-agent LLM systems. By automating the generation of adaptive workflows and intelligently managing heterogeneous resources, it paves the way for advanced AI agents capable of tackling open-ended problems requiring complex planning and collaboration.

The future work outlined, such as incorporating richer agent profiles beyond Planner, Executor, and Summarizer (e.g., Thinker and Verifier as explored in the appendix), suggests a clear path for further enhancing the sophistication and capabilities of agentic routing, making these systems more versatile and powerful.
