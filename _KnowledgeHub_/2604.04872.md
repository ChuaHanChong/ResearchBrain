# Synthetic Sandbox for Training Machine Learning Engineering Agents

> [!summary] Summary
> SandMLE is a framework that creates synthetic, micro-scale machine learning engineering environments, making on-policy trajectory-wise reinforcement learning practical for training LLM agents. This approach reduces average code execution time by 13.7 times, enabling Qwen3 models to achieve up to a 100.7% relative improvement in "Any Medal" rates on MLE-Bench-Lite compared to baseline methods.

## Problem

- Applying on-policy trajectory-wise Reinforcement Learning (RL) to Machine Learning Engineering (MLE) tasks is computationally infeasible due to the long execution times of full ML pipelines.
- Each MLE code execution takes around 200 seconds, making the large-scale rollouts required for on-policy RL impractical.
- Existing methods like supervised fine-tuning (SFT) or step-wise RL with proxy rewards for MLE agents fail to leverage the exploration and generalization benefits of on-policy RL.

## Method

- Developed **SandMLE**, a ==multi-agent framework== to autonomously generate diverse, verifiable synthetic MLE environments with ==micro-scale datasets== (50-200 samples).
- Constrained synthetic datasets drastically reduce execution latency from approximately 200 seconds to about 14 seconds per task.
- Applied ==trajectory-wise Group Relative Policy Optimization (GRPO)== with a ==dense milestone-based reward function== to train LLM agents effectively.

## Results

- Achieved a **13.7x** speedup in average code execution time (from **196.17s** to **14.31s**) by using synthetic micro-datasets.
- SandMLE-trained Qwen3 models showed up to **100.7%** relative improvement in "Any Medal" rates over base models on MLE-Bench-Lite and surpassed SFT baselines.
- Demonstrated robust generalization across various agent scaffolds and benchmarks, indicating transferable reasoning capabilities for trained LLM agents.

## Takeaways

> [!tip] Key Insights
> - The primary bottleneck for applying on-policy RL to MLE tasks is the execution latency caused by dataset size, which can be overcome with micro-scale synthetic data.
> - A multi-agent system can effectively generate a diverse curriculum of structurally complex yet computationally light synthetic MLE tasks.
> - Dense, milestone-based reward functions are critical for stable and effective policy optimization in long-horizon, complex agentic tasks.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

The application of Large Language Models (LLMs) to complex, open-ended engineering tasks, particularly in software engineering (SWE) and machine learning engineering (MLE), represents an active area of research. LLMs have demonstrated advanced reasoning capabilities, which can be further optimized through Reinforcement Learning with Verifiable Rewards (RLVR). For long-horizon tasks like SWE and web search, prior work has successfully utilized trajectory-wise reinforcement learning (RL) to enhance LLM reasoning. This paradigm involves extending rollouts over multiple turns and assigning rewards based on the final outcome of the entire trajectory, thereby optimizing the model's long-term decision-making.

However, applying this trajectory-wise RL approach to MLE tasks presents a significant challenge. Unlike SWE tasks, where unit tests provide rapid feedback, MLE tasks inherently require executing full machine learning pipelines—including data preprocessing, model training, and metric evaluation—on potentially large datasets. This process is computationally intensive, with a single code execution often taking minutes, creating an orders-of-magnitude gap in feedback latency compared to SWE. This computational overhead makes the large-scale rollouts necessary for on-policy trajectory-wise RLVR impractical for MLE. Consequently, existing efforts to train LLMs for MLE tasks have largely resorted to supervised fine-tuning (SFT) or step-wise RLVR using proxy offline rewards. These methods, however, sacrifice the exploration benefits and generalization capabilities typically associated with on-policy RL algorithms.

The current work addresses this bottleneck by proposing a novel approach that enables the practical application of on-policy trajectory-wise RL to MLE. It positions itself as a method to enhance the LLM's intrinsic reasoning abilities, in contrast to much existing research that focuses on developing complex agent scaffolds or test-time compute scaling to improve performance at inference time. While scaffolding can improve task performance, the authors note that such gains are often contingent on specific scaffold designs and do not fundamentally improve the underlying model's transferable reasoning capacity. This research aims to fill the gap by providing a scalable training paradigm that fosters robust, framework-agnostic MLE capabilities.

### 2. Key Objectives and Motivation

The primary motivation for this research stems from the significant computational bottleneck encountered when attempting to apply on-policy trajectory-wise reinforcement learning (RL) to Machine Learning Engineering (MLE) tasks. Unlike Software Engineering (SWE) tasks, where verification via unit tests is rapid, MLE tasks demand the execution of complete ML pipelines, encompassing data preprocessing, model training, and metric evaluation on substantial datasets. This process is time-consuming, with a single code execution averaging approximately 200 seconds on standard problems, rendering large-scale RL rollouts prohibitively slow. This latency prevents the effective use of on-policy RL, forcing prior work into less effective strategies like supervised fine-tuning (SFT) or reliance on offline proxy rewards, thereby foregoing the exploration and generalization advantages of on-policy methods.

A key insight driving this work is the observation that the primary source of this execution bottleneck in MLE is the size of the sandbox dataset. Building on this insight, the key objectives and motivations are:

1. **Overcome Prohibitive Execution Latency:** The foremost objective is to significantly reduce the execution time associated with MLE tasks to make on-policy trajectory-wise RL computationally feasible. The authors identified dataset size as the core issue and aimed to address it by constraining data volume.

2. **Generate Diverse, Verifiable Synthetic MLE Environments:** To enable efficient training while maintaining relevance to real-world problems, the research aims to develop a method for generating synthetic MLE tasks. These synthetic environments are designed to preserve the structural and technical complexity and mathematical "hidden rules" of authentic MLE problems, but with intentionally constrained, micro-scale datasets (50-200 samples per task). This strategy is intended to ensure rapid environment feedback.

3. **Develop a Multi-Agent Framework for Automated Environment Generation:** A specific objective is to design a fully-automated, agent-driven pipeline capable of generating these diverse, verifiable synthetic MLE tasks. This framework involves orchestrating multiple specialized language model roles (Data Strategist, MLE Developer, MLOps Engineer, Technical Writer) to procedurally create task specifications, data assets, and evaluation environments.

4. **Apply Trajectory-wise RL with Dense Reward Formulation:** With the creation of computationally feasible synthetic environments, the objective is to successfully apply trajectory-wise RL, specifically Group Relative Policy Optimization (GRPO), to the MLE domain. This includes designing a dense, milestone-based reward function to mitigate the challenges of reward sparsity inherent in long-horizon agentic tasks. This approach seeks to directly enhance the LLM's intrinsic MLE problem-solving capabilities in a manner that is framework-agnostic.

Ultimately, the motivation is to unlock a scalable path for training MLE agents that learn and improve through direct interaction with their environment, rather than solely through imitation of expert behavior, thereby fostering more robust and transferable engineering reasoning capabilities in LLMs.

### 3. Methodology and Approach

The core methodology of SandMLE involves the creation of synthetic, micro-scale Machine Learning Engineering (MLE) environments that drastically reduce execution latency, thereby enabling large-scale, on-policy trajectory-wise Reinforcement Learning (RL) for training LLM agents.

#### 3.1. Synthetic Environment Generation

The pipeline for generating these synthetic environments is a multi-agent workflow that transforms curated real-world seed tasks into lightweight, verifiable synthetic micro-tasks. This process involves four interconnected phases:

1. **Task Amplification and Specification (Data Strategist):**
 - **Structural DNA Extraction:** An agent abstracts a seed task into a "Task DNA," a mathematical schema (e.g., data modality, resolution, label cardinality) devoid of semantic context.
 - **Domain Attribution:** The abstracted DNA is then mapped to novel, broader application scenarios (e.g., repurposing an animal image classification into road damage detection).
 - **Adversarial Mutation:** The agent injects realistic difficulty through a noise configuration (e.g., image blurring).
 - **Concrete Specification Compilation:** These elements are merged to define a complex hidden rule (e.g., `l = f(z) + ϵ`) connecting features `z` to labels `l` in the synthetic micro-dataset. The dataset size is strictly constrained to 50–200 samples.
 - The agent also specifies multiple baseline methods of varying complexity to establish progressive milestone thresholds for dense reward assignment.

2. **Agentic Data Generation (ML Developer):**
 - An ML Developer agent writes a self-contained Python script to synthesize micro-scale datasets (`D_train`, `D_test`) based on the specifications.
 - It implements the defined hidden rules to deterministically map generated features to ground-truth labels.
 - The script trains and evaluates the baseline methods specified by the Data Strategist to empirically calculate and lock in the progressive milestone thresholds.
 - A dummy sample submission file with random predictions is generated to serve as a strict schema reference.
 - An execution-based verification loop is enforced: if the script fails, it is returned for iterative debugging.

3. **Evaluation Environment Setup (MLOps Engineer):**
 - An MLOps Engineer agent writes a robust evaluator script.
 - **Metric Standardization:** The evaluation metric, optimization direction, and milestone thresholds are hard-coded to ensure deterministic scoring.
 - **Data Alignment and Computation:** The script loads an agent’s submission, aligns it with hidden ground-truth labels from `D_test`, computes the metric, and outputs the final score.
 - **Execution-based Verification:** The evaluator script is tested against a dummy submission, with errors fed back for debugging.

4. **Task Description Synthesis (Technical Writer):**
 - A Technical Writer agent compiles metadata into a comprehensive markdown document.
 - This involves adapting the original seed task’s narrative to match the new synthetic domain, drafting a clear problem overview, defining the expected output format using the generated sample submission schema, and cataloging public data files while strictly omitting hidden answers.

#### 3.2. Environment Sanity Verification

Before RL training, an automated sanity check ensures the logical consistency of generated environments. For each task, a baseline score from a dummy submission and the progressive milestone thresholds (`S = {s_1..., s_k}`) are evaluated. A task is verified only if its thresholds satisfy a strict monotonic constraint based on the optimization direction of the metric, ensuring valid, monotonic reward signals.

#### 3.3. Trajectory-Level GRPO

SandMLE enables the practical application of trajectory-level GRPO, an efficient variant of Proximal Policy Optimization, by reducing the environment execution cost (`c_exec`) by over 13 times.

- **On-policy RL for MLE Tasks:** During the rollout phase, the LLM agent interacts with a SandMLE environment using the ReAct framework, iteratively generating actions and receiving observations. Strict boundary conditions are enforced: a per-step execution time limit (`τ_max`) and a maximum trajectory length (`T_max`).
- **Dense Reward Formulation:** To mitigate reward sparsity, a dense reward function is designed:
 `r = w_format * r_format + w_execute * I_execute + sum(w_si * I_si)`
 - `r_format` (0-1): Ratio of steps properly utilizing reasoning tags.
 - `I_execute` (0/1): Boolean indicator for successfully generating a valid output file.
 - `I_si` (0/1): Tiered performance milestones, evaluating if the final score surpasses predefined thresholds in `S`.
 Weights `w` are distributed to sum to 1.0, guiding the agent from basic compliance to higher performance.
- **Selective Masking for Backpropagation:** Loss masking is applied to calculate policy gradients exclusively on the agent’s generated reasoning and action tokens, while observations and trajectories exceeding the time limit are masked.

### 4. Main Findings and Results

The research presents several findings regarding the efficacy of SandMLE in enabling on-policy trajectory-wise RL for MLE agents and the performance of models trained using this framework.

#### 4.1. Statistics of Synthetic Training Data

The synthetic generation pipeline produced a diverse training corpus from 60 seed tasks.
- **Diversity:** The generated tasks span various application domains (healthcare, retail, manufacturing, IT), data modalities (image-based, tabular, text, multi-modal, graph, audio), and task formulations (classification, regression, ranking, forecasting, reconstruction). Image-based tasks constituted 48.7%, and classification tasks 56.2%.
- **Task Reliability and Difficulty:** Benchmarking four established models (GPT-4o-mini, Gemini-2.5-Flash, DeepSeek-V3, Claude-4.5-Sonnet) on a random sample of 64 synthetic tasks confirmed that the tasks differentiate models according to their known capabilities, with Claude-4.5-Sonnet exhibiting a 92.9% win rate, indicating meaningful difficulty and reliability.
- **Dataset Scale and Execution Latency:** The pipeline constrained per-task datasets to a micro-scale, with most tasks containing between 120 and 150 samples. This led to a substantial reduction in average code execution time, from 196.17 seconds on original MLE-bench tasks to 14.31 seconds on synthetic tasks, representing a 13.7x speedup. This speedup is crucial for making trajectory-wise GRPO practical.

#### 4.2. Main Results

Experiments were conducted using Qwen3 models (8B, 14B, 30B-A3B) and compared against various baselines on MLE-Bench-Lite and MLE-Dojo.

- **Comparison with Baselines (MLE-Bench-Lite):**
 - SandMLE-trained models achieved significant relative improvements in "Any Medal" rate over respective Base models: +66.9% at 8B, +24.7% at 14B, and +100.7% at 30B.
 - The Seed-SFT baseline, fine-tuned on expert trajectories, showed marginal or no improvement over Base models, suggesting that behavioral cloning alone does not transfer iterative problem-solving effectively.
 - SandMLE models demonstrated a 20.3% to 66.9% relative improvement over the Seed-SFT baseline, indicating the value of direct environment interaction through RL.
 - The performance of SandMLE-trained open-weight models rivaled that of advanced closed-source systems, with the 8B SandMLE matching Deepseek-V3.1 and Gemini-2.5-flash (22.7% Any Medal rate), and 14B/30B models (27.3%) closing the gap with Claude-4.5-Sonnet (31.8%).

- **Combining SFT and RL (SFT-SandMLE):**
 - Initializing GRPO from a Seed-SFT checkpoint consistently improved operational reliability, as indicated by higher "Valid Submission" rates, while maintaining "Any Medal" rates. For example, Qwen3-8B-SFT-SandMLE increased "Valid Submission" from 63.6% to 90.9%.
 - This suggests that SFT contributes to format compliance and pipeline construction, while RL enhances higher-order reasoning, offering complementary benefits.

- **Scaling with Model Sizes:**
 - "Valid Submission" rates for pure SandMLE models monotonically increased with model size (63.6% for 8B to 100% for 30B), while Base models remained largely flat. This indicates that larger models better resolve the tension between exploration and output reliability.
 - "Above Median" rates for SandMLE also scaled from 27.3% (8B) to 36.4% (30B), reflecting broader improvements in engineering competence.
 - The reliance on SFT initialization for reliability diminished with larger models, suggesting that larger models can internalize both formatting discipline and reasoning through RL alone.

#### 4.3. Test-Time Scaling of SandMLE Models

The Qwen3-30B-SFT-SandMLE model, when given increased interaction turns (T_max) on MLE-Bench-Lite (ReAct framework), exhibited positive test-time scaling. Both "Any Medal" and "Above Median" rates steadily increased, peaking at 30 turns. Beyond this, performance regressed due to context window overflows and loss of historical context, highlighting context length as a bottleneck for long-horizon tasks.

#### 4.4. Training Dynamics

Training curves across Qwen3-8B, 14B, and 30B models demonstrated stable convergence of the RL objective on synthetic environments. Larger models started at higher rewards and converged to higher ceilings. The ability to produce valid submissions was observed as a learned behavior, acquired faster and more consistently by larger models.

#### 4.5. Framework Generalization

SandMLE models demonstrated robust generalization across alternative agent scaffolds (AIDE, AIRA, MLE-Agent) on both MLE-Bench-Lite and MLE-Dojo.
- **MLE-Bench-Lite (AIDE, AIRA):** SandMLE models consistently surpassed Base model performance across all metrics and scaffolds, while SFT models occasionally showed brittleness.
- **MLE-Dojo (AIDE, MLE-Agent):** Qwen3-30B-SandMLE with MLE-Agent achieved an 83.9% "Valid Submission" rate and a "HumanRank" score of 38.56, significantly outperforming Base and SFT variants, which often collapsed (e.g., 30B SFT-MLE-Agent at 17.7% Valid Submission). This confirms that SandMLE instills transferable reasoning, not just scaffold-specific performance.

#### 4.6. Effectiveness of Milestone-Based Rewards

An ablation study comparing the dense, milestone-based reward against a sparse reward formulation (only basic format compliance and highest performance standard) confirmed the necessity of dense feedback. Under sparse rewards, models struggled to find meaningful gradients and showed significant performance degradation across all scales, especially at 30B, where "Any Medal" rate dropped from 27.3% to 13.6%. This empirically validates that a hierarchical reward landscape is crucial for stabilizing policy optimization and achieving high-level engineering capabilities.

### 5. Significance and Potential Impact

The introduction of SandMLE represents a notable advancement in the training of machine learning engineering (MLE) agents, offering a scalable solution to a fundamental bottleneck in the field. Its significance and potential impact stem from several key contributions:

1. **Enabling On-Policy Trajectory-wise RL for MLE:** For the first time, SandMLE makes trajectory-wise on-policy reinforcement learning (RL) practical and computationally feasible for MLE agents. This addresses a critical limitation where the high computational cost of running full ML pipelines for verification previously made such training prohibitively slow. By reducing execution time by over 13x, SandMLE unlocks a training paradigm that was previously largely theoretical for this domain.

2. **Addressing the Execution Latency Bottleneck:** The work effectively identifies and mitigates the primary bottleneck in MLE agent training—dataset size-driven execution latency. The strategy of generating micro-scale synthetic environments (50–200 samples) while preserving structural and technical complexity offers a concrete method to achieve rapid feedback cycles crucial for RL.

3. **Scalable and Diverse Environment Generation:** The multi-agent framework for generating synthetic MLE tasks is a significant contribution. It allows for the automated creation of diverse, verifiable training curricula from a limited number of seed tasks. This amplifies the availability of high-quality training environments, fostering robust policy optimization without the need for extensive manual curation or large real-world datasets.

4. **Enhancing Intrinsic Reasoning Capabilities:** Unlike many approaches that focus on improving agent performance through complex external scaffolding or test-time compute, SandMLE aims to enhance the LLM's intrinsic engineering reasoning abilities through direct environmental interaction. The demonstrated framework-agnostic generalization indicates that the learned capabilities are robust and transferable across different agent architectures, leading to more capable base models.

5. **Validation of Dense Reward Design:** The ablation study unequivocally confirms the importance of a dense, milestone-based reward formulation for complex, long-horizon tasks. This provides empirical evidence that hierarchical feedback, validating format compliance, execution success, and progressive performance tiers, is essential for stabilizing RL policy optimization and guiding agents toward advanced capabilities.

6. **Opening New Research Avenues:** The principle underlying SandMLE—that carefully constructed synthetic micro-scale environments can serve as effective proxies for real-world MLE tasks—opens scalable pathways for further research. This includes exploring more sophisticated synthetic generation techniques, investigating novel RL algorithms tailored for such environments, and extending the approach to other complex long-horizon agentic tasks beyond MLE. The work suggests a future where LLM agents learn continuous improvement through active interaction rather than merely imitating pre-recorded expert behaviors.
