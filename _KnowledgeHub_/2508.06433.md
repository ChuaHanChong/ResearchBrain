# Memp: Exploring Agent Procedural Memory

> [!summary] Summary
> Memp treats an LLM agent's procedural memory as a learnable, updatable object. It distills past trajectories into step-by-step traces and abstract scripts, retrieves them by task similarity, and revises them online through validation, reflection and deletion. On ALFWorld and TravelPlanner, agents gain success rate and need fewer steps. Memory built by a strong model also transfers to weaker models.

## Problem

- Agent procedural knowledge is hand-crafted, stored as brittle prompt templates, or entangled in model parameters that are expensive to update, so it cannot grow with experience.
- Existing memory frameworks give coarse buffers or rule chunks but leave the life-cycle of skills (build, index, patch, prune) largely unexamined and unmeasured.
- Existing memory updates usually just append new entries, so agents repeat costly exploration on similar tasks and cannot correct or discard outdated or harmful memories.

## Method

- Build: a builder turns each trajectory and its reward into memory as ==verbatim trajectories==, ==abstract scripts==, or **Proceduralization**, which combines full trajectories with a distilled high-level script.
- Retrieve: memories are stored under keys and matched to a new task by ==cosine similarity==. Keys are the raw query or **AveFact**, an average over ==LLM-extracted keyword similarities==.
- Update: an ==online mechanism== that adds, deletes and modifies memories. Variants are vanilla append, ==validation== keeping only successes, and ==adjustment==, which revises a failed memory in place using its failed trajectory.

## Results

- With GPT-4o on ALFWorld, Proceduralization lifts test success from **42.14** to **77.86** and cuts steps from **23.76** to **15.01**. The trajectory-only and script-only variants score lower.
- On TravelPlanner with GPT-4o, AveFact retrieval beats random sampling and query keys. Commonsense score rises from **71.93** to **76.02** and steps drop from **17.84** to **14.64**.
- GPT-4o memory transferred to Qwen2.5-14B raises TravelPlanner completion by **5%** and cuts **1.6** steps. Reflection-style updates gave the largest gains, cutting **14** steps by the final task group.

## Takeaways

> [!tip] Key Insights
> - Combine concrete trajectories with abstract scripts: trajectories help on tasks like those already seen, scripts generalize better to new ones, and the combination performs best.
> - Memory quality matters more than quantity: performance plateaus and then declines as more memories are retrieved, since extra items add noise and lengthen the context.
> - Procedural memory works as a portable, model-agnostic experience store. Knowledge from a strong model can be reused by smaller models without any retraining.

## Detailed Report

### 1. How this work fits into the broader research landscape

The broader research landscape involves the development of Large Language Model (LLM)-based agents capable of performing complex, long-horizon tasks. These agents, augmented with reasoning capabilities and external tools, are designed to handle sophisticated workflows, data analysis, and multi-step interactions. A central challenge for these agents is the efficient management and utilization of past experiences, particularly in dynamic environments where tasks may share underlying structural commonalities.

Existing LLM-based agents often suffer from limitations in their procedural memory. This memory, which pertains to "knowing how" to perform tasks and skills, is typically either manually engineered, embedded in brittle prompt templates, or implicitly diffused within the model's static parameters, making it difficult and costly to update. While various memory-augmented frameworks and cognitive architectures (e.g., LangGraph, AutoGPT, Memory Bank, Soar) incorporate memory components, they frequently provide coarse abstractions (buffers, rule chunks) and often do not offer a systematic approach to optimizing the lifecycle operations of procedural memory, such as how skills are constructed, indexed, updated, or pruned.

Prior works like Voyager, AWM, and AutoManual have explored the use of procedural memory to enhance agent capabilities for similar tasks. However, these efforts have not provided a systematic analysis of the entire lifecycle of procedural memory. This paper addresses this gap by investigating strategies for building, retrieving, and updating procedural knowledge in a structured, learnable, and lifelong manner for LLM-based agents. It treats procedural memory as a primary optimization objective, aiming to enable agents to continuously distill, chronicle, and re-apply lessons from their own experiential trajectories to improve performance and efficiency across diverse tasks.

### 2. Key objectives and motivation

The primary objective of this work is to investigate strategies for endowing LLM-based agents with a learnable, updatable, and lifelong procedural memory. The researchers aim to develop a task-agnostic framework, named MemP, that treats procedural memory as a first-class optimization object, allowing agents to distill past experiences into actionable knowledge.

The motivation for this research stems from several limitations observed in current LLM-based agents when performing intricate, long-horizon tasks:
- **Brittle Procedural Memory:** Existing agents' "how-to" knowledge is often manually crafted, stored as static prompt templates, or implicitly embedded within model parameters. This makes it inflexible, difficult to adapt to new situations, and expensive to update.
- **Inefficient Task Execution:** Complex tasks often require numerous steps and protracted runtimes. When unpredictable external events (e.g., network issues, UI changes) cause failures, agents must restart from scratch, leading to significant redundancy in exploration and computation.
- **Lack of Learning from Experience:** Many complex tasks share structural commonalities. However, current agents often fail to effectively extract and reuse experience from past successes or failures, preventing them from developing reusable templates of reasoning, tool sequences, or recovery tactics.
- **Unexamined Memory Lifecycle Operations:** While memory components exist in agent architectures, there is a recognized lack of systematic analysis on how procedural skills are built, indexed, patched, and eventually pruned. This absence hinders the ability to measure the efficiency of skill acquisition or to ensure that new experiences consistently improve performance without causing degradation.

By addressing these motivations, the authors aim to enable agents to progress step by step, learning from every interaction, and ultimately making even convoluted missions routine, thereby enhancing both success rates and operational efficiency.

### 3. Methodology and approach

The proposed framework, MemP, systematically explores strategies for the entire lifecycle of procedural memory, encompassing its construction (Build), access (Retrieval), and maintenance (Update). The overall framework is depicted in Figure 2 of the paper.

#### 3.1. Preliminary Foundation

The agent's interaction with the environment is modeled as a Markov Decision Process (MDP), where at each time step `t`, the agent takes an action `a_t` in state `s_t`, leading to a new state `s_{t+1}` and observation `O_t`. A complete interaction trajectory `τ` is recorded, and a reward function `R` evaluates task completion. The paper highlights that while current MDP-like approaches generate valuable contextual information, they incur high test-time costs due to redundant exploration in similar environments. MemP aims to shift from parallel to sequential task completion, allowing agents to distill experience. The agent's policy `π(a_t|s_t)` is augmented to `π_m_p(a_t|s_t)` by integrating learned procedural memory `m_p`.

#### 3.2. Memory Construction (Build)

Procedural memories (`m_p`) are constructed from task trajectories (`τ`) and their corresponding rewards (`r`). A memory builder `B` processes `τ_t` and `r_t` for each task `t`, accumulating a procedural memory library `Mem`. Two primary formats for storing procedural knowledge are investigated:
- **Trajectory:** Gold trajectories (successful execution traces) are filtered from the training set and stored verbatim, round by round. During inference, the top-k most similar trajectories are retrieved and provided as context.
- **Script:** The model analyzes and summarizes gold trajectories, distilling them into abstract, high-level procedural knowledge (scripts) which are then provided as prompts.
- **Proceduralization:** This method combines both the full retrieved trajectories and the high-level scripts, integrating concrete examples with abstract guidance.

#### 3.3. Memory Retrieval

When a new task `t_new` arrives, a procedural memory retriever recalls the most relevant memory from `Mem`. This is generally achieved by finding the memory `m_p_i` whose associated task `t_i` is most similar to `t_new`. Cosine similarity of vector embeddings (`ϕ`) of tasks is used for this matching: `m_retrieved = argmax(S(t_new, t_i))`, where `S` is the similarity function. Different key construction methods for memory storage are explored to facilitate vector-based matching:
- **Random Sample:** Memories are randomly extracted from the memory bank without using specific keys for vector retrieval.
- **Query:** The task description (query) itself is used as the key for storage, leveraging semantic similarity for retrieval.
- **AveFact:** A large language model extracts keywords from the task's query, and retrieval is based on the average similarity across these matched keywords.

#### 3.4. Memory Update

The memory update mechanism dynamically adds, deletes, or modifies procedural memories based on task execution context and feedback. The current procedural memory `M(t)` is updated to `M(t+1)` using a function `U` that considers execution feedback `E(t)` and completed tasks `τ_t`. `U` can be conceptualized as `Add(M_new) ⊖ Del(M_obs) ⊕ Update(M_est)`. Several online memory update strategies are designed:
- **Vanilla Memory Update:** After a set of `t` tasks, all trajectories from these tasks are consolidated into procedural memories and directly appended to the memory bank.
- **Validation:** After `t` tasks, only trajectories that resulted in successful task completion are extracted, abstracted into symbolic procedural memories, and added. Failed trajectories or redundant data are discarded.
- **Adjustment (Reflection):** If a retrieved procedural memory leads to a failed execution, the erroneous trajectory is combined with the original memory, revised in place, and then used to update the procedural memory.

#### 3.5. Experimental Settings

- **Datasets:** TravelPlanner (for tool-use and complex planning) and ALFWorld (for long-horizon household tasks, including a test split for generalization).
- **Backbones:** Three LLMs are used: OpenAI's GPT-4o, Anthropic's Claude-3.5-sonnet, and the open-source Qwen2.5-72B-Instruct.

### 4. Main findings and results

The experiments conducted using MemP across various configurations yielded several findings regarding the construction, retrieval, and update of procedural memory.

#### 4.1. Memory Storage & Retrieval

- **Impact of Construction Methods (Table 1):** All memory construction methods (Script, Trajectory, Proceduralization) demonstrated performance improvements over the "No Memory" baseline across both TravelPlanner and ALFWorld datasets. These improvements included higher success rates and reduced steps, indicating the benefit of distilling and reusing prior experience.
 - The "Script" method showed relatively better generalization on the ALFWorld test set, suggesting its effectiveness for tasks different from those encountered during training.
 - The "Trajectory" method performed better on the ALFWorld dev set, indicating its suitability for tasks similar to previous completions.
 - The "Proceduralization" approach, which combines abstracted guidelines (scripts) with concrete execution traces (trajectories), consistently achieved the optimal performance across both datasets and backbone models, indicating that a combination of both explicit and abstract knowledge is beneficial.
- **Impact of Retrieval Strategies (Table 2):** Compared to "Random Sample" retrieval, both "Key=Query" and "Key=AveFact" methods significantly improved performance on TravelPlanner.
 - The "Query" method benefited from capturing semantic contexts for more accurate matches.
 - The "AveFact" method, by extracting and averaging similarities of key features, focused on core task elements, leading to enhanced retrieval efficacy. This suggests that incorporating semantic understanding and key feature extraction improves memory access and downstream task performance.

#### 4.2. Memory Update

- **Effectiveness of Update Mechanisms (Figure 3):** All investigated memory update strategies (Vanilla Memory Update, Validation, Adjustment) contributed to improved performance on subsequent tasks as the memory was iteratively refreshed across task groups.
 - The "Adjustment" (reflection-based) update mechanism was identified as the most effective approach. By the final task group, this method exhibited a substantial advantage, surpassing the second-best strategy by 0.7 reward points and achieving a reduction of 14 steps. This highlights the value of continuous memory refinement guided by an error-correction process.

#### 4.3. Comparison with Baselines (Figure 4)

- On the ALFWorld dataset, MemP demonstrated superior performance compared to other baselines using GPT-4o.
 - "React" performed the worst in terms of success rates and steps.
 - "Expel" and "AWM" showed progressively better performance.
 - MemP achieved the highest success rates on both dev and test splits while requiring the fewest execution steps, indicating significant improvements in both task effectiveness and execution efficiency.

#### 4.4. Additional Analysis

- **Procedural Memory Boosts Accuracy and Cuts Trials (Figure 6):** A case study on an egg heating task illustrated that without procedural memory, the agent often performed illegal or incorrect actions, exceeding context limits or completing the task suboptimally. With procedural memory, the agent efficiently located objects and performed actions correctly and consecutively, completing the task in fewer steps (e.g., 14 steps vs. 27 steps, saving 685 tokens).
- **Transferability of Procedural Memory (Figure 5a):** Procedural memory constructed by a stronger model (GPT-4o) was successfully transferred to a weaker model (Qwen2.5-14B). The 14 billion parameter model, when equipped with GPT-4o's procedural memory, showed a 5% increase in task completion rate and a 1.6-step reduction in average steps on the TravelPlanner benchmark. Similar gains were observed on ALFWorld, confirming that knowledge from a powerful model can be distilled and effectively transferred to smaller models.
- **Scaling Memory Retrieval (Figure 5b):** As the number of retrieved procedural memories increased, the agent's performance initially improved steadily. However, retrieving an excessively large number of memories led to a plateau and then a decline in performance. This suggests that while more relevant context is beneficial up to a point, too much memory can negatively impact context length and introduce less accurate information, hindering overall effectiveness.

### 5. Significance and potential impact

The MemP framework represents an advancement in the development of LLM-based agents by systematically addressing the challenge of learnable, updatable, and lifelong procedural memory. By treating procedural memory as a core optimization target, this work provides a structured approach for agents to distill, reuse, and refine their past experiences.

The significance and potential impact of this research include:
- **Enhanced Agent Performance:** MemP enables agents to achieve higher success rates and greater operational efficiency (reduced steps and token consumption) on long-horizon, complex tasks. This is crucial for deploying agents in real-world scenarios where tasks require multi-step reasoning and interaction.
- **Continual Learning and Adaptability:** The framework's dynamic update mechanisms, particularly the reflection-based adjustment strategy, allow agents to continuously learn, correct errors, and refine their procedural knowledge while acting in dynamic environments. This fosters the development of self-improving and resilient agents capable of adapting to new information and evolving task requirements.
- **Improved Generalization:** By distilling abstract scripts and combining them with concrete trajectories, MemP facilitates better generalization to new, analogous tasks, reducing the need for extensive re-exploration.
- **Knowledge Transferability:** The demonstration that procedural memory built from stronger models can be effectively transferred to weaker models with substantial performance gains has implications for resource optimization. It suggests that high-quality procedural knowledge can be leveraged across models of varying capacities, potentially reducing computational costs associated with training and improving the capabilities of smaller models.
- **Systematic Memory Management:** MemP offers a systematic analysis of memory construction, retrieval, and update strategies, providing a foundational framework for future research into optimizing the entire lifecycle of an agent's procedural knowledge.

Despite its contributions, the paper acknowledges limitations, including the reliance on vector-similarity search with manually crafted keys and the dependency on explicit, benchmark-supplied reward signals. Addressing these limitations in future work could further enhance the framework's robustness and applicability to real-world settings where rewards are sparse or absent, moving towards a continuous loop of task execution, self-assessment, and memory refinement.
