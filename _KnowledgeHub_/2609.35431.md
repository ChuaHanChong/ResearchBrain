# Memory in the Sky: Low-Altitude Question Answering with Multi-Agent Memory Aggregation

> [!summary] Summary
> MemCen is a memory-centric resource-allocation framework for low-altitude question answering, in which memories from many UAVs are pooled at a ground server and an LLM answers questions from them. A generative adversarial exam scores each candidate memory by how many of its self-generated questions the current global memory cannot answer. UAV selection and transmit power are then optimized to maximize that score. MemCen reaches 92.4% QA accuracy in CARLA and 88.5% on real multi-UAV data.

## Problem

- Existing low-altitude wireless network designs optimize sensing coverage, throughput, control safety or computation, ignoring how much each UAV's memory actually contributes to downstream question-answering accuracy.
- Semantic communication preserves embedding similarity between transmitter and receiver, an intermediate metric that can miss subtle but critical differences in long memory contexts that decide QA answers.
- Task-oriented communication assumes closed-set tasks with known labels, but open-set QA memories must be built before questions are known, leaving no explicit, optimizable memory objective.

## Method

- ==Generative adversarial exam (GAE)==: each candidate UAV memory generates questions from verified pilot-frame facts, and the questions the current global memory cannot answer give a black-box quality-of-memory score.
- ==Memory-centric (MemCen)== formulation jointly selects UAVs and allocates transmit power under rate, deadline and power constraints. A ==QoM-aware capped water-filling== law governs UAV activation and power saturation in noise-limited regimes.
- ==Penalty successive optimization (PSO)== solves the nonconvex mixed-integer problem through convex surrogates, while ==learning to memorize (L2M)== imitates PSO decisions for low-latency inference. The ==OpenMAMS== benchmark platform is released.

## Results

- In CARLA Town04 with **10** UAVs, MemCen reaches **92.4%** QA accuracy, versus **65.6%** for throughput-maximizing ComCen, **88.6%** for sensing-centric SenCen and **41.0%** for the standalone-memory Remember baseline.
- L2M keeps **95.0%** of PSO's GAE score while cutting execution time from **4.60 s** to **0.04 s** (**115x**), and keeps at least **97.46%** of optimal QoM at unseen UAV densities.
- On real PMAS multi-UAV data, MemCen reaches **88.5%** accuracy, at least **12.0 points** above every baseline. It uploads as many memories as SenCen yet achieves **54.7%** higher summed memory quality.

## Takeaways

> [!tip] Key Insights
> - Higher communication throughput does not mean higher task utility. Redundant nearby observations consume bandwidth but add little new knowledge, so schedulers should value data by its marginal downstream contribution.
> - The open-set downstream value of data can be estimated by having an LLM examiner simulate plausible future queries, which avoids needing a differentiable captioning, retrieval and reasoning pipeline.
> - Spatial grounding remains the main failure mode: Where questions trail yes/no questions (79% versus 98%), so better memory selection improves coverage but cannot fix weak localization in captions.

## Detailed Report

### 1. Overview

Several drones can collect observations over long periods. A ground server, however, must build a queryable global memory of those observations from only a subset of their records. A strong wireless link does not tell the server which archive will make an answer possible.

The authors estimate what each candidate memory adds to the answers the deployed system can give. They then use that estimate to choose which UAV memories to upload and how to allocate power. In the tested PMAS setting, the resulting system, MemCen, answers more questions than a coverage-driven selector despite the same mean number of uploads.

### 2. Test the missing knowledge

The server has to value an archive before the user's question is known. Its exam has three steps. First, a drone uploads a representative pilot subset. The server then captions it and generates grounded question–answer pairs from verified observations. Finally, it tests whether the current global memory can answer them using the deployed retrieval-and-answering pipeline. The authors call this a generative adversarial exam (GAE).

Quality-of-memory (QoM) is the fraction of those candidate-grounded questions that the current memory cannot answer. A higher QoM means a larger measured gap in this exam and suggests greater potential utility for the candidate. It does not guarantee improvement on every future query.

Task-prior weights can favor evidence sources relevant to a mission. The authors use the weighted QoM values as an optimization-compatible approximation to marginal QA utility. The exam is a forward simulation. It rests on the authors' assumption that user questions are unpredictable but their patterns are more limited.

### 3. Spend power on useful memories

MemCen jointly selects UAV memories and assigns transmit power. The choice is subject to payload, channel, interference, per-UAV and total-power constraints. A channel-only or sum-rate objective can make poor choices: a high-value memory may have a weaker link, while a strong-link upload can be redundant.

The authors derive an allocation rule that holds in the noise-limited regime only. There, the QoM-aware capped water-filling rule:

- allocates more power to greater task-weighted QoM;
- favors smaller remaining payload;
- gives zero power to zero-QoM candidates;
- stops adding utility after upload completion.

PSO is an iterative optimization solver. L2M is a learned predictor of PSO decisions. L2M's reported 115× speedup applies to the optimization solver, compared with PSO under the same formulation. It does not establish lower GAE workload or faster end-to-end QA. In the authors' three-UAV physical setting, GAE evaluation averaged 29.96 seconds.

### 4. What the tests establish

**Simulation (CARLA Town04).** The setup has ten UAVs and a five-UAV initial memory. QA accuracy counts correctness across three question types: object presence, an explicit location within 50 m of ground truth, and which UAV saw the object. Each realization has 30 questions, and results average 20 runs. On this measure, MemCen reaches 92.4% QA accuracy versus 65.6% for ComCen, the sum-rate-maximizing baseline. Greedy is the closest accuracy baseline, at 89.8%.

**Field data (PMAS).** Each of 20 trials evaluates ten presence and ten spatial-grounding questions on field-collected aerial data. Communication is evaluated by offline channel replay, not a live wireless field test. MemCen reports 88.50±4.50% overall QA accuracy versus 76.50±8.67% for SenCen, and both average 1.90 UAV uploads. "Where" accuracy remains lower than yes/no accuracy: 79.0% versus 98.0% for MemCen.

A robot dog navigates to a basketball court, alongside first-person, third-person, and point-cloud views.

The paper also reports a single demonstration of memory reuse for embodied navigation. A user first asks whether a basketball court is present, then asks the robot dog to go there. The memory-supported system supplies a target coordinate, and the dog reaches the court.

### 5. Contribution and limits

The allocation target is evidence that changes what the ground server can answer, not the amount of traffic moved by itself. The authors conclude that GAE supplies a task-driven interface between distributed memory and wireless allocation. The evidence supports that claim in the tested settings. It is not a general guarantee for arbitrary queries, platforms, or live networks.

The released recorder and satellite-backhaul tools do not include the paper's GAE and MemCen optimization implementations ([OpenMAMS README](https://github.com/SIAT-INVS/OpenMAMS)).
