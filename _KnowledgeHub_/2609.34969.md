# NavJev: Efficient Vision-Language Navigation via Action-Centric Visual Compression and Discriminative Action-Semantic Memory

> [!summary] Summary
> NavJev is a zero-shot vision-and-language navigation framework that replaces per-step multimodal generation with text compression plus typed action selection. Action-Centric Visual Compression turns each candidate waypoint into geometry, a BLIP caption and RAM tags; Discriminative Action-Semantic Memory strips shared tags and logs action evidence; Jev picks an option label. On R2R-CE it reaches 27.0% SR, 22.4% SPL at 0.65 s per step.

## Problem

- Zero-shot MLLM navigators such as Open-Nav, SmartWay and P2DNav invoke autoregressive multimodal reasoning every step, costing roughly 5 to 27 seconds per step and limiting real-time responsiveness.
- Each step's decision is structurally a choice among a few waypoints or stop, yet prior methods encode full images and generate free text, a costly mismatch.
- Plain text descriptions of neighboring candidate directions share most scene semantics, so redundant tags bloat the state while giving little signal for discriminating between actions.

## Method

- **Action-Centric Visual Compression** (**ACVC**): binds each waypoint's motion description, heading and distance to a ==BLIP== caption and ==RAM== tags from its nearest sub-view, computed in parallel deduplicated batches.
- **Discriminative Action-Semantic Memory** (**DASM**): ==Common-Tag Filtering== moves tags shared by all candidates into one scene context, and each executed action with its filtered evidence is appended to history.
- **Typed navigation decision**: **Jev**, a ==non-autoregressive Choice model==, takes the instruction plus structured action-semantic state and outputs a probability over option labels mapped to waypoints or STOP.

## Results

- On 100 R2R-CE val-unseen episodes NavJev reaches **27.0%** SR and **22.4%** SPL, versus **19.0%**/**16.1%** for Open-Nav with GPT-4o, and matches SmartWay's **22.5%** SPL.
- Step time is **0.65 s** versus 27.0, 5.3 and 4.92 s for Open-Nav, SmartWay and P2DNav; GPT-4o on the same representation costs **$3.67** versus **$0.06** and gets **14.0%** SR.
- Adding DASM lifts SR from **21.0%** to **27.0%** and SPL from **16.1%** to **22.4%**; real office and cafe tests give **50.0%** SR versus **35.0%** for Qwen3.8-Max.

## Takeaways

> [!tip] Key Insights
> - When the action space is a small finite set, a classifier-style selection model over text states can replace autoregressive generation with large latency and cost savings.
> - Removing semantics shared by all options helped more than adding richer descriptions; contrast between choices, not total information, drives selection quality.
> - Caution: compressing vision into captions and tags loses fine spatial relations; 82% of failures were wrong waypoint picks, and P2DNav still reaches much higher SR.

## Detailed Report

### 1. Overview

NavJev targets a practical bottleneck in vision-and-language navigation. An agent follows a natural-language instruction through an unfamiliar continuous indoor space and sees a panoramic view at each location. At each step, it ultimately chooses among a small set of reachable waypoints or stops. Invoking an autoregressive multimodal model at every step can make this loop slow. NavJev instead describes those options compactly, keeps track of what distinguishes them, and asks Jev to choose among typed options rather than generate open-ended reasoning.

### 2. Turning observations into choices

Jev's typed Choice interface selects among predefined alternatives and returns a probability distribution without generating text token by token. The TypeSafe AI post [“Introducing System One Models & Jev”](https://typesafe.ai/blog/introducing-system-one-models-and-jev) introduced this structured-decision idea. Jev had operated on textual or structured states. The open problem was translating rich visual observations into compact, discriminative states.

NavJev begins with a panoramic RGB-D observation. From it, NavJev forms up to five navigable waypoint candidates, and each represents a local direction and distance. For each candidate, BLIP supplies a short visual caption and RAM supplies semantic tags. These are combined with the candidate's motion description, heading and distance. The resulting description says both where that action goes and what is seen along it. The paper calls this step Action-Centric Visual Compression (ACVC).

Discriminative Action-Semantic Memory (DASM) then finds the RAM tags shared by all current candidates. It keeps them once as shared scene context and removes them from each action's tag set. After an action is executed, its motion, heading, distance, caption and filtered tags are appended to the ordered navigation history. Jev receives the instruction, this structured state and the available action labels. The selected label maps to a waypoint command or STOP, and the cycle repeats.

Overview of NavJev, from left to right: an instruction and panoramic view, waypoint prediction, and candidate descriptions with motion, heading, distance, a BLIP caption and RAM tags. These lead to shared-tag filtering, an action-semantic memory table, and Jev selecting a typed option. The probabilities shown are illustrative values in the diagram, not benchmark measurements.

### 3. What the comparisons establish

Testing used 100 episodes of R2R-CE val-unseen under the Open-Nav evaluation framework. SR, the success rate, counts successful termination within the goal region. SPL weights success by path length, so it reflects path efficiency.

The first comparison supplies the same ACVC–DASM state to each decision model, with reasoning disabled for the autoregressive comparators. Under these conditions, NavJev records 27.0% SR and 22.4% SPL, while Qwen3.8-Max records 25.0% SR and 16.0% SPL. NavJev's average wall-clock time per step is 0.65 seconds, compared with 1.15 for Qwen3.8-Max. Its total API cost is $0.06, compared with $2.19. Step time and API cost are separate measures. These results do not establish fewer generated tokens or fewer attempts. The comparison also involves different models, so it does not prove that output typing alone explains every difference.

The second comparison is a component ablation. With BLIP captions alone, SR/SPL are 19.0/14.4. Adding RAM without DASM gives 21.0/16.1, and adding DASM gives 27.0/22.4. Not every measure improves monotonically: nDTW is 36.2 with BLIP alone, falls to 35.0 with RAM and no DASM, and reaches 43.5 with DASM. This supports the combined DASM component. It does not separate the contribution of common-tag filtering from that of retaining action-specific evidence across steps.

### 4. Boundaries

This is a 100-episode zero-shot evaluation. It is not evidence that NavJev is the most accurate navigator: P2DNav scores higher on SR and SPL. Among NavJev's 73 failed episodes, 60 are attributed to incorrect waypoint selection.

NavJev's contribution is a proposed way to preserve useful navigation cues while avoiding repeated multimodal generation. Its efficiency claim concerns inference and elapsed time under the reported comparisons. It is not a general solution to fine-grained spatial grounding.
