# ProAct-VLM: Pre-Failure Vision-Language Task Replanning with Continuous Perception Feedback

> [!summary] Summary
> ProAct-VLM is a closed-loop robot task planner that uses a pre-trained VLM as a black-box planner and runs a real-time perception pipeline alongside it. A plan monitor watches for objects being added or removed and for goal changes, and re-plans before a failure happens. On a real Franka sorting task, Gemini 2.5 Pro reached 100% success and efficiency across seven disturbance scenarios.

## Problem

- Most VLM and LLM task planners work offline: they plan once at the start and assume the environment will not change during execution.
- Replanning frameworks such as Replan and ReplanVLM are reactive: they replan only after an execution failure or a failed post-task goal check, so the robot may already have done wasteful or damaging actions.
- Scene-graph and object-centric methods check the scene only before and after each action, so changes that happen during an action go unnoticed and invalid actions proceed.

## Method

- **Environment State Estimator**: ==Grounded-SAM== detection, ==DeAOT== mask tracking and CAD-based ==FoundationPose== 6-DoF pose tracking produce a structured state with persistent object IDs, at roughly 30 Hz tracking.
- ==Comparing Mask Results (CMR)==: every n frames detection runs again, and a mask counts as a new object if more than half of it lies in the tracked background; it then gets a fresh ID.
- ==Plan Monitor== plus ==instance-level prompting==: a binary trigger fires on object added, object removed or goal changed, then re-prompts the VLM with an image overlaid with object IDs and their class labels.

## Results

- Backbone ablation, 7 scenarios with 10 trials each: Gemini 2.5 Pro **100% success and 100% efficiency**, **GPT-4o 89%/93%**, **Llama 4 Maverick 70%**, **Qwen 2.5-VL 40%**, **Claude Opus 4 21.4%**.
- Grounding comparison with GPT-4o: ID-overlay prompting averages **89% success** versus **83% for OWG**, **61.4% for LLM3+Image** and **50% for VILA/ReplanVLM**; Llama 4 shows 70% versus **47.1-52.5%**.
- VILA/ReplanVLM scores **0%** on scenarios with identical duplicate objects (S2, S7), and about **30%** of OWG failures come from the VLM misclassifying objects.

## Takeaways

> [!tip] Key Insights
> - Running a cheap perception loop all the time and calling the expensive VLM only when a change is detected gives mid-action awareness without paying VLM latency on every frame.
> - VLMs resolve which-instance questions better from IDs drawn on the image than from coordinates written in text; visual instance grounding beats structured positions.
> - Let specialist detectors supply object class labels instead of asking the VLM to recognize objects; the VLM's own misclassifications become direct planning errors.

## Detailed Report

### 1. Overview

A robot is sorting objects into baskets and has already begun its plan when a new object appears. A plan that made sense at the start can become unsafe or useless when the scene changes while the robot is acting. The authors' system keeps tracking the scene during execution. When it detects a relevant change, it sends the planner an updated view instead of waiting to learn that the old plan failed. In the paper's pictured real-robot trial, the new object is detected, the plan is revised, and the updated plan is executed successfully. That trial shows the loop can respond. It does not establish that the object would otherwise have caused a failure. The system is called ProAct-VLM, and the authors frame its approach as "pre-failure" replanning.

A setup photograph and numbered robot-view screenshots 1–12 from an added-object episode. The paper identifies screenshot 8 as the point where the added object is detected. Screenshots 9–12 show execution of the updated plan.

### 2. A plan that can notice change

The planner is a VLM, a model that reasons over both visual and text input. A task prompt and the current scene go to the VLM, which returns symbolic actions referring to individual object IDs. A low-level planner then maps those IDs to poses and executes trajectories.

Meanwhile, an environment estimator tracks a structured state: object identities, class labels, 6-DoF poses, and an image annotated with IDs. During execution, a monitor compares the current state with the prior state. Object addition, object removal, or a user-supplied goal change can trigger replanning. When that happens, execution stops, the current state is included in a new prompt, and the VLM produces a revised plan.

Perception combines several tools. Grounded-SAM pairs Grounding DINO detection with SAM segmentation. DeAOT tracks object masks between detections. Model-based FoundationPose estimates and tracks 6-DoF poses using CAD models. Periodic detection checks for new objects against the tracked scene, assigns new IDs, and updates the tracked state.

Monitoring is continuous at the perception level. The VLM is called initially and again only when a relevant change triggers a new plan. On an RTX 4090 workstation, tracking runs at about 30 Hz and periodic full updates take about 200 ms each. The authors report effective monitoring above 20 Hz in practice.

System-flow illustration. A user's planning prompt and a VLM-produced pick/place plan pass through the environment-state estimator and plan monitor to replanning and the low-level planner/robot. Added, removed, or changed goals act as monitor triggers.

### 3. What the tests establish

In the main evaluation, a real Franka arm sorts YCB objects into baskets by category. Seven scenarios vary object additions, removals, and goal changes at different stages, and each scenario was run for 10 trials. Success rate is the share of trials in which the intended goal was achieved.

Efficiency is the shortest possible number of primitive actions divided by the number in the VLM plan, multiplied by 100. It is computed only for successful plans and counts redundant actions. It measures action-plan efficiency, not elapsed time.

With Gemini 2.5 Pro as the backbone, the system reached reported averages of 100% success and 100% efficiency. Claude Opus 4 averaged 21.4% success and 38% efficiency, which shows substantial dependence on the VLM backbone.

A separate comparison tests the grounding prompt rather than replanning timing. For GPT-4o, the paper reports 89% average success with its prompt, versus 83% for Open-World Grasper (OWG) and 61.4% for LLM3+Image across the seven scenarios. The authors' explanation is that their prompt pairs an image annotated with object IDs with explicit class labels, while OWG asks the VLM to infer categories from the annotated image. These are comparisons between bundled prompt configurations. There is also an exception: for LLaMA 4 Maverick in S4, "Ours" scores 10% and OWG scores 20%.

Success rates (%) by backbone, prompt, and scenario. For GPT-4o, the averages are 89 (Ours), 83 (OWG), and 61.4 (LLM3+Image). For LLaMA 4 Maverick in S4, Ours scores 10 and OWG scores 20.

The paper characterizes reactive methods such as ReplanVLM ([paper](https://www.alphaxiv.org/abs/2407.21762)) and REPLAN ([paper](https://www.alphaxiv.org/abs/2401.04157)) as replanning after task execution or failure. Its comparison with them is descriptive and covers object addition and removal. It omits goal changes because the original methods do not model mid-execution instruction updates. The paper reports no quantitative test that holds everything constant except the replanning trigger.

### 4. The loop's boundary

The established contribution is a working real-robot system that refreshes its view of a changing scene and can ask the planner to replace a plan before finishing it. This is task-level replanning; the paper presents adaptive motion planning as future work. The implementation assumes a predefined relevant-object vocabulary and CAD models for pose estimation. It was not evaluated under heavy perception noise or extreme clutter.
