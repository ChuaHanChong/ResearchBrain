# Scope-WM: Scoped Computation for Efficient Visual World Models

> [!summary] Summary
> Scope-WM is a sparse visual world model built on DINO-WM that limits computation to the latent tokens that matter for prediction and to promising action sequences. A distilled action-conditioned selector picks which tokens get full dynamics prediction. A pooled foreground-delta context cheaply updates the remaining background tokens. An elite-bank CEM planner reuses good early plans. On Push-T it plans 6.97x faster and keeps 88% success.

## Problem

- Dense patch-level world models like DINO-WM propagate every visual token across long horizons for many CEM samples, so planning latency and peak memory block real-time deployment.
- Sparse imagination methods either drop tokens at random, ignoring the prediction objective and capping safe sparsity, or add heavy localization and cross-attention modules with multi-stage training.
- Cheaper rollouts alone do not fix sample-intensive CEM planning, and visual-change heuristics miss tokens that matter dynamically but look static, such as contacts and obstacles.

## Method

- **Distilled Relevance Selection (DRS)**: a small token-wise MLP conditioned on state and action, distilled by ==KL== from a dense teacher's gradient-times-input relevance scores, selects the top-K foreground tokens.
- **Foreground-Delta Background Update (FDBU)**: mean-pooled foreground states and predicted deltas drive a ==gated residual update== of background tokens, avoiding token-to-token attention; trained jointly with the sparse predictor under a full-grid loss.
- **Elite-Bank CEM (EB-CEM)**: front-loads the sampling budget (300 samples at the first ==MPC== step, 100 later) and stores the best initial sequences, which seed perturbed local proposals during later replanning.

## Results

- On Push-T, the K=32 configuration keeps **88%** success versus **90%** for dense DINO-WM while cutting FLOPs **6.05x**, planning time to **14.3%**, and peak GPU memory to **18.1%**.
- The K=98 configuration raises Push-T success to **94%** at a **2.59x** speedup and reaches **100%** on PointMaze and **0.22** Chamfer distance on Granular, but Rope degrades (**0.71** versus **0.41**).
- Ablations at K=32: random selection **76%**, background copy **56%**, standard CEM **82%**, full model **88%**. EB-CEM matches 200-sample CEM's **88%** in 34.6s instead of 61.0s.

## Takeaways

> [!tip] Key Insights
> - Distilling a teacher's own gradient-based prediction relevance gives a better sparsity signal than attention or visual-change heuristics, because it captures dynamically important but visually stable regions.
> - Token selection and background propagation are strongly coupled: good selection without background updates performs worst, so sparse world models must treat both parts as one design.
> - Efficiency gains compound across levels. Front-loaded search helps only when rollouts are cheap, and it hurt dense DINO-WM, so planner budgets should match model cost.

## Detailed Report

### 1. Overview

In visual robot planning, a model must repeatedly imagine what could happen under many candidate actions. Propagating every image feature through every imagined future makes planning slow and memory-intensive. Scope-WM addresses this in three ways. It picks the image patches likely to matter for predicting a planned action. A lightweight update carries the rest of the scene forward. Good action sequences from an initial broad search are saved and refined later.

The clearest test is Push-T, a visual task that involves moving a T-shaped object toward a goal. There, Scope-WM's aggressive setting applies full dynamics prediction to 32 rather than 196 image tokens. It attains 88% success versus dense DINO-WM's 90%. It also reduces cumulative planning time from 240.96 s to 34.56 s (6.97× speedup) and peak GPU memory from 18,436 MB to 3,334 MB.

Push-T. (a) Success rate versus full-dynamics token ratio: Dense (100%) 90%, Fast (50%) 94%, Faster (16%) 88%. (b) Planning time is 100/38.6/14.3% of Dense, and peak GPU memory is 100/38.4/18.1%. Fast and Faster run 2.59× and 6.97× faster.

Planning time here is cumulative CEM sub-planner time across MPC steps. Peak memory is the maximum CUDA allocation during an evaluation run. For Push-T, success requires a position error below 20 and an orientation error below $\pi/9$.

### 2. Predict selected regions, update the rest cheaply

Scope-WM builds on DINO-WM, which predicts future patch-level visual features from a frozen DINOv2 encoder. DINO-WM plans with model-predictive control (MPC), which repeatedly plans, acts, then replans.

Scope-WM's Distilled Relevance Selection (DRS) uses a dense DINO-WM teacher's prediction loss to estimate which input tokens affect prediction error. It then trains a small selector conditioned on image token, action, and proprioceptive state, and keeps the top K. The selection is therefore prediction-aware. It does not rely only on visual change.

The sparse dynamics model predicts the selected foreground tokens. Foreground-Delta Background Update (FDBU) then pools the predicted foreground state and its change. It uses that context for a lightweight gated residual update of each background token, which avoids dense token-to-token interactions.

### 3. Spend the search budget unevenly

The planner uses the cross-entropy method (CEM), which evaluates candidate action sequences by rolling them through the model. In Scope-WM's version, Elite-Bank CEM (EB-CEM), a larger initial search stores high-quality action sequences. Later replanning steps perturb some banked sequences to refine them and sample the rest from the current CEM distribution. The main configuration uses 300 candidates initially and 100 later. DRS and FDBU reduce the cost of each rollout. EB-CEM reallocates search across replanning steps.

Push-T planner comparison, with Scope-WM at K=32. Samples are initial/subsequent MPC-step budgets.

The table shows a benefit that depends on the model. On Push-T, Scope-WM with ordinary CEM needs 60.96 s to reach 88% success at 200/200 samples. EB-CEM reaches the same success in 34.56 s with 300/100 samples. On dense DINO-WM, EB-CEM does not help: success falls from 90% to 84%, while planning time rises from 240.96 s to 267.36 s. The evidence supports a benefit for the sparse Scope-WM setup. It does not show a universal benefit from front-loading samples or reusing elites.

### 4. Where the gains weaken

Across five tasks, Rope is a meaningful performance exception. Rope is scored by Chamfer Distance, the symmetric average nearest-neighbor distance between the final and goal particle sets, where lower is better. The best Scope-WM Chamfer Distance on Rope is 0.71, versus 0.41 for dense DINO-WM.

Memory savings also vary by task. On Wall, peak memory is 125.8% of dense, partly because EB-CEM's initial search population is larger. The token budget is fixed at training time: Fast and Faster were trained independently for K=98 and K=32.

### 5. Spend compute where it matters

Scope-WM combines prediction-focused token selection and cheaper background updates with a planner that reuses promising searches. On Push-T, this yields nearly dense-level success with much less planning time and memory. The tested benefit is a task-specific trade-off: Rope performance and Wall memory both run the other way.
