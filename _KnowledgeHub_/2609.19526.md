# Self Improvement via Fast Tree-search

> [!summary] Summary
> SIFT (Recursive Self-Improvement via Fast Tree-search) is a self-improving coding-agent framework that replaces most expensive benchmark evaluations with pairwise LLM-as-a-judge comparisons between candidate patches, aggregated by a regularized Bradley-Terry model into strength scores that drive rank-based parent sampling inside a disaggregated tree search. It reaches 35.1% on Polyglot with o3-mini in under 5 hours wall-clock and 42 CPU hours, beating DGM and HGM baselines.

## Problem

- Prior self-improving agents such as Gödel Agent, SICA and DGM validate every candidate patch against a full benchmark suite, costing thousands of CPU hours and up to $22,000 per run.
- Cheaper alternatives that evaluate on small randomly sampled task subsets yield noisy strength estimates, since nodes drawing easier tasks score highly by chance rather than by merit.
- Because expansion blocks on slow benchmark runs, tree search stalls: the evaluation bottleneck, not candidate patch generation, dominates wall-clock time in prior self-improvement loops.

## Method

- **Pairwise LLM-as-a-judge**: each new candidate harness is compared, using full post-patch files rather than diff chains, against the archive's top-10 incumbents, each verdict logged as one win or loss.
- **Regularized Bradley-Terry aggregation** with a pseudo-count smoothing term, solved by ==minorization-maximization fixed-point updates==, converts sparse and inconsistent pairwise wins into one global latent strength score per node.
- **Disaggregated tree search**: parent sampling mixes Bradley-Terry rank, accuracy rank and a log visit-count exploration penalty, while a ==priority queue== runs full evaluation in parallel with continued expansion.

## Results

- On Polyglot-225 SIFT reaches **35.1%** with o3-mini and **32.0%** with Qwen3-Coder-30B, above DGM's **30.7%** and HGM's **30.5%**, using **42-224** CPU hours against HGM's **347**.
- On TerminalBench the judge's rank-1 agent repeats at **36.7%**, versus **28.1%** for the accuracy-rank-1 agent and **29.2%** for the no-judge ablation; SWE-60 pools **52.1%** against **47.5%**.
- Judge-input ablation: full files give Spearman correlation **0.68** with realized accuracy versus **0.40** for diff chains at **$0.011** per comparison; removing the exploration term drops Polyglot to **30.1%**.

## Takeaways

> [!tip] Key Insights
> - Cheap noisy relative preferences can steer expensive search: using judge scores only through induced ranks removes any need for the judge to be calibrated.
> - Search-time accuracy on small subsets is an unreliable selector; a code-reading judge catches failure modes, like a flag-gated dead verifier, that benchmark scores never surface.
> - Weaker judges keep global ranking correlation but degrade at the frontier top, suggesting a tiered setup: cheap judge for bulk comparisons, stronger judge for final selection.

## Detailed Report

### 1. Position Within the Broader Research Landscape

This paper addresses recursive self-improvement in coding agents, a research area concerned with allowing an AI system to modify the code that defines its own operation. The underlying idea has theoretical roots in Schmidhuber’s Gödel Machine, which proposed that a self-referential program could identify and implement provably beneficial self-modifications. More recent empirical systems, including Gödel Agent, SICA, the Darwin-Gödel Machine (DGM), and the Huxley-Gödel Machine (HGM), have shown that language-model-based agents can generate modified versions of their own harnesses and evaluate whether those changes improve coding performance.

Existing systems generally represent self-improvement as a search tree. Each node is an agent implementation, and each child is produced by asking a self-improvement model to diagnose weaknesses and create a code or prompt modification. The child must then be evaluated on coding tasks. Systems differ in how they select parent nodes, preserve diversity, and allocate evaluation resources. DGM maintains an archive of strong agents, HGM uses lineage-level productivity signals, and other work has explored crossover, multi-agent evolution, and workflow search.

SIFT contributes primarily to the efficiency of this process. The authors argue that candidate generation is not the main bottleneck; instead, the expensive downstream evaluation required to determine whether each candidate is useful dominates computational and financial cost. SIFT therefore combines two research directions: recursive agent evolution and pairwise LLM-as-a-judge ranking. It uses a judge model to provide an inexpensive, relative assessment of candidate implementations, then aggregates those assessments with a Bradley–Terry model. This signal is used to guide tree exploration before full benchmark results are available.

The work is also related to automated agent design systems such as ADAS and AFlow, which search over agent architectures or workflows. Its distinctive setting is recursive modification of a functioning coding-agent harness, rather than one-time design of a workflow.

### 2. Objectives and Motivation

The central objective is to improve coding-agent performance while reducing the resources required for recursive self-improvement. Prior approaches commonly evaluate each candidate on a subset of benchmark tasks before deciding whether to expand it further. Although this provides behavioral evidence, even partial benchmark evaluations can require substantial API usage, CPU time, and wall-clock time. The paper cites previous self-evolution experiments that incurred costs of thousands of CPU hours and, in some settings, tens of thousands of dollars.

The authors identify a signal-to-cost trade-off. Full benchmark evaluation provides relatively reliable evidence but is expensive. Evaluating a smaller random task subset is cheaper but introduces noise, because a candidate may appear strong or weak based on the particular tasks it receives. In addition, waiting for evaluation results makes the search sequential and prevents the system from generating new candidate agents while evaluations are still running.

SIFT is motivated by the hypothesis that a language model can provide useful intermediate information by comparing two agent implementations directly. The judge does not execute benchmark tasks or observe their outcomes. Instead, it examines the candidate code and ranks which implementation is more likely to improve coding performance. Such judgments are not expected to replace benchmark validation. They are intended to prioritize exploration and evaluation.

The paper has several specific goals:

1. To replace some per-candidate benchmark evaluations with cheap pairwise preference judgments.
2. To aggregate sparse and potentially inconsistent judgments into a global ranking using a regularized Bradley–Terry model.
3. To combine judge rankings with measured task accuracy and an exploration term in a disaggregated tree-search process.
4. To determine whether this approach improves final benchmark performance under fixed resource constraints.
5. To test whether the resulting agent harnesses transfer across different coding models and benchmarks.

### 3. Methodology and Approach

#### 3.1. Recursive Self-Improvement Loop

The system begins with a base coding agent. A separate diagnosis and self-improvement model examines the agent’s source code, previous evaluation information, and failure traces. It then proposes a patch that produces a child agent. The child is tested and eventually evaluated on coding tasks. This process is repeated, forming a tree of agent versions.

SIFT maintains an archive containing candidate agents, their benchmark results, pairwise judge outcomes, and the number of times each node has been selected as a parent.

#### 3.2. Pairwise LLM Judging

After a new candidate is generated, a judge model compares it against a small number of existing agents. The default configuration compares the candidate with up to ten strong incumbent nodes. The judge receives the complete contents of the runtime files that differ between candidates, rather than only a sequence of patches. It is asked to rank the candidates according to their likely effect on agent performance and correctness.

The authors test several input formats. Providing only diffs produces a Spearman correlation of approximately 0.40 between judge ranking and realized Polyglot accuracy. Providing complete files increases the correlation to 0.68. Presenting candidates in both comparison orders approximately doubles cost without materially improving the correlation, so the default system uses full files without swap-ordering.

#### 3.3. Bradley–Terry Aggregation

Each judge comparison produces one win and one loss in a global comparison matrix. SIFT fits a regularized Bradley–Terry model, in which each agent has a latent positive strength parameter \(\theta_i\). The probability that agent \(i\) is preferred over agent \(j\) is modeled as:

\[
P(i \succ j)=\frac{\theta_i}{\theta_i+\theta_j}.
\]

A pseudo-count regularizer is added to every pair so that newly generated nodes with few comparisons do not receive unstable or unbounded scores. The fitted strengths are normalized and converted into ranks. SIFT uses these ranks rather than the raw score magnitudes.

#### 3.4. Parent Sampling and Exploration

Parent selection combines three signals:

- The Bradley–Terry judge rank.
- The rank based on measured benchmark accuracy.
- A visit-count penalty that reduces the probability of repeatedly selecting the same node.

The sampling probability is proportional to:

\[
\exp[-\alpha r_b(i)-\beta r_a(i)-\eta\log(1+v_i)],
\]

where \(r_b\) is judge rank, \(r_a\) is accuracy rank, and \(v_i\) is the number of times node \(i\) has been selected. The reported experiments use \(\alpha=\beta=\eta=1\). The visit term encourages branching and reduces excessive concentration on a single lineage.

#### 3.5. Disaggregated Evaluation Pipeline

SIFT separates expansion, judging, and benchmark evaluation. A new candidate first passes an easy gate that filters out broken patches. It is then judged against strong archive members and inserted into a priority queue. Full benchmark evaluations are launched according to judge and accuracy priority, while new self-improvement expansions proceed asynchronously.

Candidates that have not completed full evaluation temporarily inherit their parent’s accuracy for sampling. This allows a strongly judged candidate to influence future exploration before its expensive benchmark run finishes.

#### 3.6. Experimental Settings

The principal benchmark is Aider Polyglot, which contains 225 multilingual coding tasks. During search, the authors use a four-task gate and a fixed 50-task subset called Polyglot-50. The full 225-task benchmark is reserved for final evaluation. Experiments are performed in sandboxed Docker containers.

The authors also evaluate SIFT on TerminalBench 2.1 and SWE-60, a 60-task subset of SWE-bench Verified. Comparisons include SICA, DGM, HGM, and no-judge ablations. Resource use is reported in API cost, CPU hours, and wall-clock time.

### 4. Main Findings and Results

#### 4.1. Polyglot Performance and Cost

With Qwen3-Coder-30B as the coding model, the base agent achieves 20.0% on Polyglot-225. SICA, DGM, and HGM reach 25.1%, 27.1%, and 30.5%, respectively. SIFT reaches 31.1% with Qwen3-480B as the judge and 32.0% with gpt-5.4 as the judge.

Using o3-mini as the coding model, the base agent scores 14.2%. DGM reaches 30.7%, while SIFT reaches 35.1% with gpt-5.4 as judge and 31.6% with gpt-5-mini. A no-judge SIFT configuration reaches 29.8%, indicating that the judge contributes to the strongest result in this setting.

One Qwen3-30B run reaches 31.1% after 30 expansion steps at an API cost of $34.30, 224 CPU hours, and 6.7 hours of wall-clock time. The paper reports that this uses substantially fewer CPU hours than the cited DGM and HGM searches. A separate o3-mini experiment is reported as completing in under five hours and 42 CPU hours, although the resource table gives a different configuration involving 20 expansion steps, 59 CPU hours, and $86.80. These figures reflect different runs rather than a single uniform configuration.

The search-time Polyglot-50 accuracy increases during evolution, but it is not always a reliable indicator of final performance. This supports the authors’ argument that benchmark accuracy alone is too noisy for prioritizing every node.

#### 4.2. TerminalBench Results

On TerminalBench, the starting agent scores 14 out of 50 on the search subset and averages 29.2% on repeated full-benchmark evaluations. The agent selected by the highest SIFT judge rank scores 18/50 during search but achieves 36.7% on repeated full evaluations. By contrast, the candidate with the highest search-subset accuracy achieves 28.1% on the full benchmark, and the no-judge baseline achieves 29.2%.

Across fully evaluated nodes, judge rank correlates with final benchmark accuracy at Spearman \(\rho=0.72\). A weaker gpt-5 judge produces a similar overall correlation of \(\rho=0.71\), but is less accurate among the top five candidates. The results suggest that judge rankings are useful for identifying promising regions of the search tree, while a stronger judge may be needed for final selection among closely matched candidates.

#### 4.3. SWE-60 Results

On SWE-60, the starting agent scores 40.0%. The judge-guided search produces selected candidates with repeated mean accuracies of 50.4% and 53.8%. The no-judge search produces corresponding means of 44.6% and 50.4%. Pooled results are 52.1% for SIFT and 47.5% for the no-judge ablation.

The paper gives qualitative examples in which the judge favors conservative improvements to patch application, including support for full-file and add-file patch wrappers. It also identifies risks in proposed modifications, such as silent misapplication of edits.

#### 4.4. Qualitative and Ablation Findings

The authors observe that useful modifications are often small and located on the agent’s active execution path. One example adds a test-running tool and instructs the agent to use iterative test feedback; a more elaborate descendant adds a test analyzer but performs worse. This suggests that additional machinery can introduce runtime or regression risks.

Ablation results indicate that asynchronous disaggregation accounts for most of the speedup. Speculative expansion based on judge rankings provides additional gains by allowing the system to continue exploring before full evaluations finish.

The discovered harnesses also transfer across coding models. Harnesses evolved with o3-mini and Qwen3-Coder-30B improve performance when evaluated with other models, including gpt-5-mini and gpt-5.4-mini.

### 5. Significance and Potential Impact

SIFT’s principal significance is methodological. It separates inexpensive candidate ranking from expensive behavioral verification. This enables recursive self-improvement systems to explore more agent modifications under fixed compute and financial budgets.

The approach could make experiments on self-improving coding agents more accessible and could be applied to other agent-design problems in which candidate implementations are expensive to test. The use of pairwise comparisons also avoids requiring the judge to produce calibrated absolute scores.

However, the results do not establish that judge evaluation can replace benchmark testing. SIFT still depends on downstream evaluations for validation, and the strongest configurations use a judge model more capable than the coding model. Bradley–Terry ranking also reduces agent quality to one scalar, which may obscure task-specific tradeoffs. A modification that helps debugging may harm simpler repair tasks.

There are additional evaluation-integrity and safety concerns. Self-modifying agents may attempt to alter timeouts, retry limits, or benchmark code. The authors mitigate these risks with sandboxing, restricted writable files, and explicit rejection of harness modifications. Future systems will require these safeguards, as well as methods for detecting benchmark overfitting and task-specific exploitation. Overall, the paper presents SIFT as a resource-allocation mechanism for recursive agent evolution, with empirical evidence that cheap preference signals can improve search efficiency when combined with, rather than substituted for, behavioral evaluation.
