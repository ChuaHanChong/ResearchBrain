# RESOURCE2SKILL: Distilling Executable Agent Skills from Human-Created Multimodal Resources

> [!summary] Summary
> Resource2Skill presents a framework to automatically distill executable skills for software agents from diverse human-created multimodal resources, particularly tutorial videos. The system improved agent performance by an average of +11.9 percentage points across seven software-authoring domains, and human evaluators favored its outputs in 85.5% of non-tied ratings.

## Problem

- Existing LLM agents struggle to acquire complex, multi-step software operation skills from diverse human-created multimodal resources, such as tutorial videos.
- Current skill acquisition methods are limited to hand-authoring, agent-generated traces, or text/code mining, missing rich procedural and perceptual information embedded in multimodal formats.
- Directly integrating raw high-dimensional multimodal data into agent memory is computationally inefficient and fails to preserve precise, actionable information.

## Method

- The **Resource2Skill** framework employs a ==four-stage pipeline== (construction, wiki organization, selection, execution) to distill executable skills from multimodal resources into a ==Hierarchical Multimodal Skill Wiki==.
- Each skill is represented as a multimodal tuple `(p, x_text, x_visual, x_code, m)` including a taxonomy path, structured prose, visual examples, and executable code fragments.
- A ==Multimodal Distiller==, powered by a vision-capable LLM, extracts and distills modality-specific evidence from various resource types, with a domain-specific ==acceptance predicate== validating candidate skills.

## Results

- Resource2Skill agents achieved an average overall score of **56.8%** compared to **45.0%** for agents without skills, representing a statistically significant average improvement of **+11.9 percentage points** across seven diverse domains.
- Human A/B studies corroborated these findings, with human evaluators preferring outputs from agents utilizing Resource2Skill in **85.5%** of non-tied ratings.
- Performance scaled monotonically with skill library size, with online acquisition boosting mean scores on stress-test tasks by **+21.6 percentage points**, demonstrating adaptive capability.

## Takeaways

> [!tip] Key Insights
> - Distilling procedural knowledge from multimodal human-created resources significantly enhances agent capabilities for complex software-authoring tasks.
> - A hierarchical organization and multimodal skill representations (text, visual, code) provide substantial performance benefits over flat, text-only skill libraries.
> - Online skill acquisition effectively fills capability gaps, enabling agents to dynamically extract and apply new skills from resources for novel task requirements.

## Detailed Report

### 1. Broader Research Landscape

This work is situated within the evolving landscape of large language model (LLM) agents, which are increasingly expected to perform complex, multi-step tasks involving software operation, tool invocation, and artifact generation. Contemporary LLM agents often rely on reasoning and execution capabilities to interact with external environments. A key abstraction in this field is the concept of "skills," representing reusable procedural knowledge that can convert observations into actionable instructions, code fragments, and execution recipes.

Prior skill-based agent systems have demonstrated the value of such abstractions, particularly in text-heavy workflows like programming and document editing. However, existing methods for skill acquisition typically involve hand-writing by experts, accumulation from an agent's own interaction traces, or mining from predominantly text- or code-based resources. This approach leaves a significant volume of human-created knowledge unaddressed, particularly multimodal resources such as tutorial videos, which are a common and effective learning method for humans interacting with commercial and creative software. Videos convey temporal operation sequences, visual effects of editing steps, and tacit design choices that are challenging to articulate through text alone.

Resource2Skill addresses this gap by focusing on the automatic distillation of skills from diverse multimodal human-created resources. It differentiates itself from existing skill-library frameworks, such as those that grow text- or code-only libraries from agent traces (e.g., Voyager, AWM, ASI, SkillFlow) or rely on hand-authored skill bundles (e.g., Anthropic Agent Skills). While SkillFoundry explores mining text/code skills offline into a knowledge tree, Resource2Skill specifically integrates multimodal input, a hierarchical wiki interface, artifact-level evaluation, and controlled online skill acquisition across a broader range of authoring domains. The framework also distinguishes itself from approaches that consume raw multimodal resources only for pretraining or retrieval context by instead distilling them into a structured, validated, and executable format.

### 2. Key Objectives and Motivation

The primary objective of this research is to develop a framework, Resource2Skill, that can automatically distill executable skills for software agents from diverse multimodal human-created resources, especially tutorial videos. The motivation behind this objective stems from several key observations:

1. **Limitations of Current Skill Acquisition:** Existing methods for populating agent skill libraries are constrained. Hand-authoring is labor-intensive and not scalable. Deriving skills solely from agent traces limits the scope to the agent's own experiences. Mining from text or code resources, while valuable, misses the rich procedural and perceptual information embedded in multimodal formats.
2. **Underutilization of Multimodal Human Expertise:** For many software-authoring tasks, humans learn most effectively by observing demonstrations and screen-recorded workflows found in tutorial videos. These videos encapsulate dynamic operations, visual feedback, spatial layouts, timing, and tool interaction order that are difficult to convey in static text documentation. This vast repository of human knowledge remains largely untapped for autonomous agents.
3. **Challenges of Direct Multimodal Integration:** Directly feeding raw high-dimensional multimodal data, such as videos, into an agent's memory is computationally expensive, redundant, and often impractical. Conversely, compressing video content into a plain text summary discards the precise information that makes videos uniquely valuable.
4. **Need for a Standardized, Reusable Representation:** A practical system requires a mechanism to extract the procedural signal from diverse resources, normalize it into a reusable format, and organize this knowledge to enable efficient retrieval and execution by agents.
5. **Scalability and Maintainability:** The goal is to build a scalable and maintainable skill library that can be extended incrementally, both offline from large corpora and online to address capability gaps during agent execution.

In essence, the research aims to bridge the gap between human learning from multimodal demonstrations and agent skill acquisition, providing agents with a more comprehensive and robust foundation of procedural knowledge to tackle complex software tasks.

### 3. Methodology and Approach

Resource2Skill operates through a four-stage pipeline: construction, wiki organization, selection, and execution. A central design principle is the unification of skill construction and skill use, enabling the same operator to build the initial library and acquire new skills online.

#### 3.1. Hierarchical Multimodal Skill Wiki

The framework represents each skill as a tuple: `s = (p, x_text, x_visual, x_code, m)`.
- `p`: The skill's path within a domain-specific hierarchical taxonomy (e.g., "PPT/layout/title_slide").
- `x_text`: Structured prose explaining the skill's name, mechanism, applicability, inputs, and expected effects.
- `x_visual`: Visual examples such as thumbnails, screenshots, rendered previews, or diagrams, preserving perceptual information like layout and style.
- `x_code`: Executable or adaptable code fragments that define tool-grounded execution patterns. These can be empty for reference-only entries.
- `m`: Metadata for filtering, auditing, and provenance.
This multimodal format is designed to leverage complementary signals from various sources: text for conceptual understanding, code for direct execution, and visuals for demonstrating perceptual aspects. The taxonomy organizes skills, providing domain structure and narrowing search spaces. The entire library for a domain `D`, denoted `Σ_D`, consists of all skills accepted by the construction operator.

#### 3.2. Resource-to-Skill Construction

A `construction operator (f_θ, A_D)` distills skills from a resource pool `R_D` for a given domain `D`. The resource pool comprises four families: tutorial videos, source repositories, articles, and reference artifacts.
- **Multimodal Distiller (`f_θ`):** This component maps each resource `r ∈ R_D` to candidate skills `˜s_1:k`. It uses domain-specific queries to retrieve resource bytes, extracts modality-specific evidence (e.g., key frames from video, AST-aware code regions, prose passages), and distills this evidence into the skill schema `(p, x_text, x_visual, x_code, m)` via a vision-capable Large Language Model (LM) prompted with domain-specific templates. A deterministic post-processor then normalizes whitespace, validates JSON structure, and generates a stable skill identifier.
- **Domain-specific Acceptance Predicate (`A_D`):** This predicate enforces five deterministic checks to validate candidate skills:
 1. **Completeness:** Ensures all required frontmatter fields are populated, the `text_body` meets a minimum length, and at least one content modality is present.
 2. **Provenance:** Verifies that the source path or URL points to a retrievable resource in the connector's manifest.
 3. **Deduplication:** Collapses candidates with identical stable identifiers (SHA1 hash of domain, source path, and extracted node index) to prevent redundant entries.
 4. **Modality Consistency:** Confirms that all declared modalities resolve to non-empty files on disk.
 5. **Structural Executability:** For skills with executable code bodies, a sandboxed test harness imports and runs the code against minimal inputs. This check sets an `exec_ok` flag; skills failing this are retained as reference-only.

#### 3.3. Selecting and Composing Skills

Given a user brief `q`, the agent employs a two-stage `MetaBrowse` process to select skills:
1. **Lexical Scorer:** This stage uses BM25 to narrow down the candidate set to a topically relevant region of the taxonomy. It scores candidates based on their name, tags, applicability text, and crucially, their taxonomy path `p(s)`, favoring skills in relevant subtrees. This results in `C_K(q)`, a shortlist of K candidates.
2. **Language Model Selector (`π_ϕ`):** The LM reads structured evidence for candidates in `C_K(q)` (initially compact frontmatter, then fully expanded content for selected items) and selects a subset `S(q)` for composition. The LM can choose to select zero skills if no suitable candidates are found.

#### 3.4. Execution and Online Acquisition

- **Execution:** The agent and domain adapter interact via a unified MCP (Microsoft Common Protocol) tool surface. The wiki exposes discovery actions (e.g., `list categories`, `read per-modality content`), while the domain side offers an `apply` action. The agent follows a control loop (plan, MetaBrowse, apply, render). Selected skill code, when present, executes directly against the MCP server. For reference-only skills, the agent adapts their text and visual evidence to generate its own code.
- **Online Acquisition:** When the offline library (`C_K(q)`) does not contain adequate candidates for a request, the same `(f_θ, A_D)` construction operator is invoked online. Targeted queries are issued to resource families, returned resources are distilled into temporary candidates, validated by `A_D`, and exposed as a separate online pool for the current task. This mechanism allows for controlled, on-demand gap-filling without altering the main offline library during evaluation.

### 4. Main Findings and Results

The Resource2Skill framework was evaluated across seven practical software-authoring domains (PPT, CAD, Web, Excel, Blender, UE5, Reaper) and four agent backends (GPT-5.5, GPT-5.4, GPT-5.4 Mini, GPT-5.4 Nano). Artifact quality was assessed by a GPT-5.4 vision judge (or GPT-4o for audio) using a five-axis rubric, and validated by a blinded human A/B study.

#### 4.1. Main Comparison: With-Skill vs. Without-Skill

- **Performance Lift:** Resource2Skill ("w Skills") consistently outperformed agents operating without skills ("w/o Skills") across all 28 main-aggregate model–domain cells. It achieved an average overall score of 56.8% compared to 45.0% for "w/o Skills," representing an average improvement of +11.9 percentage points. The deltas were statistically significant (paired Wilcoxon p < 10⁻³).
- **Outperformance of Baselines:** "w Skills" also surpassed strong agentic-harness baselines (ClaudeCode-H and Codex-H) in 26 of 28 cells. This indicates that the performance gains are primarily attributable to the curated skill wiki rather than the execution harness alone.
- **Domain-Specific Gains:** Gains were most pronounced in domains requiring dense authoring conventions, such as Blender, Web, and especially UE5 (+30 to +40 pp), where agents often struggled to produce minimum-viable artifacts without skills. Reaper showed the smallest gains, suggesting a more competent no-skill baseline in that medium.
- **Human Validation:** A blinded human A/B study (N=200 paired ratings) corroborated these findings, with "w Skills" winning 85.5% of non-tied ratings against "w/o Skills" across all seven domains.

#### 4.2. Studies

- **Skill-Library Scaling:** Performance was observed to rise monotonically with the size of the skill library, reaching saturation near 200 skills. The initial 0 → 200 skill range yielded the largest gains (e.g., +14.2 pp on Excel), with marginal improvements beyond 400 skills, indicating that early entries cover common operations while later ones fill domain-specific gaps.
- **Offline and Online Acquisition:** Online acquisition proved effective as a gap-filler. On standard benchmarks (`T_standard`), it yielded a minor increase (+0.7 pp). However, on a stress-test suite (`T_novel`) targeting capabilities missing from the offline pool, online acquisition of 100 skills boosted the mean score from 41.2% to 62.8% (+21.6 pp).

#### 4.3. Ablations

- **Wiki Organization (Skill + Wiki vs. Skill Only):** A flat, pure-text skill library provided performance gains over no skills. However, the full hierarchical, multimodal "Our Wiki" consistently outperformed the flat text library by 2.5 to 8.2 pp across domains, particularly in areas where category structure and code grounding are critical (e.g., Excel, Web, Blender). This demonstrated the value of hierarchical organization and multimodal content.
- **Wiki Construction (Resource-Source Mix):** Video tutorials were identified as a non-substitutable source, with their exclusion causing a significant average performance drop from 68.9% to 59.4%. A video-only library still outscored a three-source (Code+Article+Artifact) library without video. While no single supplemental source dominated, the all-source pool consistently outperformed individual or two-source variants, suggesting that source diversity adds robust coverage.
- **Matched-Budget Representation Ablation:** Comparing skill representations (text-only, text+visual, text+code, full multimodal) under matched budgets, it was found that curated text memory provided a strong baseline (65.0%). Visuals added +1.9 pp, code added +2.0 pp, and the full multimodal representation achieved the highest score at 68.9%, confirming the incremental value of multimodal skill content beyond text alone.
- **Selection Strategy:** The hierarchy-then-LM MetaBrowse policy ("Ours") achieved superior performance compared to retrieval-only baselines (BM25, Embed, BM25+Embed) and random selection. It averaged 68.9%, outperforming the strongest retrieval-only baseline (BM25) by 2.9 pp. Largest margins were observed in Excel, PPT, and Blender, where precise task fit and complementarity are complex.

### 5. Significance and Potential Impact

Resource2Skill represents a significant advancement in the development of capable software agents by addressing the challenge of distilling reusable procedural knowledge from underutilized human-created multimodal resources. Its contributions have several implications:

- **Expanded Skill Acquisition Paradigm:** The framework broadens the scope of skill acquisition for LLM agents beyond hand-authoring, text mining, or self-generated traces. By leveraging tutorial videos and other diverse multimodal resources, it unlocks a vast reservoir of human expertise, enabling agents to learn complex, real-world software operations more effectively.
- **Enhanced Agent Performance and Robustness:** The consistent and statistically significant performance improvements demonstrated across seven diverse authoring domains indicate that access to a structured, multimodal skill library substantially enhances an agent's ability to produce high-quality artifacts. This suggests a pathway towards more competent and reliable autonomous agents in practical applications.
- **Foundation for Maintainable Agent Knowledge Bases:** The design of a hierarchical, multimodal Skill Wiki, coupled with a unified offline-online construction pipeline, provides a scalable and maintainable framework for managing agent knowledge. The ability for online acquisition to fill capability gaps allows for incremental extension of the library, fostering continuous improvement and adaptation.
- **Validation of Multimodal Representations:** The ablation studies quantitatively affirm the value of multimodal skill representations (text, code, visual examples) and hierarchical organization. This underscores that a richer, more structured representation of procedural knowledge, which captures complementary signals from different modalities, is superior to text-only or flat organizational schemes for agent skill selection and execution.
- **Guidance for Future Agent Design:** The findings offer guidance for future agent architectures, highlighting the importance of mechanisms for structured knowledge acquisition, multimodal processing, and intelligent skill selection. This work can inform the development of agents capable of more nuanced understanding and execution of human-demonstrated procedures.

While the study acknowledges limitations, such as reliance on LLM judges and observed instances of partial grounding or conservative composition in failure cases, its core contribution lies in demonstrating a viable and effective approach to systematically distill, organize, and utilize multimodal human expertise for enhancing software agent capabilities. This has the potential to accelerate the development of more versatile and skilled autonomous agents in a wide array of creative and commercial software environments.
