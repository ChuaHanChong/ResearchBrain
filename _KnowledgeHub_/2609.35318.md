# DexAgent: An Agentic Human2Sim2Robot Framework for Dexterous Manipulation with Self-Evolving Tool Library

> [!summary] Summary
> DexAgent is an agentic Human2Sim2Robot framework that turns one egocentric human video and a task prompt into verified robot training data. A VLM agent runs four stages (semantic understanding, property-based simulation reconstruction, trajectory optimization, data generation), selecting or writing skills and verifiers stored in a self-evolving library. Policies trained on its data reach 63.6% real-world success, about 3.5x the best baseline.

## Problem

- Existing Human2Sim2Robot pipelines rely on fixed, predefined reconstruction and motion-generation procedures that cannot adapt to diverse object properties such as articulated joints or deformable topology.
- Long-horizon tasks contain subgoals needing different motion strategies, yet prior retargeting pipelines apply one strategy throughout, failing on multi-step, articulated, and deformable tasks.
- Without per-stage physical verification, reconstruction and retargeting errors silently propagate into robot data, and stateless pipelines pay the full processing cost again for every new video.

## Method

- Four-stage agentic workflow where each subgoal's motion comes from either human-motion-guided ==pose optimization== or VLM code-generated trajectories, followed by ==simulation augmentation==, VOID inpainting and Blender retexturing.
- ==Verification-guided generation loop==: property-specific simulation verifiers (mass, joint axis, grasp shake tests, whole-trajectory checks) gate each stage and feed failures back until all pass or the budget runs out.
- ==Self-evolving tool library== of typed Python skills and verifiers, forked rather than overwritten, where each reconstruction skill must generalize to 3 parameterized variants before it is stored.

## Results

- Policies from pi0.5 fine-tuned on 500 generated episodes average **63.6%** real-world success over eleven dexterous tasks, versus **18.2%** for SPIDER and **17.3%** for V2D; rope knotting reaches **50%** while every baseline scores zero.
- Open-loop replay succeeds on **11/11** tasks versus **6/11** for SPIDER; OakInk retargeting reaches **85.7%** physics-check success versus **81.0%** for Do as I Do, with lower rotation error.
- HOI4D reconstruction Chamfer distance drops **40.8%** on rigid objects; library reuse cuts per-video processing from **4.3 h** to **2.2 h**, and to **13.1 min** with asset reuse.

## Takeaways

> [!tip] Key Insights
> - Letting an agent pick per-object, per-subgoal procedures beats any single fixed retargeting pipeline, especially once articulated, deformable, and long-horizon tasks are involved.
> - Gating each pipeline stage with executable simulation verifiers stops early reconstruction errors from compounding downstream, so verifier design matters as much as generation quality.
> - Persisting agent-written tools spreads cost across videos, but undetected errors persist in the library too, so verification completeness limits how much self-evolution helps.

## Detailed Report

### 1. Position Within the Broader Research Landscape

Dexterous manipulation is a difficult robotics problem because it requires coordinating many degrees of freedom, maintaining stable hand–object contacts, and responding to the physical properties of objects. These requirements are particularly demanding for multifingered hands, which have more complex kinematics and contact patterns than conventional parallel-jaw grippers.

A central limitation in this field is the shortage of robot demonstrations. Collecting demonstrations through teleoperation or direct physical operation is expensive, time-consuming, and difficult to scale. Human videos provide a much larger and more diverse source of manipulation examples, including activities involving tools, articulated mechanisms, deformable objects, and long sequences of actions. However, a human hand and a robot hand differ substantially in morphology, reachability, force production, and control interfaces. A human demonstration therefore cannot simply be copied directly onto a robot.

Recent research has addressed this embodiment gap through Human-to-Simulation-to-Robot pipelines. These systems reconstruct human–object interactions in simulation, retarget the motion to a robot, and use the resulting trajectories to train policies. Related work includes human-video representation learning, human–robot co-training, physics-based retargeting, and video-to-action systems. Methods such as R3M, EgoVLA, EgoMimic, and EgoScale use egocentric human videos to improve robot representations or policies, but generally still require robot demonstrations for adaptation. Other systems, including Do as I Do, SPIDER, TopoRetarget, EgoInfinity, and V2D, attempt to convert human videos into simulated or robot-ready data more directly.

DexAgent is positioned as an extension of these Human2Sim2Robot approaches. Its main distinction is that it does not use one fixed reconstruction and retargeting procedure for every task. Instead, it selects or develops skills according to the object properties and task requirements. It also uses verifiers at multiple stages to identify invalid reconstructions or trajectories before errors propagate. The framework further maintains a persistent library of skills and verifiers, allowing capabilities developed for one video to be reused on later videos.

### 2. Objectives and Motivation

The primary objective is to convert a single egocentric human video and a natural-language task prompt into physically grounded robot trajectories and policy-training data for dexterous manipulation.

The authors identify several problems with existing pipelines. First, fixed procedures are poorly suited to heterogeneous objects. A rigid cup, a screw-cap bottle, a sliding drawer, a pair of scissors, and a rope require different geometric representations and interaction constraints. Second, long-horizon activities contain multiple subgoals, and the motion strategy appropriate for one subtask may not be suitable for another. Third, errors in early video interpretation or simulation reconstruction can propagate into trajectory optimization and ultimately produce unusable robot data. Finally, manually designing a new reconstruction method or task-specific motion generator for every new object limits scalability.

DexAgent is designed to address these issues through four objectives:

1. **Task and object understanding:** Identify the relevant objects, their physical properties, the acting hand, and the sequence of subtasks in a human demonstration.
2. **Property-aware simulation reconstruction:** Build simulated assets that reproduce the properties necessary for the observed interaction, including joints, joint limits, topology, stability, and contact behavior.
3. **Physically valid trajectory generation:** Produce robot motions that satisfy both the demonstrated behavior and task-specific physical constraints.
4. **Scalable data generation:** Use one verified trajectory to create multiple robot-training episodes by varying object and robot states and rendering multiple camera views.

A further objective is to make the system self-evolving. Skills and verifiers developed during processing are retained rather than discarded, so the cost of handling later videos can decrease when similar objects or interactions recur.

### 3. Methodology and Approach

#### 3.1. Overall Agentic Workflow

DexAgent processes each input through four stages. At every stage, the agent selects existing tools from its library or writes new tools when the current library is insufficient. The generated result is evaluated by stage-specific verifiers. If verification fails, the agent uses the feedback to revise the asset, pose, or trajectory. Only outputs that pass the required checks proceed to the next stage.

Skills and verifiers are implemented as typed Python functions. A skill generates an asset, pose, or motion. A verifier accepts or rejects the output based on simulation behavior or task requirements. When a tool is improved, the original version is forked rather than overwritten. Each stage is limited by a specified budget or by 100 agent turns. If the budget is exhausted without passing verification, the stage is recorded as a failure.

#### 3.2. Semantic Understanding

The input consists of one egocentric RGB video and a natural-language task description. A vision-language model first uses the prompt to hypothesize which objects are involved and what properties may be relevant. It then examines video frames to confirm object identities, motion, contacts, and mechanisms.

The system can invoke auxiliary skills for depth estimation, gravity-direction estimation, and human-pose extraction. It records the resulting information in a structured `scene_semantics.json` file. This file specifies object types, such as rigid, articulated, or deformable; properties that must be represented in simulation; and an ordered decomposition of the task into subtasks.

For example, opening and pouring from a bottle may be divided into loosening the cap, removing the cap and attached tube, and tilting the bottle toward a mug. A drawer task may include opening the drawer, grasping the toy, moving it over the drawer, releasing it, and closing the drawer. Each subtask includes an acting hand, object references, and an observable success condition.

#### 3.3. Property-Based Simulation Reconstruction

The second stage creates object assets and places them in a simulation scene. The required verifiers depend on the properties identified in Stage 1. For rigid objects, checks may include silhouette, scale, mass, and resting stability. For articulated objects, checks include the existence and orientation of joints, travel range, and self-locking behavior. For deformable objects, topology is explicitly considered.

If an appropriate reconstruction skill exists, DexAgent calls it with parameters such as appearance, dimensions, number of joints, or joint movement range. If no suitable tool exists, the agent writes a parameterized reconstruction function intended to work across a category of objects rather than only the demonstrated instance.

The system begins with an editable object description, such as a URDF file, and modifies it property by property. After individual properties pass their verifiers, all checks are run jointly to detect conflicts. The new reconstruction skill is then tested on three additional parameter variants. Only a function whose variants also pass is stored in the tool library.

Object placement is optimized by comparing a rendered simulation mask with the object mask observed in the human video. Camera parameters are estimated using depth and visual alignment of the human and robot hands. The output is a scene containing the reconstructed objects, robot setup, camera, and initial states.

#### 3.4. Robot Trajectory Optimization

For every subtask, DexAgent defines a task-specific success condition. Examples include reaching a target object position, achieving an articulated joint state, establishing a required contact, or producing a visible mark on a surface.

The framework selects among several motion-generation strategies. It may retarget human hand poses, optimize robot finger joints to reproduce human hand–object contacts, or generate a new grasp based on contact, force-closure, and clearance requirements. The selected target poses are themselves tested. A transport grasp may be subjected to lifting and shaking tests, while a pose for an articulated object may be tested through sliding or rotational motion.

Once target poses pass verification, inverse kinematics converts them into arm configurations. The agent generates code to connect these key configurations, using the demonstrated human trajectory as a motion prior when appropriate. Subtask trajectories are combined into a complete episode. If an earlier subtask leaves the object or robot in a state that prevents a later subtask, the earlier motion is revised. Whole-trajectory verifiers then check motion limits, contact consistency, and execution feasibility.

#### 3.5. Data Generation and Policy Training

The verified trajectory is augmented by varying initial object positions and robot states within the reachable workspace. Each candidate episode is checked for reachability and task feasibility. In the appendix procedure, 1,500 random seeds are sampled and valid configurations are retained until 500 training episodes are available.

To reduce the visual simulation-to-real gap, the demonstrator’s hands and manipulated objects are removed from the source video using VOID. Rendered robot and object images are composited into the cleared scene and retextured using Blender. Simulation additionally provides egocentric and left- and right-wrist camera views. These data are used to fine-tune the π0.5 vision-language-action model.

### 4. Main Findings and Results

#### 4.1. Reconstruction Quality

On HOI4D, DexAgent achieved the strongest reported reconstruction results for both rigid and articulated objects among the listed methods. For rigid objects, it obtained an F-5 score of 0.83, an F-10 score of 0.96, and a Chamfer distance of 0.29. For articulated objects, the corresponding values were 0.47, 0.68, and 1.08.

Relative to the strongest baseline for each metric, the paper reports improvements of 15.3% and 5.5% in rigid-object F-5 and F-10, respectively, and a 40.8% reduction in rigid-object Chamfer distance. For articulated objects, the reported gains were 17.5% for F-5, 11.5% for F-10, and a 10.7% reduction in Chamfer distance. These results support the use of property-specific reconstruction and iterative physical verification.

#### 4.2. Trajectory Generation Quality

On OakInk, DexAgent converted 85.7% of evaluated clips into trajectories that passed the physics-based success criteria. The strongest comparison, Do as I Do using a Sharpa hand, achieved 81.0%. DexAgent matched the baseline’s mean positional error of 0.03 meters and reduced mean rotational error to 0.12 radians, compared with 0.15 radians.

The results indicate that DexAgent does not merely minimize visual pose differences. It adapts human motion to robot kinematics and task constraints, producing trajectories that are more likely to remain physically executable.

#### 4.3. Real-World Trajectory Replay

The physical evaluation used two Sharpa hands mounted on a bimanual YamBox station, with an egocentric RealSense camera and two wrist cameras. Eleven tasks covered rigid, articulated, deformable, tool-use, and long-horizon manipulation.

In open-loop replay, DexAgent succeeded on all 11 tasks under the paper’s criterion that at least one of ten trials succeed. SPIDER succeeded on 6 of 11, V2D on 5 of 11, and the other listed methods on fewer tasks. DexAgent was the only evaluated system reported to succeed on the rope-knot, bottle, biology, and battery-related tasks as a complete set.

#### 4.4. Learned-Policy Performance

Policies trained using the same augmentation and visual-processing protocol achieved an average success rate of 63.6% with DexAgent-generated data. SPIDER reached 18.2%, V2D 17.3%, GPT-6 Astra 16.4%, Do as I Do 10.9%, TopoRetarget 8.2%, EgoInfinity 7.3%, and Dex-retargeting 0%.

DexAgent’s per-task success rates ranged from 40% to 90%. The reported rates included 80% on drawer placement, 50% on rope knotting, 70% on bottle opening, 60% on biology experiments, and 70% on multi-object manipulation. The results suggest that the framework’s benefits extend beyond rigid-object grasping to articulated, deformable, and multi-stage activities.

#### 4.5. Library Growth and Processing Cost

Across 100 EgoDex samples, the library reached 85 skills and 168 verifiers in the main experiment. The appendix reports a broader current library of 103 skills and 188 verifiers, reflecting a different accumulation setting. Processing time declined from 4.3 hours for an initial video to 2.2 hours when skills were reused and 13.1 minutes when both skills and object assets were reusable. The complete 100-video run required 210 hours.

### 5. Significance, Potential Impact, and Limitations

DexAgent’s main significance is architectural. It treats human-video conversion not as a fixed sequence of perception, reconstruction, and retargeting modules, but as an adaptive process in which the system chooses tools according to task properties and verifies intermediate results. This design could make human video a more practical source of dexterous robot data, especially for tasks that are difficult to model with generic object assumptions.

The self-evolving library also provides a mechanism for amortizing engineering effort. A newly developed skill for screw mechanisms, deformable strings, writable surfaces, or drawer joints can be reused on later examples. This is relevant to scaling data generation across object categories and task families.

However, the paper identifies important limitations. Semantic and geometric errors may still occur, and incomplete verifiers can allow invalid results to pass. Errors that enter the persistent library could affect later demonstrations. Some force-sensitive interactions may fail on a real robot even when they pass simulation checks. The approach also depends on reliable vision-language-model reasoning, code generation, object modeling, simulation fidelity, and visual sim-to-real transfer. Finally, the physical study uses eleven tasks and ten trials per task, so broader evaluation across robots, environments, object instances, and force-intensive manipulation would be needed to establish generality.
