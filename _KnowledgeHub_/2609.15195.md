# HarnessVLN: Unifying Training-Free Embodied Navigation through an Agent Harness

> [!summary] Summary
> HarnessVLN is a zero-shot, training-free navigation framework that handles both instruction-following and object-goal tasks through one shared Agent Harness. The Harness routes perception, memory, grounding and motion tools through a unified interface, validates every planner proposal against evidence, geometry and subgoal state, and maintains hierarchical event memory plus a persistent spatiotemporal graph. It reaches 60.8%, 53.9%, 76.0% and 59.3% success across four benchmarks.

## Problem

- Training-based navigation policies learn from task-specific demonstrations, so new task formulations or environments demand fresh supervision and retraining rather than reuse.
- Existing MLLM navigation systems use the model only as a planner in task-specific pipelines, leaving evidence retention, proposal validation and failure handling without unified coordination.
- Stronger semantic reasoning does not guarantee grounded action: recognizing a target does not establish arrival, and issuing an action does not establish subgoal completion.

## Method

- An **Agent Harness** exposes perception, retrieval, grounding, navigation, backtrack and termination tools behind one input-output contract, validating each proposal for evidence provenance, geometric feasibility and subgoal consistency before dispatch.
- ==Hierarchical event memory== splits working, progress and reflection stores, tracking bounded observation context, four-state subgoals, and per-subgoal failure traces that contextualize recovery decisions.
- A persistent ==spatiotemporal graph== of place and entity nodes scores retrieval by semantic relevance, recency and salience minus a failure penalty, and gates stopping on a semantic, geometric and progress conjunction.

## Results

- Success rates of **60.8%** on R2R, **53.9%** on RxR, **76.0%** on HM3D-v2 and **59.3%** on HM3D-OVON beat prior training-free bests by **5.8**, **12.1**, **1.6** and **9.1** points.
- Under a matched planner on 100 OVON episodes, it scores **55.0%** success versus MSGNav's **37.0%**, isolating the framework from the model; a stronger planner lifts this to **63.0%**.
- Cumulative ablations add **8.0**, **6.0** and **4.0** points on R2R for event memory, graph retrieval and stop validation, but stop validation lowers OVON path efficiency from **34.2%** to **33.0%**.

## Takeaways

> [!tip] Key Insights
> - Gating termination on embodied evidence rather than planner confidence converts semantic recognition into verified arrival, and shrinks the oracle-versus-actual success gap.
> - Separating task-centric event history from an environment-centric spatial graph keeps planner context bounded as trajectories lengthen, since retrieval returns a fixed top-K set.
> - Completion gains do not transfer to efficiency: validation and recovery add steps, so success weighted by path length can trail weaker but more direct baselines.

## Detailed Report

### 1. Position within the Broader Research Landscape

Embodied navigation concerns an agent’s ability to move through an environment toward a specified destination. Two widely studied forms are **instruction-following navigation**, in which the agent follows a natural-language route description, and **object-goal navigation**, in which it searches for an object such as a dishwasher, printer, or chair. Both tasks require perception, language grounding, mapping, exploration, planning, and low-level control under partial observability.

Recent navigation research has followed two principal directions. Training-based vision-language-action systems learn navigation policies from demonstrations, trajectories, or task-specific data. These methods can achieve strong results on established benchmarks, but adaptation to new environments, task definitions, or robot platforms may require additional training. In contrast, zero-shot or training-free systems use pretrained vision-language models or multimodal large language models (MLLMs) to reason about instructions and observations without navigation-specific fine-tuning.

HarnessVLN addresses a limitation in many existing MLLM-based systems. In those systems, the MLLM often acts primarily as a planner: perception modules provide images, the MLLM proposes a subgoal, and separate components attempt to ground and execute that proposal. This arrangement can fail when the planner’s reasoning becomes disconnected from the agent’s actual position, accumulated spatial evidence, task progress, or execution failures. For example, identifying an object does not necessarily mean that the agent has reached it, and issuing a navigation command does not demonstrate that the corresponding subgoal was completed.

The paper places its contribution within the emerging area of **agent harnesses**, which coordinate models, tools, memory, execution, and environmental feedback. Earlier harness-based systems have focused mainly on manipulation or robot programming. HarnessVLN extends this paradigm to long-horizon navigation by providing a common runtime for instruction following and object-goal navigation. Its central claim is that reliable zero-shot navigation depends not only on semantic reasoning, but also on systematic validation and state management.

### 2. Objectives and Motivation

The primary objective is to develop a single, training-free framework that can support multiple navigation tasks and environments without changing the underlying planning and execution protocol. Specifically, the authors aim to unify instruction-following navigation and object-goal navigation through a shared Agent Harness and tool interface.

The motivation has several components. First, navigation decisions must be grounded in spatial evidence. A language model may correctly interpret “turn right at the doorway,” but the system still needs to identify the correct doorway, determine whether the proposed target is reachable, and verify that the agent has arrived at the intended location.

Second, navigation requires persistent state across a sequence of decisions. The system must remember visited locations, observed landmarks, candidate objects, completed route segments, and previous failed attempts. Without such memory, the agent may repeat unsuccessful actions or lose track of the relationship between its current position and the original task.

Third, execution outcomes must influence later planning. A target may be unreachable, incorrectly grounded, blocked by an obstacle, or associated with insufficient depth information. HarnessVLN therefore treats tool feedback as structured evidence rather than as an informal signal. Failures are recorded and used to modify subsequent retrieval and recovery decisions.

Finally, termination must be verified. The authors argue that allowing an MLLM to stop based solely on its confidence can produce premature termination. HarnessVLN requires semantic, geometric, and task-progress evidence before accepting a stop request.

### 3. Methodology and Approach

#### 3.1. Agent Harness and State Representation

At each decision step, the Harness maintains a state containing the task specification, a pose-aligned RGB-D observation and local geometric map, the agent pose, task progress, hierarchical event memory, and a persistent Spatiotemporal Graph (ST Graph).

The task specification is either a route instruction or an object category. Task progress is represented differently for each task family. In instruction following, it records the active route segment, satisfied motion constraints, and observed landmarks. In object-goal navigation, it records explored regions, candidate target hypotheses, and their verification status. The underlying Harness protocol remains unchanged.

The MLLM does not directly execute arbitrary environment actions. Instead, it proposes semantic operations through a unified tool interface. The Harness validates those proposals and dispatches only approved calls.

#### 3.2. Unified Tool Interface

The core tools include:

- **Observation tools:** `observe`, `observe_panorama`, and `query_depth`.
- **Retrieval and grounding tools:** `retrieve_memory` and `ground_target`.
- **Navigation tools:** `navigate_to`.
- **Recovery tools:** `backtrack`.
- **Termination tools:** `request_stop`.

Before dispatch, the Harness checks the validity of the tool arguments, the provenance and recency of supporting evidence, geometric reachability, consistency with the active subgoal, and relevance of previous failure records. Each tool returns structured feedback, including execution status, measurements, and failure information. This feedback updates the Harness state, event memory, and ST Graph.

The architecture also separates high-level planning from navigation execution. The MLLM proposes a semantic target, while a replaceable Navigation Executor converts the validated target into paths and motion commands. The simulator uses a Fast Marching Method planner for planar motion and NavDP for stair traversal.

#### 3.3. Hierarchical Event Memory

HarnessVLN uses three levels of task-centric memory.

**Working memory** stores the current observation, a bounded history of panoramic views, the active target hypothesis, and recent tool feedback. It is deliberately limited to prevent context growth over long trajectories.

**Progress memory** represents task decomposition. Subgoals have stable identifiers and one of four states: pending, active, completed, or blocked. Only one subgoal may be active at a time. A subgoal can be marked completed only when supported by a pose-aligned observation or successful tool result.

**Reflection memory** records detailed execution events, including unreachable targets, incorrect grounding, collisions, lack of progress, failed backtracking, and rejected stop requests. Each record includes the context, location, timestamp, feedback, and supporting observation. Lightweight references to relevant failures can be attached to the ST Graph without duplicating the complete event history.

#### 3.4. Spatiotemporal Graph

The ST Graph is environment-centric, whereas event memory is task-centric. It contains place nodes, entity nodes, spatial relations, timestamps, and failure annotations.

Place nodes summarize visited locations and traversable waypoints. Spatially compatible observations are merged into existing places; otherwise, new places are created. Consecutive places are linked by bidirectional navigability relations, supporting both forward navigation and backtracking.

Entity nodes represent object-goal targets and instruction-referenced landmarks. They store semantic aliases, spatial hypotheses, confidence estimates, and supporting views. Relations such as “observed from” preserve the viewpoint and time associated with an observation, while “contains” connects entities to places.

Before each planning decision, the Harness retrieves a compact set of graph evidence. Retrieval ranks places according to semantic relevance to the active subgoal, recency, spatial salience, and penalties from applicable prior failures. The system expands a small number of seed places by one graph hop, limiting the amount of information provided to the MLLM.

#### 3.5. Grounded Execution and Termination

For every proposed command, the Harness attempts to ground the semantic target to a view and image region, estimate depth, and determine whether the target is geometrically reachable. The executor then returns outcomes such as arrival, collision, unreachability, or lack of progress.

Stopping is treated as a separate verification operation. The stop condition requires:

1. **Semantic evidence:** the visible or referenced target is the correct target.
2. **Geometric evidence:** the agent is sufficiently close to the grounded target.
3. **Progress evidence:** the relevant navigation task or route segment has been completed.

For ObjectNav, the object must be visibly supported and within the stopping radius. For instruction following, the evidence must support the final route segment, landmark, and endpoint.

### 4. Main Findings and Results

#### 4.1. Simulation Benchmarks

The framework was evaluated on four benchmarks: VLN-CE R2R and RxR for instruction following, and HM3D-v2 and HM3D-OVON for object-goal navigation. It used RGB-D observations at 640 × 480 resolution. GroundingDINO and SAM supplied open-vocabulary detection and segmentation, while GPT-5.5 served as the instruction-following planner and GPT-5.6-luna as the ObjectNav planner.

HarnessVLN achieved success rates of:

- **R2R:** 60.8%.
- **RxR:** 53.9%.
- **HM3D-v2:** 76.0%.
- **HM3D-OVON:** 59.3%.

For R2R, the system reached an SPL of 43.5%, an oracle success rate of 72.7%, and a navigation error of 4.01 meters. Compared with AgenticNav using the same GPT-5.5 model, success increased by 5.8 percentage points and oracle success increased by 7.7 points, while navigation error decreased from 5.19 to 4.01 meters.

On RxR, HarnessVLN improved success by 12.1 percentage points over HSGM and increased SPL by 12.9 points. Navigation error decreased by 1.01 meters. Its normalized dynamic time warping score was 54.8%, close to HSGM’s 54.9%, suggesting that the improvement was more evident in task completion than in trajectory similarity.

For HM3D-v2, HarnessVLN achieved 76.0% success and 37.9% SPL, exceeding MSGNav’s success rate by 1.6 points. On the open-vocabulary HM3D-OVON benchmark, it achieved 59.3% success and 36.6% SPL, exceeding DRIVE-Nav by 9.1 and 4.0 points, respectively. Its success rate was also higher than the listed strongest training-based result on HM3D-OVON, although the comparison involves different methodological categories.

#### 4.2. Ablation Results

Cumulative ablations were conducted on fixed 100-episode subsets of R2R and HM3D-OVON. Adding event memory increased success by 8.0 points on R2R and 7.0 points on HM3D-OVON. Adding the ST Graph produced further success gains of 6.0 and 1.0 points, respectively, and improved SPL on both subsets. Stop validation added another 4.0 points on R2R and 2.0 points on HM3D-OVON.

The full Harness improved success over the base agent by 18.0 points on R2R and 10.0 points on HM3D-OVON. However, stop validation did not uniformly improve efficiency: SPL decreased slightly on the HM3D-OVON subset. The appendix also reports sensitivity to the planning model, with success ranging from 51.0% using Qwen3.8-flash to 63.0% using GPT-6-astra on a fixed HM3D-OVON subset.

#### 4.3. Real-World Deployment

The system was deployed on an AgiBot A3U humanoid robot equipped with LiDAR, RGB-D and fisheye cameras, stereo-based depth estimation, and onboard NVIDIA Thor computing. Qwen-3.8-27B served as the planning model, and a local path planner converted validated targets into waypoints.

The authors demonstrate instruction following, open-vocabulary printer search, and a combined task involving an entrance signboard followed by a vending-machine search. These demonstrations show that the same Harness protocol can preserve landmark and target evidence across multiple navigation stages. The deployment evidence is primarily qualitative rather than a large-scale statistical evaluation.

### 5. Significance and Potential Impact

HarnessVLN’s main significance is architectural. It presents navigation as a managed closed loop involving planning, evidence retrieval, proposal validation, execution, memory updates, recovery, and verified termination. This design provides a common interface across task families while allowing perception and navigation executors to be replaced.

The reported results indicate that memory and execution validation can improve training-free navigation beyond planner-only pipelines. The ST Graph may be particularly useful for long-horizon tasks because it preserves spatial provenance and failure information without passing the entire trajectory to the MLLM.

Potential applications include general-purpose service robots, household object search, indoor delivery, and humanoid systems operating across varied environments. The approach may also reduce the need for task-specific navigation training when adapting to new object vocabularies or route formulations.

Several limitations remain. The framework depends on strong pretrained MLLMs, external perception modules, depth quality, and manually designed validation rules. Model sensitivity results show that performance varies with the selected planner. The Harness orchestration is predefined rather than self-improving, and the real-world evaluation is demonstrated through a small set of scenarios rather than a broad quantitative study. Consequently, the paper supports the value of structured runtime coordination, but further work is needed to assess computational cost, robustness to sensor failures, transfer across robot morphologies, and performance in less controlled environments.
