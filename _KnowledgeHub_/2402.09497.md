# Instruction Tuning for Secure Code Generation

> [!summary] Summary
> Researchers at ETH Zurich developed SafeCoder, an instruction tuning methodology that dramatically improves the secure code generation rate of large language models by approximately 30% while preserving their general utility. This approach uses a joint optimization scheme with masked loss functions and an automated pipeline to curate high-quality security datasets from GitHub commits.

## Problem

- Modern instruction-tuned large language models (LMs) frequently generate insecure code, posing significant risks for software development.
- A critical challenge exists in enhancing code security without degrading the LM's general utility and instruction-following abilities.
- There is a lack of high-quality, diverse, and scalable datasets specifically designed for training LMs to generate secure code.

## Method

- **SafeCoder** introduces a novel ==instruction tuning== approach that jointly optimizes for utility and security by mixing standard and security-specific datasets.
- It employs ==masked negative log-likelihood loss== for secure code and ==masked unlikelihood loss== for vulnerable code, focusing training signals on security-critical tokens.
- An automated, two-step pipeline extracts high-quality security vulnerability fixes from GitHub commits, using ==heuristic filtering== and ==static analysis with CodeQL==.

## Results

- SafeCoder improved the secure code generation rate by approximately **30%** across various LMs (from **~60%** to **~90%**) while preserving utility on functional correctness and natural language understanding benchmarks.
- Ablation studies confirmed the critical importance of SafeCoder's collected security data, masked loss functions, and unlikelihood loss for achieving optimal security performance.
- SafeCoder significantly outperformed prior work like SVEN, which showed trade-offs between security and functional correctness, demonstrating superior joint optimization.

## Takeaways

> [!tip] Key Insights
> - Jointly optimizing for security and utility during instruction tuning is effective, enabling substantial security gains without compromising the model's general capabilities.
> - Automated data collection from vulnerability fixes, using heuristics and static analysis, can yield high-quality and diverse datasets crucial for security training.
> - Simply prompting instruction-tuned models with security-aware instructions is insufficient to achieve meaningful improvements in code security.

## Detailed Report

### 1. How this Work Fits into the Broader Research Landscape

The rapid advancement and widespread adoption of large language models (LMs) have significantly impacted various domains, with programming emerging as a particularly prominent use case. Tools like GitHub Copilot and similar AI assistants are increasingly integrated into software development workflows. These LMs typically undergo two main training stages: initial pretraining on vast code corpora to understand syntax and semantics, followed by **instruction tuning** (or supervised fine-tuning). Instruction tuning is crucial as it enhances the LM's ability to follow user instructions, align with human preferences, and perform specific tasks, thereby greatly increasing their practical utility.

However, a critical gap exists in the current landscape: the **security of generated code**. While instruction tuning often incorporates safety mechanisms for natural language outputs (e.g., reducing toxicity), code security has received inadequate attention. As highlighted by the authors and prior research (Pearce et al., 2022; Li et al., 2023; Khoury et al., 2023), even state-of-the-art instruction-tuned LMs frequently produce insecure code, introducing significant vulnerabilities that can be costly to fix or even lead to production compromises. This is a severe impediment to the trustworthy deployment of AI in software development.

Existing work on securing LM-generated code, such as SVEN (He & Vechev, 2023), primarily focused on *pretrained* code completion models. While pioneering, these methods often face limitations when applied to the instruction-tuning paradigm, such as inherent trade-offs between security and utility. Furthermore, existing vulnerability datasets, crucial for security training, often suffer from quality or diversity issues, relying on simplistic heuristics or expensive manual curation.

SafeCoder directly addresses these shortcomings. It positions itself as a novel approach within the instruction-tuning phase, specifically designed to inject security awareness into LMs that are already adept at following instructions. By focusing on instruction-tuned models, SafeCoder tackles the security problem at a highly practical and impactful stage of LM deployment. Its key differentiators include:
1. **Joint Optimization of Security and Utility:** Unlike previous methods that might involve trade-offs, SafeCoder aims for simultaneous improvement in both aspects.
2. **Automated High-Quality Data Collection:** It introduces a scalable pipeline to overcome the challenges of obtaining diverse and accurately labeled security datasets.
3. **Targeting Instruction-Tuned LMs:** It specifically caters to the models currently being widely adopted for user interaction in programming contexts, where instruction-following is paramount.

Thus, SafeCoder represents a significant step forward in the field of secure AI-assisted software development, bridging the gap between highly capable instruction-tuned LMs and the critical need for secure code generation.

### 2. Key Objectives and Motivation

The primary objective of this research is to **address the pervasive issue of insecure code generation by modern, instruction-tuned large language models (LMs)**. The authors observe that despite their sophisticated capabilities and widespread adoption in programming, even state-of-the-art instruction-tuned LMs frequently produce code riddled with security vulnerabilities. This poses substantial risks, including costly post-development fixes and potential security breaches in production environments.

The motivation for SafeCoder stems from two core challenges identified by the authors:

1. **Dual Objective of Security and Utility:** Enhancing the security of generated code cannot come at the expense of the LM's general utility. A truly effective AI programming assistant must be both functionally correct (e.g., generating code that passes tests) and secure (e.g., free from common vulnerabilities). Existing instruction tuning schemes prioritize general utility and instruction following, largely overlooking code security. The challenge is to achieve a "security-for-free" benefit, where security is drastically improved with minimal or no compromise on other aspects of utility, such as functional correctness, natural language understanding, or truthfulness.

2. **Lack of Effective Security Training Datasets:** Training LMs to generate secure code requires high-quality, diverse datasets containing examples of both secure and vulnerable programs, accurately labeled, and covering a wide range of vulnerability types (CWEs) and programming languages. Existing datasets are often limited in quality (containing mislabeled examples) or diversity (focusing on a narrow set of vulnerabilities or languages), or are painstakingly curated manually, which is not scalable. The motivation here is to develop an automated and scalable method for collecting such a dataset to facilitate effective security training.

In essence, the authors are motivated to develop a practical and effective instruction-tuning methodology that equips LMs with a deep understanding of code security, enabling them to generate robust and safe code while retaining their general-purpose capabilities and instruction-following prowess, all supported by a scalable data acquisition process.

### 3. Methodology and Approach

SafeCoder introduces a novel instruction tuning approach designed to jointly optimize for both utility and security in code generation. Its methodology consists of a specialized security instruction tuning scheme, its integration with standard instruction tuning, and an innovative automated data collection pipeline.

#### 3.1. SafeCoder's Instruction Tuning

The core idea is to perform a joint optimization by mixing a standard instruction tuning dataset (`D_std`) with a security-specific dataset (`D_sec`).

- **Standard Instruction Tuning (`L_std`):** For samples from `D_std` (which covers various general tasks and human preferences, not just programming), the LM is fine-tuned using a standard negative log-likelihood loss, aiming to predict the desired output `o` given an instruction `i`. This preserves the LM's general utility.

- **Security Instruction Tuning (`L_sec` and `L_vul`):** For samples from `D_sec`, SafeCoder employs a more nuanced approach. Each sample in `D_sec` is a tuple `(i, o_sec, o_vul)`, where `i` is an instruction for a security-sensitive task, `o_sec` is a secure implementation, and `o_vul` is a vulnerable one. Importantly, `o_sec` and `o_vul` are designed to be functionally identical, differing only in security-critical aspects.
 - **Masked Negative Log-Likelihood Loss (`L_sec`):** This loss function is applied to `(i, o_sec)`. It uses a binary mask (`m_sec`) to focus the training signal *only* on the security-related tokens of `o_sec`. By minimizing this loss, the LM is encouraged to increase the probability of generating secure code.
 - **Masked Unlikelihood Loss (`L_vul`):** This loss function is applied to `(i, o_vul)`. It also uses a binary mask (`m_vul`) to identify security-critical tokens in `o_vul`. Instead of increasing probability, this loss *penalizes* the generation of these insecure tokens, thereby discouraging the LM from producing vulnerable code. This provides a crucial negative learning signal.
 - The masks `m_sec` and `m_vul` are generated by computing token-level differences between `o_sec` and `o_vul` using `difflib`, ensuring that training focuses precisely on the security-relevant code changes.

- **Combined Training (Algorithm 1):** In each training iteration, a sample is randomly drawn from the combined `D_std` and `D_sec`. If it's a `D_std` sample, `L_std` is applied. If it's a `D_sec` sample, the combined security loss (`L_sec + L_vul`) is applied. This joint optimization is key to achieving both high security and preserved utility, as it ensures that the model learns security-awareness without forgetting its general instruction-following capabilities.

- **Handling Data Imbalance:** Within the `D_sec` dataset, an oversampling strategy is applied to minority classes (defined as unique CWE-programming language pairs). This ensures sufficient exposure to less common vulnerability types, improving security performance and stabilizing training. The relative size imbalance between `D_std` and `D_sec` is not explicitly addressed, as the authors found LMs still achieve high security, and `D_sec` is relatively small, minimizing training overhead.

#### 3.2. SafeCoder's Data Collection Pipeline

Recognizing the need for high-quality and diverse security data, the authors developed an automated, two-step pipeline to extract vulnerability fixes from GitHub commits (Algorithm 2).

1. **Heuristic Commit Filtering (`heuristicFilter`):**
 - This is a lightweight initial filter applied to hundreds of millions of GitHub commits.
 - It uses keyword matching in commit messages (tailored for specific CWEs) and filters out commits with too many changes (e.g., over 40 lines changed or 2 files changed) or unsupported file types.
 - This step drastically reduces the candidate pool (by ~3 orders of magnitude), making subsequent expensive analysis feasible.

2. **Verifying Vulnerability Fixes (`analyzeCode` with CodeQL):**
 - For the filtered commits, the industry-leading static analysis tool CodeQL (GitHub, 2023) is run on both the pre-commit (`r`) and post-commit (`r'`) versions of the repository.
 - A commit is confirmed as a vulnerability fix if CodeQL detects vulnerabilities in `r` that are *completely eliminated* in `r'` for a specific vulnerability type. This ensures accurate security labels.

3. **Constructing Final Samples:**
 - For each verified fix, the `changedFuncs` function extracts pairs of functions (`o_vul`, `o_sec`) from the pre- and post-commit versions, respectively.
 - **Instruction Generation (`generateInst` with GPT-4):** GPT-4 is then used to generate a concise instruction `i` that describes the *common functional goal* of `o_sec` and `o_vul`, explicitly excluding any security-specific mentions. This ensures the generated instruction aligns with typical user queries.

This pipeline, starting from 145 million GitHub commits, successfully curated a high-quality dataset of 465 samples across 23 CWE categories and 6 programming languages, which was then combined with a smaller existing dataset (He & Vechev, 2023) to form the final training set of 1268 samples.

### 4. Main Findings and Results

The extensive experimental evaluation of SafeCoder across six state-of-the-art LMs (three coding-specific and three general-purpose) and various benchmarks yielded several significant findings:

- **Dramatic Security Improvement with Utility Preservation:** The most salient finding is SafeCoder's ability to **drastically improve the secure code generation rate by approximately 30%** (from around 60% for baselines to ~90%) across all tested LMs. Crucially, this improvement is achieved while **preserving the LM's utility** in other aspects. Performance on functional correctness benchmarks (HumanEval, MBPP) and natural language understanding tasks (MMLU, TruthfulQA) remained comparable to, or only negligibly lower than, models fine-tuned with standard instruction tuning alone. This validates the "security-for-free" claim.

- **Broad Applicability:** SafeCoder proved effective across a diverse range of models, from smaller 1B-3B parameter models (StarCoder-1B/3B, Phi-2-2.7B) to larger 7B models (CodeLlama-7B, Llama2-7B, Mistral-7B), indicating its robustness and generalizability across different LM architectures and intended purposes (coding-specific vs. general-purpose).

- **Ineffectiveness of Prompting Alone:** The authors demonstrated that simply including security-aware instructions in the prompt (e.g., "Make sure the generated code is secure") does not significantly enhance the security of code generated by state-of-the-art instruction-tuned LMs. This underscores the necessity of a dedicated security-centric fine-tuning approach like SafeCoder.

- **Ablation Studies Confirm Component Importance:**
 - **Value of Collected Data:** Excluding the security dataset collected by SafeCoder's pipeline ("no collected data") led to a substantial ~20% decrease in security, particularly for CWEs not covered by the older dataset. This highlights the critical contribution of SafeCoder's diverse and high-quality dataset.
 - **Importance of Loss Masks:** Removing the `m_sec` and `m_vul` masks from the loss functions ("no loss masks") resulted in a ~10% drop in security, confirming that focusing the training signal on security-critical tokens is essential for optimal results.
 - **Necessity of Unlikelihood Loss:** Omitting the unlikelihood loss (`L_vul`) during training ("no unlikelihood") led to a 5-10% reduction in security, demonstrating the value of explicitly discouraging insecure code generation.

- **Superiority Over Prior Work (SVEN):** A direct comparison with SVEN (He & Vechev, 2023), adapted for the instruction-tuning setting, showed that SafeCoder significantly outperforms SVEN. SVEN exhibited a trade-off between security and functional correctness due to its conflicting objectives, whereas SafeCoder successfully achieved excellence in both dimensions simultaneously, largely due to its joint optimization training procedure.

- **Limited Generalization to Unseen CWEs:** A notable limitation is that SafeCoder does not show significant improvements in security for vulnerability types (CWEs) that were *not* included in its training set. This suggests that while highly effective for trained CWEs, it does not achieve strong generalization across entirely novel vulnerability categories.

- **Effectiveness of Oversampling:** The oversampling strategy for minority CWE-language pairs within the security dataset was shown to be highly beneficial. It significantly improved the mean security rate and reduced the variance of training outcomes, contributing to a more stable and effective training process.

### 5. Significance and Potential Impact

SafeCoder represents a significant advancement in the field of secure AI-assisted code generation, with profound potential impact on software development practices and cybersecurity.

#### 5.1. Addressing a Critical Security Gap

The most immediate and significant impact of SafeCoder is its direct address of the critical security vulnerabilities frequently generated by even cutting-edge instruction-tuned LMs. By enabling LMs to generate secure code at a substantially higher rate (approaching 90%), SafeCoder transforms these powerful tools from potential sources of risk into reliable allies in secure software development. This is particularly crucial as AI assistants like GitHub Copilot become ubiquitous, making the security of their outputs paramount.

#### 5.2. Practical Benefits for Developers and Organizations

- **Reduced Vulnerability Remediation Efforts:** Developers currently spend significant time identifying and fixing security flaws in AI-generated code. SafeCoder's ability to produce inherently more secure code will drastically reduce this burden, freeing up developer resources for more complex or innovative tasks.
- **Lowered Risk of Production Vulnerabilities:** By mitigating the generation of insecure code at the source, SafeCoder helps prevent vulnerabilities from leaking into production systems, thereby reducing the risk of costly security breaches, data exposure, and reputational damage for organizations.
- **Enhanced Trust in AI-Assisted Development:** The "security-for-free" property fosters greater trust in AI programming assistants. Developers and organizations can leverage the productivity benefits of LMs without constantly worrying about hidden security flaws, accelerating the adoption of these technologies.

#### 5.3. Contribution to the Research Community

The authors' decision to open-source their code and the high-quality, diverse security dataset is a substantial contribution. This will:
- **Accelerate Future Research:** Provide a valuable benchmark and training resource for other researchers working on secure code generation, enabling faster experimentation and innovation.
- **Promote Reproducibility:** Allow other researchers and practitioners to reproduce the results and build upon SafeCoder's foundations.
- **Democratize Security Training:** Make advanced security training techniques and datasets accessible to a wider audience, including academic institutions and smaller development teams.

#### 5.4. Paving the Way for Future Innovations

The work explicitly identifies limitations, such as the lack of strong generalization to unseen CWEs and the focus on supervised fine-tuning. These limitations, clearly articulated, open up exciting avenues for future research, including:
- **Improving Generalization:** Developing techniques to enable LMs to infer and avoid novel or untrained vulnerability types.
- **Post-Hoc Security Patching:** Exploring methods for securely patching already deployed instruction-tuned LMs without full retraining.
- **Reinforcement Learning for Security:** Extending SafeCoder's principles to reinforcement learning settings for even more nuanced security alignment.
- **Application to Pretrained Models:** Investigating how SafeCoder's insights can be adapted for directly enhancing the security of pretrained code completion models.

#### 5.5. Societal Impact and Ethical Considerations

By enhancing the security of AI-generated code, SafeCoder contributes positively to society by promoting safer software systems in an increasingly interconnected world. The authors also responsibly acknowledge the dual-use nature of the technology, noting that while their techniques aim to improve security, they could theoretically be misused to train models for generating unsafe code. Their provision of evaluation methods serves as a mechanism to detect and counteract such malicious applications, demonstrating a commitment to responsible AI development.

In conclusion, SafeCoder is a timely and impactful contribution that significantly elevates the security posture of instruction-tuned LMs for code generation. Its practical effectiveness, combined with the open-sourcing of resources, positions it as a foundational work that will likely influence both industry practices and future research directions in secure AI.
