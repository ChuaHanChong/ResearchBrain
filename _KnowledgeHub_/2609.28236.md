# EmbodiedMemory-Bench: Benchmarking Embodied Memory for Long-Horizon Embodied Tasks

> [!summary] Summary
> EMem-Bench is a memory-centric embodied benchmark of 2,554 executable AI2-THOR and ProcTHOR episodes. In each episode, an agent must turn a long interaction history full of distractors into memory, then act in the environment to finish a later task. Four task families test passive observation, dynamic tracking, interaction failure and experience generalization. Its baseline, Embodied-Memorizer, stores spatial, event and scene memories and raises GPT-5.4-mini by 23.6 success-rate points.

## Problem

- Existing embodied benchmarks test memory only inside single tasks such as navigation, question answering or state revision, and never cover all four memory demands together in one interactive evaluation.
- Agent-memory benchmarks such as LoCoMo, LongMemEval and WorldMemArena score answers or reconstructed knowledge, not whether remembered information correctly guides later physical actions in an environment.
- Strong MLLMs fail long-horizon embodied tasks mostly through memory deficits: forgotten visual cues, missed state changes, unrecorded failure feedback and poor experience transfer together explain 91% of sampled failures.

## Method

- **EMem-Bench** construction pipeline: joins AI2-THOR rooms into multi-room homes and filters ProcTHOR homes, plants a memory cue per task family, injects ==PDDL-planned== distractor trajectories, then applies four-layer automated validation and manual review.
- **Embodied-Memorizer** (EMem): an external memory with a ==spatial entity graph== holding each object's latest location and state, an ==event memory== of actions, feedback and corrections, and a ==room-scoped scene memory==.
- **EMem-8B**: Qwen3-VL-8B ==fine-tuned== on teacher-supervised ProcTHOR trajectories to decide what to write, which memories to query and how to act, plus a new ==Error Recurrence Rate== metric.

## Results

- The strongest full-context model, Gemini-3-Flash, reaches only **64.2%** average success rate; embodied MLLMs lag, with RynnBrain-8B at **3.6%** and Cambrian-S-7B at **0.8%**, against **25.4%** for Qwen3-VL-8B.
- EMem on GPT-5.4-mini reaches **58.9%** average success rate, **23.6 points** above full context and **21.1** above TeleMem; EMem-8B beats its Qwen3-VL-8B backbone by **20.6 points**.
- Adding maximal historical RGB frames lowers success rate from **36.6% to 26.2%** while raising tokens **4.9x** and latency **9.5x**; removing any single memory module cuts average success rate by **11-12 points**.

## Takeaways

> [!tip] Key Insights
> - More raw context hurts embodied memory: structured, task-relevant memory beats feeding long multimodal histories, which lowers accuracy while multiplying compute cost.
> - Training for spatial perception or robot planning does not teach a model to keep, revise and act on world state over long interactions; memory is a separate skill.
> - The bottleneck is replacing stale state and reasoning over it, not retaining history; action errors are rare, so memory updating deserves more attention than motor execution.

## Detailed Report

### 1. Overview

A robot sees a book moved from the bed to a box and then to a desk. Later, it is asked to bring the book to a table. If it acts on the old location, it goes to the bed; if it uses the latest evidence, it goes to the desk. This is the paper's illustrative Dynamic Tracking example, not a measured success-rate result.

Seeing an object once, or retaining a long history, does not ensure the robot will use the right state later. The proposed system, EMem, does three things. It keeps the latest object state, preserves what actions and feedback taught, and connects visual details to their scene. It then retrieves the relevant records before acting again. In a controlled comparison of memory systems evaluated with GPT-5.4-mini as the shared backbone, EMem reaches 58.9% average success rate versus 37.8% for TeleMem.

Overview of EMem-Bench, showing representative examples of what the benchmark tests, not measured model performance. In the Dynamic Tracking example, the failure path returns to the bed using an outdated state; the success path goes to the desk using the updated state.

### 2. Three records, one loop

EMem keeps three complementary memories:

- **Spatial memory** is an entity graph that tracks the latest known locations and states. A new location replaces an outdated conflicting location.
- **Event memory** preserves actions, feedback, and corrections in order. It can summarize repeated corrections into a reusable rule.
- **Scene memory** stores selected visual context and associates objects with their scenes. This helps distinguish same-named objects in different rooms.

These memories operate in a loop. While processing history chronologically, the system writes supported observations, state changes, and outcomes without knowing the later target instruction. Once the task is given, it queries whichever records are relevant, combines them with the current observation, and generates actions. New observations and feedback update memory during execution.

### 3. What the comparisons establish

The authors test EMem on EmbodiedMemory-Bench (EMem-Bench), which contains 2,554 executable episodes. In each episode, an agent receives an earlier multimodal interaction history and must use it to complete a later task by acting in the simulator.

Success rate (SR) is the share of episodes reaching the target terminal state. The overall average is the equally weighted mean of the four task-family SRs.

**Comparison with other memory systems.** With GPT-5.4-mini as the matched backbone, EMem scores 58.9% average SR and 24.3% error-recurrence rate (ERR). TeleMem scores 37.8% SR and 35.7% ERR. ERR is the rate of repeated memory-related errors such as acting on stale locations, repeating known failures, or violating learned regularities. This is the best overall result among the evaluated memory systems in that comparison.

**Adding raw visual history.** A second test asks whether a model can simply be given more historical images. For GPT-5.4-mini on the same 800 episodes, adding historical RGB images decreased average success from 36.6% to 26.2%. Over the same change, per-episode mean input tokens rose from 41,770 to 206,489, and model-step latency rose from 4.1 to 39.1 seconds. Both conditions retained the complete textual history and current RGB observation, and latency excludes simulator rendering.

This test compares raw-history input; it does not compare EMem directly against the expanded-image condition. It shows that adding raw images did not help in this tested setup. It does not prove that every visual-history method or context strategy will fail.

EMem memory ablation with GPT-5.4-mini as the backbone. Each row removes one memory while leaving the other two active. The full system reaches 58.9 average SR, compared with 47.9 without spatial memory, 46.9 without event memory, and 47.3 without scene memory.

In the ablation, all three removals lower average SR. The largest task-specific drops align with the authors' interpretation: spatial memory most supports Dynamic Tracking, event memory supports Interaction Failure and Experience Generalization, and scene memory supports Passive Observation. These results support contributions from each component in this setup. They do not establish that each component is the only cause of its associated task-family performance.

### 4. Remember the change

Embodied memory must preserve what was seen, and also what actions and feedback changed or revealed. It must then bring the relevant evidence back when the robot acts. The benchmark is primarily simulation-based, and its results do not establish long-term memory performance on physical robots.
