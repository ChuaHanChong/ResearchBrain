# VLCP: Vision Language Control Policy Closed-Loop Code Replanning for Robot Manipulation

> [!summary] Summary
> VLCP keeps a frozen VLM as a code-writing manipulation policy: every K=50 steps it re-observes multi-view RGB, proprioceptive state, and state delta, then rewrites a short Python control function mid-episode. Training-free, no fine-tuning. On a 57-task MuJoCo/RoboVerse sweep it reaches 35.1% pooled success versus 3.5% for an open-loop single-query variant.

## Problem

- VLA fine-tuning maps observations onto action tokens never seen in pretraining, discarding much of the reasoning ability that motivated using a large model.
- Existing code-generation policies query the model once before execution, so any runtime failure after the arm starts moving goes uncorrected for the rest of the episode.
- Monitoring and replanning methods detect failures but only retry a fixed policy or reselect a subtask, never rewriting the control code that actually failed.

## Method

- ==Closed-loop code replanning==: a frozen VLM is re-queried every K steps from live multi-view RGB, proprioceptive state, and an explicit state delta to rewrite the control(obs, J) function mid-episode.
- ==Three-block cache-structured prompt== (docs/API/examples, skill library, goal pin) plus truncated conversation history to keep replans cheap via prompt-cache reuse.
- **Cross-episode skill library**: helper modules emitted during any replan are saved atomically to a shared on-disk directory and re-injected verbatim into later prompts, within and across episodes.

## Results

- Closed-loop VLCP reaches **35.1%** pooled success (**60.0%** Object Picks, **33.3%** Kitchen, **23.5%** Living-Room) versus **3.5%** for the matched open-loop K=T ablation, a tenfold gap with non-overlapping confidence intervals.
- **27.3%** of failed grasps (**15 of 55** episodes with a failed grasp) are re-approached and lifted by a later replan, with a median of **3** replans to recover.
- A median **84%** of input tokens hit prompt cache, episodes need only about **10** VLM calls (median **18.8s** latency each), and all **778** generated code blocks parsed and compiled successfully.

## Takeaways

> [!tip] Key Insights
> - Closing the loop at the level of the artifact that actually fails, the control code itself, recovers far more than closing it at the observation or subtask level alone.
> - Keeping a frontier model inside its pretraining-fluent representation, here Python code instead of action tokens, preserves reasoning capability that fine-tuning to a new action space would erode.
> - Recovery is common but not guaranteed: replanning converts many first-attempt failures into successes but cannot buy more time within a fixed episode horizon.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

The integration of large language models (LLMs) and vision-language models (VLMs) into robotics, particularly for manipulation tasks, constitutes an active area of research. Existing approaches generally fall into several categories, each with distinct trade-offs.

One dominant paradigm involves **Vision-Language-Action (VLA) models**. These models adapt a pretrained VLM backbone to emit low-level robot actions. Examples include VLA-0, OpenVLA, and $\pi_0$. This adaptation typically requires extensive fine-tuning on large demonstration datasets, which can introduce a distribution mismatch, potentially diminishing the reasoning capabilities inherent to the original pretrained model. The paper notes that abstracting actions into plain text, as in VLA-0, can mitigate some of this mismatch, suggesting that minimizing deviation from the VLM's pretraining distribution is beneficial.

A contrasting approach is **code-as-policies**, where LLMs generate executable Python code to control robots. Pioneering works like Code-as-Policies, ProgPrompt, ELLMER, and Robotic Programmer leverage the LLM's proficiency in code generation. This method maintains the model's reasoning abilities by keeping it within its natural domain. However, a limitation of these methods is their typically **open-loop** nature; the code is generated once before execution, rendering the system blind to runtime failures or unexpected environmental changes. If a robot's grasp fails, the pre-written code cannot adapt, leading to task failure.

A third category involves **closed-loop monitoring and replanning methods** (e.g., Code-as-Monitor, DoReMi, Inner Monologue). These approaches aim to recover from failures during execution. However, they generally operate at a higher level, such as retrying a fixed policy, reselecting a subtask, or escalating to a planner. They typically do not modify the underlying control code that caused the initial failure. Therefore, they cannot address issues rooted in the specific logic of the control program itself. Act-Observe-Rewrite is a related work that rewrites the full controller, but it does so between trials rather than within a single ongoing episode.

VLCP positions itself at the intersection of these paradigms by addressing a specific gap: the ability to **close the loop on the control code itself within a single episode**. It integrates the code-generation capabilities of VLMs with a dynamic replanning mechanism, allowing the VLM to observe, diagnose, and rewrite its own control policy during task execution. This approach aims to leverage the VLM's full reasoning potential while enabling real-time adaptation and recovery from failures, a capability largely absent in prior code-as-policy methods and not specifically addressed by higher-level replanning strategies. Concurrent work like CaP-Agent0 shares some design points, indicating the relevance of this research direction.

### 2. Key Objectives and Motivation

The primary objective of this research is to develop and evaluate a novel, training-free robot manipulation framework, VLCP (Vision Language Control Policy), that enables **closed-loop code replanning within a single execution episode**. The motivation stems from several limitations observed in current approaches to integrating large language models with robot control:

1. **Preserving VLM Reasoning Abilities:** Traditional VLA models often require fine-tuning a pretrained VLM to emit novel action representations (e.g., specialized motor tokens). This process can pull the model away from its pretraining distribution, potentially diminishing the sophisticated reasoning and coding abilities that make VLMs valuable. The researchers are motivated to maintain the VLM's core competencies by having it generate control policies in a language it is already fluent in: Python code. This avoids the need for fine-tuning and specialized datasets.

2. **Addressing Open-Loop Limitations:** While code-as-policy methods (where a VLM writes a Python function for control) leverage the VLM's coding proficiency, they are typically open-loop. This means the code is generated once before execution begins, and the robot proceeds blindly, unable to react to or recover from runtime failures such as a missed grasp or an object shifting unexpectedly. A significant motivation is to introduce a mechanism that allows for real-time correction of such errors.

3. **Closing the Loop at the Appropriate Granularity:** Existing closed-loop or replanning methods in robotics often react at a higher level (e.g., retrying the same policy, selecting a different subtask, or replanning at a task level). These methods fail to address failures that originate from a flaw in the low-level control code itself. The core motivation for VLCP is to close the loop at the most relevant level: by **rewriting the actual control function** that failed, rather than merely re-executing it or escalating to a broader plan. This allows for a precise, code-level correction to runtime issues.

4. **Enabling Within-Episode Recovery:** The motivation includes demonstrating that such a code-level replanning mechanism can lead to within-episode recovery from failures. Instead of an entire episode being considered a failure due to an early misstep, the system should be able to re-observe the scene, diagnose the problem, and generate revised control code to correct the error and complete the task.

5. **Analyzing Feasibility and Cost:** A practical motivation is to assess the computational and financial feasibility of frequent VLM queries in a closed-loop setting. This involves investigating strategies like prompt caching and analyzing token usage and latency to ensure the approach remains viable for robotic applications despite the cost associated with frontier models.

6. **Exploring Generalization:** The research also aims to investigate the robustness of a training-free VLM-based policy to variations in task instructions, specifically through instruction reframing, to determine if its understanding is robust beyond specific phrasing seen in training data.

In summary, the key objective is to demonstrate that by repeatedly observing the environment and rewriting its own control code within a single episode, a frozen VLM can achieve robust robot manipulation, effectively recovering from failures and leveraging its native reasoning capabilities without requiring fine-tuning or extensive demonstration data.

### 3. Methodology and Approach

VLCP operates as a training-free closed-loop manipulation framework that integrates a frozen Vision-Language Model (VLM) into a robot control system. The core principle involves the VLM periodically re-observing the scene and rewriting the robot's control policy as a Python function within an ongoing episode.

**Problem Formulation:**
The system is designed for episodic manipulation tasks with a horizon $T$. At each time step $t$, the agent receives:
- Multi-view RGB images from two fixed cameras.
- A proprioceptive state vector (end-effector pose, joint positions).
- Poses of task-relevant objects provided directly from the simulator.
The policy is represented as a Python function `control(obs, J) -> actions`, where `obs` is the current observation, `J` is the $3 \times 7$ end-effector Jacobian (computed analytically), and `actions` is a dictionary of per-joint position targets for the simulator's PD controller.

**Closed-Loop Code as a Recovery Mechanism:**
VLCP employs a two-tiered closed-loop system:
1. **Within-Block Loop:** For $K$ steps, the compiled `control` function executes open-loop on its logic but is closed-loop on observations. It receives fresh `obs` and `J` at each step and can react to numeric state changes. However, its underlying logic remains fixed during these $K$ steps.
2. **Across-Blocks Loop (Code Replanning):** Every $K$ steps, the VLM is re-queried. It observes the scene and **rewrites the `control` function itself**. This is the mechanism for recovering from failures rooted in the control logic, as it allows the VLM to modify its strategy based on observed outcomes. The default $K$ is set to 50 steps, dividing a 500-step episode into approximately 10 replans. This cadence balances correction latency with VLM query costs.

**Role of Vision:**
While the system receives privileged object poses for initial task bootstrapping, multi-view RGB observations are critical for failure diagnosis. The VLM uses these images at each replan boundary to perceive the outcome of the previous control block (e.g., a gripper closing short, an object nudged out of place, a failed grasp). This visual feedback informs the VLM's decision to rewrite the control function. The use of privileged poses for initial object location is a design choice to isolate the study of closed-loop code replanning from perception errors.

**Prompt Structure for VLM Queries:**
Each VLM query for replanning is structured using a three-part system prompt, followed by a conversation history and a fresh user turn, designed to maximize cache reuse:
- **Block A (Static Prefix):** Contains general robot and environment documentation, the API for available skills, and three worked single-phase control examples. This part is largely constant.
- **Block B (Learned Skill Library):** Dynamically injected source code of helper modules currently saved in an on-disk skill library. It includes up to 12 most recent entries, allowing new control functions to import previously written skills.
- **Block C (Goal Pin):** The task identifier and natural-language goal. This is placed in the system prompt to prevent truncation from conversation history.
The **user turn** for replan $n$ includes:
- Multi-view RGB images from the *start* of the previous block.
- The code generated for the previous block and the $K$ action dictionaries it produced.
- Current synchronized multi-view RGB images.
- A JSON numeric observation summary (EE pose, joint positions, object poses).
- A prompt requesting a new `control` function for the next $K$ steps.
Images are only present in the live API turn; their textual references are removed from the history to avoid dangling pointers. The conversation history is truncated to a maximum of $H=20$ turns.

**Skill Library Mechanism:**
During replanning, the VLM can generate helper modules (e.g., `# skills/move_to_grasp.py`) alongside the main `control` function. These modules are atomically written to a shared on-disk directory and immediately importable. If an import fails, the file is reverted, and the error is surfaced to the VLM. These skill files persist across episodes and are re-injected into Block B of subsequent prompts, allowing for cross-episode skill accumulation and reuse.

**Experimental Setup:**
Evaluation is conducted in the MuJoCo simulator using RoboVerse, controlling a Franka Panda 7-DoF arm with a parallel gripper. The VLM used is GPT-5.5. The evaluation comprises a 57-task sweep across three scene families: Object Picks (10 LIBERO-Object tasks), Kitchen Scenes (30 tasks), and Living-Room Scenes (17 tasks). Each task runs for a single episode, with the skill library reset beforehand. Pooled success rates with Wilson 95% confidence intervals are reported.

**Baselines and Comparisons:**
- **Open-loop VLCP (K=T):** This is the primary controlled baseline. It uses the identical system but queries the VLM only once at the beginning of the episode (K=T), disabling within-episode replanning. This ablation isolates the contribution of the closed-loop code replanning.
- **VLA-0:** A demonstration-trained VLA, used as an upper reference for certain studies (e.g., instruction reframing), not as a direct, matched baseline due to its reliance on fine-tuning.
- **CaP-Agent0:** A concurrent training-free coding agent, cited as an external reference point but not a controlled comparison due to differences in benchmark and harness.

### 4. Main Findings and Results

The research presents several key findings demonstrating the efficacy and characteristics of the VLCP framework.

**1. Within-Episode Replanning Drives Success:**
The central experiment compared closed-loop VLCP (K=50) against its open-loop degenerate case (K=T), where the VLM is queried only once per episode. This comparison isolates the impact of within-episode code replanning.
- **Closed-loop VLCP (K=50)** achieved a pooled success rate of 35.1% [24.0, 48.1] across the 57-task sweep. Task family breakdown: 60.0% on Object Picks, 33.3% on Kitchen Scenes, and 23.5% on Living-Room Scenes.
- **Open-loop ablation (K=T)**, using the exact same system but without mid-episode replanning, resulted in a pooled success rate of 3.5% [1.0, 11.9]. Task family breakdown: 10.0% on Object Picks, 3.3% on Kitchen Scenes, and 0.0% on Living-Room Scenes.
This represents a tenfold increase in pooled success rate for the closed-loop variant, with non-overlapping confidence intervals in every scene family. This result indicates that within-episode replanning is a dominant factor for task completion in this setup, directly attributable to the ability to revise control code during execution.

**2. Generalization under Instruction Reframing:**
An evaluation was conducted on 6 LIBERO-Object tasks with original and reframed instructions (e.g., "pick up {object} and place it in the basket" vs. "put {object} in the basket").
- **VLA-0**, a fine-tuned VLA, showed uneven performance. While near-ceiling on original instructions (97.3% pooled), its performance dropped to 75.0% pooled under reframing. Notably, VLA-0 collapsed completely on tasks like 'butter' (96% to 0%) and significantly on 'bbq_sauce' (96% to 50%). This suggests VLA-0's high performance can depend on specific instruction phrasing rather than robust task understanding.
- **VLCP** exhibited no such systematic phrasing dependence. Its pooled success rate remained unchanged under reframing (40.0% in both conditions). Per-task differences were observed, but they scattered both ways, with no consistent pattern of collapse. This indicates a more robust understanding of task goals that is less sensitive to superficial linguistic variations.

**3. Within-Episode Recovery Behavior:**
To quantify the mechanism behind the success gain, the researchers analyzed 75 closed-loop pick-and-place episodes for within-episode recovery. A "failed grasp" was defined as the gripper being at the object, closed, but the object remaining on the surface.
- Of the 75 episodes, 55 contained at least one failed grasp.
- In 15 of these 55 episodes (27.3%), a later replan successfully re-approached and lifted the object, leading to recovery. The median number of replans required for recovery was 3.
- The open-loop (K=T) variant, by construction, has a 0% recovery rate from such failures.
Qualitative analysis of logged traces confirmed that the VLM explicitly diagnoses the failure (e.g., "recenter lower and regrasp... closed before the hand got low enough") and rewrites the control code to correct it, as illustrated in an example trace where a missed grasp is followed by a successful re-approach and lift.

**4. Cost, Latency, and Prompt Caching:**
The feasibility of frequent VLM queries was analyzed across 81 closed-loop episodes (721 replan calls).
- **VLM Calls:** A median of 10 VLM calls were made per episode (for a 500-step horizon with K=50).
- **Prompt Caching Efficiency:** Prompt caching was effective, with a median of 84% of input tokens served from the static, cache-eligible prefix of the prompt. The mean input tokens per replan was 43k.
- **Output Tokens:** The VLM emitted a median of 349 output tokens per replan (mean 421), indicating compact code generation.
- **Latency:** Median wall-clock latency per replan call was 18.8 seconds (mean 25.9 s), primarily due to server-side generation by the frontier model.
- **Code Validity:** All 778 generated control blocks across the episodes successfully parsed and compiled (100% validity), indicating the VLM's ability to produce syntactically and semantically correct code.
These results suggest that while VLM inference incurs latency, prompt caching and compact outputs make the replanning loop affordable in terms of token cost and practical for tasks not requiring high-frequency reactive control.

### 5. Significance and Potential Impact

The VLCP framework introduces a method for robot control that represents a notable shift in how vision-language models are utilized in manipulation tasks. Its significance and potential impact can be summarized as follows:

1. **Advancing Closed-Loop Robot Control:** VLCP's primary contribution is demonstrating a functional closed-loop system that operates at the level of the control code itself, within a single episode. This addresses a limitation of prior code-as-policy methods (which are often open-loop) and distinct from monitoring/replanning methods that do not modify the core control logic. By allowing the VLM to rewrite its own policy in response to observed failures, VLCP enhances the robot's ability to recover and adapt to unforeseen circumstances, leading to a tenfold increase in success rate over open-loop execution.

2. **Leveraging VLM Native Capabilities:** The approach allows a frozen VLM to directly generate and revise Python control code, leveraging its pre-existing fluency in coding and reasoning without requiring task-specific fine-tuning. This minimizes the risk of diminishing the VLM's general intelligence by forcing it into a novel action representation, thereby preserving its inherent capabilities. This "training-free" aspect reduces the heavy reliance on large, specialized demonstration datasets, a common bottleneck in robot learning.

3. **Enhanced Robustness and Generalization:** The study's findings on instruction reframing suggest that VLCP-enabled agents may possess a more robust understanding of task goals, less susceptible to specific linguistic phrasing than fine-tuned VLA models. This indicates a greater capacity for generalization to new instructions or variations in task descriptions.

4. **Tangible Mechanism for Recovery:** The direct measurement of within-episode recovery from failed grasps (27.3%) provides concrete evidence for the mechanism by which VLCP improves performance. This moves beyond anecdotal observations to quantify the system's ability to self-correct, offering clearer insights into how VLM reasoning contributes to real-time adaptation.

5. **Feasibility for Practical Application:** The analysis of cost and latency, coupled with the effectiveness of prompt caching, indicates that while VLM inference introduces a time delay, the system can be computationally affordable for certain classes of tasks. This provides a pathway for deploying VLM-driven code generation in robotic systems where high-frequency reactive control is not paramount.

6. **Foundation for Continual Learning:** The cross-episode skill library mechanism holds significant potential for future development. By allowing helper modules to be saved, reused, and composed across episodes without retraining, VLCP provides a natural substrate for continual learning. This could enable robots to progressively accumulate and refine a repertoire of behaviors and skills over time, leading to more competent and versatile agents.

7. **Reduced Data Dependency and New Paradigms:** More broadly, VLCP points towards a paradigm shift in robot policy learning that could bypass the arduous process of large-scale demonstration collection. By enabling robots to write, execute, observe, and self-correct their own code, the method offers a path towards more autonomous and self-improving robotic systems that leverage the vast knowledge encoded in foundation models.

**Limitations and Future Directions:**
The current instantiation of VLCP has limitations. Its reliance on simulator-provided object poses and its evaluation solely in simulation means its robustness to real-world perception noise and complex robot dynamics remains untested. The latency of frontier VLMs also restricts its application to relatively slow manipulation tasks. Future work could involve integrating learned detectors, exploring open-weight VLMs for affordability, and developing more sophisticated replanning cadences (e.g., task-adaptive schedules around contact events) to overcome these constraints. Investigating multi-seed evaluations and scaling the skill library across more diverse tasks on real robots are also identified as critical next steps.

In conclusion, VLCP represents a significant step towards developing adaptable and robust robot manipulation systems by directly integrating the reasoning and coding capabilities of large vision-language models into the control loop. Its ability to self-correct through code revision offers a promising direction for future research in embodied AI.
