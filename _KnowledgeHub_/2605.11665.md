# Nautilus: From One Prompt to Plug-and-Play Robot Learning

> [!summary] Summary
> NAUTILUS, a domain-specific harness for robot learning, automates complex research workflows by interpreting natural language prompts, reducing the engineering burden associated with integrating policies, benchmarks, and diverse robotic hardware. It provides standardized interfaces, chambered execution, and domain-specific procedural knowledge, enabling improved reproducibility and seamless real-robot deployment.

## Problem

- Robot learning research suffers from significant fragmentation across policy families, benchmarks, and robot embodiments, leading to substantial manual engineering effort for integration and reproduction (estimated Θ(N·M·K) complexity).
- Dependency conflicts, interface mismatches, and the lack of standardized validation protocols impede the reproducibility and trustworthiness of robot learning research.
- General-purpose LLM coding agents struggle with end-to-end reproduction in complex robot learning workflows due to the absence of a robust 'harness' encompassing orchestration, tools, and domain-specific priors.

## Method

- NAUTILUS is a two-layer harness with a 'substrate' for engineering invariants (typed interface contracts, chambered execution for dependency isolation, uniform inter-module communication) and a 'content layer' for robotics-specific procedures.
- It integrates 'Guides' to direct agent behavior, 'Sensors' for post-generation output validation, and a 'State' registry to store verified module knowledge, providing reusable agent skill sets and reducing integration complexity.
- The system provides unified execution environments that abstract away underlying complexities, allowing generated artifacts to run in isolated 'chambers' and communicate via a lightweight WebSocket protocol.

## Results

- NAUTILUS-generated benchmark wrappers faithfully reproduced published reference results for various policies (IL, VLA, WAM) across diverse benchmarks (LIBERO, ManiSkill, RoboCasa), with most wrapped outcomes closely matching published figures.
- The harness enabled shared-interface onboarding with similar or lower costs compared to a vanilla coding agent, showing efficiency gains (fewer agent turns) with predefined structures and greater benefits with weaker LLM backbones.
- Policies wrapped once by NAUTILUS were seamlessly deployed from simulation benchmarks to heterogeneous real-world robots (Franka arm, Unitree H1 humanoid) without requiring separate policy-integration efforts or modifications to the policy code.

## Takeaways

> [!tip] Key Insights
> - The primary bottleneck for automated robot learning workflows with LLMs is the absence of a robust domain-specific 'harness' rather than inherent limitations of the LLM models themselves.
> - Explicit, standardized interface contracts and uniform communication protocols are crucial, with an ablation study showing a significant drop in success (55.3%) without a stable inter-module transport mechanism.
> - Incorporating domain-specific procedural knowledge via guides, sensors, and a verified state registry significantly enhances an agent's ability to achieve end-to-end success in complex robotics research workflows.
