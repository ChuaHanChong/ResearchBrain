# Explore, Execute, Evolve: A Skill Acquisition and Reuse Loop for Embodied Agents

> [!summary] Summary
> RoboSkill is a framework that lets general-purpose multimodal agents accumulate and reuse robot skills through an Explore, Execute, Evolve loop: agents probe for missing information, execute via code calling a robot SDK with visual and tactile feedback, then self-review records into text-plus-code skill packages. On LIBERO-10 it raises first-episode success 12.5-25.0 points and cuts runtime 7.6-72.4% across four agents; real-robot success rises 8.3 points.

## Problem

- General-purpose multimodal agents solve robot tasks zero-shot but restart every execution from scratch, repeating perception, physical trial-and-error, and failure recovery at high time cost.
- Skill-distillation methods from web, GUI, and coding agents assume structured states and reliable action feedback, which physical interaction with partial observations and uncertain outcomes does not provide.
- VLA and world-action models execute fast but stay bound to their training data, generalizing poorly to unseen tasks such as a tilted nail needing a new strike direction.

## Method

- **RoboSkill**'s ==Explore, Execute, Evolve loop==: ==exploration subtasks==, such as probing table height by descending until contact, gather missing knowledge that guides ==closed-loop execution== and then skill updates feeding the next cycle.
- ==SDK-based interaction== instead of fixed tools: agents compose SDK calls into executable scripts like depth-to-pointcloud or contact-verified height checks, observing RGB, depth, ==finger tactile==, and wrist ==force/torque== signals.
- ==Self-reviewed skill packages==: at exit the agent consolidates session records into text guidance, ==hierarchical reusable code==, failure cases, trajectories, and keyframe metadata; later tasks select up to three relevant packages.

## Results

- On LIBERO-10, Opus 5 **SR@30m** jumps from **17.5%** to **82.5%** with average time falling from **80.9** to **22.3 minutes**; GPT-5.6 Sol final success rises from **82.5%** to **97.5%**.
- Cross-agent transfer: skills built by **four** other agents lift Kimi K3 first-episode success from **12.0%** to **42-66%**; on real robots, Astra-built skills raise Sol success from **13.3%** to **70.0%**.
- Ablations: removing code drops Sol first-episode success from **67.5%** to **15.0%**; removing tactile input on a real robot task lowers success from **90%** to **80%** and raises time from **20.0** to **33.6 minutes**.

## Takeaways

> [!tip] Key Insights
> - Executable code carries skills better than text alone, especially for weaker agents, because it preserves procedural details that would otherwise have to be re-derived through reasoning.
> - Skills distilled by one LLM agent transfer to different agents, suggesting embodied experience can be stored as model-agnostic text-plus-code artifacts rather than baked into policy weights.
> - Successive skill updates are not monotonic and agent-selected skill sets do not beat fixed rules for every model, so accumulated experience needs validation rather than blind appending.

## Detailed Report

### 1. Overview

When a robot moves cream cheese toward a basket, its grasp can fail. An uncertain depth estimate can also leave it unsure how high the table is. In the paper's illustrative example, the agent does not simply retry the grasp or start over. It probes down until it feels contact, verifies a table height of approximately 0.446 m, and then grasps successfully. This example is an illustration, not a benchmark result. The idea behind RoboSkill is that a robot agent should not have to rediscover every useful procedure from scratch. The record of its actions, including what failed, can become a skill that guides later work.

Schematic of the loop. Task context and selected skills feed an agent, which acts through an SDK and receives visual/tactile feedback. Session records and code feed an evolution step that produces skills for the library. Below is an illustrative example: a failed grasp, uncertain RGB-D depth, probing down to contact, a verified height of about 0.446 m, and a successful retry. It is not proof that the loop always resolves grasp failures.

### 2. From a retry to a skill

The loop starts when the agent receives a task. Available skills guide optional exploration when information is missing. The agent then executes code through the robot SDK and uses visual and tactile feedback to continue or revise its actions. It also keeps records and the executed code. When the agent exits, it reviews the session and creates or updates a skill. Later tasks can select up to three relevant packages.

A skill is more than a fixed replay. It combines textual strategy and applicability conditions with reusable code and supporting records, including failures and trajectories. The authors defer this consolidation until the task ends because reviewing after every subtask would add overhead.

Tactile feedback means pressure or force/torque information. It provides evidence of contact that images alone may miss. In the cheese example, contact provides a check on the table height, and the resulting estimate guides the next attempt.

### 3. Does saved experience change outcomes?

LIBERO-10 is a ten-task simulation benchmark. The main protocol uses four evaluation seeds per task and excludes the seed used to construct the skill. That gives 40 task–seed evaluation cells per condition. The paper reports two main metrics. SR@30m is the percentage of cells successful within 30 minutes. Average time is time to success or termination, averaged over all cells, including failures.

For Opus 5 on LIBERO-10, SR@30m rises from 17.5% without saved skills to 82.5% with RoboSkill. Average time falls from 80.9 to 22.3 minutes. Across all four agents, first-episode and 30-minute success increase, while episode count and time decrease. Some final success rates were already 100%. The clearest change is therefore reaching success sooner or with fewer resets, rather than raising eventual success everywhere.

Reported LIBERO-10 simulation metrics for four models, comparing Baseline and RoboSkill. For Opus, SR@30m is 17.5% vs 82.5%, and Avg. Time is 80.9 vs 22.3 minutes. Average time includes failures.

The real-robot evaluation covers six easy and six hard tasks, with ten trials per task. On these tasks, GPT-6 Astra's first-episode success rises from 91.7% to 100.0% on easy tasks and from 80.0% to 88.3% on hard tasks. Average time over successful trials only falls from 20.3 to 16.6 minutes and from 27.0 to 23.1 minutes, respectively.

### 4. Does the code matter?

A sharper test removes executable code from a skill while keeping its textual guidance. For Sol, adding code raises first-episode success from 15.0% to 67.5% and cuts average time from 67.1 to 39.9 minutes. Code reduces average time for all four agents. Opus's first-episode success, however, slips from 70.0% to 67.5%. The paper measures elapsed time, not reasoning tokens.

First-episode success and average time for text-only versus text-plus-code skills. The comparison removes code while retaining textual guidance. Sol improves from 15.0% to 67.5% and from 67.1 to 39.9 minutes. Opus's success falls from 70.0% to 67.5%, while its time falls from 32.1 to 30.4 minutes.

### 5. Experience as the contribution

RoboSkill's contribution is a loop that explores, acts while checking feedback, and keeps the procedure as text plus adaptable code. In these tested settings, saved skills helped agents reach success sooner. The ablation does not show that code is the only cause of the overall gains, and the results do not establish that every skill transfers or every update helps.
