# OmniManip: Towards General Robotic Manipulation via Object-Centric Interaction Primitives as Spatial Constraints

> [!summary] Summary
> This paper presents a novel object-centric representation system for bridging high-level vision-language models with precise robotic manipulation

## Problem

- Current VLMs lack fine-grained 3D spatial understanding needed for precise manipulation
- Fine-tuning VLMs on robotic datasets is costly and limits generalization
- Existing methods for defining and using interaction primitives are task-agnostic and unstable

## Method

- Introduces object-centric interaction primitives defined in canonical space based on object functionality
- Implements a dual closed-loop system: one for planning through primitive resampling and VLM checking, another for execution via pose tracking
- Uses off-the-shelf models for universal 6D pose estimation and grasping without requiring VLM fine-tuning

## Results

- Demonstrated strong zero-shot generalization across diverse manipulation tasks and robustness across different viewpoints compared to baseline methods
- Achieved over **15%** improvement in performance with closed-loop planning
- System proved effective for automated generation of demonstration data for behavior cloning

## Takeaways

> [!tip] Key Insights
> - An object's canonical space, defined by functional affordances, provides structured way to describe interaction primitives
> - Interaction primitives in canonical space bridge VLM reasoning with precise 3D spatial constraints
> - Self-correction through rendering and resampling enables closed-loop reasoning and mitigates VLM hallucination issues

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

Robotic manipulation in unstructured environments remains one of the most challenging problems in robotics. While Vision-Language Models (VLMs) have demonstrated impressive reasoning capabilities for a variety of tasks, they often lack the fine-grained 3D spatial understanding necessary for precise robotic manipulation. Fine-tuning VLMs on robotic datasets (creating Vision-Language-Action models) is costly, time-consuming, and leads to agent-specific models with limited generalizability.

### 2. Key Objectives and Motivation

OmniManip addresses these challenges by introducing a novel framework that bridges the gap between high-level reasoning from VLMs and the precision required for robotic manipulation. Unlike previous approaches that require task-specific training or VLM fine-tuning, OmniManip represents robotic actions in terms of object-centric interaction primitives—points and directions defined within the canonical space of objects—translated into spatial constraints that guide robot motion.

### 3. Methodology and Approach

#### 3.1. Object-Centric Interaction Primitives

The core innovation of OmniManip is its object-centric representation approach. Rather than attempting to directly map from language to robot actions, OmniManip uses interaction primitives that capture the essential spatial relationships required for manipulation tasks:

1. **Interaction Points**: Key locations on objects where interaction occurs (e.g., the spout of a teapot for pouring)
2. **Interaction Directions**: Orientations that define how objects should be manipulated (e.g., the pouring direction of a teapot)

These primitives are defined in the object's canonical space, which is based on the object's functional affordances. This makes the representation semantically meaningful and structured:

```
InteractionPrimitive = {
    point: (x, y, z) in object canonical space,
    direction: unit vector in object canonical space
}
```

This representation offers several advantages:
- It is object-centric, focusing on the objects being manipulated rather than robot-specific parameters
- It captures the task-relevant spatial relationships between objects
- It generalizes across different objects with similar functional affordances
- It can be translated into concrete spatial constraints for robot motion planning

#### 3.2. System Architecture

OmniManip's architecture consists of four main components:

1. **Task Decomposition and Object Grounding**: Breaks complex tasks into stages involving active and passive objects
2. **Primitive Extraction**: Extracts interaction primitives from objects using VLMs and LLMs
3. **Dual Closed-Loop System**: Ensures robust planning and execution through continuous feedback
4. **Trajectory Optimization**: Generates robot motion based on spatial constraints

#### 3.3. Task Decomposition and Object Grounding

OmniManip starts by decomposing complex tasks into stages. Each stage involves:
- An action (e.g., grasp, pour)
- An active object (that performs the action)
- A passive object (that receives the action)

For example, the task "Pour tea into the cup" is decomposed into:
1. **Stage 1**: Grasp the handle of teapot with gripper
 - Action: Grasp
 - Active: Gripper
 - Passive: Teapot
2. **Stage 2**: Pour tea from teapot into cup
 - Action: Pour
 - Active: Teapot
 - Passive: Cup

This decomposition allows OmniManip to focus on the relevant objects and their interactions at each stage of the task.

#### 3.4. Interaction Point Grounding

After identifying the relevant objects, OmniManip needs to locate the interaction points on these objects. This is done through:

1. **Object Canonicalization**: A universal 6D object pose estimation model is used to determine the canonical pose of objects
2. **3D Mesh Generation**: A single-view 3D generation network creates detailed object meshes
3. **Interaction Point Localization**: Points are identified using VLM with visual prompting

For points that are visible in the scene, direct localization is performed. For invisible or intangible points (like the inside of a teapot), OmniManip uses multi-view reasoning to infer their positions:

```python
# Pseudocode for interaction point grounding
def ground_interaction_point(object_mesh, view_image, task_description):
    # Create grid on object surface
    grid_points = generate_grid_on_object_surface(object_mesh)

    # For visible points
    if point_is_visible(object_mesh, view_image):
        heatmap = vlm.generate_heatmap(view_image, f"Where should I interact with the {object_name} to {task_description}?")
        interaction_point = get_max_heatmap_location(heatmap)

    # For invisible points
    else:
        multi_views = generate_multiple_views(object_mesh)
        scores = []
        for view in multi_views:
            score = vlm.evaluate_point(view, grid_point, task_description)
            scores.append(score)
        interaction_point = grid_points[argmax(scores)]

    return interaction_point
```

#### 3.5. Interaction Direction Sampling

In addition to interaction points, OmniManip identifies interaction directions that define how objects should be oriented during manipulation:

1. **Principal Axis Sampling**: Initial directions are sampled along the object's principal axes
2. **Direction Evaluation**: VLM and LLM are used to evaluate the relevance of these directions to the task
3. **Direction Selection**: The most appropriate direction is selected based on these evaluations

For example, when pouring tea from a teapot, the system would evaluate different potential pouring axes and select the one that extends outward from the spout.

```
# Direction evaluation using VLM
Prompt: "I want to pour tea from this teapot into a cup. Is the highlighted axis appropriate for this task?"

Response for horizontal axis through spout: "Yes, this axis is appropriate as it extends from the spout, which is where the tea will pour from."

Response for vertical axis: "No, this axis is not appropriate for pouring because it does not align with the flow direction from the spout."
```

#### 3.6. Dual Closed-Loop System

One of the key innovations of OmniManip is its dual closed-loop system, which ensures robust planning and execution:

1. **Planning Loop (Primitive Resampling)**: This loop uses a self-correction mechanism based on Resampling, Rendering, and Checking (RRC) to mitigate hallucination issues in the VLM. The system renders interaction images, submits them to the VLM for validation, and refines the primitives based on the feedback.

2. **Execution Loop (Pose Tracking)**: This loop uses a 6D object pose tracking algorithm to continuously update the poses of the active and passive objects in real-time, allowing for dynamic adjustments to the end-effector's target pose.

The planning loop is particularly important for addressing VLM hallucinations. When the VLM proposes interaction primitives, these are rendered in a virtual environment and checked again by the VLM:

```python
# Pseudocode for self-correction
def self_correct_primitives(interaction_primitives, object_meshes, task):
    while True:
        # Render the scene with current primitives
        rendered_image = render_scene(object_meshes, interaction_primitives)

        # Check if the primitives are appropriate
        evaluation = vlm.evaluate(rendered_image, f"Is this a good way to {task}?")

        if evaluation.is_positive():
            return interaction_primitives

        # Extract feedback from VLM
        feedback = vlm.get_feedback(rendered_image, f"How should I adjust to better {task}?")

        # Update primitives based on feedback
        interaction_primitives = update_primitives(interaction_primitives, feedback)
```

#### 3.7. Trajectory Optimization

Once the interaction primitives have been established and validated, OmniManip converts them into spatial constraints for trajectory optimization. The optimization aims to generate smooth, collision-free motions that satisfy the defined constraints:

The constraints are expressed as relationships between the active and passive objects:
- Alignment of active and passive axes
- Distance relationships between active and passive points
- Orientation requirements for specific interactions

The trajectory optimization problem can be formulated as:

$$
\min_{\mathbf{q}} \sum_{t=1}^{T} w_1 \| \mathbf{q}_t - \mathbf{q}_{t-1} \|^2 + w_2 \| \ddot{\mathbf{q}}_t \|^2 + w_3 L_{constraint}(\mathbf{q}_t) + w_4 L_{collision}(\mathbf{q}_t)
$$

where $\mathbf{q}_t$ is the robot configuration at time $t$, $L_{constraint}$ is the constraint loss, and $L_{collision}$ is the collision loss.

### 4. Main Findings and Results

#### 4.1. Experimental Results

OmniManip demonstrated strong zero-shot generalization across a variety of manipulation tasks without task-specific training. The system was evaluated on several benchmark tasks including:

1. Pouring tasks (tea, water)
2. Insertion tasks (pens into holders)
3. Assembly tasks
4. Articulated object manipulation

Compared to baseline methods (VoxPoser, CoPa, and ReKep), OmniManip achieved superior performance in open-vocabulary manipulation tasks. Key findings include:

- Higher success rates across all task categories
- Improved stability due to the object-centric canonical representation
- Consistent performance across different viewpoints
- Effective handling of both visible and invisible interaction points
- Robust performance in the presence of distractors

The dual closed-loop system proved particularly effective, with the self-correction mechanism significantly reducing planning failures caused by VLM hallucinations.

### 5. Significance and Potential Impact

#### 5.1. Limitations and Future Work

Despite its strong performance, OmniManip has several limitations that point to directions for future work:

1. **3D Mesh Quality**: The system relies on single-view 3D generation, which can produce imperfect meshes. Improving 3D reconstruction methods would enhance performance.

2. **Computational Efficiency**: Multiple VLM calls for interaction point grounding and direction sampling can be computationally expensive. More efficient methods for primitive extraction could improve real-time performance.

3. **Deformable Objects**: The current implementation focuses on rigid and articulated objects. Extending the approach to handle deformable objects would increase its applicability.

4. **Force Feedback**: Incorporating force sensing and feedback would enable more precise manipulation for tasks requiring specific forces.

5. **Multi-stage Planning**: Currently, each stage is planned independently. Developing methods for joint optimization across task stages could improve overall task success.

#### 5.2. Conclusion

OmniManip presents a significant advancement in general robotic manipulation by bridging the gap between high-level reasoning from VLMs and low-level precision required for robotic control. Through its object-centric interaction primitives and dual closed-loop system, OmniManip enables robots to perform diverse manipulation tasks without task-specific training or VLM fine-tuning.

The system's ability to leverage the reasoning capabilities of VLMs while addressing their limitations in 3D spatial understanding makes it particularly valuable for applications requiring adaptable manipulation skills in unstructured environments. By representing manipulations in terms of semantically meaningful interaction primitives, OmniManip provides a more interpretable and generalizable approach to robotic manipulation.

Future work will focus on extending the system to handle a wider range of objects and environments, improving computational efficiency, and incorporating additional sensory modalities for more robust performance.
