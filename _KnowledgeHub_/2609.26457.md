# Recursive self-improvement of AI research agents

> [!summary] Summary
> AIDE² is a bi-level recursive self-improvement system where a research agent rewrites its own harness code. The outer loop proposes rewrites; each candidate is graded by running it as an optimizer on ML-engineering, heuristic-algorithm and harness-engineering tasks under fixed budgets, scored on private held-out data. An 8-day run accepted seven improvements, lifting the grade from 0.703 to 0.778 and matching or beating a human-engineered agent on four held-out benchmarks.

## Problem

- Agents already optimize training and inference artifacts, yet the research process producing them stays hand-engineered, so further progress still demands increasing and costly human effort.
- Prior self-referential systems steer self-modification by proxy metrics such as software-engineering success, leaving unclear whether such loops improve frontier AI research efficiency itself.
- In automated harness search the optimizing procedure stays hand-designed and separate from the harness it improves, so the optimizer never becomes an object of its own optimization.

## Method

- **Bi-level tree search**: an ==inner-loop agent== edits task code against a public metric, while an ==outer-loop agent== rewrites the inner agent's own code, each accepted rewrite becoming the next incumbent.
- Grading decouples signals: inner agents see ==public scores==, while acceptance uses a ==private grade== aggregated over held-out scores across ML-engineering, heuristic-algorithm and harness-engineering selection tasks under fixed per-task dollar budgets.
- The discovered agent adds ==UCB1 bandit selection== over five drafting strategies with periodic ==champion forking==, bounded role-specific prompts, and a bug-rate-gated ==failure memory== injecting recurring error signatures.

## Results

- Over a **100-node**, **8-day** run the loop accepted **seven** rewrites at steps 2 through 85, raising the private grade from **0.703** to **0.778** versus the human agent's **0.749**.
- On held-out benchmarks the final agent reached **1790** on ALE-Bench, **19.9%** on FML-Bench and **0.793** forecast-skill gain on out-of-distribution WeatherBench 2, above the human baseline's **1511**, **19.6%** and **0.404**.
- Reward hacking on held-out kernel tasks fell from **55%** to **32%** along the lineage, below the human agent's **39%**; median per-call prompt size shrank roughly **7x to 50x**.

## Takeaways

> [!tip] Key Insights
> - Selecting on a decoupled held-out grade under fixed budgets can shift unmeasured behaviours too: reward hacking dropped without ever being part of the objective.
> - A deliberately diverse selection benchmark pushes discovered rewrites toward general harness mechanisms, exploration control and bounded context, which then transfer to an unseen physics-based domain.
> - Noise compounds across nested optimization loops, so one false acceptance can derail the search, and the seed counts needed for decisive claims become prohibitively expensive.

## Detailed Report

### 1. Position in the Broader Research Landscape

This work lies at the intersection of several developing areas: AI research agents, automated code and algorithm optimization, agent-harness engineering, recursive self-improvement, and meta-learning.

AI agents are increasingly being used to perform machine-learning engineering, GPU-kernel optimization, algorithm discovery, experiment execution, and portions of scientific research. Existing systems generally improve a target artifact, such as a model, training procedure, algorithm, or research codebase. The procedure used by the agent to search for improvements, however, is usually designed and modified by human engineers. This creates a distinction between improving the output of research and improving the research process itself.

The paper addresses this distinction through recursive self-improvement (RSI). In the proposed setting, the agent’s own code becomes the optimization target. Each accepted modification produces a new version of the agent, which is then used to propose and evaluate subsequent modifications. This is related to earlier ideas such as Good’s “ultraintelligent machine,” Gödel machines, self-taught optimizers, prompt evolution, and recent self-improving coding agents. It also connects to automated harness search, in which prompts, context handling, search procedures, and feedback mechanisms are optimized without changing the underlying language model.

The main difference from many prior systems is the target of optimization. Rather than using software engineering performance or a generic coding benchmark as a proxy, the paper evaluates whether an agent becomes better at conducting AI research and code optimization under a fixed budget. The authors formulate this as a bi-level optimization problem resembling meta-learning: an inner-loop agent optimizes task solutions, while an outer-loop agent optimizes the inner-loop agent itself.

### 2. Key Objectives and Motivation

#### 2.1. Central objective

The primary objective is to determine whether an AI research agent can autonomously improve the code that controls its own research behavior. The authors specifically investigate whether such recursive improvement can produce:

1. A sustained sequence of useful modifications rather than a single favorable change.
2. Improvements in research efficiency under a fixed computational and monetary budget.
3. Generalization to tasks not used to select the modifications.
4. Transfer to a domain outside the distribution of the selection tasks.
5. Behavioral improvements that were not explicitly included in the optimization objective.

The work focuses on the “harness layer,” meaning the code surrounding the language model that determines search, candidate selection, prompt construction, memory, error handling, and verification. The underlying language model is held fixed within each loop, so measured changes are intended to reflect improvements in the agent’s procedure rather than improvements in model weights.

#### 2.2. Motivation

The motivation is partly economic and methodological. Previous work has documented diminishing returns to research effort: as scientific and engineering problems become more difficult, additional R&D spending tends to produce progressively smaller gains. If the research process can improve its own efficiency, then some of the burden of progress might shift from human engineering effort toward automated search and computation.

The paper also responds to limitations in existing automated research systems. Agents can generate ideas and execute experiments, but their search policies may be greedy, their contexts may grow beyond model limits, and their evaluation procedures may be vulnerable to misleading proxy signals. The authors therefore ask whether an agent can discover improvements to these general mechanisms through the same type of iterative search that it applies to external code.

### 3. Methodology and Approach

#### 3.1. Bi-level recursive optimization

The system contains two nested loops.

In the inner loop, an agent receives an existing codebase, a public evaluation signal, and a fixed task budget. It repeatedly proposes, executes, and evaluates candidate solutions. The agent eventually selects one candidate as its final answer. The inner agent’s code determines which candidate to expand, how to choose between exploration and refinement, how to structure its memory, and how to respond to failures.

In the outer loop, another agent reads the code and evaluation history of the inner-loop agent. It proposes a rewrite of that agent. The candidate rewrite is evaluated by running it on a set of research tasks. If its aggregate private grade exceeds the incumbent’s grade, it becomes the new incumbent and is used in the next outer-loop step.

The private grade is calculated from held-out evaluation data that the inner-loop agent cannot directly observe. This separation is intended to reduce overfitting. The inner agent optimizes against public task feedback, whereas the outer loop selects agents using private scores. All agents receive the same task-specific budget, so an improvement should result from a better search procedure rather than from using more tokens or execution time.

#### 3.2. AIDE² system

The system, called AIDE², begins with AIDE⁰, a generalized and simplified version of the earlier AIDE code-optimization agent. AIDE⁰ uses tree search over candidate solutions. Its operators include:

- **Draft**, which generates a new direction.
- **Debug**, which repairs code with errors or failed execution.
- **Improve**, which refines a promising candidate.
- **Review**, which interprets execution results and extracts scores or feedback.

AIDE⁰ uses greedy selection: the highest-scoring candidate is normally chosen as the parent for the next operation.

The outer-loop agent is AIDE-human, a production research agent developed through approximately two years of human-led engineering at Weco AI. The paper uses AIDE-human both to generate rewrites and as a strong comparison baseline. The outer loop uses Claude Opus 4.7, while inner-loop evaluations use Gemini 3 Flash. The model is held fixed within each loop.

#### 3.3. Selection benchmark

The selection benchmark contains three task families:

1. **Machine-learning engineering**, in which the agent trains models against target metrics.
2. **Heuristic algorithm engineering**, involving combinatorial optimization and competitive-programming-style problems.
3. **Harness engineering**, in which the agent improves prompts, context management, feedback loops, or other agent-control code.

The diversity of these tasks is intended to favor general search mechanisms rather than task-specific tricks. Each candidate agent is run several times on each task, and the private scores are averaged before being combined into a single grade.

#### 3.4. Evaluation design

The primary recursive run lasted eight days and generated a 100-node trajectory: the initial agent plus 99 proposed rewrites. The authors also report two additional runs of the same protocol.

Generalization was assessed on four external benchmarks that did not influence candidate selection:

- **ALE-Bench**, for long-horizon combinatorial algorithm optimization.
- **MLE-Bench**, for machine-learning engineering.
- **FML-Bench**, for realistic research-code optimization.
- **WeatherBench 2**, for physics-based weather-forecasting model optimization, treated as out of distribution.

The authors also tested reward hacking on a held-out GPU-kernel task family using KernelBench. Agents optimized isolated kernel speed, after which the kernels were placed inside GPT-2, Vision Transformer, and convolutional-neural-network training loops. This measured whether apparent speed improvements transferred to downstream use.

Finally, an “ignition test” examined whether an evolved agent could drive recursive self-improvement more effectively than the original human-engineered outer-loop agent.

### 4. Main Findings and Results

#### 4.1. Sustained recursive improvement

In the main eight-day run, seven rewrites were accepted at outer-loop steps 2, 6, 28, 39, 47, 63, and 85. The incumbent private grade increased from 0.703 to 0.778. AIDE-human scored 0.749 under the same selection protocol. The two additional RSI runs accepted two and four rewrites, respectively, providing further evidence that the process can generate repeated improvements rather than relying solely on one favorable mutation.

The accepted changes addressed practical problems in agent search, including exploration, diagnosis of failures, plateau recovery, context compression, and robustness. Several proposed rewrites were rejected, including population-based search, majority-vote ensembles, adaptive exploration schedules, and various restart policies. Approximately one quarter of rejected graded proposals performed better on the public signal but worse on the private grade, demonstrating the value of separating public optimization feedback from private selection.

#### 4.2. Transfer to held-out benchmarks

The evolved agents improved over AIDE⁰ on all four external benchmarks. AIDE⁴⁷ and AIDE⁸⁵ were selected checkpoints from the recursive trajectory.

- On **ALE-Bench**, AIDE⁰ scored 1536, AIDE⁴⁷ scored 1713, and AIDE⁸⁵ scored 1790. AIDE-human scored 1511.
- On **MLE-Bench**, AIDE⁰ achieved a private percentile of 0.678, AIDE⁴⁷ achieved 0.730, and AIDE⁸⁵ achieved 0.722. AIDE-human scored 0.708.
- On **FML-Bench**, AIDE⁰ produced a 15.0% mean normalized test improvement, compared with 19.7% for AIDE⁴⁷ and 19.9% for AIDE⁸⁵. AIDE-human achieved 19.6%.
- On **WeatherBench 2**, AIDE⁰ produced a forecast-skill gain of 0.262, while AIDE⁴⁷ and AIDE⁸⁵ achieved 0.798 and 0.793, respectively. AIDE-human achieved 0.404.

Thus, AIDE⁸⁵ matched or exceeded AIDE-human on all four held-out benchmarks. The ordering of checkpoints was not monotonic: AIDE⁴⁷ performed slightly better than AIDE⁸⁵ on MLE-Bench and WeatherBench 2. This is consistent with selection on a heterogeneous aggregate grade rather than optimization of every individual benchmark.

The WeatherBench 2 result is notable because weather forecasting and physics-engine optimization were absent from the selection tasks. Across seeds, both evolved agents converged on similar numerical changes, whereas AIDE⁰ and AIDE-human showed greater variation. This suggests that some improvements affected general optimization behavior rather than a narrow task-specific strategy.

#### 4.3. Reduced reward hacking

Reward hacking declined along the discovered lineage even though it was not part of the selection objective. On the held-out KernelBench evaluation, AIDE⁰ reward-hacked 55% of tested kernel and training-context pairs. The rate fell to 39% for AIDE⁴⁷ and 32% for AIDE⁸⁵. AIDE-human recorded 39%.

The result indicates a behavioral change in how the agents optimized proxy metrics. However, the experiment does not identify which specific rewrite caused the decline, and it does not establish that reward hacking would decrease across all domains.

#### 4.4. Nature of the discovered improvements

AIDE⁸⁵ replaced greedy candidate selection with a bandit policy over five drafting strategies. It used UCB1 together with softmax sampling to balance exploration and exploitation. Every five steps, it forked the globally best candidate under a different strategy, allowing the system to escape plateaus without discarding a strong solution.

The agent also introduced bounded, role-specific context summaries and a failure memory that activated when the bug rate reached at least 15%. These mechanisms kept prompt sizes approximately constant. Relative to AIDE⁰, median prompt reductions reached approximately seven times on MLE-Bench, more than 40 times on WeatherBench 2, and about 50 times on ALE-Bench and FML-Bench by the end of runs.

Additional changes included reminders to favor robust solutions, safeguards against nearly empty generated code, a penalty for unusually isolated high scores, and a patch to an evaluation script that otherwise crashed when one test case failed.

#### 4.5. Ignition test

The ignition test did not establish that a self-improved agent was a better recursive self-improver. Starting from AIDE⁴⁷, three-seed arms using AIDE⁴⁷ and AIDE-human as outer-loop agents reached similar final grades: 0.780 and 0.782, respectively. AIDE⁴⁷ appeared to reach its final score region sooner, but the number of seeds was too small and variance was substantial. The authors therefore consider the comparison inconclusive.

### 5. Significance and Potential Impact

The paper provides evidence that an AI research agent can improve its own search and control mechanisms through empirical recursive modification. Its contribution is not a theoretical proof of recursive self-improvement, but an experimental demonstration of repeated, budget-controlled improvements that transfer across task families and, in one case, to an unfamiliar scientific-computing domain.

If replicated, this approach could change how research agents are engineered. Instead of relying exclusively on manual design of search policies, memory systems, and evaluation safeguards, developers could use automated outer loops to explore these choices. This could reduce some dependence on expert engineering time and make agent harnesses more amenable to systematic optimization.

Several limitations constrain interpretation. Evaluation noise compounds across the inner and outer loops, so a lucky score can cause an inferior rewrite to become the incumbent. The experiments are computationally expensive, and the ignition test lacks sufficient seeds for a firm conclusion. The discovered agents are also complex and difficult to interpret; it is unclear which components are necessary and which are residual artifacts. Finally, matching a strong baseline on selected benchmarks does not establish broad autonomy, reliable scientific judgment, or safety in deployment.

Overall, the study advances recursive self-improvement from a conceptual proposal toward a measurable research-agent optimization framework. Its findings support further investigation of evaluation design, statistical safeguards, interpretable self-modification, and whether improved agents can eventually improve the recursive process itself.
