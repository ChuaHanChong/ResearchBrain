# Code-as-Symbolic-Planner: Foundation Model-Based Robot Planning via Symbolic Code Generation

> [!summary] Summary
> Introducing "Code-as-Symbolic-Planner," a framework that enables large language models to directly generate executable symbolic code for robot task and motion planning, rather than merely producing text-based plans or interfacing with external solvers. This system from MIT and Harvard achieved an average success rate of 52.3% with GPT-4o, an improvement of 24.1% over the best baseline, and demonstrated superior scalability in complex multi-robot planning scenarios.

## Problem

- Existing LLM-based robot planning methods either lack the symbolic computation necessary for complex numeric constraints and search algorithms or are limited by the generalizability of pre-defined external solvers.
- Traditional Task and Motion Planning (TAMP) approaches often require significant human expertise to implement specialized planners and formal representations, hindering broader applicability.
- The unreliability of raw LLM-generated code in initial attempts at complex planning tasks presented a challenge for robust robotic execution.

## Method

- A multi-agent, multi-round guidance framework allows ==Large Language Models (LLMs)== to generate executable Python code that functions as the robot's Task and Motion Planning (TAMP) planner, solver, and checker.
- The system employs three LLM agents (TaskLLM, SteerLLM, CheckLLM) and a rule-based Symbolic Complexity Checker, which work iteratively to refine and verify the generated planning code.
- Feedback from CheckLLM (verifying plan correctness) and the Symbolic Complexity Checker (assessing algorithmic sophistication) guides SteerLLM to prompt TaskLLM for more robust and algorithmic code generation over up to three rounds.

## Results

- The framework achieved an average success rate of **52.3%** using GPT-4o, representing a **24.1%** improvement over the best baseline, and reached **63.9%** success with Claude3-5-Sonnet across seven diverse TAMP tasks.
- It demonstrated enhanced scalability, exhibiting significantly slower performance degradation as task complexity increased, outperforming other methods in handling more challenging scenarios.
- The approach achieved **100%** success in real-world and 3D simulation experiments for the BoxNet task with up to three robots, maintaining **95%** with six robots, showcasing practical applicability and robustness to execution errors.

## Takeaways

> [!tip] Key Insights
> - Large Language Models possess the capability to dynamically generate sophisticated symbolic algorithms, such as A* search or DFS, to directly solve complex robotic planning problems.
> - Iterative guidance and objective verification, provided by dedicated LLM agents and a complexity checker, are crucial for transforming initial LLM outputs into reliable and correct algorithmic solutions.
> - Integrating symbolic computation with an LLM's common-sense reasoning, through code generation, overcomes the limitations of purely textual planning and rigid pre-defined solvers.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

The field of robotics has long sought to enable autonomous agents to execute complex tasks in dynamic environments, a challenge encapsulated by Task and Motion Planning (TAMP). Traditionally, TAMP problems are solved using formal representations like PDDL or temporal logic, requiring specialized planners and significant human expertise. While effective for well-defined scenarios, these methods often lack generalizability and are difficult for non-expert users to implement.

The advent of Large Language Models (LLMs) has revolutionized many AI domains, naturally extending to robotics. The broader research landscape for LLM-based TAMP can generally be categorized into two main paradigms, which this paper discusses and aims to transcend:

1. **LLMs as Direct Planners:** In this paradigm, LLMs are used to generate high-level plans, sub-goals, or action sequences directly in text or code format. Examples include SayCan, Inner Monologue, Code-as-Policies, and ProgPrompt. These approaches primarily leverage the LLM's common-sense reasoning abilities. However, a significant limitation is their unreliability for complex TAMP tasks that require precise numeric constraints, optimization, search algorithms, or intricate logical reasoning, where common sense alone is insufficient. The generated plans often lack the symbolic computation necessary for guaranteed correctness and efficiency.

2. **LLMs as Translators/Interfacers:** This approach uses LLMs to translate natural language instructions into formal representations (e.g., PDDL, reward functions) that can then be fed into traditional, pre-defined TAMP solvers or reinforcement learning systems. While these methods benefit from the symbolic reasoning capabilities of existing solvers, their generalizability is constrained by the availability and design of these specialized planners and the custom integration frameworks required for each task. The LLM acts as a bridge, but the core planning logic still resides in external, often rigid, components.

"Code-as-Symbolic-Planner" addresses the limitations of both existing paradigms by proposing a **novel third paradigm**. Instead of merely generating text-based plans or acting as an interface to external, pre-designed planners, this work steers LLMs to **directly generate executable code that functions as the TAMP planner, solver, and checker itself**. This approach fully leverages the LLMs' growing coding proficiency and symbolic computing potential, which has been extensively demonstrated in domains like mathematical problem-solving and software development. By having the LLM generate the underlying algorithms (e.g., A* search, DFS) for planning and verification, the method aims to integrate powerful symbolic computation directly into the LLM's output, thereby achieving both sophisticated reasoning and broad generalizability without relying on a fixed set of external solvers. This positions the work as a significant advancement in empowering LLMs to handle the intricate optimization and constraint satisfaction inherent in complex robotic tasks.

### 2. Key Objectives and Motivation

The primary objective of this research is to **enhance the capabilities of Large Language Models (LLMs) in Task and Motion Planning (TAMP) by enabling them to directly generate symbolic code that serves as the robot's planner, solver, and checker.** This aims to overcome fundamental limitations observed in previous LLM-based TAMP approaches.

The core motivations driving this work are:

- **Addressing Insufficiency of Pure Textual Reasoning:** Existing LLM approaches for TAMP often rely on generating text-based reasoning chains or simple action sequences. While useful for high-level conceptual planning, these methods are frequently insufficient for complex TAMP tasks that involve intricate numeric constraints, multi-objective optimization, sophisticated search algorithms (e.g., A*, DFS), and rigorous logical verification. Such tasks demand precise symbolic computation that pure textual reasoning cannot adequately provide.
- **Overcoming Generalizability Gaps of Pre-defined Solvers:** Another line of work augments LLMs with pre-defined TAMP solvers or planners. While these augmentations introduce symbolic reasoning, they typically lack generalizability. Each new task often necessitates the design of specialized planners and customized integration frameworks, limiting their applicability across diverse robotic scenarios. The authors aim for a solution that maintains broad generalizability without this overhead.
- **Leveraging LLMs' Underutilized Coding Proficiency:** Modern LLMs are increasingly proficient in code generation, having been trained on vast code datasets. The authors recognize that this capability is not fully exploited in current LLM-based TAMP. By steering LLMs to generate actual symbolic code for planning and verification, they seek to harness this powerful, yet often overlooked, facet of LLMs.
- **Integrating Symbolic Computation with Common Sense:** The goal is to create a synergy where LLMs can both utilize their common-sense reasoning (often expressed textually) to understand task goals and context, and simultaneously generate precise symbolic code to perform the necessary computations, optimization, and constraint verification. This aims for a more holistic and robust planning system.
- **Improving Reliability of LLM-Generated Code:** Initial tests showed that LLMs, while capable, often produce inconsistent or ineffective code. A key motivation is to develop a framework that refines this raw code through iterative guidance and verification, leading to more reliable and correct solutions for TAMP problems.

In essence, the authors are motivated to establish a more capable and generalizable paradigm for LLM-based robot planning by making LLMs not just reasoners or translators, but **active creators of symbolic algorithms** that can autonomously solve complex robotic challenges.

### 3. Methodology and Approach

The core of this paper's methodology is **Code-as-Symbolic-Planner**, a novel framework designed to leverage LLMs for generating symbolic code that directly functions as the robot's TAMP planner and checker. This approach departs significantly from prior work by empowering the LLM to write the algorithms required for planning, rather than merely using code to interface with pre-existing modules or translating to formal languages for external solvers.

The framework, illustrated in Figure 2, operates on a **multi-agent, multi-round guidance and answer evolution** paradigm to address the challenge of LLMs initially generating non-optimal or inconsistent code. It involves three distinct LLM agents (though implemented using the same LLM instance) and a rule-based checker:

1. **TaskLLM:** This is the primary agent responsible for generating the complete planning code in Python. It receives the initial task description and guidance from SteerLLM. Initially, TaskLLM might produce simplistic code (e.g., a hardcoded sequence of moves), as shown in "TaskLLM Answer 1" of Figure 1.

2. **SteerLLM:** This agent acts as the orchestrator and guide. Its role is to:
 - Provide explicit guidance prompts to TaskLLM, encouraging it to generate more sophisticated symbolic code (e.g., suggesting A* search or depth-first search).
 - Review the results from CheckLLM and Symbolic Complexity Checker.
 - Determine whether the generated plan is complete and correct, and decide when to finalize the answer or request further refinement.
 - Maintain a history of previous answers to inform new guidance.

3. **CheckLLM:** This agent is responsible for verifying the correctness of the plan generated by TaskLLM's code. It generates and executes its own code to check criteria such as task completion, collision avoidance, time limits, and logical consistency. The results of this verification, along with explanatory feedback, are then provided to SteerLLM. This objective, code-based verification is a crucial part of the iterative refinement loop.

4. **Symbolic Complexity Checker:** This is a **rule-based script** (not an LLM) that analyzes the Python code generated by TaskLLM. Its purpose is to quantify the level of symbolic computation present in the code by detecting patterns indicative of iteration, search processes, numeric operations, permutations, and combinations. It provides a complexity summary and a score to SteerLLM, helping assess if TaskLLM is genuinely implementing algorithms rather than just text-like plans. This feedback informs SteerLLM's guidance, pushing TaskLLM towards more robust, algorithmic solutions.

**The Multi-Round Process:**
The process is iterative, with a maximum of three re-guidance and regeneration rounds:
- **Round 1:** TaskLLM receives the initial question and attempts to generate code.
- **Evaluation:** CheckLLM verifies the plan, and the Symbolic Complexity Checker assesses the code's sophistication.
- **Guidance:** SteerLLM uses this feedback to generate refined guidance (e.g., suggesting a more efficient search algorithm if the initial one timed out or was too simplistic).
- **Regeneration:** TaskLLM receives the new guidance and generates an improved version of the code and plan.
- This cycle repeats for up to three rounds, after which the final answer is accepted.

**Problem Description and Input/Output:**
The framework handles both single- and multi-robot TAMP, assuming the LLM has full environmental knowledge. Task goals and observations are manually translated into detailed text prompts for the LLM. The LLM's output must be either sequences of high-level actions (for task planning) or sequences of timed waypoints (for motion planning), adhering to specific formats and constraints (e.g., velocity limits, collision avoidance, time limits).

**Experimental Setup:**
The methodology is evaluated against five baseline methods:
- **LLMs as direct planners:** "Only Question," "Code Answer" (with Chain-of-Thought), SayCan, and HMAS-2.
- **LLM with integrated code interpreter:** OpenAI Code Interpreter.

Experiments cover seven representative TAMP tasks:
- **Discrete Task Planning:** BoxNet, Blocksworld, BoxLift, Gridworld.
- **Continuous Motion Planning:** Path-Racecars, Shape Formation, Path-Drones.
These tasks span single/multi-robot settings, 2D/3D simulations, and real-world environments. Each task includes 140 test samples of varying complexity. Success is evaluated based on syntax correctness, task completion, and satisfaction of all constraints, with a 50-second execution time limit for generated code. GPT-4o, Claude3-5-Sonnet, and Mistral-Large are the LLMs used.

### 4. Main Findings and Results

The experimental evaluation of Code-as-Symbolic-Planner demonstrates its significant advantages over existing LLM-based TAMP approaches across a diverse set of robotic planning tasks.

**1. Superior Performance Across Tasks and LLMs:**
- **GPT-4o Evaluation (Table I):** Code-as-Symbolic-Planner achieved an average success rate of 52.3% across the seven tasks, outperforming all baselines. This represents an average improvement of 24.1% over the best baseline method, OpenAI Code Interpreter (34.3%), which itself aims to incorporate symbolic computing. Against direct-planner baselines, the improvement was even more pronounced (e.g., 13.9% for "Only Question").
- **Claude3-5-Sonnet and Mistral-Large Evaluation (Table II):** The framework's superior performance was consistent across other powerful LLMs. With Claude3-5-Sonnet, Code-as-Symbolic-Planner achieved an impressive average success rate of 63.9%. Even with Mistral-Large, it reached 46.0% success rate on average, again significantly outperforming the respective baselines for these models.

**2. Enhanced Scalability to Higher Complexity:**
- Figure 5 illustrates that Code-as-Symbolic-Planner demonstrates markedly better scalability compared to other methods, especially as task complexity increases (more objects, larger environments). While all methods show a decline in success rate with increasing complexity, Code-as-Symbolic-Planner's performance degradation is considerably slower, indicating its robustness in handling more challenging scenarios due to its ability to generate algorithmic solutions. Direct-planner methods, like "Only Question," experience the fastest performance decline.

**3. Effectiveness of Multi-Round Guidance:**
- Experiments varying the maximum number of guidance and generation rounds (Figure 6) confirmed the benefit of the iterative framework. Success rates for tasks like BoxLift and Blocksworld consistently improved as the number of rounds increased from 1 to 3, before gradually plateauing. This validates the effectiveness of the multi-round self-correction mechanism and supports the choice of three rounds as a reasonable balance between performance and computational cost.

**4. Crucial Role of CheckLLM and Symbolic Complexity Checker:**
- The ablation study in Table I highlights the importance of the framework's key components. Removing CheckLLM led to an average success rate drop of 9.6%, while removing the Symbolic Complexity Checker resulted in an 11.0% decrease. This quantitatively demonstrates that both the code-based correctness verification (CheckLLM) and the analysis of algorithmic sophistication (Symbolic Complexity Checker) are vital for providing effective guidance to SteerLLM and improving the quality of the generated plans.

**5. Validation in 3D Simulation and Real-World Robotics:**
- For the BoxNet task, Code-as-Symbolic-Planner achieved perfect 100% success rates in real-world experiments with two robot arms and in 3D simulations with three robot arms (Table III). Even with six robots in a complex 3D simulation, it maintained a high 95% success rate, dramatically outperforming baselines (e.g., 0% for "Only Question" with six robots). This showcases the framework's practical applicability and scalability to actual hardware and complex physics-enabled environments, including handling dynamic factors and re-planning due to execution errors.

**Identified Failure Reasons/Limitations:**
Despite its strengths, the authors identified limitations:
- **Code Optimality:** For highly complex tasks, the generated symbolic code, while correct, was not always optimal. This sometimes led to execution times exceeding the 50-second limit, contributing to failures in the most challenging scenarios.
- **Task Formalization:** A significant bottleneck remains the LLM's difficulty in abstracting real-world application problems into formal optimization or logistical tasks that are readily solvable by code, a challenge even for human experts.
- **Output Format Sensitivity:** The required output format for plans significantly influenced the coding success rate, suggesting a need for LLMs to improve their self-formalization capabilities regarding problem output structures.

Overall, the results strongly support the efficacy and generalizability of Code-as-Symbolic-Planner, positioning it as a robust new paradigm for LLM-based TAMP by effectively integrating symbolic computing into the LLM's code generation capabilities.

### 5. Significance and Potential Impact

The "Code-as-Symbolic-Planner" framework marks a significant advancement in the burgeoning field of Large Language Model (LLM) applications in robotics, particularly for Task and Motion Planning (TAMP). Its primary significance lies in introducing and validating a **novel third paradigm** for LLM-based TAMP, which transcends the limitations of prior approaches.

**Key Contributions and Significance:**

1. **Bridging Common Sense and Symbolic Computation:** The framework effectively bridges the gap between the LLM's common-sense reasoning abilities and the rigorous demands of symbolic computation. Instead of relying on common sense alone or delegating to external, rigid solvers, Code-as-Symbolic-Planner empowers the LLM to *generate* the symbolic algorithms (e.g., search, optimization) directly. This allows for both natural language understanding and precise, verifiable execution, a critical step towards more intelligent and capable robotic systems.
2. **Enhanced Generalizability:** By enabling LLMs to dynamically generate task-specific planners and checkers in code, the method achieves strong generalizability across a diverse range of TAMP problems. This includes discrete and continuous tasks, 2D and 3D simulations, single and multi-robot scenarios, and varied constraints. This stands in contrast to traditional methods requiring specialized planners or LLM-translator approaches that are limited by pre-defined solver libraries, making robotics more adaptable to novel, unforeseen tasks.
3. **Increased Reliability through Iterative Refinement:** The multi-agent, multi-round guidance framework, coupled with the CheckLLM and Symbolic Complexity Checker, provides a robust mechanism for self-correction and iterative improvement of the generated code. This significantly enhances the reliability of LLM-generated solutions, transforming potentially inconsistent initial outputs into more correct and sophisticated planning algorithms.
4. **Practical Demonstrations:** The successful deployment in 3D simulation and real-world robot arm experiments, including dynamic re-planning due to execution errors, underscores the practical viability and robustness of the approach. This moves LLM-based robotics closer to real-world applications where adaptability and error recovery are paramount.
5. **A Blueprint for Future LLM Agent Design:** The architecture of SteerLLM, TaskLLM, CheckLLM, and the Symbolic Complexity Checker provides a valuable blueprint for designing more sophisticated LLM agents in general. It demonstrates how internal self-reflection, objective verification, and complexity analysis can steer large models towards generating higher-quality, algorithmically sound solutions.

**Potential Impact:**

- **Democratization of Robotics:** By allowing non-expert users to describe complex tasks in natural language and having the LLM generate the underlying planning logic, Code-as-Symbolic-Planner could significantly lower the barrier to entry for programming robots. This could enable a broader range of users to deploy robots for diverse applications without deep expertise in traditional robotics planning languages.
- **More Autonomous and Adaptive Robots:** Robots equipped with this capability could become more autonomous, adapting to new tasks and environments with greater flexibility. They could "program themselves" for specific sub-problems, leading to more versatile and intelligent robotic assistants and industrial systems.
- **Foundation for AI-Generated Algorithms:** This work opens doors for a future where AI not only solves problems but also *generates the algorithms* to solve them. This could accelerate scientific discovery and engineering design by offloading the complex task of algorithm development to advanced AI models.

**Limitations and Future Directions:**

The authors openly acknowledge limitations, which also serve as promising avenues for future research:

1. **Optimality and Efficiency:** Improving the optimality and efficiency of generated code remains a challenge, as current LLMs may produce correct but sub-optimal solutions that exceed time limits for highly complex tasks. Future work could focus on guiding LLMs to generate more efficient algorithms or strategically combining LLM-generated code with highly optimized, specialized traditional planners where appropriate.
2. **Task Formalization from Diverse Inputs:** Enhancing the LLM's ability to translate complex real-world problems into abstract, solvable code structures is crucial. This includes incorporating multimodal inputs (e.g., vision, force sensing) to move beyond detailed text descriptions, allowing robots to perceive and formalize tasks more autonomously.
3. **Self-Formalization of Output Formats:** The observed sensitivity to output format suggests a need to improve LLMs' inherent capabilities for self-formalization, allowing them to autonomously define or infer optimal output structures for a given TAMP problem.

In conclusion, "Code-as-Symbolic-Planner" introduces a powerful and generalizable approach for robot planning, significantly advancing the integration of LLMs with symbolic AI. Its impact could reshape how robots are programmed and how intelligent agents tackle complex decision-making problems.
