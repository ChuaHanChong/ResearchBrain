# ModuLoop : Low-Level Code Generation using Modular Synthesizer and Closed-Loop Debugger for Robotic Control

> [!summary] Summary
> ModuLoop presents a framework enabling pre-trained Large Language Models to autonomously generate and refine low-level robot control code through a closed-loop debugging mechanism using real-world execution feedback. The system demonstrated 100% accuracy in generating physically feasible coordinates for a UR3 robot and achieved 86.67% accuracy in hand-eye calibration, while also achieving 96% success rates on simpler pick-and-place tasks.

## Problem

- Existing LLM-based robotic control methods struggle with prompt dependency, poor generalization, and a lack of feedback for refining directly generated low-level control code.
- Precise low-level robotic tasks, like hand-eye calibration, require highly accurate motion, real-time error handling, and adaptability to environment-specific execution, which open-loop code generation systems cannot provide.
- Traditional calibration methods often rely on markers or accurate initial alignments and can be sensitive to training data distributions, requiring data efficiency and robustness.

## Method

- **ModuLoop** integrates a Modular Code Synthesizer (MCS) that decomposes natural language commands into subtasks and generates corresponding Python code modules.
- A Closed-Loop Debugger (CLD) iteratively refines generated code by detecting runtime errors and accuracy issues, inserting diagnostic 'probing messages', and applying targeted corrections.
- A simulation-based validation loop ensures physical feasibility and collision-free robot motion planning, providing robust coordinates for tasks like hand-eye calibration.

## Results

- The simulation-based validation method achieved **100%** accuracy in generating physically feasible and collision-free coordinates for robot motion, outperforming analytical and IK-verified methods.
- ModuLoop achieved the highest code generation success rate (**96.67%**) and calibration accuracy success rate (**86.67%**) for hand-eye calibration, significantly surpassing baselines like ProgPrompt and Code-as-Policies.
- For pick-and-place tasks, ModuLoop maintained high success rates of **96%** on simpler tasks and **60%** on the most complex task requiring intricate spatial reasoning, outperforming single-prompt and modular code synthesizer baselines.

## Takeaways

> [!tip] Key Insights
> - Integrating a closed-loop debugger with probing messages significantly enhances the robustness, accuracy, and efficiency of LLM-generated code for physical robot tasks by enabling autonomous error diagnosis and correction.
> - Modular code generation, combined with iterative feedback, allows LLMs to tackle complex low-level robotic tasks more effectively than single-pass generation methods, improving structuredness and maintainability.
> - Validating robot motion in a simulator before real-world execution, through an iterative LLM-simulator feedback loop, ensures 100% physically feasible and collision-free coordinates, crucial for precision and safety.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

This research contributes to the evolving field of AI-enabled robotics, specifically focusing on the application of Large Language Models (LLMs) for robotic control. The broader landscape of LLM integration in robotics generally follows two primary directions. The first direction involves using LLMs for high-level action planning, where natural language commands are translated into abstract action sequences that rely on external modules for execution. Examples include systems like SayCan and the RT series (PaLM-E, RT-1, RT-2), which integrate LLMs with affordance models or multimodal inputs. These approaches limit LLM involvement in the direct generation of executable code.

The second direction, which ModuLoop aligns more closely with, explores the direct generation of executable low-level control or perception code from natural language instructions. Prior work in this area, such as Code-as-Policies, ProgPrompt, and RobotGPT, often generates code through user-defined APIs. However, these methods typically exhibit limitations such as reliance on structured inputs, prompt dependency, and poor generalization across diverse environments. A critical challenge in low-level robotic control is the need for precise motion, real-time error handling, and adaptability to environment-specific execution. Many existing code generation systems, including those based on LLMs like Codex, operate in an open-loop manner, producing static code without integrating execution feedback for refinement. While frameworks like AutoGen and Reflexion introduce iterative improvement through multi-agent interactions or self-reflection, their application has largely been confined to abstract programming rather than physical robotic control, where continuous sensing and physical feedback are essential. MCCoder has attempted to incorporate sensor feedback for microcontroller-based robots, but its approach still relies on hardware-specific prompts and rigid templates, thereby limiting generalizability.

In the context of hand-eye calibration, a fundamental task in vision-based manipulation, traditional methods involve estimating the spatial transformation between a robot's end-effector and a mounted camera. Recent learning-based approaches have aimed to automate this process, reducing marker dependence or manual effort. However, these methods can be sensitive to training data distributions and often require accurate initial alignments for reliable performance.

ModuLoop seeks to bridge these gaps by enabling LLMs to participate actively in the full control loop for low-level robotic tasks. It addresses the limitations of prompt dependency and poor generalization by integrating a closed-loop debugging mechanism that leverages real-world execution feedback to refine generated code autonomously. Furthermore, it aims to provide an automatic and adaptive calibration solution without requiring prior data or extensive manual tuning, distinguishing it from existing learning-based calibration methods. By combining modular code synthesis with a feedback-driven refinement process, ModuLoop positions itself as a framework designed to enhance the practicality and generalizability of LLM-based robotic control in real-world scenarios.

### 2. Key Objectives and Motivation

The primary motivation for this research stems from the observed limitations of Large Language Models (LLMs) in low-level robotic control. While LLMs have demonstrated capabilities in various domains, including code generation and general problem-solving, their application in tasks requiring precise manipulation, real-time feedback, and environment-dependent execution in robotics has been restricted. Existing LLM-based robotic control approaches either delegate low-level execution to external modules or suffer from issues like prompt dependency and poor generalization when attempting direct code generation, largely due to a lack of feedback-based refinement mechanisms. These challenges are particularly pronounced in low-level control where errors can lead to physical failures and an inability to adapt to unforeseen circumstances.

To address these limitations, the overarching objective of this work is to propose and validate ModuLoop, a Closed-Loop Modular Code Synthesizer framework. This framework aims to enable pre-trained LLMs to actively engage in the entire control loop of low-level robotic tasks without requiring task-specific fine-tuning.

More specifically, the key objectives and motivations are:

- **Enabling Full Control Loop Participation**: To develop a framework that allows LLMs to not only plan and generate code but also to iteratively execute, debug, and refine that code based on real-world feedback, thereby participating in the complete control loop for low-level robotic tasks.
- **Modular Code Planning and Generation**: To design a system that decomposes high-level natural language commands into fine-grained subtasks and converts them into executable Python modules. This modular approach is intended to improve the structure, maintainability, and reliability of the generated code compared to single-pass generation methods.
- **Systematic Debugging and Refinement**: To implement a closed-loop debugging mechanism that inserts debugging probes during execution to observe code behavior. This mechanism is motivated by the need for autonomous error detection, diagnosis, and correction in dynamic robotic environments, moving beyond static code generation.
- **Validation in Real-World Settings**: To apply the proposed framework to representative robotic tasks, specifically the calibration of an RGB-D camera and a robotic arm, and a subsequent pick-and-place task. This is motivated by the need to demonstrate the framework's practical effectiveness, accuracy, and autonomy in physical environments.
- **Enhancing Data Efficiency and Accuracy for Calibration**: To incorporate a simulation-based feedback loop for verifying the physical feasibility of motion planning (reachability and collision avoidance). This aims to secure collision-free executable coordinates for hand-eye calibration, thereby improving data efficiency and the accuracy of the calibration process.
- **Demonstrating Extensibility and Scalability**: To show that the framework is not only effective for calibration but also extensible to more complex manipulation tasks, such as pick-and-place, with minimal additional guidance, thereby illustrating its potential for broader applicability and scalability in LLM-based robotic control.

In summary, the research is motivated by the aspiration to elevate LLMs from passive planners to autonomous agents capable of generating, executing, and adapting robot control code in real-world environments, thereby enhancing the reliability and autonomy of robotic systems.

### 3. Methodology and Approach

The ModuLoop framework is designed to enable pre-trained Large Language Models (LLMs) to autonomously generate, execute, and refine low-level robot control code through a closed-loop feedback mechanism. The methodology integrates simulation-based validation, modular code synthesis, and iterative debugging.

**Overall Architecture:**
The ModuLoop system initiates with a high-level task command provided in natural language. It then decomposes this instruction into subtasks, which are translated into executable Python code. The framework iteratively executes the generated code, gathering feedback from runtime errors and performance metrics. This feedback drives a dynamic refinement process, creating a closed-loop structure that enables the robot to autonomously learn and improve its control programs.

**Components and Workflow:**

**A. Iterative Interaction between LLM and Simulator for Physically Valid Motion Planning**
This initial stage focuses on ensuring the physical feasibility of robot trajectories before execution in the real world, particularly for calibration tasks.
1. **Candidate Position Generation**: The LLM acts as a coordinate generator, taking the robot's workspace constraints (W) and historical data of reachable, collision, and unreachable positions (L_rea, L_col, L_unr) as input. It then generates a set of candidate 3D end-effector positions (C_gpt).
2. **Inverse Kinematics (IK) Filtering**: The generated candidates (C_gpt) are passed through an IK solver. Only positions that are kinematically reachable (i.e., for which an executable joint trajectory exists) are retained, forming the set C_gen.
3. **Simulation-Based Validation**: Each position in C_gen is evaluated within a simulation environment (Isaac Sim). The simulator classifies positions into three categories:
 - **C_rea**: Positions successfully reached without any collisions (self-collision or environment collision).
 - **C_col**: Positions that result in collisions.
 - **C_unr**: Positions the robot fails to reach in simulation.
4. **Feedback Loop**: These classified results (C_rea, C_col, C_unr) are fed back into the LLM prompt. This continuous feedback loop guides the LLM in refining its subsequent generations of candidate positions until a sufficient number of physically feasible and collision-free coordinates are collected. This process ensures that only validated coordinates are used for real robot code generation, enhancing execution fidelity and safety.

**B. ModuLoop for Hand-eye Calibration**
This stage implements the core code generation and debugging for the calibration task using GPT-4o.
1. **Environment Setup**: The framework receives the high-level goal (e.g., calculate 3D-to-3D transformation between robot and camera), along with essential contextual information such as the robot's IP address, sensor specifications, and the movable coordinates obtained from the simulation-based validation.
2. **Modular Code Synthesizer (MCS)**:
 - **Task Decomposition & Planning**: The LLM breaks down the overall calibration task into a sequence of independent subtasks (e.g., move to coordinates, acquire sensor data, perform matrix computation). Each subtask is then fed as a structured prompt to subsequent LLM instances.
 - **Modular Code Generation**: For each identified subtask, the LLM generates a corresponding Python function or code block.
 - **Code Integration**: The individual code blocks are assembled into a coherent, executable Python script. This script is then run via subprocesses, allowing the system to monitor robot actions and process camera data in real time.
3. **Closed-Loop Debugger (CLD)**: This mechanism iteratively refines the generated code based on execution feedback.
 - **Execution and Error Detection**: The current version of the code (C) is executed in the robotic environment. The system captures the output (o) and any error messages (e).
 - **Syntax Error Debugging (Fig. 4)**: If a runtime error (e) is detected, an Analyzer component hypothesizes potential causes. To validate these hypotheses, the Analyzer inserts "probing messages" (diagnostic code) into the script (C_d), which is then re-executed. A Refiner component uses the results from the probing execution to apply targeted modifications to the code, resolving issues such as version mismatches or incorrect API calls.
 - **Accuracy Improvement Debugging (Fig. 5)**: If no runtime error occurs, an Evaluator assesses the calibration accuracy. If the output indicates "calibration inaccurate," the Analyzer diagnoses potential reasons (e.g., insufficient data quality, incorrect processing steps). The Refiner then updates the code to improve accuracy, for example, by adding depth alignment or filtering strategies to the camera pipeline.
 - **Termination Conditions**: This iterative loop continues until either the calibration achieves a predefined accuracy threshold ("calibration success") or a maximum number of iterations (T) is reached, indicating a failure to converge.

**C. Generalizability to Pick-and-Place Tasks**
To assess the framework's broader applicability, ModuLoop was extended to a pick-and-place task.
1. **Perception Pipeline (Fig. 7)**: RGB-D images from front and gripper-mounted cameras are processed by the Segment Anything Model (SAM) to generate object masks and extract center coordinates.
2. **LLM-based Object Recognition**: The annotated images, along with the natural language command, are provided to the LLM. The LLM contextually interprets the scene to identify target objects, assign unique labels, and determine if rotation is necessary for precise manipulation.
3. **Static Debugging**: Due to the inherent risks of physical collision and environmental changes during pick-and-place trials, a "static debugging" approach was adopted. Instead of real-time iterative execution feedback, GPT-4o was provided with a structured evaluation checklist to anticipate and reason about potential failure cases, guiding the generation of more robust initial code. The LLM then handles object recognition, coordinate alignment, motion planning, and grasp planning through its reasoning and code generation capabilities.

This comprehensive methodology aims to create an autonomous, adaptive, and robust framework for low-level robotic control using LLMs.

### 4. Main Findings and Results

The research evaluated ModuLoop’s performance across two primary tasks: hand–eye calibration and a pick-and-place manipulation task. The evaluation encompassed code generation success, calibration accuracy, and task completion rates, comparing ModuLoop against various baselines and LLM variants.

**A. Performance in Hand-eye Calibration**

1. **Reachable Coordinate Generation Accuracy (Table I)**:
 - An analytical method based on Denavit–Hartenberg (DH) parameters achieved 56.67% accuracy in calculating reachable coordinates.
 - Extending the analytical method with real-robot inverse kinematics (IK) verification improved accuracy to 83.33%.
 - The proposed simulation-based validation method, which integrates LLM-guided position generation with physics-based checks, achieved 100% accuracy in providing physically feasible and collision-free coordinates. This demonstrates the effectiveness of the iterative LLM-simulator feedback loop.

2. **Calibration Performance with Modular Code Generation and Closed-Loop Debugger (Table II)**:
 - **ModuLoop's Superiority**: The combination of the Modular Code Synthesizer (MCS) and the Closed-Loop Debugger (CLD) with probing (ModuLoop) achieved the highest code generation success rate (96.67%) and accuracy success rate (86.67%) for calibration tasks (defined as an error < 0.02 m). The mean/median verified error for successful cases was 0.048m / 0.011m.
 - **Impact of Modularity**: MCS alone showed significantly lower performance (23.33% code generation success, 6.67% accuracy success), indicating that while modular decomposition is beneficial, it requires robust debugging for practical application.
 - **Impact of Closed-Loop Debugging**:
 - The Single-Path Generator (SPG) without any feedback or with a basic debugger, showed minimal success (6.67% and 10.0% code generation success respectively), with high mean errors (0.802m / 0.802m and 0.485m / 0.062m).
 - Integrating the CLD, especially with probing, substantially improved performance. MCS + Debugger achieved 73.33% code generation success and 60.0% accuracy success. This highlights the critical role of feedback-driven refinement.
 - **Comparison with Baselines (ProgPrompt, Code as Policies - CaP)**:
 - ProgPrompt achieved 66.67% code generation success, and CaP with Full API achieved 90.0%. However, these models typically relied on predefined APIs and lacked an inherent feedback mechanism for error correction. ModuLoop, in contrast, generates low-level control code without predefined APIs and iteratively refines it, demonstrating robustness in precise robotic tasks.
 - **Efficiency of Debugging (Fig. 6)**: The integration of the CLD, particularly with probing, improved calibration efficiency by leading to more successful initial samples and requiring fewer iterations for convergence. This supports the assertion that error-hypothesis probing accelerates convergence and enhances robustness.
 - **LLM Variant Evaluation**:
 - GPT-4.1-mini showed slightly lower success rates compared to GPT-4o (73.33% code gen, 40.0% accuracy success) but was identified as a potentially cost- and time-efficient alternative despite reduced reliability.
 - Gemini achieved comparable code generation (90.0%) and accuracy success (73.33%) to GPT-4o, but the derived transformation matrices demonstrated limited calibration stability, failing to consistently meet the required accuracy threshold.

**B. Generalizability and Practicality in Pick-and-Place Tasks**

1. **Task Complexity (Table III)**: ModuLoop was evaluated on five pick-and-place tasks of increasing complexity, ranging from basic object targeting to those requiring logical reasoning, semantic categorization, distance-based ordering, and precise spatial reasoning and orientation control.

2. **Success Rates Across Tasks (Table IV)**:
 - **ModuLoop's Performance**: ModuLoop achieved the highest success rates across all tasks, consistently outperforming the Single-Prompt Code Generator and Modular Code Synthesizer (MCS) alone.
 - For simpler tasks (Simple 1, Moderate 1), ModuLoop achieved 96% success.
 - For moderately complex tasks (Moderate 2, Moderate 3), it achieved 92% success.
 - For the most complex task (Hard 1), requiring intricate spatial reasoning and precise relative positioning, ModuLoop still achieved a 60% success rate, significantly higher than the Single-Prompt (24%) and MCS (48%) baselines.
 - **Value of Structured Decomposition and Debugging**: These results underscore that ModuLoop's structured command decomposition and GPT-based debugging mechanism are crucial for translating complex manipulation commands into executable code, particularly for tasks involving semantic reasoning, spatial understanding, and precise motion planning.
 - **Limitations in Pick-and-Place**: The paper acknowledges a limitation that ModuLoop currently relies on minimal APIs providing object positions. This restricts its applicability to relatively simpler tasks, indicating that more complex, contact-rich manipulation tasks would require richer environmental understanding and a wider array of perception, motion planning, and value map composition APIs.

In summary, the findings demonstrate that ModuLoop effectively enables LLMs to generate, execute, and adapt control code for low-level robotic tasks. The modular code synthesis, coupled with an iterative, closed-loop debugging mechanism that incorporates probing, significantly enhances code robustness, accuracy, and efficiency compared to open-loop or less sophisticated feedback approaches. The framework’s extensibility to pick-and-place tasks further illustrates its generalizability, albeit with acknowledged limitations concerning API richness for highly complex scenarios.

### 5. Significance and Potential Impact

This research presents a framework, ModuLoop, that demonstrates the feasibility of employing pre-trained Large Language Models (LLMs) to autonomously generate and execute low-level robot control code without the need for additional task-specific training or fine-tuning. This represents a notable advancement in LLM-based robotics, moving LLMs beyond high-level planning into the direct, iterative control of physical systems.

The significance of ModuLoop lies in several key aspects:

- **Enabling Autonomous Low-Level Control**: By positioning the LLM as a central, self-correcting agent in the control loop, ModuLoop significantly enhances the autonomy of robotic systems. It enables robots to interpret natural language commands, generate appropriate code, and adapt to execution outcomes in real-time. This capability can potentially reduce the need for extensive manual programming and domain expertise in developing robotic applications.
- **Addressing Limitations of Prior LLM-Robotics Approaches**: The framework directly tackles challenges such as prompt dependency, poor generalization, and the lack of feedback-based refinement prevalent in earlier LLM-based control methods. The closed-loop debugging mechanism, particularly with its probing capabilities, allows the system to diagnose and correct runtime errors and improve task accuracy autonomously, making the generated code more robust and reliable in dynamic environments.
- **Enhanced Calibration and Manipulation Accuracy**: The validation across camera-to-robot calibration and pick-and-place tasks demonstrates high execution accuracy. The simulation-based workspace validation component ensures that only physically feasible and collision-free coordinates are used, contributing to safer and more efficient robot operations, especially in calibration where precision is paramount.
- **Modularity and Generalizability**: The Modular Code Synthesizer (MCS) approach, which decomposes complex tasks into manageable subtasks, contributes to the generation of structured and logically consistent code. This modularity, combined with the successful application to tasks of varying complexity, suggests the framework's generalizability across different low-level robotic manipulation scenarios.
- **Practicality for Industrial Applications**: The ability to generate complex control logic without manual programming or task-specific training indicates the practicality of ModuLoop. This could pave the way for more flexible and adaptive automation in industrial settings, where robots could be rapidly repurposed or instructed for new tasks through natural language.

**Potential Impact:**

The successful implementation of ModuLoop could have a transformative impact on several domains:

- **Robotics Development**: It could simplify the programming of robotic systems, making robotics more accessible to users without specialized coding skills. Researchers and engineers could focus more on high-level task descriptions, with the LLM handling the low-level implementation details and debugging.
- **Industrial Automation**: The framework could enable more adaptable and reconfigurable manufacturing processes. Robots could learn and execute new assembly, inspection, or material handling tasks with minimal human intervention, enhancing efficiency and reducing downtime.
- **Human-Robot Interaction**: By allowing natural language instructions to directly translate into executable robot code with self-correction, ModuLoop could lead to more intuitive and effective human-robot collaboration in various service, logistics, and healthcare applications.
- **AI Research**: It provides a concrete example of how LLMs can be integrated into physical systems with effective feedback loops, potentially inspiring further research into autonomous AI agents that can learn, adapt, and operate in real-world environments.

**Future Directions and Limitations:**

While significant, the study acknowledges certain limitations that highlight avenues for future research. The inherent latency in generating complete control code using LLMs can limit real-time responsiveness, suggesting a need for optimization. Additionally, ModuLoop's current reliance on minimal APIs providing object positions restricts its applicability to relatively simpler tasks. Extending the framework to handle contact-rich manipulation, such as assembly or opening drawers, would require a richer understanding of the environment through advanced perception modules, motion planners, and value map composition provided as APIs. Future work aims to extend the framework to real-world industrial applications, such as process and factory automation, and evaluate its generality and hardware-independence across a diverse range of robotic platforms beyond the UR3.
