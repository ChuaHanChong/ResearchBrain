# Training Agents to Evolve with Their Harness: TaoLive Digital Avatar Agent Technical Report

> [!summary] Summary
> Harness-Aware Training (HAT) trains a compact Qwen3.6-35B-A3B policy to work under changing agent harnesses (Skills, Hooks, prompts, tool schemas) instead of memorizing one configuration. It uses Harness-State Augmentation across three stages: SFT, general on-policy distillation, and RL. For live-stream e-commerce avatars it scores 94.8 on Live-Stream QA, meets real-time latency, and gains 0.91% item-page views in an online A/B test.

## Problem

- Large models can adapt zero-shot to changing harnesses, but their latency is too high for real-time live streaming. DeepSeek-V4-flash has a median end-to-end latency above 11 seconds.
- Compact models trained on one fixed harness overfit to surface forms such as skill names, tool names and prompt templates, so they fail when the harness evolves.
- Fixed-Harness fine-tuning also erodes general instruction following, dropping IFEval by 7.7 points. Test-time adaptation breaks latency budgets, and continual learning re-pays retraining cost for every harness edit.

## Method

- **Harness-State Augmentation (HSA)** applies ==task-preserving transformations== to Skill identifiers and content, tool schemas, prompt structure, and Hook functions, so training covers a ==distribution of harness states== rather than one snapshot.
- **HSA-SFT** trains the compact model on quality-filtered teacher trajectories from diversified harness environments. ==General On-Policy Distillation== from the base model then recovers general capabilities that domain SFT damaged.
- **HSA-RL** runs ==GRPO== inside HSA-diversified environments of a production-informed ==live-room simulator==. Rewards cover accuracy, effectiveness, and tool rationality, improving skill selection and tool use under harness shifts.

## Results

- HAT reaches **94.8** on Live-Stream QA (base **80.3**, best general LLM **93.0**) and **94.6** on Harness-Variant QA (base **75.4**). The gap between original and variant harnesses is only **0.2** points.
- Fixed-Harness SFT cuts IFEval by **7.7** and **5.3** points and Prompt Robustness by **4.6**. HAT gets **83.5** and **88.7** on IFEval. Without HSA, RL drops Prompt Robustness by **5.9** points.
- On one H20 GPU with multi-token prediction, P50 latency is **3.4 s** and P95 is **8.1 s**. The Taobao Live online A/B test showed a **0.91%** item-page-view uplift over ReAct.

## Takeaways

> [!tip] Key Insights
> - Make deployment-time configuration part of the training distribution. Task-preserving variation of surface form teaches a model to read the active harness instead of memorizing one version.
> - Augmentation matters most when introduced during SFT and RL. RL on a fixed harness raises task scores but sharply erodes robustness, so RL needs environment diversity too.
> - General distillation and harness augmentation are complementary. Distillation restores general capability lost to domain tuning, while augmentation stops the overfitting that caused the loss in the first place.

## Detailed Report

### 1. Overview

A viewer in a live-commerce stream asks about a product. The avatar must answer from the live room's context, engage viewers, and sometimes use tools. It then delivers the reply publicly, through speech and an animated avatar. Campaign rules and merchant preferences change often, and retraining a model for every edit is slow. Large models can handle unfamiliar instructions but may be too slow for live interaction. Compact models are faster, but training them on one fixed set of instructions and tools can make them brittle when those details change.

The authors train the compact model on changing versions of its operating setup, rather than teaching it one fixed version. The model must then respond to the current meaning of its instructions rather than rely on familiar names or templates. The trained model scores highly both under the original setup and under the evaluated changes.

Table 4, cumulative training-pipeline ablation. The fixed path's Prompt Robustness is 72.8 at Base, 68.2 after SFT, 72.6 after OPD, and 66.7 after RL. The augmented path gives 77.3 after HSA-SFT, 77.1 after OPD, and 77.6 after HSA-RL. Arrows denote descriptive changes from the preceding row; they do not include retraining variance.

### 2. What changes around the agent

The agent receives a viewer comment plus dialogue, product, and room context. It can load a Skill, call tools, and produce a final response that is converted to speech and avatar video. Its operating setup, the "Harness," has four components that can be changed independently of the policy model:

- **Skills** contain behavior rules and strategies.
- **The Tool Registry** exposes product and commerce functions.
- **The System Prompt Pipeline** assembles instructions and context.
- **Hooks** check inputs, parameters, outputs, and retries.

This creates a tension. Domain training helps a compact model, but a single fixed Harness risks surface-form memorization, and large zero-shot models may be too slow.

### 3. Training on the Harness in front of you

Harness-State Augmentation (HSA) varies the Harness while aiming to preserve the task. It varies five dimensions:

- Skill identifiers and descriptions, including distractors or renamed Skills
- Skill wording, rule order, and masking
- Tool names and descriptions
- Prompt structure and operationally valid numeric constraints
- Hook behavior, message structure, and retry behavior

For example, if a Skill or tool is renamed, the model should use the instructions and function rather than a memorized label. This is the authors' design hypothesis, not proof that arbitrary Harness edits preserve task semantics.

Harness-state augmentation. The left side pairs original and augmented examples for tools (search_product versus find_product), Skills (item_qa versus goods_qa and changed rules), Hooks (80- versus 60-character limit), and prompt role and order instructions. The right side shows four example trajectories. Calling unavailable Tool A, selecting nonexistent Skill α, and ignoring modified prompt instructions are marked failures. Training runs in three stages:

1. **HSA-SFT** trains on teacher-generated, quality-filtered trajectories under original and augmented Harnesses.
1. **General OPD** uses the base model as teacher on general instruction data to recover capabilities harmed by domain-specific SFT.
1. **HSA-RL** trains the policy on its own trajectories in a production-informed simulator with Skills, tool execution, Hooks, multiple rounds, and controlled tool failures. Demonstrations show preferred trajectories, while on-policy rollouts can expose errors and recovery attempts.

### 4. The fixed-Harness trade-off, tested

Live-Stream QA and Harness-Variant QA each use 978 real live-room cases. Two metrics score each reply:

- **Accuracy** is binary.
- **Effectiveness** is 0, 0.5, or 1.

AVG is their per-sample arithmetic mean.

Results for Qwen3.6-35B-A3B:

- **Live-Stream QA:** HAT scores 94.8 AVG, versus 80.3 for the base model and 93.0 for the best general-model comparator, GLM-5.2.
- **Harness-Variant QA:** HAT scores 94.6, versus the base model's 75.4.

The variant result shows performance on the evaluated Harness changes, not arbitrary future changes.

The ablation tests the mechanism more directly. Fixed-Harness SFT takes Prompt Robustness AVG from the base model's 72.8 to 68.2. It also takes IFE-P, which measures compliance with the full set of prompt instructions, from 81.5 to 73.8. HSA-SFT instead reaches 77.3 on Prompt Robustness and 81.7 on IFE-P.

After General OPD, the fixed-Harness path's Prompt Robustness falls from 72.6 to 66.7 with RL. The HSA path rises from 77.1 to 77.6 with HSA-RL. Both RL paths improve business-task scores. These are cumulative training pathways: the HSA path varies Harness states during both SFT and RL, so the contrast does not isolate HSA-RL alone as the cause. HAT's final model reaches 83.5 IFE-P.

### 5. Scope

The central move is to put Harness variation in the training distribution. A compact agent can then learn to respond to the current runtime setup rather than only the version it saw during training. The boundary is that Harness-Variant QA tests a defined set of augmented configurations, while broader tool and prompt robustness uses synthetic scenarios.
