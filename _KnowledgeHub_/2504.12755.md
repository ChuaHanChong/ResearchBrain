# Trajectory Adaptation using Large Language Models

> [!summary] Summary
> Researchers from the Robert Bosch Centre for Cyber-Physical Systems, Indian Institute of Science, Bengaluru, India, developed a language-based framework that uses pre-trained Large Language Models to adapt existing robotic trajectories based on natural language instructions. The framework generates executable code and a high-level plan for trajectory modification, successfully handling complex, multi-step, and numerically-oriented commands across various robot platforms while integrating an iterative user feedback loop for refinement.

## Problem

- Traditional planning methods for robot trajectory adaptation are computationally expensive, requiring replanning for every new situation, while learning-based models often demand complex mathematical formulations inaccessible to non-experts.
- Existing language-based trajectory adaptation methods typically require task-specific training, struggle with complex or numerical instructions, and lack generalizability to diverse scenarios.
- There is a significant gap in translating high-level, abstract human language commands into precise, low-level robot control actions, and a need for more interpretable and feedback-driven adaptation systems.

## Method

- A framework utilizing pre-trained ==Large Language Models (LLMs)== to generate both a human-readable High-Level Plan (HLP) and executable Python code for trajectory adaptation.
- A comprehensive prompt is constructed for the LLM, integrating user instructions, environmental context, task-agnostic rules, predefined functions (e.g., `detect_objects`), and in-context examples to guide generation.
- An iterative user validation and feedback loop is implemented where the user reviews the HLP; if issues are found, feedback is provided to the LLM to refine the plan and code, ensuring alignment with human intent.

## Results

- The framework successfully generated code that adapted both position waypoints and velocity components of trajectories, demonstrating smooth and intended adjustments according to instructions.
- LLMs devised accurate high-level plans and corresponding code for intricate and diverse commands, including precise numerical values and compound instructions, even with only one or two in-context examples.
- The approach allowed for free-form manipulation of waypoints and facilitated user feedback to correct LLM misinterpretations, enhancing robustness, and was validated across manipulator, aerial, and ground robots in Pybullet and Gazebo simulators.

## Takeaways

> [!tip] Key Insights
> - Pre-trained LLMs can effectively bridge the semantic gap between natural language instructions and low-level robot control by generating executable Python code for precise trajectory waypoint and velocity modifications.
> - The integration of a high-level, human-readable plan alongside code generation significantly enhances interpretability and allows for an effective human-in-the-loop feedback mechanism to correct LLM misinterpretations.
> - Careful prompt engineering, including in-context examples and explicit rules, enables LLMs to process complex, multi-step, and numerically-specific instructions for trajectory adaptation without requiring task-specific training.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

The field of human-robot interaction (HRI) increasingly seeks to enable robots to adapt their behavior intuitively and scalably based on human instructions. Trajectory adaptation is a core component of this challenge. Traditionally, this domain has been addressed through two primary approaches: planning-based methods and learning-based models.

Planning-based methods, such as those employing RRT or A-star algorithms, often necessitate computationally expensive replanning for every new situation, which can be problematic for real-time applications. Learning-based models, exemplified by approaches like Task-Parameterized Gaussian Mixture Models (TP-GMM) or Elastic Dynamical System Motion Policies, offer faster adaptation by adjusting learned models to new environments. However, these methods typically require precise mathematical modeling and the explicit formulation of task-specific frames, limiting their flexibility and ease of use for non-expert users.

Recent advancements in Large Language Models (LLMs) have opened new avenues for HRI, particularly in bridging the gap between high-level human commands and low-level robot control. LLMs have demonstrated capabilities in interpreting natural language, generating high-level plans, and even generating code for robot control. Works such as LaTTe (Language Trajectory Transformer) have explored multi-modal representations combining language with environmental observations for trajectory adaptation, but often require task-specific training and are limited to simpler instructions. Other research has utilized LLMs for generating robotic trajectories directly, or for producing code as policies for embodied control, often in zero- or few-shot settings without extensive fine-tuning. Some approaches focus on generating new waypoints to achieve a task, while others concentrate on explainable trajectory corrections based on natural language inputs, interpreting commands that describe desired adaptations to features like speed, direction, or proximity to objects. Closed-loop strategies integrating feedback (e.g., success detection, scene description, human interaction) have also been explored to refine robot behavior.

This work contributes to this landscape by proposing a language-based framework that utilizes pre-trained LLMs to adapt existing robotic trajectories, rather than generating entirely new ones from scratch or relying on task-specific training. It extends the concept of using code as a bridge between high-level language and low-level control to the specific problem of trajectory *adaptation*. Unlike prior work like LaTTe, this method aims to handle more complex, multi-step, and numerically oriented instructions without requiring explicit task-specific training. It also integrates an explicit human feedback loop, allowing for iterative refinement of the generated adaptation plan and code, enhancing interpretability and robustness against misinterpretations. This positions the work as an advancement towards more intuitive, flexible, and scalable natural language interfaces for modifying robot trajectories in diverse and dynamic environments.

### 2. Key Objectives and Motivation

The primary objective of this research is to develop a flexible, language-based framework for adapting existing robotic trajectories based on human instructions, thereby enhancing the intuitiveness and scalability of human-robot interactions.

The motivation for this work stems from several challenges inherent in current trajectory adaptation paradigms:
1. **Computational Cost of Replanning:** Traditional planning-based methods necessitate computationally intensive replanning whenever a new situation arises, making them less suitable for real-time or dynamic applications where rapid adjustments are required.
2. **Complexity of Learning-Based Models:** While learning-based approaches offer faster adaptation, they typically demand precise mathematical modeling and explicit formulation of task frames, which can be complex and inaccessible to non-expert users. There is a need for methods that bypass these complex mathematical formulations.
3. **Limitations of Current Language-Based Adaptation:** Existing natural language-based approaches for trajectory adaptation often require task-specific training, which limits their generalizability to new scenarios or instructions. They may also struggle with complex, multi-step, or numerically specific commands, reducing the granularity of control available to users.
4. **Gap between Language and Low-Level Control:** Translating high-level human preferences (e.g., "Go higher," "Move slower") into precise low-level robot control actions remains a significant challenge due to the semantic gap between natural language and robot kinematics/dynamics. There is a need for a robust mechanism to bridge this gap.
5. **Lack of Interpretability and Feedback:** Many existing learning-based systems can act as "black boxes," making it difficult for users to understand *why* a robot made a particular adaptation or to provide effective feedback for correction. A transparent and interactive feedback mechanism is desirable for robust HRI.

To address these motivations, the specific objectives of this research are formulated as follows:
- To enable natural language-based adaptation of generic robotic trajectories, regardless of whether they were produced by off-the-shelf motion planners (e.g., RRT, A-star) or learned from human demonstrations.
- To leverage pre-trained Large Language Models (LLMs) to generate executable code that serves as a policy for adapting trajectory waypoints, including both position and velocity components.
- To facilitate the incorporation of a broader range of human commands, specifically including complex, multi-step instructions and numerical inputs, which are often challenging for existing methods.
- To develop an approach that does not require task-specific training, offering greater flexibility and reducing the development overhead compared to feature-based sequence-to-sequence models.
- To enhance the interpretability of trajectory adaptations and provide a more effective feedback mechanism by explicitly generating a high-level plan for user validation prior to code execution.
- To validate the proposed framework across diverse robotic platforms, including manipulators, aerial vehicles, and ground robots, in various simulation environments.

### 3. Methodology and Approach

The methodology proposed in this work leverages the capabilities of Large Language Models (LLMs) to adapt robot trajectories based on natural language instructions. The core approach involves a parallel process of generating both a human-readable High-Level Plan (HLP) and executable Python code, followed by an iterative feedback loop with the user.

#### 3.1. Problem Formulation

The problem is formally defined as mapping an initial trajectory, environmental context, and natural language instructions to an adapted trajectory.
- The initial trajectory, denoted as $\tau$, is a sequence of N waypoints, each comprising 3D position coordinates and a velocity component: $\tau = \{(x_1, y_1, z_1, v_1), \ldots, (x_N, y_N, z_N, v_N)\}$. This trajectory can originate from standard planning algorithms or human demonstrations.
- $L_{\text{instruct}}$ represents the user's natural language command for trajectory adjustment (e.g., "Slow down when near the person"). These commands are assumed to clearly convey intent, potentially including multiple preferences.
- $O$ is an observation set of $m$ objects in the environment, with each object $O_i$ having a position $P(O_i) \in \mathbb{R}^3$ and a label $Label(O_i)$.
- $E_d$ is an optional natural language description of environmental semantics and rules.
The objective is to learn a function $g$ (implemented by an LLM) that produces an adapted trajectory $\tau_{\text{mod}}$:
$\tau_{\text{mod}} = g_{\text{LLM}}(\tau, L_{\text{instruct}}, O)$

#### 3.2. Methodology Pipeline

The approach follows a pipeline structure:

1. **Prompt Creation:** A comprehensive prompt is constructed for the LLM. This prompt integrates:
 - The natural language instruction ($L_{\text{instruct}}$).
 - An optional environmental description ($E_d$).
 - Task-agnostic guidelines and rules for trajectory adaptation.
 - Definitions of available functions that the LLM can use to interact with the environment and trajectory.
 - In-context examples to guide the LLM's response format and reasoning.

2. **HLP Generation (High-Level Plan):**
 - The LLM interprets the user's instructions and the environmental context (from $E_d$ and object observations).
 - It then generates a step-by-step high-level plan, outlining the logical sequence of operations required to adapt the trajectory according to the user's preferences. This plan is designed to be human-readable, facilitating user validation. Examples of HLPs are provided in the appendix, showcasing how instructions like "Go left" or "Walk further away from the box" are broken down into identifiable steps (e.g., shifting goal position, identifying object locations, iterating over intermediate points).

3. **Code Generation:**
 - Concurrently with the HLP, the LLM generates executable Python code. This code directly implements the modifications outlined in the high-level plan. The LLM is provided with definitions for two crucial functions:
 - `detect_objects(object_name)`: Returns the 3D position of a specified object or `None` if not present.
 - `get_trajectory`: Returns the current trajectory as a list of `(x, y, z, velocity)` waypoints.
 - The generated code is expected to utilize these functions to manipulate the trajectory.

4. **User Validation and Feedback Loop:**
 - After the HLP and code are generated, the HLP is presented to the user for review.
 - **If the user confirms the plan's correctness:** The generated Python code is executed to produce the adapted trajectory, which is then sent to the robot's execution module.
 - **If the user identifies issues or omissions:** They provide feedback. This feedback, along with the original instruction, is fed back into the framework (i.e., appended to the prompt for the LLM). The LLM then generates an updated HLP and code, entering an iterative refinement cycle until the user is satisfied. This closed-loop system allows for correcting misinterpretations and refining complex instructions.

#### 3.3. Prompt Design Considerations

Key considerations for designing the prompt to guide the LLM's behavior include:
- **Environment Configuration:** The prompt defines a `COORDINATE SYSTEM` (e.g., positive X is left, positive Y is front, positive Z is up) and provides optional `ENVIRONMENT DESCRIPTION` to contextualize spatial commands (e.g., "Go left/right"). It also outlines the available functions (`detect_objects`, `get_trajectory`).
- **Desired Trajectory Characteristics (Rules):** The prompt includes rules to guide the LLM in generating smooth, coherent trajectories:
 - Prioritize gradual shifts for smooth transitions.
 - Infer whether the start or goal positions should remain fixed based on instructions.
 - Allow for adding or removing waypoints as needed, while ensuring constraint adherence.
 - Modify intermediate waypoints for smoothness.
 - Store the new trajectory in a specific variable (`modified_trajectory`).
 - Ensure velocity changes are relative to original velocities and smooth.
- **In-context Examples:** Two examples of high-level plans are provided in the prompt (e.g., "Go left," "Walk further away from the box") to ground the LLM's responses and ensure the generated HLP is suitable for human debugging.
- **LLM Choice:** The GPT-4o model is used for all experiments, with a temperature setting of 0.1 to promote consistent and deterministic code generation.

This methodology aims to bridge the gap between abstract natural language and concrete robot actions by leveraging LLMs for interpretable planning and executable code generation, supported by an interactive user feedback mechanism.

### 4. Main Findings and Results

The experiments conducted aimed to validate the proposed LLM-based trajectory adaptation framework across three key questions. The findings from these simulations demonstrated the framework's capabilities in various robotic contexts.

#### 4.1. Code Generation for Trajectory Transformation (Waypoints and Velocity)

The first question addressed whether LLMs could generate code capable of transforming trajectories, including both position waypoints and velocity components.
- **Results:** The simulation experiments showed that the code generated by the LLM successfully adapted trajectories according to the intended meaning of the instructions. The adapted trajectories exhibited smooth adjustments, largely maintaining the overall shape of the original path, as illustrated in Figures 3 and 4. This indicates that the LLM, guided by the prompt design, was able to translate high-level commands into precise code for modifying both spatial and temporal aspects of the robot's movement.

#### 4.2. Devising Plans for Intricate and Diverse Commands with Few Examples

The second question investigated the LLM's ability to create plans for complex and varied commands, even with only one or two in-context examples of high-level strategies provided in the prompt.
- **Results:** The framework was tested not only on a subset of the LaTTe dataset (which primarily contains simpler instructions) but also on a custom-designed dataset featuring more complex instructions. This custom dataset included commands with precise numerical values (e.g., "Go left by 20," "Keep at least 10 distance from the box") and compound instructions (e.g., "Go left by 20 keeping a distance of at least 10 from the box").
- **Observation:** Figure 4 and Appendix A.4 demonstrate that the LLMs were capable of understanding these complex modifications and generating appropriate high-level plans and corresponding code. This suggests that the LLM's inherent reasoning capabilities, combined with effective prompt engineering and a few-shot learning approach, enabled it to generalize to novel and intricate instructions beyond the scope of simple commands.

#### 4.3. Free-Form Manipulation and Advantages over State-of-the-Art Methods

The third question explored how the proposed approach facilitates free-form (open-ended) manipulation of waypoints and its advantages over existing state-of-the-art methods, particularly in handling misinterpretations.
- **Results:**
 - **Handling Free-Form Commands:** The framework demonstrated the ability to process a wide range of natural language commands, including those involving numerical inputs and object-specific references (e.g., "Stop when you reach near the box"). In such cases, the method accurately identified the closest waypoint to the specified object and adapted the trajectory to halt at that point (Figure 4). This capability extends beyond the general changes typically found in datasets like LaTTe, which tend to focus on non-numerical adjustments.
 - **User Feedback for Corrections:** A significant advantage highlighted is the integration of user feedback for correcting LLM misinterpretations. Figure 5 illustrates how providing additional clarifying information from the user (e.g., modifying the high-level strategy) allowed the system to correct initial inconsistencies and produce more accurate outputs. This closed-loop mechanism enhances the robustness and reliability of the adaptation process, particularly for ambiguous or underspecified commands.
 - **No Task-Specific Training:** A key distinction from state-of-the-art feature-based sequence-to-sequence models (which often require training) is that this method operates without task-specific training. This characteristic contributes to its flexibility and reduces the effort required for deployment in new scenarios.

#### 4.4. Simulation Environment and Robot Diversity

The framework's utility was assessed across diverse robotic platforms and simulation environments:
- **Robots:** Experiments were conducted on a robotic manipulator (Kuka arm), an aerial vehicle (Crazyflie drone), and a ground robot.
- **Simulators:** The Kuka arm and Crazyflie drone were tested in Pybullet, while the ground robot was tested in Gazebo (Figure 2).
- **Tasks:** These experiments demonstrated object-oriented trajectory shifting (e.g., "Shift the trajectory to reach yellow bowl"), generic shifts (e.g., "Drive at a greater distance from person"), and directional shifts (e.g., "Go towards left passing closer to the duck"). This cross-platform validation suggests the framework's generalizability and compatibility with various robot dynamics and low-level inverse kinematics modules.

In summary, the main findings indicate that pre-trained LLMs, when integrated into a carefully designed prompt and feedback loop, can effectively generate code to adapt complex robot trajectories based on free-form human instructions, including numerical and multi-step commands, without requiring task-specific training. The interpretability offered by the high-level plan and the iterative feedback mechanism provides a practical means for error diagnosis and correction.

### 5. Significance and Potential Impact

This research presents a significant contribution to the field of human-robot interaction and robotic autonomy by introducing a flexible, language-based framework for trajectory adaptation. The work's significance and potential impact can be summarized as follows:

#### 5.1. Enhanced Human-Robot Interaction (HRI)

The proposed method enables more intuitive and scalable HRI by allowing non-expert users to modify robot trajectories using natural language commands. This capability reduces the technical barrier to programming or reconfiguring robot tasks, making robotic systems more accessible and user-friendly for a broader range of applications and users. The ability to express complex preferences, including numerical and object-specific instructions, directly through language represents a step towards truly collaborative robots that understand nuanced human intent.

#### 5.2. Flexibility and Generalizability

A key aspect of this work is its reliance on pre-trained Large Language Models (LLMs) and the avoidance of task-specific training. This design choice grants the framework considerable flexibility, allowing it to adapt generic trajectories—whether derived from traditional motion planners or human demonstrations—without extensive retraining for each new scenario or instruction set. This contrasts with many existing learning-based methods that require substantial data and training for specific tasks, thus broadening the applicability of the proposed approach.

#### 5.3. Interpretability and Robustness through Feedback

The generation of a high-level plan alongside the executable code significantly enhances the interpretability of the robot's intended adaptation. Users can review this plan, understand the LLM's reasoning, and provide targeted feedback. This closed-loop human-in-the-loop system is crucial for correcting LLM misinterpretations, refining ambiguous instructions, and ensuring the robot's behavior aligns with human expectations. This iterative refinement capability improves the robustness of the system in real-world, uncertain environments where initial instructions may be incomplete or imprecise.

#### 5.4. Handling Complex and Numerical Instructions

The framework demonstrates the ability to handle a broader spectrum of commands, including complex, multi-step instructions and those incorporating precise numerical inputs (e.g., "Go left by 20," "Keep at least 10 distance from the box"). This goes beyond the capabilities of many current language-conditioned methods that are often limited to simpler, qualitative adjustments. This capacity for fine-grained control allows for more precise and task-relevant trajectory modifications.

#### 5.5. Diverse Robotic Platform Applicability

The validation of the framework across different robotic platforms—a robotic manipulator, an aerial vehicle, and a ground robot—in diverse simulation environments (Pybullet and Gazebo) highlights its potential for broad applicability. This suggests that the approach is not limited to a specific robot form factor or task domain, but can be integrated with various robot dynamics and low-level control modules.

#### 5.6. Potential for Future Research and Applications

This work opens several avenues for future research, including the exploration of more complex instructions and long-horizon tasks, further investigation into the implications of LLM-specific biases, and the conduct of user studies to rigorously evaluate the method's effectiveness and ease of use in human-robot collaboration scenarios. The framework can serve as a foundation for developing more advanced human-robot collaboration paradigms where robots dynamically adjust their behavior based on ongoing natural language dialogue and feedback.

#### 5.7. Limitations

Despite its advancements, the method has acknowledged limitations. The effectiveness of adaptations is contingent on the descriptiveness and completeness of user instructions; subjective terms like 'very' or 'relatively slower' can lead to ambiguity. Furthermore, the method currently lacks mathematical guarantees for trajectory smoothness, potentially resulting in semantically accurate but kinetically irregular paths. Lastly, tailoring a universal constraint satisfaction module for all possible open-vocabulary instructions remains a challenge.

In conclusion, this research significantly advances the utility of LLMs in robotics by offering a practical, flexible, and interpretable method for trajectory adaptation, paving the way for more natural and effective human-robot partnerships.
