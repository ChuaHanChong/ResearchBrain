# MIKASA-Robo-VLA: Benchmarking Memory in VLA Models for Long-Horizon Manipulation

> [!summary] Summary
> MIKASA-Robo-VLA is a ManiSkill 3 benchmark of 90 language-conditioned manipulation tasks covering 10 memory types. In 80 of the tasks, the cue an action depends on is hidden before the action; the other 10 are reactive controls. It releases 22,500 oracle demonstrations in RLDS and LeRobot formats with dense rewards. A pi0.5 baseline with no memory reaches only 0.211 mean success, roughly what chance-level cue selection predicts.

## Problem

- Generalist VLA policies see only one to sixteen recent frames, and standard evaluations cannot show how they use information that disappears during a task.
- General suites such as CALVIN, LIBERO and RoboCasa emphasize skill composition and transfer, never systematically varying what must be remembered or for how long.
- Memory benchmarks like MemoryBench, RoboMME and LIBERO-Mem cover few tasks and memory types, lacking controlled retention, horizon stratification, dense rewards and GPU-parallel execution.

## Method

- ==Memory taxonomy== of 10 types (Object, Spatial, Capacity, Temporal, Negative, Sequential, Procedural, Prospective, Tracking, Checklist) spanning 26 parameterized task families with difficulty and timing variants.
- ==Information-gap metric== derived from environment phase timings that measures the provably cue-absent interval, paired with Short/Medium/Long horizon splits spanning 25 to 2,160 steps, separating retention from episode length.
- ==Oracle dataset pipeline==: ==PPO policies== and ==scripted motion planners== with privileged state generate 250 successful episodes per task, re-rendered through VLA observation wrappers into ==RLDS== and LeRobotDataset v3.

## Results

- Of the **70** tasks with determined gaps, **28** exceed the **16**-frame window of the widest fixed-context VLA surveyed, and the longest gap reaches **1,000** steps.
- Fully fine-tuned pi0.5 without observation history achieves **0.211** ± **0.044** mean success on **14** tasks, with **33** successes in **140** episodes versus **35.3** expected from uniform guessing.
- Long-split tasks reach **0.017** success versus **0.264** elsewhere (permutation p = **0.008**); separately, a **64**-token recurrent memory module (muVLA) lifts OpenVLA-OFT from **0.42** to **0.84** mean success on five trained tasks.

## Takeaways

> [!tip] Key Insights
> - Episode length is not memory demand: long sequences can stay locally observable while short tasks hinge on a vanished cue, so measure cue absence directly.
> - Aggregate success can hide guessing that ignores the cue; compare against an analytic 1/k chance reference before crediting a policy with memory.
> - Open-loop action chunking confounds long-horizon memory evaluation, shifting per-task success by up to 0.65, so control the execution regime before attributing failures to memory.

## Detailed Report

### 1. Overview

In one task, a robot tests batteries one by one, reads the lamp result, and must keep track of which ones worked before pressing the confirmation button. To do this, the robot has to carry forward the results of earlier tests while it continues the task. The authors turn this kind of information-retention demand into repeatable simulated tasks, with instructions and training data, so that researchers can compare policies on the same challenge.

Batteries Checker Easy render preview: insert each battery, observe the lamp result, remember which batteries work, and press the confirmation button. This is an environment preview, not evidence of a policy's success rate.

The benchmark, MIKASA-Robo-VLA, extends [[2502.10550|MIKASA-Robo]] into 90 language-instructed tasks across 10 memory categories. It includes difficulty variants, dense rewards, a shared evaluation setup, and 22,500 demonstrations in RLDS and LeRobotDataset v3. The original suite had 32 tasks and four memory types.

### 2. When the cue disappears

During sustained manipulation, a robot may need to use a cue that is no longer visible. The task instruction states the goal, but the observation history can determine how to achieve it. The authors therefore distinguish **episode horizon** from **retention interval**. A long sequence may keep its important cue visible, while a short task may depend on a cue that has disappeared.

To make this demand explicit, the authors define an *information gap*. It is the time from when a task-relevant cue was last available to the start of the phase requiring an action based on it. The gap is measured from environment phase timings, not from a policy's actions.

Seventy tasks have a gap determined by the environment. In 10 control tasks the cue stays visible. In 10 other tasks the interval depends on the policy and cannot be determined from phase timings alone. Of the 70, 28 have a median cue-absent interval longer than 16 steps. Sixteen steps is a reference to the widest fixed observation window surveyed in the paper. It is not a limit on recurrent or external memory.

The gap measures only the provably cue-absent interval, not the full time a policy may need to retain information. Every memory-dependent task still requires retention by construction, including tasks with short or zero measured gaps. Fifteen tasks have zero measured gap even though recall may be required during the action phase.

Two rows of eight top-camera frames from a nominal 600-step horizon. Top: RememberColor5-Long, instructed to observe a cube's color, wait, then touch a matching cube. Bottom: ShellGameShuffleColorLampTouch-Long, instructed to observe which color is under each cup, track cups as they shuffle, then touch the cup matching the lamp color. The image illustrates the cue-to-action relationship, not a model score.

### 3. What the reference score can tell us

The reference policy is π₀.₅, fine-tuned from `pi05_base` on 14 tasks using 3,500 LeRobot episodes. It receives current images from two cameras and proprioception, but no observation history or explicit memory. Its predictions execute in open-loop chunks of eight actions. The evaluation covers one training run, 20 evaluation episodes per task, and a nonrepresentative subset of the benchmark.

Mean task success is 0.211 ± 0.044. Success means the task condition held at any point in an episode. The aggregate is the unweighted mean of the 14 task success rates, and ±0.044 is the standard error across tasks. This score comes from one model, one checkpoint, and one protocol. It is not a ceiling on memory-free performance or proof that memory caused its failures.

The most direct cue-use check covers seven tasks where success is a choice among a fixed number of equally likely candidates. On these, the baseline records 33 successes in 140 episodes. A hypothetical uniform choice after successful manipulation would be expected to produce 35.3 (standard deviation 5.1). No task exceeds that reference by more than one reported standard error, so the results provide no clear evidence of cue-dependent selection on this subset. The reference is an analytic guessing reference, not a learned-policy baseline, and it assumes the arm can execute the selected action.

A stronger test asks whether explicit memory helps. The separate [[2606.12497|μVLA study]] addresses this on the same benchmark family. In that study, recurrent memory tokens carry a state from one environment step to the next inside OpenVLA-OFT. With 64 tokens and TBPTT length K=2, mean success reached 0.84 on five trained tasks, versus 0.48 for an episodic-dataloader no-memory reference. The ordinary no-memory recipe scores 0.42, so the change in data ordering alone accounts for part of the difference. On 11 held-out tasks with matched memory semantics, the study reports 0.23 versus 0.07. Its seven held-out tasks with novel memory semantics stayed near the memoryless references.

That study used 100 deterministic episodes per environment and receding-horizon inference, under an earlier release protocol. It is not a matched rerun of this paper's π₀.₅ baseline.

### 4. Contribution and boundary

A task's duration alone does not show what the robot had to retain. The lasting contribution of MIKASA-Robo-VLA is a shared target for testing memory under defined cue demands. Its environments and trajectories are simulated, and its policy results remain conditional evidence, not a verdict that current VLA models cannot remember.
