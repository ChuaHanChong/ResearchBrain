# PyVision: Agentic Vision with Dynamic Tooling

> [!summary] Summary
> The PyVision framework equips multimodal large language models with the ability to autonomously generate, execute, and refine Python code for visual reasoning tasks. This approach leads to consistent performance improvements across various benchmarks, including a 7.8% gain on fine-grained visual search with GPT-4.1 and a 31.1% increase on symbolic vision tasks with Claude-4.0-Sonnet.

## Problem

- Multimodal Large Language Models (MLLMs) struggle with novel or complex visual reasoning due to reliance on static, predefined toolsets.
- Current MLLM agents lack the ability to dynamically generate custom computational tools, limiting their adaptability to diverse visual tasks.
- Prior approaches lacked sufficient interpretability and verifiability for complex, compositional visual reasoning tasks.

## Method

- An interactive, ==multi-turn framework== empowers MLLMs to dynamically generate and execute Python code for visual reasoning.
- Python and its rich ecosystem of libraries (e.g., OpenCV, NumPy) serve as the ==exclusive primitive for tool creation==, enabling dynamic composition of task-specific solutions.
- The framework ensures robust multi-turn interaction through ==process isolation==, cross-turn state persistence, and secure I/O for iterative refinement.

## Results

- PyVision-GPT-4.1 achieved performance increases of **+1.8%** on MathVista, **+2.4%** on MMMU, and **+7.8%** on V* benchmarks.
- PyVision-Claude-4.0-Sonnet showed significant gains, including **+4.8%** on MathVista, **+8.3%** on Visual Puzzles, and **+31.1%** on VLMsAreBlind-mini.
- Analysis of dynamically generated code revealed adaptive tool usage, with specific tool types predominantly invoked according to task demands and domain characteristics.

## Takeaways

> [!tip] Key Insights
> - MLLMs can move beyond static tool usage to dynamically invent task-specific computational tools using a Python-based framework.
> - The framework provides enhanced interpretability and verifiability by allowing inspection of the AI's generated Python code and execution steps.
> - PyVision's dynamic tooling complements and amplifies the inherent strengths of its backend MLLMs, leading to varied performance boosts depending on the model's core capabilities.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

The research on PyVision is situated at the intersection of several rapidly evolving fields: large language models (LLMs), multimodal AI, and AI agents. It addresses a critical limitation in current multimodal large language models (MLLMs) by advancing their ability to engage in "agentic vision" through dynamic tool generation.

Historically, AI systems for visual reasoning have evolved from rule-based systems to deep learning models. Within deep learning, early neuro-symbolic approaches like Neural Module Networks (NMNs) introduced the idea of orchestrating predefined functional modules for complex visual tasks. This line of work, and its successors (e.g., IEP, VisProg), embraced a more transparent and interpretable reasoning paradigm compared to end-to-end black-box models. However, these systems were typically limited by static, predefined toolsets and workflows, meaning they could only execute tools that were explicitly designed for them.

With the advent of powerful LLMs and their remarkable coding capabilities, the concept of "tool-using agents" has gained significant traction. LLMs can now plan, reason, and call external tools (e.g., APIs, databases, specific models) to solve complex problems. Early multimodal tool-using models like Visual ChatGPT, MM-REACT, HuggingGPT, and ViperGPT demonstrated this potential by integrating MLLMs with a fixed set of visual foundation models (e.g., for object detection or segmentation). While these marked a step forward, they still operated within the confines of *predefined* toolsets. Even more recent works like Visual Sketchpad, which allowed LLMs to program and execute code, largely relied on a static or predefined collection of visual parsers.

PyVision distinguishes itself by moving beyond this limitation. It argues for the "profound leap" of an agent's ability to *invent* tools, not just use them. This aligns with a broader trend in AI research towards more autonomous and adaptive agents, where models can dynamically generate code snippets tailored to the specific task and environment. OpenAI's "Thinking with Images" blog post alluded to this potential, but PyVision provides a concrete framework and extensive analysis of *how* advanced MLLMs (like GPT-4.1 and Claude-4.0-Sonnet) can achieve this.

By focusing on Python as the sole primitive for tool creation and leveraging its rich ecosystem (OpenCV, Pillow, NumPy, SciPy), PyVision positions itself as a highly flexible and generalizable approach. It aims to overcome the "bottleneck" of static visual parsers, allowing the MLLM to synthesize novel, task-specific computational tools on the fly. This represents a significant step towards genuinely agentic and creative AI systems capable of adapting to diverse and novel visual reasoning scenarios, embodying the "tool-making animal" analogy for intelligence.

### 2. Key Objectives and Motivation

The primary objective of the PyVision project is to develop and analyze an interactive, multi-turn framework that empowers multimodal large language models (MLLMs) to **autonomously generate, execute, and iteratively refine Python-based tools tailored to the task at hand**. This framework, named PyVision, aims to unlock more flexible, interpretable, and grounded problem-solving capabilities in visual reasoning.

The motivation for this work stems from several limitations observed in prior approaches to visual reasoning and multimodal tool-using:
- **Limitations of Predefined Workflows and Static Toolsets**: Existing MLLM agents, while capable of using external tools, are largely constrained by a fixed set of predefined tools or models (e.g., a specific object detector or segmenter). This limits their flexibility, creativity, and adaptability when facing novel or complex visual reasoning challenges that do not fit neatly into established tool functions.
- **Need for Adaptive and Task-Specific Tooling**: Real-world visual problems are diverse and often require unique, dynamically composed solutions. A static toolset cannot sufficiently address this variability. The researchers are motivated by the idea that truly intelligent agents should be able to "invent" problem-solving tools on the fly, much like humans do.
- **Desire for Interpretability and Verifiability**: End-to-end deep learning models, while powerful, can be black boxes. Approaches that explicitly represent reasoning steps and produce transparent intermediate outputs offer a promising path for tackling complex, compositional visual reasoning. By generating and executing Python code, PyVision provides a clear, verifiable trace of the model's computational process.
- **Leveraging Advanced MLLM Capabilities**: Modern MLLMs like GPT-4.1 and Claude-4.0-Sonnet possess strong coding and reasoning abilities. The project is motivated to harness these innate strengths, particularly their capacity for dynamic code generation, to overcome the aforementioned limitations in visual reasoning. The introductory Ebbinghaus illusion example (Figure 1) vividly illustrates this motivation: a standard MLLM falls for an illusion, while PyVision, by dynamically generating code to analyze pixel values and segment objects, correctly ascertains the sizes, demonstrating reasoning "beyond superficial pattern matching."

In essence, PyVision seeks to elevate MLLMs from mere tool *users* to tool *inventors*, enabling a more agentic form of visual intelligence that can adapt, explain, and ground its reasoning in the visual environment.

### 3. Methodology and Approach

PyVision proposes an **interactive, multi-turn framework** that allows an MLLM to dynamically generate and execute Python code during an inference session. This methodology is designed to facilitate flexible and interpretable multimodal reasoning.

**Core Framework (Figure 2):**
1. **Input and MLLM Generation**: In each turn, the MLLM receives the current context (user query, previous code outputs, and initial image inputs). Based on this, it generates a Python code block (`code_block_i`).
2. **Code Execution**: The generated Python code is executed within an isolated Python runtime environment.
3. **Output Feedback**: The execution produces multimodal results (`mm_clue_i`), which can be textual (e.g., print statements, numerical data) or visual (e.g., matplotlib plots, modified images).
4. **Iterative Refinement**: These multimodal outputs are appended to the MLLM’s context, allowing it to update its reasoning, generate further code, or formulate a final answer in subsequent turns. This loop continues until the MLLM decides it has resolved the query.

**Key Design Principles:**
- **Python as the Sole Primitive Tool**: Unlike prior methods that rely on predefined sets of specialized visual parsers (e.g., GroundingDINO for detection, SAM for segmentation), PyVision provides only the Python language and its rich ecosystem of general-purpose scientific and vision libraries (e.g., OpenCV, Pillow, NumPy, Pandas, Scikit-learn, Scikit-image). This design choice is fundamental to enabling dynamic tool generation, as the MLLM composes these primitives into task-specific tools.
- **System Prompt Design**: A carefully constructed system prompt guides the MLLM. It includes:
 - Instructions to generate Python code for task solving.
 - Pre-loading of input images as `image_clue_i` variables, along with their resolution.
 - Specification for outputting results via `print` (for text) and `plt.show` (for visualizations).
 - Requirement for code blocks to be wrapped in `<code>` tags for reliable parsing.
 - Requirement for final answers to be enclosed in `<answer>` tags for consistent evaluation.
- **Robust Multi-Turn Interaction**: To ensure seamless and safe operation of the dynamic tooling loop, PyVision incorporates:
 - **Process Isolation**: Each generated code snippet runs in a dynamically spawned subprocess, preventing crashes or side effects from one execution from impacting the overall session.
 - **Cross-Turn Persistence**: The runtime environment maintains variables and state across turns. This is crucial for iterative operations, such as cropping an image, then filtering it, and then computing features from the filtered image.
 - **File-System Safe I/O**: Communication between the runtime and the MLLM uses structured variable passing and system prompts, avoiding direct dependencies on the host file system for security and stability.

**Tooling Taxonomy Creation**:
To understand the diversity and nature of tools generated by PyVision, the researchers developed a taxonomy. This involved:
1. **Collection**: Gathering generated code snippets from various inference sessions across diverse tasks and domains.
2. **Embedding**: Using a text embedding model (OpenAI's `text-embedding-3-large`) to convert code snippets into numerical representations.
3. **Clustering**: Applying clustering algorithms to these embeddings to identify emergent categories of tools.
4. **Interpretation**: Manually inspecting and interpreting the clusters to define five major classes: Basic Image Processing (e.g., cropping, rotation, enhancement), Advanced Image Processing (e.g., segmentation, detection, OCR), Visual Prompting and Sketching (e.g., rendering marks, lines), Numerical and Statistical Analysis (e.g., image histograms, numerical computations), and Long-Tail Operations (creative, one-off tools like image differencing).

This systematic methodology allows PyVision to not only perform visual reasoning but also to adapt its computational strategy dynamically, making its reasoning processes more transparent and verifiable.

### 4. Main Findings and Results

The research paper presents several key findings, demonstrating the effectiveness and characteristics of PyVision's agentic visual reasoning:

1. **Consistent Performance Gains**: PyVision consistently boosts the performance of strong backend MLLMs (GPT-4.1 and Claude-4.0-Sonnet) across a diverse suite of benchmarks.
 - **GPT-4.1 Improvements**: PyVision-GPT-4.1 showed uniform gains, including +1.8% on MathVista, +2.4% on MMMU, and a significant **+7.8% on V*** (a fine-grained visual search benchmark).
 - **Claude-4.0-Sonnet Improvements**: PyVision-Claude-4.0-Sonnet also demonstrated notable gains, with +4.8% on MathVista, +8.3% on Visual Puzzles, and a dramatic **+31.1% on VLMsAreBlind-mini** (a symbolic vision task).
 - These results highlight that dynamic tool generation delivers broad, task-dependent improvements, especially significant in tasks requiring precise visual manipulation or abstract symbolic reasoning.

2. **PyVision Amplifies Backend MLLM Strengths**: The study found a complementary pattern: PyVision tends to amplify the inherent strengths of the backend MLLM.
 - **Reasoning-centric tasks**: Claude-4.0-Sonnet, which showed stronger innate performance on abstract reasoning tasks like MathVision-mini (48.0% vs. GPT-4.1's 46.4%), experienced a larger relative boost from PyVision (+3.3% vs. GPT-4.1's +2.3%).
 - **Perception-centric tasks**: Conversely, GPT-4.1, which excelled in perceptual tasks like V* (68.1% vs. Claude-4.0-Sonnet's 56.5%), achieved a substantially greater improvement with PyVision (+7.8% vs. Claude's +0.3%).
 - This suggests that dynamic tooling does not override core model capabilities but rather *unlocks* and enhances them, making the interplay of reasoning and perception crucial.

3. **Diverse and Adaptive Tool Usage (Taxonomy Analysis)**: The analysis of dynamically generated tools revealed strong task- and domain-specific preferences, demonstrating PyVision's adaptability.
 - **Math and Logic Benchmarks**: For MathVista, MathVision, MMMU, and VisualPuzzles, PyVision frequently generated numerical and statistical analysis tools, often accompanied by visual prompting and sketching tools to ground abstract logic.
 - **Symbolic Vision Tasks**: On VLMsAreBlind, advanced image processing tools (e.g., segmentation, detection) were predominant, reflecting the need for structure extraction and visual parsing (e.g., identifying contours of nested squares, Figure 5).
 - **Fine-Grained Visual Search**: For V*, cropping tools overwhelmingly dominated (over 83% of all tools), indicating PyVision's ability to focus attention on localized regions for precise queries (e.g., refining crop boxes to read text on a small advertising board, Figure 3).
 - **Domain-Specific Adaptations**: In medical imaging, contrast enhancement tools were frequently invoked to reveal subtle patterns (Figure 4). In remote sensing, segmentation tools were more common for delineating objects.
 - "Long-tail operations" also emerged, such as direct pixel subtraction for "spot-the-difference" tasks (Figure 7), showcasing creative, on-the-fly problem decomposition.

4. **Varied Agentic Behavior in Code Generation**: There were distinct differences in how often and how much code different MLLMs generated.
 - **Claude-4.0-Sonnet** consistently generated more code blocks per query across all domains, often with longer toolchains, sometimes achieving 100% code coverage (meaning code was used in every interaction).
 - **GPT-4.1** tended to use fewer code blocks.
 - These patterns suggest underlying differences in how each MLLM perceives task complexity and utilizes code to support its reasoning process.

In summary, PyVision provides a powerful, adaptable framework for agentic visual reasoning, delivering significant performance boosts, demonstrating sophisticated tool-making capabilities, and revealing nuanced interactions with the inherent strengths of its backend MLLMs.

### 5. Significance and Potential Impact

PyVision represents a significant advancement in the field of artificial intelligence, particularly in the realm of multimodal reasoning and agentic AI. Its potential impact spans several key areas:

1. **Advancement in Agentic AI**: The most profound impact of PyVision is its contribution to the development of truly agentic AI systems. By enabling MLLMs not just to *use* predefined tools but to *invent* new computational tools on the fly, PyVision pushes AI closer to the human capacity for adaptive problem-solving. This "tool-making animal" paradigm signifies a shift towards more autonomous, versatile, and creative AI agents capable of tackling novel and complex challenges in real-world visual environments.

2. **Enhanced Visual Reasoning Capabilities**: PyVision significantly improves the performance of MLLMs on a wide array of visual reasoning tasks, from fine-grained visual search and symbolic puzzles to complex mathematical and medical image analysis. This means AI systems can now interpret visual information with greater precision, adapt their approach to specific visual ambiguities (like illusions), and perform more sophisticated quantitative analysis directly on images.

3. **Increased Interpretability and Trust**: The methodology of generating and executing Python code provides a transparent and verifiable trace of the AI's reasoning process. Researchers and users can inspect the generated code, understand the computational steps taken, and even debug or refine the process. This increased interpretability is crucial for building trust in AI systems, especially in high-stakes domains like medical diagnosis (Figure 4) or scientific research.

4. **Flexibility and Generalizability**: By leveraging the vast and flexible Python ecosystem rather than relying on a static set of specialized visual models, PyVision offers unparalleled flexibility. It can dynamically compose custom solutions for diverse tasks and domains without requiring prior training on domain-specific modules. This reduces the need for constant retraining or integration of new specialized models, making MLLMs more generalizable and applicable to a broader range of visual problems.

5. **Catalyst for Future Research**: PyVision opens new avenues for research into how LLMs can best integrate with computational environments. It prompts questions about how to further enhance code generation quality, manage complex multi-turn interactions, and develop more sophisticated methods for self-correction and refinement in code-based reasoning. The observation that PyVision amplifies backend model strengths also suggests tailored approaches for combining different MLLMs with dynamic tooling.

6. **Practical Applications**: The improvements demonstrated across various benchmarks suggest immediate practical applications. For instance, in scientific domains, PyVision could assist in analyzing complex data visualizations. In e-commerce, it could enable more nuanced product searches. In robotics, it could inform more adaptive perception and planning. The ability to reason accurately with medical images could lead to new diagnostic aids.

In conclusion, PyVision represents a crucial step forward in multimodal AI, demonstrating that empowering models to dynamically invent tools is not just a performance booster but a fundamental paradigm shift towards more intelligent, adaptable, and interpretable AI systems that can genuinely "think visually" and make sense of the world around them.
