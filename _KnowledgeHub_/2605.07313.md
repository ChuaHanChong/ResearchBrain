# When Stored Evidence Stops Being Usable: Scale-Conditioned Evaluation of Agent Memory

> [!summary] Summary
> A scale-conditioned evaluation protocol for agent memory: task-relevant evidence is held fixed while irrelevant sessions grow from 0 to 400, and agent-memory trajectories are logged to report budget-compliant reliability (Pass@B), tail retrieval-call burden (P90R), failure-regime decomposition, and the usable-scale boundary. Across LongMemEval and LoCoMo with flat, planar, and hierarchical interfaces, reliability loss proves to be several distinct phenomena, not one.

## Problem

- Memory-agent evaluations report fixed-snapshot accuracy or retrieval quality, which cannot show how far a scalability claim extends as irrelevant accessible history accumulates.
- Endpoint accuracy collapses distinct failure regimes into one score: retrieval ranking, excessive agent-memory interaction, failure to stop, and wrong synthesis all look identical.
- Memory-systems research designs backends and reports storage capacity, but never states scalability as a joint claim over agent, interface, scale range, and interaction budget.

## Method

- Evidence-preserving scaling ladder: for each query, annotated evidence sessions stay fixed while 0/100/200/300/400 irrelevant sessions are injected, growing accessible history from 4.2K to 1.03M tokens.
- Trajectory diagnostics: Pass@B counts a rollout only if the answer is correct and agent-issued memory calls stay within budget B; P90R tracks the 90th-percentile retrieval-call tail.
- Failure-regime decomposition splits errors into budget-induced trajectories and wrong-within-budget answers, plus breakdown onset, the first scale where reliability drops below the threshold.

## Results

- On LongMemEval, HippoRAG never exceeds the two-call budget yet loses 20.0, 19.1, and 16.0 Pass@2 points from evidence-only to 400 irrelevant sessions across Qwen3-8B/32B/235B.
- LiCoMemory is agent-dependent: Qwen3-8B is already below the 70% threshold at scale zero with 38.6% budget-induced failures, while 32B and 235B stay reliable past 400 sessions.
- Larger agents cut interaction burden on the multi-hop interface, with P90R shrinking from 5 to 4 to 2 and budget-induced trajectories falling 38.6% to 15.7% to 2.0%.

## Takeaways

> [!tip] Key Insights
> - Storing the right evidence is not enough; usable memory is a joint property of agent, interface, scale range, and interaction budget, so claims must state all four.
> - Interface shape predicts failure type: flat and single-pass retrieval fails within budget, while iterative and multi-hop retrieval burns calls on retrieve-verify loops.
> - Model scale fixes stopping behavior on some interfaces but not others, so a stronger backbone is not a general remedy for memory scalability.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

Large Language Model (LLM) agents are increasingly designed to combine reasoning capabilities with external tools, structured workflows, and autonomous environmental interaction. A critical component for enabling long-horizon interaction in these agents is the integration of memory systems. These systems are intended to persist information across multiple sessions and make relevant context accessible during inference.

Prior research in agent memory primarily operates in two domains:
1. **Systems Research**: Focuses on designing memory backends that efficiently retrieve relevant evidence. This includes various architectures such as OS-like, lifecycle-managed, lightweight, graph-based, or hierarchical interfaces.
2. **Evaluation Research**: Typically assesses memory performance based on fixed-snapshot accuracy or retrieval quality. Benchmarks in this area evaluate growing histories, multi-session conversations, and interactive memory use.

However, the authors identify a significant gap in the existing evaluation landscape. Current fixed-snapshot scores do not adequately address how the usability of stored evidence changes as irrelevant information accumulates over time in deployed agents. Furthermore, these evaluations often fail to decompose the causes of failure, making it difficult to discern whether a problem stems from retrieval ranking, excessive interaction, answer synthesis, or scoring noise.

This paper positions itself as an advancement in evaluation methodology. Instead of introducing a new memory architecture or benchmark, it proposes a trajectory-level evaluation protocol designed to measure "usable memory under evidence-preserving growth." The work extends the evidence-preserving scaling concept from LongMemEval by transforming it into a diagnostic framework. The objective is to provide a more granular and conditional assessment of memory scalability, moving beyond simple storage capacity or fixed-snapshot accuracy metrics. It aims to clarify under what specific conditions (agent, interface, scale, budget) a memory system remains effective.

### 2. Key Objectives and Motivation

The central motivation for this research stems from a recognized limitation in existing evaluations of agent memory systems. While current benchmarks assess accuracy or retrieval quality, they typically do so with a fixed "snapshot" of memory. This approach fails to capture the dynamic reality of deployed agents, where memory continuously accumulates sessions and observations, a significant portion of which may be irrelevant to a given task. Consequently, a fixed-snapshot score cannot effectively convey:
1. **Scalability Extension**: How far a claim of scalability for a memory system genuinely extends as the volume of irrelevant accessible history grows.
2. **Failure Attribution**: Whether a subsequent failure is due to issues with retrieval ranking (difficulty finding evidence), excessive interaction (too many memory calls), problems in answer synthesis (inability to use retrieved evidence), or noise in the scoring process.

To address these limitations, the paper sets forth several key objectives:
- **Investigate Agent Behavior Under Memory at Scale**: The primary goal is to systematically study how agent performance and memory usability change when irrelevant accessible memory increases, while task-relevant evidence remains constant. This "evidence-preserving scaling" is a controlled intervention designed to isolate the effect of irrelevant memory growth.
- **Develop a Scale-Conditioned Evaluation Protocol**: The core objective is to introduce a novel, trajectory-level evaluation protocol that explicitly measures whether an agent can still effectively utilize fixed task evidence as irrelevant sessions accumulate within its accessible history. This protocol is intended to provide a more comprehensive understanding of agent-memory system behavior.
- **Introduce Trajectory-Level Diagnostic Metrics**: To provide a granular understanding beyond aggregate accuracy, the paper aims to define and utilize a suite of diagnostics. These include:
 - **Budget-compliant reliability (Pass@B)**: To measure success under explicit interaction budget constraints.
 - **Tail retrieval-call burden (P90R)**: To quantify the computational or interaction cost incurred by the agent when memory scales.
 - **Failure-regime decomposition (p_exh and p_wrong)**: To categorize observed failures into those resulting from budget exhaustion versus incorrect answers within budget.
 - **Usable-scale boundary (s*α)**: To identify the specific scale at which a system's reliability falls below a predefined threshold.
- **Establish Conditional Scalability Claims**: The overarching motivation is to advocate for a framework where claims about scalable memory are explicitly conditional. Such claims should be tied to the specific agent model, memory interface, tested scale range, and interaction budget, rather than being presented as inherent properties of a memory system alone. This framework aims to make memory evaluations more auditable and transparent.
- **Empirically Audit Diverse Memory Interfaces and Agents**: To demonstrate the utility and insights provided by the new protocol, an empirical audit is planned across various memory interface families (flat, planar, hierarchical) and different LLM agents. This will highlight how similar reliability curves can mask fundamentally different failure mechanisms.

The scope of this work is deliberately focused on "usable memory" under evidence-preserving growth and agent-issued retrieval calls. It explicitly *does not* aim to measure total storage scalability, offline indexing cost, hidden backend computation, semantic density of returned evidence, adversarial memory robustness, or management of stale/contradictory memory. The emphasis is on an agent-facing interface evaluation rather than a full end-to-end systems-cost comparison.

### 3. Methodology and Approach

The research introduces a scale-conditioned evaluation protocol designed to assess the usability of agent memory under conditions of growing irrelevant information.

#### 3.1. Evaluation Protocol

For each benchmark query `q`, the evaluation proceeds through four defined steps:
1. **Evidence Identification**: The protocol first identifies the set of annotated task-relevant evidence sessions, denoted `E(q)`, pertinent to the query `q`.
2. **History Construction**: Accessible histories, `H(s)(q)`, are constructed by holding `E(q)` fixed and incrementally adding a specified number of irrelevant sessions, `N_irr(s)`. This method, termed "evidence-preserving scaling," ensures that changes in performance are attributable solely to the increased volume of irrelevant data, not to the removal or alteration of essential evidence. The evaluation uses a shared discrete scale ladder `S = {s0, ..., s4}` with matched irrelevant-session counts across benchmarks (0, 100, 200, 300, 400 irrelevant sessions).
3. **Agent Execution and Logging**: An agent `A` is run with a specific memory interface `M` against the constructed history `H(s)(q)`. During this execution, all agent-issued external memory API calls are meticulously logged.
4. **Scoring and Diagnostic Computation**: The final answer produced by the agent is scored for correctness. Subsequently, four trajectory-level diagnostics are computed: budget-compliant reliability, retrieval-call quantiles, failure-regime decomposition, and breakdown onset.

#### 3.2. Agent–Memory Interaction Under Scale

The focus is on "usable memory scalability" as an agent–interface operating property.
- **Evidence-Preserving Memory Scaling**: As detailed above, this ensures that `E(q)` is consistently present across all scales `s`, and `H(s)(q) \ E(q)` contains only additional irrelevant sessions. This isolates the challenge of retrieval control.
- **Agent–Memory Trajectories**: A rollout `τ` captures the sequence of observations and actions. The `retrieval-call count`, `R(τ)`, is defined as the total number of agent-issued external memory API calls within `τ`. `C(τ)` is a binary indicator of final-answer correctness. The primary retrieval-call budget `B0` is set to 2.

#### 3.3. Trajectory-Level Diagnostics for Memory Scalability

The protocol defines four key metrics to characterize agent–memory behavior:

1. **Budget-compliant reliability (Pass@B)**:
 - **Definition**: `pass_B(τ) = 1` if the final answer is correct (`C(τ)=1`) AND the retrieval-call count is within budget (`R(τ) <= B`), otherwise `0`.
 - **Metric**: `Pass@B(A, M, s)` is the expectation of `pass_B(τ)` over queries and rollouts at a given scale `s`.
 - **Purpose**: Measures the operational reliability of the system under a stated interaction budget, not just raw accuracy.

2. **Retrieval-call quantile (P90R)**:
 - **Definition**: `Q_p(A, M, s)` is the `p`-th quantile of the `R(τ)` distribution.
 - **Metric**: `P90R(A, M, s)` is the 90th percentile, focusing on the tail of the retrieval-call distribution.
 - **Purpose**: Tracks the growth of interaction burden, particularly for harder queries, as irrelevant memory increases.

3. **Failure-regime decomposition (p_wrong, p_exh)**:
 - **Definition**:
 - `p_wrong`: Probability of a wrong answer while staying within budget (`C(τ)=0` AND `R(τ) <= B`).
 - `p_exh`: Probability of exceeding the retrieval budget (`R(τ) > B`).
 - **Purpose**: Distinguishes between failures where the agent provides an incorrect answer despite limited interaction and failures where the agent exhausts its allowed interaction budget, providing insight into the root cause of reliability drops.

4. **Breakdown onset (s*α)**:
 - **Definition**: The number of added irrelevant sessions at the first evaluated scale `s_j` where `Pass@B(A, M, s_j)` falls below a fixed reliability threshold `α` (set to 0.7 for primary results).
 - **Purpose**: Provides a concise summary of how far a memory-scalability claim extends before usability significantly degrades under specified conditions.

#### 3.4. Experimental Setup

- **Models**: Qwen3-8B, Qwen3-32B, and Qwen3-235B were primarily evaluated. Additional diagnostics included LLaMA-3.1 variants and GPT-OSS models.
- **Memory Interfaces**: The protocol was applied to diverse interface families:
 - **Flat**: OpenClaw, MemOS-text.
 - **Planar**: Mem0, MemOS-Tree.
 - **Hierarchical**: HippoRAG, LiCoMemory.
- **Benchmarks**: LongMemEval and LoCoMo were used, sharing the same scale ladder (`s0` to `s4`, with `N_irr` from 0 to 400).
- **Scoring**: A GPT-4o-mini LLM-as-judge was used to score final answers, ensuring independence from retrieval-call counts.
- **Parity Conditions**: Crucially, all evaluated systems adhered to strict parity conditions: the same accessible history, retrieval-call budget (`B0=2` for primary results), and number of model-visible returned evidence units per retrieval step. This ensured that comparisons reflected interface differences under matched conditions. The budget counts agent-visible API calls and is applied post-hoc.

### 4. Main Findings and Results

The application of the scale-conditioned evaluation protocol yielded several findings regarding agent memory scalability.

#### 4.1. Usable Memory Scalability as a Joint Operating Property

The research demonstrates that usable memory scalability is not an intrinsic property of a memory system but a joint operating property dependent on the agent, memory interface, scale range, and interaction budget.
- **Impact of Irrelevant Sessions**: Even when task-relevant evidence is held constant, an increase in irrelevant sessions (from s0 to s4) significantly impacts budget-compliant reliability (Pass@B0). This indicates that the agent-facing problem changes, reflecting the burden of retrieving, selecting, verifying, and utilizing evidence within a larger accessible history.
- **Interface and Agent Dependence**:
 - **HippoRAG**: Across all Qwen3 models, HippoRAG experienced substantial reliability drops (16-20 percentage points in Pass@B0 from s0 to s4), pushing even the strongest model below the 70% threshold.
 - **LiCoMemory**: Performance varied significantly with the agent. Qwen3-8B with LiCoMemory showed low initial reliability (53.5%) and remained below the threshold. In contrast, Qwen3-32B and Qwen3-235B with LiCoMemory maintained high reliability (78.5% and 80.1% respectively at s4) across all tested scales, staying above the 70% threshold.
- These results highlight that a memory-scalability claim requires explicit specification of the agent, interface, scale range, and interaction budget.

#### 4.2. Different Failure Regimes Underpin Similar Reliability Drops

The decomposition of failures into budget-induced trajectories (`p_exh`) and wrong-within-budget answers (`p_wrong`) revealed distinct failure mechanisms depending on the memory interface.
- **Flat Interfaces (OpenClaw)**: These systems exhibited a high proportion of `p_wrong` failures (e.g., Qwen3-8B: 54.5% at s4), with `p_exh` near zero. This suggests that while simple access avoids long search loops, the returned context might be noisy, insufficient, or challenging to synthesize, leading the agent to produce incorrect answers within its budget.
- **Planar Interfaces (Mem0)**: These interfaces showed search-and-stopping instability. For Qwen3-8B, `p_wrong` was dominant (85.6% at s4), indicating incorrect stopping. For larger models like Qwen3-32B and Qwen3-235B, `p_exh` became the primary failure mode (83.6% and 79.2% respectively), suggesting the agent engaged in prolonged search-and-verification loops that exceeded the budget.
- **Hierarchical Interfaces**:
 - **HippoRAG**: Similar to flat retrieval, HippoRAG consistently showed `p_exh = 0`, with `p_wrong` rising significantly from s0 to s4 across all Qwen3 models (e.g., Qwen3-8B: 21.8% to 41.8%). This indicates within-budget failures, potentially due to increased competition for a fixed set of returned evidence units.
 - **LiCoMemory**: This interface exposed a multi-hop control burden. Qwen3-8B had a high `p_exh` (38.6% at s4), suggesting budget exhaustion. However, this `p_exh` rate decreased substantially with larger Qwen3 models.
- This decomposition demonstrates that reliability drops are not uniform but originate from different operational breakdowns, emphasizing the need for granular diagnostics.

#### 4.3. Larger Agents Improve Interface Control in Specific Cases

The study found that larger Qwen3 agents, when paired with the LiCoMemory interface, demonstrated improved budget compliance and reduced tail retrieval-call burden.
- **LiCoMemory Performance with Agent Scale**: With LiCoMemory at s4, the P90R (90th percentile of retrieval calls) decreased from 5 (Qwen3-8B) to 4 (Qwen3-32B) to 2 (Qwen3-235B). Concurrently, budget-induced trajectories (`p_exh`) fell from 38.6% to 15.7% to 2.0%, and Pass@B0 increased from 52.2% to 78.5% to 80.1%.
- **Improved Search and Stopping**: This improvement suggests that larger models are better at controlling the multi-hop interaction with LiCoMemory, making more efficient use of the retrieval budget and stopping when sufficient evidence is found.
- **Interface Dependency**: It was noted that this pattern is not universal, as stronger models could still exhaust the budget on certain planar or flat adapters. The magnitude of interaction burden also varied with the benchmark (e.g., smaller drops on LoCoMo).

#### 4.4. Breakdown Onset as a Usability Boundary

The `s*α` metric (breakdown onset) provides a compact, threshold-dependent summary of the usable-scale boundary.
- **Interface-Specific Onset**:
 - **HippoRAG**: Its `s*0.7` values (100 or 300 irrelevant sessions) were insensitive to budget relaxation (B0=2, B1=3, B2=5) because it operates as a single-pass system, with failures driven by `p_wrong`.
 - **LiCoMemory**: Qwen3-8B consistently failed at s0 (breakdown onset of 0 irrelevant sessions) even with relaxed budgets. However, Qwen3-32B and Qwen3-235B maintained `s*0.7 > 400` (no observed breakdown) across all tested budget settings, showing robustness to irrelevant memory growth.
- The breakdown onset, therefore, encapsulates the combined effects of Pass@B, P90R, and failure decomposition, providing an operational summary of a system's usability limits under specific conditions.

### 5. Significance and Potential Impact

The presented scale-conditioned evaluation protocol offers a more nuanced and rigorous approach to assessing agent memory systems, addressing key limitations of prior fixed-snapshot evaluations. Its significance and potential impact are multifaceted:

1. **Enhanced Understanding of Agent-Memory Dynamics**: By isolating the effect of increasing irrelevant memory while keeping task-relevant evidence fixed, the protocol provides clearer insights into how memory growth specifically burdens agents. This moves beyond simple capacity discussions to focus on the *usability* of stored information.

2. **Granular Failure Analysis**: The introduction of trajectory-level diagnostics, particularly the breakdown into budget-induced (`p_exh`) and wrong-within-budget (`p_wrong`) failures, allows researchers and developers to pinpoint the operational failure modes of an agent-memory system. This is crucial for targeted improvements, differentiating between issues in retrieval efficiency, stopping heuristics, or answer synthesis.

3. **Conditional Scalability Claims**: The research advocates for and demonstrates a framework where claims about memory scalability are explicitly conditional. Instead of vague statements, reports must specify the agent model, memory interface, tested scale range, evidence condition, and interaction budget. This increases transparency, comparability, and verifiability of research findings, moving the field towards more auditable claims.

4. **Informed System Design and Deployment**: Developers of LLM agents can use this protocol to:
 - **Select appropriate memory interfaces**: Understand which interfaces are robust to irrelevant information growth for a given agent and interaction budget.
 - **Optimize agent-memory interaction**: Identify whether an agent struggles with retrieving evidence efficiently (high `p_exh`) or with correctly utilizing the retrieved evidence (high `p_wrong`).
 - **Set realistic deployment expectations**: Determine the practical "usable scale boundary" (`s*α`) of a system before its reliability degrades below acceptable levels.

5. **Benchmarking and Comparison Standard**: The protocol establishes a standardized set of metrics and a systematic approach to evaluate memory systems, facilitating more meaningful comparisons between different architectures and agent models. It enables direct comparisons of `Pass@B`, `P90R`, and failure regimes across systems.

6. **Highlighting Agent Capabilities**: The finding that larger agent models can exhibit better control over multi-hop memory interfaces (e.g., LiCoMemory) indicates that agent reasoning capabilities play a significant role in effective memory utilization, not just the memory backend's efficiency. This suggests a co-design paradigm for agents and their memory systems.

**Limitations**: The paper acknowledges several limitations: the protocol focuses on inference-time usability under a retrieval-call budget, rather than total storage scalability, offline indexing costs, or hidden backend efficiency. It also does not cover advanced memory management aspects like stale, contradictory, privacy-sensitive, or adversarial memories. The budget is applied post-hoc for diagnostic purposes, not as a hard-stop deployment policy. Despite these, the methodology provides a valuable tool for understanding practical memory performance.

In conclusion, this work significantly refines the evaluation paradigm for LLM agent memory, offering a powerful diagnostic lens to understand when and why stored evidence ceases to be usable under real-world-like conditions of growing irrelevant context.
