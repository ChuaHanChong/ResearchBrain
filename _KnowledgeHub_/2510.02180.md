# GRACE: A Language Model Framework for Explainable Inverse Reinforcement Learning

> [!summary] Summary
> GRACE (Generating Rewards As CodE), developed at Apple and the University of Oxford, introduces an Inverse Reinforcement Learning framework that infers interpretable, executable Python reward functions directly from expert demonstrations. It achieved competitive policy learning performance on tasks in MuJoCo, BabyAI, and AndroidWorld, often matching ground-truth rewards and outperforming prior methods with an order of magnitude fewer demonstrations, while also fostering the creation of reusable code modules.

## Problem

- Manually designing reward functions for Reinforcement Learning (RL) is often labor-intensive, error-prone, and doesn't scale well to complex or multi-task environments.
- Existing Inverse Reinforcement Learning (IRL) methods, especially those using deep neural networks, often produce "black-box" reward models that lack interpretability and verifiability, hindering debugging and trust.
- Prior LLM-based approaches for generating rewards as code typically require explicit task descriptions, goal states, or ground-truth reward signals beyond just demonstrations.

## Method

- **GRACE** employs an ==evolutionary search== framework powered by Large Language Models (LLMs) to iteratively generate and refine reward functions represented as executable Python code.
- The system uses an AIRL-like discriminator loss as a fitness function to evaluate how well a candidate reward function differentiates expert from negative trajectories.
- LLMs serve as both initializers and mutation operators, generating new reward functions and intelligently debugging/refining existing ones by analyzing "wrong examples" and their associated reward values.

## Results

- GRACE consistently achieved a reward accuracy of 1.0 on BabyAI and AndroidControl tasks, and learned policies matched or outperformed GAIL with **200x** fewer expert trajectories (e.g., 10 for GRACE vs. 2000 for GAIL on MuJoCo).
- The framework demonstrated high sample efficiency, recovering perfect reward functions on BabyAI tasks with as few as eight expert demonstrations and non-trivial accuracy with just one.
- The evolutionary process fostered the emergence of reusable code modules and functions, forming a domain-specific library for multi-task scenarios, which improved generalization and efficiency.

## Takeaways

> [!tip] Key Insights
> - Leveraging LLMs within an evolutionary search paradigm can effectively synthesize high-quality, interpretable reward functions directly from demonstrations without requiring additional explicit task descriptions or ground-truth rewards.
> - Generating rewards as human-readable and executable code inherently provides interpretability and verifiability, addressing a core limitation of black-box deep IRL models.
> - The LLM's strong priors and reasoning capabilities enable superior sample efficiency, allowing accurate reward recovery and policy learning with significantly fewer expert demonstrations than traditional deep IRL methods.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

The field of Reinforcement Learning (RL) frequently relies on well-defined reward functions to guide agents towards desired behaviors. Traditionally, these reward functions are designed manually, a process that can be labor-intensive, prone to errors, and difficult to scale, particularly in complex multi-task environments. Inverse Reinforcement Learning (IRL) emerged as an alternative paradigm to automate reward specification by inferring a reward model from expert demonstrations.

Early IRL approaches focused on recovering reward functions that rendered the expert's policy optimal. With the advent of Deep RL, methods like Generative Adversarial Imitation Learning (GAIL) and Adversarial Inverse Reinforcement Learning (AIRL) represent reward functions using deep neural networks. While effective in many scenarios, these neural network-based reward models are often "black boxes," lacking interpretability and making debugging and verification challenging. Furthermore, these methods can require substantial amounts of data and may not always yield accurate or transferable rewards.

More recently, the concept of expressing reward models as executable code has gained traction, leveraging the program synthesis capabilities of Large Language Models (LLMs). This approach is motivated by the observation that reward functions, which often define task goals, can be simpler to articulate programmatically than the complex policies required to achieve them. Prior work in this area, such as EUREKA and Reward-As-Code, typically relies on explicit human-provided task descriptions, goal states, or access to ground-truth reward signals to generate or evaluate reward programs.

GRACE (Generating Rewards As CodE) positions itself within this landscape by addressing a specific gap: the recovery of interpretable, code-based reward functions *purely* from expert demonstrations in an IRL-style setting, without the need for explicit task descriptions, domain-specific design assumptions, or ground-truth reward signals. It integrates LLMs into an evolutionary search framework, effectively revisiting the IRL paradigm by combining program synthesis with gradient-free optimization, aiming to produce transparent and verifiable reward models. This contrasts with both traditional black-box IRL methods and existing code-as-reward approaches that require additional supervisory signals beyond demonstrations.

### 2. Key Objectives and Motivation

The primary objective of this research is to develop an efficient framework that can infer interpretable reward functions, represented as executable code, directly from expert demonstrations using Large Language Models (LLMs). This overarching goal is driven by several motivations:

1. **Addressing Limitations of Manual Reward Design:** Manual crafting of reward functions is often impractical, especially in complex, real-world scenarios or contemporary multi-task RL settings. It is prone to human error and does not scale well to diverse problem domains. Automating this process is a key motivation.

2. **Enhancing Interpretability and Verifiability of Reward Models:** Traditional Deep IRL methods, while capable of learning complex reward functions, typically produce opaque "black-box" models (e.g., deep neural networks). These models are difficult to interpret, understand *why* they assign certain rewards, or verify their correctness and safety. The researchers are motivated to move beyond these black-box representations by generating rewards as human-readable and executable code, which intrinsically offers transparency, inspectability, and verifiability. This is critical for building trust in learned reward systems and for debugging agent behavior.

3. **Improving Sample Efficiency in Reward Learning:** Many deep IRL methods require substantial amounts of expert demonstration data to learn effective reward functions, which can be costly or difficult to acquire in real-world applications. A key motivation for GRACE is to demonstrate that LLMs, with their strong priors and reasoning capabilities, can be leveraged to recover accurate and generalizable rewards from a relatively small number of expert demonstrations, thereby improving sample efficiency.

4. **Enabling Generalization and Modularity in Multi-Task Settings:** In multi-task RL, it is desirable for reward functions to be generalizable and to potentially leverage shared components across tasks. The use of code as a reward representation is motivated by its potential to foster the emergence of modular and reusable functions, which can form a domain-specific library, thereby enhancing generalization and facilitating efficient reward design for complex, related tasks.

5. **Closing the Gap in Code-Based Reward Generation:** While prior work has explored generating rewards as code, these approaches often depend on explicit task descriptions, goal states, or ground-truth reward signals. The authors are motivated to investigate whether it is possible to recover such code-based reward functions *purely* from observed expert behavior, in a manner analogous to classical IRL, but without these additional forms of supervision.

In summary, GRACE aims to deliver a framework for sample-efficient, interpretable, and modular reward function recovery from demonstrations, thereby addressing critical challenges in the specification and understanding of reward signals in Reinforcement Learning.

### 3. Methodology and Approach

GRACE (Generating Rewards As CodE) is an interpretable Inverse Reinforcement Learning (IRL) framework that generates reward functions as executable Python code. The methodology is structured around an iterative optimization procedure inspired by evolutionary search, which leverages Large Language Models (LLMs) to generate and refine reward programs. The process is divided into three main phases: Initialization, Reward Refinement through Evolutionary Search, and Active Data Collection via Reinforcement Learning.

**Phase 1: Initialisation**
The process begins by collecting two sets of trajectories: expert demonstrations ($D^+$) and random trajectories ($D^-$). $D^+$ is sourced from an expert policy or human demonstrations, while $D^-$ is generated by a random policy.
1. **LLM Prompting:** An LLM is prompted with a random subset of $D^+$ and, optionally, supplementary environment information (e.g., Python code or tool signatures).
2. **Initial Reward Generation:** The LLM generates an initial set of Python-based reward functions ($R_{init}$). Each function `r` in $R_{init}$ is designed to assign high reward values to expert states ($S_e$) and low values to negative states ($S_n$). This set of functions constitutes the initial population for the evolutionary search.
3. **Optional Data Cleaning:** The LLM can optionally analyze states within $D^+$ to identify a precise subset of expert states ($S_e$) that truly solve the task (positive samples). All other states from $D^+$ not identified as goal states, combined with states from $D^-$, form the set of negative samples ($S_n$).

**Phase 2: Reward Refinement through Evolutionary Search**
This phase iteratively improves the reward functions within the population ($R$) by applying an evolutionary search strategy.
1. **Fitness Function:** The quality of each reward function `r` is evaluated using a fitness function `f(r)`. This function measures how effectively `r` differentiates expert states from negative states, adopting an AIRL-like discriminator loss. Specifically, $f(r) = E_{s \sim S_e}[\log D_r(s)] + E_{s \sim S_n}[\log(1 - D_r(s))]$, where $D_r(s) = \frac{\exp(r(s))}{\exp(r(s)) + \pi(a|s)}$ is a discriminator parameterized by `r`.
2. **Mutation Operator:** An LLM acts as the mutation operator `m`. It generates a mutated reward function `r'` by taking the current reward's source code (`source(r)`) as input. Crucially, the LLM is also provided with "context" to guide targeted debugging and improvement. This context includes:
 - The Python source code of the "parent" reward function `r`.
 - A random sample of "wrong examples" ($s_w$)—states with low fitness under the current reward `r`.
 - The reward values `r(s_w)` produced by the current function for these low-fitness states.
 - (Optional) Additional environment information, such as source code or a text description.
 - (Optional) Debug information provided by a `debug(s, D+, D-)` function defined by the LLM, allowing it to print intermediate variables or aggregate information.
3. **Population Evolution:** In each iteration, a set of parent rewards is sampled from `R` based on a softmax distribution of their fitness scores. The mutation operator generates new candidate rewards from these parents. To maintain a high-quality population, the top `P` performing functions (based on their fitness scores) are retained from the combined set of current and newly mutated rewards. This process is repeated for `K` iterations, ultimately returning the reward function with the highest fitness, $r^*$.

**Phase 3: Active Data Collection via Reinforcement Learning**
This phase aims to further improve the learned reward function by actively exploring the environment and generating new data.
1. **Policy Training:** A policy $\pi_{r^*}$ is trained using a standard RL algorithm (e.g., PPO) with the current optimal reward $r^*$ obtained from Phase 2. This training is conducted under a predefined environment interaction budget ($N$) rather than to convergence.
2. **Data Expansion:** New trajectories ($D_{r^*}$) generated by the trained policy are collected.
3. **Dataset Augmentation:** These new trajectories are added to the existing dataset of negative trajectories ($D^-$). This expanded dataset is then used in subsequent iterations of Phase 1 and 2, allowing the reward function to be refined with exposure to new edge cases or failure modes discovered by the learning agent. This loop continues for `M` data augmentation steps.

**Additional Reward Shaping (Optional)**
If the reward function's offline performance on $D$ does not translate to effective online RL performance, indicating poor reward shaping, an additional refinement step can be triggered. In this scenario, the LLM's context for mutation (Eq. 4.2) is augmented to include full expert trajectories and the current reward value for each state. The LLM is then explicitly instructed to reshape the reward function, using expert trajectories as a reference, to provide a monotonically increasing signal that better guides the agent.

### 4. Main Findings and Results

The research empirically evaluated GRACE across three distinct domains: BabyAI (procedurally generated maze environments), MuJoCo (continuous control physics simulations), and AndroidWorld (a real-world UI simulator). The evaluation focused on reward accuracy, policy learning performance, qualitative properties of the rewards, and their interpretability and multi-task efficacy. GRACE was not provided with any in-context environment descriptions or source code for fair comparison with baselines.

#### 4.1. Accuracy and Generalization of Recovered Rewards

GRACE demonstrated consistent success in recovering underlying task rewards from demonstrations.
- **High Accuracy:** The evolutionary search (Phase 2) achieved a reward accuracy of 1.0 across all tested BabyAI tasks (single-level and multi-level settings) and on AndroidControl. An accuracy of 1.0 indicates that the learned reward function assigns higher values to all expert states than to all negative states.
- **Sample Efficiency:** Experiments on BabyAI indicated robust performance even with limited data. Non-trivial accuracy was achieved with a single expert demonstration, and perfect scores were attained with only eight expert trajectories. The number of negative trajectories also contributed to accuracy, though to a lesser extent, with 0.95 accuracy possible with just one negative trajectory given sufficient expert examples.
- **Efficient Convergence:** In multi-task settings for BabyAI and AndroidControl, GRACE reliably converged to high-fitness reward functions in fewer than 100 generations (evolutionary search steps), and without the need for online data augmentation (M=1).

#### 4.2. Policy Learning Performance

GRACE's recovered reward functions were used to train RL policies (via PPO) and compared against PPO with ground-truth sparse rewards (oracle) and Generative Adversarial Imitation Learning (GAIL).
- **MuJoCo Performance:** Across four continuous control tasks (Hopper, Walker, Ant, Humanoid), GRACE consistently matched or outperformed GAIL, which was provided with a significantly larger dataset (2000 trajectories for GAIL vs. 10 trajectories for GRACE). GRACE's performance, using both GPT-4o and Qwen3-Coder-30B for LLM calls, often approximated that of PPO trained with ground-truth rewards (Table 1). While generally strong, the method encountered challenges with the high-dimensional Humanoid environment, hypothesized to be due to LLM difficulties in parsing extensive numerical arrays.
- **BabyAI Performance:** GRACE matched or exceeded the success rates of GAIL on numerous BabyAI tasks, despite GAIL being trained with 2000 expert trajectories per task compared to GRACE's 8. In several instances, GAIL exhibited complete failure, whereas GRACE achieved success rates comparable to or matching Oracle PPO with ground-truth rewards (Table 2, 3).
- **AndroidWorld Performance:** For AndroidWorld Clock tasks, GRACE-learned rewards enabled successful policy learning, with training curves demonstrating mean episode success comparable to ground truth rewards (Figure 3).

#### 4.3. Well-Shaped Rewards

GRACE demonstrated the capacity to produce well-shaped rewards that enhance learning efficiency. For tasks such as "OpenTwoDoors" in BabyAI, initial rewards might be correct but unshaped, leading to local optima and agent stagnation. Through targeted shaping in Phase 3, where the LLM is explicitly tasked to introduce shaping terms, GRACE refined the reward to provide a denser learning signal. This process significantly improved both the final performance and the speed of learning, allowing the agent to solve the task more efficiently (Figure 6).

#### 4.4. Interpretability and Multi-Task Efficacy (Code Reuse)

- **Interpretability:** A core finding is that GRACE generates rewards as executable Python code, making them inherently interpretable and verifiable, unlike opaque neural network models.
- **Modularity and Reuse:** In the multi-task BabyAI setting, the evolutionary search process naturally fostered the emergence of reusable functions and modules, forming a domain-specific reward library (Figure 5). Early generations showed a higher rate of new module creation, which sharply declined after approximately 10 generations as GRACE began to prioritize reusing existing, effective high-level modules. Examples such as the "Goal" module and "agent_pos" function demonstrated repeated invocation and reuse across different reward definitions, indicating efficient multi-task generalization.

### 5. Significance and Potential Impact

The GRACE framework presents several significant contributions to the fields of Inverse Reinforcement Learning and general Reinforcement Learning, with potential impacts across research and practical applications.

1. **Enhanced Interpretability and Verifiability:** A primary challenge in modern RL is the black-box nature of many learned components, including reward functions. By generating rewards as executable Python code, GRACE fundamentally addresses this issue. The resulting reward functions are transparent, inspectable, and verifiable, which is crucial for building trust, debugging agent failures, and ensuring safety in real-world deployments where understanding the underlying motivation for agent behavior is paramount. This interpretability can facilitate human oversight and collaboration with AI systems.

2. **Superior Sample Efficiency:** GRACE demonstrates the ability to recover accurate and generalizable reward models from a remarkably small number of expert demonstrations (e.g., eight trajectories for BabyAI tasks). This significantly contrasts with traditional deep IRL methods like GAIL, which often require thousands of demonstrations. This sample efficiency is a substantial advantage in data-scarce domains or scenarios where collecting extensive expert data is costly or impractical. The strong priors and reasoning capabilities of LLMs are posited as the source of this efficiency.

3. **Practical Applicability Across Diverse Domains:** The empirical validation across continuous control (MuJoCo), procedural reasoning (BabyAI), and real-world device control (AndroidWorld) underscores GRACE's versatility and practical utility. Its successful application to tasks like controlling an Android device directly from user interaction data indicates its potential for developing autonomous agents in complex, high-dimensional human-computer interaction environments.

4. **Promotion of Modularity and Generalization:** The evolutionary search process encourages the emergence of reusable code modules, effectively building a domain-specific library of reward components. This modularity can facilitate more efficient reward design for multi-task learning by allowing agents to generalize concepts across related tasks and reduces redundant code generation, potentially leading to more robust and scalable reward systems.

5. **Advancement of Program Synthesis for RL:** GRACE demonstrates a novel and effective integration of LLMs with evolutionary search for symbolic program synthesis in the context of reward function generation. This approach pushes the boundaries of how LLMs can be used beyond simple code generation to tackle complex optimization problems in AI.

**Limitations and Future Directions:**
The paper acknowledges a key limitation: GRACE's current scalability to very high-dimensional state spaces (e.g., raw pixel inputs) remains challenging for evolving symbolic reward functions. While code offers interpretability, neural networks are inherently better suited for learning distributed representations from such raw sensory data.

Future work could address this by exploring hybrid approaches. This includes equipping LLMs with "tool use" capabilities, allowing them to integrate pre-trained computer vision models (e.g., object detectors) for processing high-dimensional inputs, and then reasoning over their symbolic outputs. Another direction involves generating hybrid reward functions that combine coded logic with small, learnable neural network modules for specific, perception-dependent components. These extensions could mitigate the limitations of purely programmatic solutions while preserving interpretability and sample efficiency.
