# Where Memory Belongs: Ledger, an Object Ledger for Memory-Augmented VLAs

> [!summary] Summary
> LEDGER is a memory harness for a single fine-tuned pi0.5 policy that splits memory by type: short-term perceptual memory (frame-sampling feature modulation) stays inside the policy, while long-term object memory lives outside as a ledger built from SAM3 tracks, VLM demonstration transcripts, and an LLM planner deciding at step boundaries. On RoboMME it averages 64.3% versus 45.9% for the strongest prior method.

## Problem

- In-policy VLA memories each excel on one RoboMME suite and collapse on others; the best reaches only 44.5% average against an 84.1% oracle given grounded subgoals.
- Object maps and scene graphs store present-tense snapshots only, recording neither where an object rested earlier nor what came to cover it, so container swaps go untracked.
- Memory selection is decided before execution, for example by DIRECT's router trained on per-task success labels, rather than at runtime from the instruction and the accumulated record.

## Method

- **Ledger** ==object ledger==: SAM3 tracks per-object ==stationary intervals== and cover timestamps via an LLM occlusion query, plus a Qwen3-VL demonstration transcript; all spatial queries reduce to one ==co-location primitive==.
- ==Frame-sampling feature modulation==: 32 uniformly sampled past frames are pooled and cross-attended by each pi0.5 ==action-expert== layer to produce near-zero-initialized ==scale and shift modulation== parameters.
- ==Task-conditional subgoal dropout== (0.9 on temporal/procedural, 0.15 on spatial/object suites) plus an ==LLM planner== at proprioception-confirmed step boundaries that grounds a coordinate subgoal or emits an empty one to defer.

## Results

- RoboMME **16**-task average of **64.3% plus or minus 0.9**, versus **45.9%** for FrameSamp+Modul and **43.3%** for MemER under identical **three**-seed evaluation, using one set of weights.
- Leads Permanence (**86.7%** vs **56.2%**) and Reference (**60.7%** vs **40.3%**); trails FrameSamp by **2 points** on Counting and **8** on Imitation, mostly from MoveCube (**60.7%** vs **76.0%**).
- Re-deciding after each step lifts UnmaskSwap from **68%** to **92%** but drops Repick from **60%** to **28%** until the remaining plan is carried across decisions, restoring it to **54%**.

## Takeaways

> [!tip] Key Insights
> - Memory type should dictate placement: repetition, timing, and motion work best as in-policy features, while persistent object state and event history belong in an explicit, readable external record.
> - Without subgoal dropout, step-by-step text subgoals become a training shortcut, so the policy never builds the perceptual memory it needs once subgoals are withheld.
> - Replanning at stable, proprioception-confirmed step boundaries beats once-per-episode planning, but stateless re-deciding miscounts repetitions; the planner needs its own decision history carried forward.

## Detailed Report

### 1. Overview

A robot is told to watch a video, then pick up the container hiding the green cube. The current image shows containers, not the hidden cube. The relevant clue lies in past events.

Ledger gives the robot two complementary kinds of memory. Recent visual and motion history stays inside one action policy. Persistent object locations and past events go into a readable record outside it. At step boundaries, a planner uses the instruction and that record to choose one of two outputs. It can give the policy a grounded target, or it can leave the subgoal empty so the policy acts from its own memory. On the RoboMME benchmark, mean success across 16 tasks is 64.3% for Ledger versus 45.9% for FrameSamp, the strongest prior method in the authors' reproduced comparison.

Paper Figure 1, a conceptual system diagram. The upper "Long-Term Object Ledger" path feeds observations to a SAM3 tracker and video-VLM narration, producing an object record. The lower "Short-Term Perceptual Memory" path sends frames through a frame-sampling π0.5 policy to the robot. At a step boundary, the planner sends either a coordinate subgoal or an empty one. The example record and coordinate are illustrative, not a benchmark result.

### 2. Two kinds of memory, one decision loop

Short-term perceptual memory preserves what the robot recently saw and did, such as repetition counts, timing, or a demonstrated movement pattern. Long-term object memory preserves persistent world state and event history, such as where an object rested or what covered it. In the authors' view, rich visual and motion traces suit an in-policy representation. Persistent object facts benefit from an explicit record that can be read and reasoned over.

The record works as follows. SAM3 tracks objects through any demonstration and the live rollout. The record stores object descriptions, current image coordinates, stationary intervals, and timestamps for cover events. If tracking is interrupted, a planner query distinguishes occlusion by the robot arm from a cover. When a demonstration exists, a video VLM supplies an ordered action transcript. The transcript conveys events and order, but it can confuse destinations among visually identical objects. For that reason, spatial targets are resolved from tracked intervals and co-location rather than from transcript text alone.

The low-level policy uses 32 uniformly sampled past observations as in-policy memory. At the start, and after each completed step, an LLM planner reads the instruction, ledger, annotated frame, transcript, and execution log. It then issues a grounded coordinate subgoal or an empty subgoal that defers to policy memory.

### 3. What the results show

Ledger's 64.3% is task success averaged across the 16 tasks. Each task was evaluated on 50 episodes and three seeds, using final checkpoints, under the authors' stated common evaluation protocol. Ledger leads the evaluated methods overall. FrameSamp remains stronger on some temporal or imitation tasks.

The sharpest comparison is with Tracker, which uses SAM3 tracks but lacks historical event records. On RoboMME's Reference suite, Ledger scores 60.7%, versus 32.7% for Tracker and 37.3% for in-policy FrameSamp. The oracle-grounded reference reaches 95.2%. This result is consistent with the value of event history for identifying which object to act on. It compares complete methods, however, rather than isolating a single component.

Paper Table 1. Rows are methods, and columns group 16 task success rates (%) into Counting, Permanence, Reference, and Imitation, followed by the 16-task average. The upper block shows results reported by RoboMME. The lower block shows the authors' reproduced methods under one protocol. Human and oracle rows are references, not deployable methods.

Re-deciding at step boundaries also mattered. On UnmaskSwap, success rises from 68% with a single plan made at episode start to 92% when the planner re-decides at step boundaries while carrying the plan. This ablation uses one seed and 50 episodes per cell, and a cell's binomial standard error can be as high as 7 points.

### 4. Closing

Ledger's contribution is a division of labor. Motion history stays where the policy can use it, and object history goes where a planner can inspect it. The evaluation is in simulation with 2D image-coordinate targets. Transcripts can still fail on event semantics: on VideoPlaceOrder, Ledger scores 64.0% against 100% with oracle grounding.
