# MaskHarness-WAM: Instance-Grounded Harnessing for Long-Horizon Robot Manipulation

> [!summary] Summary
> MaskHarness-WAM wraps a mask-conditioned world action model in a task-level closed-loop harness for long-horizon sequential manipulation of visually identical objects. A planner decomposes instructions into ordered instance-specific subtasks, SAM3 generates target masks, and VLM entry/exit gates verify each mask and confirm completion before switching targets. On a real dual-arm robot it reaches 84-96% success, far above π0, Fast-WAM and MaskWAM.

## Problem

- Limited-horizon VLA and WAM policies like π0 and Fast-WAM lack explicit instance identity, so category-level language cannot pick the correct target among visually identical objects.
- Completing a local motion does not signal a valid stage transition; without task-state tracking, wrong progress estimates propagate and cause cascading failures across subsequent subtasks.
- Visual-prompting methods such as MaskWAM supply a single static mask at episode start, which becomes stale once an instance is completed and the next target changes.

## Method

- **Mask-conditioned WAM policy**: head-view target mask and RGB share one ==VAE== with ==channel-concatenated latents==, trained on joint future-RGB, future-mask and action losses; inference needs only one initial mask.
- **Instance-grounded harness**: a planner decomposes instructions into ordered subtasks with spatially specified targets, while memory tracks initial state, current target ID, verified mask and completed-instance set.
- **Dual VLM gates** with recovery: a ==Qwen3.5== entry gate verifies ==SAM3== mask overlays, an exit gate compares against the subtask-start frame; rejected masks trigger re-segmentation, unconfirmed completion holds the current subtask.

## Results

- Trained only on 4-instance demos, SR reaches **88/84/84%** on cubes and **96/88/88%** on test tubes across 3/4/5 instances; lowest PR **91.2%**.
- Baselines collapse: on 5-instance cubes π0, Fast-WAM and MaskWAM reach **0%**, **0%** and **4%** SR; on 4-instance tubes all are at most **20%**.
- OOD SR **91.7/91.7/83.3%** vs MaskWAM **66.7/41.7/58.3%** across appearance, scene-composition and geometry shifts; zero-shot unseen bread reaches **68.0%** SR versus MaskWAM **16.7%**.

## Takeaways

> [!tip] Key Insights
> - Separating which-instance and when-to-advance decisions from the motor policy lets one unchanged finite-horizon policy generalize to unseen orders, task lengths and categories without retraining.
> - Masks work best as a dynamic interface refreshed at every subtask boundary, not a one-shot prompt; mask grounding alone (MaskWAM) still fails long-horizon transfer without state management.
> - A high progress-rate but low success-rate pattern indicates intact local skill but broken target selection or sequencing, pointing fixes at the orchestration layer, not the policy.

## Detailed Report

### 1. Overview

Some robot tasks require placing identical-looking objects in a set order. Long-horizon manipulation is not just a chain of successful grasps. When identical-looking objects must be handled in a specified order, the robot must keep track of which instance is next and verify that it has actually finished each step. Take one task: place four test tubes into a box in the requested order, 4–2–3–1. A local manipulation policy can move an object without knowing which tube should come next or whether the task is ready to advance.

The authors' fix works as a loop. Before acting on each next tube, the system looks again, marks the intended tube, and checks that the mark is right. It checks the result before moving on. The system, MaskHarness-WAM, adds an external harness that updates a target mask for each subtask, checks the mask before execution, and advances only after visual confirmation of completion. The paper's real-robot sequence shows the tubes being placed in that order. It is an illustrative execution, not a guarantee that every run succeeds.

Representative real-robot executions. The top row shows four blue blocks placed in left-to-right index order 2–1–3–4. The bottom row shows four test tubes placed into a box in order 4–2–3–1. The frames illustrate target switching and task progression, not a measured success rate.

### 2. The target mask changes between subtasks

A planner turns the language instruction into ordered, target-specific subtasks. Memory records the current subtask and target, completed instances, and a visual reference from the start of that subtask. At a subtask boundary, the system re-observes the scene and generates a target mask with SAM3. A vision-language model (Qwen3.5) checks an overlay of that mask on the global head-camera view. Only a verified mask is sent to the low-level policy. If the mask is rejected, the harness keeps the same task state, observes again, and regenerates and rechecks the mask. The policy receives multi-view RGB, robot state, the local instruction, and the verified mask, and it generates a finite-horizon action chunk.

After execution, a second visual check compares the new observation with the subtask's initial reference. If completion is not confirmed, the system stays on that subtask. It switches targets only after completion is confirmed.

The policy uses one verified initial mask per invocation. It does not generate future masks at inference or perform per-frame segmentation. Instance switching is handled entirely by the harness.

Framework of MaskHarness-WAM. The upper portion shows task planning and memory across instance-specific subtasks. Segmentation and mask verification happen before policy execution, and failed masks trigger re-observation and re-segmentation. The lower portion separates joint RGB–mask–action training from action-only inference conditioned on the initial observation and target mask.

### 3. Testing complete ordered execution

The closest prior work, [[2606.13515|MaskWAM]], already uses a first-frame target mask as a visual anchor. The authors position their contribution as verifying, maintaining, and updating visual conditions throughout long-horizon execution.

The main tests ran on a real ARX dual-arm, 7-DoF robot, with 25 trials per setting. Training demonstrations use four instances, and some execution orders are reserved for evaluation. Two metrics score the runs:

- **Success rate (SR)** counts only trials completing every subtask in order.
- **Progress rate (PR)** averages the fraction of the longest correct subtask prefix. Out-of-order steps and anything after the first mistake do not count.

In the four-instance test-tube condition, MaskHarness-WAM achieves **88.0% SR and 94.0% PR**, versus MaskWAM's **8.0% and 42.0%**. Four instances match the training scale, but the evaluated orders are held out. MaskHarness-WAM leads on SR and PR across all six main settings, with at least 84.0% SR and 91.2% PR.

Sequential manipulation results (%) for π⁰, Fast-WAM, MaskWAM, and MaskHarness-WAM on Cubes and Test Tubes at 3, 4, and 5 instances. With four test tubes, MaskHarness-WAM reaches 88.0 SR / 94.0 PR, versus MaskWAM's 8.0 / 42.0. MaskHarness-WAM leads on both metrics in all six task/count settings.

The authors attribute baseline failures to target selection and task progression. This comparison alone does not isolate which harness component accounts for the gains. MaskWAM was reimplemented from its paper, and there is no ablation of the mask refresh, completion gate, or memory.

### 4. What the result shows

The mask-and-feedback loop is the authors' proposed way to extend finite-horizon skills to ordered execution without modifying the underlying policy. The evidence comes from real-robot block and test-tube tasks in finite evaluation settings. It does not show general-purpose reliability.
