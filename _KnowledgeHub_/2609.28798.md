# OCC4M: Object-Centric 4D Memory for Spatiotemporal Reasoning in Long-Horizon Manipulation

> [!summary] Summary
> OCC4M builds an object-centric 4D memory for long-horizon manipulation: learned detection writes world-frame object tracks, deterministic association adds temporal, motion and containment relations, and a VLM reads the JSON serialization once to pick targets for a frozen history-free low-level executor. Across seven simulation conditions it reaches 96.6% memory and 88.9% end-to-end success versus 54.6% and 57.7% for a full-history VLM baseline.

## Problem

- History-aware policies encode past observations inside learned weights, so remembered targets stay implicit and cannot be re-expressed as metric coordinates after the robot's viewpoint moves.
- VLMs reasoning over sampled frames recover which event happened but not a persistent metric reference frame; extra frames alone do not specify where to act.
- Keyframe-retrieval and scene-graph memories supply spatial state or relevant frames, yet leave unaddressed how historical references bind to actionable geometry for a history-free low-level controller.

## Method

- Perception-to-world-frame pipeline: ==SAM 3== noun-phrase detections intersect calibrated camera rays with a known support plane, storing each object as a world point that stays fixed under ego-motion and reprojects into the current view.
- Persistent object tracks via per-class ==Hungarian assignment== on planar distance gated at 12 cm around a constant-velocity prediction, with deterministic rules recording appearance order, motion onset with pre-motion pose, and containment edges.
- Memory-to-action interface: one **Gemini 2.5 Flash** call reads a JSON serialization of the graph and returns a skill sequence, whose targets a frozen **pi-0.5** LoRA executor grounds from rendered cues re-bound to live tracks.

## Results

- Over 350 episodes in seven conditions, OCC4M hits **96.6%** memory and **88.9%** end-to-end success against **54.6%** and **57.7%** for FrameSamp with the full 32-frame history and the same executor.
- Viewpoint control isolates the gap: with the base translated 0.30 m, FrameSamp drops to **6%** (median error 28.8 cm, matching the displacement) while OCC4M holds **100%** memory, **98%** end-to-end.
- On 20 real Franka episodes OCC4M gets **85%** joint memory versus **20-30%** for FrameSamp, **45%** two-stage end-to-end; oracle actions add **8.3 points** in sim, oracle memory only **4.3**.

## Takeaways

> [!tip] Key Insights
> - Storing state in explicit world coordinates, not frames, is what survives ego-motion; adding observation frames never supplies the reference frame a moved camera needs.
> - Split timescales: decide which object once at the task level, let perception keep updating where it is, so disturbances need no replanning call.
> - Once memory is near-perfect, low-level skill reliability dominates; compounding per-object success across multi-step episodes caps completion, so measure memory and execution separately.

## Detailed Report

### 1. Overview

A robot watches a green cube disappear. Its base then moves, and it must place a red cube where the green cube stood. The target is no longer visible, and remembering an old image location does not by itself say where that location is in a new view. OCC4M keeps the old place tied to the world, so the robot can project it into its new view. It preserves the robot's history as persistent object identities, places, and relations, not just a sequence of pictures. The authors frame the contribution as an action interface between perception, task reasoning, and history-free manipulation, rather than a new detector, mapper, or low-level policy. In a controlled simulation test with a 0.30 m base translation, OCC4M records 100% memory success and 98% end-to-end success. The FrameSamp baseline records 6% on both.

The robot must place a red cube where a green cube stood after the green cube disappears and the base moves. Watch the remembered location be grounded from the new viewpoint.

### 2. Keep the place, update the view

For each observation, SAM 3 detections and camera calibration place detected objects in a shared world frame. They do this by intersecting camera rays with a known support plane at the object's height. Persistent instance tracks retain identities even when several objects share a semantic class.

The memory records:

- first and last observation times
- visibility
- positions
- motion events, including pre-motion and current poses
- directed containment relations

A vanished object beneath a nearby cover can be linked to the cover. The cover's pose then supplies an inferred location until the object reappears.

For the moved-base task, the key distinction is simple. The stored historical place does not move when the robot moves, but its projection into the current camera does.

At query time, one VLM call reads a JSON serialization of the memory. It selects identities and coordinates already in memory and returns an ordered skill sequence. During execution, a classical controller handles base navigation. The frozen low-level skill policy receives current images, joint state, a skill word, and a rendered target cue. It does not receive the instruction, the memory, or past frames. A selected object target can follow its live track without another VLM call, while a historical-place target remains fixed. The system assumes known support geometry.

Perception and geometry feed an object-centric 4D memory. Memory-based target selection makes one skill-sequence prediction, and current-view grounding drives frozen VLA skills and classical base control. A historical place stays fixed, while a selected object's live location can update without a new VLM call.

### 3. When history meets a new viewpoint

"Memory success" is correctness of the complete pre-execution perception–memory–VLM decision. "End-to-end success" uses each task's native completion criterion.

Three conditions separate retrieving an old observation from transferring it into a changed view:

- **T1** allows historical-frame grounding.
- **T1b** requires the current frame but keeps the viewpoint fixed.
- **T1c** adds a 0.30 m base translation while keeping the current-frame requirement.

FrameSamp, which uses Gemini 3.7 Flash on sampled raw frames, scores 100% memory success on T1 and T1b. On T1c, FrameSamp falls to 6% memory and end-to-end success, while OCC4M scores 100% and 98%. Both frame budgets cover the full history in these conditions. So the current-frame constraint alone does not cause the FrameSamp memory failure; the combined viewpoint change and constraint does.

The authors report median target error of 1.2 cm for OCC4M and 28.8 cm for FrameSamp, near the imposed 30 cm displacement. They interpret this pattern as consistent with reusing a stale image location. The comparison supports their view that historical recall and actionable viewpoint transfer are distinct demands. It does not prove that all raw-history systems must fail this way.

Memory / end-to-end success (%). T1: FrameSamp 100/96, OCC4M 100/94. T1b: 100/92 vs 100/94. T1c: 6/6 vs 100/98. FrameSamp is Gemini 3.7 Flash with K=16, sufficient for the full histories in these tests.

Across seven simulation conditions, with 50 episodes each, OCC4M's mean is 96.6% memory success and 88.9% end-to-end success. Full-history FrameSamp (K=32) reaches 54.6% and 57.7%. The rows share a frozen executor but not the VLM backbone or input representation: OCC4M uses Gemini 2.5 Flash on structured memory. The results therefore favor the evaluated OCC4M system over this baseline. They do not isolate memory structure as the sole cause of the gap.

### 4. Boundary

OCC4M's contribution is a persistent representation that keeps "which object or old place?" separate from "where is the selected object now?" The viewpoint-transfer test is in simulation.

On 20 fixed-camera Franka histories, OCC4M has 85% joint memory accuracy, versus at most 30% for FrameSamp. The fixed camera means that experiment does not test world-frame viewpoint invariance.
