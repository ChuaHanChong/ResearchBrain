# SWE-agent: Agent-Computer Interfaces Enable Automated Software Engineering

> [!summary] Summary
> SWE-agent pairs a language model with a custom agent-computer interface (ACI) for software engineering. The ACI gives simple search, file-viewer and line-range edit commands, with linter guardrails and concise feedback. With no change to model weights, GPT-4 Turbo resolves 12.5% of SWE-bench and 87.7% of HumanEvalFix, far above earlier non-interactive baselines.

## Problem

- Language model agents using a raw Linux shell struggle to edit file segments reliably. The shell gives no feedback on invalid edits, which hurts performance on complex programming tasks.
- Existing interfaces such as shells and IDEs were built for human users. They overwhelm models with verbose output, and models cannot ignore distracting context the way humans can.
- Prior work on code agents treated tool use, prompting and execution feedback separately. It did not study how interface design shapes agent behavior on real-world software engineering tasks.

## Method

- ==Agent-computer interface==: a small set of simple, compact commands (find_file, search_file, search_dir, open, scroll, goto, edit) replaces the granular shell action space, so each step makes meaningful progress.
- Edit command with integrated ==linter guardrails==: the agent replaces a line range in one step, the viewer refreshes automatically, and syntactically invalid edits are discarded so the agent retries.
- ==Context management==: a 100-line ==file viewer== window, search results capped at 50 with a prompt to refine, and observations older than the last five collapsed to one line each.

## Results

- SWE-agent with GPT-4 Turbo resolves **12.47%** of the full SWE-bench (previous best **3.8%** from a retrieval baseline) and **18.00%** of SWE-bench Lite. Claude 3 Opus reaches **10.46%**.
- The LM-friendly ACI gives a **64%** relative gain over the Shell-only agent (**11.0%** on Lite). On HumanEvalFix, SWE-agent reaches **87.7%** Python pass@1 against **47.0%** for GPT-4.
- Ablations on Lite: removing linting drops **18.0%** to **15.0%**, and having no edit command drops it to **10.3%**. Iterative search gives **12.0%**, worse than no search at **15.7%**. Full-file viewing gives **12.7%**.

## Takeaways

> [!tip] Key Insights
> - Interface design is a lever on par with model choice. Tailoring actions and feedback to language model strengths and weaknesses lifts performance without training or changing weights.
> - Compact, consolidated actions and concise feedback beat granular or exhaustive ones. Agents given many results tend to inspect every one, exhausting budget and context.
> - Guardrails such as an edit-time linter cut error propagation and speed recovery. Human-oriented interfaces do not automatically transfer to agents, so interface principles should be tested per model.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

The work presented in "SWE-agent" sits at the intersection of several rapidly evolving fields: **large language models (LLMs)**, **AI agents**, and **automated software engineering (ASE)**.

Historically, LLMs have demonstrated remarkable capabilities in code generation, often evaluated on self-contained problems like HumanEval. However, the real-world complexity of software engineering, which involves navigating large codebases, understanding contextual issues, and iteratively debugging, goes far beyond simple code snippets. Recent benchmarks like SWE-bench, co-developed by some of the authors, have emerged to bridge this gap, presenting more challenging, repository-level bug-fixing tasks.

This paper directly addresses the limitations of applying LLM agents to such complex environments. Traditional approaches often involve agents interacting directly with raw command-line interfaces (e.g., Linux shell), which are designed for human users and are verbose, error-prone, and inefficient for LMs. The core innovation of SWE-agent is the introduction of the **Agent-Computer Interface (ACI)**. This concept draws a direct parallel from **Human-Computer Interaction (HCI)**, where well-designed user interfaces (like Integrated Development Environments, IDEs) significantly enhance human productivity. By proposing that LMs represent a "new category of end users" with their own unique needs and abilities, SWE-agent advocates for interfaces specifically tailored for them.

This work extends existing research on **LM agents and tool use**. While prior efforts have explored tool integration, prompting techniques, and execution feedback in interactive settings, SWE-agent unifies these elements under the ACI framework. It posits that the *design* of the interface itself—how commands are structured, how feedback is presented, and how context is managed—is as crucial as the underlying language model or the specific tools used. This represents a significant shift from simply providing tools to optimizing the *interaction* with those tools for an artificial agent. By doing so, SWE-agent seeks to unlock the full potential of LLMs in highly interactive and complex digital environments, particularly in the demanding domain of software engineering.

### 2. Key Objectives and Motivation

The primary motivation behind SWE-agent stems from an observation regarding the disparity between how human software engineers and current LM agents interact with computing environments. Human engineers benefit immensely from sophisticated applications like VSCode, which offer tailored interfaces, powerful tools, and insightful feedback to manage complex tasks. In contrast, LM agents typically interact with raw, low-level interfaces such as the Linux shell or Python interpreter, which are not designed with an LM's unique strengths and limitations in mind. The authors note that LMs often "struggle to reliably take actions in this environment," leading to inefficiencies and difficulties in error recovery.

Given this gap, the key objectives of the "SWE-agent" research are:

1. **Investigate Interface Design Impact:** To systematically explore how the design of an interface (an Agent-Computer Interface or ACI) influences the performance of language model agents when tackling complex software engineering tasks.
2. **Introduce the ACI Concept:** To formally define and demonstrate the utility of ACIs as an abstraction layer specifically built to enhance LM agents' abilities in computer environments.
3. **Develop and Open-Source SWE-agent:** To build a practical system, SWE-agent, that incorporates a custom ACI to enable LMs to autonomously perform real-world software engineering tasks, such as those found in the challenging SWE-bench benchmark.
4. **Achieve State-of-the-Art Performance:** To validate the effectiveness of the ACI approach by achieving superior performance on established software engineering benchmarks like SWE-bench and HumanEvalFix.
5. **Provide Design Insights:** To derive and articulate generalizable principles for effective ACI design based on empirical observations and ablation studies, offering guidance for future development of LM agents across various digital domains.

In essence, the paper aims to shift the paradigm of LM agent interaction by recognizing LMs as a new type of user, arguing that a thoughtfully designed interface is paramount to unlocking their full potential in complex, interactive environments.

### 3. Methodology and Approach

The core of SWE-agent's methodology revolves around the design, implementation, and rigorous evaluation of its custom Agent-Computer Interface (ACI).

#### 3.1. ACI Design Principles and Components

The authors posit that an effective ACI should help LMs understand the environment, manage history, and use actions efficiently. Drawing inspiration from HCI, they identified key design principles:
1. **Simplicity and Understandability:** Actions should be simple, with few options and concise documentation, to reduce cognitive load on the LM.
2. **Compactness and Efficiency:** Important operations should be consolidated into as few actions as possible, enabling meaningful progress in a single step.
3. **Informative but Concise Feedback:** Environment feedback should provide substantive information without unnecessary detail, directly addressing the LM's fixed context window and computational costs.
4. **Guardrails for Error Mitigation:** Built-in mechanisms to detect and prevent common LM errors, aiding in faster recovery.

Based on these principles, SWE-agent's ACI comprises several specialized components atop the Linux shell:
- **Search and Navigation:** Custom commands like `find_file`, `search_file`, and `search_dir` provide summarized, concise search results (max 50 per query) to avoid overwhelming the LM, promoting efficient localization.
- **File Viewer:** The `open` command displays a window of up to 100 lines of a file at a time, with contextual information (full path, total lines, omitted lines, line numbers). `scroll_down`, `scroll_up`, and `goto` commands enable in-file navigation.
- **File Editor:** The `edit` command allows LMs to replace a specific range of lines in an open file in a single step. Critically, it integrates a **code linter** (e.g., `flake8`) that automatically checks for syntax errors (e.g., indentation, undefined names) and discards invalid edits, providing specific error feedback to the agent for recovery. A `create` command is also available for new files.
- **Context Management:** The system leverages the ReAct framework, prompting the LM for a "thought" and an "action" at each step. It manages history by collapsing older observations (beyond the last 5 turns) into a single line to keep context concise. Malformed generations trigger specific error messages, prompting a retry and omitting redundant past errors.

#### 3.2. Design and Refinement Process

The ACI design was an iterative process combining qualitative and quantitative methods:
- **Qualitative Analysis:** Manual inspection of agent behavior on a small development set of SWE-bench instances helped identify common difficulties and inform the design of specific commands, feedback formats, and guardrails.
- **Quantitative Tuning:** A grid search was performed over hyperparameters like file viewer window size, history processing strategy, and decoding temperature on a subset of the development split to select the optimal ACI configuration.

#### 3.3. Experimental Setup and Evaluation

- **Datasets:** Evaluated primarily on **SWE-bench** (full 2,294 tasks and a Lite subset of 300 tasks), a challenging dataset of real-world GitHub issues requiring repository-level code changes. Also evaluated on **HumanEvalFix** for basic code debugging capabilities.
- **Language Models:** GPT-4 Turbo (gpt-4-1106-preview) was the primary model, and Claude 3 Opus (claude-3-opus-20240229) was also tested to demonstrate ACI portability. Other models (Llama 3, DeepSeek Coder) were experimented with but found subpar, often due to smaller context windows.
- **Baselines:**
 - **Retrieval-Augmented Generation (RAG):** Non-interactive, retrieving relevant files and generating a patch directly.
 - **Shell-only agent:** Interactive, but with direct access to a standard Linux shell, adapted from InterCode. This served as a crucial ablation to highlight the value of the custom ACI.
- **Metrics:** `% Resolved` (or `pass@1`) – the proportion of instances where all tests pass. `$ Avg. Cost` – API inference cost per instance (with a $4 budget).
- **Analysis:** Beyond quantitative performance, the authors conducted detailed qualitative analyses of agent trajectories, characterizing common problem-solving patterns and categorizing failure modes (even using GPT-4o for automated categorization of unresolved instances). All experiments were run in Docker containers for reproducibility and safety.

### 4. Main Findings and Results

The results clearly demonstrate the significant advantage of SWE-agent's tailored ACI over conventional interactive and non-interactive approaches.

#### 4.1. State-of-the-Art Performance

- **SWE-bench:** SWE-agent with GPT-4 Turbo achieved a pass@1 rate of **12.47%** on the full SWE-bench test set and **18.00%** on the SWE-bench Lite subset. This substantially outperforms previous state-of-the-art results, including non-interactive RAG systems (3.8% for Claude 3 Opus, 1.31% for GPT-4 Turbo on full SWE-bench) and the Shell-only baseline (11.00% for GPT-4 Turbo on Lite). This represents a remarkable **64% relative increase** over the Shell-only agent on SWE-bench Lite, highlighting the direct impact of the ACI design.
- **HumanEvalFix:** SWE-agent with GPT-4 Turbo also achieved an impressive **87.7%** pass@1 rate on HumanEvalFix, significantly exceeding prior reported scores (e.g., GPT-4 at 47.0%, WaveCoder-DS at 57.9%). This confirms its strong basic code editing and debugging capabilities.
- **Model Portability:** The ACI design proved portable, with SWE-agent achieving 10.46% with Claude 3 Opus on full SWE-bench, confirming the interface's value beyond a single LLM.

#### 4.2. Impact of ACI Design (Ablation Studies)

Ablation studies on SWE-bench Lite revealed critical insights into effective ACI design:
- **File Editor:** The custom `edit` command with integrated linting was crucial, contributing a **3.0 percentage point increase** (18.0% vs. 15.0% without linting). Moreover, restricting editing to rudimentary bash commands ("Noedit") severely hampered performance, dropping to 10.3% resolved.
- **Search Interface:** The "Summarized" search interface, which provides concise lists of all results and guidance for refining queries, outperformed "Iterative" search (18.0% vs. 12.0%). Iterative search, despite being inspired by human IDEs, led to inefficient behavior where agents exhaustively inspected every match. "No search" (15.7%) still performed better than iterative search, emphasizing the importance of efficient information retrieval for LMs.
- **File Viewer Window Size:** An optimal window size of 100 lines yielded the best performance (18.0%), significantly outperforming smaller (30 lines, 14.3%) or larger (full file, 12.7%) windows. This indicates a sweet spot for providing sufficient context without overwhelming the model.
- **Context Management:** Collapsing older observations (beyond the last 5) dramatically improved performance (18.0% vs. 15.0% for "Full history"), underscoring the need for concise and relevant context.

#### 4.3. Analysis of Agent Behavior

The study provided qualitative insights into how agents leverage the ACI:
- **Initial Phases:** Agents typically start by either reproducing the issue (using `create`, `edit`, `python` for a reproduction script) or localizing the problematic code (`find_file`, `search_dir`).
- **Edit-Execute Loops:** Once localization is complete, the dominant problem-solving pattern becomes an iterative `edit` and `python`/`pytest` loop, allowing for immediate feedback and refinement.
- **Editing Challenges and Recovery:** Despite guardrails, editing remains challenging, with 51.7% of resolved trajectories experiencing at least one failed edit. While agents generally recover (90.5% chance after 0 failed edits), the probability of successful recovery decreases with consecutive errors (57.2% after 1 failed edit).
- **Success vs. Cost:** Successful runs tend to complete earlier and at a lower cost (median $1.21, 12 steps) compared to unsuccessful ones (mean $2.52, 21 steps), suggesting that increasing budget might not proportionally increase performance.
- **Failure Modes:** The majority of unresolved instances (52.0%) stemmed from "Incorrect Implementation" or "Overly Specific Implementation," indicating that functional correctness and generalizability remain key hurdles. "Failed Edit Recovery" accounted for another 23.4% of failures.

### 5. Significance and Potential Impact

The "SWE-agent" paper makes several significant contributions that could profoundly impact the field of AI and software engineering:

1. **Conceptual Framework of ACI:** The most impactful contribution is the formalization and empirical validation of the Agent-Computer Interface (ACI). By explicitly drawing parallels to Human-Computer Interaction (HCI) and recognizing LMs as a new class of users, the paper introduces a novel and intuitive lens through which to design and evaluate LM agent systems. This paradigm shift encourages researchers to think beyond mere tool integration towards optimizing the entire interactive experience for AI.
2. **Demonstrated Performance Leap:** SWE-agent's state-of-the-art performance on SWE-bench and HumanEvalFix provides compelling evidence that a carefully designed ACI can unlock substantial improvements in LM agents' ability to tackle complex, real-world software engineering tasks. This pushes the frontier of autonomous programming, moving beyond simple code generation to more sophisticated bug fixing and maintenance scenarios.
3. **Actionable Design Principles:** The detailed ablation studies and qualitative analyses yield concrete, actionable design principles for building effective ACIs. Insights such as the importance of simple, efficient commands, concise and informative feedback, and robust error guardrails are invaluable for future development of LM agents in any digital environment, not just software engineering.
4. **Open-Sourced and Extensible Platform:** By open-sourcing SWE-agent, the authors provide a robust and extensible platform for the research community. This facilitates further experimentation with novel tools (e.g., static analysis, web browsing, fuzzing), different LLMs, and advanced ACI designs, accelerating progress in the field of autonomous agents.
5. **Insights into LM Behavior:** The in-depth analysis of agent trajectories offers valuable insights into LM problem-solving patterns, common failure modes, and the dynamics of their interaction with environments. Understanding how LMs learn, recover from errors, and manage context is crucial for building more robust and reliable AI systems, contributing to a "comparative understanding of human and artificial intelligence."
6. **Ethical Considerations:** The paper responsibly addresses the ethical implications, particularly security risks associated with executing LM-generated code (mitigated by Docker sandboxing) and the potential for malicious use. By open-sourcing, it advocates for a collaborative research approach to develop robust safety constraints and shape the future of AI-driven software engineering responsibly.

In conclusion, "SWE-agent" is a landmark paper that not only demonstrates impressive empirical results in automated software engineering but also provides a foundational conceptual framework and practical guidelines for designing more effective and intuitive interfaces for language model agents across a wide range of digital tasks.
