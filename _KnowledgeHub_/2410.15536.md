# GRS: Generating Robotic Simulation Tasks from Real-World Images

> [!summary] Summary
> GRS turns a single RGB-D image into a runnable robotic simulation with solvable tasks. SAM2 segments the scene, a VLM describes crops and matches them to simulation-ready 3D assets, then a VLM writes both task code and a unit-test battery. An LLM router decides each iteration whether to repair the simulation or the tests, yielding 0.71 oracle reward versus 0.47 for an LLM-only baseline.

## Problem

- LLM simulation generators such as GenSim, RoboGen, and Holodeck never verify that produced scenes are functional or that an agent can actually solve them.
- Prior real-to-sim pipelines rely on text-grounded detectors or CLIP embedding matching, which break under occlusion and varying object pose or lighting.
- Code-repair loops fix only the generated program, so faulty or uninformative test code silently misdirects refinement and wastes fixing attempts.

## Method

- ==Scene comprehension==: ==SAM2== over-segments the RGB-D image, depth lifts each crop to an axis-aligned 3D bounding box in the robot frame, and a VLM writes a description per crop.
- ==Object correspondence==: a VLM pre-describes multi-view renders of every asset, then compares both crop image and crop text to that database, also rejecting non-object crops.
- **GRS**'s ==dual generation== plus ==LLM router==: a VLM emits simulation code and an oracle-policy unittest suite; the router reads errors and chooses fix_code or fix_test each round until clean.

## Results

- Object retrieval with GPT-4o on combined image plus text reached F1 **0.89**, beating image-only **0.88**, text-only **0.83**, CLIP **0.76**, and all Claude-3.5-Sonnet variants.
- Oracle-policy reward on generated tasks was **0.71** for the full system versus **0.65** without the router, **0.49** without test feedback, and **0.47** for LLM-only.
- The router averaged **0.52** test fixes and **1.08** fewer simulation fixes than the no-router ablation (**5.81** vs **6.89**), a net **0.56** fewer edits per generation.

## Takeaways

> [!tip] Key Insights
> - Pairing generated code with generated tests only pays off if something can also repair the tests; otherwise bad tests misdirect the repair loop.
> - Validating with an oracle policy rather than static scene checks costs more compute but filters for tasks that are genuinely physically achievable.
> - Multimodal matching against pre-computed asset descriptions beats raw embedding similarity, which stays brittle to occlusion, pose, and lighting shifts.

## Detailed Report

### 1. How this Work Fits into the Broader Research Landscape

GRS tackles the fundamental "real-to-sim" problem, a critical challenge in robotics, AR/VR, and game development. The goal is to automatically create interactive digital twin simulations from real-world observations, enabling virtual agents (e.g., robots) to train and interact within environments that accurately mirror physical reality.

The broader research landscape can be categorized into several key areas:

- **Scene Understanding:** Traditional methods involve 3D reconstruction, pose estimation, and inverse rendering to transform real-world observations into digital representations. Recent advancements, particularly with foundation models like the Segment Anything Model (SAM) and Vision-Language Models (VLMs), have revolutionized scene comprehension by enabling robust object segmentation and rich textual descriptions. GRS leverages SAM2 for segmentation and VLMs for describing objects, building upon these state-of-the-art vision models. It distinguishes itself from methods like OWL-ViT by using VLMs' vast knowledge to deduce manipulability from descriptions, rather than relying on specific text grounding.

- **Simulation Creation with LLMs:** A rapidly growing field explores using LLMs to automate various aspects of simulation generation. Previous works like GenSim, RoboGen, and Holodeck have demonstrated the potential of LLMs to generate robotic tasks, scenes, and even entire 3D environments from natural language prompts. GRS extends this by grounding the simulation generation in *real-world observations* (using RGB-D images) and, crucially, by ensuring the *solvability* and *functional alignment* of the generated tasks through an iterative refinement process. Many existing LLM-based simulation generation methods often produce syntactically correct but functionally flawed or non-executable code. GRS directly addresses this limitation.

- **World Models and Generative AI for Interactive Environments:** Recent research focuses on using diffusion models and other generative models to create interactive game engines or tune video-based models for control input. Examples include Genie, WHAM, and GameFactory. While impressive, these methods often produce pixel-based or abstract worlds. GRS, in contrast, generates *code* that runs on existing physics-based game engines (like CLIPort, which utilizes PyBullet or similar simulators), ensuring that hard physical constraints are enforced. This makes GRS particularly relevant for domains where real-world physics and precise behavior are paramount, such as robotic manipulation or training simulations for critical real-world tasks (e.g., surgery, piloting).

GRS distinguishes itself by offering a **closed-loop system** that not only generates simulations from real-world visual input but also iteratively validates and refines them to ensure task solvability and alignment with the initial task definition. The novel **LLM-based router system** is a key innovation, providing an intelligent feedback mechanism that goes beyond simple code repair to optimize both the simulation and its associated tests. This iterative alignment is a significant step towards creating truly robust and functional digital twins for agent training.

### 2. Key Objectives and Motivation

The primary objective of GRS is to **automatically generate robotic simulation tasks from single real-world RGB-D observations that are solvable by virtual agents.**

The core motivations driving this research are:

1. **Bridging the Real-to-Sim Gap:** The "real-to-sim" problem is a bottleneck in many AI applications. Manually creating high-fidelity digital twins and relevant simulation tasks from real-world scenes is labor-intensive, time-consuming, and requires specialized expertise. GRS aims to automate this process, enabling faster iteration and broader applicability of simulation-based training.
2. **Ensuring Solvable and Aligned Tasks:** While LLMs can generate diverse tasks, there's a significant challenge in ensuring these tasks are actually solvable by a robotic agent within a given simulation environment and that the simulation accurately reflects the intended task. GRS's novel router system is specifically designed to address this, iteratively refining both the simulation code and its test suite to maximize task-simulation alignment and feasibility. This is crucial for generating high-quality training data for robot policies.
3. **Leveraging Advanced AI Models:** The motivation includes exploring the capabilities of state-of-the-art vision-language models (VLMs) like SAM2 and GPT4o for complex tasks like scene comprehension, object description, and code generation. GRS seeks to demonstrate how these powerful models can be effectively integrated into a pipeline for end-to-end digital twin creation.
4. **Broader Applicability Beyond Robotics:** Although primarily focused on robotics, the authors explicitly motivate GRS's relevance to other domains such as game generation, AR/VR, educational games, and human training simulations. The ability to quickly create interactive, task-oriented virtual environments from real scenes has wide-ranging potential.

In essence, GRS strives to create a robust, automated system that transforms raw visual data from the physical world into functional, testable, and solvable virtual environments for agent training and interaction.

### 3. Methodology and Approach

GRS employs a two-phase, iterative methodology: 1) Scene Comprehension and 2) Simulation Generation and Evaluation.

#### 3.1. Scene Comprehension

This phase focuses on extracting a detailed understanding of the real-world scene from a single RGB-D image.

- **Image Segmentation:** The system utilizes **SAM2 (Segment Anything Model 2)** to segment the input RGB image into numerous object crops. SAM2 is chosen for its ability to produce granular, accurate segmentations, even resulting in over-segmentation of object parts and background elements.
- **3D Bounding Box Generation:** For each segmented crop, depth data from the RGB-D image is used to transform the 2D pixels into 3D positions in the robot's coordinate frame. These 3D points are then fitted within axis-aligned 3D bounding boxes, providing geometric and spatial information for each potential object.
- **Object Correspondence (VLM-based):** This is a critical step that matches detected real-world objects to available simulation-ready 3D assets.
 1. **Asset Database Creation:** A VLM (e.g., GPT4o) analyzes multiple rendered views of each 3D asset in a pre-existing library. This generates rich, multi-perspective textual descriptions for every asset, which are stored in a database. This is a one-time pre-processing step.
 2. **Candidate Object Description:** The *same* VLM is used to describe the segmented real-world image crops based solely on their visual information. This ensures consistency in the descriptive language.
 3. **Description Comparison:** The VLM compares the real-world candidate object descriptions (and the cropped image itself) against the asset descriptions in the database to find the best match. It can also identify if a crop does not correspond to a known object (addressing over-segmentation). This process yields a list of identified scene assets with their corresponding 3D bounding box information.

#### 3.2. Simulation Generation and Evaluation

This phase translates the scene understanding into a functional simulation with solvable tasks, using an iterative refinement process.

- **Task Definition Generation:** Given the scene description (identified assets and their placements) and the input image, a VLM is prompted to generate a contextually relevant robotics task definition. The VLM can select a subset of the observed assets and define manipulation goals (e.g., "pack food items in a box"). The output is a JSON-like structure detailing the task name, description, and assets involved.
- **Simulation Program Generation:** A VLM generates Python code that implements the defined task within a simulation framework (specifically, a modified CLIPort environment). This code defines the simulator's initial configuration (object types, positions from the scene comprehension phase) and the desired end state. The LLM is allowed to modify object positions during iteration to ensure task feasibility.
- **Test Code Generation:** Crucially, alongside the simulation program, an LLM also generates a battery of Python unit tests. These tests are designed to validate whether an "oracle robot policy" can successfully complete the task within the generated simulation. Testing with an oracle agent (a hypothetical perfect agent) ensures the task is fundamentally achievable and the simulation code is correct and functional, rather than just syntactically valid.
- **Iterative Refinement with LLM-based Router:** This is the core innovation for achieving alignment and solvability.
 1. **Run Tests:** The generated tests are executed against the simulation program.
 2. **Router Decision:** An LLM-based "router" analyzes the test outcomes and any runtime errors. Based on this feedback and the original task description, the router intelligently decides whether to:
 - **Fix the Simulation Program:** If the simulation code has errors or leads to low oracle reward, the VLM (given scene image, errors, and task definition) attempts to revise the simulation code. Common fixes observed include simplifying the task, increasing maximum steps, or enlarging target areas.
 - **Fix the Test Program:** If test feedback is too sparse, or if the tests themselves are flawed (e.g., missing imports, misusing simulation objects), the LLM attempts to revise the test code, often adding more diagnostics or refining assertions.
 3. **Repeat:** This cycle of running tests, router decision, and fixing continues until the tests pass without errors, indicating a robust and solvable simulation.

This iterative process, guided by the LLM router, ensures that the generated simulations are not only derived from real-world scenes but are also functionally correct and aligned with the intended robotic tasks, a significant improvement over purely generative approaches.

### 4. Main Findings and Results

The experiments conducted by the authors demonstrate the effectiveness of GRS across several dimensions, particularly in object correspondence and task environment generation.

#### 4.1. Object Correspondence Performance

The study compared GRS's VLM-based object correspondence against several baselines using 10 distinct table-top scenes with objects from the HOPE dataset.

- **Superior Accuracy of VLM (GPT4o):** GRS, utilizing both image and text descriptions with GPT4o, achieved the highest F1 score of **0.89** (with a 95% CI of 0.87, 0.90). This significantly outperformed:
 - **CLIP Embedding Distance:** A baseline method using CLIP embeddings yielded an F1 score of 0.76. This suggests that simple similarity matching is less robust to real-world variations.
 - **Text-only Matching:** Claude-3.5-Sonnet scored 0.67, and GPT4o scored 0.83.
 - **Image-only Matching:** Claude-3.5-Sonnet scored 0.55, and GPT4o scored 0.88.
- **Model Performance:** GPT4o consistently demonstrated superior performance across all object correspondence tasks compared to Claude-3.5-Sonnet, highlighting the importance of the underlying VLM's capabilities.
- **Statistical Significance:** Kruskal-Wallis testing confirmed statistically significant differences (p < 0.05) across task types, models, and their interaction, validating the robustness of the findings. The results underscore that combining visual context with rich textual descriptions via a powerful VLM is key to accurate asset retrieval.

#### 4.2. Robot Task Generation Effectiveness

This experiment evaluated GRS's ability to produce working simulators for robot policies, focusing on the success rate of an "oracle policy" (a perfectly capable robot agent) in completing generated tasks.

- **Improved Oracle Policy Reward:** GRS (with the router) achieved an average reward of **0.71**, indicating successful completion of a significant portion of task goals. This was superior to all ablation baselines:
 - **No Router:** 0.65 reward. This ablation only fixed the simulation but lacked the intelligent test/simulation choice.
 - **No Fix:** 0.49 reward. This ablation generated the simulation only once without any iterative fixing.
 - **LLM (no image, no fix):** 0.47 reward. This was the closest to the original GenSim method, highlighting the substantial gains from real-world grounding, iterative refinement, and VLM usage.
- **Router Efficiency:** The router demonstrated efficiency in the refinement process:
 - It performed an average of **0.52 fixes to tests** per task, indicating a frequent need to refine the initial test generation.
 - It performed **1.08 fewer simulation fixes** on average compared to the "no router" ablation (5.81 vs. 6.89), resulting in **0.56 fewer total changes** per generation. This suggests the router's ability to choose the *correct* component to fix (simulation or tests) leads to more efficient automation.

#### 4.3. Qualitative Analysis of Code Generation

- **Router Behavior:** The router effectively utilized sparse error feedback to decide whether to refine the simulation or the tests. It was observed to correctly identify when test code was problematic (e.g., missing imports, incorrect object usage) and prioritize fixing the tests to provide better diagnostics.
- **Simulation Fixing:** When the oracle achieved only partial success, the system often responded by simplifying the task (reducing objects), increasing the maximum number of steps, or enlarging target placement areas, demonstrating an ability to reason about task feasibility.
- **Test Fixing:** Test fixes focused on adding diagnostics (e.g., monitoring step count, intermediate goal achievement, reward accumulation) to provide richer feedback. They also addressed fundamental issues like incorrect environment initialization and goal misinterpretation. These improvements were achieved with generic prompts, showcasing the inherent adaptability of the system with improved LLMs.
- **Common Failure Cases:**
 - **Non-terminating Loops:** Rarely, generated simulation code included indefinite `while` loops, causing the generation process to hang. This highlights a need for better loop control or timeout mechanisms.
 - **LLM Misdiagnosis/Re-implementation:** Occasionally, the LLM would misdiagnose the cause of test failures and implement workarounds, sometimes re-implementing basic geometric functions or even mocking core simulation behaviors, bypassing the intended API. This points to current limitations in LLM's deeper reasoning and adherence to established APIs.

#### 4.4. Scene-level Extension

GRS demonstrated preliminary scalability to more complex environments. By integrating a background reconstruction pipeline and using a significantly larger asset database (150,000 assets from Objaverse), the system successfully converted real-world images into detailed 3D simulation environments, showcasing its potential for generating complex scene-level tasks beyond table-top arrangements.

### 5. Significance and Potential Impact

GRS represents a significant step forward in automating the creation of digital twins and interactive simulation environments from real-world observations. Its impact spans multiple domains:

- **Robotics:**
 - **Accelerated Data Generation:** GRS automates the tedious process of creating diverse and challenging simulation tasks, which are essential for training robust robot policies using reinforcement learning or imitation learning. This can significantly reduce the data generation bottleneck in robotics research.
 - **Enhanced Sim-to-Real Transfer:** By grounding simulations in real-world observations and ensuring task solvability, GRS helps create more realistic and relevant training environments, potentially improving the transferability of learned policies from simulation to the physical world.
 - **Reduced Development Cycles:** Robotics engineers can quickly convert a physical setup into a virtual one, allowing for rapid prototyping, testing, and debugging of robot behaviors without needing extensive manual scene setup.

- **Game Development and AR/VR:**
 - **Automated Level Design:** GRS can automate the creation of realistic and interactive game levels or AR/VR experiences by converting real environments into virtual spaces with meaningful, solvable objectives. This could streamline development workflows.
 - **Dynamic Content Generation:** The system's ability to generate contextual tasks based on scene understanding opens possibilities for dynamic and personalized gameplay or training scenarios.
 - **Serious Games and Education:** For applications requiring high real-world fidelity, such as training simulators for surgery, emergency response, or industrial operations, GRS can create immersive and functionally accurate environments, directly impacting learning outcomes.

- **AI Research:**
 - **Advancing LLM/VLM Capabilities:** The work demonstrates a sophisticated application of foundation models beyond text generation, showcasing their potential for complex, iterative problem-solving and code generation in embodied AI.
 - **Robustness through Iterative Refinement:** The novel LLM-based router highlights a powerful paradigm for ensuring the functional correctness of generative AI outputs, moving beyond one-shot generation to self-correcting systems.

**Limitations and Future Work:**
The authors acknowledge several limitations that also present avenues for future research:
- **Rich Physics Metadata:** The current system assumes basic physics. Integrating richer metadata (mass, inertia, friction) from asset databases would enable more sophisticated physics-based task generation.
- **Complex Scene Semantics:** Generating semantically meaningful tasks for full, complex scenes (beyond table-top) requires extending the router's understanding of intricate spatial relationships and functionalities.
- **Sim-to-Real Gap Closure:** Integrating GRS with differentiable physics engines and sim-to-real transfer learning techniques could enable automatic refinement of simulations to specifically minimize the sim-to-real gap, further streamlining the entire robotics pipeline.
- **LLM Robustness:** Addressing the occasional misdiagnosis, API re-implementation, and non-terminating loop issues will improve as underlying LLMs become more capable and reliable in code generation and reasoning.

In conclusion, GRS makes a substantial contribution by providing a robust, automated system for transforming real-world observations into solvable and functionally aligned robotic simulation tasks. Its innovative use of VLMs and an iterative, LLM-driven router addresses key challenges in the real-to-sim problem, paving the way for more efficient and effective AI agent training and digital twin applications across various industries.
