# Efficient World Action Model Inference with Adaptive Intermediate States

> [!summary] Summary
> WAMachine is a training-free inference framework that speeds up World Action Models by keeping and adapting intermediate state instead of recomputing it. It works at three levels: replans, denoising steps, and Transformer layers. Tested on Cosmos Policy, Fast-WAM-IDM and Motus, it cuts observation-to-action latency 1.47-3.05x and GPU time per replan 2.23-3.27x. It keeps 96.69-99.54% of native task success.

## Problem

- World Action Models generate actions and future representations through iterative diffusion or flow denoising, so each replan pays heavy GPU cost and limits closed-loop control frequency.
- Prior acceleration methods reuse computation at isolated points only: warm starts (RTI-DP, STEP), execution overlap (RTC, FutureRTC), or feature caching (TeaCache, DiCache, C3ache). They miss continuity across the whole pipeline.
- Reusing retained inference state as-is goes stale as observations, planning context and representations change. Naive warm starts like RTI-DP drop success sharply, to 8.5% on Motus.

## Method

- **Trajectory Remapping** stores each replan's denoised output plus a normalized ==denoising direction==. It shifts these into the next horizon and starts the next replan at a later noise stage.
- **Observation Rebinding** runs a bounded anticipatory denoising prefix during action execution, conditioned on the WAM's predicted future. It swaps in the real observation if a ==weighted-RMSE consistency score== passes, otherwise restarts.
- **Residual Rescaling** uses a shallow probe of ==DiT== layers to fit a ==least-squares scale factor==, then skips the middle layers by reusing a rescaled retained residual. It recomputes when ==cosine== or fit checks fail.

## Results

- On Fast-WAM-IDM/LIBERO, GPU time per replan falls from **367.49** to **112.52 ms** (**3.27x**) and observation-to-action latency from **416.64** to **136.42 ms** (**3.05x**).
- Large-sample success stays close to native: **97.02** vs **98.05%** on Cosmos Policy, **98.15** vs **98.60%** on Fast-WAM-IDM, **83.25** vs **86.10%** on Motus RoboTwin 2.0.
- Ablations: removing Trajectory Remapping or Residual Rescaling raises GPU time from **114.75** to about **188 ms**. Removing Observation Rebinding raises latency to **165.62 ms**. Without CUDA Graphs, speedup is still **2.53x**.

## Takeaways

> [!tip] Key Insights
> - Closed-loop generative policies show state continuity across replans, denoising steps and layers. Treat inference state as a resource to carry forward, not something rebuilt from noise each step.
> - A WAM's predicted future pays for itself at inference time: it allows anticipatory computation during execution, which hides latency instead of only lowering compute.
> - Cheap consistency checks with refresh fallbacks are what make reuse safe. Unchecked reuse or warm starts trade large speedups for collapsed task success.

## Detailed Report

### 1. Overview

While a robot executes one action chunk, its model must already prepare the next. World Action Models (WAMs) predict robot actions and how the environment may evolve, supporting future-aware control. Their iterative inference can delay the next action. The model must plan again, refine a trajectory through denoising steps, and repeatedly process states through Transformer layers. The authors describe this bottleneck as redundant computation that limits closed-loop control frequency.

A new observation can make earlier work stale. Starting every pass over, however, wastes work. WAMACHINE, a training-free framework, preserves useful intermediate computation across all three loops. It adapts that computation to changed plans or observations and refreshes it when checks fail. It does not reuse it blindly.

The representative result comes from Fast-WAM-IDM on LIBERO, evaluated on the same fixed 200-episode subset. Mean GPU inference time per replan falls from 367.49 to 112.52 ms, a 3.27× speedup. Observation-to-action (O2A) latency falls from 416.64 to 136.42 ms, a 3.05× speedup. Subset success is 97.0% versus Native’s 98.0%.

### 2. Carry computation forward

WAMACHINE exploits reuse at three nested levels, and each level checks whether the retained state still applies.

- **Trajectory Remapping** carries the prior replan’s denoised endpoint and a normalized denoising direction into the next initialization. It uses fresh noise for uncovered trajectory slots and for the first replan.
- **Observation Rebinding** performs a bounded anticipatory prefix during physical execution. This prefix issues no robot actions. Inference continues under the real observation only if prediction-consistency checks pass. Otherwise it restarts from the remapped initialization.
- **Residual Rescaling** computes a head and a shallow probe. It then rescales a retained middle-layer residual and skips those layers only when probe checks pass. On failure, it fully computes the middle layers and refreshes the retained state.

### 3. Test the explanation

The evaluation uses two distinct timing measures. GPU inference time per replan is mean DiT denoising computation per replan. It includes foreground and anticipatory work and excludes encoding and decoding. O2A is wall-clock time from the arrival of real inputs to decoded action readiness. It includes encoding, synchronization, rebinding, output transfer, and prefix wait or restart.

The two measures do not improve equally. Across three models, speedups are 2.23–3.27× in GPU time and 1.47–3.05× in O2A latency. Neither measure establishes fewer attempts or shorter total episode time.

Larger simulation evaluations test success: 6,000 episodes per LIBERO model, plus 1,000 each for Motus on RoboTwin 2.0 Clean and Randomized. In these evaluations, WAMACHINE retains 96.69–99.54% of Native average task success. Retention is accelerated average success divided by Native average success. For Fast-WAM-IDM, average success is 98.15% versus 98.60%, a retention of 99.54%.

The Fast-WAM-IDM ablation tests the components, though it does not prove that any one of them is the sole cause. Removing Trajectory Remapping raises GPU time from 114.75 to 188.02 ms. Removing Residual Rescaling raises it to 188.99 ms. Removing Observation Rebinding lowers GPU time slightly, from 114.75 to 108.45 ms, but worsens O2A latency from 144.75 to 165.62 ms. The full system has the lowest O2A latency among tested variants.

CUDA Graphs also contribute: adding them improves Native timing. Even without graphs, WAMACHINE still records 2.53× GPU-time and 2.54× O2A speedups over Native in this ablation.

### 4. What the evidence changes

WAMACHINE does not preserve every intermediate state unchanged. It makes computation reusable by pairing transport with adaptation and explicit refresh paths. The ablation’s different GPU-time and O2A responses separate two effects: less measured computation and less latency exposed to the control loop are related but not interchangeable. These are simulation results, not a real-robot deployment claim.
