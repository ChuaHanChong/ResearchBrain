# TinyVLM: Zero-Shot Object Detection on Microcontrollers via Vision-Language Distillation with Matryoshka Embeddings

> [!summary] Summary
> TinyVLM introduces a framework for zero-shot object detection on microcontroller units (MCUs), enabling operation within sub-1MB memory constraints. This approach achieved real-time inference on platforms like MAX78000 at 1,160 FPS and STM32H7 at 26 FPS, while demonstrating detection capabilities on COCO and LVIS benchmarks.

## Problem

- Large Vision-Language Models (VLMs) have substantial computational and memory requirements (hundreds of MBs/GBs), making them infeasible for microcontroller units (MCUs) with typical KB/MB memory limits.
- Existing efficient VLM variants are still 20-40 times larger than typical MCU flash memory, and their coupled architectures are inefficient for on-device inference where class candidates are known.
- Zero-shot object detection, crucial for adaptable edge AI, was previously unavailable on MCUs, limiting device intelligence for novel object recognition without retraining.

## Method

- A ==decoupled architecture== is used where text embeddings for candidate classes are precomputed offline and stored on MCU flash, with only a compact ==MobileNetV2-based vision encoder== running on-device for inference.
- ==Matryoshka distillation== trains a single student model to produce nested embeddings at multiple dimensions (e.g., 16-256), allowing flexible accuracy-memory trade-offs based on specific MCU constraints.
- Deployment optimizations include INT8 quantization of precomputed text embeddings, reducing storage by **4x**, and a specific memory layout to efficiently manage flash and SRAM on MCUs.

## Results

- TinyVLM achieved zero-shot classification with **44.1%** average accuracy (256-dim) across COCO, Flowers102, and Food101, operating with a **1.6MB** memory footprint compared to a **350MB** CLIP teacher.
- The framework demonstrated the first reported zero-shot object detection on MCUs, with TinyVLM-Det (128-dim) achieving an AP50 of **15.2%** on COCO and **10.8%** on LVIS.
- Real-time inference was observed across various MCUs, with MAX78000 reaching **1,160 FPS** (**0.86ms** latency) at **0.016 mJ** per inference, and STM32H7 achieving **26 FPS** (**38ms** latency) using **892KB** flash and **285KB** peak SRAM.

## Takeaways

> [!tip] Key Insights
> - Decoupling the VLM architecture by precomputing text embeddings offline significantly reduces real-time memory and computational load, enabling zero-shot capabilities within extreme MCU constraints.
> - Matryoshka distillation allows a single, memory-efficient VLM to dynamically scale its embedding size and corresponding accuracy to fit diverse MCU memory budgets, simplifying deployment across various platforms.
> - Despite memory reductions by orders of magnitude, a carefully distilled VLM can retain a functional portion of a larger teacher model's zero-shot classification and detection accuracy.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

The field of artificial intelligence has seen significant advancements with the development of large Vision-Language Models (VLMs) like CLIP. These models have demonstrated capabilities in zero-shot recognition, allowing them to classify or detect objects not seen during training, by leveraging natural language descriptions. This ability to recognize novel objects without requiring task-specific, labeled training data is a fundamental capability for intelligent systems and holds promise for diverse applications.

However, the prevailing challenge with these advanced VLMs is their substantial computational and memory requirements. Models such as CLIP ViT-B/32 necessitate hundreds of megabytes (MB) of parameters and gigabytes (GB) of activation memory. This scale far exceeds the constraints of microcontroller units (MCUs), which typically operate with memory budgets in the order of hundreds of kilobytes (KB) to a few megabytes. This disparity creates a significant barrier to deploying advanced zero-shot capabilities in resource-constrained edge devices.

Prior work in efficient VLMs has focused on reducing model sizes through techniques like knowledge distillation and neural architecture search, leading to models such as TinyCLIP and MobileCLIP. While these methods have shrunk model footprints to 18-39 MB, this is still 20-40 times larger than typical MCU flash memory limits. Furthermore, these approaches generally maintain a coupled vision-language architecture, requiring both vision and text encoders to operate concurrently during inference, which is inefficient for environments where class candidates can be pre-defined.

Concurrently, the TinyML community has been developing techniques for deploying machine learning models on MCUs, with efforts like MCUNet enabling ImageNet classification within KB-level memory. For object detection, specialized models such as TinyissimoYOLO have achieved detection on MCUs but are limited to task-specific, pre-trained classes and lack zero-shot capabilities.

TinyVLM addresses this gap by proposing a framework that enables zero-shot object detection directly on MCUs, operating within sub-1MB memory constraints. It aims to bridge the performance of VLMs with the stringent resource limitations of TinyML, an area not previously explored for zero-shot object detection. The work distinguishes itself by architectural modifications and distillation strategies tailored specifically for extreme memory and computational efficiency, rather than merely compressing existing VLM structures.

### 2. Key Objectives and Motivation

The primary objective of this research is to enable zero-shot object detection on microcontroller units (MCUs), a capability previously considered infeasible due to the substantial memory and computational requirements of existing Vision-Language Models (VLMs).

The motivation stems from several critical observations regarding the limitations of current VLM deployment:
- **Memory Disparity:** State-of-the-art VLMs like CLIP require hundreds of megabytes of memory for parameters and gigabytes for activations. This is orders of magnitude larger than typical MCU constraints, which are often limited to 1MB of flash memory and 512KB of SRAM. Even the smallest compressed VLM variants (e.g., 18-39MB) still exceed MCU budgets by a factor of 20-40. This fundamental incompatibility prevents the deployment of zero-shot capabilities to edge devices.
- **Architectural Inefficiency:** Most existing VLM compression techniques maintain the coupled architecture of the original models, meaning both the vision and text encoders are required during inference. For zero-shot detection where the set of candidate classes is known and fixed at deployment time (closed-set scenario), running the text encoder on the MCU is redundant and resource-intensive.
- **Need for Novel Object Recognition at the Edge:** Many edge AI applications could benefit from the flexibility of zero-shot recognition, allowing devices to adapt to new objects without needing retraining or re-deployment of new models. Examples include adaptive wildlife monitoring, industrial inspection for novel defects, and smart home systems. The inability to perform zero-shot detection on MCUs limits the intelligence and adaptability of these applications.

To overcome these challenges, TinyVLM aims to achieve the following specific objectives:
1. **Develop an MCU-compatible zero-shot detector:** The core objective is to create a framework that can perform zero-shot object detection on devices with less than 1MB of memory while maintaining competitive accuracy relative to larger VLMs.
2. **Introduce a decoupled deployment architecture:** This objective focuses on separating visual inference from text encoding. By precomputing text embeddings offline and storing them in flash memory, the inference-time load on the MCU is reduced to only the visual encoder, thus minimizing SRAM usage.
3. **Implement Matryoshka distillation for VLMs:** The goal is to train a single student model that produces nested embeddings at multiple dimensions (e.g., 16-256). This enables flexible accuracy-memory trade-offs, allowing the model to adapt to varying memory constraints of different MCU platforms without requiring separate training for each.
4. **Utilize quantized embedding storage:** This objective aims to further reduce the memory footprint of precomputed class prototypes by quantizing them to 8-bit integers, achieving a 4x reduction in storage with minimal accuracy degradation.
5. **Establish MCU benchmarks:** The research seeks to evaluate zero-shot detection performance on various MCU platforms (STM32H7, MAX78000, GAP9, ESP32-S3), providing measured hardware results and projected performance to establish baselines for future TinyML research in this domain.

### 3. Methodology and Approach

TinyVLM is a framework designed for zero-shot object detection on microcontrollers, incorporating three primary innovations to achieve its memory and computational efficiency goals.

#### 3.1. Decoupled Architecture

A central insight of TinyVLM is that for closed-set zero-shot detection, where the candidate classes are known prior to deployment, the text encoder does not need to run on the microcontroller during inference. This allows for a decoupled architecture:
- **Offline Text Embedding Precomputation:** Text embeddings for all known candidate classes are generated offline using the text encoder of a larger Vision-Language Model (VLM) or a distilled student text encoder. These embeddings are then stored in the MCU's flash memory.
- **On-Device Vision Encoder:** Only a compact vision encoder runs on the MCU at inference time. This design choice reduces the inference-time memory footprint significantly, as SRAM is only needed for the vision encoder's activations, not both encoders.
- **Vision Encoder Design:** The vision encoder is based on a MobileNetV2 architecture with a width multiplier of α = 0.35. Following global average pooling (GAP), a linear layer projects the visual features into the embedding space. This configuration is chosen to ensure the vision encoder's parameter memory fits within MCU flash constraints (892KB after INT8 quantization).

#### 3.2. Matryoshka Distillation

To address the diverse memory constraints of different MCU platforms, TinyVLM employs Matryoshka Representation Learning (MRL) through a distillation process. This technique trains a single model capable of producing nested embeddings where prefixes of different lengths are independently useful.
- **Matryoshka Embedding Structure:** The student model is trained to generate embeddings up to a maximum dimension, d_max = 256. These embeddings are structured such that prefixes of specific lengths (e.g., 16, 32, 64, 128, 256 dimensions) can be truncated and still serve as functional representations.
- **Training Objective:** The total training loss (L_total) combines three components:
 1. **Contrastive Loss (L_contrastive):** An InfoNCE loss is applied to align image and text embeddings from the student model, encouraging similar embeddings for matching pairs and dissimilar embeddings for non-matching pairs.
 2. **Embedding Distillation Loss (L_emb):** This loss minimizes the Mean Squared Error (MSE) between the student's embeddings (projected to the teacher's dimension via a learnable matrix W_proj) and the teacher CLIP model's embeddings. This transfers knowledge from the larger teacher VLM.
 3. **Matryoshka Loss (L_mat):** This is the core innovation for flexible dimensions. It sums InfoNCE contrastive losses calculated across all specified Matryoshka dimensions (e.g., 16, 32, 64, 128, 256). This explicitly encourages the model to encode critical information in the earlier dimensions of the embedding vector.
- **Dimension Selection for Deployment:** At deployment, the optimal embedding dimension (d*) is selected based on the available flash memory for storing text embeddings and the number of candidate classes. This allows dynamic scaling of the embedding size to fit device constraints.

#### 3.3. MCU Deployment Optimizations

Several optimizations are implemented to ensure efficient deployment on MCUs:
- **Text Embedding Quantization:** Precomputed text embeddings, typically stored as float32, are quantized to 8-bit integers (INT8) using per-channel symmetric quantization. This reduces storage requirements by 4x, with a reported minimal accuracy loss (<1%). During inference, these INT8 embeddings are dequantized on-the-fly.
- **Memory Layout:** A specific memory layout is designed for MCU platforms. For example, on STM32H7, the model weights (892KB INT8) and quantized text embeddings (K × d INT8) reside in flash memory, while activations (285KB peak) and I/O buffers are managed in SRAM.
- **Inference Pipeline:** The on-device inference pipeline consists of:
 1. Image preprocessing (resizing to 128x128 and normalization).
 2. Forward pass through the quantized MobileNetV2 vision encoder.
 3. Truncation of the resulting image embedding to the chosen Matryoshka dimension (d*).
 4. Computation of cosine similarity between the image embedding and the stored quantized text embeddings.
 5. Prediction via argmax over the similarity scores.

#### 3.4. Training Details

The model is trained on Conceptual Captions 3M (CC3M) for 100 epochs using an AdamW optimizer. A CLIP ViT-B/32 model (512-dim embeddings) serves as the primary teacher. The effective batch size is 256, and a cosine learning rate schedule with 10 warmup epochs is utilized. Matryoshka dimensions (16, 32, 64, 128, 256) are weighted equally in the Matryoshka loss.

### 4. Main Findings and Results

The research presents several findings regarding TinyVLM's performance in zero-shot classification and detection, as well as its efficiency on MCU platforms.

#### 4.1. Zero-Shot Classification Performance

TinyVLM achieves zero-shot classification accuracy on standard benchmarks while operating within significantly smaller memory footprints compared to existing VLMs:
- On COCO, Flowers102, and Food101, TinyVLM (256-dim) achieved an average accuracy of 44.1%, compared to the CLIP ViT-B/32 teacher's 68.7% (with a memory footprint of 1.6MB vs. 350MB).
- Even at lower dimensions, such as 64-dim, TinyVLM attained an average accuracy of 39.3% with a memory footprint of 1.0MB.
- The results indicate that TinyVLM retains a portion of the teacher's accuracy despite memory reductions of two to three orders of magnitude.

#### 4.2. Matryoshka Dimension Analysis

The Matryoshka distillation strategy allows for flexible accuracy-memory trade-offs:
- Accuracy degrades gracefully as the embedding dimension decreases. For instance, the 64-dim configuration retained 82% of the 256-dim accuracy on COCO while requiring four times less embedding storage.
- Comparing to naive truncation of CLIP embeddings, Matryoshka training yielded significantly better performance at lower dimensions, validating the effectiveness of the training objective.
- The selection of embedding dimensions influences accuracy, with higher dimensions generally correlating with higher accuracy, as expected (e.g., 256-dim COCO accuracy was 33.8% compared to 16-dim at 19.8%).

#### 4.3. Zero-Shot Detection Performance

TinyVLM was adapted for zero-shot object detection by adding a simple detection head for classifying region proposals:
- TinyVLM-Det (128-dim) achieved an AP50 of 15.2% on COCO and 10.8% on LVIS.
- TinyVLM-Det (64-dim) achieved an AP50 of 12.4% on COCO and 8.6% on LVIS.
- These results demonstrate the first reported instance of zero-shot detection on MCUs, albeit with accuracy lower than larger models like OWL-ViT or YOLO-World, which require significantly more memory.

#### 4.4. MCU Benchmarks

Deployment benchmarks across four different MCU platforms demonstrate the practical viability of TinyVLM:
- **Real-time Inference:** All tested platforms achieved real-time performance. MAX78000, with its CNN accelerator, processed images at 1,160 FPS with a latency of 0.86ms. STM32H7 achieved 26 FPS (38ms latency), GAP9 achieved 55 FPS (18ms latency), and ESP32-S3 achieved 19 FPS (52ms latency).
- **Memory Footprint:** The deployed vision encoder (INT8) occupied 892KB of flash memory. SRAM usage varied by platform; for instance, STM32H7 required 285KB peak for activations, while MAX78000 utilized only 6KB for runtime variables due to its dedicated CNN weight memory.
- **Energy Efficiency:** The MAX78000 demonstrated superior energy efficiency at 0.016 mJ per inference, significantly outperforming STM32H7 at 2.1 mJ per inference.

#### 4.5. Ablation Studies

Ablation studies provided insights into the contributions of different components:
- **Loss Components:** Including all loss components (contrastive, embedding distillation, and Matryoshka loss) resulted in the highest accuracy (e.g., 33.8% for 256-dim on COCO), indicating their collective importance.
- **Matryoshka Dimension Weighting:** Equal weighting for Matryoshka dimensions yielded the best balance across different prefix lengths compared to inverse or logarithmic weighting schemes.
- **Teacher Model:** Using larger and more accurate teacher models (e.g., CLIP ViT-L/14 or OpenCLIP ViT-G/14) led to slightly higher student accuracy, but with a slight decrease in retention percentage.
- **Embedding Quantization:** Quantizing text embeddings to INT8 reduced storage by 4x (from 20KB to 5KB for 80 COCO classes, 64-dim) with a minimal accuracy loss of 1.2% compared to float32. Even INT4 quantization was explored, incurring a 5.0% accuracy drop.

#### 4.6. Qualitative Results

t-SNE visualizations of TinyVLM image embeddings showed meaningful cluster structures for different classes despite aggressive dimensionality reduction. Qualitative predictions also illustrated the model's ability to identify objects in various contexts, including some misclassifications with confidence scores.

### 5. Significance and Potential Impact

TinyVLM represents a advancement in the deployment of advanced AI capabilities to highly resource-constrained edge devices. Its primary significance lies in being the first framework to enable zero-shot object detection on microcontroller units (MCUs) with memory footprints under 1MB. This achievement addresses a long-standing challenge in the TinyML community, bridging the gap between powerful Vision-Language Models (VLMs) and the stringent requirements of embedded systems.

**Key Contributions and Significance:**
- **Enabling Zero-Shot on MCUs:** By demonstrating zero-shot object detection on devices with limited memory (e.g., 285KB RAM and 892KB flash for the vision encoder), TinyVLM opens up possibilities for intelligent systems that can recognize novel objects without requiring continuous retraining or model updates. This capability is crucial for scenarios where target objects are unpredictable or frequently change.
- **Architectural Innovations:** The decoupled architecture, which separates visual inference from offline text encoding, is a fundamental shift for resource-constrained VLM deployment. This strategy significantly reduces real-time memory and computational load on the MCU, allowing for more efficient operation.
- **Flexible Deployment with Matryoshka Distillation:** The integration of Matryoshka distillation allows a single trained model to adapt to various memory budgets by truncating embeddings to different dimensions (16-256). This flexibility simplifies deployment across a heterogeneous landscape of MCU platforms with diverse capabilities, optimizing the accuracy-memory trade-off for each specific device.
- **Practical Edge AI Applications:** The demonstrated real-time inference speeds (26 FPS on STM32H7 and over 1,000 FPS on MAX78000) coupled with low energy consumption (0.016 mJ per inference on MAX78000) make TinyVLM suitable for practical, battery-powered edge AI applications. This could lead to:
 - **Adaptive Wildlife Monitoring:** Systems that identify new or rare species without pre-trained data.
 - **Industrial Inspection:** Devices that detect novel defects or anomalies on manufacturing lines.
 - **Accessibility Devices:** Tools that describe arbitrary objects for visually impaired users.
 - **Smart Home Systems:** Recognition of user-specified items in a dynamic environment.

**Potential Impact:**
The development of TinyVLM has the potential to expand the utility of embedded AI significantly. It could democratize access to advanced zero-shot capabilities, making them available in a broader range of low-cost, low-power devices. This could foster innovation in various sectors, from environmental conservation to personal robotics and healthcare, by enabling devices to understand and interact with their environments more intelligently and adaptably.

**Limitations and Future Work:**
The paper acknowledges several limitations and outlines future research directions:
- **Accuracy Gap:** A significant accuracy gap still exists between TinyVLM and larger CLIP models, particularly for fine-grained categories. Future work will explore more sophisticated distillation techniques to narrow this gap.
- **Closed-Set Assumption:** The current approach relies on a closed-set assumption where candidate classes are known and text embeddings are precomputed. Extending to truly open-vocabulary detection would require on-device text encoding, which presents further challenges for MCU constraints.
- **Detection Quality:** The compact vision encoder's feature quality inherently limits the overall detection quality, particularly for complex scenes or small objects.
- **Scaling with Class Count:** Text embedding storage scales linearly with the number of classes, practically limiting deployment to approximately 1,000 classes on most MCUs. Hierarchical classification or class clustering could be explored for larger vocabularies.
- **Broader Impact Considerations:** The deployment of object detection systems, even on MCUs, raises privacy concerns, particularly in public spaces. The authors encourage thoughtful deployment with appropriate safeguards.

Future research aims to evaluate advanced compression techniques (such as MCUBERT-style clustering, linear attention, and fused-weight self-attention) more comprehensively. Additionally, exploration into larger student models as MCU capabilities evolve, combining TinyVLM with on-device continual learning, and improving distillation strategies are planned.
