# Programming-by-Demonstration for Long-Horizon Robot Tasks

> [!summary] Summary
> PROLEX is a programmatic learning-from-demonstration synthesizer that learns robot policies as DSL programs with nested loops and conditionals for long-horizon household tasks. It abstracts demonstration traces into strings, learns regexes to infer control-flow sketches, then completes sketches via BERT-guided top-down search that prunes dead ends by proving unrealizability. Within 120 seconds it finds consistent programs for 80% of 120 benchmarks, recovering ground truth in 81% of those.

## Problem

- Most programmatic LfD methods learn simple Markovian decision-list policies choosing the next action from the current state, so they cannot express nested loops and conditionals.
- Prior programmatic LfD was applied to restricted domains like robot soccer with few, a-priori-known entities, not environments with thousands of objects and relations.
- Existing unrealizability proofs reason only about programming-by-example input-output behavior, not full traces, while SyGuS encodings cannot express demonstrations' intermediate states at all.

## Method

- ==Regex-based sketch inference==: typed action-string abstractions of traces are unified by a learned regex; syntax-directed rules map ==Kleene star== to foreach loops, optionals to conditionals, and perception-completeness inserts required scans.
- ==Trace-compatibility unrealizability check== (**ProgToRegex**): partially evaluates a partial program, over-approximates all completions' traces as a regex with loop-iteration counts via abstract environments, and prunes it when the demonstration string is rejected.
- ==LLM-guided sketch completion==: a probability-ordered top-down search fills holes using ==BERT masked-language-model== prompts that render the partial program in natural language and score candidate object types, properties, and relations.

## Results

- On 120 benchmarks (40 household tasks including 25 from BEHAVIOR, across three environments up to 1109 objects), PROLEX completes **80%** within **120 seconds**; **81%** of completed programs match ground truth from one demonstration.
- Ablations: without regex sketches **no task** is solved; full PROLEX solves **19% more** than NoPrune, **24% more** than SketchOnly, and **8% more** than both NoLLM and NoLoopBound.
- CVC5, even given ground-truth sketches, solves **25%** of easy-environment tasks versus PROLEX's **88%**; GPT-3.5-based GPT-Synth solves **none** with full environments, failing already with **10 distractor objects**.

## Takeaways

> [!tip] Key Insights
> - Regular expressions over type-abstracted traces are a cheap, Occam-biased route to control-flow structure: loops and branches fall out of Kleene star and optional operators.
> - End-to-end LLM synthesis collapses as environment entities grow; using a small language model only as a semantic prior inside sound symbolic search scales far better.
> - Demonstrations must be branch-complete and contain multiple instances per type; richer, cluttered environments paradoxically improve generalization by leaving fewer programs that touch exactly the demonstrated objects.

## Detailed Report

### 1. Overview

A hotel worker wants a robot to collect dirty sheets from guest rooms and put them in the room’s laundry bin. In the first room, one sheet is dirty and one is clean. In the second, two sheets are dirty. The worker’s 12-action demonstration shows the robot opening each bin, moving the relevant sheets, and closing the bin. Copying those actions does not tell a robot how to identify dirty sheets, find beds, or repeat the task in other rooms.

PROLEX (“Programming Robots with Language Models and Regular Expressions”) addresses this gap. It turns the action sequence into a simplified pattern and infers a program outline from the repetitions and choices in that pattern. It then fills the outline’s blanks. For this example, the authors’ desired policy uses loops and a property-and-relation test to select dirty sheets.

(b) Three regexes that match the abstract trace, with the intended one highlighted. (c) The resulting sketch with holes, including nested loops L1–L3 and a conditional C1. (d) The completed policy. Colored outlines link regex structure to sketch control flow.

### 2. From action pattern to policy outline

First, PROLEX abstracts the trace by action and argument type, removing specific object identities. It then learns regular expressions that match the abstract strings. A regular expression is a compact description of a sequence pattern. In this setting, repetition (Kleene star) maps to a loop, and an optional part maps to a conditional.

PROLEX translates candidate expressions into program sketches. It also adds the perception operations needed to find objects or locations before acting on them. A sketch has the program’s broad structure, but it leaves unknowns, such as scanned object types and conditional predicates, as holes.

In the sheets example, a sketch can indicate nested iteration over rooms, beds, and sheets. The action pattern alone cannot determine which property makes a sheet eligible, so PROLEX searches for completions. Its language model, BERT base uncased, assigns probabilities to candidate fills in context. As a result, semantically plausible choices are considered earlier. This guides the search, but it does not guarantee that the model knows user intent.

### 3. Pruning dead ends, and testing the claim

For an unfinished program, PROLEX statically builds a conservative regular-expression description of the traces its possible completions could produce. If the demonstrated trace falls outside that over-approximation, no completion of that partial program can match the demonstration. PROLEX can therefore discard it. An accepted trace, by contrast, does not establish that a valid completion exists.

The benchmark’s 120 cases combine 40 household tasks and three environments, from Easy (140 object instances) to Hard (1,109 instances). The test used one demonstration per task, obtained by running the manually written ground-truth program. Within 120 seconds, PROLEX produced a policy consistent with the demonstration in 80% of cases. A policy consistent with the demonstration does not necessarily capture the intended task. Of the completed cases, 81% were manually judged semantically equivalent to the ground-truth policy.

The strongest mechanism test removes unrealizability checking. The authors report PROLEX solves “19% more tasks” than this NoPrune variant. They also report that removing regex-based sketch generation leaves none of the tasks solved. These results show that the components contribute within this implementation. They do not show that any single component is the sole cause of success.

(a) Success rate against cumulative time across all environments for PROLEX and its ablations. (b) PROLEX versus CVC5 in the Easy environment only, ending at 88% and 25%. CVC5 is given the ground-truth sketch and is evaluated from initial and final states rather than the intermediate trace.

The CVC5 comparison is not like-for-like. SyGuS could not express the demonstrations’ intermediate states, and the comparison is restricted to Easy because encoding environments for SyGuS required manual work.

### 4. Scope

PROLEX’s demonstrated contribution is a synthesis pipeline that combines structural inference, guided completion, and trace-based pruning. The evidence comes from benchmark tasks in simulated household environments. Physical-robot deployment is future work.
