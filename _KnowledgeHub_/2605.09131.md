# MCP-Cosmos: World Model-Augmented Agents for Complex Task Execution in MCP Environments

> [!summary] Summary
> Researchers at IBM introduced MCP-Cosmos, a framework that augments LLM agents with generative World Models within Model Context Protocol environments, enabling predictive planning. This allows agents to simulate actions and refine plans in a latent space, leading to more efficient and successful task execution with a 100% tool call success rate and fewer redundant actions compared to reactive baselines.

## Problem

- Reactive LLM agents often suffer from "horizon myopia," leading to inefficient actions, redundant tool calls, and potential irreversible state failures in complex environments.
- Traditional planning-centric frameworks generate high-level plans based on static tool definitions, which often fail to account for dynamic environmental changes or stochastic tool outcomes.
- Existing evaluation metrics for agent performance primarily focus on task completeness, overlooking critical aspects of execution quality such as tool call efficiency and success rates.

## Method

- The **MCP-Cosmos** framework integrates generative World Models (WMs) into the Model Context Protocol (MCP) agent architecture, enabling a "Predictive Cognition" paradigm.
- Agents first engage in a "Planning with ==World Model== Simulation" phase, where they iteratively generate and simulate action sequences in a latent space to select an optimal execution plan.
- This is followed by a "Plan Execution in Real Environment" phase, where the vetted plan is executed using real MCP tools, with an optional mechanism for dynamic plan adjustment.

## Results

- WM-infused agents achieved a **100%** tool call success rate and significantly reduced the average number of tool calls, outperforming the ReAct baseline's **77.7%** success rate and higher call count.
- Incorporating the "Execution Quality" metric revealed that WM-augmented agents, such as SPIRAL-Exec + GPT-OSS-120B-WM, achieved the highest adjusted overall score of **56.5%**, demonstrating superior practical deployment efficiency.
- While WM-augmented agents incurred higher token consumption (**66%** to **504%** more per task) during planning, this overhead led to more efficient real-world execution, fewer failures, and better management of powerful planners' explorative tendencies.

## Takeaways

> [!tip] Key Insights
> - Infusing World Models into agent architectures enables agents to perform speculative look-ahead searches and refine plans proactively, mitigating the limitations of purely reactive or static planning.
> - Explicit World Models are crucial for guiding even powerful LLM planners, as they constrain extensive and costly exploration in live environments by forcing commitment to vetted plans derived from simulation.
> - The introduction of an "Execution Quality" metric, which accounts for tool call success rate and efficiency, effectively highlights the practical benefits of WM-augmented agents that traditional task-completion metrics might miss.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

The research operates within the domain of artificial intelligence, specifically focusing on the capabilities of Large Language Models (LLMs) when augmented with external tools. The Model Context Protocol (MCP) has been established to standardize the interface between LLMs and these tools, facilitating sophisticated agentic workflows.

Existing paradigms for tool-augmented LLM agents exhibit a tension between two primary architectural approaches. On one hand, planning-centric frameworks often prioritize high-level decision-making based on static tool definitions. These frameworks, exemplified by TaskBench, tend to overlook the dynamic and stochastic nature of real-world environments, potentially leading to plans that are not robust during execution. On the other hand, execution-centric benchmarks, such as MCP-Bench, employ reactive paradigms like ReAct. While these agents can navigate environments through interleaved observation and action, they often suffer from "horizon myopia," meaning they struggle to anticipate long-term consequences. This can result in inefficient behaviors such as redundant tool calls or actions leading to irreversible state failures.

The integration of world models into agent architectures is a growing area of research, with applications spanning reinforcement learning, robotics, and multimodal generation. These models learn predictive representations of environment dynamics, enabling planning, reasoning, and decision-making by simulating future states and outcomes. Recent work has explored scalable architectures, test-time rollouts, and systematic evaluation of world models. Within MCP environments, there has been recent attention to creating synthetic environments and training reinforcement learning-based world models, such as the Agent World Model (AWM) series.

This work, MCP-Cosmos, positions itself as a development that addresses the identified gap in agent conceptualization of environments. It proposes to unify three distinct technologies—MCP, World Models, and Agent architectures—to move beyond purely reactive or static planning. By infusing generative World Models into the MCP ecosystem, the framework aims to enable predictive task automation. This approach allows agents to simulate state transitions and refine plans in a latent space prior to committing to real-world execution, thereby mitigating the limitations of existing reactive and planning-centric methods and contributing to the evolution of world model-specific evaluation methods in MCP environments.

### 2. Key Objectives and Motivation

The central objective of this research is to significantly enhance the performance of task automation in Model Context Protocol (MCP) environments by integrating generative World Models (WMs) into agent architectures. This integration aims to shift the operational paradigm from purely reactive execution to "Predictive Cognition."

The motivation for this work stems from several fundamental limitations observed in current LLM-based agent systems operating within tool-augmented environments:

1. **Addressing Horizon Myopia in Reactive Agents:** Existing reactive agents, while capable of navigating complex environments, frequently exhibit "horizon myopia." This refers to their limited ability to anticipate the downstream consequences of their actions. This short-sightedness can lead to suboptimal decision-making, including repetitive or redundant tool calls, and potentially irreversible environmental state failures. The research aims to counteract this by enabling agents to perform speculative look-ahead searches.
2. **Mitigating Execution Failures and Resource Waste:** In real-world MCP environments, executing tool calls can incur costs (computational, financial, or time-based) and carry risks of failure. Current approaches often learn through trial-and-error in the live environment. The motivation is to enable agents to simulate tool calls in a latent space, allowing them to assess the impact of actions and identify potential failures or inefficiencies before interacting with actual tools. This predictive capability is expected to reduce tool call failures and minimize the necessity of unnecessary or redundant real-world interactions.
3. **Refining Plans Proactively:** Traditional planning-centric frameworks often generate high-level plans based on static tool definitions, which may not account for the dynamic environment or stochastic outcomes of tool execution. The research is motivated by the need for agents to refine their action trajectories proactively. By internalizing the environment's transition dynamics, represented as P(s_{t+1}|s_t, a_t), agents can iteratively generate and revise plans using simulated observations, thereby developing more robust and efficient execution strategies.
4. **Unifying Disparate Technologies:** The Model Context Protocol (MCP) has standardized tool integration, but a cohesive framework for agents to conceptualize and predict environment dynamics within this protocol was lacking. The work is motivated by the potential to unify MCP, World Models, and Agent architectures into a single, modular system. This "Bring Your Own World Model" (BYOWM) strategy aims to allow diverse World Models to be integrated, fostering flexibility and innovation in agent design.
5. **Developing Enhanced Evaluation Metrics:** The paper identifies limitations in existing evaluation methodologies that prioritize task completeness over execution efficiency and quality. For instance, an agent might achieve a task despite numerous failed or inefficient tool calls. A key motivation is to propose and validate new evaluation metrics, such as "Execution Quality," that specifically measure the usefulness of world models in guiding efficient tool usage, avoiding failures, and reducing operational overhead. This aims to provide a more comprehensive assessment of agent performance in practical deployment scenarios.

In summary, the core motivation is to instill predictive intelligence into MCP agents through World Models, moving beyond reactive execution to achieve more efficient, reliable, and cost-effective task automation by reasoning in a simulated environment before acting in the real one.

### 3. Methodology and Approach

The MCP-Cosmos framework integrates World Models (WMs) into the Model Context Protocol (MCP) interaction loop to enable predictive task automation. The approach is structured into two main phases: proactive planning utilizing WM simulations and subsequent execution in the real environment.

#### 3.1. Overall Architecture and Workflow

The framework proposes a "Bring Your Own World Model" (BYOWM) strategy, allowing for the integration of heterogeneous WMs. The agent workflow is formalized in Algorithm B and depicted in Figure 2.

**Phase 1: Planning with World Model Simulation**
In this initial phase, the agent leverages an initialized world model instance to simulate potential action sequences without incurring the costs or consequences of real-world execution.
- **Initialization:** The process begins with an initial state derived from the user's task instruction.
- **Iterative Action Generation and Simulation:** The agent iteratively generates tool calls ($a_t$) using a planning policy ($\pi_{plan}$). For each generated action, the World Model's `simulate` method predicts a "simulated (pseudo) observation" ($\tilde{o}_t$). This simulated observation can be varied in format and capacity, from a summary explanation to simulated data, providing insights into the expected outcome without actual execution.
- **Trajectory Accumulation:** These action-simulated observation pairs are accumulated in a "world model trajectory" ($\tau_{wm}$), which captures the agent's simulated exploration of multiple potential paths.
- **State Update and Termination:** The agent's internal state is updated based on these simulated observations, allowing for reasoning about future states and informed decision-making. This iterative process continues until a predefined maximum number of steps is reached or a termination criterion is met.
- **Optimal Plan Selection:** From the accumulated world model trajectory ($\tau_{wm}$), an optimal execution plan (P) is selected. This selection can be achieved using non-deterministic policy models (e.g., an LLM) or deterministic algorithms (e.g., reward-based Monte Carlo Tree Search, MCTS). The selected plan consists of a sequence of tool calls and their associated parameters.

**Phase 2: Plan Execution in Real Environment**
Once an optimal plan is selected, the agent proceeds to execute it in the actual MCP environment.
- **Real-World Execution:** Each action ($a_t$) in the selected plan (P) is executed using real MCP tools, and the agent receives real observations ($o_t$).
- **Execution Trajectory:** Successfully executed action-observation pairs are recorded in an "execution trajectory" ($\tau$).
- **Optional Plan Adjustment:** Although excluded from the benchmarking pipeline due to its expensive nature, the framework includes an optional plan adjustment mechanism ($\pi_{plan\_adjust}$) to modify the remaining plan if an action fails during real-world execution, thereby enhancing robustness.
- **Final Answer Synthesis:** Upon completion of the plan execution, the agent synthesizes a final answer using summarization or other generation techniques based on the execution trajectory.

#### 3.2. World Model and Agent APIs

- **`WorldModel` Abstract Class (Listing 1):** Defines a standard interface for world models, requiring initialization with a `model_name` and a `simulate` method. The `simulate` method takes a `tool_call` string, `user_request`, and optional `context` as input, returning a simulated tool response.
- **`WMInfusedAgent` Class (Listing 2):** Defines an agent class that takes a `world_model` instance as input during initialization, indicating how WMs are integrated into the agent's `execute` method.

#### 3.3. Experimental Setup

- **Dataset:** The evaluation utilized **MCP-Bench** as the primary dataset, chosen for its ecosystem-scale complexity (28 live MCP servers, 257 cross-domain tools), realistic fuzzy-instruction tasks, rigorous rule-based and judge-based metrics, and difficulty stratification. A cost-effective subset of 24 tasks was curated, focusing on 2- and 3-server scenarios to emphasize cross-domain tool dependencies. This selection resulted in over 300 trajectories across 12 unique task types.
- **Agent Architectures:**
 1. **ReAct (Baseline):** A standard reasoning and acting agent without World Model capabilities.
 2. **ReAct-Plan-Exec:** An extended ReAct agent that generates a proactive plan using action generation and world model simulation before executing it.
 3. **SPIRAL-Exec:** An advanced agent employing Monte Carlo Tree Search (MCTS) assisted by an LLM-based Planner and Simulator, using the World Model for predictive simulation.
- **World Model Configurations:** Three distinct WMs were evaluated:
 - **GPT-OSS-120B:** An LLM-based world model.
 - **Claude-Sonnet-4.6:** An LLM-based world model.
 - **Arctic-AWM-4B:** A purpose-built Agent World Model (AWM) trained on MCP environments.
- **Planner Baseline:** GPT-OSS-120B was selected as the default planner model.
- **Judge:** The `o4_mini` judge from MCP-Bench was used for evaluation.
- **Ablation Study:** An additional study replaced the GPT-OSS-120B planner with Claude-Sonnet-4.6 to assess if a stronger planner could compensate for the absence of an explicit world model.

#### 3.4. Evaluation Metrics

The research employed a hierarchical evaluation framework from MCP-Bench, augmented with new metrics:
- **Original MCP-Bench Metrics:**
 - **Task Completion:** Aggregates task requirement fulfillment and groundness of final answer claims.
 - **Tool Selection:** Aggregates appropriate tool choice and accuracy/completeness of parameter selection.
 - **Planning Effectiveness:** Aggregates parallelism in tool execution and ordered execution of tool dependency chains.
 - **Overall Score:** A high-level measure of task success rate, synthesized as the mean of Task Completion, Tool Selection, and Planning Effectiveness.
- **New Metrics (Execution Quality):**
 - **Execution Quality:** Defined as the average of `tool call success rate` and `normalized average number of tool calls`. The `normalized average number of tool calls` is computed as $(max\_avg\_calls - agent\_avg\_calls) / (max\_avg\_calls - min\_avg\_calls) \times 100$, penalizing excessive retries and rewarding efficient execution.
 - **Adjusted Overall Score:** Incorporates the Execution Quality score along with the three original aggregated metrics.

### 4. Main Findings and Results

The experiments conducted within the MCP-Cosmos framework provide several findings regarding the efficacy of World Model (WM) infusion into agent planning and execution.

#### 4.1. Performance Comparison with Baseline (Table 1)

- **Overall Performance Improvement:** WM-infused agents (ReAct-Plan-Exec and SPIRAL-Exec) generally achieved better overall scores compared to the ReAct baseline using GPT-OSS-120B as the planner. Specifically, SPIRAL-Exec + GPT-OSS-120B-WM demonstrated the highest overall score at 44.8%, followed by ReAct-Plan-Exec + Claude-Sonnet-4.6-WM at 42.4%.
- **Targeted Improvements by WMs:** WM-infused agents consistently outperformed the baseline ReAct in "Parameter Accuracy," "Parallel Efficiency," and "Tool Selection." This indicates that world models facilitate more precise tool parameterization and enable more efficient, possibly parallel, tool execution strategies.
- **Baseline Strengths:** The ReAct baseline remained stronger in "Task Fulfillment," "Dependency Awareness," and overall "Task Completion." This suggests that while WMs improve aspects of execution efficiency and selection, the baseline's direct interaction and error-recovery loops were more effective in ensuring the final completion of complex tasks under the initial evaluation metrics.
- **WM Model Efficacy:** Arctic-AWM-4B-WM, a purpose-built MCP world model, was less effective than the general-purpose LLM-based world models (GPT-OSS-120B and Claude-Sonnet-4.6) across most configurations.

#### 4.2. Token Consumption Analysis (Table 5 & 6)

- **Computational Overhead:** The baseline ReAct agent was the most token-efficient, consuming an average of 49,995 tokens per task with the GPT-OSS-120B planner. WM-augmented agents incurred significantly higher token consumption, ranging from 66% to 504% more per task. SPIRAL-Exec + Arctic-AWM-4B-WM exhibited the highest token usage, approximately 6 times that of the baseline (301,908 tokens/task).
- **Prompt Dominance:** Prompt tokens consistently dominated output tokens across all methods, typically by a factor of 9x, indicating that the primary driver of token cost is context retention and prompt construction for reasoning.
- **Planner Impact:** With the Claude-Sonnet-4.6 planner, the token usage profile shifted. ReAct-Plan-Exec + Arctic-AWM-4B-WM became relatively more token-efficient (95,993 tokens/task), even slightly below the ReAct baseline (99,126 tokens/task), suggesting that planning with AWM can be token-efficient with a powerful planner. However, SPIRAL-Exec + Arctic-AWM-4B-WM remained a high-cost outlier (686,772 tokens/task) cumulatively.

#### 4.3. Execution Quality Metric and Adjusted Overall Score (Table 2)

- **Revealed Gap in Baseline:** The ReAct baseline, despite having the highest "Task Fulfillment," exhibited a lower "tool call success rate" (77.7%) and the highest average number of tool calls (7.04). This indicated that ReAct frequently made unsuccessful tool calls but compensated through retries to eventually complete tasks.
- **WM-Infused Efficiency:** All WM-infused agents achieved a 100% tool call success rate and a significantly lower average number of tool calls.
- **Execution Quality Impact:** The introduction of the "Execution Quality" metric, which penalizes excessive tool calls and rewards success, revealed a substantial advantage for WM-infused agents. SPIRAL-Exec + GPT-OSS-120B-WM achieved an "Execution Quality" score of 91.4, dramatically improving its overall ranking.
- **New Overall Scores:** With the inclusion of "Execution Quality," the adjusted "Overall" scores highlighted the superior practical deployment performance of WM-augmented agents. SPIRAL-Exec + GPT-OSS-120B-WM achieved the highest adjusted overall score at 56.5%, demonstrating that WMs are effective in guiding efficient and successful tool usage.

#### 4.4. Ablation Study (Table 3 & 4)

- **Stronger Planner vs. WM:** Replacing the GPT-OSS-120B planner with the more capable Claude-Sonnet-4.6 indeed improved the ReAct baseline's accuracy metrics, particularly tool-call success rate. However, this came at a significant cost to efficiency. The Claude-Sonnet-4.6 baseline issued 29.78 tool calls per task on average (more than 4x the GPT-OSS baseline) and incurred a 3.4x slowdown in execution time (214.9s vs. 63.7s).
- **Planner Behavior Change:** The stronger planner exhibited a qualitative shift in strategy, engaging in a wider action space exploration and speculative batching of multiple parallel calls per reasoning step.
- **WMs Constrain Powerful Planners:** When Claude-Sonnet-4.6 was paired with a world model, the aggressive exploration was suppressed. SPIRAL variants dropped to 1.83–1.92 tool calls per task, and ReAct-Plan-Exec variants to 6.91–7.91, comparable to or even below configurations with the weaker planner. The world model's simulation step forced the planner to commit to a vetted plan rather than probe the live environment.
- **Implication:** A stronger planner does not substitute for an explicit world model on the efficiency axis. Instead, the presence of a world model becomes more critical with powerful planners to constrain their extensive exploration and manage the associated latency and costs.

### 5. Significance and Potential Impact

The MCP-Cosmos framework and its associated findings present several significant contributions and potential impacts on the field of LLM-based agents and their application in complex, tool-augmented environments.

1. **Advancement in Agentic Intelligence:** By integrating generative World Models into the Model Context Protocol (MCP) ecosystem, this work introduces "Predictive Cognition" to agentic planning. This represents a methodological advancement over purely reactive or static planning approaches, enabling agents to reason about future states and consequences before committing to real-world actions. This capability can lead to more intelligent and foresightful autonomous systems.
2. **Enhanced Operational Efficiency and Cost Reduction:** The ability of World Models to simulate state transitions and refine plans in a latent space before execution can significantly reduce the need for trial-and-error in live environments. This translates directly into:
 - **Reduced Tool Call Failures:** As demonstrated, WM-infused agents achieve higher tool call success rates.
 - **Minimized Redundant Actions:** Proactive planning helps avoid unnecessary or repetitive tool calls, which can be costly in terms of API usage, computational resources, and execution time.
 - **Improved Resource Utilization:** By shifting a portion of the reasoning process to a simulated environment, physical execution resources are conserved, leading to more robust and cost-effective deployments, particularly in production systems.
3. **Improved Robustness and Reliability:** Agents augmented with World Models can anticipate potential problems and adjust their plans preemptively, making them more resilient to the stochasticity and unexpected dynamics of real-world environments. This increased robustness is crucial for deploying AI agents in critical applications.
4. **Novel Evaluation Paradigm for World Models:** The introduction of the "Execution Quality" metric addresses a notable gap in existing evaluation methodologies. By explicitly quantifying an agent's ability to guide efficient, targeted tool usage with minimal exploratory overhead, this metric provides a more practical and deployment-relevant measure of performance. It offers a standardized way to assess the true value of world models in agent planning, guiding future research and development towards more efficient and less wasteful AI systems.
5. **Modular and Extensible Architecture:** The "Bring Your Own World Model" (BYOWM) strategy promotes modularity and extensibility. This allows for the integration of diverse World Models, fostering innovation and enabling researchers to experiment with different predictive models tailored to specific tasks or environmental complexities within the standardized MCP framework.
6. **Guidance for Powerful Planners:** The ablation study's finding that World Models constrain powerful planners, preventing excessive and costly exploration, is particularly significant. It suggests that as LLMs become increasingly capable, the role of explicit world models becomes even more critical in guiding their intelligence towards efficient and focused execution, rather than simply letting them explore a vast action space at high cost.
7. **Foundation for Future Research:** MCP-Cosmos provides a robust framework for further exploration into various aspects of World Models in agent systems, including adapting to dynamic environments, managing computational overhead, enhancing interpretability, and addressing complex challenges like managing write operations or destructive tools.

In essence, MCP-Cosmos represents a step towards creating more intelligent, efficient, and reliable autonomous agents capable of handling complex tasks in diverse real-world settings by equipping them with the power of predictive foresight.
