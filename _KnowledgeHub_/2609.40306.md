# DynaHarness: A Dynamic Physical Harness for Self-Evolving Robot Agents

> [!summary] Summary
> DynaHarness is a dynamic physical harness for long-horizon manipulation. A Qwen3-VL-4B slow brain proposes capabilities, and a deterministic 2 Hz fast brain grounds, monitors, refuses, substitutes and replans them. One execution contract covers analytic skills, recovery skills and a frozen π0.5. Its execution records drive failure attribution and gated capability revisions, reaching 75.2% on new LIBERO-Pro states versus 17.5% for the policy.

## Problem

- Agentic harnesses plan at a coarse timescale, yet contact, progress and transient success happen between planning decisions, so no explicit authority governs the running physical command.
- Self-improving robot agents repair or expand a fixed library, but task failures may arise in planning, grounding, execution, verification or recovery without being localized.
- Episode-level outcomes give little guidance on which component to revise, and local fixes can silently regress other tasks that share the same capability library.

## Method

- ==Fast-slow architecture==: the Qwen3-VL-4B ==slow brain== emits only a capability name plus symbolic arguments. The deterministic 2 Hz ==fast brain== resolves geometry, monitors progress, refuses, substitutes or requests replans.
- ==Physical execution contract==: each robot command must be grounded, bounded by a step budget, lease and 50 Hz safety check, and end on a ==latched verdict==, with all evidence logged, including refusals.
- ==Attribution-driven self-evolution==: offline diagnosis assigns each failure to the first of N ordered layers. This directs revisions stated in physical quantities, admitted only through ==paired regression gates== plus broader validation.

## Results

- On the LIBERO-Pro development block, it scores **74.25%** versus **20.3%** for PhyAgentOS and **6.0%** for Harness VLA, using the same Qwen3-VL-4B and frozen π0.5. On **800** new states: **75.2%** versus **17.5%**.
- With the same library, full dynamic execution reaches **74.0%**, versus **63.9%** for nominal one-step replanning and **63.8%** for a frozen sequence. Removing **seven** analytic contact skills drops success to **16.6%**.
- Frozen snapshots keep their development ranking on new states (**Spearman 1.00**), with a **14.3-point** gain becoming **14.4**. Latching raises a transient-success task to **95%**. Real-robot tasks reach **70-90%**.

## Takeaways

> [!tip] Key Insights
> - Analytic contact skills, not the frozen VLA, carried task competence. Harness gains on perturbed benchmarks may reflect the hand-built capability library more than better orchestration of learned policies.
> - Detecting unproductive execution is not the same as fixing it. Failures burn their whole budget, yet replacing those suffixes gave no significant gain, so monitors need effective replacement actions.
> - A revision that passed its local paired gate still lost 79 successes elsewhere. Shared capability libraries need broad regression validation beyond the cells that motivated each fix.

## Detailed Report

### 1. Overview

DynaHarness targets a practical mismatch in long-horizon robot manipulation. A language-model planner reasons too slowly to govern every physical event. An episode-level failure also often does not reveal which part of the system needs repair. The approach gives a fast controller authority over each running command. The slower planner proposes a capability and symbolic arguments. The fast controller grounds and monitors the command, can refuse or substitute it, and can request a new plan.

In one LIBERO-Pro simulation, the robot is asked to push a plate. The slow planner proposes a push that the gripper cannot perform, so the fast controller refuses it and substitutes a pick-and-place route. The robot completes the task in 246 steps within a 300-step budget. The frozen policy fails on the same seed after using the budget. This is an illustrative episode, not an estimate of average performance.

### 2. One command, one authority

The system runs on two timescales. The slow Qwen3-VL-4B planner proposes a capability and symbolic arguments on demand. The fast brain makes deterministic physical-governance decisions at 2 Hz, while control runs at 20 Hz.

The fast brain resolves geometry and preconditions, and it refuses unresolved commands with a reason. It also monitors progress and completion. While a command runs, it can continue, recover, substitute another capability, or request a replan.

One contract applies across analytic skills, recovery skills, and the frozen π0.5 vision-language-action (VLA) policy. The contract bounds each command by budget and lease and checks safety at 50 Hz. It records refusals and outcomes, and it ends commands on recorded completion or failure conditions. Because refusals are recorded, a later diagnosis can distinguish an unresolved command from an admitted capability that failed.

These records drive later repair. The system labels a failure using the earliest matching check among 13 ordered diagnostic layers. It treats that label as a hypothesis to guide a probe and a revision expressed in physical quantities rather than a task-specific branch. A paired gate checks the revision on matched suite/task/seed cases, and admission also requires broader regression checks.

The paired gate alone is not enough. One candidate passed its paired gate but cost 79 successes across five stove-hob cells in a full round, so it was reverted.

### 3. Does dynamic execution pay off?

The metric is LIBERO-Pro success rate. It is the number of episodes meeting the benchmark's success predicate divided by the full episode denominator, and episodes lost to evaluation infrastructure count as failures. The main setup has four cells: Goal and LIBERO-10, each with instruction-redirection or object-swap perturbations. Each cell has 10 tasks with 20 episodes per task, for 800 episodes.

The first comparison isolates dynamic execution from ordinary replanning. It uses the same 800 development episodes and the same capability library. Full dynamic execution scores 74.0% success, versus 63.9% for A2static. A2static keeps nominal replanning after successful skills but disables failure-triggered replanning, substitution, reordering, recovery insertion, and verifier-conditioned branching. The difference is 10.125 points, with 89 Full-only versus 8 A2static-only wins and a 95% cell-bootstrap interval of [3.375, 18.250] points. This supports the dynamic responses as a joint package. It does not identify the contribution of any single branch. These are development-block results, not unseen-task tests.

The second comparison tests new starting states. The authors froze the selected system, then generated 800 new initial states across the same 40 task–perturbation cells. On these states, the frozen system scored 75.2%, compared with 17.5% for frozen π0.5, with 473 exclusive DynaHarness wins versus 11 exclusive policy wins. This is initial-state transfer, not evidence of transfer to new task families or physical domains.

Panel c: success rate for DynaHarness versus π0.5 is 75.2 versus 17.5 on new states (n=800) and 77.0 versus 16.5 on the untouched official-state subset (n=261, 31 cells). These results do not show transfer to new task families.

### 4. Closing

The established contribution is command-level physical authority. A single contract governs grounding, refusal, execution bounds, and termination, and its records support later fault attribution and revisions. On LIBERO-Pro, this outperformed nominal replanning on development episodes and transferred to new initial states within the same cells. The main boundary is that the evidence tests the dynamic package jointly within those cells. Locally validated revisions also still require broader regression testing.
