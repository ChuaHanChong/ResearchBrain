# AgentOrchestra: Orchestrating Multi-Agent Intelligence with the Tool-Environment-Agent(TEA) Protocol

> [!summary] Summary
> The AgentOrchestra framework, based on the Tool-Environment-Agent (TEA) protocol, introduces a unified approach to managing and orchestrating multi-agent intelligence by treating tools, environments, and agents as first-class, versioned resources. It achieved state-of-the-art performance on benchmarks like GAIA (89.04%), SimpleQA (95.3%), and Humanity’s Last Exam (37.46%), demonstrating enhanced capabilities for complex tasks.

## Problem

- Existing LLM-based agent protocols suffer from fragmented lifecycle and context management, leading to monolithic agent compositions and brittle integration code.
- Current approaches lack built-in mechanisms for feedback-driven self-evolution and traceable versioning of prompts and resources.
- Computational environments are often treated as application-specific runtimes rather than first-class managed components, limiting reusability and flexible agent deployment.

## Method

- The ==Tool–Environment–Agent (TEA) Protocol== is introduced, unifying the management of tools, environments, and agents as first-class, versioned resources with explicit lifecycles and robust context management.
- The TEA Protocol includes Basic Managers for foundational services, ==Core Protocols (TCP, ECP, ACP)== to formalize interactions, Protocol Transformations for dynamic entity conversion, and a ==Self-Evolution Module==.
- AGENTORCHESTRA, a ==hierarchical multi-agent framework==, is developed as an instantiation of TEA, employing specialized sub-agents orchestrated by a central Planning Agent for complex task decomposition.

## Results

- AGENTORCHESTRA achieved state-of-the-art performance on GAIA (**89.04%** on Test set), SimpleQA (**95.3%** accuracy), and Humanity’s Last Exam (**37.46%**), significantly surpassing existing baselines.
- Ablation studies confirmed that specialized sub-agents provide substantial performance gains, with the Deep Researcher and Browser Use agents increasing GAIA performance by approximately **56%**.
- The self-evolution module, utilizing TextGrad and self-reflection, consistently improved reasoning performance, and the Tool Generator autonomously created over **50** specialized tools with a **30%** reuse rate.

## Takeaways

> [!tip] Key Insights
> - Treating Tools, Environments, and Agents as first-class, versioned resources through a unified protocol provides a principled foundation for building traceable, reproducible, and robust multi-agent systems.
> - Hierarchical orchestration with specialized sub-agents and localized tool ownership effectively reduces planning complexity and context management overhead for long-horizon tasks.
> - Integrating a self-evolution module at the protocol level, leveraging TextGrad and self-reflection, enables agent components to continuously refine and adapt based on execution feedback.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

Recent advancements in Large Language Model (LLM)-based agent systems have demonstrated capabilities in addressing complex, long-horizon tasks across various domains, including web navigation, computer operation, code execution, game playing, and research assistance. However, these systems often exhibit limitations in cross-environment generalization. Current approaches frequently involve scattered context across prompts and logs, reliance on brittle "glue code" for environment integration, and a static nature of agent-associated components that prevents improvement through execution feedback.

Existing agent protocols, such as Google’s Agent2Agent (A2A) and Anthropic’s Model Context Protocol (MCP), provide foundational elements for agent collaboration and tool integration. A2A facilitates agent-to-agent messaging and coordination, while MCP standardizes tool and resource schemas, discovery, and invocation for LLMs. However, these protocols primarily treat agents and tools as isolated service endpoints. They are noted to lack comprehensive lifecycle and context management mechanisms for maintaining consistent, versioned execution context across agent-associated components. Furthermore, they do not natively support self-evolution at the protocol level, as prompts and resources are typically managed externally rather than refined through traceable versioning based on execution feedback. Environments are often delegated to application-specific runtimes rather than being managed as first-class components with explicit boundaries and constraints. This fragmentation complicates switching agents across environments, reusing environments, and isolating parallel execution runs.

This work addresses these identified gaps by proposing a unified protocol and a hierarchical framework that aims to provide a more structured and adaptive foundation for multi-agent intelligence, integrating tools, environments, and agents within a common, lifecycle-aware ecosystem. It builds upon previous efforts in LLM-tool integration and multi-agent architectures by introducing a layer for systematic resource management and evolution.

### 2. Key Objectives and Motivation

The primary objectives and motivations for this research are rooted in addressing the limitations of existing agent systems and protocols to foster more robust, adaptive, and scalable multi-agent intelligence.

**Motivation for the Tool-Environment-Agent (TEA) Protocol:**
The core motivation for the TEA protocol stems from the observation that current agent protocols do not adequately support lifecycle-aware coordination among agents, tools, and environments. This leads to several issues:
- **Fragmented Context Management:** Execution context, including prompts, memory, and logs, is often scattered and inconsistently managed, hindering traceability and reproducibility of agent behaviors.
- **Lack of Versioning:** Agent-associated components (like prompts, tool code, environment configurations) typically lack version control, making it difficult to track changes, revert to previous states, or ensure reproducibility of results.
- **Limited Self-Evolution:** Existing systems largely treat agent components as static assets. There is no inherent protocol-level mechanism for these components to continually improve or adapt based on execution feedback, limiting the agents' ability to learn and evolve over time.
- **Passive Environments:** Environments are often treated as external, undifferentiated runtimes, requiring bespoke integrations. This absence of environments as first-class, managed components restricts their reusability, composability, and the ability to define explicit boundaries and constraints (e.g., web sandboxes, file systems).

To address these limitations, the TEA protocol was developed as a unified abstraction. Its objective is to model tools, environments, and agents as first-class, versioned resources with explicit lifecycles. This design aims to enable end-to-end context and version management, thereby improving traceability and reproducibility, and supporting the continual self-evolution of agent-associated components.

**Motivation for AGENTORCHESTRA:**
Building upon the TEA protocol, AGENTORCHESTRA was motivated by the need for a more scalable and efficient orchestration mechanism for multi-agent systems, particularly for complex general-purpose task solving. Traditional "flat" coordination models, where a central orchestrator selects from a large global pool of agents and tools, often face challenges:
- **Scalability Issues:** As the number of agents and tools grows, the orchestrator's decision-making scope expands, leading to increased complexity and potential bottlenecks.
- **Context Accumulation:** Flat architectures can lead to the accumulation of irrelevant context at the orchestrator level, reducing efficiency and clarity.
- **Limited Dynamic Adaptation:** Many existing multi-agent frameworks struggle with dynamically extending agent capabilities during execution or refining components based on real-time feedback.

AGENTORCHESTRA adopts a hierarchical multi-agent framework to address these issues. Its key objective is to leverage the TEA protocol to enable a central planner to coordinate specialized sub-agents effectively. This hierarchical delegation, coupled with localized tool ownership and a self-evolution module, aims to support tree-structured expansion while keeping the orchestrator’s decision scope bounded, thereby enhancing scalability, adaptability, and performance in general-purpose task solving.

**The contributions of this work are threefold:**
1. **Introduction of the TEA Protocol:** A unified protocol treating environments, agents, and tools as first-class, versioned components with lifecycles for context management and execution.
2. **Development of AGENTORCHESTRA:** A hierarchical multi-agent system built on TEA, demonstrating scalable orchestration through tree-structured routing and feedback-driven self-evolution.
3. **Extensive Empirical Evaluation:** Comprehensive experiments on challenging benchmarks, including ablations, to demonstrate that AGENTORCHESTRA consistently outperforms strong baselines and achieves competitive performance metrics.

### 3. Methodology and Approach

The methodology centers on the design and implementation of the Tool-Environment-Agent (TEA) protocol and its instantiation in the AGENTORCHESTRA hierarchical multi-agent framework. The TEA protocol is designed around coroutine-based asynchronous execution, enabling concurrent task processing and parallel multi-agent coordination.

#### 3.1. The TEA Protocol

The TEA Protocol architecture comprises three primary layers and an additional module:

- **i) Basic Managers:** These foundational components provide essential services for the entire protocol.
 - **Model Manager:** Abstracts heterogeneous LLM backends (e.g., OpenAI, Anthropic, Google) through a unified interface, supporting various model types and capabilities (streaming, function calling, vision).
 - **Prompt Manager:** Manages the lifecycle and versioning of prompts, supporting template rendering and dynamic updates with automatic version generation.
 - **Memory Manager:** Coordinates memory persistence via session-based concurrency control, recording execution histories and extracting insights to prevent resource conflicts.
 - **Dynamic Manager:** Enables runtime code execution and serialization/deserialization of components and their code, allowing dynamic loading and sharing.
 - **Version Manager:** Maintains evolution histories for all components (tools, environments, agents, prompts, memory), tracking changes and enabling rollback.
 - **Tracer:** Records comprehensive execution trajectories, including decision points, tool invocations, and state transitions, for audit, debugging, and dataset synthesis.

- **ii) Core Protocols:** These define context-aware management for tools, environments, and agents. Each protocol consists of a context manager for lifecycle management and semantic retrieval, and a server exposing standardized interfaces. They generate unified contract documents for resource discovery.
 - **Tool Context Protocol (TCP):** Extends existing tool integration approaches (like MCP) by introducing integrated context engineering and comprehensive lifecycle management. It supports tool loading, synthesizes multiple representation formats (function-calling schemas, natural language descriptions, type-safe argument schemas), incorporates versioning, and uses vector embeddings for semantic retrieval.
 - **Environment Context Protocol (ECP):** Formalizes computational environments as first-class components with distinct observation and action spaces. It manages environment state coherence, automatically discovers and registers environment-specific actions as standardized interfaces, and employs versioning and semantic retrieval for capabilities.
 - **Agent Context Protocol (ACP):** Establishes a unified framework for agent registration, representation, and orchestration. It maintains agent states and execution contexts, captures semantically enriched metadata about roles and competencies, and formalizes inter-agent dynamics (cooperative, competitive, hierarchical).

- **iii) Protocol Transformations:** These establish bidirectional conversion pathways between core protocol entities, enabling dynamic role reconfiguration.
 - **Agent-to-Tool (A2T):** Encapsulates an agent's capabilities into a standardized tool interface (e.g., a researcher agent as a search tool).
 - **Tool-to-Agent (T2A):** Treats tools as operational actuators, mapping an agent's goals to parameterized tool invocations (e.g., a data analysis agent invoking SQL tools).
 - **Environment-to-Tool (E2T):** Converts actions of environments into standardized tool interfaces (e.g., browser actions consolidated into a toolkit).
 - **Tool-to-Environment (T2E):** Elevates a collection of tools into an environment abstraction where functions become actions within a coherent space (e.g., a development toolkit as a programming environment).
 - **Agent-to-Environment (A2E):** Encapsulates an agent as an interactive environment, exposing its decision rules and state dynamics (e.g., a market agent as an environment for training).
 - **Environment-to-Agent (E2A):** Embeds reasoning and adaptive decision-making into an environment’s dynamics, transforming it into an autonomous agent (e.g., a game environment as an opponent agent).

- **Self-Evolution Module:** This module wraps evolvable components (prompts, memory/tool/agent/environment code, successful execution solutions) as variables for iterative optimization. It employs TextGrad for gradient-based refinement and self-reflection for strategic analysis. Optimized components are automatically registered as new versions via the Version Manager.

#### 3.2. AGENTORCHESTRA Framework

AGENTORCHESTRA is a concrete implementation of the TEA Protocol, designed as a hierarchical multi-agent framework.

- **Agent Design Principles:** Agents operate in a perception–interpretation–action cycle. They perceive observations (task, environment state, history, available resources), retrieve context from memory, interpret information via the unified LLM interface (Model Manager) to determine actions, and execute actions within the managed environment. Results are recorded to memory for refinement.
 - **Core Components:** Agent (ACP-managed), Environment (ECP-managed), Model (LLM via Model Manager), Memory (session-based, via Memory Manager), Observation (task, state, history, resources), Action (TCP-managed, parameterized tool calls).

- **Planning Agent:** This central orchestrator interprets user goals, decomposes them into sub-tasks, and delegates them to specialized sub-agents or TCP tools via ACP-mediated communication. It tracks global progress, consolidates feedback, uses long-term memory for resource selection, and dynamically constructs unified invocation interfaces (including E2T and A2T transformations). It features iterative execution, automatic replanning, and tracer-based logging.

- **Specialized Sub-Agents:** AGENTORCHESTRA instantiates several specialized agents tailored for task domains, managed via ACP:
 - **Deep Researcher Agent:** Gathers information through multi-round research workflows, performing parallel breadth-first searches across multiple engines and recursively issuing follow-up queries.
 - **Browser Use Agent:** Provides automated, fine-grained web interaction by integrating browser and computer environments under ECP, supporting DOM-level and pixel-level operations.
 - **Deep Analyzer Agent:** A workflow-oriented module for multi-step reasoning on heterogeneous multimodal data (text, PDFs, images, audio, video, zip), applying type-specific analysis and iterative refinement.
 - **Tool Generator Agent:** Facilitates intelligent tool evolution through automated creation, retrieval, and systematic reuse of TCP-compliant tools, using semantic search and code synthesis.
 - **Reporter Agent:** Aggregates and harmonizes evidence from upstream agents, composing structured markdown reports with automatically deduplicated references and normalized URLs.

### 4. Main Findings and Results

The efficacy of AGENTORCHESTRA was evaluated across four challenging benchmarks: GAIA, HLE, AIME, and GPQA-Diamond. Experiments compared a "Vanilla" variant (without self-evolution) against an "Evolved" variant (with self-reflection-based evolution), utilizing various LLM backbones.

#### 4.1. Performance across Benchmarks

- **GAIA (General AI Assistants Benchmark):**
 - **Test Set:** AGENTORCHESTRA Evolved achieved an average accuracy of 89.04%. Performance remained strong on harder partitions, reaching 85.53% on Level 2 and 81.63% on Level 3.
 - **Validation Set:** AGENTORCHESTRA Evolved achieved state-of-the-art performance with 93.33% average accuracy, outperforming baselines like agent-2030 and Alita (87.27%) and its own Vanilla variant (89.70%). The improvement from Vanilla to Evolved was most notable on Validation Level 2 (+5.26 points).
 - **Implications:** These results indicate that hierarchical decomposition and coordination are particularly beneficial for agentically demanding tasks requiring interaction, retrieval, and analysis over long horizons. The self-evolution mechanism primarily enhances robustness in medium-to-hard coordination regimes. The consistent performance across both test and validation sets suggests that the gains stem from the fundamental system design (TEA's explicit environment management and online tool refinement) rather than benchmark-specific tuning.

- **HLE (Humanity's Last Exam):**
 - AGENTORCHESTRA Evolved achieved a score of 59.6, marking a 7.97% improvement over the Vanilla variant. This placed it among leading entries, outperforming several strong open-source systems (e.g., Kimi K2.6 Thinking at 54.0) and proprietary systems (e.g., GPT-5.5 Pro at 57.2). Claude Mythos Preview remained the top system at 64.7.
 - **Implications:** HLE tasks often require sustained structured reasoning over long solution trajectories. The strong performance suggests that AGENTORCHESTRA’s hierarchical design helps maintain global coherence while specialized agents validate technical details. The improvement from the Evolved variant indicates that self-evolution strengthens domain-specific problem-solving strategies and error correction.

- **GPQA-Diamond and AIME (Scientific and Mathematical Reasoning):**
 - In a simplified setting using only the Deep Analyzer Agent, focusing on reasoning quality, the Evolved variant consistently improved GPQA scores across all five tested LLM backbones and improved AIME25 scores on four out of five.
 - The largest gains were observed with lower- and medium-reasoning backbones, particularly on mathematical settings. For instance, gpt-4.1 improved by 71.38% on AIME24 and 66.65% on AIME25.
 - **Implications:** Self-reflection-based evolution proved effective and model-agnostic, demonstrating that evolving prompts and solution traces can significantly enhance reasoning structure and decomposition, even for models with weaker baseline reasoning.

#### 4.2. Ablation Studies

- **Effectiveness of Specialized Sub-Agents (on GAIA Test):**
 - **Information Acquisition:** Adding the Deep Researcher Agent raised the average score from 36.54% to 57.14%. Further adding the Browser Use Agent increased it to 72.76%, indicating that broad evidence gathering and fine-grained web interaction are complementary.
 - **Dedicated Reasoning:** The Deep Analyzer Agent improved the average score to 79.07% and significantly boosted Level 3 performance (from 46.94% to 61.22%), suggesting that harder multimodal cases require dedicated reasoning beyond retrieval and interaction.
 - **On-Demand Capability Expansion:** The Tool Generator Agent provided the largest late-stage gain, raising the average score to 89.04% and Level 3 to 81.63%. This highlights the importance of dynamic capability expansion when static toolkits are insufficient.
 - **Overall Implication:** Strong GAIA performance emerges from the staged composition of complementary agent roles rather than from isolated modules.

- **Efficiency Analysis:**
 - **Scaling Trend:** Simple tasks completed within 30 seconds, using ~5k tokens. Medium-complexity tasks required ~3 minutes and ~25k tokens. Complex, multimodal, or long-horizon scenarios took ~10 minutes and ~100k tokens.
 - **Implication:** The hierarchical architecture efficiently allocates expensive reasoning and tool use to harder sub-problems, keeping simpler cases lightweight.

- **Effectiveness of Self-Evolution and Tool Evolution:**
 - Self-evolution's benefit, even in stripped-down settings, indicates its role in improving reasoning structure.
 - The Tool Generator autonomously created over 50 specialized tools during evaluation, with a 30% reuse rate across subsequent tasks.
 - **Implication:** The TEA framework jointly improves internal reasoning components and externally expands executable capabilities through continuous adaptation.

### 5. Significance and Potential Impact

This research introduces the Tool-Environment-Agent (TEA) Protocol, a unified framework that conceptually models environments, agents, and tools as first-class, evolvable resources. Building upon this protocol, AGENTORCHESTRA is presented as a hierarchical multi-agent system that integrates explicit protocol design, specialized coordination, and self-evolution. The consistent and strong performance demonstrated across expert-level agent tasks and scientific/mathematical reasoning benchmarks indicates the value of this approach.

The work's significance lies in proposing a structured solution to the current fragmentation and static nature of LLM-based agent systems. By providing unified context management, versioning, and self-evolution capabilities at the protocol level, TEA aims to enhance the traceability, reproducibility, and adaptability of agent construction. AGENTORCHESTRA demonstrates that hierarchical orchestration, combined with specialized agent roles and dynamic capability expansion (via the Tool Generator), can lead to more robust and scalable multi-agent systems.

The potential impact of this research includes:
- **Improved Agent Development:** The TEA protocol offers a more principled and composable framework for building complex agent systems, potentially reducing development complexity and "glue code" overhead.
- **Enhanced Adaptability and Learning:** The self-evolution module allows agents to continuously improve their prompts, tools, and strategies from execution feedback, leading to more resilient and intelligent autonomous systems.
- **Better Generalization:** By treating environments as first-class components, the framework facilitates more consistent and reusable interactions across diverse computational environments, potentially improving cross-environment generalization.
- **Advancement in Multi-Agent Collaboration:** The hierarchical architecture provides a structured approach for coordinating specialized agents, which can be crucial for tackling open-ended, complex tasks.

**Limitations:**
The paper acknowledges several limitations:
- **System Complexity and Learning Curve:** The structured abstraction layer of TEA might present a steeper learning curve for developers compared to ad-hoc scripting methods, necessitating extensive documentation and templates.
- **Communication and Execution Overhead:** The formal protocol could introduce marginal computational and communication overhead, potentially affecting real-time applications. Future work plans to optimize serialization and explore asynchronous execution.
- **Dependence on Underlying Model Capabilities:** The system's effectiveness remains limited by the reasoning and instruction-following performance of the foundational LLMs. It cannot fully compensate for model hallucinations or poor tool-use logic, suggesting a need for model-agnostic error recovery and validation layers.

**Potential Risks:**
The capabilities of AGENTORCHESTRA, particularly its interaction with local environments and web browsers, introduce ethical and security risks:
- **Misuse for Malicious Automation:** The framework's flexibility could be repurposed for unauthorized "plugins," "cheats," or automated fraud on online platforms.
- **Privacy and Security Risks:** Granting autonomous agents access to personal data or sensitive system resources, if not properly sandboxed and governed, could lead to privacy breaches or harmful system actions.
To mitigate these risks, the authors advocate for the use of AGENTORCHESTRA in isolated, monitored environments, along with robust human-in-the-loop verification mechanisms and strict access control policies.
