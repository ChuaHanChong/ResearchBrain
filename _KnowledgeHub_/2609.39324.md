# MotionWeave: Learning Motion-Centered Future Dynamics for Vision-Language-Action Policies

> [!summary] Summary
> MotionWeave is a VLA action-chunk policy that replaces future-frame reconstruction with motion-centered supervision. An Action-Induced Motion Grounder builds per-horizon queries that attend to current visual tokens, supervised by future robot-arm masks via KL; a Horizon Residual Composer injects adjacent-horizon feature differences into action tokens through a gated residual. It reaches 75.3% average success on six MetaWorld tasks, 8.6 points above pi0.

## Problem

- World-model VLAs like WorldVLA and DreamVLA reconstruct or densely imagine full future scenes, entangling control-irrelevant static appearance and background with the dynamics that matter for actions.
- Implicit guidance methods such as WoG and Fast-WAM drop pixel reconstruction but still supervise holistic future visual evolution, not horizon-specific local changes tied to each action.
- Action chunking decodes all timesteps from shared global features, giving each step homogeneous visual evidence and no explicit correspondence between action timing and its local visual consequence.

## Method

- **Action-Induced Motion Grounder (AIMG)**: learnable horizon embeddings plus mean action tokens and proprioception form per-step queries that attend over 256 current ==InternVL3-2B== visual tokens to produce interaction tokens.
- ==KL motion-grounding loss==: robot-arm masks rendered from future frames t+1 to t+4 via Robot Engine become target distributions on the 16x16 token grid, used only in training with weight 0.05.
- **Horizon Residual Composer (HRC)**: adjacent-horizon interaction differences query action tokens via ==cross-attention==, and the result is subtracted from action tokens through a proprioception-conditioned sigmoid gate before the ==flow-matching== Action DiT.

## Results

- On six MetaWorld tasks, MotionWeave averages **75.3%** success versus pi0 **66.7%**, DreamVLA **65.0%**, WoG **50.7%**, and Fast-WAM **49.3%**, leading on five of six tasks.
- Gains concentrate on sustained-interaction tasks, Disassemble **92.0%** versus best baseline **68.0%** and Shelf Place **76.0%** versus **64.0%**, while pi0 still wins Pick Place **72.0%** versus **60.0%**.
- Ablation: baseline **58.0%**, ungrounded AIMG **62.0%**, KL-supervised AIMG **70.0%**, adding HRC **75.3%**; four horizon queries matching chunk length and loss weight 0.05 work best.

## Takeaways

> [!tip] Key Insights
> - Supervising where the robot will move, rather than reconstructing whole future frames, can deliver world-model-style dynamic supervision with zero added inference cost.
> - Architecture alone gave little; explicit attention supervision drove most of the gain, suggesting action loss is too indirect a signal to shape spatial grounding.
> - Caution: evidence is six MetaWorld tasks at 25 episodes each, simulation only; arm-mask targets ignore object motion, so real-robot transfer remains untested.

## Detailed Report

### 1. Overview

MotionWeave targets simulated robot manipulation, where producing a short sequence of actions is more than selecting a destination. The policy also needs to track the local interaction as it unfolds. In the authors' framing, sparse action labels constrain the final control but do not explicitly say which regions change, or how those changes unfold over time.

MotionWeave does not reconstruct a whole future scene. It learns where the robot is interacting at each action horizon and how those horizon-specific interaction representations change. On the simulated Disassemble task, it reaches 92.0% success versus π₀'s 68.0% under the paper's shared-seed evaluation protocol.

Simulation rollouts on six tasks, one row per task with three snapshots each, from observation to successful completion.

### 2. Grounding each future step in the current image

The current image and instruction produce visual and action tokens. A separate encoder represents proprioception, the robot's own state information. The policy then predicts a four-step action chunk, meaning several consecutive actions predicted together.

The first module is AIMG. It uses the action and robot state to form a query for each future step. Each query attends to visual tokens from the current image. That attention produces horizon-specific interaction representations.

During training, masks of the robot arm in future frames supervise those attention maps. Those masks and the KL grounding loss are not used at inference. At inference, the policy receives only current inputs and does not reconstruct future images.

The second module is HRC. It takes differences between adjacent-horizon interaction representations. It then injects those differences into the corresponding action tokens with a proprioception-conditioned gate.

MotionWeave architecture. The current observation plus instruction and the robot state feed separate branches. AIMG forms four horizon-indexed interactions, and HRC composes adjacent-horizon residuals into action tokens to predict four actions. Future-arm-mask supervision is training only.

### 3. What the results establish

Each of six tasks is evaluated over 25 episodes with shared initialization seeds, a 175-step limit, and replanning every two executed actions. The macro-average is computed by taking the binary success rate for each task and averaging the six task rates equally.

On this measure, MotionWeave reaches 75.3% versus 66.7% for [[2410.24164|π₀]], an 8.6 percentage-point absolute gain. π₀ predicts continuous action chunks from observations using a flow-matching action model.

MotionWeave does not win every task. π₀ scores 72.0% on Pick Place versus MotionWeave's 60.0%, which the authors associate with short target displacement. The same-protocol gain over π₀ alone does not show that the proposed mechanism caused the full gain.

The component ablation is the strongest mechanism test. Macro-average success rises in four steps:

- 58.0% for the ablation baseline
- 62.0% with AIMG without motion loss
- 70.0% with AIMG
- 75.3% with AIMG plus HRC

Each row adds a component relative to the preceding configuration. This supports the authors' interpretation that both grounding supervision and temporal composition contribute. It is a sequential ablation, however, and not a matched control for added parameters, computation, or every alternative design.

Cumulative ablation of macro-average success (%) over six tasks: Baseline 58.0, + AIMG without motion loss 62.0, + AIMG 70.0, + AIMG + HRC 75.3. Each row adds one component to the previous one, so this is cumulative ablation evidence and not a fully matched causal test.

### 4. A stepwise visual link

MotionWeave's proposed link to control is horizon-specific visual evidence whose changes are passed into the corresponding actions, rather than a rendered future scene. The ablation is consistent with that link helping in this six-task simulation evaluation.

These are results on six simulated MetaWorld tasks, and the Pick Place exception means the gain does not hold on every task. The authors say future work must test transfer to real robots and unseen tasks.
