# SeCodePLT: A Unified Platform for Evaluating the Security of Code GenAI

> [!summary] Summary
> SECODEPLT presents a unified benchmark to evaluate the security risks and capabilities of code-generating AI models, covering 44 common weaknesses across Python, C/C++, and Java. This benchmark, built with a two-stage data pipeline and dynamic testing, reveals that current state-of-the-art models struggle significantly with secure code generation and vulnerability patching, particularly in C/C++ and Java, while also highlighting their potential to assist in cyberattacks.

## Problem

- Existing benchmarks for Code GenAI security offered limited coverage of risks and capabilities, often focusing on narrow tasks or a small set of Common Weakness Enumerations (CWEs).
- Prior evaluations relied on imprecise metrics like static analysis or LLM judgments, lacking the accuracy and reliability provided by dynamic code execution.
- A persistent trade-off existed between the high quality of small, manually curated datasets and the low fidelity of large, automatically generated datasets.

## Method

- Developed a novel ==two-stage data creation pipeline== combining expert-curated seed examples with ==automated mutation== and rigorous ==dynamic validation==, using ==dynamic testing metrics== (functionality and security test cases) for precise ==execution-based evaluation==.
- Provided comprehensive coverage of 44 CWEs across Python, C/C++, and Java, evaluating three core security capabilities: ==secure code generation==, ==vulnerability detection==, and ==patch generation==.
- Introduced a ==cyberattack helpfulness benchmark== to assess the potential for Code GenAI models to assist in end-to-end cyberattacks within simulated network environments.

## Results

- The SECODEPLT benchmark achieved nearly **100%** security relevance and prompt faithfulness, with Python functionality test cases demonstrating an average of **90.92%** line coverage.
- State-of-the-art models like Claude-3.7-Sonnet and O4-Mini showed over **50%** incorrect rates for C/C++ secure code generation and ~**40%** for Java, with patch generation the hardest task at under **20%** success on C/C++ even with Pass@5.
- Claude-3.5-Sonnet exhibited significantly higher refusal rates (**90-94%**) for dangerous cyberattack tasks compared to GPT-4o (**8-10%**), indicating stronger safety alignment in this context.

## Takeaways

> [!tip] Key Insights
> - Explicit security reminders in prompts and policy hints (candidate CWEs) significantly improve Code GenAI performance in secure coding and vulnerability detection tasks.
> - Larger, reasoning-capable models generally outperform smaller ones, but even state-of-the-art models exhibit substantial weaknesses in generating secure code and patching, especially for complex languages like C/C++ and Java.
> - The cyberattack helpfulness benchmark revealed varying safety alignments, with some models exhibiting a higher propensity to assist in malicious tasks, though full end-to-end attacks remained unsuccessful.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

The emergence of Code GenAI, including large language models (LLMs) and agents, has revolutionized software development by automating tasks like code generation, understanding, and debugging. While these models offer immense productivity gains, they also introduce significant security risks. The broader research landscape is actively grappling with evaluating these models' security posture—both their potential to generate insecure code and their capability to assist in security tasks like vulnerability detection and patching.

Prior to SECODEPLT, existing benchmarks suffered from several key limitations:
1. **Limited Coverage:** Many benchmarks focused on a narrow scope of security risks (e.g., only code completion or only vulnerability detection) or a limited number of Common Weakness Enumerations (CWEs). Some even resorted to text-based question answering, which poorly reflects real-world coding challenges.
2. **Static Evaluation Metrics:** A reliance on static analysis tools, rule-based detectors, or LLM judgments often led to imprecise evaluations. These methods frequently produce false positives or miss complex vulnerabilities that only manifest during dynamic execution.
3. **Trade-off between Data Quality and Scale:** Manually curated datasets, while high-quality, were often small and unscalable. Conversely, automatically generated datasets were typically large but suffered from low fidelity and security relevance due to a lack of human validation and contextual understanding.

SECODEPLT addresses these limitations by introducing a benchmark that provides **broader coverage** (44 CWEs across three major languages and three security capabilities), leverages **dynamic testing metrics** for higher precision, and achieves a balance between **data quality and scale** through its novel two-stage generation pipeline. It builds upon, and seeks to overcome the shortcomings of, previous benchmarks like AsleepAtTheKeyboard, PrimeVul, SecLLMHolmes, CYBERSECEVAL, SVEN, CodeLMSec, BaxBench, and AutoPatchBench. Unlike general-purpose coding benchmarks (e.g., SWE-bench, LeetCode datasets), SECODEPLT is explicitly tailored for security-specific evaluations.

Furthermore, the paper extends beyond traditional code security by introducing a **cyberattack helpfulness benchmark** (detailed in Appendix G), which assesses Code GenAI's potential to assist in end-to-end cyberattacks within a simulated network environment. This aspect positions the work at the forefront of AI red-teaming and malicious use case analysis, a critical area for AI safety. By providing a comprehensive and dynamically evaluable benchmark, SECODEPLT aims to set a new standard for assessing the security risks and capabilities of Code GenAI, facilitating the development of more secure and robust AI systems.

### 2. Key Objectives and Motivation

The primary motivation behind SECODEPLT stems from the acknowledged shortcomings of existing benchmarks for evaluating the security of code-generating LLMs and agents. The authors identify three core challenges:

1. **Lack of Comprehensive Coverage:** Existing benchmarks often provide fragmented evaluations, covering only a limited set of security risks (CWEs) or specific tasks (e.g., only code completion or vulnerability detection). This narrow scope prevents a holistic understanding of a model's security posture.
2. **Reliance on Imprecise Evaluation Metrics:** Many benchmarks depend on static analysis (rule-based detection) or subjective LLM judgments. These methods lack the precision of dynamic execution, which can reliably confirm the presence or absence of vulnerabilities and the correctness of patches.
3. **Inherent Trade-off between Data Quality and Scalability:** High-quality benchmarks require significant manual effort, limiting their scale. Conversely, large-scale benchmarks often resort to automated data generation, sacrificing data fidelity and security relevance.

To overcome these challenges, the key objectives of the SECODEPLT project are:

- **Develop a General and Scalable Benchmark Construction Framework:** The central goal is to create a methodology that systematically builds high-quality, large-scale benchmarks for evaluating Code GenAI security.
- **Achieve Comprehensive Risk and Capability Coverage:** The benchmark aims to cover a broad spectrum of security risks (44 CWEs) and evaluate three critical capabilities: secure code generation, vulnerability detection, and patch generation, across multiple programming languages (Python, C/C++, Java).
- **Enable Dynamic, High-Precision Evaluation:** By providing a comprehensive suite of artifacts, including functionality and security test cases, the benchmark seeks to support dynamic analysis for accurate assessment of generated code and detected vulnerabilities.
- **Balance Manual Effort, Data Quality, and Benchmark Scale:** The proposed two-stage data creation pipeline aims to leverage expert insights for high-quality seed examples and automated mutation for scalability, mitigating the traditional trade-off.
- **Uncover Strengths and Weaknesses of State-of-the-Art Code GenAI:** Apply the developed benchmark to evaluate leading code LLMs and agents, providing empirical evidence of their security risks and capabilities in practical coding and security tasks, including their potential for misuse in cyberattacks.

In essence, SECODEPLT's motivation is to provide a unified, robust, and industry-relevant standard for assessing the security performance of Code GenAI, thereby fostering the development of safer and more capable AI assistants for software development.

### 3. Methodology and Approach

SECODEPLT introduces a novel, two-stage data creation pipeline designed to balance data quality and scalability while supporting comprehensive security evaluations using dynamic metrics.

#### 3.1. Programming Languages, Risks, and Capabilities

The benchmark focuses on Python, C/C++, and Java, chosen for their widespread use and representation of diverse programming paradigms. It covers 44 CWEs, selected by analyzing the top 50 CWEs with active CVEs in the past five years and merging conceptually similar ones. This ensures relevance to current attack surfaces. SECODEPLT evaluates three core security capabilities:
- **Secure Coding:** Assessing a model's ability to generate functional and secure code.
- **Vulnerability Detection:** Measuring the model's proficiency in identifying vulnerabilities in existing code.
- **Patch Generation:** Evaluating the model's capacity to produce effective security patches.

#### 3.2. Two-Stage Data Creation Pipeline

**Stage 1: Seed Generation (High-Quality, Manually Validated Examples)**
This stage focuses on creating a set of high-fidelity "seed examples" for each selected CWE and language. Each seed includes a comprehensive suite of artifacts to enable multifaceted evaluations:
- **Task Description (Prompt):** A natural language description of a coding scenario related to a specific CWE, designed to guide the LLM. An optional "security reminder" can be included to highlight potential vulnerabilities.
- **Vulnerable Code:** The insecure version of the code, aligned with the task description.
- **Patched Code:** The secure version of the code, fixing the vulnerability present in the vulnerable code.
- **Functionality Test Cases:** Inputs and expected outputs to verify the functional correctness of the generated or patched code.
- **Security Test Cases (Proof-of-Concept/PoC):** Inputs specifically designed to trigger the vulnerability in the vulnerable code and ensure its absence in the patched/secure code.

The approach to seed generation varies by language:
- **Python:** Due to a lack of existing comprehensive datasets, all Python seeds are **manually created**. Researchers analyze CVEs for each CWE, craft realistic coding scenarios, write task descriptions, develop both vulnerable and patched code, and create functionality/security test cases.
- **C/C++:** Seeds are derived from the **Arvo dataset**, which provides real-world vulnerable codebases and artifacts (build scripts, PoCs, patched code). The process involves:
 - Extracting vulnerable functions.
 - Using tools like `clangd` to extract context (definitions of called functions, global variables) to construct meaningful task descriptions.
 - Identifying root causes (vulnerable code chunks) using AST analysis for masking in code completion tasks.
 - Generating functionality tests via dynamic fuzzing (`libfuzzer`, `afl++`) using PoCs as seeds.
- **Java:** Seeds are based on the **Java Juliet Test Suite**, which offers vulnerable and patched code examples. Challenges include entangled code and obvious vulnerability indicators. The methodology involves:
 - Separating entangled vulnerable and patched functions.
 - Applying a comprehensive obfuscation strategy (removing comments, package declarations, renaming keywords like "good"/"bad" to random strings) to remove obvious indicators.
 - Using `JavaParser` to identify related function signatures and global variables for contextual task descriptions.
 - Manually writing PoC and functionality test cases.

This extensive manual effort ensures high data quality and security relevance for the seed examples.

**Stage 2: Large-scale Data Generation (Automated Expansion and Validation)**
To scale the benchmark while preserving quality, the seed examples undergo automated mutation and rigorous filtering:
- **Text Mutation:** An LLM (GPT-4o) is prompted to rephrase the task descriptions, generating variations while preserving the core security context. A high temperature is used to encourage diversity.
- **Code Mutation:** Minor mutators are applied to change variable names, function names, and the order of symmetric instructions in the vulnerable code, patched code, and test cases, ensuring consistency and preserving core program logic. This also helps prevent LLMs from relying on memorization.
- **Validation and Filtering:**
 - Each seed generates multiple mutated samples (up to 10).
 - **Dynamic Validation:** Crucially, both vulnerable and patched versions of mutated samples are executed against their respective test cases. This verifies functional correctness and confirms that only the patched code passes all security checks, while vulnerable code fails. Invalid mutations are regenerated.
 - **Redundancy Filtering:** Samples are checked for similarity to seeds using word-level Levenshtein distance. Samples exceeding a similarity threshold (0.8) are rejected to ensure novelty.

The final SECODEPLT dataset comprises over 5.9k samples, built from approximately 1.6k verified seed examples. The benchmark provides a unified framework where these artifacts support secure code generation (instruction generation/code completion), vulnerability detection (identifying vulnerabilities given code), and patch generation (fixing identified vulnerabilities), all evaluable through dynamic testing.

### 4. Main Findings and Results

The evaluation of SECODEPLT focused on two main areas: benchmark quality and the performance of state-of-the-art (SOTA) code GenAI models.

#### 4.1. Benchmark Quality

SECODEPLT's data quality was assessed across three dimensions:
- **Security Relevance:** Evaluated using an LLM-based judge, SECODEPLT achieved nearly 100% security relevance for its coding tasks, meaning tasks clearly reflected a security scenario and potential vulnerability. In contrast, the SOTA benchmark CYBERSECEVAL showed lower relevance (e.g., ~13% for CWE-338, overall 67.81%), indicating that some of its tasks were not clearly security-related.
- **Prompt Faithfulness:** This assessed whether a prompt contained sufficient information for a model to generate the intended code (vulnerable or patched). SECODEPLT again demonstrated nearly 100% faithfulness, significantly outperforming CYBERSECEVAL, whose prompts sometimes lacked crucial functional details.
- **Test Case Coverage:** For Python, functionality test cases achieved an average of 90.92% line coverage, with uncovered code typically being redundant or unrelated to the vulnerability, validating the quality of the dynamic tests.

These results affirm that SECODEPLT provides a high-quality, reliable foundation for evaluating code GenAI security.

#### 4.2. SOTA Models on SECODEPLT

Six SOTA models (DeepSeek-R1, QwQ-32B, Qwen2.5-Coder, Claude-3.7-Sonnet, GPT-4o, O4-Mini) and the Cursor agent were evaluated across the three security capabilities.

**Key General Trends:**
- **Language Difficulty:** Python tasks were generally less challenging for LLMs compared to C/C++ and Java. This is attributed to C/C++ seeds originating from more complex, real-world codebases requiring significant contextual understanding.
- **Model Performance:** Larger, reasoning-capable models (e.g., Claude-3.7-Sonnet, O4-Mini, GPT-4o) consistently outperformed smaller, non-reasoning models (e.g., Qwen2.5-Coder).
- **Impact of Security Reminders/Policies:** Providing explicit security reminders in secure coding tasks and policy hints (candidate CWEs) in vulnerability detection significantly improved model performance, confirming that targeted guidance enhances security awareness.

**Specific Findings per Capability:**

- **Secure Coding:**
 - Even SOTA models like Claude-3.7-Sonnet and O4-Mini struggled with C/C++ (over 50% incorrect rate) and Java (around 40% incorrect rate), highlighting substantial room for improvement in generating secure code for these languages.
 - Qwen2.5-Coder showed the worst performance, often failing due to compilation errors.
 - The Cursor agent (evaluated separately on Python seeds) also consistently failed to generate secure code, passing only 62% of rule-based tests and 52.8% of dynamic safety tests on average without security policies. With policies, it improved to 86.7% rule-based and 67.4% dynamic safety, but still showed significant weaknesses in handling critical vulnerabilities (e.g., 0% secure code for CWE-79, CWE-95, CWE-327, CWE-863, CWE-200 in some settings).

- **Vulnerability Detection:**
 - Performance was generally lower than secure coding, particularly for C/C++ and Java, where models struggled to analyze complex codebases and contextual dependencies.
 - Policy hints (listing candidate CWEs) helped models, especially for C/C++ cases, by narrowing down the problem space.
 - SOTA models still demonstrated limitations in accurately pinpointing vulnerabilities in complex code.

- **Patch Generation:**
 - This was identified as the most difficult task, requiring not just detection but also semantic reasoning to fix issues.
 - All models showed very low performance on C/C++ (less than 20% success rate even with Pass@5), indicating a major limitation in their ability to generate valid and effective security patches for complex systems.

#### 4.3. Cyberattack Helpfulness Benchmark (Appendix G)

- **GPT-4o vs. Claude-3.5-Sonnet:** For the most dangerous tasks (Initial Access, C2 & Execution), Claude-3.5-Sonnet exhibited significantly stronger safety alignment with refusal rates of 94% and 90% respectively. GPT-4o, in contrast, had much lower refusal rates (8% and 10%), indicating a higher risk in assisting attackers.
- **End-to-End Attacks:** All tested models (GPT-4o, Claude-3.5-Sonnet, Llama3.1-70B) achieved a 0% success rate for end-to-end cyberattacks. However, individual attack stages could be partially completed (e.g., GPT-4o passed an average of 0.68/5 categories, Claude 0.6/5). This implies that while full attacks are difficult, models can still assist in specific dangerous steps, necessitating continued safety improvements.
- **Prompting Strategies:** Different prompting strategies (e.g., "As a CTF player," "As a security researcher," "Restricted Response," "DAN") affected refusal rates and success rates, highlighting the importance of prompt engineering for both safe and effective AI interaction.

Overall, the findings underscore that while Code GenAI models are increasingly capable, significant security risks remain, and their specialized security capabilities are still nascent, particularly for complex languages and tasks like patching.

### 5. Significance and Potential Impact

SECODEPLT represents a significant advancement in the evaluation of Code GenAI's security posture, with substantial implications for research, development, and deployment of these technologies.

#### 5.1. Significance

- **Unified and Comprehensive Evaluation:** By integrating secure coding, vulnerability detection, and patch generation across multiple languages and 44 CWEs, SECODEPLT provides the most comprehensive benchmark to date. This allows for a holistic assessment of Code GenAI capabilities and risks, moving beyond fragmented evaluations.
- **High Data Fidelity and Scalability:** The two-stage data creation pipeline—combining expert-curated seeds with automated mutation and dynamic validation—successfully navigates the traditional trade-off between data quality and scale. This provides a large-scale, high-quality dataset that is robust and reliable.
- **Dynamic Evaluation for Precision:** The heavy reliance on dynamic testing metrics (executing code, running PoCs) offers a more precise and realistic assessment compared to static analysis or LLM judgments, better reflecting real-world security outcomes.
- **Quantifying LLM Security Gaps:** The evaluation of SOTA models clearly quantifies their current limitations, demonstrating that even leading models struggle with generating secure code, detecting vulnerabilities, and especially patching, particularly in complex languages like C/C++ and Java. This highlights critical areas for future AI research and development.
- **AI Safety and Red Teaming:** The inclusion of a cyberattack helpfulness benchmark is particularly significant for AI safety. It provides a structured method to evaluate a model's potential for misuse in generating end-to-end attacks, offering crucial insights for red-teaming efforts and the development of stronger safety alignments.
- **Foundation for Future Research:** SECODEPLT serves as a standardized, open-source benchmark, facilitating comparative studies, model fine-tuning, and the development of novel techniques to enhance the security awareness and capabilities of Code GenAI.

#### 5.2. Potential Impact

- **Driving Secure LLM Development:** By clearly identifying weaknesses, SECODEPLT will guide researchers and developers in building more secure code LLMs and agents. This could lead to new architectures, training methodologies, and safety mechanisms tailored to security-critical coding tasks.
- **Improved Software Security:** As Code GenAI becomes more prevalent in software development, ensuring its security is paramount. A robust benchmark like SECODEPLT can help integrate security from the design phase, reducing the introduction of vulnerabilities into generated code.
- **Enhanced AI Safety Policies:** The insights from the cyberattack helpfulness benchmark can inform policy discussions and regulatory frameworks regarding the safe and responsible deployment of powerful AI systems, especially those capable of generating malicious code or assisting in cyberattacks.
- **Practical Tool for Industry:** Software companies and security teams can use SECODEPLT to evaluate the security performance of Code GenAI tools they integrate into their workflows, making informed decisions about their adoption and necessary safeguards.
- **Education and Training:** The benchmark and its associated datasets can be valuable resources for educating and training the next generation of cybersecurity professionals and AI developers on the intricacies of secure AI development.

#### 5.3. Future Work

The authors propose several directions for future work, including:
- Enriching existing test cases, especially PoC tests, for more comprehensive patch generation evaluation.
- Extending the benchmark to cover more programming languages and risk categories.
- Supporting user-specific prompts and custom input templates for greater flexibility.
- Developing repository-level samples for vulnerability detection, especially for C/C++ and Java, to evaluate models and agents in handling large codebases.
- Utilizing SECODEPLT for model fine-tuning to directly improve Code GenAI's security awareness and capabilities.
- Extending to support other security-related tasks, such as test case generation.

In conclusion, SECODEPLT is a timely and critical contribution to the field, providing a much-needed robust framework to rigorously evaluate and advance the security and safety of code-generating artificial intelligence.
