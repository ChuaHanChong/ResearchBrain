# Physical Agentic AI: An Architecture for Orchestrating a Robot Crew with LLMs

> [!summary] Summary
> Physical Agentic AI is an architecture for LLM-orchestrated heterogeneous robot crews that separates semantic planning from actuation authority. A non-actuating foundation-model Mission Planner composes plans over typed robot skill libraries and declarative workflow contracts, while a deterministic Robot Orchestrator re-verifies every step against skills, arguments, contract order, robot state, and dispatch-time bindings before actuation. Enforcement drove false dispatch from 23-29% to 0% with 100% fault recall.

## Problem

- Software agentic frameworks assume tool calls are reversible, sandboxed, and retryable, an assumption that fails for state-dependent, time-consuming, irreversible physical robot actions.
- Classical task executives assume planners emit actions from a closed vocabulary, so free-form language planners can propose steps naming no implemented robot capability.
- Prior work conflates planner knowledge with runtime safety, so evaluations cannot tell whether gains come from richer retrieved context or from execution-time enforcement.

## Method

- Typed per-robot ==skill libraries== with parameters, preconditions, effects, cost, and synchronization requirements bound the non-actuating **Mission Planner**'s action space to implemented capabilities.
- Executable ==workflow contracts== compiled from one declarative specification into both the planner prompt and the runtime checker, encoding ordering, synchronization, argument validity, and state-bound values.
- A deterministic **Robot Orchestrator** holds sole actuation authority, re-authorizing each dispatch against skill existence, request containment, contract transition, robot state, and dispatch-time binding resolution.

## Results

- In Gazebo drone-UGV search-and-dispatch, retrieval lifted skill grounding from **51%** to **96%**, but non-enforcing arms still false-dispatched **23%** of steps with **0%** safety-gate recall.
- The Orchestrator cut false dispatch to **0%** and blocked all **eight** injected faults at **100%** recall and precision; rover goal error **0.465 m** versus **0.494 m** scripted.
- A held-plan ablation on the humanoid-quadruped crew routed identical plans through both modes, moving false dispatch from **25.7%** (**9/35** steps) to **0%**.

## Takeaways

> [!tip] Key Insights
> - Grounding is a retrieval problem while dispatch safety is an enforcement problem; better prompts cannot substitute for constraints checked outside the language model.
> - Richer planner context can convert detectable hallucinations into plausible wrong substitutions that pass syntactic checks, so request containment must be enforced explicitly.
> - Some execution-critical values only exist at dispatch time, so runtime state binding, not planning-time context, must own those channels.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

The integration of large language models (LLMs) into robotics has expanded rapidly, with LLMs being applied to interpret natural language task specifications, sequence robot skills, generate executable code, and facilitate reasoning with feedback. Concurrently, the field of agentic AI has seen the development of LLM-based agents capable of decomposing tasks, calling tools, and coordinating multi-step workflows in software environments.

However, the direct application of software-oriented agentic AI frameworks to physical robot crews presents challenges. Unlike software operations, physical robot actions are state-dependent, time-consuming, potentially irreversible, and interact directly with the physical world. Existing robot architectures, such such as ATLANTIS, AuRA, three-layer architectures, HeRO, and ROS, have historically balanced deliberative planning with reactive execution. These classical systems typically assume planners produce actions from a closed, predefined vocabulary, making grounding primarily a binding problem (mapping a known action to an implemented skill).

The introduction of foundation models complicates this by enabling free-form natural language plan generation, where a proposed step might be syntactically plausible but not correspond to any executable robot capability, or even be unsafe. This introduces a novel architectural vulnerability: the conflation of planner knowledge (what the LLM "knows" or is prompted with) with runtime safety (whether an action is actually safe and executable).

Prior research on foundation models for robot planning has extended from individual robots (e.g., SayCan, which grounds language reasoning in robot affordances) to heterogeneous multi-robot teams (e.g., SMART-LLM, RoCo, COHERENT, EMOS, EmboTeam). These systems use LLMs for high-level instruction interpretation, task decomposition, robot coalition formation, subtask allocation, and feedback-driven plan refinement. Some approaches, like SafeGate, RoCo, and COHERENT, incorporate forms of feasibility or execution feedback, but these primarily support plan construction or reactive correction rather than serving as a strict, independent gate for physical actuation.

This paper addresses the need for a principled interface between language reasoning and physical execution, specifically for heterogeneous robot crews. It posits that coordinating multiple embodied agents requires explicit architectural separation between deliberative language reasoning and deterministic execution authority. While multi-robot coordination methods and task-and-motion planning (TAMP) provide structured ways to reason about discrete goals and continuous feasibility with absolute guarantees, they often rely on carefully specified models that are difficult to connect directly to open-ended natural language requests. Software agent orchestration frameworks also lack support for physical state or irreversibility.

The work builds upon these foundations by proposing an architecture that combines the task delegation and skill library concepts of software agent orchestration with the state and precondition reasoning from classical TAMP, but specifically adapted for LLM-based planning in physical systems. It seeks to disentangle the mechanisms of providing the planner with grounded knowledge (retrieval) from enforcing execution constraints (runtime enforcement), arguing that the latter is critical for reliable and safe physical operations in heterogeneous robot teams.

### 2. Key Objectives and Motivation

The primary motivation for this research stems from the observation that while agentic AI frameworks, leveraging LLMs, offer flexibility in interpreting open-ended task goals and decomposing them into multi-step plans, this flexibility does not inherently guarantee safe or feasible physical actions when applied to robot crews. Even when LLMs are provided with rich information regarding embodiment-specific capabilities, physical preconditions, and cross-robot coordination requirements, there remains a risk of generating infeasible, mistimed, or unsafe actions. This indicates a gap between the semantic planning capabilities of LLMs and the practical requirements of physical execution.

The central objective is to isolate and study the mechanisms of planner knowledge and execution authority. The authors hypothesize that reliable physical robot crews necessitate an explicit architectural interface between semantic planning, driven by foundation models, and physical execution. This interface would ensure that every planned action is stringently verified against robot capabilities, the current system state, and predefined workflow constraints *before* any physical actuation occurs.

Specifically, the paper aims to achieve the following:

1. **Demonstrate the Dissociation of Grounding and Safety**: Conduct a controlled study to show that while providing richer context (retrieval) significantly improves the grounding of LLM-generated plans, it does not eliminate unsafe dispatches. Instead, dispatch safety is identified as a problem requiring dedicated enforcement mechanisms external to the language model.
2. **Characterize Planner Failure Modes**: Empirically analyze specific failure modes that emerge as LLMs become more informed. This includes "retrieval-induced substitution," where better-informed planners might shift from outright hallucination to plausible but incorrect actions, necessitating strict request-containment and state-interface checks at runtime.
3. **Introduce Physical Agentic AI Architecture**: Propose and realize an architectural framework designed for skill-grounded robot agent orchestration. This framework is intended to bridge the semantic reasoning of foundation models with the deterministic, safety-critical demands of physical robot execution. Key components include typed skill libraries, workflow contracts that are leveraged by both the planner and a runtime checker, and a deterministic Robot Orchestrator with sole actuation authority that verifies each action before dispatch.

By addressing these objectives, the research seeks to provide a principled approach to integrating LLMs into multi-robot systems, ensuring that the benefits of flexible natural language planning are realized without compromising physical safety and reliability.

### 3. Methodology and Approach

The proposed methodology introduces "Physical Agentic AI," an architectural framework that explicitly separates semantic task reasoning from physically grounded execution. This separation is achieved by employing a non-actuating LLM-based Mission Planner and a deterministic, procedural Robot Orchestrator (RO) with sole actuation authority.

**A. Design Principles**
The architecture is guided by four core principles:
1. **Separation of reasoning and execution**: The LLM Mission Planner interprets natural language and decomposes tasks, but it lacks direct actuation authority. Physical execution and constraint enforcement are handled by separate, deterministic components.
2. **Skill-grounded planning**: The planner operates exclusively over a predefined, typed library of executable robot skills. Each skill specifies arguments, preconditions, effects, costs, and synchronization requirements. This prevents the LLM from generating arbitrary or non-existent actions.
3. **Contract-mediated coordination**: Multi-robot workflows are governed by "executable workflow contracts." These declarative specifications encode ordering, synchronization points, resource dependencies, and argument-validity rules, and they inform both the planner and the runtime checker.
4. **Execution-time verification**: Immediately prior to any physical actuation, every proposed skill dispatch is validated against the workflow contract and the current robot state, including resolution of runtime-bound values.

**B. Architectural Components**
As depicted in Figure 1 of the paper, the architecture comprises:
- **Robot Skill Libraries**: Each robot exposes a library (K_r) of executable skills with defined parameters and constraints.
- **Mission Planner**: A non-actuating foundation model (e.g., gpt-5.4-mini) that takes a user request and system state to produce a structured plan (π) as a sequence of (phase, robot, skill) tuples. The planner selects and instantiates a workflow contract.
- **Workflow Contracts**: Declarative specifications defining robot roles, admissible skills, guarded ordering constraints, argument-validity rules, and state-bound values to be resolved at dispatch time. These contracts are compiled from a single declarative specification to inform both the planner's prompt and the RO's runtime checks.
- **Robot Orchestrator (RO)**: A deterministic procedural runtime responsible for receiving the structured plan and instantiated contract. Before dispatching any skill, the RO performs five verification checks:
 1. Skill existence on the selected robot.
 2. Grounded and valid skill arguments, adhering to "request containment" (user-specified entities cannot be silently substituted).
 3. Adherence to the workflow contract's authorized transition sequence.
 4. Satisfaction of current robot state and skill/contract preconditions.
 5. Availability and validity of any runtime-bound values (e.g., dynamic target coordinates).
Only upon successful verification does the RO forward the action to the robot's hardware execution interface.

**C. Execution Protocol**
The system operates through a five-stage protocol:
1. **Retrieval**: Skill libraries, named locations, and workflow contracts are injected into the Mission Planner's context.
2. **Planning**: The Mission Planner generates a structured workflow (instantiated contract and ordered steps).
3. **Global Validation**: The RO globally validates the entire workflow (skill/location grounding, contract ordering). One replan is permitted if validation fails.
4. **Sequential Execution with Per-Dispatch Authorization**: Approved skills are executed sequentially. Each dispatch is re-authorized against the next pending step of the validated workflow and then consumed. Robot state updates from blocking calls.
5. **Termination**: Mission completes or halts if a runtime contract violation is refused.

**D. Implementation Details**
The architecture is instantiated using CrewAI as the base agent framework, modified to enforce the planning-execution separation. The Mission Planner's prompt is augmented with context rendered from the *same declarative specifications* used by the RO. The RO is implemented as procedural code. Robot adapters map authorized skills to embodiment-specific commands via ROS2 and Unitree SDK2. This design ensures the planner and contracts remain unchanged across simulation and real robot deployments.

**E. Experimental Setup**
The framework was evaluated across two heterogeneous robot crews:
1. **Air-Ground Orchestration (Simulation)**:
 - **Platforms**: Iris quadcopter (localization) and TurtleBot3 rover (navigation) in Gazebo (ROS2, PX4 SITL, MAVROS).
 - **Scenario**: Search-and-dispatch mission where the drone localizes a victim, and the rover navigates to the reported position. Crucially, the victim's position is unknown at planning time, requiring dynamic goal binding at dispatch.
 - **Skills**: Iris skills (takeoff, search_target, get_coordinates, land), TurtleBot3 skills (navigate_to, stop).
 - **Workflow Contracts**: SEARCH-AND-DISPATCH, SEARCH-ONLY, DISPATCH-ONLY, ABORT.
 - **Evaluation Protocol**: 20 scenarios (12 nominal, 8 fault injections including robot unavailability, out-of-bounds destinations, and perception faults like NaN transmission or missed detection).
 - **Conditions**:
 - **LLM-only**: No skill registry provided to the planner.
 - **Skill-list**: Skill registry and operational area retrieved and provided.
 - **RO-prompt**: Skill and workflow constraints provided in context, but *not enforced* at execution.
 - **RO**: Full system with dispatch-time enforcement and one feedback-driven replan.
 - **LLM**: gpt-5.4-mini (temperature 0.1) with consistent output schema and parser.
2. **Humanoid-Quadruped Crew (Hardware & Mocked Simulation)**:
 - **Platforms**: Unitree G1 humanoid (manipulation) and Unitree Go2 quadruped (transport).
 - **Scenario**: Object transportation task, varying whether a direct humanoid handoff or a humanoid-quadruped delivery is required based on requester location.
 - **Skills**: G1 skills (pick_handover, pick_place), Go2 skills (navigate).
 - **Workflow Contracts**: HANDOVER, CARRY, NAVIGATION-ONLY, MANIPULATION-ONLY (e.g., CARRY contract prevents quadruped departure before humanoid loading).
 - **Evaluation Protocol**: 20 scenarios with mocked adapters for quantitative study, and 2 real-robot trials for physical validation. A held-plan ablation study was performed to isolate the RO's effect by dispatching identical plans through RO-prompt and RO modes.

### 4. Main Findings and Results

The experimental evaluations across both simulation and physical hardware testbeds provided consistent findings regarding the dissociation of planning knowledge and execution safety.

**A. Air–Ground Orchestration in Simulation (Table I)**

1. **Grounding and Safety Are Dissociable**:
 - **Retrieval Improves Grounding**: Injecting the skill registry significantly improved skill grounding. The `LLM-only` condition showed only 51% skill grounding, with nearly half of its proposed actions being entirely hallucinated. In contrast, `Skill-list`, `RO-prompt`, and `RO` conditions, which included retrieval, achieved 96% skill grounding (p=9.7×10⁻⁷), indicating that providing the planner with capability context is crucial for generating valid actions.
 - **Retrieval Alone Does Not Guarantee Safety**: Even when the planner's knowledge was saturated (as in `Skill-list` and `RO-prompt`), the non-enforcing arms still dispatched 23% of grounding- or state-faulted steps. Furthermore, they blocked 0% of the injected fault scenarios (0% safety-gate recall).
 - **Deterministic Enforcement Ensures Safety**: Only the `RO` condition, with its deterministic dispatch-time enforcement, eliminated false dispatches entirely (0% false dispatch, p=5.0×10⁻⁴ vs. `RO-prompt`). It successfully blocked all eight injected fault scenarios with no false blocks (100% safety-gate recall and precision). This highlights that runtime enforcement, rather than prompt-side knowledge, is the decisive factor for physical safety. It was noted that `RO-prompt` and `RO` shared the identical prompt, emphasizing that the difference lay solely in enforcement.

2. **Closing the Structured-Channel Bypass**:
 - The `RO` system effectively handled perception faults where critical information (e.g., victim's position) was unavailable or corrupted at dispatch time. For instance, when a `nan transmission` fault occurred (corrupted coordinate), an unenforced LLM (`RO-prompt`) attempted to "recover" by substituting an approximate, plausible but incorrect position. The `RO`, however, closed this bypass by resolving the goal against the live state interface, refusing the step with a hard `no_target_fix` refusal, thereby blocking all perception faults.

3. **Gazebo Execution Validation**: All missions were executed live in Gazebo. The false dispatches observed in the unenforced arms corresponded to actual robot movements for six of the eight injected faults (e.g., commanding unavailable robots or moving to out-of-bounds destinations). The `RO` system prevented these actions, holding the rover until the drone published a validated detection. The rover's navigation under `RO` achieved a mean error of 0.465 m, comparable to a scripted baseline.

**B. Humanoid–Quadruped Crew (Table II)**

1. **Dissociation Replicates via Held-Plan Ablation**:
 - The pattern observed in simulation was reproduced on the humanoid-quadruped hardware infrastructure. Retrieval again improved skill grounding from 9% (`LLM-only`) to 91% (`Skill-list`).
 - The non-enforcing arms (`Skill-list`, `RO-prompt`) continued to dispatch 26-29% of faulted steps.
 - The `RO` system, through enforcement, reduced the false dispatch rate to 0% and achieved 100% safety-gate recall for faults (p=1.6×10⁻⁴).
 - A held-plan ablation study definitively isolated causality: dispatching the *identical plans* generated by the planner through both `RO-prompt` and `RO` modes showed that the deterministic gate alone reduced the false dispatch rate from 25.7% (9/35 steps) to 0%.

2. **Retrieval-Induced Substitution**:
 - The study characterized a failure mode termed "retrieval-induced substitution." As more grounding information was provided to the planner, its failures evolved. For an invalid destination request (e.g., "rooftop helipad"), the `LLM-only` planner would invent a non-existent skill. The `Skill-list` planner would select a real skill but with the invalid destination. However, the `RO-prompt` planner, with a full registry, would silently *substitute* the invalid destination with a valid but incorrect one (e.g., `dropoff`).
 - The `RO` detected and safely rejected these substitutions using a strict "request-containment" rule, preventing the execution of unintended actions.

3. **Hardware Validation (Figures 5 & 6)**:
 - Qualitative demonstrations on the Unitree G1 humanoid and Go2 quadruped validated the architecture's transfer to physical robots. By changing only the requester's location, the planner correctly selected between a `HANDOVER` workflow (direct humanoid delivery) and a `CARRY` workflow (humanoid loads quadruped, quadruped transports).
 - In the `CARRY` workflow, the cross-robot `load-before-depart` constraint was enforced by the `RO`, preventing the Go2 from navigating until the G1 had completed loading the object. This demonstrated the successful enforcement of temporal and multi-robot coordination constraints in a physical setting.

Overall, the findings consistently support a clear division of labor: LLMs provide high-level task interpretation and workflow selection, while the deterministic Robot Orchestrator is indispensable for enforcing physical constraints, guaranteeing safety, and resolving runtime-bound values before any action is physically executed. Retrieval enhances plan quality, but enforcement prevents unsafe outcomes.

### 5. Significance and Potential Impact

This research presents a significant contribution to the field of robotic AI, particularly concerning the safe and reliable deployment of LLM-orchestrated robot crews.

**A. Clarified Role of LLMs in Robotics**: The work clearly delineates the appropriate role for LLMs in physical robotics. It demonstrates that while LLMs excel at semantic reasoning, task decomposition, and generating plausible plans from open-ended natural language, they are not inherently reliable as direct command generators or as systems for self-enforcing physical constraints. Instead, their optimal function is as a non-actuating "Mission Planner" that proposes actions within a constrained, pre-verified skill library. This redefines the interface between advanced language models and physical systems.

**B. Enhanced Safety and Reliability for Robot Crews**: The core impact lies in establishing a deterministic Robot Orchestrator as a critical safety and reliability layer. By introducing per-dispatch verification against robot capabilities, system state, workflow contracts, and dynamic runtime-bound values, the architecture effectively prevents infeasible, mistimed, or unsafe actions from ever reaching the physical robots. This is particularly crucial for heterogeneous multi-robot systems where complex, evolving, and cross-robot constraints must be maintained. The empirical evidence of eliminating false dispatches and achieving 100% fault recall across two distinct testbeds underscores this capability.

**C. Robustness to LLM Limitations**: The framework explicitly addresses common failure modes of LLMs, such as hallucinations and retrieval-induced substitutions. By detecting and rejecting such errors at the orchestration layer through mechanisms like strict request containment and state-interface checks, the system becomes more robust to imperfections in LLM-generated plans. This contributes to building more resilient autonomous systems.

**D. Principled Multi-Robot Coordination**: The use of explicitly defined "executable workflow contracts" provides a structured and verifiable mechanism for coordinating complex interactions and dependencies among diverse robot types. This contract-mediated approach, enforced by the Robot Orchestrator, enables robust synchronization and resource management that spans individual robot capabilities.

**E. Addressing Dynamic and Temporal Constraints**: The architecture's ability to handle execution-critical information that is not available at planning time (e.g., a dynamically discovered target location) is a key advancement. By resolving these "state-bound values" at the moment of dispatch, the system can adapt to unfolding mission dynamics without compromising safety.

**F. Foundation for Future Research and Practical Deployment**:
The findings suggest a promising pathway for integrating powerful LLM capabilities into real-world robotic applications, especially in safety-critical domains. It lays a foundation for further research into:
- Investigating how different foundation models contribute to various types of planner errors, particularly substitution failures.
- Exploring the scalability of the declarative contract layer, as skill libraries and mission complexities grow beyond hand-authored specifications.
- Developing methods to further distinguish between planner errors and physical execution failures within authorized skills (e.g., a failed grasp after a valid dispatch), to allow for appropriate recovery mechanisms.

In essence, this work offers a pragmatic and secure architectural paradigm that leverages the advanced reasoning of LLMs while maintaining the necessary deterministic control for reliable and safe operation of physical robot crews. This could accelerate the development and deployment of more capable and trustworthy autonomous robotic systems in various industrial, service, and exploration applications.
