# A Self-Improving Coding Agent

> [!summary] Summary
> SICA is a self-improving coding agent that removes the meta-agent/target-agent split: the best-scoring agent in an archive edits its own Python codebase, is re-benchmarked, and the winner becomes the next editor. Guided by a utility mixing accuracy, dollar cost and wall-clock time, it invented diff-based editing and AST symbol lookup tools, lifting SWE-Bench Verified accuracy from 17% to 53% over 15 iterations.

## Problem

- Agent scaffolds are hand-crafted by trial and error, so human designers explore only a small slice of the possible prompting and tool-orchestration space.
- Automated agent-design systems keep a fixed meta-agent improving a separate target agent, so coding gains never compound back into the improver itself.
- Prior self-referential systems edit only a narrow forward function or small logic hooks in a domain-specific language, and are evaluated on math or algorithmic tasks, never real software engineering.

## Method

- ==Self-referential meta-agent loop==: the archive's highest-utility agent is selected as ==meta-agent==, inspects past agents plus their scores, edits the full Python codebase, and the successor is benchmarked.
- ==Utility function== weighting normalised benchmark score 0.5, dollar cost 0.25 (capped $10/problem) and wall-clock 0.25 (300 s timeout, halved score on timeout) to rank agents for selection.
- Initial scaffold supplies file open/close/overwrite, shell and calculator tools, ==coding/problem-solver/reasoning sub-agents== for context isolation, an ==append-only KV-cache-friendly context layout==, and an ==asynchronous LLM overseer== polling every 30 s to flag or cancel pathological runs.

## Results

- Over **15** iterations on a 50-question SWE-Bench Verified subset accuracy rose **0.17** to **0.53**; LiveCodeBench moved **0.65** to **0.71** and the synthetic file-edit benchmark **0.82** to **0.96**.
- Efficiency improved alongside accuracy: mean per-problem time fell **130.2 s** to **114.5 s** and cache-hit rate rose **32.5%** to **40.9%**; the whole run cost roughly **$7,000** in API calls.
- On AIME 2024 plus GPQA Diamond the loop stalled near **76%** mean accuracy, below o3-mini alone at **87%** and **79%**, with added reasoning scaffolds giving no gain.

## Takeaways

> [!tip] Key Insights
> - Scaffolding self-improvement pays off mainly on long-horizon agentic tasks; when the base model already solves the task, extra structure adds nothing or interrupts its reasoning.
> - Encoding cost and latency directly in the selection objective makes an agent optimise its own tooling efficiency, not just accuracy, without any weight updates.
> - The bottleneck is idea quality, not editing ability: early poor proposals bias later ones down the same theme, so path dependency drives run-to-run variance.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

This work is positioned at the forefront of research into Large Language Models (LLMs) and their application in autonomous agent systems, specifically focusing on the ambitious goal of self-improvement. The broader landscape can be characterized by several intersecting trends:

- **LLM Agents:** The primary context is the rapidly growing field of LLM agents. As LLMs become more powerful, researchers are exploring ways to "wrap them in code" to orchestrate their calls, provide them with tools, and enable them to interact with the real world. This extends beyond simple prompting to complex architectures for sequential decision-making and problem-solving. Prior work has shown that such agent systems dramatically improve performance over "plain" LLMs through sophisticated prompting strategies like Chain-of-Thought, Tree of Thoughts, and iterative self-refinement.
- **Automated Design of Agentic Systems (ADAS):** A crucial direct precursor to this work is the concept of automating the design and optimization of agent systems. While many prompting strategies and agent architectures have been hand-crafted, there's a recognized need for automated approaches to explore the vast solution space. Projects like AgentSquare and AlphaEvolve fall into this category, often using structured or evolutionary search to optimize agent components or behaviors.
- **Self-Improvement in AI:** Beyond ADAS, a more profound ambition in AI is for systems to learn and improve themselves. This ties into concepts of open-ended learning, intrinsically motivated reinforcement learning, and autotelic agents. While some works, like OPRO and Promptbreeder, focus on optimizing prompts through language, and others use LLMs for critique and refinement, the ability of an agent to *modify its own code* represents a significant leap.
- **Coding Agents:** A specific subset of LLM agents focuses on software engineering tasks, including code generation, debugging, and refactoring. The paper notes that "the first truly self-improving agents to be coding agents, because agents are written in code" is a natural progression. Benchmarks like SWE-Bench are crucial for evaluating these agents.

The authors explicitly distinguish their work from closely related prior efforts:

- **ADAS:** The key difference highlighted is that ADAS uses a separate "meta-agent" to improve a "target-agent." In contrast, SICA eliminates this distinction, making the system "fully self-improving." Furthermore, ADAS operates on a single `forward` function written in a domain-specific language, whereas SICA modifies its *full Python codebase*, making it more general-purpose and powerful.
- **Gödel Agent and Zelikman et al. (STOP):** While these works claim self-improvement, the paper argues they do not operate as "general-purpose coding agents" as traditionally understood. Gödel Agent relies on specific tools for minor logic modifications rather than broad code editing, and Zelikman et al. focuses on algorithmic tasks rather than arbitrary software engineering problems. SICA's ability to "open/close/edit files, run commands in the terminal etc." sets it apart as a more foundational coding agent for self-improvement.

In essence, SICA pushes the boundary by demonstrating a truly autonomous, self-referential coding agent that can directly edit and improve its own underlying Python implementation, addressing a critical gap identified in the literature regarding general-purpose self-modifying AI systems.

### 2. Key Objectives and Motivation

The core objective of this research is to demonstrate the feasibility and effectiveness of a **self-improving coding agent (SICA)** that can autonomously edit its own codebase to enhance its performance.

The primary motivations driving this work are:

- **Overcoming Manual Design Limitations:** Current agent systems often rely on "ad-hoc, trial-and-error" approaches for manually designing prompting schemes and orchestrators. This human-driven process is labor-intensive, time-consuming, and only explores a tiny fraction of the potential solution space for optimal agent behavior. The authors aim to automate this design process.
- **Leveraging Compounding Improvements:** The fundamental hypothesis is that if an agent can improve its own coding abilities, these improvements can then be leveraged in subsequent self-improvement steps. This creates a positive feedback loop, leading to compounding performance gains over time.
- **Establishing a Data-Efficient, Non-Gradient-Based Learning Mechanism:** The paper seeks to demonstrate an alternative learning paradigm. Instead of relying on traditional gradient-based methods (which require massive datasets and computational resources for model weight updates), SICA learns through "LLM reflection and code updates," making it highly "sample-efficient." It inspects past outcomes and uses this detailed information to make substantial, targeted modifications.
- **Developing a Fully Self-Referential Meta-Agent Programming System:** The authors are motivated to create a system where there is no distinction between a "meta-agent" (improving agent) and a "target-agent" (task-performing agent). SICA is both, allowing it to improve itself holistically.
- **Providing a Practical and Open-Source Foundation:** A key objective is to share a working implementation of SICA, built in standard Python, as a "reference agent framework." This aims to facilitate further research in self-improving agent systems and provide a robust platform for post-training LLMs on tool use and other agentic tasks.

In summary, the research is driven by the vision of truly autonomous AI systems that can continuously evolve and optimize their own operational code, moving beyond human-in-the-loop design and traditional machine learning paradigms.

### 3. Methodology and Approach

SICA's methodology revolves around a "Meta Agent Loop" (illustrated in Figure 1 and Algorithm 1) designed for continuous self-improvement.

#### 3.1. The Meta Agent Loop

The system maintains an archive of past agent versions and their performance results. In each iteration:
1. **Selection of Meta-Agent:** The "best" performing agent from the archive (based on a defined utility function) is selected to act as the meta-agent for the current iteration. This meta-agent is tasked with identifying potential improvements and implementing them. This differs from ADAS, where the meta-agent is fixed.
2. **Improvement Generation:** The selected meta-agent examines the archive of previous agents and their benchmark results, reflects on successes and failures, and then autonomously edits its own Python codebase to create a new, improved agent version.
3. **Evaluation:** The newly generated agent is rigorously evaluated on a set of diverse benchmarks.
4. **Archiving:** The results of the evaluation are stored in the archive, along with the new agent's code, to inform future improvement steps.

#### 3.2. Utility Function for "Best" Agent Selection

The "best" performing agent is determined by a utility function `U` (Equation 1) that balances three key desiderata:
- `p_score`: Normalized benchmark performance score (0-1).
- `p_cost`: Dollar cost per problem, capped at $10.
- `p_time`: Wall-clock time per problem, with a timeout of 300 seconds.
The coefficients (`w_score=0.5, w_cost=0.25, w_time=0.25`) indicate a stronger emphasis on performance, with cost and time also being significant considerations. A timeout penalty `τ=0.5` (Equation 2) is applied if the agent times out, ensuring partial credit while penalizing inefficiency. This multi-objective utility function guides the agent towards practical, resource-efficient improvements.

#### 3.3. Initial Agent System Design

SICA starts with a sophisticated base coding agent, equipped with several foundational capabilities that are themselves amenable to self-improvement:

- **Tools:** A suite of basic coding and operational tools are provided:
 - File manipulation: `open` (add to context), `close`, `overwrite_files`.
 - Execution: `execute_command` (shell commands), `calculator`.
 - Agent control: `submit_final_answer`, `return_result` (from sub-agents), `exit_early`.
 - Meta-learning: `archive_analysis` (to facilitate reflection).
 The paper mentions a flexible, unconstrained structured generation approach for tool calling, where the LLM outputs XML-formatted calls, with the closing tag serving as a stop token.

- **Sub-Agents:** To manage complexity and context length for long-running tasks, the initial agent includes three sub-agents:
 - `coding_agent`: For general code development and modification.
 - `problem_solver_agent`: For specific problem-solving tasks.
 - `reasoning_agent`: For complex logical or mathematical reasoning.
 These sub-agents are invoked by the main agent like tool calls, accepting arguments and returning results, allowing for task decomposition and efficient context management.

- **Asynchronous Overseer:** A critical component for autonomous, extended operation is the asynchronous LLM-based overseer. Running periodically in a concurrent thread, it monitors the agent's execution state by examining a comprehensive representation of the system (call graph, event stream of LLM messages, tool calls, etc.). Its role is to:
 - Detect pathological behaviors (e.g., looping, deviation from task).
 - Intervene by sending notifications to running agents.
 - In extreme cases, cancel an agent's execution if it is stuck or deviating too far.
 This mechanism ensures the system remains on-task and prevents resource wastage, providing a safety net for autonomous exploration and modification.

- **LLM Context Window Structure:** The agent's context is meticulously structured (Figure 2) to optimize LLM performance and context management:
 - **System Prompt:** Defines agent goals, tool/sub-agent documentation, and system instructions.
 - **Core Prompt:** Contains the problem statement, open file contents, and directory tree view.
 - **Assistant Messages:** Contains the running Chain-of-Thought reasoning, tool calls/responses, sub-agent calls/responses, and overseer notifications.
 File edits are initially handled as diffs, which are periodically consolidated to keep the file view current while preserving KV cache benefits.

The system primarily uses Sonnet 3.5 (v2) for most agents, with o3 mini used for the 'reasoning agent,' indicating the use of powerful, contemporary LLMs for the complex meta-improvement task.

### 4. Main Findings and Results

The experiments demonstrate significant improvements in SICA's performance across various coding benchmarks, particularly in tasks where agents can leverage structural and guidance scaffolding.

#### 4.1. Performance on Coding Benchmarks

The primary evaluation focuses on a 15-iteration run, with results summarized in Figure 3 and Table 1.
- **SWE-Bench Verified:** SICA showed substantial performance gains, improving from an initial accuracy of 17% to 53% on a random subset of 50 questions. This is a significant improvement on a benchmark known for testing problem decomposition, code navigation, and efficient file editing.
- **LiveCodeBench:** Performance saw a subtle but less pronounced improvement, moving from 65% to 71%. This benchmark often involves competitive programming-style problems requiring more theoretical reasoning.
- **Synthetic Benchmarks:**
 - **File Editing Benchmark:** This benchmark, curated within the agent's codebase, saw strong improvements. The initial agent, only capable of inefficient full file overwrites, quickly implemented "smart" editing tools based on diffs and ranges. Accuracy improved from 82% to 91-96% across iterations.
 - **Codebase Navigation (Symbol Location) Benchmark:** For this task, the agent improved by implementing an AST-based symbol locator at iteration 9, contributing to improved performance (from 35% to 40-43%). Later, a "Hybrid Symbol Locator" combining ripgrep and AST verification further enhanced this.

#### 4.2. Specific Agent Improvements (Appendix D)

The analysis reveals *how* the agent improved itself, showcasing its learning trajectory:
- **Early Iterations (1-3):** Focused on optimizing file editing, introducing a "Smart Editor" tool and "Quick Overwrite Tool" to reduce token usage and improve efficiency.
- **Mid-Iterations (5-8):** Developed tools for code context summarization and enhanced file edit verification, making codebase exploration and modification more robust.
- **Later Iterations (9-13):** Implemented sophisticated code navigation tools like the "AST Symbol Locator" and a "Hybrid Symbol Locator" (ripgrep + AST), demonstrating an understanding of code structure. Optimizations for minimal diff output and context-sensitive diff minimization were also introduced to further reduce token usage.

#### 4.3. Resource Efficiency

While the total API cost for 15 iterations was approximately $7,000 (reflecting the complexity of the meta-improvement task and use of powerful models), the system also showed a slight decrease in the average time spent per problem and improved token caching efficiency across iterations (Table 1), indicating improvements in resource management alongside accuracy gains.

#### 4.4. Performance on Reasoning Tasks (Figure 4)

An additional experiment on reasoning-heavy question answering tasks (AIME2024 and GPQA Diamond) showed less improvement compared to coding benchmarks. The agent system, starting at 76% accuracy, found only marginal benefits despite implementing components like "Independent math verifier" and "Sympy symbolic calculator." This highlights "Agent Framework Saturation," where if the underlying LLM (e.g., o3-mini, scoring 79-87% on these tasks) is already highly capable for a specific domain, the scaffolding provided by the agent system offers diminishing returns, and might even interfere with the model's natural chain-of-thought.

Overall, the results empirically demonstrate that SICA effectively learns to improve its own implementation, particularly in "longer-horizon 'agentic' tasks where the base LLMs stand to gain more from the structure and guidance of a scaffolding system."

### 5. Significance and Potential Impact

The work on SICA marks a significant step forward in the field of artificial intelligence, particularly in the domain of autonomous systems and software engineering.

#### 5.1. Demonstration of True Self-Improvement

The most profound significance is the empirical demonstration that a general-purpose coding agent can genuinely self-improve by editing its own Python codebase. By eliminating the distinction between a meta-agent and a target agent, SICA realizes a fully self-referential system. This moves beyond merely optimizing prompts or internal states, allowing the AI to fundamentally alter its own operational logic and tooling. This capability is crucial for building increasingly autonomous and adaptive AI.

#### 5.2. Novel Learning Mechanism

SICA introduces and validates a "non weight-based learning mechanism." Unlike traditional machine learning that relies on gradient updates to model parameters, SICA learns through "reflection and code updates." This approach is highlighted as being "very sample-efficient," as it learns from detailed inspection of past outcomes to make substantial, informed modifications. This paradigm could pave the way for more efficient AI development, especially in scenarios where large-scale data collection and gradient-based fine-tuning are impractical or costly.

#### 5.3. Practical Advancements in Automated Agent Design

The demonstrated performance improvements (e.g., 17% to 53% on SWE-Bench Verified) showcase SICA's practical utility. The agent's ability to autonomously develop and integrate new tools (like smart editors, AST symbol locators) and refine existing ones could revolutionize how complex agent systems are designed and optimized. This reduces the reliance on human experts for "ad-hoc, trial-and-error" design, potentially accelerating the development of robust and efficient AI agents for diverse applications. The release of SICA's code also provides a valuable open-source framework for the community.

#### 5.4. Implications for Future AI Development

- **Joint Training of LLMs and Agent Systems:** The paper points to a promising future direction: jointly training foundation models with their agent systems. SICA's current approach focuses on scaffolding improvements, but integrating this with model weight updates (as hinted by AlphaEvolve) could unlock even greater potential for AI autonomy and capability.
- **Automated Benchmark Curation:** The successful inclusion of synthetically generated benchmarks by the agent itself suggests a path towards addressing "benchmark saturation." Future self-improving systems might not only solve tasks but also autonomously define new, challenging evaluations for themselves, fostering open-ended learning and discovery.

#### 5.5. Safety Considerations

The authors responsibly address safety implications, particularly given the self-improving nature of the system.
- **Reduced Risk (Current Scope):** They emphasize that the current system's inability to modify its own model weights inherently limits some risks (e.g., encoding stenographic messages).
- **Mitigation through Observability:** SICA is designed with robust observability mechanisms, including an interactive web interface and an asynchronous LLM-based overseer. This allows humans to monitor the agent's chain-of-thought, actions, and sub-agent invocations, enabling intervention if pathological behaviors arise. The overseer itself can use a different, potentially more constrained, LLM for judgment.
- **Iterative Evaluation with Safety Benchmarks:** The framework allows for the inclusion of safety-related evaluations in the benchmark set. This means each new agent iteration can be validated against safety criteria before being accepted as the basis for further self-improvement.

While acknowledging that full safety for systems capable of updating their own model weights requires further research, the paper provides a foundational discussion on mitigating risks within the scope of code-editing self-improvement. The primary focus on improving code editing and multi-step reasoning suggests low direct adverse societal consequences for the work itself.

In conclusion, SICA represents a compelling proof-of-concept for truly self-improving AI. Its innovative approach to learning through code modification, combined with its practical performance gains and open-source release, positions it as a significant contribution that could influence the future design, development, and capabilities of autonomous AI agents.
