# WorldCoder, a Model-Based LLM Agent: Building World Models by Writing Code and Interacting with the Environment

> [!summary] Summary
> WorldCoder is a model-based LLM agent that learns a Python program as its world model, covering transition and reward functions. It refines the program with GPT-4 from environment interactions. An optimism constraint requires the model to admit a path to reward, which drives exploration. It solves Sokoban, Minigrid and AlfWorld with far fewer interactions than deep RL and fewer LLM calls than ReAct, and it transfers by editing code.

## Problem

- Deep model-based and model-free RL need millions of environment interactions to learn even basic worlds. The learned neural world models are opaque and transfer poorly to new tasks.
- LLM agents such as ReAct use the LLM as an implicit world model and planner, so they make LLM calls at every action. Their cost grows linearly with episode length.
- Sparse-reward, long-horizon tasks make exploration hard. Program-synthesis world learners also used restricted domain-specific languages and intricate search, not general Python with pretrained LLM priors.

## Method

- ==World model as Python code==: separate ==transition and reward subroutines== over ==object-based states==. The LLM writes and debugs the simulator, and a planner (==value iteration== or ==MCTS==) acts on it.
- ==Optimism-under-uncertainty objective==: a ==logical constraint== requires the program to fit all replay data (phi1) and to allow a rewarding path to the goal (phi2). It drives exploration and zero-shot instruction following.
- ==Refinement-based synthesis==: GPT-4 repairs its program using transitions it fails to explain, guided by the ==REx bandit heuristic==. Transfer across environments comes from refining old programs in a ==curriculum==.

## Results

- Sokoban: the world model is learned within about **50 actions**, while deep RL needs over **1 million steps** for 2-box levels. ReAct solves only **15% ± 8%** of basic levels.
- Cost: front-loading roughly **400k LLM tokens** (about **$15**) lets the agent take unlimited actions without further LLM queries. ReAct-style agents pay per action.
- Ablations: without optimism, Minigrid harder tasks fail and zero-shot new goals fail, and a prompt-only reward ablation also fails. AlfWorld has no nonzero performance without it. UnlockPickup takes under **100 actions**, while PPO fails after **3×10^8**.

## Takeaways

> [!tip] Key Insights
> - Have the LLM build a simulator of the world rather than act as the simulator. Cost then amortizes to near-constant LLM calls per task, and the knowledge stays auditable.
> - Requiring the model to be consistent with data and also able to reach reward gives goal-directed exploration. It also corrects LLM mistakes when reward functions are generated for new goals.
> - Code models transfer by editing and are limited by deterministic dynamics and symbolic, discrete states. Continuous perception needs added object detectors or neurosymbolic bridges.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

WorldCoder positions itself at a critical juncture in the fields of reinforcement learning (RL), large language models (LLMs) for AI agents, and neurosymbolic AI. Traditionally, model-based RL has focused on learning world models—mappings of state-action transitions—either as neural networks (Deep Model-Based RL) or through extensive hand-engineering in symbolic domains. Recent advancements have also seen LLMs directly acting as "world models" by reasoning about actions and their consequences (e.g., ReAct-style agents).

WorldCoder explicitly contrasts itself with these two dominant paradigms:
- **Against Deep Model-Based RL:** The paper argues that deep RL approaches, while powerful, often require millions of environmental interactions (high sample complexity) to learn world models, and these models are typically opaque and difficult to transfer. WorldCoder aims for significantly higher *sample efficiency* and *transferability* by learning explicit, human-interpretable code.
- **Against ReAct-style LLM Agents:** These agents leverage the LLM itself for reasoning and acting, essentially using its implicit world knowledge. However, they suffer from high *compute costs* as they require LLM queries at every action. Furthermore, LLMs are known to struggle with intricate planning. WorldCoder proposes a different role for the LLM: not as the world model or the planner, but as a "programmer" that *builds* an explicit, executable world model in Python. This separates the world modeling and planning functions, leading to better compute efficiency post-learning and more robust planning.

The work builds upon prior research in program synthesis for world models, but notably extends it by using Turing-complete Python (instead of domain-specific languages) and integrating LLMs for the synthesis process. It also incorporates novel exploration strategies based on "optimism in the face of uncertainty," framed as a logical constraint, which differentiates it from purely data-fitting approaches. By synthesizing interpretable code, WorldCoder bridges symbolic and neural AI, offering advantages in terms of auditability, composability, and transfer, addressing key limitations of end-to-end deep learning.

### 2. Key Objectives and Motivation

The central objective of WorldCoder is to enable an AI system to acquire, transfer, and communicate its knowledge of "how things work" in an environment, much like humans do. This is cast as the problem of learning a *world model*, specifically a transition function that predicts the next state given the current state and action.

The motivations behind choosing a code-based world model and LLM-guided synthesis are multi-fold:
- **Knowledge Acquisition:** To allow AI systems to quickly learn fundamental environmental dynamics from limited interactions, similar to how humans infer rules for new devices or games.
- **Transferability:** To facilitate the transfer of learned knowledge to novel goals or similar environments by reusing or editing existing code, rather than relearning from scratch.
- **Interpretability and Communicability:** Representing knowledge as code inherently makes it human-interpretable and auditable, allowing for symbolic communication of learned rules. This contrasts with the black-box nature of many neural network-based world models.
- **Addressing RL Challenges:**
 - **Sample Efficiency:** Deep RL often requires vast amounts of data. WorldCoder aims to dramatically reduce the number of environment interactions needed by leveraging the LLM's prior programming knowledge and through a novel exploration objective.
 - **Compute Efficiency:** Unlike LLM agents that make expensive LLM calls per action, WorldCoder amortizes the LLM cost during the model-building phase, making subsequent planning and action much cheaper.
 - **Efficient Exploration (Sparse Rewards):** In long-horizon tasks with sparse rewards, effective exploration is difficult. The paper introduces an "optimism in the face of uncertainty" objective to guide goal-driven exploration even before positive reward is observed.
 - **Program Search Tractability:** To make the combinatorial problem of program synthesis more manageable, the approach leverages curriculum learning and refinement, where existing code is debugged and extended.

### 3. Methodology and Approach

WorldCoder operates as a model-based reinforcement learning agent with a unique architecture centered around LLM-driven program synthesis.

- **Problem Formalization:** The problem is framed as a Contextual Markov Decision Process (CMDP), where a natural language goal is provided as a context. The environment dynamics are assumed to be deterministic and fixed across goals, with states represented as sets of objects (Object-Oriented MDP).
- **World Model Representation:** The core innovation is representing the world model as Python code. This includes a `transition` function (`ˆT`) that maps (state, action) to a new state, and a `reward_model` (`ˆR`) that maps (context, state, action, next state) to (reward, done flag). Implementing these as separate Python subroutines promotes disentanglement of dynamics from rewards.
- **World Model Learning Objectives:** The learned Python programs must satisfy two key logical constraints:
 - **Fit Data (ϕ₁):** The primary objective is for the `ˆT` and `ˆR` functions to accurately predict all past observed environmental interactions (s, a, r, s', c, d) stored in a replay buffer.
 - **Optimism in the Face of Uncertainty (ϕ₂):** This novel objective is crucial for efficient exploration, especially in sparse reward settings. Given an initial state (s₀) and a goal (c), ϕ₂ demands that the learned world model (`ˆT`, `ˆR`) must *imply* that there exists a sequence of actions leading to a state with positive reward. This forces the agent to "invent" a path to reward if none has been observed, guiding exploratory behavior towards promising, unobserved states. The paper provides a theoretical analysis showing this leads to polynomial sample complexity.
- **Program Synthesis via Refinement:** WorldCoder uses an iterative refinement process to synthesize the world model code:
 1. An LLM (GPT-4) is prompted with a random subset of observed data (s, a, r, s', c, d) to propose an initial candidate program for `ˆT` and `ˆR`.
 2. If the program fails to satisfy either ϕ₁ (inconsistent with data) or ϕ₂ (cannot plan to a rewarding state), the LLM is "backprompted" with the failing data points or the violation of the optimism constraint. It is asked to debug and refine its code.
 3. This process repeats until both ϕ₁ and ϕ₂ are satisfied. The REx algorithm is used to prioritize which programs to refine, balancing fitting data and achieving optimism.
- **Overall Agent Architecture:** The agent alternates between acting and learning (Algorithm 1). It starts with random exploration, then periodically attempts to synthesize/refine its world model. Once a sufficiently good world model is learned, it uses a planner (depth-limited value iteration or Monte Carlo Tree Search for complex domains like AlfWorld) to select actions based on the current world model. A BM25-based heuristic guides planning in text-based environments by measuring textual similarity between partial trajectories and the natural language goal. When a new goal is encountered, ϕ₂ is immediately violated, triggering the refinement process for the reward function to cover the new goal.

### 4. Main Findings and Results

WorldCoder's performance was evaluated across three distinct environments: Sokoban, Minigrid, and AlfWorld, demonstrating its sample efficiency, compute efficiency, and transfer capabilities.

- **Sokoban:**
 - **Sample & Compute Efficiency:** WorldCoder achieved basic competence in Sokoban with significantly fewer environment interactions (around 50 actions) compared to Deep RL baselines (millions of steps). Its LLM token cost was amortized (400k tokens, ~$15, upfront), unlike ReAct-style agents which incur linear cost per action, making WorldCoder asymptotically more compute-efficient.
 - **Pretrained Knowledge vs. Learning:** While the underlying LLM likely benefited from pretraining on Sokoban-like dynamics, a ReAct baseline (which directly uses the LLM for reasoning) performed poorly, demonstrating that mere knowledge is insufficient; the explicit model building is crucial.
 - **Adaptability:** WorldCoder successfully learned modified Sokoban rules, including complex dynamics like teleportation gates that deactivate when blocked, showcasing its ability to adapt to unseen dynamics.
 - **Optimism Objective (ϕ₂):** ϕ₂ had minimal impact in Sokoban due to its dense reward structure, where random exploration already yields sufficient information.

- **Minigrid:** This environment suite focused on transfer learning and instruction following.
 - **Transfer Learning:** WorldCoder demonstrated effective transfer across a curriculum of environments. It could extend its knowledge to incorporate new objects and dynamics (e.g., keys and doors) with few-shot generalization. For new natural-language goals with no new dynamics (e.g., "open the door"), it achieved zero-shot generalization.
 - **Importance of Optimism (ϕ₂):** In Minigrid's sparse reward settings, ϕ₂ proved critical. Without it, WorldCoder struggled to solve harder environments, highlighting its role in promoting goal-directed exploration. An ablation ("prompt4reward") where GPT-4 was simply prompted to generate a reward function for a new goal also struggled, indicating that ϕ₂'s active correction of the LLM's generated reward function is vital for instruction following.

- **AlfWorld:** This complex household robot task planning domain tested scalability.
 - **Scalability:** WorldCoder successfully synthesized world models comprising 250+ lines of Python code, accurately modeling interactions with various objects and appliances.
 - **Optimism's Necessity:** ϕ₂ was indispensable for achieving any non-zero performance on these tasks, emphasizing its role in navigating sparse reward, long-horizon environments.
 - **Planning with Heuristics:** The use of MCTS combined with a BM25-based heuristic (measuring textual overlap between trajectories and goals) effectively guided planning, further showcasing the framework's modularity and ability to integrate different planning components.

### 5. Significance and Potential Impact

WorldCoder represents a significant step towards building AI agents that learn generalizable, interpretable, and transferable world knowledge.

- **Bridging Symbolic and Neural AI:** By leveraging LLMs to synthesize and debug explicit symbolic programs, WorldCoder effectively bridges the gap between traditional symbolic AI's strengths (interpretability, logical reasoning) and modern deep learning's capabilities (powerful pattern recognition, code generation). This "neurosymbolic" approach offers a promising direction for more robust and transparent AI.
- **Practical Advantages:**
 - **High Sample Efficiency:** The demonstrated orders-of-magnitude improvement in sample efficiency over deep RL is crucial for real-world applications where data collection is expensive or risky (e.g., robotics).
 - **High Compute Efficiency:** The amortized LLM cost makes WorldCoder attractive for deployment once the model is learned, contrasting sharply with the continuous, high cost of direct LLM agents.
 - **Transferability:** The ability to transfer knowledge by editing code rather than relearning entire models is a key enabler for rapid adaptation to new tasks and environments.
 - **Interpretability:** The world model being human-readable Python code allows developers to inspect, understand, and debug the agent's knowledge, fostering trust and enabling easier integration of human expertise.
- **Novel Exploration Strategy:** Formulating "optimism in the face of uncertainty" as a logical constraint and integrating it into program synthesis is a novel contribution to model-based RL exploration. This goal-driven exploration is particularly impactful in sparse reward settings.

### 6. Limitations and Open Directions

The paper openly discusses several limitations, which also serve as promising future research directions:
- **Deterministic Dynamics:** The current approach assumes deterministic environments. Extending to probabilistic programs would be a complex but valuable next step.
- **Symbolic/Discrete States:** WorldCoder requires symbolic state representations. Future work could integrate with pre-trained object detectors or develop neurosymbolic programs that bridge raw perception to symbolic processing.
- **Basic Knowledge Management:** The current method relies on basic code debugging for knowledge growth. Future improvements could involve building sophisticated "library learning" systems that refactor and manage reusable subroutines and classes, enabling more robust and systematic knowledge acquisition and transfer.

In summary, WorldCoder demonstrates a compelling paradigm for constructing intelligent agents that learn explicit, adaptable, and understandable models of the world, leveraging the generative and debugging capabilities of LLMs to overcome long-standing challenges in reinforcement learning.
