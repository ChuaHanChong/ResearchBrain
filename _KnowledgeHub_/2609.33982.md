# Test-Time Spatial Reasoning for Robot Manipulation Using Generative Real-to-Sim

> [!summary] Summary
> Simify is a training-free, test-time framework for physically grounded spatial reasoning in multi-object rearrangement. From a single RGB-D image it builds a simulation-ready digital twin using segmentation, amodal inpainting and image-to-3D mesh generation. It then runs evolutionary search over placement order and 6D goal poses across thousands of parallel physics rollouts, averaging 87.5% task score and beating LLM-planner and partial-geometry baselines on a real robot.

## Problem

- Spatially aware VLMs and 3D foundation models capture semantic relations but lack the geometric precision and physical grounding needed for stacking, balancing and dynamic object interactions.
- VLAs and imitation policies need massive teleoperation data yet mostly replay familiar action patterns, rarely discovering new strategies for novel tasks or unseen objects at test time.
- Prior real-to-sim pipelines need known object models, dense multi-view scans or manual setup, cannot recover occluded geometry from one view, and mostly train policies toward already-given goals.

## Method

- ==Generative real-to-sim pipeline==: ==SAM-2== segment proposals grouped by GPT-4o, Stable-Diffusion ==amodal inpainting==, ==Hunyuan3D-2== meshes scaled to depth via ==ICP==, posed with ==FoundationPose==, loaded into Isaac Lab.
- ==Evolutionary optimization== jointly mutates discrete placement order and continuous goal poses, scoring each candidate by noisy sequential placement and physics settling, keeping top-5% elites plus ==reward-softmax resampling==.
- Noisy validation stage re-scores final candidates over many perturbed rollouts and selects the highest expected reward; execution uses mesh-based grasp sampling, ==cuRobo== motion planning and force-sensed placement release.

## Results

- Simify scores **82.2, 85.9 and 94.3%** on Stacking, Cantilever and Dominoes (mean **87.5%**), versus **64.0%** without validation and **10.3%** for random arrangements on the same meshes.
- Beats LLM-GROP with GPT-5 goal-pose reasoning, which only handles Stacking well, and TSDF-EA partial geometry, which failed all 10 real Stacking trials at the planning stage.
- Generated meshes reach F1 **0.927** versus **0.682** for TSDF on low-occlusion YCB scenes; more parallel environments raise scores, and 1024 environments optimize in **73 seconds** on average.

## Takeaways

> [!tip] Key Insights
> - A physics simulator plus search can act as a test-time spatial reasoning engine, beating language-model priors whenever tasks hinge on precise continuous poses and contact dynamics.
> - Geometric completeness, including unobserved surfaces like object bottoms, matters more than visible-surface accuracy for sim-to-real transfer; generative 3D priors supply what single-view depth cannot.
> - Selecting plans by expected reward under injected noise rather than best-case score yields robust arrangements, though results stay sensitive to assumed mass, friction and center of mass.

## Detailed Report

### 1. Overview

Stacking unfamiliar objects into a tall tower takes more than choosing where each one goes. A robot must reason about what an arrangement means, and also about whether it will balance, make the intended contacts, and survive the move. Simify lets the robot test arrangements before it acts. It reconstructs a scene from one RGB-D view, searches over object placement order and poses in a physics simulator, then executes the selected plan. On three rearrangement tasks, it often found better-scoring plans than the compared alternatives. The experiments assume that the task reward function is supplied.

Examples of the system's intended use, including "Build the tallest tower with three objects," "Build the longest overhang," and "Knock over the aqua bottle." The examples are illustrative, not measured success rates.

### 2. From one view to a tested plan

From the single RGB-D view, SAM-2 proposes object segments. A vision-language model identifies manipulable objects and assigns segments. A 2D inpainting model completes occluded object views, and an image-to-3D model then generates meshes. These meshes are scaled against observed depth and registered before the scene is loaded into GPU-accelerated physics simulation. Generative completion estimates unseen geometry; it does not directly measure it.

Each candidate plan specifies a discrete placement order and continuous 6D poses. Simify simulates objects being placed and settling, then scores the final scene with the supplied reward. It keeps the top 5% unchanged, and samples and mutates the rest according to reward-based probabilities. After evolution, it evaluates candidates across multiple noisy rollouts and selects the one with the highest expected reward. This final validation matters because a pose that succeeds in a clean rollout may be brittle to placement error.

### 3. What the comparisons show

A task score is the task's reward normalized between that task's minimum and maximum reward. The study runs 10 full method repeats per task and method, then evaluates each resulting solution in 2,048 noisy simulation repeats.

In Dominoes, the robot places a green bottle and a tin can, and a static pile including a book can serve as a ramp. The reward increases with how far the target bottle moves after the scene settles. On this task, Simify scores **94.3%**, compared with **7.5% for LLM-GROP** and **8.2% for TSDF-EA**. Simify scores higher than both methods on all three tasks. LLM-GROP does well on Stacking but does not reliably complete the other tasks.

The two baselines test different things. LLM-GROP is a prior language-model-guided task-and-motion-planning system. In the adapted version, GPT-5 receives the reward, axis constraints, an annotated scene image, and object names, masses, and bounding boxes. Its results suggest that semantic goal reasoning alone was not enough for these tested precise, contact-heavy tasks.

TSDF-EA uses the same evolutionary search as Simify, but it reconstructs only visible geometry from depth instead of using generated, completed meshes. In the paper's explanation, unobserved surfaces can matter to simulated contact. For example, the tin can's unseen bottom affects how it rolls down a ramp.

Normalized task scores (%) for Simify, LLM-GROP, and TSDF-EA on Stacking, Cantilever, Dominoes, and their mean. Simify's bars are highest for each task. These are simulation task scores, not real-robot success rates.

An ablation tests the validation step using the same generated meshes. Simify's mean normalized task score across Stacking, Cantilever, and Dominoes is **87.5%**. Simify-NoVal, which omits the final noisy-rollout validation, scores **64.0%**. This supports the authors' claim that selecting for performance under perturbations matters. It does not show that validation eliminates execution failures.

### 4. Contribution and limits

Simify shows that, for these three rearrangement tasks, combining generative geometry with test-time physics search can find better-scoring plans without a training set of successful arrangements. This is simulation evidence: each method's solution is evaluated with its own optimization mesh, and sim-to-real transfer is assessed separately. The authors assume that task rewards and physical parameters such as mass and friction are given. Converting natural-language instructions into rewards remains future work. The robot's execution pipeline is also not simulated during search, so a highly rewarded simulated arrangement is not thereby guaranteed to be robot-executable.
