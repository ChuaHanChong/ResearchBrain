# MemFactory: Unified Inference & Training Framework for Agent Memory

> [!summary] Summary
> MemTensor's MemFactory presents a unified, modular, and open-source framework to streamline the development and optimization of memory-augmented AI agents, integrating static fine-tuning and dynamic policy optimization via Reinforcement Learning. It demonstrates enhanced performance on long-context tasks, with a Qwen3-1.7B model showing a 14.8% relative score increase and a Qwen3-4B model achieving a 7.3% relative increase.

## Problem

- Existing memory-augmented LLM systems relying on static Retrieval-Augmented Generation (RAG) or heuristic rules struggle with memory redundancy, conflicting information, and context window limitations.
- The Memory-Reinforcement Learning (RL) research landscape is fragmented, characterized by highly customized, task-specific implementations that hinder reproducibility and module integration.
- A unified infrastructure tailored for the complex, stateful lifecycle of memory-augmented agents, comparable to fine-tuning frameworks for general LLMs, was absent, leading to a high barrier to entry for researchers.

## Method

- **MemFactory** introduces a unified, modular framework structured into four interdependent layers (Module, Agent, Environment, Trainer) to manage the entire development and optimization pipeline for ==memory-augmented agents==.
- It decomposes complex memory engineering into atomic, plug-and-play components (==Extractors==, ==Updaters==, ==Retrievers==) within the Module Layer, enabling flexible, "Lego-like" construction of agent memory strategies.
- The framework integrates ==Group Relative Policy Optimization (GRPO)== into its Trainer Layer, allowing for memory-efficient fine-tuning of agent memory management policies based on multi-dimensional environmental rewards.

## Results

- **MemFactory** improved the average performance of a MemAgent architecture by **14.8%** for the **Qwen3-1.7B** model and **7.3%** for the **Qwen3-4B-Instruct** model on challenging long-context evaluation sets.
- The entire training and evaluation pipeline was successfully executed on a single NVIDIA A800 80GB GPU, demonstrating the framework's reproducibility and efficiency with modest computational resources.
- The **Qwen3-4B-Instruct** model exhibited robust performance gains across all evaluation sets, including out-of-distribution data, suggesting better generalization capabilities for larger models trained with the framework.

## Takeaways

> [!tip] Key Insights
> - A modular, layered architecture effectively simplifies the complex development and experimentation process for memory-augmented agents, promoting extensibility and interoperability of components.
> - Standardizing atomic memory operations enables flexible combination and rapid prototyping of diverse memory management strategies, reducing redundant engineering effort.
> - Group Relative Policy Optimization (GRPO) offers an efficient approach for optimizing dynamic memory policies through RL, even under constrained computational resources, by eliminating the need for an auxiliary value network.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

Large Language Models (LLMs) have demonstrated capabilities in natural language processing. However, their transition into autonomous AI agents necessitates the ability to maintain long-term context, accumulate historical experiences, and personalize behavior over continuous interactions. This requirement has led to a focus on memory-augmented LLMs.

Initial approaches to memory augmentation frequently utilized static Retrieval-Augmented Generation (RAG) paradigms or heuristic-based memory updating rules. These methods encountered challenges such as memory redundancy, conflicting information, and context-limit constraints, particularly in prolonged interactions.

A more recent development involves optimizing memory operations through Reinforcement Learning (RL). This paradigm frames memory management as a sequential decision-making process, enabling agents to learn policies for memory extraction, updating, and retrieval based on environmental feedback. Pioneering works in this area, such as Memory-R1, MemAgent, and RMM, have shown that RL-trained models can develop sophisticated memory strategies that may surpass heuristically driven counterparts.

Despite these advancements, the research ecosystem for Memory-RL is described as fragmented. Implementations are often customized for specific tasks, deeply coupled with particular datasets, and dispersed across isolated repositories. This fragmentation can necessitate substantial and redundant engineering effort for researchers attempting to reproduce, evaluate, or combine different memory modules (e.g., integrating a retrieval module from one work with a reranker from another).

In contrast, the broader LLM fine-tuning landscape has seen the emergence of unified frameworks like LLaMA-Factory, which have provided systematic and scalable infrastructures for model adaptation. The present work, MemFactory, aims to fill the identified gap by introducing a comparable unified infrastructure specifically designed for the complex and stateful lifecycle of memory-augmented agents, integrating modular memory construction with dynamic, RL-driven policy optimization.

### 2. Key Objectives and Motivation

The primary motivation behind MemFactory is to address the fragmentation and engineering burden prevalent in the development and evaluation of memory-augmented AI agents, particularly those utilizing Reinforcement Learning for memory management. The authors identify a lack of a unified infrastructure to streamline the integration, training, and evaluation of these complex pipelines.

Based on this overarching motivation, the key objectives for MemFactory are:

- **To establish a unified infrastructure for Memory-RL:** The framework aims to be the first comprehensive platform that unifies the training, evaluation, and inference pipelines for memory-augmented AI agents. This unification is intended to reduce the engineering overhead for researchers, allowing them to focus on algorithmic innovation rather than infrastructure development.
- **To provide a highly modular and extensible design:** MemFactory seeks to abstract the memory lifecycle into atomic, plug-and-play components. These components, categorized as extractors, updaters, and retrievers, are intended to enable a "Lego-like" assembly paradigm, facilitating the seamless construction and customization of diverse memory architectures. An "Agent Module" is also introduced to accommodate end-to-end memory policies.
- **To natively integrate Reinforcement Learning for policy optimization:** The framework is designed to support the optimization of internal memory management policies through RL. Specifically, it integrates Group Relative Policy Optimization (GRPO) to fine-tune agent behaviors based on multi-dimensional environmental rewards. This integration is motivated by the need for dynamic and adaptive memory strategies that can learn from feedback.
- **To offer out-of-the-box support for contemporary paradigms:** MemFactory intends to standardize and incorporate recent Memory-RL works, including Memory-R1, MemAgent, and RMM. This objective aims to provide readily executable baselines and foster easier reproduction and comparison of state-of-the-art algorithms, thereby lowering the barrier to entry for researchers.
- **To empirically validate its effectiveness:** The authors aim to demonstrate the framework's capability by showing that it can successfully train and optimize memory agents, yielding performance improvements over base models on relevant evaluation datasets. This validation serves to confirm MemFactory's practical utility as a research infrastructure.

In summary, MemFactory is motivated by the need for a standardized, flexible, and efficient framework to accelerate research and development in memory-augmented LLM agents, particularly those leveraging RL for adaptive memory management.

### 3. Methodology and Approach

MemFactory is designed as a unified training and inference framework characterized by a highly modular architecture. It comprises four primary components: the Module Layer, Agent Layer, Environment Layer, and Trainer Layer.

#### 3.1. Module Layer: Atomic Memory Operations

This layer serves as the core of the framework, abstracting the memory engineering pipeline into atomic operations. It defines four primary module classes, each with standardized `generate`, `rollout`, and `inference` interfaces.

- **Memory Extractor:** Responsible for parsing raw contexts into structured memory pieces, extracting facts, experiences, or insights. The framework includes a `NaiveExtractor` class, drawing inspiration from Memory-R1, for this purpose.
- **Memory Updater:** Compares newly extracted memory candidates with existing memories to formulate an update plan. The `NaiveUpdater` class, also inspired by Memory-R1, manages memory states through operations such as ADD (incorporate new information), DEL (remove obsolete facts), UPDATE (modify existing entries), and NONE (no changes required).
- **Memory Retriever:** Tasked with fetching the most relevant memories from a memory bank to inform the agent's responses. Implementations include a `NaiveRetriever` for standard semantic-based retrieval and a `RerankRetriever` which leverages Large Reasoning Models (LRMs) to re-evaluate and re-rank initial retrieval results for enhanced precision, a technique used in RMM.
- **Agent Module:** Designed to support highly integrated, end-to-end memory strategies that may not strictly separate extraction and update phases. An example is the `RecurrentMemoryModule`, which follows the design of MemAgent, synthesizing new memory states directly from the latest context and previous states without explicit retrieval operations. This module allows optimization of unified, recurrent memory policies within the framework's training mechanism.

#### 3.2. Agent Layer: Module Integration and Policy Execution

This layer functions as the central policy executor, building upon the Module Layer. It adopts a "Lego-like" paradigm for constructing memory agents by integrating various modules.

- **Agent Initialization:** During initialization, pre-trained models are loaded using `AutoClasses` from the Transformers library. FlashAttention-2 is integrated to handle long-context tasks and optimize memory usage. The loaded pre-trained model is the direct target for optimization by the Trainer Layer.
- **Agent Rollout:** The agent’s interaction process is executed by its constituent modules using their `generate` or `rollout` interfaces during the training phase. The framework dynamically pads prompt tensors on the left and generated response tensors on the right to manage batch generation and aligns action masks with sequence lengths for accurate advantage computation in the reinforcement learning pipeline.
- **Agent Inference:** MemFactory supports pure inference, allowing researchers to instantiate an agent with the same modular composition. In this mode, each module uses its `inference` interface, which supports OpenAI-style APIs and high-throughput inference engines like vLLM, bypassing the Trainer Layer. This capability enables comparison of different memory workflows and module combinations without computationally intensive RL optimization.

#### 3.3. Environment Layer: Data Processing and Reward Computation

This layer serves as the interface between the agent and the task. It processes raw datasets into standardized contextual states and computes reward signals for policy optimization.

- **Environment Design:** Inspired by the "long-term vs. short-term memory" taxonomy, two primary environment types are implemented: `MemoryBankEnv` for managing explicit, updatable long-term memory banks, and `LongcontextEnv` for processing prolonged dialogue histories in short-term, context-based memory scenarios.
- **Data Loading and Reward Management:** The layer converts diverse raw data into unified dictionary states. It provides multi-dimensional reward signals, including "Format Rewards" and "LLM-as-a-Judge" evaluations, which are crucial for policy optimization.

#### 3.4. Trainer Layer: Policy Optimization

This layer is the core optimization engine, responsible for fine-tuning the agents’ memory management policies.

- **Group Relative Policy Optimization (GRPO):** The trainer implements the GRPO algorithm, which addresses the computational overhead of traditional RL algorithms like PPO by eliminating the need for an auxiliary value network (critic). GRPO estimates the baseline by sampling a group of candidate responses for a given input and performing intra-group reward normalization. The advantage for the *i*-th candidate with reward *r_i* is calculated as:
 `ˆA_i = (r_i - mean({r_1..., r_G})) / std({r_1..., r_G})`
 This approach aims to reduce memory requirements while maintaining sample efficiency, especially for optimizing rule-based or outcome-driven rewards common in memory evaluation tasks.
- **Monitoring and Configuration:** The layer supports comprehensive hyperparameter configurations and integrates with SwanLab for real-time monitoring of training metrics, reward distributions, and generation trajectories.

### 4. Main Findings and Results

The empirical validation of MemFactory focused on the MemAgent architecture, utilizing its publicly available training and evaluation datasets. This study aimed to demonstrate the framework’s modularity and effectiveness in optimizing memory policies.

#### 4.1. Experimental Setup

- **Base Models:** Two open-source Large Language Models were used: Qwen3-1.7B and Qwen3-4B-Instruct.
- **Training Data:** Adapted from the original MemAgent training dataset, simplified by reducing the context length to approximately one-third (50 to 80 documents per sample) to enhance training efficiency while retaining the long-context nature of the tasks.
- **Evaluation Sets:** Three specific test sets from the MemAgent data were chosen: `eval_50` and `eval_100` (main-task datasets), and `eval_fwe_16384` (an out-of-distribution, OOD, dataset).
- **Training Protocol:** Each model was trained for 250 valid steps. Scores were averaged over 4 independent trials per question (avg@4) to account for generation variance.
- **Computational Resources:** The entire training and evaluation pipeline was executable on a single NVIDIA A800 80GB GPU, indicating the framework’s relative computational efficiency.

#### 4.2. Results and Analysis

The empirical study demonstrated that MemFactory consistently improved the average performance for both base models tested.

- **Qwen3-1.7B Model:**
 - The base checkpoint achieved an average score of 0.3118 across the evaluation sets.
 - After optimization with MemFactory RL, the average score increased to 0.3581.
 - This represents a relative increase of 14.8% in the average score.
 - Performance gains were primarily observed in the main-task settings (`eval_50` improved from 0.4727 to 0.5684, and `eval_100` from 0.4297 to 0.4863).
 - However, performance on the OOD benchmark (`eval_fwe_16384`) experienced a slight decrease (from 0.0332 to 0.0195).

- **Qwen3-4B-Instruct Model:**
 - The base checkpoint achieved an average score of 0.6146.
 - With MemFactory RL, the average score increased to 0.6595.
 - This indicates a 7.3% relative increase on average.
 - This larger model demonstrated more robust improvements, achieving consistent gains across all evaluation sets, including the OOD benchmark (`eval_fwe_16384` improved from 0.6270 to 0.6426). This suggests a more effective transfer of the learned recurrent memory policy to unseen settings with a larger model.

#### 4.3. Conclusions from Results

The findings support two main conclusions:
1. MemFactory successfully reproduced and optimized MemAgent-style recurrent memory policies using standard training datasets.
2. The framework delivered measurable performance improvements on challenging long-context tasks, even when employing a lightweight single-GPU setup and simplified training data. These observations confirm MemFactory's utility as an infrastructure for empirical Memory-RL research.

### 5. Significance and Potential Impact

MemFactory introduces a standardized and modular framework for the development, training, and evaluation of memory-augmented AI agents, addressing a notable gap in the existing research landscape.

The primary significance of this work lies in its potential to **lower the barrier to entry** for researchers and developers working on memory-augmented LLMs. By providing a unified, extensible, and user-friendly infrastructure, MemFactory simplifies the process of integrating, training, and evaluating complex memory pipelines. This reduction in engineering effort allows researchers to allocate more resources to algorithmic innovation and experimentation with diverse memory architectures.

The **highly modular and "Lego-like" design** enables researchers to construct custom memory agents by swapping plug-and-play components (extractors, updaters, retrievers). This flexibility is expected to facilitate rapid prototyping and comparison of different memory strategies, potentially accelerating the discovery of more effective memory management policies.

Furthermore, the **native integration of Group Relative Policy Optimization (GRPO)** is significant. By eliminating the need for an auxiliary value network, GRPO reduces the computational memory footprint associated with RL training. This efficiency gain makes sophisticated Memory-RL research more accessible to those with more modest computational resources, such as a single high-end GPU, broadening participation in this field.

The **out-of-the-box support for cutting-edge paradigms** like Memory-R1, MemAgent, and RMM standardizes existing research efforts. This standardization improves research reproducibility and provides readily available baselines for comparison, which can foster more rigorous scientific inquiry.

Empirical validation confirmed that MemFactory can effectively train and optimize memory agents, yielding performance improvements on challenging long-context tasks. These results support the framework's practical utility as a foundation for empirical Memory-RL research.

In summary, MemFactory's contribution as a unified, modular, and computationally efficient framework has the potential to streamline research, accelerate innovation, and democratize access to advanced memory-augmented agent development, serving as a foundation for future advancements in long-horizon AI agents.
