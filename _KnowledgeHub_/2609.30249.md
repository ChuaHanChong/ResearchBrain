# RAPID: Robot Agentic Programming from Demonstrations

> [!summary] Summary
> RAPID turns a single visual human demonstration into a reusable robot program using a coding agent. It segments the demo, reconstructs an interactive MuJoCo scene, infers per-phase success predicates, and writes primitives as trajectory-optimization programs composed by relational constraints, then verifies and revises them on generated scene variants. It averages 0.759 success on eight nonprehensile tasks, far above code-as-policy agents.

## Problem

- Existing robotic coding-agent systems assume ground-truth success signals, human-engineered primitives and resettable verification environments are supplied a priori, so the agentic loop cannot close autonomously.
- Programs that hardcode poses, waypoints or world-frame offsets succeed in the demonstrated scene but break when object pose, geometry or scene layout changes.
- Nonprehensile manipulation spans diverse contact-dependent interactions, so fixed primitive libraries or few-demonstration representations stay locked in hand-engineered pipelines needing explicit task specifications or per-task policy training.

## Method

- ==Object-centric relational program representation==: each primitive is a local trajectory-optimization program with semantic roles, relations, effect parameter, geometry resolver, success predicate and costs, solved by the ==cross-entropy method==.
- Strategies compose verified primitives through per-phase role maps and connecting constraints evaluated just in time, deriving each effect argument from scene geometry and the state left by the preceding phase.
- **Demonstration-bootstrapped loop**: segment the demo, infer subgoals and predicates, real-to-sim reconstruct via SAM 3, SAM 3D and FoundationPose into MuJoCo, then verify and revise across agent-filtered scene variants.

## Results

- On eight simulated nonprehensile tasks **RAPID** averages **0.759** success across 50 novel scenes per task, versus **0.146** for CaP-Agent0 and **0.013** for vanilla CaP.
- Removing scene-variant verification drops the average to **0.532** with larger variance, while adding those same variants to CaP-Agent0 instead hurt it, **0.146** down to **0.126**.
- On LIBERO-Pro **RAPID** leads five of six settings, scoring **1.00** and **0.95** on libero-object where OpenVLA and pi-0 score 0; real Franka success reaches **0.4-0.9** per task.

## Takeaways

> [!tip] Key Insights
> - The relational representation alone does not help: open-loop code generation with it stayed at 0.011, so closed-loop verification is what makes relational reasoning usable.
> - A demonstration can supply the missing scaffolding of an agentic loop, task specification, primitives and verification environment, not just a motion to imitate.
> - Generalization comes from deferring geometry to run time; tens of minutes of per-task program construction amortizes, since frozen programs bind to new scenes in seconds.

## Detailed Report

### 1. Overview

A robot may need to move an object before it can grasp it. In Task 3, it must move the object clear of obstacles, push it toward a fixture, flip it to expose a graspable edge, and then grasp it. Contact-rich manipulation calls for many geometry- and contact-dependent behaviors. That makes a fixed primitive library burdensome to engineer.

The authors' approach starts from a language instruction and one visual demonstration. Together, these give a coding agent a starting point for constructing three things: a task goal, reusable manipulation primitives, and a simulation in which to test and revise them. The system, RAPID, supplies what robot coding agents need to close their generate–execute–check–revise loop: goals, primitives, and an interactive verification environment.

### 2. From demonstration to program

In RAPID, a *primitive* is a behavior aimed at an object-level effect, such as pushing by a displacement or flipping by an angle. It is not a fixed trajectory or a black-box policy. RAPID describes these object-level effects instead of merely preserving demonstrated poses or waypoints. It composes them with relational constraints, so later actions can use the scene geometry and the state produced by earlier actions.

The loop runs in order:

- The agent segments the demonstration and infers phase goals and success predicates.
- It reconstructs an interactive simulation from the demonstration.
- It proposes a primitive with semantic object roles, relations, geometry resolution, and a trajectory cost. The cost encodes the desired terminal effect and may also guide progress through contact-rich motion. A gradient-free cross-entropy optimizer searches for a trajectory.
- It executes and revises the primitive across the demonstration scene and filtered, feasible variants.
- It then composes the verified primitives.

At runtime, a connecting constraint derives the next phase's effect argument from the preceding phase's resulting state and current scene relations. In a new scene, RAPID binds scene objects to semantic roles and optimizes motion. The learned strategy and primitives stay unchanged.

### 3. Does the structure generalize?

The main test is *nonprehensile manipulation*: moving or reorienting an object through contact, without first grasping it. The tested objects begin in positions where the parallel gripper cannot grasp them.

The evaluation covers eight tasks, each with 50 novel test scenes. These scenes vary object pose, appearance, size, shape, and material, and they include irrelevant objects. RAPID is scored with a private success criterion hidden from it. Success rate is the fraction of test scenes meeting the task's criterion.

Averaged equally over the eight tasks, RAPID reaches **75.9% ± 2.4%**. CaP-Agent0 reaches **14.6% ± 2.5%**. Both figures are the mean ± standard deviation across three trials.

The baseline had advantages. CaP-Agent0 received ground-truth success feedback during construction and could roll out and revise its program at test time. This comparison supports the full approach over that baseline. It is not a single-factor ablation proving that the representation alone caused the difference.

A second test removes synthesized scene variants from RAPID. The authors report a substantial performance drop on Tasks 3–8, but not on Tasks 1–2. Adding scene variants to CaP-Agent0 does not improve its aggregate result. These findings support the authors' account that relational representation and verification work together. They do not isolate the representation as the only cause, since full-system comparisons change more than one ingredient.

The approach has a practical cost. Constructing a task program takes tens of minutes, once per task, in these experiments. Binding scene roles takes a few seconds per novel scene.

### 4. Scope

RAPID turns one demonstration into a program that encodes what each phase should do to objects. The program recalculates the next phase from the scene and the state actually reached, rather than replaying the demonstration's motions.

The central benchmark is quasi-static rigid-body manipulation. Its novel-scene result comes from a finite set of feasible test scenes. It is not a guarantee for arbitrary objects, scenes, or robots.
