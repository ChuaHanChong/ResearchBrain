# FlowReasoner: Reinforcing Query-Level Meta-Agents

> [!summary] Summary
> FlowReasoner is a query-level meta-agent that designs a bespoke multi-agent system for each user query. It is first trained by distilling DeepSeek R1 reasoning, then refined with reinforcement learning using execution feedback and a multi-purpose reward covering performance, complexity and efficiency. It surpasses o1-mini by 10.52% accuracy across three code benchmarks.

## Problem

- Most LLM-based multi-agent systems are hand-designed, which raises human labor cost and limits scalability to new tasks and domains.
- Earlier automated designers search for one task-level system shared by every query, so easy and hard queries get the same workflow, wasting compute or underserving hard cases.
- Existing automated methods rely on prompting or search rather than trained reasoning, and lack explicit optimization against execution feedback, workflow complexity and efficiency.

## Method

- ==Reasoning distillation==: DeepSeek R1 generates reasoning traces plus workflow code for training queries, and the ==meta-agent== is ==supervised fine-tuned== on them to gain basic multi-agent system design ability.
- ==Reinforcement learning with external execution feedback==: the meta-agent writes ==code-based workflows== from a library of ==meta-workers==, runs them on generated test cases, and is updated with ==policy-gradient RL==.
- ==Multi-purpose reward==: combines a ==performance term== from execution results, a ==complexity term== penalizing overly elaborate workflows, and an ==efficiency term==, so each query gets a compact system that still works.

## Results

- On engineering and competition code benchmarks (BigCodeBench, HumanEval, MBPP), FlowReasoner surpasses o1-mini by **10.52%** accuracy averaged over the three benchmarks.
- It beats task-level automated design baselines and hand-designed multi-agent systems, showing per-query workflows outperform a single shared workflow for a whole task.
- Ablations show both stages matter: distillation supplies initial design ability, and RL with the multi-purpose reward adds further accuracy gains over the distilled-only model.

## Takeaways

> [!tip] Key Insights
> - Generating one system per query, rather than per task, lets workflow complexity match query difficulty, a design principle applicable beyond code generation.
> - Execution feedback provides a verifiable reward for training meta-agents, so RL can improve system design without human-labeled workflows.
> - Rewarding complexity and efficiency alongside accuracy keeps generated systems lean, guarding against over-engineered agent pipelines that inflate cost without raising accuracy.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

The paper positions itself within the rapidly evolving landscape of Large Language Models (LLMs) and LLM-based multi-agent systems. LLMs have demonstrated remarkable capabilities across various domains, leading to the development of complex applications. A key enabler for these applications is the concept of multi-agent systems, where multiple LLM-driven agents collaborate, often incorporating planning, reasoning, tool use, and memory.

However, the authors identify a critical limitation in the current state-of-the-art: **most effective multi-agent systems are manually designed.** This manual approach is resource-intensive, requires significant human expertise, and inherently limits scalability. To address this, previous research has explored automated methods, which can be broadly categorized:

- **Prompt/Hyperparameter Optimization:** Early methods focused on optimizing prompts or hyperparameters for agents within a *fixed* multi-agent system workflow. While automating parts of the agent design, the core workflow still required manual effort for each new scenario.
- **Graph-based Workflow Automation:** More advanced approaches formulated workflows as graphs or networks and attempted to automate their design. However, the inherent structural complexity of graphs often limited their scalability and generalizability.
- **Code-represented Workflow Optimization (Task-Level Meta-Agents):** State-of-the-art methods, such as ADAS, AFLOW, and MaAS, represent multi-agent systems as programming code. They introduce a "meta-agent" (typically a highly performant LLM like GPT-4o) to optimize these workflows. These meta-agents often rely on complex search algorithms (e.g., Monte Carlo Tree Search) over carefully designed search sets to find an optimal system.

The critical distinction drawn by the authors is that these existing automated methods, while effective, are **"task-level meta-agents."** This means they generate a *single, task-specific multi-agent system* (e.g., one system for all code generation tasks). This "one-size-fits-all" approach, while an improvement over fully manual design, still lacks dynamic adaptation. Such systems are rigid and cannot automatically customize or optimize their structure for *individual user queries* within a given task. For instance, a single system designed for general "code generation" might not be optimal for a specific query like "build a 2048 game" versus "design a calendar tool."

**FlowReasoner addresses this specific gap** by proposing a **"query-level meta-agent."** Its core contribution lies in moving from "one system per task" to "one system per user query." This paradigm shift aims to enhance the adaptability and efficiency of multi-agent systems in real-world scenarios, where user queries are diverse and often demand unique problem-solving approaches. By doing so, FlowReasoner seeks to overcome the rigidity and resource allocation inefficiencies of prior task-level approaches, offering a more personalized and dynamically optimized solution for each user interaction. The work also taps into the advancements in LLM reasoning (Chain-of-Thought, self-correction), leveraging these capabilities to enable the meta-agent to deliberatively design workflows.

### 2. Key Objectives and Motivation

The central objective of this research is to develop **FLOWREASONER**, a query-level meta-agent designed to **automate the dynamic generation of personalized multi-agent systems for individual user queries.** This represents a significant shift from previous approaches that typically generate a single, static system for an entire class of tasks.

The motivation behind this objective stems from several limitations observed in the current landscape of multi-agent system design:

- **High Human Resource Costs and Limited Scalability:** Manually designing multi-agent systems, including their constituent agents and workflows, is an intensive and costly endeavor. This human effort significantly restricts the scalability of deploying such systems across numerous diverse applications or evolving scenarios.
- **Rigidity of Task-Level Automation:** While automated methods have emerged to optimize multi-agent system design (e.g., by treating them as code and using meta-agents with search algorithms), these are predominantly "task-level" solutions. They produce a "one-size-fits-all" system for a broad category of tasks (e.g., code generation). This rigidity means the system cannot adapt its internal structure, agent roles, or workflow flow to the nuances of specific user queries.
- **Lack of Query-Specific Adaptation:** Individual user queries, even within the same overarching task, often require different reasoning paths, agent configurations, or tool invocations. A fixed workflow cannot optimally allocate inference resources or tailor its problem-solving strategy to the unique demands of each query, leading to suboptimal performance or inefficiency.
- **Reliance on Complex Search Algorithms and Designed Search Sets:** Existing automated methods often depend on computationally expensive search algorithms (e.g., Monte Carlo Tree Search) and meticulously crafted search sets (pre-defined spaces of possible workflow components). Such dependencies can be time-consuming and may not be readily available or adaptable in dynamic, real-world query-specific contexts.

In light of these motivations, FLOWREASONER aims to:
1. **Eliminate the "one-size-fits-all" limitation** by generating a novel, query-specific multi-agent system for *each* user query.
2. **Reduce human effort** in designing and adapting multi-agent systems.
3. **Enhance adaptability and efficiency** by allowing the meta-agent to leverage deliberative reasoning and external execution feedback to dynamically construct optimal workflows.
4. **Circumvent the need for complex search algorithms and pre-designed search sets** by integrating external execution feedback directly into a reinforcement learning framework, guiding the meta-agent's reasoning process.

By achieving these objectives, FlowReasoner seeks to make multi-agent systems more autonomous, flexible, and performant in addressing the diverse and dynamic nature of real-world user requests.

### 3. Methodology and Approach

FLOWREASONER's methodology is centered on training a reasoning-based query-level meta-agent that can dynamically generate multi-agent system workflows by learning from external execution feedback. The approach bypasses the reliance on complex search algorithms and pre-designed search sets, which are common in prior task-level meta-agent systems. The training pipeline consists of three main stages: Reasoning Data Distillation, Reasoning SFT Warmup, and Reinforce Reasoning from External Execution Feedback.

#### 3.1. Learn to Reason (Stages 1 & 2)

1. **Reasoning Data Syntheses:** The process begins by creating a high-quality "warm-up SFT dataset." This is achieved by leveraging a powerful, general-purpose LLM, DeepSeek R1-671B, as the initial meta-agent. For a given input query, DeepSeek R1-671B is prompted to generate multiple rounds of reasoning (`R_query`) and a corresponding multi-agent system (`S_query`). Crucially, at each round, the process incorporates "external execution feedback," simulating a real-world iterative refinement. These multi-round reasoning processes and the final multi-agent system are then paired with the original instruction and query to form synthetic training samples. This distillation process aims to imbue the smaller target model with an initial understanding of how to reason about and generate multi-agent workflows based on feedback.

2. **Reasoning SFT Warmup:** The synthetic dataset generated in the previous step is then used to supervised fine-tune (SFT) a smaller, more manageable base model, DeepSeek-R1-Distill-Qwen-7B (and a 14B variant). During SFT, the model learns to take an instruction and a user query as input and generate a reasoning process and a multi-agent system (`S_query`). This stage unlocks the model's basic ability to reason about and generate workflows, essentially providing a foundational understanding of the problem space and desired output format.

#### 3.2. Reinforce Reasoning from External Execution Feedback (Stage 3)

Following the SFT warm-up, the model's reasoning capabilities are further enhanced through a reinforcement learning (RL) phase, where it directly interacts with an environment that provides execution feedback.

- **Reinforcement Learning Method:** The chosen RL algorithm is GRPO (Grouped Relative Policy Optimization), which is adopted from DeepSeek-R1-Zero. GRPO works by sampling multiple outputs (trajectories) for each query and computing relative advantages based on the rewards received. The policy is then updated to maximize an objective function that incorporates these advantages, while a KL regularization term is used to prevent drastic policy changes and ensure training stability.
- **Multi-Purpose Reward Design:** A crucial component of the RL phase is the carefully designed reward function, which guides the meta-agent's learning. Since external feedback is available for each reasoning round, "process reward supervision" is used. The reward for each reasoning round (`r_j`) is normalized and contributes to the advantage function. The reward function considers three key aspects:
 - **Performance:** Measured by the *pass rate* of the proposed solution (code) for the given query, assessed through external execution in a sandbox environment. This directly evaluates the efficacy of the generated multi-agent system.
 - **Complexity:** Evaluated based on the *complexity score of the abstract syntax tree* of the generated workflow. This likely incentivizes workflows that are efficient or well-structured, avoiding unnecessary complexity.
 - **Efficiency/Diversity:** Assessed using a *distinctness ratio* (following Chen et al.), which aims to alleviate the "overthinking" problem common in o1-like LLMs. This encourages the meta-agent to explore diverse and potentially more direct reasoning paths, contributing to overall efficiency.
- **External Execution Feedback Loop:** During RL, the meta-agent generates a multi-agent system for a query. This system is then executed in an external sandbox, and its performance (e.g., code pass rate) is evaluated against ground truth. This feedback is converted into the reward signal, which is then used to update the meta-agent's policy, enabling it to learn which reasoning steps and workflow designs lead to better outcomes.

#### 3.3. Generating Multi-Agent Systems with FLOWREASONER

At inference time, when a user submits a query, FLOWREASONER acts as `A_meta_query(q)`. It employs deliberative reasoning to propose a novel, query-level multi-agent system (`S_query`). This system is constructed by iteratively optimizing a workflow over `l` rounds (fixed at 10 iterations in experiments). The workflow is represented as code, allowing for flexible composition using predefined operators such as:
- `Code Generator`: For producing code solutions.
- `Format Generator`: For structuring answers.
- `Ensemble Operator`: For combining multiple solutions.
- `Review Operator`: For evaluating solutions.
- `Revise Operator`: For refining solutions based on feedback.
- `Code Test Operator`: For validating code against test cases.

By continuously refining the multi-agent system through iterative external execution feedback, FLOWREASONER is designed to construct a highly adaptive and effective system tailored to maximize accuracy and performance for each specific query.

### 4. Main Findings and Results

The experimental evaluation of FLOWREASONER focuses on its ability to generate effective workflows for code generation tasks, leveraging test cases as external execution feedback. The paper uses three representative code benchmarks: BigCodeBench (engineering-oriented), HumanEval, and MBPP (algorithmically focused).

#### 4.1. Performance Comparison

- FLOWREASONER-14B consistently outperforms all baselines across all three benchmarks. These baselines include single-model direct invocation (e.g., o1-mini, GPT-4o-mini), manually designed workflows (e.g., Self-Refine, LLM-Debate, LLM-Blender using 4o-mini or o1-mini as workers), and automated task-level workflow optimization methods (e.g., AutoAgents, ADAS, Aflow, MaAS).
- Quantitatively, FLOWREASONER-14B achieves an impressive 81.89% overall accuracy, surpassing the strongest baseline, MaAS, by 5 percentage points.
- Notably, it significantly improves upon its underlying worker model, o1-mini, by an overall margin of 10.52% accuracy across the three benchmarks, demonstrating the substantial value added by the FLOWREASONER meta-agent.

#### 4.2. Ablation on Model Size and Training Stages

- **Model Size:** The 14B variant of FLOWREASONER consistently outperforms its 7B counterpart (81.89% vs. 80.53% overall accuracy for SFT+RL). This indicates a clear positive correlation between the meta-agent's model scale and its reasoning effectiveness in generating workflows.
- **Training Stages:** Models trained with both Supervised Fine-Tuning (SFT) and Reinforcement Learning (SFT+RL) exhibit notable improvements over those trained with SFT alone (e.g., 81.89% for 14B SFT+RL vs. 81.50% for 14B SFT; 80.53% for 7B SFT+RL vs. 78.89% for 7B SFT). This confirms the complementary benefits of incorporating RL with external execution feedback, further enhancing the meta-agent's ability to reason and generate effective workflows.

#### 4.3. Ablation of Meta-agents and Workers

- **Meta-agent Performance:** Open-source models (Qwen2.5-Coder) when used as meta-agents without an initial workflow (i.e., relying purely on instruction prompts) exhibited poor performance and frequently generated error-prone workflows. In contrast, API-based models (e.g., GPT-4o-mini, Claude 3.5, o1-mini) showed stronger performance, likely due to superior instruction-following capabilities.
- **Worker Effectiveness:** When using a high-performing meta-agent (Claude 3.5), o1-mini emerged as the best worker model, achieving the highest accuracy. This suggests that while the meta-agent is crucial for workflow generation, the choice of a capable worker model significantly impacts the final solution quality.

#### 4.4. Generalization Capability

- FLOWREASONER, specifically the 7B and 14B variants trained with o1-mini as the worker, demonstrates a notable degree of transferability. When paired with alternative worker models (Qwen2.5-Coder-32b, Claude 3.5, GPT-4o-mini), it largely maintains consistent performance on the same tasks.
- This suggests that FLOWREASONER's learned planning capabilities (i.e., its ability to generate effective workflows) are not tightly bound to the specific worker model used during training. The meta-agent can adapt its strategies effectively across diverse execution agents.

#### 4.5. Case Study

- Qualitative analysis through case studies (Figure 5) illustrates FLOWREASONER's ability to adapt workflow structure based on task complexity. For instance, a BigCodeBench task (engineering-oriented, complex requirements) resulted in a more intricate workflow with multiple retry loops and error analysis steps. In contrast, a HumanEval task (algorithmic, simpler) generated a more concise workflow. This showcases the "one system per user query" adaptability.

In summary, the experiments robustly demonstrate FLOWREASONER's superior performance, the effectiveness of its RL-driven training with external feedback, its scalability with model size, and its impressive generalization capabilities across different worker models, all while dynamically adapting workflow complexity to specific query demands.

### 5. Significance and Potential Impact

FLOWREASONER represents a significant advancement in the field of automated multi-agent system design, offering several key areas of significance and potential impact:

- **Paradigm Shift to Query-Level Automation:** This paper introduces and successfully demonstrates the first "query-level meta-agent." This is a fundamental shift from the prevalent "task-level" automation, moving from "one system per task" to "one system per user query." This allows for unprecedented adaptability and personalization of multi-agent systems, tailoring their structure and resource allocation precisely to the specific needs of each user interaction.

- **Enhanced Adaptability in Real-World Scenarios:** The dynamic, query-specific workflow generation addresses a critical limitation of previous rigid, one-size-fits-all systems. In real-world applications where user queries are highly diverse and unpredictable, FLOWREASONER's ability to automatically design optimal problem-solving strategies on-the-fly will lead to more robust, efficient, and higher-performing AI systems.

- **Reduction in Human Resource Costs:** By automating the intricate design of multi-agent workflows for individual queries, FLOWREASONER substantially reduces the need for human experts to manually craft or adapt these systems. This translates directly into lower development and maintenance costs, making complex AI deployments more economically viable and scalable.

- **Novel Training Methodology:** The proposed approach of incentivizing a reasoning-based meta-agent via external execution feedback, specifically through reinforcement learning guided by a multi-purpose reward, is novel and highly effective. This method circumvents the limitations of relying on complex search algorithms or pre-designed search sets, which are often computationally expensive and difficult to scale. The multi-purpose reward, balancing performance, complexity, and efficiency, is also a key innovation for guiding the meta-agent's learning towards practical and robust solutions.

- **Significant Performance Improvement:** The empirical results demonstrate a clear superiority over existing state-of-the-art methods, including strong task-level automated approaches and manually designed workflows. The 10.52% accuracy improvement over a strong baseline like o1-mini is a substantial gain, highlighting the practical efficacy of the FlowReasoner framework in complex tasks like code generation.

- **Robustness and Generalization:** The ability of FLOWREASONER to generalize its planning capabilities across different underlying worker models (e.g., Qwen2.5-Coder, Claude, GPT-4o-mini) is a critical indicator of its robustness. This suggests that the learned meta-agent policy is not overfit to a specific worker's characteristics, making FLOWREASONER a more versatile and transferable solution for various LLM ecosystems.

- **Catalyst for Future Research:** By open-sourcing the code, the authors foster further research and development in query-level meta-agents, dynamic workflow optimization, and reinforcement learning for LLM-based system design. This contributes to the broader academic and industrial understanding of building more intelligent and autonomous AI agents.

In essence, FLOWREASONER paves the way for a new generation of adaptive and efficient multi-agent systems. Its significance lies in making sophisticated AI capabilities more accessible, scalable, and responsive to the granular demands of individual users, ultimately driving advancements in AI automation and its real-world applications.
