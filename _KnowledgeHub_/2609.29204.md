# AdaHVLA: Adaptive Harnesses for Long-Horizon Vision-Language-Action Execution

> [!summary] Summary
> AdaHVLA is an adaptive task harness that sits between an LLM/VLM reasoning agent and a frozen VLA policy, editing the code-based coordination rules (context retention, goal advancement, recovery, completion) using robot rollout evidence. A multiagent loop with testable hypotheses and a revision graph drives the edits, raising quadruped navigation test success from 22.5% to 57.5% and manipulation success by up to 30.8 points.

## Problem

- VLA models give strong local action grounding but lack persistent memory and progress tracking, so locally correct actions fail to complete long-horizon multi-stage tasks.
- Planner-based agents revise plans under fixed coordination rules; skill selection alone does not settle what history to retain, when to advance stages, or how long to correct.
- Prior program-repair and agent-search methods validate code correctness or re-execution success, which does not show whether a revision caused its intended closed-loop behavioral effect.

## Method

- ==Harness VLA policy==: an editable code coordination layer that sets VLA instruction and observation context, controls visual buffer refresh, commits goal progress, and gates recovery and completion, leaving VLA weights frozen.
- ==Decoupled multiagent adaptation==: separate evidence-analysis, revision, and assessment contexts exchange structured records; each patch carries a testable coordination hypothesis, and an attribution gate credits only rollouts where the modified mechanism triggered before divergence.
- ==Revision graph== plus adaptation memory: branches store candidate harnesses, hypotheses, rollout evidence and observed effects, prioritizing candidates by task success then behavioral effect, and persisting across tasks and environments.

## Results

- On NaVILA-LH the initial harness lifts mean test success from **2.5%** to **22.5%**; AdaHVLA reaches **31.7-57.5%** across six adaptation models, adding **9.2-35.0** points.
- Manipulation improves for all three backbones on both levels; with pi-0.5, L1 test success climbs **25.0%** to **55.8%** (**+30.8**) and L2 from **10.0%** to **38.3%**.
- Ablations: flat history instead of the revision graph drops navigation from **57.5%** to **42.5%**; success-only candidate selection drops it to **38.3%**; removing completion checks to **29.2%**.

## Takeaways

> [!tip] Key Insights
> - Adapting the coordination code around a frozen VLA yields large long-horizon gains without touching its weights; memory, staging and recovery rules drive them, not the action model.
> - Credit a revision by whether the changed mechanism fired and produced its predicted effect; task success alone misattributes gains and overlooks promising candidates.
> - Keep failed branches: a revision that only exposes a later failure still guides refinement, so structured revision history beats following the latest change.

## Detailed Report

### 1. Overview

A quadruped following a multi-stage navigation instruction can finish one movement without reaching the next intended place. Long-horizon robots can take locally sensible actions and still lose the task. They must remember what has happened, know which stage remains, and recover without advancing prematurely. AdaHVLA adds editable coordination code between a task-level reasoner and the VLA. This code can retain task progress and adjust the instructions and context passed to the local executor. In the authors' real-world example, the robot deviates while approaching Goal 2, receives corrective guidance, reaches that goal, and continues. This is a qualitative illustration, not a measured success rate.

An author-described real-world quadruped navigation demo, presented as a video excerpt. The robot view and task-progress display are shown alongside comparisons with Single VLA and harness revisions. This is qualitative evidence, not a benchmark or a rate estimate.

### 2. Make coordination editable

During execution, the harness uses observation and task history to do three things: choose a local instruction and context for the VLA, update progress, and manage recovery or completion. The VLA supplies local action behavior. The source stays fixed within a rollout. Adaptation happens between rollouts, so the code that coordinates these decisions is revised, not the VLA parameters.

Revision starts from rollout evidence. Camera observations, logs, and trajectory segments are aligned to interaction request IDs and the harness revision. An analysis agent records observations separately from explanations. It then writes a testable coordination hypothesis that states the suspected mechanism, evidence, predicted behavioral effect, and observable indicator. A revision agent proposes a code patch, and a separate review checks it before execution. A separate assessment then compares parent and revised rollouts on the same task instance in a fresh context. It considers the targeted effect, overall behavior, and task success separately. An attribution check updates hypothesis support only when the modified mechanism was triggered and the trajectories had not already diverged before it. One successful episode is not proof of repeatability.

AdaHVLA maintains a revision graph linking code versions, hypotheses, rollout evidence, and assessments, which preserves alternatives for further work. The design aims to make successive revisions cumulative and testable. The experiments test parts of that claim.

The diagnosis and patch are the paper's illustrative example.

### 3. Does the evidence support it?

The main test uses simulated NaVILA-LH navigation, which has 50 instances: 10 for adaptation and 40 held out for testing. The metric is test success rate (SR), the proportion of evaluations meeting the benchmark's completion criterion. Initial Harness VLA adds online reasoning and state updates but receives no code revision; AdaHVLA adapts the harness. The best reported adapted configuration, GPT-5.6-sol Max, reaches a mean held-out test SR of **57.5%**, compared with **22.5%** for Initial Harness VLA. Rates average three restarts on the same task split. The final harness is selected using adaptation evidence alone, and the runtime reasoning agent and NaVILA executor remain unchanged. Across the six adaptation configurations, test SR ranges from 31.7% to 57.5%, so the improvement is not uniform across adaptation models.

Two adaptation ablations share the same candidate budget. SR Select picks candidates using task success alone rather than trajectories and behavioral assessments, and it reaches **38.3%** navigation SR versus **57.5%** for Full. This is evidence that behavioral evidence helps candidate selection in this setup. The ablation has limits: the revision agent still sees trajectories, and failed candidates remain eligible. Replacing the revision graph with flat history yields **42.5%**, even though versions and rollback remain available. This supports the value of organizing related revisions and behavioral evidence in this setup, but it does not prove the graph alone explains all gains.

### 4. A policy that can learn

AdaHVLA makes coordination rules revisable from robot experience while the local executor stays fixed. Results vary across adaptation models and tasks. The real-world deployment is an illustrative trajectory, not a multi-trial evaluation. Errors in visual or spatial reasoning shared by the base model can still affect both revision and assessment.
