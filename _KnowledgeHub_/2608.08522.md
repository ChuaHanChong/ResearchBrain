# EsaacSim: A Multimodal Event Camera Add-on for NVIDIA Isaac Sim

> [!summary] Summary
> EsaacSim is an event-camera add-on for NVIDIA Isaac Sim that converts RTX render products into asynchronous grayscale or Bayer RGGB event streams online, with a configurable sensor model and motion-guided frame-gap synthesis for higher temporal resolution. It publishes synchronized RGB, APS, event, depth, and IMU data over ROS 2, generating events in 6.98-29.16 ms per frame interval under 400 MB GPU memory.

## Problem

- Event-based robotics is constrained by scarce sensor hardware and large-scale event datasets, forcing reliance on simulators for algorithm development and synthetic data.
- Most existing event simulators are standalone offline dataset pipelines lacking online generation, and few integrate with modern robotics platforms or ROS 2 workflows.
- Prior Isaac Sim event plugins emit events or RGB plus events only, omitting synchronized APS, depth, IMU, color events, and multi-resolution sensor configurations needed for multimodal perception.

## Method

- Layered add-on architecture separating native Isaac Sim rendering, an extension layer for camera discovery and ROS 2 I/O, and an event generation backend, keeping the RTX pipeline untouched.
- ==Frame-based log-intensity event model== comparing per-pixel logarithmic intensity against a reference state with ON/OFF contrast thresholds, applied independently per channel for virtual ==Bayer RGGB== mosaics.
- ==Motion-guided frame-gap synthesis== backward-warps rendered frames using Isaac Sim dense motion vectors to synthesize N-1 intermediate samples, plus a configurable sensor model with mismatch, refractory, latency, shot and leak noise.

## Results

- Across **five** sensor resolutions (DVS128 to GenX320), per-frame-interval event generation took **6.98-27.28 ms** in grayscale and **7.58-29.16 ms** in Bayer RGGB mode.
- GPU memory scaled roughly linearly from **51.4 MB** (DVS128, x8) to **399.7 MB** (GenX320, x32), with Bayer mode adding at most **1.5 MB** over grayscale.
- Interpolation factors x**8**, x**16**, x**32** gave effective sampling rates of **240**, **480**, **960 Hz** on a consumer RTX 4060; raising contrast threshold from **0.00** to **0.30** sharply cut event counts while preserving contours.

## Takeaways

> [!tip] Key Insights
> - Decoupling event generation from the renderer lets one rendered image stream be reused under many sensor configurations, making sensor-model sweeps cheap and pipeline-compatible.
> - Motion-vector-guided interpolation buys temporal resolution without raising render frequency, a general trick for simulating high-rate sensors atop fixed-cadence graphics pipelines.
> - Efficiency and qualitative consistency do not establish fidelity: a frame-based backend lacking circuit-level physics and real-sensor validation may misrepresent downstream perception performance.

## Detailed Report

### 1. How this Work Fits into the Broader Research Landscape

Event-based vision represents an alternative sensing paradigm to traditional frame-based cameras, characterized by low latency, high dynamic range, and high temporal resolution. These characteristics render event cameras suitable for robotics applications operating in dynamic environments, such as autonomous navigation, aerial robotics, and robotic manipulation, where they can offer advantages under challenging motion and illumination conditions.

Despite these potential benefits, the widespread adoption of event-based robotic systems is constrained by the limited availability of physical event sensors and the scarcity of large-scale event datasets. This limitation has driven the development of event camera simulators, which serve as tools for synthetic data generation and algorithm development. Early simulation efforts included frame-based emulators like jAER, pyDVS, and PIX2NVS, and more recent approaches such as V2E and a real-time simulator by Ziegler et al., which convert conventional image sequences into event streams. Physics-based simulators, including ESIM, PECS, EventTracer, and NeRF-based simulators, aim to model the event generation process with greater accuracy by incorporating sensor characteristics and scene interactions.

Concurrently, the robotics community has increasingly relied on simulation platforms for development, with NVIDIA Isaac Sim emerging as a prominent environment due to its photorealistic rendering, GPU-accelerated physics, and integration capabilities. While some robotics-oriented simulators, such as the DVS Gazebo Plugin and AirSim, have integrated event camera support, comprehensive solutions within modern platforms like Isaac Sim have been less common. EVIS, a recent physics-grounded event camera plugin for Isaac Sim, marked an advancement in this area by focusing on synchronized RGB and event generation.

EsaacSim positions itself within this landscape by extending the capabilities of event camera simulation within NVIDIA Isaac Sim. It aims to provide a more comprehensive, multimodal, and robotics-centric solution compared to prior work. Specifically, it expands beyond RGB and event generation to include synchronized Active Pixel Sensor (APS) frames, depth images, and IMU data, alongside support for various event camera resolutions and native Bayer RGGB event generation. By providing a configurable sensor model and native ROS 2 integration, EsaacSim addresses the need for a versatile simulation tool that facilitates the development of multimodal robotic perception pipelines, thereby helping to mitigate the challenges associated with limited real-world event camera data and sensor availability.

### 2. Key Objectives and Motivation

The primary objectives and motivations behind the development of EsaacSim are multifaceted, addressing current limitations in event-based vision research and its application in robotics:

1. **Bridging the Gap in Sensor Availability and Data Generation:** Event-based cameras possess properties such as low latency, high dynamic range, and high temporal resolution, which are advantageous for robotic perception in dynamic and challenging environments. However, the limited availability of these specialized sensors and the lack of large-scale, diverse datasets impede the development and testing of event-based algorithms. EsaacSim aims to mitigate this by providing a means to generate synthetic event data, reducing reliance on physical sensors and allowing for data generation under controlled and diverse conditions.

2. **Enabling Online Simulation within Modern Robotics Platforms:** Robotics research workflows increasingly rely on integrated simulation platforms that offer photorealistic rendering and physics simulation. NVIDIA Isaac Sim is identified as a platform that meets these requirements. Previous event camera simulators often operate as standalone tools or are integrated into less comprehensive platforms. A key motivation for EsaacSim is to integrate online event generation directly into Isaac Sim, allowing researchers to leverage its existing features for scene creation, physics, and robot control while simultaneously simulating event cameras. This integration supports real-time algorithm development and testing.

3. **Providing Multimodal Sensor Output:** Many robotic perception systems utilize multiple sensor modalities (e.g., RGB cameras, depth sensors, IMUs) in addition to event cameras. Existing event camera simulators often focus solely on event stream generation or, at most, synchronized RGB and events. EsaacSim aims to provide a comprehensive multimodal output, including synchronized RGB images, Active Pixel Sensor (APS) frames, event streams (both grayscale and Bayer RGGB), depth images, and IMU data. This facilitates the development and evaluation of advanced multimodal perception algorithms, such as event-based visual-inertial odometry or RGB-event fusion techniques.

4. **Supporting Configurable Sensor Models and Diverse Event Camera Resolutions:** Real-world event cameras come in various resolutions and exhibit different characteristics (e.g., contrast thresholds, noise profiles, refractory periods). EsaacSim seeks to offer a configurable sensor modeling framework that allows users to emulate a range of existing event camera profiles. This flexibility enables researchers to simulate sensors relevant to their specific applications and investigate the impact of different sensor parameters on algorithm performance. Support for multiple event camera resolutions ensures broad applicability.

5. **Facilitating Robotics-Oriented Integration:** Seamless integration with robotics middleware, particularly ROS 2, is crucial for developing and deploying robotic systems. EsaacSim is motivated to provide native ROS 2 interfaces for all its generated data streams, ensuring compatibility with standard robotics software stacks for visualization, recording, and real-time processing.

In summary, the key objectives are to overcome the data and sensor availability limitations of event cameras by providing an integrated, multimodal, configurable, and robotics-friendly online event camera simulation add-on for NVIDIA Isaac Sim.

### 3. Methodology and Approach

EsaacSim is implemented as an add-on for NVIDIA Isaac Sim, designed to generate online event streams from rendered image sequences. Its methodology integrates into Isaac Sim's existing rendering pipeline and extends it with specialized event generation and multimodal output capabilities.

#### 3.1. System Overview and Architecture

The system is structured into three logical layers:
- **Native Isaac Sim Layer:** This foundational layer handles scene representation, physics simulation (using PhysX), and photorealistic RTX rendering to produce camera images (HDR RGB and depth).
- **EsaacSim Extension Layer:** Built atop the Isaac Sim infrastructure, this layer manages the lifecycle of configured camera primitives, acquires rendered image buffers via GPU-oriented ingestion paths, and facilitates runtime configuration. It also provides visualization and ROS 2 communication interfaces.
- **Event Generation Backend:** This core component converts grayscale or Bayer image streams into asynchronous events. It utilizes a frame-based log-intensity model, incorporates a configurable sensor model, and then forwards event batches to output interfaces.

This layered design ensures decoupling between rendering, event generation, and data dissemination, allowing independent evolution of components while maintaining compatibility with Isaac Sim. Unlike some prior approaches, EsaacSim functions as a multimodal sensing layer built on Isaac Sim's native sensor pipeline, enabling synchronized RGB, APS, event, depth, and IMU outputs.

For runtime deployment, the EsaacSim extension operates within the Docker-based Isaac Sim environment. It receives rendered images and generates event streams, which are then published via ROS 2 to external applications running in a host environment (managed with pixi). This separation allows for integration with visualization tools and robotics software without interfering with the simulation environment.

#### 3.2. Event Generation

The event generation process in EsaacSim involves two main steps:
1. **Log-Intensity Event Model:** This model is based on the principle that event cameras generate events when the change in logarithmic image intensity exceeds a predefined threshold.
 - An HDR image \( I_k \) from the renderer is first converted into a scalar intensity representation \( S_k \). This can be done using grayscale conversion, weighted luminance, or a Bayer Red-Green-Green-Blue (RGGB) sampling pattern, depending on the configured intensity mode.
 - The logarithmic intensity \( L_k(x, y) = \log(S_k(x, y) + 1) \) is computed for each pixel.
 - An event is generated at pixel \( (x, y) \) if the accumulated contrast, \( \Delta L_k(x, y) = L_k(x, y) - L_{\text{ref}}(x, y) \), exceeds a positive contrast threshold \( C_{\text{ON}} \) or falls below a negative contrast threshold \( -C_{\text{OFF}} \).
 - Upon event generation, the pixel's reference intensity \( L_{\text{ref}} \) is updated.
 - For Bayer RGGB event generation, the scalar intensity \( S_k \) is derived from the virtual RGGB mosaic, applying the same log-intensity model independently to each color channel (R, G1, G2, B) at its respective pixel location.

2. **Motion-Guided Frame-Gap Synthesis:** To increase the effective temporal resolution beyond Isaac Sim's rendering frequency, EsaacSim synthesizes intermediate intensity images.
 - Given two consecutive rendered images \( I_{k-1} \) and \( I_k \), Isaac Sim provides a dense motion vector field \( v(x, y) \) describing pixel displacement between frames.
 - Intermediate samples are synthesized by backward warping the current rendered image \( I_k \) using a temporally scaled motion field. For an interpolation factor \( \alpha = n/N \), where \( n = 1, \dots, N-1 \) are subdivisions, the synthesized image \( I_{k,n}(x, y) = I_k(x - \alpha u(x, y), y - \alpha v(x, y)) \) is created using bilinear interpolation.
 - Each synthesized image, along with the rendered images, is then processed by the log-intensity event generation model at uniformly spaced timestamps \( t_{k,n} \).
 - If motion vectors are unavailable, the system defaults to linear image interpolation.

#### 3.3. Sensor Model Configuration

EsaacSim features a configurable sensor model, allowing users to define characteristics for each simulated camera instance at runtime. This enables the emulation of various event camera profiles within the same scene. Configurable parameters include:
- **Spatial resolution:** Supporting resolutions like 128x128 (DVS128), 240x180 (DAVIS240), 304x240 (ATIS), 346x260 (DAVIS346), and 320x320 (GenX320).
- **Contrast thresholds:** \( C_{\text{ON}} \) and \( C_{\text{OFF}} \).
- **Threshold mismatch:** Pixel-wise variability in thresholds.
- **Refractory period:** Minimum time between events at the same pixel.
- **Latency:** Event output delay.
- **Timestamp quantization:** Resolution for event timestamps.
- **Noise characteristics:** Shot noise (random spurious events) and leak noise (background activity).
- **Intensity mode:** Grayscale, luminance, or Bayer RGGB intensity generation.
These parameters exclusively affect the event generation backend and are independent of the rendering pipeline.

#### 3.4. Output Interfaces

To facilitate integration with robotics applications, EsaacSim provides native ROS 2 message interfaces for event streams. Events can be published individually (\texttt{Event.msg}), grouped into conventional packets (\texttt{EventPacket.msg}), or encoded using a packed Structure-of-Arrays layout (\texttt{PackedEventPacket.msg}) for high-rate communication.

Beyond event streams, EsaacSim publishes synchronized auxiliary data directly from Isaac Sim, including APS intensity images (grayscale or Bayer RGGB), depth images, and IMU measurements. All data streams are consistently timestamped, supporting the development of multimodal perception pipelines.

### 4. Main Findings and Results

The evaluation of EsaacSim involved qualitative comparisons of generated data and performance benchmarking across various sensor resolutions and temporal interpolation factors.

#### 4.1. Qualitative Evaluation

- **Multimodal Data Generation:** EsaacSim consistently generated synchronized multimodal outputs. For various YCB objects with diverse geometries and textures, the simulator produced synchronized RGB images, APS grayscale images, grayscale event visualizations, Bayer RGGB event visualizations, and depth images from the same virtual sensor configuration.
- **Content Consistency:** The results indicated that the framework preserved object appearance and geometric structure across different sensing modalities. Grayscale and Bayer event visualizations captured object contours and intensity transitions resulting from camera motion. Depth images provided accurate representations of the three-dimensional scene geometry. These findings suggest the framework's capability for simulating heterogeneous event-camera data in robotic environments.

#### 4.2. Sensor Model Evaluation

- **Contrast Threshold Influence:** The configurable sensor model's effect was demonstrated by varying the contrast threshold while keeping other parameters constant. Increasing the contrast threshold led to a substantial reduction in the number of generated events, as expected from the event generation model, requiring larger logarithmic intensity variations to trigger an event.
- **Preservation of Structure:** Despite reduced event density at higher thresholds, the dominant object contours and motion-induced structures remained visible in the event visualizations. This indicates that the framework allows for runtime-configurable event camera behavior while maintaining the qualitative characteristics of the event stream.

#### 4.3. Performance Evaluation

The computational efficiency was assessed on a workstation with an NVIDIA GeForce RTX 4060 GPU (8 GB memory). Five event camera resolutions (DVS128, DAVIS240, ATIS, DAVIS346, GenX320) were evaluated with temporal interpolation factors of ×8, ×16, and ×32. Assuming a 30 Hz rendering cadence, these factors correspond to effective temporal sampling frequencies of 240 Hz, 480 Hz, and 960 Hz, respectively. The evaluation focused solely on the event generation pipeline.

- **Event Stream Generation Time:** The time required to generate an event stream per rendered-frame interval generally increased with both sensor resolution and temporal interpolation factor due to the processing of more intermediate samples.
 - For grayscale event generation, times ranged from 6.98 ms (DVS128, ×8 interpolation) to 27.28 ms (GenX320, ×32 interpolation).
 - For Bayer RGGB event generation, times ranged from 7.58 ms (DVS128, ×8 interpolation) to 29.16 ms (GenX320, ×32 interpolation).
 - Small non-monotonic variations were observed between sensors with similar pixel counts, which was attributed to implementation and memory-access characteristics.
- **GPU Memory Consumption:** GPU memory allocation scaled approximately linearly with sensor resolution and temporal interpolation factor.
 - Memory usage ranged from 51.4 MB (DVS128, ×8 interpolation) to 399.7 MB (GenX320, ×32 interpolation) for grayscale mode.
 - Bayer RGGB event generation showed only a marginal increase in GPU memory, with differences of at most 1.5 MB compared to grayscale mode.
 - Even under the most demanding configuration, the event generation backend utilized less than 400 MB of additional GPU memory, leaving substantial capacity for other Isaac Sim components on the 8 GB GPU.

- **Overall Performance:** The results suggest that EsaacSim efficiently generates both gray and Bayer RGGB event streams across commonly used event camera resolutions, exhibiting predictable computational and memory scaling on consumer-grade hardware. This indicates its capability to support online event simulation on accessible workstations.

#### 4.4. Limitations

The current version of EsaacSim has several identified limitations:
- **Frame-based Event Generation:** The event generation backend is currently frame-based only, meaning physics-grounded effects like optical path modeling and pixel-level circuit behavior are not yet incorporated. The physics-grounded backend, though reserved in the sensor interface, remains unimplemented.
- **Lack of Quantitative Validation:** The evaluation primarily focused on computational efficiency and qualitative consistency. A quantitative comparison against real event camera recordings is needed to assess the fidelity of the generated event streams.
- **Limited Scene Diversity in Evaluation:** Experiments were conducted on a single consumer-grade GPU with a limited set of static and quasi-static robotic scenes. Further evaluation with more dynamic manipulation tasks and multi-camera configurations is required to characterize performance under more demanding robotic workloads.

### 5. Significance and Potential Impact

EsaacSim addresses a critical need in event-based vision and robotics research by providing a multimodal, online event camera simulation add-on for NVIDIA Isaac Sim. Its significance and potential impact can be summarized as follows:

1. **Accelerated Research and Development:** By offering a platform for synthetic data generation, EsaacSim helps to overcome the limitations imposed by the scarce availability of physical event cameras and large-scale, diverse real-world event datasets. This enables researchers to develop, test, and validate event-based algorithms (e.g., for visual odometry, SLAM, object detection, and learning) without requiring access to specialized hardware, thereby accelerating the pace of innovation in neuromorphic vision.

2. **Facilitating Multimodal Perception Systems:** The provision of synchronized RGB, APS, event, depth, and IMU outputs through native ROS 2 interfaces is a key contribution. This capability directly supports the development of complex multimodal perception pipelines, which are becoming increasingly prevalent in robotics for robust and comprehensive scene understanding. Researchers can readily integrate event data with other modalities, fostering advancements in fusion algorithms and event-enhanced perception.

3. **Configurable and Reproducible Experimentation:** The configurable sensor model allows users to emulate a range of event camera characteristics, including resolution, contrast thresholds, and noise profiles. This enables systematic investigation into the impact of different sensor parameters on algorithm performance, facilitating reproducible research and aiding in the design of future event camera hardware or the optimization of algorithms for specific sensor types.

4. **Integration with Modern Robotics Workflows:** EsaacSim's integration into NVIDIA Isaac Sim, a prominent robotics simulation platform, aligns with modern simulation-centric development workflows. This allows robotics researchers to leverage Isaac Sim's photorealistic rendering, GPU-accelerated physics, and robot learning frameworks while incorporating event-based sensing. The native ROS 2 support ensures seamless integration into existing robotics software ecosystems.

5. **Accessibility and Scalability:** The performance evaluation demonstrates that EsaacSim can achieve efficient online event simulation at high effective temporal rates (up to 960 Hz) with moderate GPU memory consumption, even on consumer-grade hardware. This accessibility lowers the barrier to entry for researchers and practitioners, enabling a wider community to experiment with event-based vision without requiring high-performance computing infrastructure. The framework's ability to scale across different resolutions also supports diverse application requirements.

In the future, the planned enhancements, such as incorporating physics-based event generation, quantitative validation against real-world data, and evaluation in more dynamic robotic tasks, could further increase the fidelity and utility of EsaacSim. These advancements would strengthen its role as a robust tool for advancing event-based vision in robotics.
