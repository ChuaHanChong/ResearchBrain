# OpenHands: An Open Platform for AI Software Developers as Generalist Agents

> [!summary] Summary
> OpenHands is an open-source MIT-licensed platform for building AI agents that act like software developers by writing code, running a command line, and browsing the web. It combines an event-stream architecture, a Docker-sandboxed runtime, an extensible skills library, and multi-agent delegation. Its CodeAct generalist agent resolves 26% of SWE-Bench Lite and is evaluated on 15 benchmarks.

## Problem

- Existing agent frameworks rarely bundle sandboxed code execution, a full web browser, and human-agent collaboration together, forcing developers to assemble these pieces themselves for each new agent.
- Specialized agent-computer interfaces such as SWE-Agent tools are costly to build, maintain, and distribute, and are hard to share across different agent implementations.
- Agents that run arbitrary code risk harming user systems, and prior frameworks lack standardized evaluation harnesses, making agents hard to compare across diverse benchmarks.

## Method

- ==Event stream architecture== records chronological actions and observations as agent state; agents implement a simple ==step function== mapping history to an action such as IPythonRunCellAction, CmdRunAction, or BrowserInteractiveAction.
- ==Agent runtime== launches a ==Docker sandbox== per session with a bash shell, Jupyter IPython server, and Playwright Chromium browser, exposed through an ==action execution API== installable into arbitrary images.
- **AgentSkills** library adds Python tools like edit_file and parse_pdf only where LLM-written code is insufficient, and ==AgentDelegateAction== lets a generalist **CodeActAgent** hand subtasks to specialists like **BrowsingAgent**.

## Results

- On SWE-Bench Lite without hints, CodeActAgent v1.8 with claude-3.5-sonnet resolves **26.0%** at **$1.10** average cost, versus **18.0%** for SWE-Agent and **19.0%** for AutoCodeRover.
- On HumanEvalFix the 0-shot generalist fixes **79.3%** of bugs with gpt-4o, nearly double StarCoder2-15B at **48.6%**, and reaches **76.5%** on ML-Bench versus **64.4%** for Aider.
- On WebArena, delegating to BrowsingAgent gives **15.3%** with claude-3.5-sonnet versus **15.5%** for the specialist directly; on MiniWoB++ delegation scores **39.8%** against **40.8%**.

## Takeaways

> [!tip] Key Insights
> - A small, general action space of bash, Python, and browser commands can cover many tasks, letting one generalist agent compete with specialists across 15 benchmarks without task-specific tooling.
> - Delegation to specialist agents costs almost nothing in accuracy, so a generalist can stay simple and hand off hard subdomains like web browsing.
> - Add custom tools only when the LLM cannot easily write the code itself; otherwise rely on code generation. This keeps the tool library small and maintainable.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

The development of AI agents capable of autonomous interaction with digital environments is a rapidly evolving area within artificial intelligence, heavily influenced by advancements in large language models (LLMs). OpenHands positions itself at the forefront of this landscape by addressing a critical need for a standardized, open, and comprehensive platform for developing, evaluating, and deploying generalist AI agents.

**Evolution of AI Agents:** The paper acknowledges the rapid progress in LLMs, which has enabled user-facing AI systems like ChatGPT to perform complex tasks, leading to an increased focus on AI agents. These agents are moving beyond simple query-response systems to tackle intricate problems in domains like software development (e.g., Devin, SWE-Agent), web navigation (e.g., WebArena), robotics, and scientific research. OpenHands builds upon this trend, specifically focusing on agents that emulate human developers' interactions with software and digital environments.

**Existing Frameworks and Their Limitations:** The paper critically compares OpenHands with existing open-source frameworks such as AutoGPT, LangChain, MetaGPT, AutoGen, and specialized tools like SWE-Agent and BrowserGym. It highlights that while many frameworks facilitate agent development by providing interfaces, environments, or interaction mechanisms, they often suffer from several limitations:
- **Lack of Generality:** Many existing agents or frameworks are specialized for particular tasks (e.g., software engineering, web browsing) and lack the generalist capabilities to handle diverse problems. OpenHands aims to create "general digital agents" capable of excelling across various categories.
- **Insufficient Sandboxing and Code Execution:** While some frameworks offer code execution, they may lack robust, securely isolated sandboxed environments for executing arbitrary, agent-generated code, which is crucial for real-world software development tasks. OpenHands explicitly provides a Docker-sandboxed operating system.
- **Limited Web Interaction:** Full web browsing capabilities, including interaction with complex web elements beyond simple text extraction, are often missing or rudimentary in general agent frameworks. OpenHands integrates a powerful web browser (Playwright Chromium) with a domain-specific language from BrowserGym.
- **Absence of Standardized Evaluation:** A fragmented landscape of benchmarks makes it difficult to systematically compare and track the progress of different agents. OpenHands integrates 15 established benchmarks across diverse categories to provide a comprehensive evaluation framework.
- **Lack of Community-Driven Development:** While some projects are open-source, OpenHands emphasizes its "community-driven" nature, aiming to lower the barrier for contribution and foster a collective effort in agent development.

**Agent-Computer Interface (ACI):** OpenHands acknowledges the importance of a well-crafted ACI, as highlighted by works like SWE-Agent, but takes it a step further by creating an extensible "AgentSkills" library. This library provides reusable tools that abstract complex operations, making it easier for agents to interact with the environment without needing to re-learn basic functionalities or handle low-level system details. This approach simplifies tool creation, maintenance, and distribution across different agent implementations.

In essence, OpenHands positions itself as a unifying and accelerating force in the AI agent ecosystem. It seeks to provide a comprehensive, extensible, and safely sandboxed platform that can serve as a common ground for academic research and industrial application, pushing the boundaries of what generalist AI agents can achieve by mimicking human software development workflows.

### 2. Key Objectives and Motivation

The core objectives and motivations behind OpenHands are clearly articulated, aiming to address critical gaps in the current landscape of AI agent development and deployment:

1. **Develop Powerful and Flexible Generalist AI Agents:** The primary objective is to create a platform that facilitates the development of AI agents capable of interacting with the world "in similar ways to those of a human developer: by writing code, interacting with a command line, and browsing the web." This emphasis on mimicking human developer workflows is central to its design, enabling agents to tackle complex, real-world tasks that go beyond simple task automation.

2. **Enable Safe and Controlled Interaction:** A significant motivation is to ensure that agent development is "safe and avoids negative side effects on the users' systems." This is addressed through the provision of securely isolated Docker-sandboxed environments, where all agent actions are executed, mitigating risks associated with arbitrary code execution.

3. **Provide a Comprehensive and Extensible Platform:** OpenHands aims to offer a complete ecosystem that streamlines the entire agent development lifecycle. This includes:
 - **Flexible Interaction Mechanisms:** An event stream architecture allows seamless interaction between user interfaces, agents, and environments.
 - **Robust Runtime Environment:** A sandboxed operating system equipped with a bash shell, web browser, and IPython server provides a rich environment for agents.
 - **Developer-like Interface:** Tools for code creation/editing, arbitrary code execution, and web browsing are provided, mirroring a human software engineer's toolkit.
 - **Modular Agent Design:** The platform supports the implementation of new agents and the composition of multiple specialized agents through delegation.
 - **Extensible Tooling:** The "AgentSkills" library aims to simplify the creation, maintenance, and distribution of reusable tools for agents.

4. **Facilitate Systematic Evaluation:** A crucial objective is to provide a standardized framework for evaluating agent performance across a wide range of tasks. This addresses the challenge of systematically tracking progress in building generalist digital agents and allows for robust comparisons between different agent implementations.

5. **Foster a Community-Driven Open-Source Ecosystem:** As an open-source project released under the permissive MIT license, OpenHands is motivated to lower the barrier to entry for agent development and foster broad community contributions from both academia and industry. This collaborative approach is seen as a "catalyst for future research innovations and diverse applications."

In essence, OpenHands seeks to bridge the gap between impressive LLM capabilities and reliable, versatile, and safe autonomous agent behaviors, particularly within the domain of digital interaction and software development. It aims to empower researchers and developers to build more capable and trustworthy AI agents by providing the necessary infrastructure, tools, and evaluation methodologies.

### 3. Methodology and Approach

OpenHands adopts a modular and comprehensive approach to building a generalist AI agent platform. Its methodology is centered around three main components: Agent Abstraction, Event Stream, and Agent Runtime, supplemented by Agent Skills, Multi-Agent Delegation, and a robust Evaluation Framework.

#### 3.1. Agent Abstraction and Event Stream

The core of OpenHands' architecture is its agent abstraction, where an `Agent` perceives the `State` of the environment and produces an `Action` for execution.
- **State and Event Stream:** The `State` is a data structure encapsulating all relevant information, with the `event stream` being a chronological record of past `Actions` and `Observations`. This history is crucial for agents to maintain context and plan future steps.
- **Actions:** Inspired by CodeAct, OpenHands defines a set of general actions that mirror human developer interactions:
 - `IPythonRunCellAction`: Executes arbitrary Python code within a Jupyter IPython environment.
 - `CmdRunAction`: Executes arbitrary bash commands in the sandbox.
 - `BrowserInteractiveAction`: Interacts with a web browser using a domain-specific language from BrowserGym.
These actions are chosen for their comprehensiveness and flexibility, allowing agents to perform diverse tasks, including code editing, debugging, and information gathering. The framework also supports existing tool-calling agents by allowing Python functions (tools) to be defined using these primitives.
- **Observations:** These describe the environmental changes resulting from executed actions or user inputs (e.g., command output, Python execution results, browser state).
- **Implementing Agents:** The agent abstraction is simplified through a `step` function that takes the current `State` and generates an `Action`, allowing developers to focus on agent logic.

#### 3.2. Agent Runtime

The Agent Runtime provides the sandboxed environment where agent actions are executed, mimicking a human developer's workstation.
- **Docker Sandbox:** Each task session spins up a securely isolated Docker container. This isolation is critical for safety, preventing malicious or erroneous agent actions from affecting the host system.
- **OpenHands Action Execution API:** A REST API server runs *inside* the Docker sandbox, listening for action execution requests from the OpenHands backend. This API server provides interfaces to:
 - A **bash shell** for command-line interactions.
 - A **Jupyter IPython server** for interactive Python code execution.
 - A **Chromium browser** based on Playwright, enabling complex web interactions (navigation, clicking, typing, scrolling, form submission) and providing rich observations (HTML, DOM, screenshots).
- **Arbitrary Docker Image Support:** A key feature is the ability to run agents on user-provided, arbitrary Docker images. OpenHands includes a build mechanism to install its action execution API into any given image, allowing agents to operate in diverse pre-configured software environments.

#### 3.3. Agent Skills

To enhance agent capabilities and simplify development, OpenHands includes an "AgentSkills" library.
- **Extensible Toolbox:** This Python package contains utility functions (tools) automatically imported into the IPython environment. This lowers the barrier for community contributions of new tools.
- **Inclusion Criteria:** New skills are added only when LLMs cannot easily achieve the functionality directly by writing code (e.g., complex file editing, multi-modal document parsing) or when external models are involved (e.g., speech-to-text).
- **Currently Supported:** Examples include `edit_file`, `scroll_up`/`scroll_down` (for file navigation), and `parse_image`/`parse_pdf`/`parse_audio`/`parse_video`/`parse_pptx`/`parse_latex` (for multi-modal document understanding using vision-language models or other specific parsers).

#### 3.4. Multi-Agent Delegation

OpenHands supports cooperative multi-agent interaction through a special `AgentDelegateAction`. This allows a generalist agent to offload specific subtasks to specialized agents (e.g., a CodeActAgent delegating web browsing to a BrowsingAgent), promoting modularity and specialized expertise.

#### 3.5. AgentHub and Evaluation Framework

- **AgentHub:** Based on the flexible agent abstraction, OpenHands provides an "AgentHub" with community-contributed agent implementations, including the default `CodeActAgent` (a generalist), a `BrowsingAgent` (a web specialist), `GPTSwarm Agent`, and `Micro Agent` (specialized prompts atop generalist agents).
- **Evaluation Framework:** A comprehensive evaluation framework integrates 15 established benchmarks across software engineering (e.g., SWE-Bench, HumanEvalFix), web browsing (e.g., WebArena, MiniWoB++), and miscellaneous assistance (e.g., GAIA, GPQA, AgentBench). This systematic approach enables rigorous comparison and tracking of agent performance.
- **Quality Control (Integration Tests):** The platform pioneers an end-to-end agent test framework that includes prompt regression, action validation, and sandbox environment testing. This uses foundation model mocking for deterministic behavior, ensuring software quality and preventing bugs, a critical feature for complex agent systems.

This layered methodology ensures that OpenHands is not just a collection of tools but a cohesive platform designed for robustness, extensibility, safety, and systematic advancement of AI agent research.

### 4. Main Findings and Results

The paper presents a comprehensive evaluation of OpenHands agents across 15 diverse benchmarks, categorized into software engineering, web browsing, and miscellaneous assistance tasks. The key takeaway from the results is the demonstrated **generality** of the OpenHands CodeAct agent, which achieves competitive performance across these varied categories without task-specific modifications to its system prompt.

#### 4.1. Software Engineering Benchmarks (Table 4)

- **SWE-Bench Lite (Fixing GitHub Issues):** The CodeActAgent v1.8, using `claude-3.5-sonnet`, achieved a 26.0% resolve rate. This is competitive with other specialized open-source SWE agents like Aider (26.3%) and Moatless Tools (26.7%), and surpasses SWE-Agent (18.0%) and AutoCodeRover (19.0%) using different GPT models. The `gpt-4o` model also performed strongly at 22.0%. Notably, the `gpt-4o-mini` achieved 7.0% at a significantly lower cost.
- **HumanEvalFix (Fixing Python Bugs):** OpenHands CodeActAgent v1.5 with `gpt-4o` successfully fixed 79.3% of bugs in a 0-shot setting. This is a substantial improvement over non-agentic approaches (e.g., StarCoder2-15B at 48.6%) and almost doubles `gpt-3.5-turbo-16k` (20.1%). While SWE-Agent achieved 87.7% with a 1-shot demonstration, OpenHands' 0-shot performance highlights its inherent capability.
- **ML-Bench (Machine Learning Coding):** OpenHands CodeActAgent v1.5 with `gpt-4o` achieved 76.5%, outperforming Aider (64.4%) and SWE-Agent (42.6%).
- **BioCoder (Bioinformatics Coding):** CodeActAgent v1.5 with `gpt-4o` achieved 27.5% success, demonstrating capability in specialized scientific domains.
- **Gorilla APIBench (Software API Calling):** CodeActAgent v1.5 with `gpt-4o` scored 36.4%, showing proficiency in API usage.
- **ToolQA (External Tool Use):** CodeActAgent v1.5 with `gpt-4o` achieved 47.2%, indicating strong reasoning and tool-use capabilities.
- **BIRD (Text-to-SQL):** CodeActAgent v1.5 with `gpt-4o` achieved 47.3% execution accuracy, showcasing its ability to interact with databases.

#### 4.2. Web Browsing Benchmarks (Table 5)

- **WebArena (Realistic Browsing):** The specialized BrowsingAgent v1.0 and the generalist CodeActAgent v1.8 (via delegation) both achieved competitive performance with `claude-3-5-sonnet` (15.5% and 15.3% respectively) and `gpt-4o` (14.8% and 14.5% respectively). These results are comparable to other LLM-based web agents like WebArena Agent (14.4% with `gpt-4-turbo`) and notably better than smaller models or those without self-improvement.
- **MiniWoB++ (Synthetic Web Tasks):** BrowsingAgent v1.0 and CodeActAgent v1.8 (via delegation) with `gpt-4o` achieved 40.8% and 39.8% respectively on the full set, demonstrating capabilities in short trajectory web tasks, including those requiring vision.

#### 4.3. Miscellaneous Assistance Benchmarks (Table 6)

- **GAIA (General AI Assistants):** The GPTSwarm v1.0 agent, using `gpt-4o`, achieved a 32.1% success rate on the L1 validation set, surpassing AutoGPT (13.2%).
- **GPQA (Graduate-Level Q&A):** CodeActAgent v1.8 with `claude-3-5-sonnet` achieved 52.0% on the challenging Diamond set, significantly outperforming GPT-4 (38.8%) and `gpt-3.5-turbo-16k` (29.6%) in few-shot CoT settings, and demonstrating a substantial gap with non-expert human performance (21.9%). This highlights the agent's strong reasoning and tool-use (including code) capabilities for complex problem-solving.
- **AgentBench (OS Interaction):** CodeActAgent v1.5 with `gpt-4o` achieved 57.6% on the OS subset, outperforming AgentBench Baseline Agents (`gpt-4` at 42.4%, `gpt-3.5-turbo` at 32.6%).
- **MINT (Multi-turn Interaction with Tools):** CodeActAgent v1.5 with `gpt-4o` achieved 77.3% on the math subset and 50.0% on the code subset, showing strong performance in multi-turn interactions with tool use and feedback.
- **ProofWriter (Deductive Logic Reasoning):** CodeActAgent v1.5 with `gpt-4o` achieved 78.8%, comparable to Logic-LM (79.6%), which combines GPT-4 with a symbolic solver. This indicates strong inherent reasoning capabilities.
- **Entity Deduction Arena (Strategic Planning):** CodeActAgent v1.5 with `gpt-4o` achieved 38.0% (average over "Things" and "Celebrities"), comparable to zero-shot GPT-4 (40.0%).

**Overall Assessment:**
While OpenHands agents may not achieve state-of-the-art in *every single* benchmark when compared to highly specialized or extensively fine-tuned models, their significant achievement lies in their **generality**. The same underlying CodeAct agent architecture, with minimal or no prompt engineering specific to each benchmark, demonstrates strong and competitive performance across software engineering, web browsing, and complex reasoning tasks. This suggests that OpenHands provides a robust and flexible foundation for building genuinely generalist digital agents, a crucial step towards more autonomous and versatile AI systems. The cost analysis also indicates that even highly capable agents can be run at a reasonable cost, especially with models like `gpt-4o-mini`.

### 5. Significance and Potential Impact

OpenHands represents a significant contribution to the field of AI agents, with wide-ranging potential impacts on research, development practices, and the future of human-AI collaboration.

1. **Accelerating Generalist AI Agent Research:** By providing a unified platform with standardized interfaces, a safe sandboxed environment, and a comprehensive evaluation framework, OpenHands significantly lowers the barrier to entry for researchers and developers. This facilitates faster iteration, comparison, and improvement of generalist AI agents. The ability to integrate new agents, skills, and benchmarks easily means the platform can adapt to future research directions and expand its capabilities organically.

2. **Bridging Academia and Industry:** The extensive multi-institutional collaboration, including major tech companies like Alibaba and AI startups like All Hands AI alongside top universities, signifies OpenHands' appeal and utility across both research and practical application domains. Its open-source nature (MIT license) encourages widespread adoption, fostering a vibrant ecosystem where innovations from one part of the community can benefit all.

3. **Enhancing Agent Robustness and Safety:** The emphasis on Docker-sandboxed execution environments is paramount. This robust isolation is crucial for experimenting with and deploying AI agents that can execute arbitrary code or interact with the web, mitigating significant security risks. The pioneering of end-to-end integration tests for agents further contributes to software quality and reliability, addressing a critical challenge in complex AI systems where subtle errors can have large consequences.

4. **Promoting Standardized Evaluation and Reproducibility:** The integration of 15 diverse benchmarks provides a common ground for evaluating agent performance. This standardization enables meaningful comparisons across different agent architectures and LLMs, accelerating progress by clearly identifying strengths and weaknesses. The focus on reproducible baselines (e.g., 0-shot prompting) further enhances the scientific rigor of agent development.

5. **Democratizing AI Software Development:** By open-sourcing a platform that mirrors a human developer's interaction style, OpenHands empowers a broader community to build, customize, and deploy AI software engineers. This could lead to a democratization of AI-assisted software development, making advanced tooling accessible to more practitioners and fostering new applications beyond traditional software engineering.

6. **Paving the Way for More Capable Human-AI Collaboration:** The platform's design supports human-AI collaboration, allowing users to interrupt agents, provide feedback, and guide their actions. This interactive approach is vital for building trustworthy agents, ensuring human oversight and control as AI capabilities advance. This model also supports multi-agent delegation, enabling more sophisticated collaborative problem-solving.

7. **Future Directions and Limitations Addressed:** The paper openly discusses limitations, such as the need for enhanced multi-modality support, stronger agents, improved file editing, and more robust web browsing. It also envisions future advancements like automatic workflow generation through graph-based frameworks. By laying a solid foundation and acknowledging areas for improvement, OpenHands positions itself as an enduring and evolving platform rather than a static research artifact.

In conclusion, OpenHands is more than just a research paper; it is a foundational open-source project that seeks to define and advance the paradigm of generalist AI agents. Its focus on safety, extensibility, comprehensive evaluation, and community-driven development makes it a highly significant and potentially transformative platform for the future of AI.
