# On Exploring Input Resolution Scaling For Anytime LiDAR Object Detection

> [!summary] Summary
> MURAL is a framework that enables dynamic input resolution scaling for LiDAR object detection DNNs within a single model. It achieves improved detection accuracy across varying latency requirements and enhances autonomous driving safety in simulations by dynamically adapting to different operational scenarios.

## Problem

- State-of-the-art LiDAR object detection DNNs are computationally expensive, making real-time deployment on resource-constrained embedded hardware challenging.
- The optimal balance between accuracy and latency for object detection varies dynamically with operational environments, a flexibility that fixed-resolution models cannot provide.
- Existing anytime LiDAR approaches have limitations, such as reduced effectiveness with sparse CNNs or significant accuracy drops under tight deadlines due to incomplete input processing, with input resolution scaling being largely unexplored for LiDAR.

## Method

- **MURAL** employs a ==multi-resolution training== scheme with ==resolution-aware Batch Normalization (BN)== layers, allowing a single model to effectively operate across multiple predefined input pillar/voxel sizes.
- It incorporates a post-training synthesis mechanism that uses ==quadratic regression== to generate BN layer parameters for additional, untrained input resolutions, providing finer-grained control over latency-accuracy trade-offs without retraining.
- A ==deadline-aware scheduler== dynamically selects the highest possible input resolution by accurately predicting execution times, especially for sparse CNNs, using ==max-pooling emulation== for pillar-based models and an offline lookup table for voxel-based models.

## Results

- MURAL consistently achieved detection accuracy comparable to or better than individually trained fixed-resolution baselines and surpassed prior anytime LiDAR methods across a range of deadlines on embedded platforms.
- The framework demonstrated superior memory efficiency, requiring significantly less memory than deploying multiple fixed-resolution models (e.g., **61.378 MiB** for MURAL Pillarnet compared to **6x ~61 MiB** for baselines).
- In closed-loop simulations, MURAL enabled collision-free navigation in high-speed dynamic hazard environments (avoiding all **30** collisions) and more efficient navigation in dense urban environments by dynamically adapting its resolution to situational demands.

## Takeaways

> [!tip] Key Insights
> - Employing resolution-aware Batch Normalization within a single model allows effective multi-resolution LiDAR object detection, addressing accuracy degradation typically seen when using a fixed model across varied input resolutions.
> - Parameters for Batch Normalization layers can be accurately synthesized for new input resolutions post-training, providing flexible accuracy-latency trade-offs without the need for extensive retraining.
> - Accurate, dynamic prediction of sparse CNN execution times is critical for effective deadline-aware scheduling in anytime LiDAR, ensuring the selection of the optimal resolution to maximize accuracy within latency constraints.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

Autonomous systems critically rely on real-time, accurate detection of surrounding objects, a task often performed by LiDAR-based Deep Neural Networks (DNNs). While numerous highly accurate LiDAR object detection DNNs have been developed, their computational expense frequently challenges deployment on resource-constrained embedded hardware, necessitating trade-offs between accuracy and latency. These trade-offs are not static but depend on dynamic operational environments; for instance, fine-grained processing might be desirable in complex urban settings, while faster, coarser processing might be preferred on highways.

This context introduces the concept of "anytime algorithms," which can dynamically adjust quality and latency. In the realm of DNNs, prior research has explored early-exit architectures, criticality-based input slicing, and dynamic image resolution scaling, primarily for camera-based image classification and object detection.

For LiDAR-based object detection, anytime capabilities have been less explored. Previous efforts like "Anytime-LiDAR" focused on early-exit methods combined with detection head scheduling for models without sparse CNNs, showing limited effectiveness for more accurate models utilizing sparse CNNs. "VALO" explored deadline-aware input slicing and scheduling, improving anytime performance but potentially sacrificing accuracy under tight deadlines due to incomplete input processing. A significant gap identified in the literature is the underexplored factor of input resolution scaling for LiDAR detection models. While adjusting resolution offers a clear trade-off between accuracy and execution time, deploying multiple models (one for each resolution) results in linear memory growth, posing a challenge for practical embedded system deployment.

This paper introduces MURAL, a framework designed to enable multi-resolution inference for LiDAR object detection DNNs within a single model. MURAL addresses the limitations of prior work by focusing on input resolution scaling while maintaining a single DNN model and aiming for accuracy comparable to or exceeding dedicated fixed-resolution models. By providing a memory-efficient and highly adaptable solution for LiDAR-based 3D object detection, MURAL positions itself as an advancement in enabling anytime capabilities for autonomous driving perception, particularly for modular, industry-standard approaches.

### 2. Key Objectives and Motivation

The motivation for this research stems from the inherent challenges of deploying state-of-the-art LiDAR object detection DNNs in real-time autonomous systems, particularly on resource-constrained embedded hardware. These challenges are multifold:
- **Computational Expense:** Modern LiDAR object detection DNNs are computationally demanding, making it difficult to achieve high accuracy within strict latency budgets on systems with limited size, weight, and power (SWaP).
- **Dynamic Operational Requirements:** The optimal balance between accuracy and latency is not fixed but changes with the environment. In a dense urban setting, high accuracy might be paramount, even if it incurs higher latency, to detect numerous slow-moving objects. Conversely, on a highway, lower latency for quick hazard detection might be more critical than capturing fine details.
- **Limitations of Existing Anytime Approaches for LiDAR:**
 - **Early-exit/detection head scheduling:** Approaches like Anytime-LiDAR have shown limited effectiveness with higher-accuracy models that rely on sparse Convolutional Neural Networks (CNNs).
 - **Input data slicing and scheduling:** Methods such as VALO, while improving anytime performance, may suffer significant accuracy degradation under tight deadlines because they process only a portion of the input data, relying on forecasting for missed information.
 - **Input Resolution Scaling Gap:** Although varying input resolution (e.g., pillar or voxel size) offers a direct trade-off between accuracy and latency, it has been largely overlooked for LiDAR. A naive approach of deploying multiple models, each trained for a different resolution, results in prohibitive memory requirements for embedded platforms. Furthermore, simply running a single model trained at one resolution with a different inference resolution leads to a substantial drop in accuracy, as illustrated by the reported 78.8% to 18.0% mAP reduction for Pillarnet with resolution mismatch.

To address these motivations, the MURAL framework sets out to achieve the following key objectives:
1. **Enable Dynamic Multi-Resolution Inference with a Single Model:** The primary objective is to allow dynamic selection of input resolution for pillar- or voxel-based LiDAR object detection DNNs at runtime, using a single, shared set of network weights. This aims to facilitate flexible accuracy-latency trade-offs without the memory overhead of deploying multiple distinct models.
2. **Support Additional Input Resolutions Post-Training:** To enhance flexibility and provide more granular control over latency-accuracy trade-offs, MURAL aims to enable the use of input resolutions beyond those explicitly used during training. This is achieved through a synthesis mechanism that predicts resolution-specific parameters for new Batch Normalization (BN) layers post-training, avoiding the need for retraining or fine-tuning.
3. **Implement a Deadline-Aware Scheduler with Accurate Execution Time Prediction:** MURAL seeks to incorporate a scheduler that dynamically selects the highest possible input resolution (smallest pillar/voxel size) that can meet a given deadline. This requires accurately predicting the end-to-end execution time for each candidate resolution at runtime, a complex task due to the irregular nature of LiDAR point clouds and the variability in sparse CNN execution times.

By achieving these objectives, MURAL aims to provide a robust, memory-efficient, and adaptable solution for real-time LiDAR object detection in dynamic autonomous driving environments.

### 3. Methodology and Approach

MURAL (MUlti-Resolution Anytime LiDAR framework) is designed to transform pillar- or voxel-based LiDAR object detection DNNs into anytime algorithms, balancing detection accuracy and execution latency by dynamically adjusting the input resolution.

#### 3.1. Overview

MURAL's core mechanism involves dynamically adjusting the size of pillars or voxels used to encode the input point cloud. Larger pillar/voxel sizes reduce the number of processed elements and grid resolution, leading to faster inference but potentially lower accuracy. This adjustment is achieved through modifications to the target DNN's normalization layers and a specialized training methodology. MURAL also supports additional resolutions post-training by synthesizing new parameters for these layers. A deadline-aware scheduler selects the optimal pillar/voxel size at runtime by predicting execution times. Complementary optimizations from prior work, such as dense CNN optimizations, object forecasting, and region dropping (for voxel-based models), are integrated to enhance performance.

#### 3.2. Multi-Resolution Training and Inference

MURAL introduces a DNN training scheme that allows a single model to operate effectively across a predefined set of pillar sizes.
- **Loss Accumulation:** During training, for each input batch, a separate forward pass is performed for every targeted pillar size. The loss values from these passes are accumulated (`L_total = Σ L(f_θ(x, p), y)`), and backpropagation updates model parameters `θ` based on this total loss. This ensures gradients from all resolutions contribute to parameter updates.
- **Resolution-Aware Batch Normalization (BN):** To address accuracy degradation when a single model is used for multiple resolutions, MURAL replaces all standard BN layers with resolution-aware BN layers. Each resolution-aware BN block contains separate BN layers, each dedicated to a specific input resolution. This design is motivated by the observation that different input resolutions lead to distinct statistical distributions in feature maps, affecting BN layer behavior. During training, all BN layers within an active resolution-aware block are updated. During inference, only the BN layers corresponding to the selected resolution are activated. This approach introduces a negligible memory overhead while significantly improving accuracy for each supported resolution.

#### 3.3. Synthesizing Additional Input Resolutions Post-Training

To provide finer-grained latency-accuracy trade-offs, MURAL can generate support for additional input resolutions beyond those used in training without requiring retraining.
- **Parameter Regression:** For pillar-based models, parameters (running mean, variance, learnable scale, and shift) of BN layers for new resolutions are predicted using quadratic regression models. These models are fitted independently per layer and input channel to the parameters of the BN layers that were trained.
- **Limitations for Voxel-based Models:** This synthesis approach is currently effective only for pillar-based models. For voxel-based models, the 3D convolutions in sparse CNNs are more sensitive to resolution changes, making the synthesized BN layers less effective without modifications to the convolutional layers themselves.

#### 3.4. Dynamic Resolution Scheduling

MURAL's scheduler aims to maximize detection accuracy under a given deadline by selecting the highest possible resolution that can complete execution on time. This requires accurate runtime latency prediction.
- **Latency Decomposition:** The total latency `L` of a LiDAR object detection model is decomposed into four components: Pillar/Voxel Feature Encoder (`L_PFE/VFE`), Sparse CNN (`L_SC`), Dense CNN (`L_DC`), and Post-Processing (`L_PP`).
- **Predictable Components:** `L_PP` and `L_DC` exhibit minimal variation. Their 99th percentile values, determined offline for each resolution, serve as reliable predictions. `L_PFE/VFE` shows a strong correlation with the number of input points, modeled by quadratic regression for runtime prediction.
- **Sparse CNN Latency Prediction (Pillar-based):** `L_SC` is highly variable due to the dynamic nature of sparse convolutions. MURAL employs lightweight max-pooling operations to emulate sparse convolution layers. By replicating kernel size, stride, and padding, max pooling infers the number and coordinates of active output pillars for each sparse convolution layer without executing the full CNN. These predicted per-layer pillar counts are then mapped to execution times using pre-fitted quadratic equations, and summed to estimate `L_SC`. This is done for each candidate pillar size.
- **Sparse CNN Latency Prediction (Voxel-based):** For voxel-based models, 3D max pooling is too computationally expensive. MURAL uses an offline lookup table containing measured execution times for representative input samples across resolutions. At runtime, it identifies the row in the table whose latency values for the last frame's resolution are closest to the last frame's actual execution time. This row's values are then used as predicted execution times for all candidate resolutions, assuming spatial consistency.
- **Scheduling Algorithm:** The scheduler performs a top-down search, starting from the highest resolution (smallest pillar/voxel size). It predicts the execution time for each candidate resolution and selects the first one that is predicted to meet the given deadline. If no candidate resolution meets the deadline, the lowest resolution (largest pillar/voxel size) is chosen as a fallback.

#### 3.5. Dense CNN Optimizations

MURAL incorporates optimizations for the dense CNN from prior work to reduce latency without accuracy loss:
- **Empty Region Cropping:** Large portions of the Bird's-Eye View (BEV) grid can be empty. These empty regions are cropped to speed up dense CNN processing.
- **Region-of-Interest Computation:** Computations in detection head dense convolutions are limited to regions where objects are likely located, avoiding redundant calculations across the entire grid.

#### 3.6. Forecasting

To improve robustness, MURAL integrates a forecasting mechanism:
- **Predicting Object Positions:** Based on estimated velocity and ego-vehicle localization, previously detected objects' current positions are predicted.
- **Compensating for Missed Detections:** This helps track objects that might be missed in the current frame (e.g., due to occlusion) or when a lower resolution is used, by merging current detections with forecasted objects, prioritizing current detections.

#### 3.7. Region Dropping (Voxel-based Only)

For voxel-based models, whose sparse CNN time prediction relies on an offline lookup table (due to prohibitive max pooling overhead), prediction inaccuracies can occur.
- **Mitigating Deadline Misses:** If a potential deadline miss is anticipated after the sparse CNN stage due to underprediction, the region-dropping mechanism trims the dense input tensor. Regions are cropped equally from the left and right sides of the BEV, as these areas are typically less likely to contain safety-critical objects (ego-vehicle and immediate surroundings are usually centered).

### 4. Main Findings and Results

The evaluation of MURAL was conducted in two phases: an open-loop study using the nuScenes dataset to assess detection performance under hard deadlines, and a closed-loop simulation study to evaluate its impact on autonomous driving safety and efficiency. Experiments were performed on NVIDIA Jetson AGX Xavier and Orin platforms, operating at a 30W power profile.

#### 4.1. Open-loop Evaluation: Training Results

- **Accuracy Equivalence/Superiority:** MURAL, as a single multi-resolution model, achieved accuracy comparable to individually trained fixed-resolution baseline Pillarnet models for the smallest (0.100 m²) and largest (0.200 m²) pillar sizes. For the medium pillar size (0.128 m²), MURAL surpassed the baseline (0.560 mAP vs. 0.537 mAP), attributed to a regularization effect from multi-resolution training.
- **Post-training Synthesis Effectiveness:** MURAL demonstrated satisfactory accuracy for pillar sizes introduced post-training via synthesized BN layers, with performance falling between neighboring trained resolutions. This enables more flexible latency-accuracy trade-offs without re-training.

#### 4.1.2. MURAL on Pillarnet

- **Superior Accuracy-Latency Trade-offs:** MURAL consistently outperformed both fixed-resolution Pillarnet baselines and the prior state-of-the-art anytime method, VALO, across a wide range of deadlines on both Jetson AGX Orin and Xavier.
- **Rationale for Outperformance:** MURAL's dynamic resolution scheduling allows it to select from a broader range of resolutions, always processing the complete input frame (albeit at varying resolutions). This contrasts with VALO's data scheduling strategy, which processes only a fraction of input data under tight deadlines and relies heavily on forecasted detections, leading to lower accuracy.

#### 4.1.3. MURAL on PointPillars

- Similar to Pillarnet, MURAL achieved better or comparable accuracy across all evaluated deadlines compared to PointPillars baselines and VALO-applied PointPillars, further demonstrating its versatility.

#### 4.1.4. MURAL on CenterPoint

- **Generalizability to Voxel-based Models:** MURAL maintained better or comparable accuracy across most tested deadlines compared to CenterPoint baselines and VALO on CenterPoint, despite not utilizing post-training pillar size synthesis (a feature limited to pillar-based models).
- **Tight Deadline Exception:** For the tightest deadline on Orin, VALO's accuracy, though very low, was higher than MURAL's. However, MURAL still significantly outperformed the baselines in this scenario. This exception indicates MURAL's difficulty in meeting very tight deadlines with its smallest input resolution, which VALO can sometimes achieve by processing a minimal subset of data.

#### 4.1.5. Ablation Study

- **Dynamic vs. Static Scheduling:** Dynamic scheduling (DS) improved performance over static scheduling (SS) due to more accurate execution time prediction.
- **Additional Pillar Sizes (APS):** Introducing APS further improved accuracy by allowing better utilization of available time.
- **Dense CNN Optimizations (DCO):** DCO allowed meeting deadlines with higher resolutions without sacrificing accuracy, and its overhead was compensated by accelerated dense CNN execution.
- **Forecasting (FRC):** FRC contributed to overall detection accuracy by recovering occluded or missed objects from previous frames.
- **Resolution-Aware BN (RABN):** MURAL with RABN significantly outperformed MURAL without RABN, highlighting the critical role of separate BN layers per resolution in adapting to distinct statistical distributions and maintaining high accuracy.

#### 4.1.6. Time Prediction Error

- MURAL's max-pooling based sparse CNN time prediction for pillar-based models demonstrated superior accuracy compared to VALO's history-based approach. MURAL precisely estimates per-layer input pillar counts, which are crucial for execution time, while VALO's assumption of spatial consistency across frames can break down in dynamic environments.

#### 4.1.7. Time and Memory Overhead Analysis

- **Scheduling Overhead:** Static scheduling incurred negligible overhead. Dynamic scheduling for Pillarnet had moderate overhead due to sparse convolution emulation, while PointPillars (no sparse CNN) had low overhead. CenterPoint (history-based sparse CNN prediction) had moderate overhead. Additional pillar sizes and dense CNN optimizations increased scheduling overhead, but the latter was offset by execution acceleration. Forecasting incurred negligible overhead as it runs in parallel.
- **Memory Overhead:** MURAL exhibited significantly lower memory overhead compared to deploying multiple baseline models (e.g., 61.378 MiB for MURAL Pillarnet vs. 61.003 MiB x 6 for baselines). This is because MURAL's memory increase per additional resolution is limited to the parameters for new BN layers, which are minimal compared to full model weights.

#### 4.2. Closed-loop Evaluation: Dense Urban Environment (Traffic Intersection Scenario)

- **False Positives (FPs) and Stalls:** Low-resolution baselines (0.200 m², 0.128 m²) exhibited high FP rates, frequently misclassifying static objects (e.g., lampposts) as pedestrians due to lost fine-grained features during voxelization. These FPs caused unnecessary vehicle stalls or decelerations, increasing median track completion times by up to 59% compared to the high-resolution baseline (0.100 m²).
- **MURAL Performance:** MURAL achieved a completion time comparable to the high-resolution baseline. Its FP rate was higher than the 0.100 m² baseline because it dynamically switched to larger pillar sizes at higher speeds to meet tighter deadlines, leading to increased FPs during those instances.

#### 4.2.2. Dynamic Hazard Environment (High-speed Reactive Scenarios)

- **Collision Rates:** The high-resolution baseline (0.100 m²) failed to avoid 16 out of 30 hazards due to high average detection latency (247.8 ms). The intermediate resolution (0.128 m²) reduced collisions to 11/30 (average latency 172.2 ms). Only the low-resolution baseline (0.200 m²) and MURAL avoided all 30 collisions.
- **MURAL's Adaptability:** MURAL avoided all collisions with an average latency (174.4 ms) comparable to the 0.128 m² baseline. This demonstrated MURAL's ability to dynamically reduce latency (by choosing larger pillar sizes) during high-speed scenarios when deadlines are tightest, enabling timely hazard detection.

#### 4.2.3. Discussion of Closed-loop Simulation Results

- The closed-loop results underscore that no single fixed resolution is optimal for all driving conditions. High resolution is crucial in complex urban scenes to minimize FPs and avoid unnecessary stalls, while low latency is critical at high speeds for hazard avoidance. MURAL's dynamic adaptation of input resolution provided the necessary versatility for both efficient navigation in dense urban environments and safe collision avoidance in high-speed dynamic scenarios, outperforming fixed-resolution baselines which cannot adapt.

### 5. Significance and Potential Impact

This research presents MURAL, a multi-resolution anytime framework for LiDAR 3D object detection, which contributes to the field of real-time autonomous systems in several significant ways:

1. **Novelty in LiDAR Anytime Computing:** MURAL is positioned as the first work to enable runtime resolution scaling for LiDAR-based object detection DNNs within a single, deployable model. This addresses a recognized gap in the literature, where prior anytime approaches for LiDAR were either limited in their applicability to high-accuracy models or introduced accuracy compromises under tight deadlines.
2. **General Applicability Across Architectures:** The framework's demonstrated effectiveness across both pillar-based (Pillarnet, PointPillars) and voxel-based (CenterPoint) architectures highlights its generalizability, suggesting its potential integration into a range of existing and future LiDAR detection models.
3. **Superior Accuracy-Latency Trade-offs:** Through comprehensive open-loop evaluations, MURAL consistently achieved higher detection accuracy across various deadlines compared to both fixed-resolution baseline models and the prior state-of-the-art anytime LiDAR approach (VALO). This indicates a more effective mechanism for managing the accuracy-latency spectrum.
4. **Memory-Efficient Deployment:** By employing resolution-aware batch normalization and a shared weight architecture, MURAL avoids the linear memory overhead associated with deploying multiple distinct models for different resolutions. This memory efficiency is critical for resource-constrained embedded platforms commonly found in autonomous vehicles.
5. **Enhanced Operational Safety and Efficiency:** The closed-loop simulation experiments demonstrate MURAL's practical benefits in an autonomous driving context. It enabled collision-free navigation in high-speed dynamic hazard environments by prioritizing low latency when necessary, while simultaneously avoiding unnecessary stalls in dense urban environments by allowing for higher accuracy through finer resolutions at lower speeds. This adaptability directly translates to improved safety and operational efficiency in varied driving conditions.
6. **Robust Scheduling with Accurate Prediction:** The methodology for predicting sparse CNN execution times, particularly the max-pooling emulation for pillar-based models, represents an advancement in managing the unpredictability of LiDAR data processing, leading to more reliable deadline adherence.
7. **Open-Source Contribution:** The open-source release of MURAL (https://github.com/CSL-KU/MURAL) facilitates further research and development in this area, allowing other researchers and developers to build upon and extend its capabilities.

In summary, MURAL provides a practical and effective solution for enabling adaptive, high-performance LiDAR object detection on embedded systems. Its ability to dynamically adjust to changing operational demands by optimizing the accuracy-latency trade-off without incurring significant memory overhead has the potential to enhance the reliability, safety, and efficiency of autonomous driving systems.
