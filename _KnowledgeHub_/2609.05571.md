# Grounded Skill Synthesis from Code at Scale for Agentic Intelligence

> [!summary] Summary
> Code2Skill is an automated pipeline that mines popular GitHub repositories, ranks procedural source units, and lifts them into typed skill records (atomic operation, composite workflow, recurring pattern) carrying applicability, steps, invariants, failures and provenance. Records are verified by source-body-blind reconstruction plus a source-aware judge. The resulting CodeSkillBank holds 1,006,822 accepted records and lifts agent scores 11.7% on average.

## Problem

- Trajectory-based skill synthesis stays coupled to the generating agent's model, task distribution, tools and harness, so quality is capped by that agent's own competence and experience.
- Document-sourced skill synthesis avoids agent traces but has no concrete execution to ground claims against, leaving synthesized procedures unverified and unsupported by evidence.
- Existing code-derived approaches serialize skills already written for agents or summarize implementations, without reuse ranking, typed records, provenance, or verification that a skill is supported by its source.

## Method

- ==Candidate selection== parses functions, methods, command-line entry points and file-level components across 19,769 repositories with over 500 stars, using a ranking score plus an ==LLM tagger== to pick reusable units.
- ==Typed skill-record extraction== at three granularities, **atomic operation**, **composite workflow** and **recurring pattern**, each recording when-to-use, control rule, workflow, invariants, failures, anti-goals and source-span provenance.
- **Source-body-blind reconstruction** regenerates code from the record alone; a ==source-aware judge== compares it to the original and an adjudicator separates unsupported records from reconstruction failures, then ==feature tagging== and ==purpose indexing== build retrieval views.

## Results

- Across **72** protocol-matched runs spanning nine model settings and eight benchmarks, skills raise the macro-average from **42.90** to **47.90**, an **11.7%** relative gain, winning **57** cases; all nine SWE-bench Verified pairs improve.
- Under a shared agent loop Code2Skill averages **49.5** versus **31.0** for Trace2Skill, **27.9** for ExpeL and **32.8** for SkillRL-Bank, beating the strongest baseline by **6.6** to **13.3** points per benchmark.
- In coding RL, post-generation review reaches **38%** resolve rate versus **24%** without skills; banks built from AI-generated code score **93.50%** on LiveCodeBench against **93.00%** for human code, and annotators judge **92%** of descriptions accurate.

## Takeaways

> [!tip] Key Insights
> - Where retrieved knowledge enters the loop matters more than how much: reviewing a concrete draft beats prompting first-pass generation, which must operationalize guidance blindly.
> - Compact summaries retain nearly all utility after removing about nine tenths of retrieved text, so the bare procedure, not surrounding implementation detail, carries the value.
> - Reconstruction-from-abstraction is a cheap scalable grounding test when no test suite exists, though it checks support by source, not behavioral correctness.

## Detailed Report

### 1. Overview

When an agent faces a multi-step coding or terminal task it has never attempted, it has no personal trajectory to consult. Code2Skill addresses this by reading a procedure directly from maintained software, turning it into a bounded operational record, and then testing that record: a reconstructor works without seeing the source body, and a source-aware judge compares the result with the original before the record is accepted. A bank built from 19,769 GitHub repositories raised the eight-benchmark unweighted macro-average from 42.90 without skills to 47.90 with retrieved CodeSkillBank skills—a 5.00-point absolute gain—with 57 of 72 protocol-matched evaluations improving.

Code2Skill pipeline: GitHub repositories enter AST parsing and ranking; top-k candidates become typed skill cards; a blind reconstructor regenerates code without seeing the source body; a source-aware judge accepts or rejects; accepted records enter the evidence archive. The bank reached 1,006,822 accepted skills from the 19,769 repositories processed.

### 2. From code to a checked procedure

The pipeline selects candidate functions, methods, command-line entry points, and file-level components, then excludes unsafe files, tests, binaries, very short units, trivial wrappers, and project-local boilerplate. An LLM tagger scores each candidate on reusable intent, ordered steps, boundary conditions, interface sufficiency, and non-triviality. Selected units become one of three record types: atomic skills for one meaningful operation, composite skills for ordered multi-operation workflows, or recurring-pattern skills for higher-level implementations across a localized operation or workflow.

The AdGuard DNS-over-QUIC case illustrates what a composite skill captures. A resolver reuses a QUIC connection, but a cached connection can fail after a restart, idle close, stateless reset, NAT breakage, or 0-RTT rejection. The extracted rule is not simply "retry on error": retry only a failed cached connection, close it before reacquiring, retry once, and clear the QUIC token store only for `Err0RTTRejected`; do not retry a freshly opened connection or create an unbounded loop. That conditioned boundary—not a code summary—distinguishes the accepted record.

The consistency check hides the source body, repository, and path from a reconstructor while leaving the skill description, interface, language, and relevant context visible. A source-aware judge then compares observable behavior, side effects, return semantics, and error handling with the original. When the comparison fails, adjudication decides whether the skill is wrong or the generated code failed; an adjudicated accept keeps the skill but discards the failed artifact. This is an LLM consistency filter, not formal program equivalence or execution-based verification. ([GitHub repository](https://github.com/ant-intl/Code2Skill))

### 3. Does the bank transfer?

The same bank and retrieval index were used across model families, reasoning modes, and benchmarks; the default retrieval pool was a random 10% sample for computational efficiency. As one representative setting, GPT 5.2 with reasoning mode "No" rises from 43.15 without CodeSkill to 49.16 with it; within that setting, SWE-bench Verified rises from 62.20 to 67.91 and TerminalBench from 42.48 to 51.32. The full pattern across all settings is 57 improvements in 72 protocol-matched evaluations, with some BigCodeBench, LongCLI, and AgentBench-OS conditions flat or worse.

The decisive comparison uses a shared DS4-Flash loop, five runs, and held-out construction splits. [Trace2Skill](https://www.alphaxiv.org/abs/2603.25158) distills trajectory patches, [ExpeL](https://www.alphaxiv.org/abs/2308.10144) stores experience-derived insights and examples, and SkillRL-Bank distills policy rollouts; under the common loop, Code2Skill averages 49.5 against 31.0 for Trace2Skill, 27.9 for ExpeL, and 32.8 for SkillRL-Bank. Code2Skill also exceeds the best-per-benchmark trajectory baseline oracle at 40.1 by 9.5 points. The compared banks differ in construction, scale, and engineering, so the result supports an end-to-end advantage for this repository-derived bank rather than isolating the code substrate alone.

### 4. Where the skill enters matters

Planning-time retrieval improved all eight DS4-Flash and Qwen3.5 benchmark pairs tested—gains of +10.0, +3.4, +14.5, and +3.1 percentage points for DS4-Flash on AIME, HMMT, Terminal, and SWE respectively, and +3.3, +6.7, +3.3, and +2.0 for Qwen3.5. First-pass prompting was less consistent: DS4-Flash gained on all four benchmarks, but Qwen3.5's TerminalBench score fell by 5.6 percentage points and other changes were near zero.

Planning-time insertion: blue bars show the no-skill baseline and orange bars show +CodeSkill for DS4-Flash (left) and Qwen3.5 (right) across AIME, HMMT, Terminal, and SWE. All eight comparisons improve.

On BigCodeBench Instruct-Hard at $k=3$, summary rendering reduced visible skill text from 6,352 to 707 average characters—88.9% less—while preserving Qwen's full-record score and improving DS4-Flash from 28.40 to 31.80. This is a context-length result, not evidence of fewer generated tokens or lower elapsed computation.

### 5. A pre-experience memory

Source code lets an agent inherit tested procedural structure—with its conditions, failure boundaries, and provenance—before it has accumulated its own trajectories, and the reconstruction challenge keeps the inherited rule inspectable. The 57-of-72 improvement record shows where that inheritance is broad and where gains remain uneven.
