# AutoHarness: improving LLM agents by automatically synthesizing a code harness

> [!summary] Summary
> AutoHarness has a small LLM (Gemini-2.5-Flash) write its own code harness around itself. A tree search with Thompson sampling refines the code using environment feedback. The learned harness rejects illegal actions across 145 TextArena games. With it, Flash beats the larger Gemini-2.5-Pro. In the extreme case the whole policy is code, needs no LLM calls at test time, and beats GPT-5.2-High on 1-player games.

## Problem

- LLM agents often propose actions the environment strictly prohibits; in Kaggle GameArena chess, 78% of Gemini-2.5-Flash losses came from illegal moves rather than strategic blunders.
- Fine-tuning on game trajectories is slow and costly at flagship scale, and can degrade unrelated abilities such as instruction following.
- Hand-written harnesses that check move validity are brittle and labor-intensive, and each new game or environment needs fresh manual engineering.

## Method

- ==Code-as-harness search==: candidate programs form a tree, and ==Thompson sampling== picks which node to refine next. Node value is the ==legal-move success rate==, and the LLM acts as the ==mutation operator==.
- A ==Critic== consolidates up to 5 failed steps from 10 parallel rollouts. The ==Refiner== then rewrites is_legal_action and propose_action, changing only propose_action when the verifier correctly rejected a move.
- Three harness forms: ==action-filter==, ==action-verifier== (the main focus, which re-prompts on illegal moves), and ==harness-as-policy==. The last is pure Python with no LLM at test time, trained on ==reward-augmented heuristic== H = 0.5 + 0.5r.

## Results

- Learned verifiers reached a **100%** legal-action rate on all **145** TextArena games. Training took **14.5** tree-search iterations on average, and **19 of 32** evaluated games needed fewer than **10**.
- Flash+Harness beat Gemini-2.5-Pro in 2-player games with a **56.3%** vs **38.2%** win rate, winning **9 of 16** games. It won **64.8%** against vanilla Flash. In 1-player games it averaged **0.745** reward vs **0.707** for Pro and **0.673** for Flash.
- Harness-as-policy averaged **0.870** reward on 16 1-player games, above GPT-5.2-High at **0.844**, Gemini-2.5-Pro at **0.707** and GPT-5.2 at **0.635**. It cost near zero at test time, while GPT-5.2 runs cost about **$640**.

## Takeaways

> [!tip] Key Insights
> - Move rule-checking out of the LLM's implicit world model into an executable, verifiable program. Small models can then match or beat much larger ones with rejection sampling.
> - Environment feedback plus search over code gives a cheap, scalable route to reliability, avoiding fine-tuning and hand engineering. The harness template can range from a thin verifier to a full code policy.
> - Caveats: harnesses are learned per game, and harness-as-policy is only shown for 1-player games. The authors propose distilling harnesses back into the base model and building reusable harness libraries.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

This research directly addresses a critical and widely recognized challenge in the burgeoning field of LLM agents: their brittleness and inability to consistently adhere to environmental rules. While LLMs have demonstrated remarkable capabilities in complex reasoning, strategic planning, and code generation, their application as autonomous agents often falters due to a tendency to propose "illegal" or invalid actions, even when their higher-level strategic understanding is sound. This disconnect, highlighted by previous work (e.g., Valmeekam et al., 2023a; Petrov et al., 2025), represents a significant barrier to the widespread deployment of reliable LLM agents.

Traditional approaches to mitigate this issue typically involve fine-tuning LLMs on specific game trajectories or manually crafting "harnesses" – external code modules that validate and filter LLM outputs. However, the authors correctly point out the limitations of these methods: fine-tuning is computationally expensive, time-consuming for large models, and can lead to performance degradation on other tasks, while manual harnesses are labor-intensive, brittle, and not scalable across diverse environments.

"AutoHarness" positions itself as a scalable and automated alternative by leveraging the LLM's own powerful code-generation capabilities (Chervonyi et al., 2025; Huang & Yang, 2025). Instead of external human intervention or costly fine-tuning, the LLM is tasked with generating the very code that enforces environmental constraints. This approach effectively externalizes the "action applicability problem" (Kokel et al., 2025) – the challenge of knowing which actions are valid in a given state – from the LLM's internal, potentially unreliable world model to a verifiable external program.

The paper builds upon several established lines of research:
- **LLMs for Game Playing and Reasoning:** Prior work has explored LLMs in various game environments, utilizing techniques like "chain-of-thought" (Wei et al., 2022) and "tree of thoughts" (Yao et al., 2023) to enhance strategic planning. However, these often rely on the LLM's internal simulation, which is prone to "hallucination" regarding valid state transitions. AutoHarness diverges by offloading this critical validity check to an external, verifiable program.
- **Code as Policy:** The concept of using LLMs to generate executable code for agent control has gained traction, exemplified by works like Voyager (Wang et al., 2023) for Minecraft and Eureka (Ma et al., 2024) for reward function design, and more directly, "Code as Policies" (Liang et al., 2023) for robotics. AutoHarness extends this by focusing on the iterative refinement of a *hybrid* code+LLM harness, emphasizing the "glue" aspect rather than the entire policy initially.
- **Iterative Refinement and Search for Code Generation:** The methodology incorporates principles from iterative code refinement and search algorithms, drawing parallels to Reflexion (Shinn et al., 2023) which uses verbal reinforcement, AlphaCode (Li et al., 2022) for large-scale sampling, and AlphaEvolve (Novikov et al., 2025) for evolutionary code search. Crucially, AutoHarness adapts these concepts into a structured tree search guided by Thompson sampling (Tang et al., 2024), applied in an online, multi-turn setup specifically for generating robust code harnesses.

In essence, AutoHarness synthesizes these disparate but related areas into a novel framework that enhances LLM agents' robustness, reliability, and efficiency by making them self-sufficient in addressing their own rule-following deficiencies.

### 2. Key Objectives and Motivation

The primary motivation behind AutoHarness stems from a fundamental observed flaw in current LLM agents: their frequent failure to adhere to the explicit rules of an environment, even when demonstrating sophisticated strategic understanding. The paper highlights this issue with a compelling example: in the recent Kaggle GameArena chess competition, 78% of Gemini-2.5-Flash losses were attributable not to strategic blunders but to simple illegal moves. This "disconnect" between reasoning capability and action validity leads to inefficient, costly, and unreliable agent behavior.

Against this backdrop, the key objectives of the research are multifaceted:

1. **Eliminate Illegal Actions:** The most immediate and crucial objective is to develop a method that prevents LLM agents from attempting strictly prohibited actions. This involves automatically synthesizing a "code harness" that can verify the legality of a proposed action against the environment's rules.
2. **Enhance Performance of Smaller LLMs:** The authors aim to demonstrate that by augmenting a smaller, more cost-effective LLM (e.g., Gemini-2.5-Flash) with an automatically generated code harness, its overall performance in rule-based tasks can surpass that of larger, more computationally expensive models (e.g., Gemini-2.5-Pro) that lack such external validation. This objective directly addresses the economic and efficiency considerations of deploying advanced AI.
3. **Automate Harness Synthesis:** To overcome the limitations of manual harness creation—which is labor-intensive and not scalable across diverse games or environments—a core objective is to leverage the LLM's own code generation capabilities to automatically synthesize these harnesses. This aims for a more generalizable and less brittle solution.
4. **Explore Code-as-Policy:** Pushing the technique to its logical extreme, an ambitious objective is to investigate whether an LLM can generate the *entire policy* (action selection mechanism) directly in code. This would eliminate the need to invoke the LLM for decision-making at inference time, leading to near-zero test-time costs and significantly faster execution.
5. **Develop a Robust and Scalable Learning Framework:** To achieve the above objectives, the paper aims to develop an iterative code refinement process guided by environmental feedback and an efficient search algorithm, making the synthesis process robust and applicable to a wide array of games.

In essence, the motivation is to transform LLM agents from sophisticated but often unreliable reasoners into robust and efficient performers by enabling them to "self-correct" their actions through automatically generated, verifiable code.

### 3. Methodology and Approach

The core methodology of AutoHarness is centered around "code as harness," a framework where an LLM leverages its code-generation capabilities to autonomously create the auxiliary code necessary to make itself a more reliable agent. The process is formulated as a search problem over the space of programs, driven by iterative refinement and environmental feedback.

**Harness Types:** The paper explores three main types of code harnesses:
- **Harness-as-Action-Verifier (Primary Focus):** This is the main type investigated. The LLM first proposes an action. This action is then passed to a `is_legal_action()` function (generated by the LLM) for verification. If the action is found to be invalid, the LLM is re-prompted with explicit feedback about the illegal move, prompting it to propose a different action. This acts as a rejection sampler.
- **Harness-as-Action-Filter:** In this variant, the LLM generates a *set* of potentially legal moves. The harness would then use the LLM (possibly with further reasoning like chain-of-thought) to rank these legal moves and select the best one. This type is mentioned but less explored experimentally.
- **Harness-as-Policy:** This represents the most extreme case where the entire game-playing policy is encapsulated in generated code. The `propose_action()` function, once fully synthesized, makes decisions using only primitive Python functions and standard libraries (like `numpy`), entirely bypassing the need for LLM calls during inference.

**Code-as-Harness Learning Process:**
The learning process for synthesizing these harnesses is an iterative refinement loop (Figure 1):
1. **Initialization:** The process starts with a basic or template code structure for the `propose_action()` and `is_legal_action()` functions.
2. **Rollout and Execution:** The current code harness is used to interact with a set of parallel environments (10 in their experiments). During rollouts, if the generated action is illegal or code execution fails, the rollout is terminated.
3. **Critic Feedback:** Up to 5 failed steps, along with their error messages, are sampled and fed to a "Critic" module. The Critic consolidates various types of errors (e.g., syntax errors, runtime exceptions, illegal moves flagged by the environment).
4. **Refiner (LLM as Mutation Operator):** The error messages, consolidated feedback, and the current code are sent to a "Refiner" module, which is itself an LLM (Gemini-2.5-Flash in this work). The Refiner is prompted to analyze the failures and propose refinements to the code. The prompt structure (Appendix B.2) encourages step-by-step reasoning and focuses on fixing critical failure steps while improving overall game progress.
5. **Tree Search and Thompson Sampling:** To efficiently explore the space of possible code refinements, the methodology employs a tree search algorithm guided by Thompson sampling (inspired by Tang et al., 2024). This mechanism maintains multiple code hypotheses in a tree structure. Each node in the tree represents a code variant and has a heuristic value (average legal move accuracy). Thompson sampling helps balance exploration (trying new, distinct logic structures) and exploitation (refining partially working harnesses that show promise), selecting which node (code variant) to refine next.
6. **Termination:** The iterative process continues until the heuristic value (legal action success rate) reaches 1.0 (indicating 100% legal moves) or a timeout is reached.

**Experimental Setup:**
- **Game Environment:** The experiments were conducted on 145 1-player (1P) and 2-player (2P) games from **TextArena** (Guertler et al., 2025), a diverse collection of text-based games. Free-form text/dialog games were excluded.
- **Enhanced Challenge:** To make the problem more difficult and representative of real-world scenarios, the "Available Moves" hints were manually removed from game observations (Appendix A.4). This forced the generated harness to deduce legal actions from environmental feedback rather than simply parsing them.
- **LLMs Used:** Gemini-2.5-Flash was used for training the harnesses. For evaluation, agents included vanilla Gemini-2.5-Flash, Gemini-2.5-Pro, Gemini-2.5-Flash+Harness (ours), and for the harness-as-policy evaluation, GPT-5.2 and GPT-5.2-High.
- **Evaluation Metrics:**
 - **Harness Training:** Legal action success rate (aiming for 100%).
 - **Agent Performance (1P games):** Average reward over 20 matches.
 - **Agent Performance (2P games):** Win/draw/loss rates over 40 matches, with balanced first/second player starts.
- **Harness-as-Policy Specifics:** For this variant, the heuristic value for Thompson sampling was modified to incorporate the environment reward (`H = 0` for illegal actions, `H = 0.5 + 0.5r` for legal actions, where `r` is the sparse environment reward). Training was capped at 256 iterations.

This systematic approach, combining LLM code generation with iterative refinement and an efficient search strategy, allows the system to automatically learn robust, game-specific logic for action validation and, in some cases, the entire game policy.

### 4. Main Findings and Results

The experiments demonstrate significant improvements in LLM agent performance and reliability through the automatic synthesis of code harnesses.

**Harness Synthesis Success:**
- **100% Legal Action Rate:** AutoHarness, using Gemini-2.5-Flash as the refiner, successfully synthesized code harnesses that achieved a **100% legal action success rate across all 145 selected TextArena games**. This is a critical finding, showcasing the robustness and effectiveness of the iterative refinement process.
- **Efficiency of Synthesis:** On average, the training process for a harness concluded in 14.5 tree search iterations, with 19 out of 32 key games requiring fewer than 10 iterations. More complex games like GermanWhist-v0, Cryptarithm-v0, Othello-v0, and Chess-v0 required more iterations, but all eventually converged to a perfect legal action rate.

**Improved Agent Performance with Harness-as-Action-Verifier:**
The integration of the synthesized harnesses dramatically boosted the performance of the smaller Gemini-2.5-Flash model:
- **Two-Player (2P) Games (16 games evaluated):**
 - **Against Gemini-2.5-Pro:** Gemini-2.5-Flash+Harness (ours) achieved an overall win rate of **56.3%** by winning 9 out of 16 games, significantly outperforming Gemini-2.5-Pro, which had an overall win rate of 38.2%.
 - **Against Vanilla Gemini-2.5-Flash:** Our method further improved, winning 12 out of 16 games with an overall win rate of **64.8%**.
 This clearly demonstrates that a smaller, less powerful LLM, when augmented with a precisely tailored code harness, can surpass a much larger model in competitive game environments.
- **One-Player (1P) Games (16 games evaluated):**
 - Gemini-2.5-Flash+Harness achieved a higher average reward than Gemini-2.5-Pro in 8 out of 16 games and tied in 5 games.
 - The average reward for our method was **0.745**, compared to 0.707 for Gemini-2.5-Pro and 0.673 for vanilla Gemini-2.5-Flash. This indicates a consistent performance uplift even in non-adversarial settings where strategic optimization is key.

**Harness-as-Policy Performance:**
Pushing the approach to generate the entire policy in code yielded even more impressive results for 1P games:
- **Highest Average Reward:** The Harness-as-Policy agent achieved the highest average reward of **0.870** across 16 1P games. This significantly outperformed all other evaluated agents:
 - GPT-5.2: 0.635
 - Gemini-2.5-Pro: 0.707
 - Gemini-2.5-Flash+Harness (our action verifier): 0.745
 - GPT-5.2-High (high thinking): 0.844
- **Cost-Effectiveness:** A standout result is the **"nearly zero" test-time cost** for the Harness-as-Policy agent, as no LLM calls are needed during inference. This starkly contrasts with the approximate $640 cost for the GPT-5.2 and GPT-5.2-High experiments, highlighting a massive practical advantage for deployment.
- **Code Quality:** The appendix provides example code snippets (e.g., for Minesweeper-v0 and Chess-v0), illustrating that the generated harnesses are sophisticated Python code, capable of complex logic such as probabilistic heuristics and game-specific move validation.

These findings collectively confirm that AutoHarness successfully addresses the problem of LLM agent unreliability, not only preventing illegal moves but also enabling smaller models to outperform larger, more expensive counterparts, especially when the entire policy can be compiled into code.

### 5. Significance and Potential Impact

The AutoHarness research presents a highly significant advancement in the field of LLM agents, with substantial potential impact across various domains.

**1. Enhanced LLM Agent Reliability and Trustworthiness:**
The most immediate and profound impact is the ability to automatically confer perfect rule adherence upon LLM agents. By preventing strictly prohibited actions, AutoHarness addresses a fundamental barrier to deploying LLMs in critical applications where safety, legality, and correctness are paramount. This dramatically increases the trustworthiness and practical utility of LLM agents, moving them from prone-to-error experimental systems to robust, deployable solutions.

**2. Increased Efficiency and Cost-Effectiveness:**
The finding that a smaller, less powerful LLM (Gemini-2.5-Flash) can outperform larger models (Gemini-2.5-Pro, GPT-5.2-High) when augmented with a custom code harness is economically groundbreaking. Smaller models are cheaper to run, have lower latency, and require less computational overhead. Furthermore, the "harness-as-policy" approach, which eliminates LLM calls at inference time, offers near-zero operational costs, making it incredibly attractive for large-scale, real-time deployments. This could democratize access to advanced AI capabilities by making them more resource-efficient.

**3. Scalability and Generalizability of Agent Design:**
The successful synthesis of harnesses for 145 diverse TextArena games demonstrates the scalability of the AutoHarness framework. Unlike brittle manual coding or game-specific fine-tuning, this automated approach can be applied across a broad spectrum of rule-based environments, significantly reducing the development effort for new LLM agents. This paves the way for a more generalized approach to agent design, where the agent itself becomes responsible for defining its operational constraints.

**4. A New Paradigm for LLM Agent Architectures:**
AutoHarness proposes a paradigm shift in how LLM agents are constructed. Instead of solely relying on an LLM's internal "world model" or reasoning to infer action applicability (which can hallucinate), it advocates for a hybrid architecture where the LLM leverages its code-generation prowess to build verifiable, externalized logic. This separation of concerns—LLM for strategic reasoning and generated code for rule enforcement—leads to more robust, auditable, and interpretable agents.

**5. Foundations for Recursive Self-Improvement:**
The paper hints at exciting future work, including distilling the learned domain-specific harnesses back into the base LLM for recursive self-improvement. This vision suggests a path toward truly autonomous AI systems that can continuously learn, adapt, and refine their own operational logic, rather than being statically programmed.

**6. Broader Applicability Beyond Games:**
While demonstrated in text games, the principles of AutoHarness are highly transferable. Any domain where LLM agents need to operate under strict rules or environmental constraints could benefit. This includes:
- **Robotics:** Ensuring robotic actions adhere to physical limitations or safety protocols.
- **Software Engineering:** Automating code fixes or generating compliant code.
- **Scientific Experimentation:** Designing experiments that follow strict scientific methodology.
- **Legal or Financial Systems:** Ensuring compliance with complex regulations.
- **Healthcare:** Generating treatment plans that adhere to medical guidelines.

In conclusion, AutoHarness represents a significant leap forward in making LLM agents practical, reliable, and cost-effective. By enabling LLMs to automatically "engineer" their own guardrails, this research addresses a fundamental limitation and opens new avenues for scalable, robust, and ultimately more intelligent AI systems.
