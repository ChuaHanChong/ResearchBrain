# SkillWeaver: Agentic Exploration over Neural Interaction Skills for Scalable Robot Data Generation

> [!summary] Summary
> SkillWeaver is an agentic robot data engine. A VLM agent composes Neural Interaction Skills, which are reusable RL-trained closed-loop PICK, PLACE, OPEN and CLOSE policies, using verifier-guided Monte Carlo tree search with reflection and semantic memory in IsaacLab. It generates 39.1K verified demonstrations across 14.1K scenes. Distilled into Pi0.5, this data sharply improves LIBERO-PRO OOD generalization and enables zero-shot sim-to-sim and sim-to-real transfer.

## Problem

- Teleoperated robot demonstrations are expensive and labor-intensive, so they struggle to cover the long tail of objects, scene configurations and long-horizon behaviors needed for broad generalization.
- Simulation pipelines such as MimicGen, InternData-A1 and MolmoBot still generate behavior from source demonstrations, scripted skill sequences, open-loop grasp proposals or engineered motion-planning programs.
- Program-based robot agents like Code as Policies expose capabilities through code and APIs, which suit contact-rich interaction poorly because it needs continuous closed-loop adaptation to physical state.

## Method

- ==Neural Interaction Skills==: ==PPO==-trained PICK, PLACE, OPEN and CLOSE policies with specialized sub-policies, invoked as parameterized tools after a motion planner reaches a local pre-interaction pose.
- ==Verifier-guided MCTS== over skill invocations: a hierarchical subgoal-plus-progress VLM verifier, given privileged simulator state, scores each expansion and writes natural-language reflections in place of costly rollouts.
- ==Experience memory== distills finished searches into reusable strategies and failure rules, retrieved top-K per subgoal. ==Semantic axis alignment== computes target orientations analytically from annotated canonical object axes.

## Results

- Adding SkillWeaver data lifts Pi0.5 on the LIBERO-PRO Object-suite Position shift from **0.0%** to **77.0%**. Trained only on generated data, it reaches **77.1%** zero-shot on SIMPLER-WidowX.
- The learned PICK skill succeeds **97.4%** on **170** unseen assets versus **65.1%** for GraspGen plus motion planning. Privileged state lifts verifier accuracy from **78.8%** to **99.5%**.
- On a real Franka with no teleoperation, large-scale sim pretraining raises average success from **30.8%** to **62.5%**, and from **1.3%** to **57.2%** with swapped objects.

## Takeaways

> [!tip] Key Insights
> - Giving an agent learned closed-loop policies as tools, instead of code or APIs, lets VLM reasoning choose what to do while RL handles contact-rich execution.
> - Privileged simulator state makes verification nearly perfect during data generation, so oracle signals can supervise search even though deployed policies see only sensory observations.
> - Generated data helps most under position and task shifts but slightly hurts language-object combinations, so benchmark gains should be read against exploitable dataset correlations.

## Detailed Report

### 1. Overview

Generating robot demonstrations is the practical bottleneck. Teleoperation is labor-intensive, and scripted simulation pipelines are difficult to extend to behaviors that require choosing a next step or recovering from a failed one.

Take the task "put the toothbrush into the cup" when the cup is lying on its side. A direct insertion cannot work. SkillWeaver gives an agent learned manipulation behaviors it can call. The agent sees the result of each one and can change course. Here it must discover an unstated prerequisite before placing the toothbrush: stand the cup upright. The authors' framing is to turn simulation into a place where an agent actively searches for its own training experience.

"Place the toothbrush into the mug" (4 skills). The mug starts lying down and must be stood upright before insertion.

### 2. Searching with physical tools

The agent does not generate low-level robot commands or follow a fixed task script. It works with **Neural Interaction Skills (NIS)**, which are reusable, parameterized, learned closed-loop policies. The agent specifies the interaction and the target, and the policy adapts the low-level motion as contact and physical state change. SkillWeaver uses reinforcement-learned PICK, PLACE, OPEN, and CLOSE policies for contact-rich interactions. A motion planner handles free-space motion.

The agent chooses a skill, a target object or part, and parameters. Calling the skill changes the simulated world, and the agent observes the result. **Monte Carlo Tree Search (MCTS)** lets it explore and prioritize alternative action branches rather than commit to one predicted sequence.

A hierarchical verifier judges two things: whether a skill achieved its local subgoal, and whether the task is progressing. It supplies scores and natural-language feedback for replanning. A memory module retrieves strategies, failure explanations, or verification rules learned from earlier searches. On the toothbrush task, the authors describe a four-skill solution: pick up the lying cup, place it upright, pick up the toothbrush, place it in the cup. On this tested task, their memory ablation reports search success rising from 0% without memory to 80% with memory.

Overview of SkillWeaver: the agent selects and parameterizes a skill, executes it in simulation, verifies the outcome, and searches again. Failures are summarized into memory, and successful trajectories become training data.

A skeptical reader may wonder whether branching search itself helps. The paper tests this by comparing MCTS with linear skill sequencing on five long-horizon tasks, using the same agent and NIS library under the same simulation budget. MCTS reduced expansions per successful trajectory from 6.74 to 3.60. It also reduced elapsed time per successful trajectory from 891 seconds to 645 seconds.

The reported dataset contains 39.1K verified demonstrations, 14.1K scenes, and 11.0M frames.

### 3. From simulated scenes to a real robot

The real-robot test uses two training stages, and both use only simulation-generated demonstrations. Large-scale training (LST) generates broad experience in varied scenes. Post-training (PT) adds task-specific experience in a reconstructed simulation of the target real-world environment. The resulting Pi0.5 policy is deployed zero-shot on a real Franka Panda, with no real-world demonstrations used for training.

Across 12 pick-and-place tasks with 50 trials each, adding LST to PT raised average success in three settings:

- from 30.8% to 62.5% in the original setup
- from 1.3% to 57.2% when object positions were swapped
- from 16.2% to 41.7% when the background changed

The authors interpret this as broad simulation experience reducing dependence on a particular object arrangement. The comparison supports improvement under these tested conditions, not universal robustness. Individual tasks remain difficult, especially spatially specified placement.

### 4. The robot can make its own practice

SkillWeaver lets an agent test learned interaction tools, receive physical feedback, and retain successful traces as training experience. The paper's evidence supports this as a route to scaling behavior discovery in simulation. That route is bounded by the fidelity of the simulator and the available skill library. The current library is limited to PICK, PLACE, OPEN, and CLOSE, and the space of behaviors the agent can discover is bounded by its tool library.
