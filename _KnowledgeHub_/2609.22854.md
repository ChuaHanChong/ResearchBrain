# SmoLSTM: A Compact Vision-Language-Action Model with Recurrent Memory that Persists

> [!summary] Summary
> SmoLSTM is a compact vision-language-action policy that keeps a whole episode in a fixed-size recurrent state instead of a growing observation window. A frozen 256M SmolVLM plus modality encoders feed 217 tokens and 10 action queries into one never-reset mLSTM stream, and a rectified-flow head emits 10-step action chunks. With 40.4M trainable parameters it reaches 85.1% subgoal coverage and 77.5% full-task success on LIBERO-Mem.

## Problem

- Policies conditioned only on the current observation cannot separate histories that look identical yet demand different next actions, such as occlusion or duplicate-object tasks.
- Widening the observation window makes the history length a hyperparameter and lets per-step compute and storage grow with elapsed episode time.
- Prior memory designs bridge a slow memory module to a fast per-chunk decoder that resets each chunk, so the decoder does no memory work and the bridge carries everything.

## Method

- A single 6-block ==mLSTM stream== interleaves 217 observation tokens with 10 learned action queries and is never reset within an episode, giving ==O(1) state storage== and per-step cost.
- A **rectified-flow action head** reads only the query hiddens, injecting the noisy chunk and flow time before ==chunk-local self-attention==, integrating 10 pose deltas in 8 ==Euler steps== without re-entering the trunk.
- Two **shortcut-blocking objectives**: observation dropout at 0.15 plus per-sensor dropout at 0.10, and auxiliary ==DINOv2 latent forecasting== 5 and 10 steps ahead weighted 0.5.

## Results

- On LIBERO-Mem the flow variant hits **85.1%** coverage and **77.5%** success with **0.04B** trainable parameters, beating 2AM by **8.8** coverage points and MemoryVAM's **42.5%** success.
- Resetting the recurrent state every control step collapses success to **7.0%** and coverage to **10.5%** with all sensors intact; longer reset intervals recover performance unevenly per task class.
- One jointly trained checkpoint reaches **79.6%** average success on standard LIBERO, **7.8** points above VLM-initialized flow baseline; removing the wrist camera drops success to **12%**.

## Takeaways

> [!tip] Key Insights
> - Unifying observation and action tokens in one unreset recurrent stream lets committed actions enter memory implicitly, removing the seam between a memory module and a per-chunk decoder.
> - Behaviour cloning alone lets a memory-capable policy stay Markovian; deliberately hiding observations forces the state to carry task-relevant semantics.
> - Mid-depth layers of a frozen language model can be a degenerate band; taps at both ends plus segment pooling and mean-centering preserve instruction detail.

## Detailed Report

### 1. Overview

SmoLSTM targets a practical problem in robot manipulation: the next move can depend on what happened earlier, even when the current image looks much like an earlier one. A robot asked to rotate three identical bowls must keep track of which bowl has moved. A policy that sees only the present scene can lose the history needed to choose correctly. SmoLSTM keeps a compact running record of the scene and its own prior decisions, and uses that record to select its next move.

These examples illustrate solved episodes. The image alone does not isolate memory use.

### 2. One stream carries the episode

The usual workaround is to feed the policy a longer and longer window of past observations. That approach makes the window length a design choice and increases per-step cost with the horizon. SmoLSTM instead carries episode history in a fixed-size recurrent state, which is the controller's running internal representation of earlier inputs.

The process works in four steps:

- A frozen vision-language backbone and other sensor encoders create the current observation tokens.
- Learned action queries join those tokens in the same causal mLSTM stream.
- The stream's fixed-size recurrent state persists throughout the episode.
- Query outputs condition a separate flow-matching head, which generates a continuous action chunk.

Because the policy's own action queries share the stream, the state available to the next decision has processed both earlier observations and previous action queries.

The efficiency claim is bounded. The recurrent state has fixed storage. The authors describe per-step computation as independent of elapsed episode length, unlike an attention decoder over an expanding history. At each control step, the action head generates a 10-step chunk using eight Euler integration steps. Those iterations run the 4.87M-parameter action head, not the recurrent trunk. This is not a measured wall-clock speedup.

### 3. What the tests establish

LIBERO-Mem is a 10-task manipulation benchmark. On it, the correct action can depend on object motion, sequence, relations, or occlusion. *Coverage* is mean subgoal completion, and success is full-task completion. Across 20 held-out initial configurations per task, SmoLSTM's flow variant reaches 85.1% coverage and 77.5% full-task success.

Its coverage is 8.8 percentage points above the 76.29% completion reported by [[2609.11308|2AM]], a closely comparable measure of subgoal progress. 2AM places task memory in an Agent that communicates remembered intent to an episodically stateless action model. Its full-task scores are 63% *relaxed* success and 11.83% strict success, so its 63% is not a strict-success comparison.

The decisive test is an intervention on the trained policy itself. With all sensor streams kept but the recurrent state reset every control step, success falls from 77.5% to 7.0% and coverage from 85.1% to 10.5%. This result shows that the trained policy depends strongly on recurrent context between decisions. It does not show how a separately trained memoryless policy would perform. Effects vary by task class. Object Relations success is only 8% even with the reference, while Object Occlusion success is 95% with no resets and 82% when reset every 30 control steps.

A second intervention qualifies the interpretation. Replacing the state at subgoal boundaries with one from another rollout of the same task yields 75.0% success when the donor shares the initial state and 70.0% when it does not. With no intervention, success is 77.5%. These substitutions occur at subgoal boundaries, unlike fixed-step resets, so the two effects are not directly matched.

### 4. Memory that carries

This compact recurrent state avoids replaying an expanding observation window, and the trained policy also relies on it across control decisions. The state interventions characterize this particular design. They do not establish an advantage over every memory mechanism.
