# T$^2$Mem: Learning Test-Time Memory for Robotics

> [!summary] Summary
> T²Mem adds a test-time-trained fast-weight memory inside a pretrained π0.5 VLA, so one policy learns to keep and use past observations without external reasoning models or memory labels. An observation-grounded interface writes vision-language features into fast weights through self-supervised updates, and alternating memory-policy training shapes that memory through action supervision. On 16 RoboMME tasks, average success rises from 17.93% to 56.83%.

## Problem

- Explicit memory modules such as memory banks, scene graphs and external VLM reasoners act as a bottleneck: information dropped before action prediction is lost, and what they store is not chosen by the decisions it must support.
- Recurrent memory methods often add auxiliary reconstruction of past observations, but reconstructing history is not the same as keeping the decision-relevant cues a manipulation policy actually needs.
- Earlier robot test-time-training work puts fast weights inside the action expert to scale visuomotor context, which lengthens history but does not selectively keep semantic task cues.

## Method

- **Observation-grounded memory interface**: ==16 learned query tokens== attend only to VLM vision-language features, produce query/key/value projections for fast-weight reads and writes, and merge readouts through a ==tanh channel-wise gate==.
- **Test-time fast-weight memory**: per-head ==MLPs== updated online by a self-supervised ==key-value reconstruction loss==, reading before writing, with an ==adaptive write scale== in [0.1, 1] that weakens updates aligned with stored memory.
- **Alternating memory-policy learning**: after memory-free adaptation of ==π0.5==, training alternates between learning memory with the policy frozen and learning the policy with memory frozen, both supervised by expert actions only.

## Results

- On 16 RoboMME tasks, average success reaches **56.83%** versus **17.93%** for memory-free π0.5, **42.38%** for MemER, and roughly **18-22%** for the TTT and RMT recurrent-memory baselines.
- On VideoUnmask and MoveCube, the VLM-side interface reaches **84%** and **71%** versus **30%** and **26%** for RoboTTT-style action-expert memory; joint non-alternating training scores **30%** and **28%**, close to the no-memory baseline.
- Turning off online writes cuts success by up to **82.67 points**; conflicting donor memory gives **1/300** successes versus **300/300** with correct memory; inference runs **3.0×** faster than FrameSamp+Modul and **69×** faster than MemER.

## Takeaways

> [!tip] Key Insights
> - Action supervision alone can teach a memory-free foundation policy what to remember; when memory formation is trained through downstream control, memory labels and reconstruction targets are unnecessary.
> - Memory should be written from semantic vision-language features, not action-expert representations; giving it access to action history invites shortcut extrapolation instead of genuine tracking of task state.
> - Keeping information is not the same as reasoning over it: implicit memory recalls stored bindings well but struggles with swap-tracking tasks, which stay limited by the base model's temporal reasoning.

## Detailed Report

### 1. Position in the Broader Research Landscape

Robotic manipulation policies are often trained to map the current camera image, robot state, and language instruction directly to an action. This approach is effective when all task-relevant information remains visible, but it is inadequate for tasks involving occlusion, repeated actions, demonstrations, or changes in object state. In such settings, the robot must use information observed earlier in an episode.

Existing approaches to robotic memory generally fall into several groups. Explicit memory systems store visual observations, keyframes, spatial maps, or language-level subgoals. Examples include scene-memory transformers, spatial mapping systems, and memory banks integrated with visual foundation models. These methods make historical information directly available but incur storage, retrieval, and attention costs. Their representations may also be separated from the action policy that ultimately uses them.

Recurrent policies provide another alternative by compressing the past into a persistent hidden state. Systems such as RoboFlamingo, ReMem-VLA, and recurrent memory transformers avoid storing the complete history, but their compressed states may preserve information that is not directly useful for future control. Auxiliary reconstruction objectives can encourage retention of past observations without ensuring that the memory supports the correct decision.

T²Mem is positioned at the intersection of vision-language-action (VLA) policies and test-time training (TTT). TTT methods adapt model parameters during inference using self-supervised objectives. In the fast-weight formulation used here, temporary parameters encode information from the current episode. Unlike conventional recurrent memory, the history is stored in the weights of a small adaptive network rather than in an explicit sequence buffer or a single recurrent vector.

The paper’s central argument is that robotic memory should be decision-relevant: it should retain information because that information will support later action selection. T²Mem therefore connects the memory mechanism directly to the VLA policy and trains it through action supervision, while using only observations for memory updates during deployment. This distinguishes it from methods that add an external memory or reasoning model after policy training.

### 2. Objectives and Motivation

The primary objective is to determine whether a pretrained, memory-free VLA policy can acquire useful memory for manipulation tasks using action demonstrations alone. The authors focus on three capabilities:

1. **Retention of hidden information.** For example, after observing which container hides a particular colored cube, the robot must select the correct container after the cube is no longer visible.
2. **Tracking of repeated events.** The robot may need to count how many times an action has occurred or determine when a repeated sequence is complete.
3. **Reproduction of demonstrated procedures.** The instruction may specify a goal but not the method, requiring the robot to remember how an action sequence was performed.

The motivation is both functional and architectural. A robot should not need to retain every frame, since most observations are irrelevant to later decisions. Conversely, a generic recurrent state or reconstruction-trained memory may fail to preserve the particular object identity, action order, or task state needed for control. The authors propose that action supervision can shape what the memory stores and how the policy interprets it.

A second objective is computational efficiency. Explicit approaches may require repeatedly processing many historical images or invoking an external vision-language model to summarize them. T²Mem instead stores a compact episode-specific state in fast weights and retrieves it through a learned interface. The stated design goals are therefore selective memory formation, integration within a single policy, avoidance of memory-specific labels, and reduced inference cost.

### 3. Methodology and Approach

#### 3.1. Overall Architecture

T²Mem is built on the pretrained π0.5 VLA architecture, consisting of a vision-language model (VLM) and an action expert (AE). The proposed memory pathway is placed between these components while preserving the original direct pathway from current visual-language features to the action expert.

The memory interface extracts semantic information from the VLM using 16 learned interface tokens. These tokens attend only to valid vision-language features and are prevented from directly attending to action, proprioceptive, or other interface tokens. This restriction is intended to force memory formation to depend on observations rather than exploiting an action-history shortcut.

The VLM and action expert each contain 18 transformer layers. Memory modules are allocated at all layers, although the paper states that 17 of these connections are effectively used because an interface update is consumed only by subsequent layers. The interface summarizes current vision-language features and uses the summary for both memory writing and retrieval.

#### 3.2. Fast-Weight Memory

At each selected observation, the interface generates queries, keys, and values. A query retrieves information from the current fast-weight state. Keys and values form an association that is written into the memory through a self-supervised objective:

\[
\mathcal{L}_{mem} = \|f_W(K_t)-V_t\|^2.
\]

The fast weights are updated by gradient descent on this objective. Reads occur before writes, meaning that an observation affects subsequent decisions rather than the action predicted from that same observation.

The slow parameters—including the policy, interface, memory projections, fusion gates, and initial fast weights—are learned across training episodes. The fast parameters represent the episode-specific memory and are reset to the learned initialization at the beginning of each episode. During deployment, the slow parameters remain fixed, while the fast weights are updated from observations without action labels.

The memory has 16 heads, with each head implemented using a nonlinear multilayer perceptron. The episode-specific state contains approximately 9.5 million FP32 parameters, corresponding to about 36.35 MiB, excluding activations and attention caches. This is a fixed-size representation rather than an expanding history buffer.

Retrieved memory is fused with current VLM information through a channel-wise gated residual connection. The gates are initialized to contribute minimally, preserving the pretrained policy’s original behavior while allowing action supervision to learn where memory is useful.

#### 3.3. Alternating Memory–Policy Learning

The authors argue that jointly optimizing memory and policy can be unstable because both components continually change the representation used by the other. T²Mem therefore uses alternating optimization.

- **Stage 0:** The pretrained π0.5 model provides the initial VLA.
- **Stage 1:** The policy is adapted without memory to establish task-specific visuomotor skills.
- **Stage 2A:** The VLM and action expert are frozen while the memory interface, projections, initialization, gates, and update parameters are trained. The action loss backpropagates through the fixed action expert, shaping memory toward information useful for control.
- **Stage 2B:** The memory mechanism is frozen while the VLM and action expert learn to use the retrieved representations.

These phases are repeated. Both stages use imitation or flow-matching action supervision, but neither uses labels specifying memory contents, task progress, or hidden state. Fast-weight updates still occur during training so that gradients can pass through the sequence of memory writes.

#### 3.4. Adaptive Writing and Evaluation Protocol

The method includes an adaptive write-strength coefficient. It reduces updates that are aligned with information already accumulated in the fast weights and preserves stronger updates for poorly reconstructed or less redundant observations. A curvature-calibrated step size is also used. The purpose is to reduce interference with earlier bindings as the episode continues.

The main evaluation uses RoboMME, a benchmark with 16 tasks across counting, permanence, reference, and imitation categories. The benchmark includes tasks involving hidden objects, repeated actions, object-location associations, and action-sequence reproduction. The policy predicts 64 actions and executes 32 before replanning. The reported scores average 50 test episodes per task over three evaluation seeds.

### 4. Main Findings and Results

#### 4.1. Overall Performance

T²Mem achieves an average success rate of **56.83%** on RoboMME. The memory-free π0.5 baseline achieves **17.93%**, while the Stage 1 memory-free adaptation reaches **16.38%**. The result indicates a substantial improvement when the learned memory pathway and alternating training procedure are introduced.

The recurrent-memory baselines reported in the benchmark perform substantially lower: TTT averages **22.35%**, and RMT averages **18.15%**. Perceptual-memory methods score between approximately 30% and 45%, while MemER reaches **42.38%**. Symbolic-memory systems using external models obtain variable results, with oracle versions benefiting from privileged information. These comparisons should be interpreted cautiously because the baselines differ in information access and external components.

T²Mem performs relatively well on tasks requiring direct retrieval of an earlier observation or tracking repeated events. Its success is weaker on swap variants, in which object-location bindings change over time. This distinction suggests that the method can retain earlier information but does not automatically provide robust reasoning about how that information changes across subsequent events.

The model also encounters low-level control failures. On InsertPeg, for example, qualitative analysis indicates that the policy may identify and approach the correct target but fail during the final insertion. Thus, the benchmark score combines memory-dependent decision quality with motor execution precision.

#### 4.2. Ablation Results

The architecture and training schedule each make a measurable contribution. On two single-task evaluations, VideoUnmask and MoveCube, T²Mem obtains **84% and 71%** success, respectively. A memory-free policy obtains **23% and 28%**, while a RoboTTT-style memory placed on action-expert representations obtains **30% and 26%**. This supports the authors’ claim that memory should be formed from semantic vision-language features rather than only action-expert representations.

Alternating optimization also matters. The alternating model reaches the same 84% and 71% scores on the two tasks, whereas jointly optimizing memory and policy produces approximately **30% and 28%**, close to the memory-free baseline. This result is consistent with the hypothesis that a fixed counterpart is needed while the other component learns.

Adaptive writing improves retention of early memory bindings. In a replay experiment, adaptive writing reduces normalized reconstruction error by **18.8% to 46.9%** compared with a fixed write-strength control across the tested time intervals and episodes.

#### 4.3. Evidence That Online Memory Is Used

Intervention experiments provide evidence that the model depends on episode-specific memory rather than only on its learned initialization. Disabling online writes reduces success by **82.67 percentage points** on VideoUnmask, **64.67 points** on SwingXtimes, and **41.33 points** on MoveCube.

Content-replacement experiments are also informative. When the correct demonstration memory is supplied, the model succeeds in **300 of 300** trials. With conflicting memory from another episode, it succeeds in only **1 of 300** trials. With empty demonstration memory, it succeeds in **101 of 300** trials. The strong difference between correct and conflicting memory indicates that the retrieved content influences the decision, rather than functioning merely as a generic recurrent signal.

Write timing further localizes the useful information. On VideoUnmask, writing before the relevant occlusion achieves **76.67%** success, matching the full-demonstration condition, while writing only after occlusion achieves **20.67%**. This indicates that the memory must encode the target identity while it is visible; later updates cannot reconstruct information that was never stored.

#### 4.4. Inference Efficiency

Under a controlled batch-one profile on RTX A5000 GPUs, T²Mem’s end-to-end inference latency is **146.6 ms**, compared with **440.0 ms** for FrameSamp+Modul and **10,135.6 ms** for MemER. The corresponding ratios are approximately **3.0 times faster** than FrameSamp+Modul and **69.2 times faster** than MemER. The memory-related component alone takes 7.7 ms for T²Mem, compared with 148.9 ms and 9,890.9 ms for the two comparison configurations.

These measurements exclude initialization, compilation, communication, environment execution, and physical action execution. They therefore characterize model computation under the specified workload rather than complete robot-cycle latency.

### 5. Significance and Potential Impact

T²Mem contributes a method for embedding adaptive, decision-oriented memory within a single VLA policy. Its main significance is methodological: it demonstrates that self-supervised online memory updates can be shaped indirectly by action loss, without requiring annotations describing what the robot should remember. The intervention results provide evidence that the learned fast weights store task-specific content and affect later actions.

If the approach generalizes, it could provide a middle ground between explicit memory banks and purely recurrent policies. Fixed-size fast weights may reduce the computational cost of long histories while preserving information needed for occlusion recovery, counting, and demonstration-conditioned manipulation. The design may also complement larger reasoning models rather than replace them, particularly for low-level closed-loop control.

Several limitations remain. The evaluation is concentrated on one benchmark and one pretrained VLA family. The method depends on the underlying model’s visual representation and temporal reasoning, which is reflected in weaker performance on changing object associations. Fast-weight adaptation also introduces additional memory state, update stability concerns, and episode-boundary requirements. Finally, the reported efficiency comparisons use controlled profiling and include baselines with different architectures and information pathways. Further evaluation on physical robots, longer and more varied tasks, distribution shifts, and stronger temporal-reasoning models would be needed to establish the method’s broader applicability.
