# Co-Harness: Co-Evolving Harnesses and Model Weights for LLM Agents

> [!summary] Summary
> Co-Harness is a dual-loop post-training framework that jointly evolves an LLM agent's runtime harness (prompt, tools, skills, middleware, memory) and its weights. An LLM HarnessCritic attributes failed trajectories to structured harness causes and proposes validated local diffs; the model is then fine-tuned on trajectories collected under the improved harness. Two rounds lift average tool-integrated reasoning accuracy by 20.4 points across Qwen3-8B and Qwen3-32B.

## Problem

- Post-training pipelines update model weights while the harness that generates, verifies and records trajectories stays hand-designed and frozen, creating a mismatch.
- Harness-optimization work edits prompts, tools or middleware around a fixed model, improving inference-time scaffolding but never feeding back into the loop that trains the next model.
- Automated agentic-design search optimizes task scores at inference, without failure attribution or any check that discovered designs yield high-quality training trajectories.

## Method

- Dual-loop alternation: an **AutoHarnessLoop** improves the harness with weights frozen, then a **ModelAlignLoop** runs supervised fine-tuning on trajectories collected under the evolved harness.
- **HarnessCritic** converts failed trajectories into structured records (root cause, harness dimension, severity, evidence, diff suggestion) over a ==six-label taxonomy== spanning prompt, tool, skill, middleware, memory and an agent-error abstention.
- ==Diff aggregation== ranks edits by recurrence, severity and field-path consistency; a patch is committed to a versioned harness registry only if held-in reward rises and held-out reward does not fall.

## Results

- Average accuracy climbs **58.5%** at Round 0 to **73.5%** after one round to **78.9%** after two, a **20.4**-point cumulative gain and **24.7** points over the human-designed static harness.
- Gains scale with difficulty: HMMT25 improves **20.1** points for Qwen3-8B and **27.2** points for Qwen3-32B, versus only **10.6** points on the easier AIME24 for the 32B model.
- A **200-hour** autonomous run produced **22** harness versions, fixing a **32-second** startup crash, cutting wall-clock time **8.7-fold** (3.78h to 1.11h), and reaching **63.3%** via majority-vote ensembling.

## Takeaways

> [!tip] Key Insights
> - Scaffolding and weights are coupled optimization axes: freezing either caps improvement, while alternating between them compounds only if each edit genuinely raises trajectory quality.
> - Failure-grounded attribution beats undirected search because structured root-cause records make the edit space auditable, local, and cheaply reversible via registry rollback.
> - Training on scaffolding-assisted trajectories did not create harness dependence here, but over-patching, SFT plateaus, and attribution cascades remain real ways the loop stalls.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

The development of sophisticated AI agents requires not only improvements in large language models (LLMs) themselves but also in the surrounding systems that orchestrate their behavior. These surrounding systems, collectively referred to as the "Harness," include elements such as prompts, tools, skills, middleware, and memory management.

Existing paradigms for post-training LLM agents typically treat model parameters and the agent's runtime Harness asymmetrically. Model parameters are often optimized through methods like supervised fine-tuning (SFT), reinforcement learning (RL), or preference optimization, while the Harness is frequently hand-designed and remains fixed during the model's training process. This creates a recognized mismatch: the Harness dictates the quality and nature of trajectories used for model training, yet it is not adaptively improved based on observed failures during these interactions. This limitation can constrain agent performance, particularly as models become more adept at complex tasks requiring software engineering and tool-use capabilities.

Recent research efforts have begun to address the static nature of the Harness. Approaches like Meta-Harness, Agentic Harness Engineering, and AEVO focus on optimizing the Harness components—from prompts and demonstrations to full agent code—based on execution feedback, scores, or observability signals. These works have demonstrated that performance can be improved by editing the system around the model. However, these methods primarily focus on finding a better inference-time scaffold for a *fixed* model. They do not integrate Harness optimization into the model's post-training loop, meaning the improved Harness does not directly influence the data generation process for subsequent model updates.

This paper extends the prior work by proposing a framework that addresses this limitation. Instead of optimizing the Harness or the model independently, Co-Harness integrates both optimizations into a joint, alternating process. This approach seeks to establish a feedback loop where an improved Harness generates higher-quality training data, which in turn leads to a stronger model. A stronger model can then expose new, higher-order Harness bottlenecks or opportunities, enabling further refinements to the Harness. This positions Co-Harness as a contribution that bridges the gap between dynamic Harness engineering and iterative model fine-tuning, aiming for a compounding self-improvement mechanism beyond what either approach achieves in isolation.

### 2. Key Objectives and Motivation

The primary objective of Co-Harness is to jointly optimize both the agent's runtime Harness and the model's parameters during post-training. This is motivated by the observation that current agent post-training pipelines exhibit a fundamental mismatch: the Harness, which includes crucial components like prompts, tool definitions, reusable skills, middleware logic, and memory policies, largely determines the quality of trajectories generated for training, yet it remains static and is not directly improved from failures observed during this process.

The specific motivations and objectives can be detailed as follows:

- **Address the Fixed Harness Bottleneck:** Existing systems often assume a fixed Harness while the model parameters are updated. This fixed scaffolding can become a performance bottleneck, preventing the model from generating useful trajectories if, for example, a tool schema is incorrect, retry logic is absent, or prompts are underspecified. The paper aims to make the Harness a learnable and adaptable part of the post-training system, rather than a static environment.
- **Establish a Positive Feedback Loop:** The central motivation is to create a "co-evolution" where improvements in one component lead to improvements in the other. A better Harness is hypothesized to produce cleaner tool use, fewer avoidable crashes, and more informative trajectories. These higher-quality trajectories can then be used to train a stronger model. A stronger model, in turn, can potentially exploit a richer, more advanced Harness, or expose new, subtle Harness-level bottlenecks that were previously masked by the model's weaker base behavior. The objective is to realize this compounding self-improvement.
- **Automate Harness Repair from Failures:** The paper aims to develop a systematic method for identifying and rectifying Harness-level failure modes. Rather than relying on manual intervention, a key objective is to leverage an LLM-based critic to analyze failed trajectories, attribute failures to specific Harness components (e.g., prompt ambiguity, tool schema errors), and propose validated, local updates to the Harness.
- **Distill Harness Improvements into Model Weights:** A critical objective is to ensure that successful Harness revisions are not just temporary inference-time scaffolds but become persistent model capabilities. This is achieved by fine-tuning the model on trajectories generated by the improved Harness, thereby distilling the effective scaffolding behaviors and strategies into the model's parameters.
- **Improve Agent Performance on Complex Tasks:** The ultimate objective is to demonstrate that this joint optimization leads to quantifiable improvements in agent performance, particularly on challenging Tool-Integrated Reasoning (TIR) tasks where the Harness plays a crucial role in mediating tool interactions and error recovery.

By achieving these objectives, Co-Harness aims to advance the automation of AI research and development, moving beyond siloed optimization of either models or their operational environments.

### 3. Methodology and Approach

Co-Harness employs a dual-loop co-evolution architecture that alternates between improving the agent Harness and updating the model parameters. This process is structured into two main loops: the Co-Harness Loop (for Harness optimization) and the Model Alignment Loop (for model optimization).

#### 3.1. Harness Configuration (ϕ)

A Harness configuration ϕ is defined as a structured five-tuple: ϕ = (P, T, S, Mid, M).
- **P (Prompt):** Instruction templates provided to the model.
- **T (Tools):** Tool definitions and their interface schemas.
- **S (Skills):** Reusable skills or modules that the agent can invoke.
- **Mid (Middleware):** The agent's runtime control surface, including orchestrator logic (main loop, protocol), hooks for interception and verification, and context management (compression, truncation, retrieval routing).
- **M (Memory):** Policies for long-term memory management.

#### 3.2. Dual-Loop Co-Evolution Architecture

The framework alternates between the two loops over `T` rounds:

- **Co-Harness Loop (Harness Optimization):**
 - **Input:** The current model θ_t and Harness ϕ_t.
 - **Process:** The agent first collects rollouts on a task set. Failed trajectories (F⁻_t) observed under (θ_t, ϕ_t) are passed to `HarnessCritic`.
 - `HarnessCritic` (C) is an LLM-based component that analyzes each failed trajectory. It attributes the failure to a structured Harness-level cause (e.g., prompt ambiguity, tool schema error, missing skill, middleware mismatch) based on a predefined taxonomy (Table 4). For each failure, it generates a structured record containing the root cause, implicated Harness dimension, severity, supporting evidence from the trajectory, and a concrete diff suggestion.
 - These structured attributions (A_t) are then aggregated into a single Harness Diff (∆Φ_t). Aggregation prioritizes edits by recurrence, severity, and consistency of the proposed field path.
 - The proposed patch (˜ϕ_t) is applied to the current Harness (ϕ_t).
 - **Patch Validation:** A crucial step is validation. A proposed patch is accepted only if it demonstrably improves the targeted failure mode (δ_in > 0) without causing regression on held-out behaviors (δ_out ≥ 0) on a validation set (V_in for target failures, V_out for general behavior). Accepted patches are committed to a versioned Harness registry; rejected patches are rolled back.
 - This loop finds environment-level fixes for scaffolding-related failures. The accepted Harness configuration is denoted ϕ∗t.

- **Model Alignment Loop (Model Optimization):**
 - **Input:** The evolved Harness ϕ∗t.
 - **Process:** The current model θ_t is re-run under the newly evolved Harness ϕ∗t to collect a set of high-quality trajectories (D_t). These trajectories include full interaction traces with prompt context, tool calls, responses, intermediate decisions, and verified outcomes. Only trajectories satisfying task verifiers or quality filters are kept.
 - The model θ_t is then fine-tuned (SFT) on this D_t to obtain the updated model θ_t+1. This step aims to distill the improved behaviors enabled by the evolved Harness directly into the model's parameters.
 - **Output:** The updated model θ_t+1, which is then fed back into the next Co-Harness round, initialized with ϕ_t+1 ← ϕ∗t.

#### 3.3. Overall Co-evolution Algorithm (Algorithm 3)

One round of co-evolution:
1. Initialize with model θ_t and Harness ϕ_t.
2. Collect failed trajectories F⁻_t.
3. For `K` inner iterations:
 - `HarnessCritic` generates attributions A_t from F⁻_t and ϕ_t.
 - Aggregate attributions into a diff ∆Φ_t.
 - Apply diff to get ˜ϕ_t.
 - Validate ˜ϕ_t. If non-regressive, commit ∆Φ_t and update ϕ_t. Else, reject.
 - Refresh F⁻_t under (θ_t, ϕ_t) if Harness was updated.
4. Collect high-quality trajectories D_t under the final evolved Harness ϕ∗t.
5. Fine-tune θ_t on D_t to get θ_t+1.
6. Return evolved Harness ϕ∗t and updated model θ_t+1.

The alternating schedule continues until no patch passes validation or marginal reward gains fall below a threshold. The system includes a versioned Harness registry for auditability and rollback.

### 4. Main Findings and Results

The research presented several findings from experiments conducted on Tool-Integrated Reasoning (TIR) tasks using mathematical competition benchmarks (AIME24, AIME25, HMMT25) and two model scales (Qwen3-8B and Qwen3-32B).

#### 4.1. Dual-Loop Co-Evolution Performance

The core experiment involved running two full rounds of Co-Harness co-evolution, comparing against a Baseline (Round 0, with one HarnessCritic pass but no SFT) and a Human-designed static Harness.

- **Consistent Compounding Gains:** Co-Harness demonstrated monotonic accuracy improvements across rounds for both model scales and all benchmarks. The average accuracy increased from 58.5% (Baseline) to 73.5% (Round 1, +15.0 percentage points (pp)) and further to 78.9% (Round 2, +20.4 pp cumulative).
- **Surpassing Human-Designed Harness:** Round 2 results surpassed the human-designed static Harness by an average of +24.7 pp, indicating that the automated co-evolution can exceed the performance ceiling of carefully hand-crafted configurations.
- **Impact of Task Difficulty:** Gains were most significant on the most difficult benchmark, HMMT25 (+20.1 pp for Qwen3-8B and +27.2 pp for Qwen3-32B). This suggests that a better Harness is particularly impactful when models face complex, multi-step reasoning tasks where scaffolding deficiencies are more likely to cause failures.
- **Model Scale Interaction:** Stronger models (Qwen3-32B) showed larger absolute gains on hard tasks (e.g., +27.2 pp on HMMT25 for 32B vs. +20.1 pp for 8B). This supports the hypothesis that a stronger model possesses greater latent capacity that can be unlocked by an improved Harness. For simpler benchmarks like AIME24, the 8B model showed signs of saturation (84.0% in R1 to 84.7% in R2), while the 32B model continued to improve (85.3% in R1 to 87.3% in R2).

#### 4.2. Autonomous Harness Evolution Case Study

A 200+ hour autonomous case study on AIME24 with Qwen3-8B illustrated the practical capabilities of the Co-Harness Loop:

- **Phase 1: Engineering Fixes (init–v7):** The initial configuration crashed due to a vllm KV cache error. HarnessCritic autonomously identified and patched a tool schema error in the launch configuration. It also resolved a zombie thread bug by switching from ThreadPool to ProcessPool, leading to the first complete evaluation at 59.6% accuracy.
- **Phase 2: Efficiency Optimization (v12–v15):** HarnessCritic identified sequential execution as a bottleneck. It introduced global-batched inference, reducing wall-clock time by 8.7x (from 3.78 hours to 1.11 hours) while maintaining accuracy at 61.5% after restoring chain-of-thought on follow-up turns and extending turn limits.
- **Phase 3: Ensemble Validation (v18–v22):** The system discovered an ensemble strategy by combining two diverse seeds via majority voting, achieving the highest accuracy of 63.3% within the time budget. It also detected and rolled back regressions caused by domain-specific prompts that conflicted with the model's internal reasoning.

This case study demonstrated the system's ability to autonomously recover from crashes, improve inference efficiency, navigate accuracy-efficiency trade-offs, and discover non-obvious strategies like ensembling, while also detecting and reverting regressions.

### 5. Significance and Potential Impact

The Co-Harness framework presents a conceptual shift in agent training by recognizing the interdependent nature of the agent Harness and the model parameters. Its significance and potential impact stem from several aspects:

- **New Paradigm for Agent Post-Training:** Co-Harness introduces the first framework to co-evolve both the model and its scaffolding, moving beyond paradigms that either fix the Harness (e.g., SWE-smith, AgentTuning) or freeze the model (e.g., ADAS, OPRO). This dual-loop optimization realizes a compounding self-improvement mechanism that is not achieved by optimizing either component in isolation.
- **Enhanced Agent Performance and Robustness:** The demonstrated significant accuracy gains (average +20.4 pp) on complex Tool-Integrated Reasoning benchmarks, particularly on harder tasks and with more capable models, indicate that automated co-evolution can substantially improve agent performance. The ability to autonomously recover from system crashes and optimize inference efficiency, as shown in the case study, suggests increased robustness and practicality for agent deployment.
- **Reduced "Harness Debt":** The research implicitly addresses the concept of "Harness Debt," where models trained under specific scaffolding might over-rely on it. By fine-tuning the model on trajectories generated by an *improved* Harness, Co-Harness aims to distill transferable reasoning skills into the model, reducing dependency on a fragile external scaffold. The results show that models trained via Co-Harness achieve higher absolute accuracy at test time, indicating genuine skill acquisition rather than mere memorization of Harness-dependent behaviors.
- **Automation of Agent Engineering:** The `HarnessCritic` component automates critical aspects of agent engineering, such as failure attribution and localized patch generation. This reduces the need for manual debugging and iterative design, potentially accelerating the development cycle for advanced AI agents.
- **Applicability to Complex Tool-Integrated Reasoning (TIR):** The framework's particular effectiveness in TIR tasks is significant. In TIR, Harness deficiencies can cause complete task failures, providing a sharper gradient for `HarnessCritic` to act on. This highlights the framework's relevance for domains where reliable tool use and complex multi-step reasoning are crucial.

**Limitations and Future Directions:**
The paper acknowledges limitations, including the requirement for a capable critic LLM, a minimum volume of failure trajectories for cold-start, significant compute for multi-round SFT, and potential degradation of attribution accuracy for complex control-flow reasoning. Structural Harness redesign beyond local diffs remains a human responsibility.

Despite these, the work opens several promising future directions. These include online Co-Harness for real-time, within-run Harness adaptation; RL-based Harness evolution to discover non-obvious configurations; and Multi-agent Co-Harness, where inter-agent middleware becomes a key optimization target. These extensions suggest a path toward continuous, autonomous scaffolding health monitoring and evolution for AI agents.
