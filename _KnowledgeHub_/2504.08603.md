# FindAnything: Open-Vocabulary and Object-Centric Mapping for Robot Exploration in Any Environment

> [!summary] Summary
> FindAnything is a real-time open-vocabulary volumetric mapping framework for MAVs that fuses CLIP features with eSAM-segmented objects into submap-based occupancy maps, matching state-of-the-art semantic accuracy while cutting memory by up to 60% and enabling onboard autonomous exploration.

## Problem

- Class-level semantic mapping needs a priori known label sets, capping expressiveness for open-world robot deployment in unknown environments.
- Voxel-level vision-language feature fusion into volumetric maps demands vast memory, blocking scalability to large environments and resource-constrained platforms.
- Prior instance-level scene-graph or point-cloud open-vocabulary methods drop full 3D geometry or lack drift-correction like loop closures for large-scale use.

## Method

- ==Object-centric VL feature aggregation==: ==eSAM== segment masks are tracked and their ==CLIP== features weighted-averaged per segment ID rather than stored per voxel.
- ==As-fine-as-possible oversegmentation strategy==: image-space segment tracking greedily fuses eSAM proposals with rendered map segments, favoring the smallest partition available.
- ==Submap-based integration== with ==OKVIS2-X VI-SLAM== and ==supereight2== occupancy mapping, plus a ==language-guided exploration planner== weighting candidate views by CLIP query similarity.

## Results

- On Replica, FindAnything reaches **48.87** mAcc / **62.71** f-mIoU, competitive with RayFronts and processes a sequence in **5m24s** versus RayFronts' **9m19s** and HOV-SG's **11h12m**.
- On SemanticKITTI at **0.1m** resolution FindAnything achieves **51.24** mAcc / **53.90** f-mIoU using **16.23GB** while RayFronts fails outright from GPU memory limits.
- At matched **0.5m** resolution FindAnything uses only **40%** of RayFronts' memory (**9.91GB** vs **24.61GB**) and language-guided exploration improves mesh completeness and RMSE over a non-semantic baseline.

## Takeaways

> [!tip] Key Insights
> - Decoupling voxel resolution from language representation via object-level feature aggregation lets high-resolution geometry coexist with tractable memory for open-vocabulary semantics.
> - Oversegmenting objects into parts preserves fine-grained query resolution without losing whole-object semantic grouping at query time.
> - Tracking segments in image space rather than 3D avoids volumetric discrepancies from viewpoint change, a lighter-weight alternative to 3D instance tracking.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

The field of robotics for autonomous operation in unknown environments relies on robust and informative map representations. Initially, robot mapping focused on geometric accuracy, providing representations of the physical structure of an environment. Subsequent advancements introduced semantic information, categorizing parts of the environment into predefined classes (e.g., "chair," "wall," "floor"). However, these class-level semantic maps are limited by their reliance on a priori known sets of classes, which restricts their expressiveness and applicability in diverse or novel environments.

The emergence of Vision-Language (VL) foundation models, such as CLIP, represents a shift towards open-vocabulary semantic understanding. These models can associate visual features with natural language descriptions, allowing for flexible and generalizable semantic querying. Integrating such high-dimensional VL features into 3D volumetric maps presents significant computational and memory challenges, particularly for real-time deployment on resource-constrained platforms like Micro Aerial Vehicles (MAVs). Existing approaches have explored several strategies:

- **NeRFs or Gaussian splats:** These methods can generate photorealistic renders and embed VL features but typically require extensive offline training, limiting their scalability and real-time use on robots.
- **Monolithic TSDF maps:** These fuse VL features efficiently but are constrained in map size due to high memory requirements.
- **Point clouds or 3D scene graphs:** These approaches offer improved scalability by storing features at instance levels but may not preserve full 3D geometric information crucial for downstream tasks like navigation, or they may lack robust drift-correcting mechanisms.
- **Voxel-level VDB occupancy maps:** Fusing VL features at the voxel level, as seen in methods like RayFronts, results in high memory usage, limiting large-scale applicability.

FindAnything addresses these limitations by developing an open-vocabulary mapping framework that integrates vision-language information into dense volumetric submaps efficiently. It seeks to combine the advantages of geometric accuracy, open-vocabulary semantic understanding, memory efficiency, and scalability, while enabling real-time operation on resource-constrained platforms. By employing an object-centric aggregation strategy for VL features within a submap-based SLAM framework, FindAnything aims to overcome the computational and memory bottlenecks that have hindered the widespread adoption of open-vocabulary mapping in dynamic robotic applications.

### 2. Key Objectives and Motivation

The primary objective of this research is to develop a real-time, open-vocabulary, and object-centric 3D mapping system named FindAnything, designed for robust deployment on robots, specifically Micro Aerial Vehicles (MAVs), in unknown and unstructured environments.

The motivation for this work stems from the increasing demand for autonomous robots in applications such as Search and Rescue (S&R) and disaster response. In these critical scenarios, robots must operate safely with minimal human supervision in hazardous or inaccessible environments, providing timely and high-level information to human operators. This necessitates map representations that go beyond mere geometry and appearance, incorporating semantic understanding and object localization capabilities.

Specifically, the authors identify several key requirements for such a system:

- **Real-time Operation:** The robot must incrementally reconstruct the unknown scene online, as it navigates, to provide immediate information to operators.
- **Scalability to Large Environments:** The mapping system must be capable of representing extensive areas, such as multi-story buildings, without compromising performance.
- **Memory Efficiency:** For deployment on resource-constrained platforms like MAVs, the map representation and processing must be optimized for low memory footprint.
- **Open-Vocabulary Semantic Understanding:** To handle diverse and unpredictable environments, the system requires generalizable semantic reasoning that does not rely on a predefined set of object classes. This enables operators to query the map for arbitrary objects or concepts using natural language.
- **Geometric Accuracy:** The map must maintain sufficient geometric detail for safe navigation and interaction with the environment.
- **Drift Correction:** In large-scale operations, state estimation drift is inevitable. The mapping system must incorporate mechanisms like loop closures to maintain global consistency and accuracy.

The paper highlights the challenge of integrating high-dimensional Vision-Language (VL) features, which provide open-vocabulary capabilities, into 3D maps without incurring prohibitive computational and memory costs. Traditional voxel-level feature storage becomes unfeasible for large maps or fine resolutions. FindAnything aims to address these motivations by proposing an object-centric approach to aggregate VL features within a submap-based volumetric framework, offering a scalable and efficient solution for advanced scene understanding in real-world robotic applications.

### 3. Methodology and Approach

FindAnything is presented as an open-world mapping framework that integrates vision-language information into dense volumetric submaps. Its architecture comprises several interconnected modules: a Visual-Inertial SLAM (VI-SLAM) system, a volumetric occupancy mapping component, and a Vision-Language (VL) feature fusion module.

#### 3.1. A. Visual-Inertial SLAM (VI-SLAM)

The system utilizes OKVIS2-X, an extension of OKVIS2, as its state estimation module. This multi-sensor SLAM system tracks the robot's pose in a static world coordinate frame using an Inertial Measurement Unit (IMU) and multiple cameras, incorporating depth information to enhance accuracy. It operates in real-time, employing a sliding window optimization and loop closure detection. This process provides updated robot poses (`T_WS`) for incoming stereo image pairs, ensuring globally consistent pose estimates that are crucial for accurate map integration.

#### 3.2. B. Volumetric Occupancy Mapping

Geometric scene information is managed using the supereight2 framework, which partitions the environment into volumetric submaps. This representation distinguishes between occupied, free, and unmapped regions, facilitating direct use for path planning and navigation. The submap architecture is central to the system's scalability in large environments, as it allows for shallower data structures and faster data access. Rigid transformations between submaps are tracked and refined after each SLAM optimization, including corrections from loop closures, by associating each submap with a keyframe.

#### 3.3. C. Vision-Language Feature Fusion

The core innovation lies in the efficient integration of open-vocabulary semantic information. This module addresses the high computational and memory demands of pixel-wise or voxel-wise VL feature aggregation.

1. **VL Feature Extraction:** CLIP (specifically ViT-L/14, pre-trained for 336x336 pixel images) is used as the VL feature extractor. It produces a 768-dimensional feature embedding for each pixel in the image.
2. **Object-Centric Aggregation:** Instead of direct voxel-level aggregation, FindAnything adopts an object-centric approach. This strategy decouples the language representation from the voxel resolution, enabling high-resolution geometric mapping without excessive memory usage for semantic features.
3. **Image-Based Segmentation:** EfficientSAM (eSAM), a lightweight and faster variant of SAM, is employed to generate binary segment masks (`E_t`) from the RGB images. These masks represent object proposals.
4. **Segment Tracking and Oversegmentation:**
 - To track objects and fuse new segments, a segment image of the existing map is rendered from the current camera pose, yielding a collection of binary masks with associated segment IDs (`R_t`).
 - An "as-fine-as-possible" segmentation strategy is applied: eSAM segments and rendered map segments are fused based on 2D image overlap, prioritizing smaller segments (above a defined threshold) for partitioning. This creates a per-pixel segment ID image (`K_t`).
 - This 2D image-space tracking, performed on the CPU, alleviates potential volumetric discrepancies and frees GPU resources for foundation models.
 - The strategy allows for both fine-grained queries (by oversegmenting objects into parts) and understanding of larger concepts (preserved by generalized VL features). Semantic and spatial consistency across submaps means inter-map segment tracking is not explicitly performed.
5. **Feature Aggregation and Update:**
 - Supereight2's volumetric occupancy map is extended to incorporate segment IDs into occupied voxels.
 - Each unique segment ID (`k`) stores an associated average language feature (`f_k`) and the total number of pixels (`N_k`) that have contributed to its update.
 - For each frame, a weighted average update is performed for the per-segment feature vectors. If `N` pixels in the current frame's segment ID `k` have CLIP features `F_t[u_i]`, the segment's average feature `f_k` and pixel count `N_k` are updated using the following equations:
 `f_k ← (N_k * f_k + Σ(F_t[u_i] for i in N)) / (N_k + N)`
 `N_k ← N_k + N`
 - This weighted averaging process from multiple viewpoints enhances the consistency and robustness of the VL embedding representation for each segment.

This integrated methodology enables FindAnything to construct a scalable, open-vocabulary, and geometrically accurate 3D map online, suitable for real-time deployment on resource-constrained robotic platforms.

### 4. Main Findings and Results

The evaluation of FindAnything focused on semantic accuracy, computational efficiency, memory usage, and its utility in downstream tasks, using both indoor (Replica) and outdoor (SemanticKITTI) datasets, as well as real-world MAV experiments.

#### 4.1. A. Semantic Accuracy

- **Replica Dataset (Indoor):** FindAnything demonstrates semantic accuracy competitive with, and in some configurations surpassing, state-of-the-art approaches (Table I). When using the NARADIO VL encoder, it achieved an mAcc of 53.55 and f-mIoU of 66.91, which was higher than RayFronts using the same encoder. Even with standard CLIP features, it maintained high accuracy (mAcc 48.87, f-mIoU 62.71). The difference in semantic accuracy between using ground-truth (GT) poses and SLAM poses was negligible due to the high accuracy of SLAM in these smaller environments. Submapping also provided a minor improvement over a monolithic map variant due to better global consistency with loop closures.
- **SemanticKITTI Dataset (Outdoor, Large-scale):**
 - At a coarse voxel resolution of 0.5m, FindAnything (mAcc 36.89, f-mIoU 51.48) yielded a higher f-mIoU than RayFronts (mAcc 45.85, f-mIoU 35.60), despite RayFronts having a higher mAcc for some fine-grained structures.
 - Crucially, at a finer resolution of 0.1m, FindAnything (mAcc 51.24, f-mIoU 53.90) exhibited superior scalability and performance, achieving significantly higher semantic accuracy. RayFronts failed to run at this resolution due to insufficient GPU memory.
 - When evaluated with SLAM poses, semantic accuracy degraded due to drift, which is common in large-scale scenarios. However, the submapping approach of FindAnything (mAcc 32.26, f-mIoU 37.77) still outperformed a monolithic map variant (mAcc 23.81, f-mIoU 28.24) by allowing drift-correcting mechanisms to improve map consistency.

#### 4.2. B. Computational Efficiency and Memory Usage

- **Replica Dataset (Table II & IV):** FindAnything exhibited significantly faster processing times compared to several baselines. It processed sequences in an average of 5m 24s, substantially faster than HOV-SG (11h 12m) and RayFronts (9m 19s). When processing every tenth frame, FindAnything completed sequences in 1m 19s, outperforming OVO-SLAM (3m 2s) under similar conditions. The per-frame timing breakdown indicated that CLIP and eSAM inference, segment tracking, and VL feature fusion were the main computational stages, but the system remained real-time capable.
- **SemanticKITTI Dataset (Table III):**
 - **Memory Efficiency:** A key finding was FindAnything's ability to operate with substantially less memory. At 0.5m resolution, it used 9.91 GB of memory, compared to RayFronts' 24.61 GB. At 0.1m resolution, FindAnything used a moderate 16.23 GB, while RayFronts failed due to exceeding the 24.5 GB GPU memory limit. This memory efficiency is attributed to the object-centric aggregation of VL features.
 - **Runtime:** FindAnything maintained similar runtimes to RayFronts at coarser resolutions and showed only a negligible increase in processing time at finer resolutions, demonstrating efficient scaling.

#### 4.3. C. Ablation Studies

- **Segmentation Model Choice (Table III):** Using eSAM at half image resolution (FA - half-res) significantly reduced runtime (124.5s) with a minor impact on semantic accuracy (mAcc 50.59, f-mIoU 53.29), showing a trade-off benefit for constrained devices. Replacing eSAM with SAM2 increased runtime and memory usage without substantial accuracy gains for the chosen map resolution, suggesting eSAM is an effective choice for efficiency.
- **Feature Fusion Strategy (Table III & Fig. 4):** The proposed weighted-mean feature embedding update (Eq. 1) improved semantic accuracy compared to simply storing the first feature vector for each segment (FA - no fusion: mAcc 49.88, f-mIoU 50.26 vs. FindAnything: mAcc 51.24, f-mIoU 53.90), demonstrating the benefit of accumulating information from different viewpoints. The "as-fine-as-possible" oversegmentation strategy qualitatively enabled distinguishing parts of objects (e.g., "wheel") while maintaining understanding of larger entities (e.g., "car").

#### 4.4. D. Autonomous MAV Exploration Application

- FindAnything was integrated into an autonomous MAV exploration pipeline in a simulated environment (Habitat-Matterport 3D dataset). By guiding exploration using natural language queries (e.g., "bed," "bathroom"), the system achieved higher completeness and mesh accuracy for items/regions of interest compared to a non-semantic baseline (Fig. 5). For "bed," FindAnything showed generally higher completeness (e.g., median around 90%) and lower RMSE (median around 0.05m) than the baseline. For "bathroom," the improvements were more pronounced in completeness and accuracy, indicating its effectiveness in observing larger areas of interest by sampling candidate views within segment cubes. The system also demonstrated more consistent results across multiple runs.

#### 4.5. E. Real-World Experiments

- FindAnything was successfully deployed online on a resource-constrained MAV (custom quadcopter with RealSense D455 camera and NVIDIA Jetson Orin NX 16 GB).
- In a simulated firefighting scenario in an office environment, the MAV performed autonomous exploration guided by queries like "fire extinguisher" and "kitchen," demonstrating its ability to reconstruct 3D environments and aggregate language embeddings in object-centric submaps suitable for navigation and query-based interaction (Fig. 1). Adaptations like image downsampling and sparse point queries for eSAM, along with occasional depth integration without full VL processing, were made to maintain real-time performance on the onboard computer.

### 5. Significance and Potential Impact

FindAnything represents a development in the field of robotic mapping and semantic scene understanding, particularly for resource-constrained platforms. Its significance and potential impact can be summarized as follows:

- **Enabling Open-Vocabulary Mapping on Resource-Constrained Devices:** A primary contribution is the demonstration of real-time, open-vocabulary 3D mapping on onboard computational resources of MAVs. Previous approaches often suffered from high memory consumption or computational demands, limiting their deployment to offline processing or high-end ground robots. FindAnything's object-centric and submap-based approach directly addresses these limitations, making advanced semantic understanding accessible to a wider range of robotic platforms.
- **Enhanced Scene Understanding for Diverse Environments:** By leveraging vision-language foundation models, FindAnything provides an open-vocabulary semantic understanding of environments. This allows robots to comprehend and respond to natural language queries about objects or concepts without prior training or a predefined class list, increasing adaptability in novel or unstructured settings. This moves beyond traditional fixed-class semantic mapping, offering a more flexible and generalizable scene representation.
- **Improved Human-Robot Interaction and Task Planning:** The ability to query the map live with natural language (e.g., "fire extinguisher," "exit") facilitates more intuitive human-robot interaction. This directly impacts downstream tasks like exploration, inspection, and object search, allowing human operators to guide robot missions effectively and receive high-level, interpretable information from the robot.
- **Scalability for Large-Scale Operations:** The submap-based volumetric representation, coupled with efficient object-centric feature aggregation and robust SLAM with loop closures, enables FindAnything to operate in large-scale indoor and outdoor environments. This addresses a critical limitation of monolithic or voxel-level mapping approaches, which typically struggle with memory and computational overhead as map size increases.
- **Direct Application in Critical Domains:** The demonstrated utility in a simulated Search and Rescue (S&R) scenario highlights the immediate practical relevance of FindAnything. In disaster response, where MAVs can provide safety-critical information from hazardous areas, the system's ability to rapidly build semantically rich maps and locate specific items or areas is valuable.
- **Balanced System Design:** FindAnything achieves a balance between semantic accuracy, computational performance, and memory efficiency. The careful selection of foundation models (eSAM for segmentation, CLIP for VL features) and the proposed feature fusion strategy (weighted average, oversegmentation) contribute to this equilibrium, making it a viable solution for real-world robotic applications.
- **Foundation for Future Research:** The framework opens avenues for further research, including the incorporation of semantic priors and hierarchical map representations for more informed and intelligent exploration, as well as addressing the challenges of dynamic objects and people in the scene.

Overall, FindAnything contributes a practical and efficient methodology for integrating high-level semantic intelligence into robot mapping systems, extending their capabilities for autonomous operation and interaction in complex, real-world environments.
