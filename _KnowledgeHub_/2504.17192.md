# Paper2Code: Automating Code Generation from Scientific Papers in Machine Learning

> [!summary] Summary
> Researchers at KAIST developed PaperCoder, a multi-agent Large Language Model (LLM) framework that generates functional, repository-level code directly from machine learning scientific papers. This approach significantly outperforms existing LLM-based code generation methods, achieving an average score of 3.74 out of 5 on the Paper2CodeBench and requiring only 0.81% of code line modifications for successful execution.

## Problem

- A pervasive reproducibility crisis in machine learning, where only 19.5% of top-tier papers provide code, making validation and extension difficult.
- The process of manually reverse-engineering methods and experimental setups from textual paper descriptions is time-consuming and labor-intensive for researchers.
- Existing LLM-based code generation tools often rely on pre-existing implementations, partial code snippets, or defined APIs, failing to address the "cold start" problem of generating code solely from papers.

## Method

- PaperCoder employs a ==multi-agent, multi-stage LLM== framework that mimics human software development workflows, decomposing the process into Planning, Analysis, and Coding stages.
- The Planning stage generates structured abstractions like overall plans, ==architectural designs== (file lists, class/sequence diagrams), logic designs (ordered file lists, fine-grained specifications), and configuration files.
- The Analysis stage then iteratively processes each file to create detailed implementation guidelines, followed by the ==Coding stage== that generates the repository code sequentially using all accumulated context.

## Results

- PaperCoder consistently outperformed all baselines (ChatDev, MetaGPT, Abstract, Paper) on the Paper2CodeBench, achieving an average score of **3.74** (out of 5) compared to ChatDev's **2.97** and MetaGPT's **2.73**.
- On the PaperBench Code-Dev benchmark, PaperCoder achieved the highest replication score (**45.14%** with o3-mini-high), substantially outperforming existing agentic baselines (e.g., BasicAgent at **5.1%**).
- Generated repositories were near-executable, requiring an average of only **0.81%** of code lines to be modified for successful execution, and **92%** of human judges found the repositories "helpful" for reproduction.

## Takeaways

> [!tip] Key Insights
> - A structured, multi-stage pipeline effectively reduces the cognitive load on LLMs, enabling them to tackle complex, repository-level code generation tasks from scientific papers with higher accuracy.
> - Emulating human development practices, such as explicit planning for architecture and logic design, is crucial for producing cohesive and dependency-aware multi-file codebases.
> - The quality of code generation is highly dependent on the precision and detail within the paper's methodology section, underscoring the importance of comprehensive scientific descriptions.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

This research sits at the intersection of several rapidly evolving fields: machine learning reproducibility, large language models (LLMs) for code generation, and LLM-powered scientific discovery.

**Reproducibility in Machine Learning:** The paper highlights a critical and persistent challenge in machine learning research: the low availability of code implementations. Citing statistics that only 19.5% of papers at top-tier ML conferences in 2024 provide code, the authors underscore the significant hurdle this poses to scientific progress. Reproducibility is foundational for validating findings, building upon prior work, and accelerating innovation. The traditional process of reverse-engineering methods from papers is time-consuming and labor-intensive, slowing down research. PaperCoder directly addresses this gap by aiming to automatically generate runnable code, thus enhancing transparency and accelerating the pace of scientific discovery.

**LLMs for Code Generation:** Recent advancements in LLMs, such as GPT-4o, DeepSeek-Coder, and Qwen-Coder, have demonstrated remarkable capabilities in understanding natural language and generating high-quality code. Early work in code generation primarily focused on isolated tasks or short code snippets. However, with improved long-context reasoning abilities, the field has increasingly shifted towards "repository-level coding," which involves generating multi-file, modular, and dependency-aware codebases. Existing approaches in this domain, like ChatDev and MetaGPT, often employ multi-agent or role-based frameworks to simulate software development workflows, typically starting from natural language requirements or partial code.

**LLM-Powered Scientific Research:** Beyond general code generation, LLMs are increasingly being applied to accelerate various stages of the scientific process. This includes ideation (generating hypotheses, summarizing literature), experimental design, and even automated experimental validation. However, much of this prior work often *assumes access to pre-existing code implementations, partial snippets, or well-defined APIs*. This significantly limits their real-world applicability given the low code availability issue.

**Novelty of PaperCoder:** PaperCoder distinguishes itself by tackling the *underexplored task of generating faithful, repository-level code implementations directly from scientific papers, without relying on pre-existing code, APIs, or additional supplementary materials.* This is a crucial differentiator, as it directly confronts the challenge of sparse code availability. While concurrent work like PaperBench focuses on *evaluating* AI systems for paper reproduction, PaperCoder complements this by primarily focusing on the *methodological aspects* of how to achieve this transformation. By doing so, it pushes the boundaries of LLM capabilities from understanding structured requirements to interpreting complex, often ambiguously described, scientific methodologies in natural language papers and translating them into functional software systems.

### 2. Key Objectives and Motivation

The central motivation for PaperCoder stems from the severe challenges in reproducibility within machine learning research. As noted, a vast majority of published papers in top-tier conferences do not release their code, forcing researchers to expend significant time and effort in manually reverse-engineering methods. This impedes validation, collaboration, and the cumulative progress of science.

The key objectives of this work are:

1. **To develop a framework (PaperCoder) that automates the generation of operational code repositories directly from scientific papers in machine learning.** This aims to eliminate the need for manual code implementation or reverse-engineering, providing a direct path from published methodology to executable code.
2. **To ensure the generated code is "faithful,"** meaning it accurately implements the methods and experiments described in the source paper. This involves capturing not just the core algorithms but also experimental setups, hyperparameters, and evaluation protocols.
3. **To produce "repository-level" code,** meaning multi-file codebases that account for architectural design, modular structure, and inter-file dependencies, rather than isolated code snippets.
4. **To validate the effectiveness of PaperCoder** through extensive evaluations, including both automated model-based assessments (reference-based and reference-free) and expert human evaluations (specifically by the authors of the original papers).
5. **To establish a new benchmark (Paper2CodeBench)** for this novel task, drawing from recent machine learning conferences, and to demonstrate PaperCoder's strengths on existing benchmarks like PaperBench Code-Dev.

Ultimately, the overarching motivation is to **accelerate scientific progress** by making research findings more accessible, verifiable, and easier to build upon, thereby fostering an environment of open science and rapid experimentation.

### 3. Methodology and Approach

PaperCoder adopts a structured, multi-agent LLM-powered framework that emulates the human software development workflow by decomposing the complex paper-to-code task into three coordinated stages: Planning, Analysis, and Generation (Coding). Each stage is orchestrated by specialized LLM agents.

**Overall Task Decomposition:**
Given a paper R, the process is formalized as:
Planning: P = M_plan(R)
Analysis: A = M_analysis(R, P)
Coding: C = M_code(R, P, A)
where P represents the high-level plan, A the detailed analysis, and C the final code repository.

#### 3.1. Planning Stage

This initial stage transforms the unstructured textual content of a scientific paper into structured, implementation-level abstractions. This is crucial because papers are written for human communication, often containing high-level motivations and ambiguities from a software engineering perspective. The planning stage is further broken down into four sequential sub-components:

1. **Overall Plan:** The agent extracts a high-level summary of core components, functionalities, model components, training objectives, data processing steps, and evaluation protocols. This forms the foundational roadmap for subsequent steps.
2. **Architecture Design:** Based on the overall plan and paper, the agent defines the repository-level architecture. This involves generating a file list, outlining the overall file structure, a class diagram (detailing static representations of classes and attributes), and a sequence diagram (modeling dynamic interactions between modules). The aim is a coherent and maintainable structure.
3. **Logic Design:** This phase specifies *how* components should be instantiated by considering their execution flow and dependencies. It produces an *ordered file list* (dictating the sequence of implementation and execution) and elaborates on the fine-grained logic within each file, addressing module interdependencies.
4. **Configuration Generation:** The final planning step synthesizes a `config.yaml` file with key hyperparameters, model settings, and runtime options. This grounds the code generation process with explicit details and allows researchers to easily adjust experimental configurations.

#### 3.2. Analysis Stage

Following the high-level planning, the analysis phase focuses on detailed, implementation-level specifications for each module within each file. For each file identified during planning, an analysis agent iteratively generates a detailed analysis (`a_i`). This includes functional goals, input-output behaviors, intra- and inter-file dependencies, and algorithmic specifications derived from the original paper. This stage bridges the gap between abstract design and concrete implementation.

#### 3.3. Coding Stage

This is the final stage where the complete code repository is produced. Each file's code (`c_i`) is generated sequentially, according to the execution order determined in the logic design stage. The generation process leverages all accumulated contextual information from previous stages: the original paper, the overall plan, architecture design, logic design, configuration file, and file-specific analyses. This iterative, dependency-aware generation ensures consistency and completeness across the entire codebase.

**LLM Backbone:** The framework primarily uses `o3-mini-high` (an OpenAI model with high reasoning effort) as its default backbone LLM, acknowledging its strong code understanding and reasoning capabilities. The use of prompt templates (`T` functions) is central to instructing the LLM agents at each stage.

### 4. Main Findings and Results

PaperCoder demonstrates robust and superior performance across various evaluation metrics and benchmarks, highlighting its effectiveness in automating code generation from scientific papers.

- **Superior Performance on Paper2CodeBench:** On the newly introduced Paper2CodeBench (comprising 90 papers from ICLR, ICML, and NeurIPS 2024), PaperCoder consistently outperforms all baselines (ChatDEV, MetaGPT, Abstract, Paper) in both reference-based and reference-free model evaluations.
 - For **reference-based evaluation**, PaperCoder achieved average scores of 3.68 (ICLR), 3.72 (ICML), and 3.83 (NeurIPS), significantly higher than the best baseline (Paper) which scored around 3.08-3.28.
 - For **reference-free evaluation**, PaperCoder scored an impressive 4.73-4.77, which is statistically on par with the "Oracle" (author-released repositories) scores of 4.80-4.84, demonstrating its ability to generate code of comparable quality to human-authored implementations.
 - PaperCoder also generates substantially larger and more complex repositories (avg. 14,343 tokens, 6.97 files, 35.22 functions) compared to baselines, indicating a higher degree of completeness.
- **Strong Performance on PaperBench Code-Dev:** PaperCoder achieved the highest replication scores (45.14% with o3-mini-high, 51.14% with Claude 3.5 Sonnet) on the PaperBench Code-Dev benchmark, significantly outperforming its dedicated baselines (Basic Agent and Iterative Agent). This underscores its generalizability and robustness.
- **High Correlation between Model-Based and Human Evaluation:** A strong positive correlation (Pearson r=0.79) was observed between reference-based and reference-free model evaluations, suggesting that reference-free evaluation serves as a reliable proxy when ground-truth code is unavailable. Human evaluations, conducted by original paper authors, further validated PaperCoder's superiority, with it being ranked best and exhibiting strong correlation with model-based scores (e.g., Spearman r=0.78 for reference-based and 0.73 for reference-free with o3-mini-high). Inter-annotator agreement among human judges was high (Cohen's kappa = 0.79), ensuring the reliability of human feedback.
- **Effectiveness of Multi-Stage Pipeline (Ablation Studies):** Ablation studies confirmed that each component of PaperCoder (Overall Plan, Architecture Design, Logic Design, Configuration Generation, Analysis) contributes to the overall performance gains. The Logic Design stage was particularly critical for resolving issues arising from a purely architectural design by explicitly defining execution order and dependencies.
- **Benefits of Self-Refinement:** Augmenting planning and analysis phases with self-refinement steps (following Self-Refine) led to measurable improvements in their outputs and subsequent stages, reducing downstream errors.
- **Impact of LLM Backbone and Paper Quality:**
 - Proprietary LLMs (o3-mini-high) consistently outperformed open-source alternatives (DS-Coder, Qwen-Coder, DS-Distill-Qwen), emphasizing the importance of a capable backbone.
 - Papers with higher recognition (oral/spotlight) yielded slightly higher scores, suggesting clearer writing may correlate with easier code generation.
 - Removing the Methodology section from papers drastically reduced code quality (average score dropped from 4.26 to 3.75), highlighting the necessity of precise and explicit descriptions in the source paper.
- **Fine-Grained Analysis and Practical Utility:**
 - 92% of human annotators agreed that PaperCoder's top-ranked repositories would make reproduction easier than starting from scratch.
 - Component-level analysis showed high coverage for Method (80%) and Evaluation (79%) sections, with Data Processing being a more common source of errors due to underspecified details in papers.
 - Human judges preferred PaperCoder for its **completeness, clean structure, and faithfulness to the original papers**.
- **Near-Executable Code and Reproducibility:**
 - Manual execution evaluations on a subset of papers revealed that only a minimal average of 0.81% of code lines required minor modifications (e.g., API updates, data type mismatches) for successful execution, indicating near-executability with minimal human intervention.
 - LLM-assisted debugging could resolve most issues automatically (primarily syntactic or import-related errors), making the repositories even more robust.
 - Further experiments showed that PaperCoder's repositories, even with minimal debugging, were more capable of reproducing original experimental results than baselines.

### 5. Significance and Potential Impact

PaperCoder represents a significant step forward in the automation of scientific research, particularly within the fast-paced field of machine learning. Its potential impact is multifaceted:

- **Accelerating Scientific Discovery and Reproducibility:** By automating the conversion of scientific papers into runnable code, PaperCoder directly addresses the critical issue of reproducibility and code availability. This will drastically reduce the time and effort researchers spend reverse-engineering methods, allowing them to focus more on novel research and experimentation. Faster reproduction means faster validation, iteration, and ultimately, faster scientific progress.
- **Enhancing Open Science:** The framework facilitates open science practices by lowering the barrier to entry for researchers who wish to build upon existing work, even if the original authors did not release code. This promotes transparency, collaboration, and the democratization of research.
- **Advancing LLM Capabilities for Complex Tasks:** PaperCoder pushes the boundaries of what LLMs can achieve in complex, multi-faceted tasks. Moving beyond single-file code snippets or API-driven generation, it demonstrates the ability of LLMs to interpret extensive, unstructured scientific documents, perform high-level planning, detailed analysis, and synthesize entire functional software repositories. This showcases a deeper form of understanding and problem-solving in LLMs.
- **Pioneering Agentic AI Systems for Research:** The multi-agent, multi-stage architecture of PaperCoder provides a valuable blueprint for future agentic AI systems designed to tackle complex, open-ended research challenges. The structured decomposition of tasks, collaborative agents, and iterative refinement process can be adapted to other domains requiring sophisticated problem-solving.
- **Practical Utility for Researchers:** The high quality and near-executability of the generated code, coupled with positive human feedback from original paper authors, demonstrate PaperCoder's immediate practical value. It can serve as a robust starting point for implementing new ideas, benchmarking against existing methods, or simply understanding complex algorithms through their executable forms.
- **Ethical Considerations and Future Directions:** The authors responsibly acknowledge potential ethical risks, such as the unintended reproduction of code for sensitive or harmful research (e.g., jailbreaking). This highlights the need for safeguards like content filters and secure execution environments in real-world deployment. Future work could also extend PaperCoder to process visual inputs (figures, tables) from papers using advanced OCR models and expand its application beyond machine learning to other scientific domains where code is not the primary validation medium. Improving executability further, possibly with dedicated "DevOps" agents, also remains an important research avenue.

In conclusion, PaperCoder represents a significant stride towards automating a fundamental bottleneck in scientific research. Its innovative methodology and compelling results position it as a foundational work in the emerging field of AI-assisted scientific discovery, promising to accelerate the pace of innovation across machine learning and potentially beyond.
