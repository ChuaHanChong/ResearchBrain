# AgentSquare: Automatic LLM Agent Search in Modular Design Space

> [!summary] Summary
> AgentSquare automatically searches for LLM agent designs inside a modular space of four modules with uniform IO interfaces: Planning, Reasoning, Tool Use and Memory. It alternates module recombination and module evolution, and uses an in-context performance predictor to skip weak candidates. Across six benchmarks it beats the best hand-crafted agents by 17.2% on average.

## Problem

- Most LLM agents are hand-designed for specific tasks, relying on expert insight and heavy labor, and they adapt poorly to novel tasks.
- Prompt-rewriting methods and whole-code search such as ADAS cannot explicitly recombine strong modules discovered by different researchers in separate codebases.
- Evaluating each candidate agent is very expensive, for example about $60 for a single CoT agent on ALFWorld with GPT-4o, so large-scale search is economically unsustainable.

## Method

- A ==modular design space== with four module types (Planning, Reasoning, Tool Use, Memory) and ==standardized IO interfaces==, abstracted from 16 published agents into 1050 combinations, extensible with new modules.
- ==Module recombination== has an LLM propose new agents by swapping modules from the pool, while ==module evolution== uses an ==evolutionary meta-prompt== to program new modules from task descriptions and past performance.
- An ==in-context surrogate performance predictor== scores newly recombined agents from task description, module profiles and past results, so only promising candidates are run in the real environment.

## Results

- On six benchmarks (Webshop, ALFWorld, SciWorld, M3Tool, TravelPlanner, PDDL) with GPT-4o, AgentSquare scores **0.607**, **0.695**, **0.781**, **0.524**, **0.583**, **0.669**, beating every hand-crafted agent, **17.2%** on average over the best human design.
- It also beats module search, prompt search (OPRO) and ADAS baselines, for example ALFWorld **0.695** versus 0.634 for Bayesian and 0.543 for ADAS, with a steadier search trajectory.
- Ablations lower scores: on TravelPlanner, dropping recombination gives **0.280** versus **0.583** full, and dropping evolution lowers ALFWorld from **0.695** to **0.649**. The predictor tracks actual performance at about **0.025%** of full evaluation cost.

## Takeaways

> [!tip] Key Insights
> - Standardized module interfaces turn agent design into recombination of prior work, and even random module recombination beats prompt-level search, so constraining the search space matters more than unconstrained freedom.
> - Combining discrete recombination of existing modules with open-ended programming of new ones covers the space better than either alone, and recombination contributes the larger gain.
> - A cheap LLM surrogate that predicts candidate performance from past trials can replace most expensive real evaluations, making automated agent design affordable and yielding interpretable design insights.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

The development of LLM-powered autonomous agents has emerged as a rapidly expanding and critical area within AI. These agents, equipped with capabilities like reasoning, planning, and tool use, are poised to transform numerous domains, from web navigation and robotics to complex problem-solving. However, the current state of the art largely relies on human experts meticulously crafting agent architectures and prompts for specific tasks. This manual design process is inherently time-consuming, resource-intensive, and often lacks the adaptability required for novel or dynamically changing tasks.

This paper addresses a significant gap in this landscape by introducing an automated approach to LLM agent design. It builds upon and distinguishes itself from several existing lines of research:

- **Hand-crafted LLM Agents:** The foundational work in this area involves designing specific prompting strategies (e.g., Chain-of-Thought, Tree-of-Thoughts), memory mechanisms, or tool integration (e.g., Toolformer, HuggingGPT). While effective, these are individual, often monolithic designs. AgentSquare aims to move beyond this manual, task-specific paradigm.
- **Automated Prompt Optimization:** Recent works like OPRO (Optimizing Prompts by Reinforcement Learning) and Promptbreeder use LLMs to iteratively refine and optimize prompts for existing agents. These approaches primarily operate within the prompt space, offering limited flexibility in reconfiguring the underlying architectural components of an agent.
- **General Agent Search in Code Space:** More broadly, ADAS (Automated Design of Agentic Systems) proposes searching for entire agentic systems defined in code space. While powerful, this unconstrained search space can be vast and computationally expensive to explore efficiently.

AgentSquare carves out a unique niche by introducing **Modularized LLM Agent Search (MoLAS)**. Its core distinction lies in:
1. **Modularization:** It proposes a structured, modular design space, abstracting LLM agents into four fundamental, interoperable modules: Planning, Reasoning, Tool Use, and Memory. This modularity facilitates the recombination of successful components from diverse existing agents.
2. **Standardized Interfaces:** A crucial innovation is the definition of uniform Input/Output (IO) interfaces for these modules. This standardization is key to enabling seamless "plug-and-play" functionality, allowing modules from different research efforts to be combined, which current frameworks (like LangChain, AutoGPT) primarily offer at an operation-level, not a module-level search.
3. **Exploiting Prior Knowledge:** By defining a modular space, the framework implicitly leverages the collective intelligence embedded in previously published and evaluated agent designs. This allows for more targeted and efficient exploration compared to entirely unconstrained code-level search.

In essence, AgentSquare seeks to provide a principled, systematic approach to LLM agent design that is more adaptable than hand-crafted methods, more flexible than prompt-only optimization, and more efficient than unconstrained code search by focusing on reusable, composable building blocks. It is framed as a platform to "consolidate the collective efforts of the research community" by offering a standardized way to share and combine agent components.

### 2. Key Objectives and Motivation

The primary objectives and motivations behind the AgentSquare framework are driven by the limitations of current LLM agent development practices:

1. **Overcome Manual Design Limitations:** Existing LLM agents are predominantly hand-crafted, requiring significant human expertise, intuition, and labor. This manual approach is slow, prone to sub-optimal solutions, and struggles to scale or adapt to new tasks. The paper aims to automate this complex design process.
2. **Enhance Adaptability to Novel Tasks:** Manually designed agents are often highly specialized for particular tasks, making them difficult to generalize or adapt to new, unseen scenarios without extensive re-engineering. A key objective is to enable the discovery of agents that are more flexible and broadly applicable.
3. **Facilitate Module Reusability and Knowledge Accumulation:** There is a lack of a unified design framework for LLM agents, leading to fragmented research where successful components from one agent cannot be easily integrated or tested with others. The paper aims to propose a "modular design space" with "uniform IO interfaces" to address this, enabling convenient reuse of existing components and accumulating new discoveries as a community resource.
4. **Efficiently Explore a Vast Design Space:** The combination of various planning, reasoning, tool-use, and memory modules creates an enormous search space. The objective is to develop an efficient search algorithm that can navigate this space to find optimal or near-optimal agent configurations without prohibitive computational costs.
5. **Accelerate Agent Evaluation:** Evaluating LLM agents is often expensive and time-consuming, especially when interacting with real-world environments or complex APIs. A crucial motivation is to mitigate these costs to allow for larger-scale and more frequent evaluations during the search process.
6. **Generate Interpretable Design Insights:** Beyond just finding high-performing agents, the paper aims to provide insights into *why* certain modular combinations or newly evolved modules perform well, fostering a deeper understanding of effective agent architectures.

In summary, the core motivation is to transition LLM agent design from a largely artisanal, task-specific endeavor to a more automated, systematic, and community-driven process, ultimately unlocking the full potential of LLMs for complex, real-world applications.

### 3. Methodology and Approach

AgentSquare introduces a novel framework for Modularized LLM Agent Search (MoLAS), which operates on a structured modular design space and employs an iterative search algorithm.

#### 3.1. Modular Design Space (MoLAS)

The foundation of AgentSquare is its modular design space, abstracted from a comprehensive literature review of 16 popular LLM agents. This space categorizes existing LLM agent designs into four fundamental modules, each with a standardized Input/Output (IO) interface to ensure seamless integration and extensibility:

- **Planning Module (P):** Responsible for decomposing a given task into a sequence of sub-tasks. It takes a task description and optional feedback as input and outputs a plan (e.g., `{s1, s2, ..., sn}`).
- **Reasoning Module (R):** Executes sub-tasks sequentially, leveraging LLM's inherent reasoning capabilities. It takes a sub-task description and optional feedback as input and outputs a solution.
- **Tool Use Module (T):** Enables the agent to interact with external tools when internal LLM knowledge is insufficient. It takes a problem description and a predefined tool pool as input, selects the best-matched tool, and outputs the tool's response.
- **Memory Module (M):** Manages the agent's past thoughts, actions, and observations, allowing for dynamic storage and retrieval of relevant information during the reasoning process. It supports `write` (adding observations) and `retrieve` (retrieving knowledge) operations.

An LLM agent `A` is defined as a combination of these four modules: `A = (P, R, T, M)`. The problem of MoLAS is then formulated as an optimization problem: `arg max P∈P,R∈R,T∈T,M∈M Eval_d(P, R, T, M)`, aiming to find the module combination that maximizes performance for a given task `d`.

#### 3.2. AgentSquare Search Algorithm

AgentSquare tackles the challenges of a vast search space, open-ended module sets, and high evaluation costs using three core mechanisms:

- **Initialization:** The process begins by seeding a global experience pool with well-designed agents and their performance values. Modules from these initial agents populate the respective module pools `{P, R, T, M}\}$.
- **Module Evolution:** This mechanism focuses on creating *new* modules through "program-level optimization." An evolutionary meta-prompt, powered by an LLM (π_ξ), is used as a "module programmer." Inspired by FunSearch, this LLM proposes new module variants based on the target task, existing modules, and performance feedback from previous evaluations. For example, it might mutate an existing planning module into a new variant (P*). These newly created modules are then added to the module pools.
- **Module Recombination:** This mechanism focuses on strategically *combining existing* modules from the populated module pools. An LLM (π_θ) acts as a "self-adaptive proposer" that suggests promising new agent configurations by replacing modules of an initial agent with alternatives from the pool (e.g., replacing R0 with R' from the Reasoning module pool). This expands the search space beyond single-module modifications.

These two operations, module evolution and recombination, alternate iteratively. Module evolution broadens the solution space by generating novel module designs, while module recombination efficiently explores combinations within the expanded module pool.

- **Performance Predictor:** To address the high cost of evaluating LLM agents, AgentSquare incorporates an additional LLM (π_p) that functions as an "in-context surrogate model." This predictor estimates the performance of *newly proposed agents from the module recombination phase* (agents with existing modules) without requiring a full, expensive evaluation in the real environment. It leverages task descriptions, module profiles, and in-context performance examples from the experience pool to score candidate agents. New modules created during module evolution, however, are still evaluated in the real task environment to ensure accurate performance data for novel designs.

The algorithm iteratively generates a population of child agents through either evolution (generating new module code) or recombination (combining existing modules). The best-performing agents, either truly evaluated or predicted, are selected to guide the next iteration of the search process.

### 4. Main Findings and Results

The experiments conducted across six diverse benchmarks (Webshop, ALFWorld, SciWorld, M3Tool, Travelplanner, PDDL) spanning web, embodied, tool-use, and game applications demonstrate the effectiveness and superiority of AgentSquare. Key findings include:

1. **Superior Performance Against Hand-crafted Agents:** AgentSquare consistently discovered novel LLM agents that significantly outperformed best-known human-designed agents across all six benchmarks.
 - On average, AgentSquare achieved a **17.2% performance gain** compared to the best human designs. Specific improvements include 14.1% on Webshop, 26.1% on ALFWorld, 20.5% on SciWorld, 30.6% on M3Tool, and 6.0% on Travelplanner and PDDL (using GPT-4o).
 - The discovered agents also proved to be cost-efficient, striking a favorable performance-cost trade-off compared to baselines.

2. **More Efficient Search Trajectory:** AgentSquare demonstrated a steeper and more stable optimization trajectory compared to other search algorithms.
 - It consistently surpassed module-level search methods (Random, Bayesian) and prompt-level search methods (OPRO), indicating that searching in a modular design space (even with simple recombination) is more effective than prompt-only optimization.
 - It also outperformed ADAS, a more general agent search method, in achieving higher performance within a fixed LLM token budget, suggesting that the modular constraint helps guide the search more efficiently.

3. **Effectiveness of Core Mechanisms:**
 - **Module Evolution and Recombination:** Ablation studies confirmed that both module evolution (creating new modules) and module recombination (combining existing ones) are crucial. Removing either component led to a noticeable performance decline, with module recombination having a larger impact, suggesting its role in efficiently exploring the expanded search space.
 - **Performance Predictor:** Empirical validation showed a strong correlation between the predicted performance of agents and their actual real-world performance, demonstrating the effectiveness of the in-context surrogate model. This predictor significantly reduced evaluation costs (e.g., 0.025% of a full evaluation cost in ALFWorld), enabling larger-scale and more cost-efficient searches.

4. **Interpretable Design Insights and Novel Modules:** AgentSquare not only finds high-performing agents but also generates human-interpretable design insights for newly discovered modules.
 - For example, for ALFWorld, it discovered a best agent combining an existing memory module from "Generative Agents" with newly created planning (named TD, for "timeline-based approach") and reasoning (named SF-ToT, for "Self-reflection and Self-improvement Tree-of-Thoughts") modules.
 - Other notable discovered modules include HTSS (a hybrid Tree-of-Thoughts, Self-Consistency, Self-Refine reasoning module for Webshop), Hier (a hierarchical memory module for SciWorld), ToolBF (a "ToolbenchFormer" tool-use module for M3Tool), TH (a hierarchical tool-use module for Travelplanner), CASRC (Context-Aware Self-Refine Chain-of-Thought for PDDL), and IR (Iterative Refinement planning for PDDL). These examples highlight AgentSquare's ability to combine and innovate upon successful concepts from prior research.

### 5. Significance and Potential Impact

The AgentSquare framework and the Modularized LLM Agent Search (MoLAS) problem it introduces represent a significant step forward in the field of LLM agent research, with several profound implications and potential impacts:

1. **Accelerating LLM Agent Development:** By automating the architectural design and optimization of LLM agents, AgentSquare can drastically reduce the time, effort, and expert intuition currently required for their creation. This will enable faster iteration cycles and deployment of sophisticated agents in various applications.
2. **Democratizing Agent Design:** The framework moves beyond the need for deep expert knowledge in designing complex agentic systems. By providing a structured search mechanism, it opens up the possibility for a wider range of researchers and developers to create high-performing LLM agents, lowering the barrier to entry.
3. **Fostering Collaborative AI Research:** The proposed modular design space with standardized IO interfaces is a crucial contribution. It acts as a common language and platform for the research community, allowing researchers to easily share, combine, and build upon each other's successful module designs. This could lead to a more consolidated and cumulatively progressive research paradigm for LLM agents, transforming the field from disparate, individual agent designs to a more systematic, component-based engineering discipline.
4. **Unlocking New Agent Capabilities:** By enabling efficient exploration of a vast modular design space, AgentSquare has the potential to discover novel agent architectures and module combinations that might be non-intuitive or too complex for human designers to conceive manually. This could lead to agents with emergent capabilities or superior performance on challenging, real-world tasks.
5. **Cost-Efficiency in AI Development:** The performance predictor mechanism significantly reduces the computational and API costs associated with evaluating candidate agents during the search process. This makes the automated search process economically viable for larger-scale and more frequent experiments, accelerating discovery without prohibitive expenses.
6. **Interpretability and Design Insights:** The ability to generate human-interpretable design insights from the discovered best agents is invaluable. It not only demonstrates the "why" behind performance gains but also provides actionable knowledge that can guide future manual or automated agent design efforts, leading to a deeper understanding of effective LLM agent architectures.

In conclusion, AgentSquare shifts the paradigm of LLM agent development from a predominantly artisanal craft to a more systematic, automated, and collaborative engineering discipline. Its modular approach, efficient search algorithm, and cost-effective evaluation promise to accelerate the advancement of LLM-powered autonomous agents, making them more adaptable, performant, and accessible for real-world applications.
