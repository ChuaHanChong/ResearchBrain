# Executable Code Actions Elicit Better LLM Agents

> [!summary] Summary
> The CodeAct framework unifies LLM agent actions into executable Python code, enabling dynamic interaction, self-correction, and leveraging the Python ecosystem. This approach significantly improves task success rates and efficiency for LLM agents on complex multi-tool tasks, with the open-source CodeActAgent demonstrating strong performance on agentic benchmarks while retaining general LLM capabilities.

## Problem

- Traditional LLM agent action formats (text, JSON) offer limited flexibility, constraining action space and struggling to express complex logic like conditional flows or loops for multi-step tasks.
- Existing code generation approaches for LLM agents often treat code as a static output, lacking the ability for dynamic adjustment, multi-turn interaction, or self-debugging based on execution feedback, or for fully utilizing existing software packages.
- There is a performance gap between open-source and proprietary LLMs in complex agent tasks, hindering broader adoption and research in the open-source community.

## Method

- The **CodeAct** framework unifies LLM agent actions into ==executable Python code==, enabling agents to emit and execute code, receive observations, and dynamically revise actions in a multi-turn interaction loop.
- A new benchmark, ==M³ToolEval==, was curated to evaluate CodeAct's effectiveness in complex multi-tool, multi-turn scenarios requiring control and data flow.
- An open-source LLM agent, **CodeActAgent**, was instruction-tuned using ==CodeActInstruct==, a high-quality dataset of agent-environment interaction trajectories, and integrates with a Python interpreter to execute code and receive real-time results or error messages.

## Results

- CodeAct achieved up to a **20.7%** absolute improvement in task success rates and required **2.1** fewer turns on average for `gpt-4-1106-preview` on complex multi-tool tasks (M³ToolEval) compared to text or JSON action formats.
- CodeActAgent (**7B** parameters) consistently outperformed other open-source LLMs on both in-domain and out-of-domain agent tasks, showing competitive performance to much larger **70B** models in some scenarios, and demonstrated autonomous self-debugging via execution tracebacks and use of packages like Pandas and Scikit-Learn.
- Fine-tuning with CodeActInstruct and general conversation data did not compromise CodeActAgent's performance on standard general LLM benchmarks (e.g., MMLU, HumanEval, GSM8K) and often showed slight improvements.

## Takeaways

> [!tip] Key Insights
> - Executable Python code expands the action space for LLM agents, enabling complex logic with control and data flow and allowing agents to directly leverage the vast existing Python software ecosystem (e.g., Pandas, Matplotlib) without requiring custom tool development.
> - Integrating code execution with an interpreter enables LLM agents to receive real-time feedback, including error messages, facilitating autonomous self-debugging and multi-turn refinement of actions.
> - Instruction tuning with high-quality agent-environment interaction data can bridge the performance gap for open-source LLMs in complex agentic tasks while preserving general LLM capabilities.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

The rapid advancement of Large Language Models (LLMs) has opened new avenues for artificial intelligence, extending their capabilities beyond mere text generation to performing actionable tasks in various environments. This shift has led to the emergence of "LLM agents," which are LLMs augmented with the ability to interact with external tools, memories, and physical environments.

Historically, LLM agents have primarily relied on generating actions in pre-defined text or JSON formats. While these methods have enabled basic tool invocation (e.g., calling APIs), they suffer from significant limitations:
- **Constrained Action Space:** Actions are often tailored for specific tasks, limiting their generalizability across diverse real-world problems.
- **Restricted Flexibility:** JSON or simple text formats struggle to express complex logic, such as composing multiple tools, handling conditional flows (if-statements), or iterating through data (for-loops) within a single action. Each tool call typically requires a separate, explicit generation.
- **Limited Dynamic Adaptation:** Many existing approaches struggle to dynamically adjust or emit new actions based on immediate environmental observations or feedback, which is crucial for complex, multi-step problem-solving and self-correction.

Concurrent research has explored using code generation (e.g., Python) for problem-solving (e.g., Code4Struct, PaL, Meta-GPT, code-as-policy, Voyager). However, many of these efforts treat code as a static sequence of actions, failing to fully leverage the interactive nature of programming. They often rely on heavy prompt engineering for specific tasks and lack the ability to dynamically adjust actions in multi-turn interactions or self-debug based on execution feedback. Voyager (Wang et al., 2023a) is a notable exception that performs iterative prompting to fix code errors, but it is often constrained to function definitions rather than dynamic atomic actions, and requires significant prompt engineering.

"Executable Code Actions Elicit Better LLM Agents" directly addresses these limitations by proposing **CodeAct**, a novel framework that unifies LLM agent actions into executable Python code. This positions the work at the forefront of LLM agent development, bridging the gap between static code generation and dynamic, interactive, and intelligent agent behavior. By leveraging Python's inherent control and data flow capabilities, and integrating with an interpreter, CodeAct aims to unlock the full potential of LLMs to act as versatile and adaptive agents in complex, real-world scenarios, while also contributing an open-source solution (CodeActAgent) to democratize these advanced capabilities.

### 2. Key Objectives and Motivation

The core objective of this research is to **effectively expand the action space of LLM agents for solving complex real-world problems**. The authors are motivated by the inherent limitations of conventional text and JSON-based action formats, which restrict the complexity and flexibility of tasks LLM agents can perform.

The specific motivations and objectives for proposing CodeAct are:

1. **Unifying Action Space:** To consolidate diverse agent actions (tool invocation, robot control, data processing) into a single, general-purpose, and flexible format: executable Python code.
2. **Enabling Dynamic Interaction and Self-Correction:** To allow LLM agents to execute code actions, receive real-time observations (e.g., execution results, error messages), and dynamically revise prior actions or emit new ones through multi-turn interactions. This is crucial for robust problem-solving and self-debugging.
3. **Leveraging Existing Software Ecosystems:** To enable LLM agents to directly utilize the vast array of existing Python packages and libraries, thereby expanding their capabilities far beyond handcrafted, task-specific tools. This significantly reduces the need for custom tool creation.
4. **Capitalizing on LLMs' Pre-training in Code:** To exploit the extensive exposure of modern LLMs to code data during their pre-training, making code generation a more "natural" and cost-effective approach for action representation compared to specialized JSON or text formats.
5. **Facilitating Complex Logical Operations:** To harness Python's native support for control flow (e.g., `if-statements`, `for-loops`) and data flow (storing intermediate results in variables), allowing LLMs to compose multiple tools and perform intricate logical operations within a single, coherent piece of code.
6. **Building Open-Source Agent Capabilities:** To create an open-source LLM agent, **CodeActAgent**, specifically instruction-tuned with CodeAct principles, to democratize these advanced capabilities and foster further research and application in the agent community. This includes developing a high-quality instruction-tuning dataset, **CodeActInstruct**, to achieve this goal.

### 3. Methodology and Approach

The methodology centers around the proposed **CodeAct framework** and its empirical validation, followed by the development of an open-source agent.

#### 3.1. CodeAct Framework

CodeAct redefines an LLM agent's "action" as a piece of executable Python code. This is integrated with a Python interpreter. In a multi-turn interaction framework (involving agent, user, and environment), the agent receives observations (user instructions, code execution results), plans its next step (e.g., Chain-of-Thought), and emits an action as Python code. The environment executes this code, and its output (results or errors) becomes the next observation for the agent, enabling a dynamic loop of action and observation. The choice of Python is motivated by its popularity and rich ecosystem of open-source packages.

#### 3.2. Empirical Validation of CodeAct

The authors conduct extensive experiments with 17 off-the-shelf LLMs (both open-source and proprietary) to compare CodeAct against JSON and text-based action formats.

- **Atomic Tool Use (API-Bank):** To assess LLMs' familiarity with code, they re-purpose API-Bank (Li et al., 2023) to test the generation of single, atomic tool calls in Python function call format (CodeAct), JSON object, or pre-defined text format. This experiment isolates the "code familiarity" advantage by largely ablating control and data flow.
- **Complex Tool Use (M³ToolEval):** To demonstrate CodeAct's benefits from control and data flow, the authors curate a new benchmark, M³ToolEval. This benchmark consists of 82 human-curated tasks across diverse domains (web browsing, finance, science, etc.) that require *multiple calls to multiple tools in multi-turn interactions*, often involving intricate coordination and composition. Models are allowed up to 10 interaction turns to solve problems by generating functional Python code or proposing an answer. Success rate and average number of turns are the key metrics.

#### 3.3. Empowering Open-source LLM Agents (CodeActAgent)

Recognizing the performance gap between open-source and closed-source LLMs, the authors aim to improve open-source models' CodeAct capabilities through instruction tuning.

- **CodeActInstruct Dataset Collection:**
 - **Agent-Environment Interaction Use Cases:** Trajectories (multi-turn interactions) are generated for four main use cases:
 - **Information Seeking:** Using HotpotQA (Yang et al., 2018), LLMs search for information via a Wikipedia search API (Python function).
 - **Software Package Usage:** From APPS (Hendrycks et al., 2021a) for code generation (importing packages, defining functions) and MATH (Hendrycks et al., 2021b) for math problems (using `sympy`).
 - **External Memory:** From WikiTableQuestions (Pasupat & Liang, 2015), tweaked into SQL-based (using `sqlite3`) and Pandas-based tasks.
 - **Robot Planning:** Using ALFWorld (Shridhar et al., 2020), an embodied environment simulator, with robot-control APIs (Python functions) and in-context demonstrations for `for-loops` and `if-statements`.
 - **Data Down-sampling:** Only the most challenging instances from each dataset are kept to enhance efficiency and focus on hard problems.
 - **Repurposing for Multi-turn:** Single-turn problems are adapted into multi-turn interactions, allowing LLMs to test solutions and self-debug before final submission.
 - **Trajectory Generation:** `gpt-3.5-turbo-0613` (and `gpt-4-0613` for unsolved problems) is used to generate interaction trajectories, often leveraging the MINT evaluation framework.
 - **Data Selection Heuristic:** A high-quality subset of generated trajectories is selected, specifically promoting instances where the model initially errors but self-corrects in later interactions ("self-improving" behavior).
- **Training CodeActAgent:**
 - CodeActAgent is fine-tuned from Llama-2 7B (Touvron et al., 2023) and Mistral 7B (Jiang et al., 2023) using a mixture of **CodeActInstruct** (7k multi-turn trajectories) and **general conversation data** (sub-sampled OpenOrca, ShareGPT, CapyBara).
 - Full-parameter supervised fine-tuning is performed with specific hyperparameters (sequence length, learning rate, epochs, batch size).
- **Evaluation of CodeActAgent:**
 - Evaluated on a diverse range of agent tasks using CodeAct (MINT - in-domain and out-of-domain, M³ToolEval) and text actions (MiniWob++, ScienceWorld) to test generalization.
 - General LLM capabilities are also assessed using standard benchmarks: MMLU (knowledge QA), HumanEval (single-turn code-gen), GSM8K (math reasoning), and MT-Bench (instruction-following).
 - Ablation studies are performed to understand the contribution of CodeActInstruct and general conversations.

### 4. Main Findings and Results

The research presents compelling evidence supporting the advantages of CodeAct and the effectiveness of CodeActAgent.

#### 4.1. CodeAct vs. Text/JSON Actions

- **Atomic Tool Use (API-Bank):** CodeAct generally achieves comparable or better performance than JSON and text formats even for simple, atomic tool calls. This is particularly pronounced for open-source LLMs, suggesting their pre-training on code data makes CodeAct a more natural fit. Closed-source models also perform well with JSON, possibly due to explicit fine-tuning.
- **Complex Tool Use (M³ToolEval):** This is where CodeAct's strengths truly shine.
 - **Higher Success Rates:** CodeAct yields significantly higher task success rates (outperforming alternatives in 12 out of 17 evaluated LLMs). The best model, `gpt-4-1106-preview`, achieved a **20.7% absolute improvement** over the next best action format (text).
 - **Fewer Interaction Turns:** CodeAct requires a lower average number of turns to complete tasks (better in 12 out of 17 LLMs), indicating greater efficiency in problem-solving. For `gpt-4-1106-preview`, it required **2.1 fewer turns** on average.
 - **Scalability with LLM Capability:** The performance gains of CodeAct become more pronounced as the capabilities of the underlying LLMs increase.
 - **Open-source vs. Closed-source Gap:** While CodeAct improves open-source models, a substantial performance gap remains between the best open-source (13.4%) and closed-source (74.4%) models on M³ToolEval, highlighting the need for further improvement in open-source LLMs for complex, zero-shot tasks.

#### 4.2. CodeAct Benefits from Multi-turn Interaction and Existing Software

- **Leveraging Python Ecosystem:** CodeActAgent, when integrated with a Python interpreter, demonstrates the ability to perform sophisticated tasks (e.g., model training, data visualization) by autonomously importing and utilizing existing Python packages like Pandas, Scikit-Learn, and Matplotlib. This eliminates the need for user-provided or custom-crafted tools.
- **Autonomous Self-Debugging:** The interactive nature of CodeAct allows agents to receive automated error messages (e.g., tracebacks) from code execution. This feedback enables the LLM agent to "self-debug" and rectify errors in multi-turn interactions, significantly improving task completion without requiring explicit in-context demonstrations.

#### 4.3. CodeActAgent Performance

- **Excellence in CodeAct Tasks:** CodeActAgent (both Llama-2 and Mistral variants) consistently outperforms other open-source LLMs on both in-domain and out-of-domain MINT agent tasks. The Mistral variant of CodeActAgent shows significant improvement on M³ToolEval, performing comparably to 70B models despite being 7B parameters. An anomaly was noted for Llama-2 variant on M3ToolEval, potentially due to pre-training data artifacts or weaker fundamental capabilities.
- **Generalization to Text Actions:** CodeActAgent (LLaMA2, 7B), despite not being explicitly optimized for text actions, achieves performance comparable to models specifically tuned for text actions (e.g., AgentLM-7B) on out-of-domain tasks like MiniWob++ and ScienceWorld. This indicates good generalization capabilities across action formats.
- **Maintaining General LLM Capabilities:** Crucially, fine-tuning with CodeActInstruct and general conversations does not compromise the CodeActAgent's performance on a diverse suite of general LLM tasks (MMLU, HumanEval, GSM8K, MT-Bench), and often even shows slight improvements.
- **Ablation Study:** Both CodeActInstruct and general conversation data are found to be essential. CodeActInstruct specifically contributes to agent task performance, while general conversations are vital for maintaining strong performance across general LLM tasks.

### 5. Significance and Potential Impact

The introduction of CodeAct and CodeActAgent represents a significant step forward in the development of capable and versatile LLM agents, with profound implications across several dimensions:

1. **Unified and Flexible Action Space:** CodeAct standardizes the action space for LLM agents to executable Python code, offering unparalleled flexibility. This unification simplifies the development of agents by removing the need for diverse parsing and tool creation efforts tailored to specific tasks or formats (JSON, text). This flexibility allows for complex logical constructs like loops and conditionals, enabling single actions to encapsulate intricate multi-step processes.

2. **Enhanced Problem-Solving through Dynamic Interaction:** The integration of CodeAct with a Python interpreter enables a powerful multi-turn interaction loop. Agents can generate code, observe execution results (including error messages), and dynamically self-correct or refine their actions. This "self-debugging" capability mimics how human programmers iteratively solve problems and is crucial for tackling real-world challenges that rarely yield to a single, perfect first attempt.

3. **Leveraging the Rich Python Ecosystem:** By allowing LLMs to directly utilize existing Python packages (e.g., Pandas, Scikit-Learn, Matplotlib), CodeAct massively expands the functional capabilities of LLM agents. Instead of requiring developers to hand-craft APIs for every new function, agents can tap into the vast, readily available, and well-documented software ecosystem, greatly reducing development effort and accelerating the deployment of agents in diverse domains like data science, scientific research, and robotics.

4. **Advancing Open-Source LLM Agents:** The release of CodeActInstruct, a high-quality, diverse instruction-tuning dataset focusing on agent-environment interactions and self-improvement, is a major contribution to the open-source community. CodeActAgent, fine-tuned on this data, demonstrates that open-source models can achieve significantly improved agentic capabilities without compromising their general performance, thus democratizing access to more advanced LLM agents and fostering further research in this domain.

**Potential Societal Consequences and Limitations:**

- **Labor Market Impact:** The development of more powerful, autonomous LLM agents, as exemplified by CodeActAgent, has the potential to transform the labor market by automating a wider range of tasks previously requiring human intervention. While this could lead to increased productivity, it also raises concerns about job displacement and the need for workforce reskilling, as discussed in prior work (Eloundou et al., 2023).
- **Safety and Control:** Granting LLM agents direct access to execute code in a sandbox environment, while powerful, introduces inherent risks. There's a critical need for robust safety mechanisms to prevent agents from breaking sandbox restrictions and causing unintended harm through cyber-attacks or other malicious actions, a concern highlighted by recent research (Tang et al., 2024). This work acknowledges CodeActAgent as a prototype and emphasizes the importance of future work in designing better safeguards.
- **Hallucination and Alignment:** Like all LLMs, CodeActAgent may suffer from hallucinations, imagining variable content or generating incorrect code. This underscores the ongoing need for further alignment techniques (e.g., human feedback) to ensure the agent's behavior is reliable and adheres to user intentions.
- **Scalability of Self-Improvement:** While CodeActAgent demonstrates self-debugging, the full potential of iterative self-improvement through extensive environmental interaction remains an active research area. Future work can build upon CodeActAgent to develop agents that continually learn from their mistakes in more complex and open-ended environments.

In conclusion, "Executable Code Actions Elicit Better LLM Agents" presents a foundational shift in how LLM agents interact with the world, moving towards a more flexible, dynamic, and powerful code-based paradigm. This research not only empirically validates the superiority of executable code actions but also provides crucial open-source resources, pushing the boundaries of what LLM agents can autonomously achieve while simultaneously raising important considerations for their safe and ethical deployment.
