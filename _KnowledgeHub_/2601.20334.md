# Demonstration-Free Robotic Control via LLM Agents

> [!summary] Summary
> FAEA (Frontier Agent as Embodied Agent) applies an unmodified Claude Agent SDK ReAct loop to robotic manipulation, treating control as iterative program synthesis: the agent writes Python scripts, executes them in simulation, and refines from privileged-state feedback without demonstrations or fine-tuning. It reaches 84.9% on LIBERO, 85.7% on ManiSkill3, and 96% on MetaWorld, approaching VLAs trained on demonstrations.

## Problem

- VLA policies demand task-specific demonstrations and fine-tuning for every new task or environment, and stay brittle, dropping from 95% to below 30% under modest perturbations.
- LLM-robot pipelines like VoxPoser, Code-as-Policies and SayCan each rebuild agent infrastructure with handcrafted API abstractions and platform-specific prompting, so engineering insight does not transfer across systems.
- Frontier multimodal models plan well but fail at low-level manipulation, and no prior study tested whether unmodified production agent SDKs transfer to embodied control.

## Method

- **FAEA** wraps the unmodified ==Claude Agent SDK== ==ReAct loop==: reason about the task, write a Python episode script, execute it through the Gymnasium interface, observe results, refine until success.
- An ==iterative program-synthesis== formulation samples each script from the LLM conditioned on instruction, tool set, and accumulated context of prior scripts, observations and success flags, with no gradient updates.
- One shared prompt template, plus an optional human-coaching variant of manipulation heuristics, and post-hoc automated ==trace validation== flagging hardcoded coordinates, exhaustive search, or bypassed task semantics.

## Results

- Demonstration-free FAEA scores **84.9%** on LIBERO's 120 tasks and **88.2%** with coaching, against **86.0%** for pretrained pi-0 and **88.75%** for SmolVLA 2.25B.
- ManiSkill3 gives **85.7%** over 14 tasks and 5 seeds, matching or beating Diffusion Policy and ACT trained on 100 demos; MetaWorld reaches **96%** versus SmolVLA's **68.2%**.
- Transferring LIBERO coaching tips to ManiSkill drops success to **81.4%** and raises cost **47%** (**$150** to **$220**); sub-centimeter PegInsertion stays at **0%** throughout.

## Takeaways

> [!tip] Key Insights
> - Test-time iteration can substitute for demonstration data when execution feedback is cheap and reliable, shifting manipulation from policy learning toward in-context program discovery.
> - Prompt coaching is task-specific, not universal: heuristics tuned on one benchmark actively degrade another while inflating cost, so treat them as overfitting.
> - Deliberative agents fit seconds-scale task planning, not millisecond precision control; privileged state and multi-minute latency bound the result to simulation and trajectory generation.

## Detailed Report

### 1. How This Work Fits into the Broader Research Landscape

This research is situated within the evolving field of robotic manipulation, specifically at the intersection of large language models (LLMs) and embodied AI. Historically, learning-based robotic policies have largely relied on extensive datasets of expert demonstrations, fine-tuning, and specialized execution pipelines. This paradigm, exemplified by Vision-Language-Action (VLA) models such as RT-1, RT-2, the $\pi$ series, NVIDIA's GR00T N1, OpenVLA, and SmolVLA, has achieved high performance but incurs significant data collection and engineering costs for each new task or environment. These models can also exhibit brittleness and poor generalization under domain shifts.

A distinct line of research integrates LLMs into robotics through custom pipelines. These approaches use LLMs for high-level planning, code generation, or feedback loops, as seen in projects like VoxPoser, Code-as-Policies, SayCan, Inner Monologue, ProgPrompt, and MALMM. While these systems leverage LLM reasoning, they typically necessitate the development of task- or platform-specific agent infrastructure, including custom prompt engineering, error recovery mechanisms, tool interfaces, and execution loops. This fragmentation limits the transferability of engineering insights and capabilities. Proprietary approaches, such as Gemini Robotics, also combine vision-language models with action models, often requiring robotics-specific fine-tuning.

The present work, FAEA (Frontier Agent as Embodied Agent), diverges from these established approaches by investigating whether *general-purpose LLM agent frameworks*, originally developed for software engineering tasks, can be directly applied to embodied manipulation without modification. This shifts the focus from learning policies through large-scale data collection or building bespoke robotics-specific agent systems, to leveraging the inherent iterative reasoning and program synthesis capabilities of frontier LLM agents for discovering manipulation strategies. The paper posits that production-grade agent SDKs (e.g., Claude Agent SDK, OpenAI Assistants API, Gemini ADK, LangChain), which feature robust architectures like the ReAct pattern for interleaving reasoning and action, context management, error handling, and execution tracing, could provide the necessary control structure for partially observable embodied environments. This contrasts with many robotics research prototypes that often lack such mature infrastructure.

Furthermore, previous benchmarking efforts like Embodied-Bench have highlighted that native frontier MLLMs excel at high-level planning but struggle with low-level, real-time control. FAEA addresses this by delegating low-level control to simulator-provided motion primitives, allowing the LLM agent to focus on task decomposition and program refinement at a deliberative timescale. The research thus explores a complementary question: can advanced MLLM agents generate successful manipulation trajectories without demonstration data by leveraging their ability to iterate through multiple trials and refine strategies in-context? This reframing emphasizes policy discovery through iterative program synthesis rather than policy learning from demonstrations.

### 2. Key Objectives and Motivation

The primary motivation behind this research stems from the inherent challenges and resource demands of current learning-based robotic manipulation policies. These policies typically require substantial task-specific demonstrations, meticulous fine-tuning, and the development of specialized execution pipelines. These prerequisites translate into significant data-collection and engineering costs, hindering the agile adaptation of robots to new tasks or diverse environmental conditions. The authors seek to address these limitations by exploring an alternative control paradigm.

The central objective of this work is to determine if a general-purpose language model agent can effectively perform robotic manipulation tasks by leveraging its existing reasoning and tool-use capabilities, thereby circumventing the need for task-specific demonstrations or specialized robotics training. This inquiry proposes a shift from data-intensive policy learning to an iterative process of policy discovery through program synthesis.

To systematically investigate this overarching objective, the study articulates three specific claims for evaluation:
1. **Demonstration-Free Program Discovery:** To ascertain whether a single, unmodified LLM agent and model can autonomously discover manipulation programs without requiring any expert demonstrations. This challenges the conventional wisdom that robotic manipulation necessitates pre-recorded examples.
2. **Cross-Simulator Transferability:** To evaluate if the same fundamental prompt structure and agent reasoning loop can be transferred across different simulation environments, specifically under the controlled conditions of privileged state access and Cartesian control. This claim aims to test the generality of the agent's reasoning framework rather than its perception or low-level motor control.
3. **Trajectory Generation for Data Augmentation:** To demonstrate that successful manipulation programs discovered by the agent can be leveraged to generate valid simulation trajectories. This capability is presented as a potential solution to the data bottleneck in embodied learning, offering a method for automated training data augmentation for VLA models.

The authors explicitly state that this work does not claim generality across different agent frameworks or the direct transferability to physical hardware, thereby bounding the scope of their immediate conclusions.

### 3. Methodology and Approach

FAEA (Frontier Agent as Embodied Agent) implements an unmodified, general-purpose LLM agent framework, specifically the Claude Agent SDK, for robotic control in simulation environments. The core methodological insight is that the iterative reasoning and error-recovery mechanisms native to software engineering agents can be directly applied to refine manipulation strategies.

The approach conceptualizes robotic manipulation as an iterative program synthesis problem. Given a task instruction ($\ell$) and a set of available tools ($\mathcal{T}$), the agent generates a sequence of Python scripts ($\sigma_i$). Each script consists of a series of tool invocations designed to achieve the task. Following each script's execution in the simulation, the agent receives observations (error messages, success signals, visual feedback) and evaluates the terminal state ($E(s^{(i)}_{T_i})$). This feedback, along with previous attempts, is accumulated into an in-context history ($C_i$), which informs the generation of subsequent scripts. Crucially, this process involves no gradient updates to the underlying LLM; policy discovery occurs through in-context program synthesis and iterative refinement.

**Prompting and Agent Architecture:**
The agent is initialized using a structured prompt template (Figure 1), which defines its role as a robotics control expert, specifies success criteria, and outlines expected outputs. Two variants were evaluated: a baseline FAEA utilizing the core template, and an enhanced version incorporating "coaching tips." These coaching tips were high-level manipulation heuristics derived from analyzing preliminary failure cases (e.g., maintaining gripper height, considering gripper orientation). The Claude Agent SDK orchestrates the core ReAct loop: the agent reasons about the task, writes or refines a Python script, executes it in the simulation, and observes the results to adjust its approach.

**Trace Validation:**
To ensure the integrity of the results, successful execution traces were post-hoc validated using Claude Code. This automated review flagged suspicious patterns, such as hardcoded coordinates derived from simulator internals, exhaustive grid searches, or solutions that bypassed intended task semantics. Two MetaWorld traces flagged by this process were excluded from the results.

**Simulation Interface and Observation Modality:**
The agent autonomously interacts with the simulation environments (LIBERO, ManiSkill3, MetaWorld) by reading Gymnasium documentation. It identifies and utilizes standard APIs such as `step(action)`, `reset()`, `check_success()`, and `get_obs()` to generate Python control scripts. The authors configured each simulator and exposed its API. A key constraint is the use of absolute end-effector Cartesian position control across all benchmarks, limiting direct conclusions about transferability to other control interfaces.
FAEA operates with privileged ground-truth state observations (object positions, gripper state) obtained via `get_obs()`, rather than raw RGB images. This design choice isolates the agent's capability for strategic policy discovery from the complexities of real-world perception. This also positions FAEA as a potential tool for generating synthetic trajectories to augment VLA training data.

**Model Selection:**
All experiments were conducted using Claude Opus 4.5 (claude-opus-4-5-20251101), chosen as the best available model within the authors' budget and given anticipated future cost-effectiveness of such models.

**Benchmarks:**
The evaluation involved three benchmarks:
- **LIBERO:** Comprising 120 long-horizon manipulation tasks across four suites (Spatial, Object, Goal, Long-horizon), utilizing a Franka Panda robot. This benchmark was used for initial prompt development and exploring coaching strategies.
- **ManiSkill3:** Featuring 14 manipulation tasks with extensive domain randomization, designed to test generalization to visual and physical variations.
- **MetaWorld:** Consisting of 50 tabletop manipulation tasks, employing a Sawyer robot. This benchmark tested transfer to a different robot arm and simulation environment.

**Experimental Progression on LIBERO:**
A pilot study with a 10-trial cap and minimal prompting achieved 70.6% success. The baseline condition removed this cap, allowing the agent to iterate until success or self-termination, leading to recovery of some initially failed tasks. Finally, a "human coaching" variant incorporated manually identified high-level heuristics into the prompt, further optimizing performance.

### 4. Main Findings and Results

The research paper presents empirical results across three distinct simulation benchmarks, demonstrating the capabilities of the FAEA framework in demonstration-free robotic control.

**Performance on LIBERO Benchmark (Table I):**
On the LIBERO benchmark, FAEA demonstrated iterative learning capabilities. A pilot study with a 10-trial cap yielded a 70.6% success rate across 120 tasks. Removing the trial cap for the baseline FAEA condition improved the overall success rate to 84.9%. This performance level was competitive with certain VLA models (e.g., $\pi_0$ pretrained at 86.0%) that utilize limited LIBERO fine-tuning data, notably without requiring any demonstrations. When augmented with human-provided coaching tips, FAEA's performance further increased to 88.2%, approaching the success rate of SmolVLA (88.75%). It is important to note that these comparisons are contextual, as FAEA utilized privileged state observations, while VLA baselines typically use RGB images, and inference protocols differed.

**Performance on ManiSkill3 Benchmark (Table II & VI):**
FAEA was evaluated on ManiSkill3, a benchmark incorporating domain randomization to test generalization. Across 5 seeds and 14 tasks (70 total trials), the baseline FAEA achieved an 85.7% success rate. This performance often matched or exceeded imitation learning baselines trained with 100 demonstrations, particularly on coarse manipulation tasks (e.g., 100% success for PickCube, PushCube, StackCube, compared to 76-100% for Diffusion Policy with 100 demos). However, tasks requiring sub-centimeter precision, such as PegInsertion and PlugCharger, remained challenging for FAEA, resulting in 0% and 0-60% success rates, respectively. Applying the LIBERO-derived coaching tips to ManiSkill3 resulted in a decrease in overall success to 81.4% and an increase in API cost, suggesting that coaching benefits are task-specific and can be detrimental if irrelevant.

**Performance on MetaWorld Benchmark (Table III):**
The MetaWorld benchmark was used to test cross-embodiment transfer, featuring a different robot arm (Sawyer vs. Franka Panda) and simulation environment. With a configured simulator interface, FAEA achieved a 96% success rate (48/50 tasks) using its native agent capabilities. Two tasks were excluded from the successful count due to the agent exploiting internal MetaWorld state or performing an exhaustive search. With LIBERO-derived coaching, FAEA achieved 100% success. These results represent a substantial outperformance compared to VLA baselines, including SmolVLA (68.2%), in this simulated domain.

**Computational Resources and Agent Reasoning (Table IV & V):**
The computational cost and time per task varied significantly with task difficulty. Mean wall-clock times for task discovery ranged from 2.0 to 24.6 minutes per task category, encompassing multiple simulation attempts. API costs varied from $0.51 to $5.60 per task, with harder tasks demanding more tokens, turns, and tries. For instance, ManiSkill Hard tasks were 11 times more expensive and 12 times longer than Easy tasks.
Analysis of execution traces revealed systematic reasoning patterns. Tool usage showed Bash (script execution) dominating at 51% of total calls, followed by Write (script generation) at 30% and Read (output inspection) at 14%. WebFetch (documentation retrieval) accounted for 2%, primarily for initial API understanding. The consistent use of Read across benchmarks highlights the importance of feedback interpretation. The agent demonstrated hypothesis-driven debugging, performing structured root cause analysis when attempts failed. An example involved identifying a gripper displacement issue in a LIBERO task, leading to targeted debugging scripts and refinement of the approach trajectory.

### 5. Significance and Potential Impact

The research presented in "Demonstration-Free Robotic Control via LLM Agents" carries several implications for the field of robotic manipulation and the broader application of large language models.

**Addressing Data and Engineering Costs:** A primary significance of FAEA is its demonstration-free capability. By achieving competitive manipulation performance without requiring task-specific demonstrations or specialized robotics training, the framework directly addresses a significant bottleneck in current learning-based robotic policies: the substantial data collection and engineering costs. This could reduce the resources required to adapt robots to new tasks or environments.

**Iterative Policy Discovery:** The work highlights that the iterative reasoning and program synthesis capabilities inherent in general-purpose LLM agent frameworks, originally designed for software debugging, are transferable to the domain of embodied manipulation. This approach shifts the paradigm from learning policies from vast datasets to discovering effective manipulation programs through trial and error at test time, offering an alternative to traditional supervised learning.

**Tool for Data Augmentation:** A key potential impact lies in FAEA's ability to autonomously generate successful demonstration trajectories in simulation. This capability has immediate practical value for embodied learning, as it could serve as a scalable method for augmenting training data for VLA models. By automating the generation of diverse and successful trajectories, FAEA could help alleviate the labor-intensive process of manual teleoperation, thereby accelerating the development and generalization of VLA models.

**Leveraging Production-Grade Agent Infrastructure:** The study underscores the robustness of off-the-shelf, production-grade LLM agent SDKs for embodied control. By directly utilizing frameworks designed for reliable, long-running agent tasks—complete with context management, error handling, and structured tool interfaces—the research suggests that the robotics community might benefit from adopting such existing infrastructure rather than rebuilding custom agent systems, potentially accelerating development and improving system reliability.

**Limitations and Future Directions:** While demonstrating significant capabilities in simulation, the study also identifies important limitations that shape its immediate impact and outline future research. The consistent failure on tasks requiring sub-centimeter precision (e.g., peg insertion) suggests a fundamental mismatch between the deliberative, seconds-scale reasoning of the LLM agent and the milliseconds-scale requirements of fine-grained control. This implies that FAEA may be better suited as a deliberative planning layer above conventional, real-time controllers rather than a standalone real-time solution.

The current reliance on privileged state information and Cartesian control in simulation means that real-world deployment would necessitate robust perception modules (for object detection, pose estimation, and uncertainty handling), sophisticated motion layers (for collision-aware inverse kinematics and closed-loop control), and independent safety supervisors. These requirements indicate that FAEA is currently better supported as a simulation trajectory generator or a high-level deliberative layer.

Future work includes systematically characterizing task regimes to determine where agentic reasoning is most beneficial, developing robust guardrails for safe real-world deployment, and evaluating the quality and diversity of automatically generated trajectories for VLA training. The research's findings, though currently constrained to specific simulation conditions and a single agent framework, open avenues for developing more autonomous and adaptable robotic systems by creatively leveraging advanced LLM capabilities.
