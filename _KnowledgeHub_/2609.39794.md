# Inline Memory Meets Reusable Skills: Memory-centric Framework for Vision-Language-Action Model

> [!summary] Summary
> Optimus-R is a memory-centric adaptation framework for pi0.5-based VLAs that treats learning new tasks as query-skill memory tuning instead of weight updates. Learnable memory tokens inside the VLA prefix yield retrieval queries and action-grounded skill embeddings, stored as clustered prototypes with residual updates. With 30% data it adds 16.5 points on LIBERO, and it cuts real-world lifelong forgetting from 15% to 10%.

## Problem

- Most VLAs adapt to new tasks by fine-tuning weights, so every new skill is an implicit parameter change that is costly and risks catastrophic forgetting.
- Existing memory-augmented robot methods attach detached external context or episodic retrieval, weakly coupled to the action-conditioning pathway, so stored memories encode little control-relevant information.
- Under visual or dynamics domain shift such as sim-to-real, target-domain observations drift away from the source memory space, so queries no longer match stored skills.

## Method

- ==Inline Memory Interface==: ==learnable memory tokens== in the pi0.5 prefix stream, read by two ==attention-pooling heads== into a retrieval query and a skill embedding supervised by an action-chunk-reconstructing ==skill decoder==.
- ==Query-Skill Memory Bank==: decoupled query and skill prototypes built by ==query-space clustering== split on skill variance, retrieved top-2 via softmax similarity, with non-overwriting ==residual offsets== and gated prototype appending.
- ==Bridge-and-Adapt training==: Stage B aligns target-domain queries through a ==memory alignment map==, residuals and a zero-initialized ==low-rank skill adapter==; Stage C freezes the backbone and replays latent query-skill exemplars for lifelong learning.

## Results

- With **30%** data, LIBERO average rises from **72.1%** to **88.6%** over pi0.5 and CALVIN length from **2.09** to **2.51**; at full data it reaches **97.8%** LIBERO and **55.0%** RoboTwin Hard.
- Sim-to-real on **nine** bimanual Galaxea R1 Lite tasks: **33.3%** vs **19.4%** with **20** demos and **72.2%** vs **63.3%** with **80**; lifelong forgetting drops from **15.0%** to **10.0%**.
- Removing the Stage-B bridge barely hurts in-domain but drops 20-demo real-world success from **33.3%** to **12.8%**; versus pi0.5-LoRA it trains in **86** versus **128 GPU hours**, running at **14 Hz**.

## Takeaways

> [!tip] Key Insights
> - Memory that stores skills should live inside the policy's own conditioning pathway; detached retrieval prompts carry less control-relevant signal and lose several points in ablation.
> - Separating what-to-retrieve keys from how-to-act values, and updating through residuals rather than overwriting, offers a cheap route to continual learning with less interference.
> - Under domain shift, adding memory alone is not enough; realigning target queries to the existing memory coordinates matters most, making retrieval alignment the transfer bottleneck.

## Detailed Report

### 1. Overview

A robot has learned to place a red apple on a plate. Now it faces a changed pairing: a green apple and a basket. This calls for reusing what it already knows rather than building the behavior from scratch. Adapting by tuning parameters can be costly and can interfere with earlier skills. Optimus-R instead treats robot adaptation as a problem of saving and reusing skills, rather than making each new behavior another change to the model's weights. It builds a skill memory into the vision-language-action (VLA) model's own processing path, so new behaviors are retrievable and updateable.

The framework still uses parameter updates in some stages. It reduces reliance on repeated global fine-tuning rather than eliminating tuning altogether. ### 2. A skill memory inside the policy

Learnable memory tokens are inserted into the VLA's input prefix, so the backbone produces memory states within the policy pathway. Two separate readouts come from these states. A **query** is used to decide what to retrieve, and a **skill** is the action-related content to retrieve. During training, a skill decoder reconstructs future action chunks to supervise that skill representation.

The bank stores query prototypes paired with skill values. A prototype is a representative stored entry. At use time, the current query retrieves the top two matching entries and combines their skill values. The result is projected into tokens that condition the flow policy's action-chunk generation.

Memory can also be updated. In the lifelong stage, new samples are matched to existing prototypes or buffered. Existing entries receive residual corrections. A new prototype is added only after a buffered cluster has sufficient support and low query–skill variance. Latent query–skill exemplars support replay. The paper says these exemplars do not require storing raw images, actions, or trajectories.

### 3. The bridge matters when the domain shifts

The cross-domain test starts from RoboTwin 2.0 simulation pretraining. The model then adapts with 20, 50, or 80 real-world demonstrations per task on a 14-DoF bimanual robot. The score is average success rate over nine real-world tasks, with 20 rollouts per task. At 20 demonstrations per task, Optimus-R averaged 33.3%, versus 19.4% for reproduced π0.5, a difference of 13.9 percentage points. This is evidence for adaptation with limited target-domain demonstrations, not for zero-shot sim-to-real transfer. It is also not proof that memory alone caused the performance difference.

Which part of the design matters here? Stage B aligns target-domain queries to the existing memory coordinates and can adapt retrieved skills. It also unfreezes the backbone, so not every adaptation update is memory-only. The ablation "without Stage-B Bridge" means memory expansion without coordinate alignment.

At 20 real-world demonstrations per task, removing the bridge reduces average success from 33.3% to 12.8%. On RoboTwin 2.0 Hard at 50% data, the score changes only from 21.6% to 21.4%. This supports the authors' interpretation that memory-space alignment matters especially for this cross-domain setting. It does not establish that alignment is the only cause of transfer, or that the bridge guarantees it under more severe shifts.

Ablation success rates on RoboTwin 2.0 Hard at 50% and 100% data and on nine real-world tasks at 20, 50, and 80 demonstrations, comparing four ablations with the full method. Without the Stage-B Bridge: 12.8% versus 33.3% at 20 demos, and 21.4% versus 21.6% on RoboTwin at 50% data.

### 4. Make skills retrievable

The contribution is not simply storing past observations. Optimus-R organizes control-relevant skills so a policy can retrieve and adjust them when task context changes. The authors state its limits: cross-domain transfer still requires demonstrations and alignment, and it depends on a strong pretrained VLA. Transfer is not guaranteed under large embodiment changes, severe visual shifts, or substantially different dynamics.
