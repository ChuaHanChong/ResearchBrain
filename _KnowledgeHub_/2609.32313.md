# MemTransfer: Benchmarking Memory Beyond Matched Experience in Embodied Decision-Making

> [!summary] Summary
> MemTransfer is a benchmark that tests whether memory still helps an embodied agent when conditions change. It compares six memory types (working, full-context, summary, semantic, hybrid, episodic) under one frozen vision-language policy on 100 Isaac Sim warehouse navigation cases. Trajectory memories reach 95-100% success when the start matches the demonstration but lose about 48 points from a new start, and no single memory type is robust to every kind of mismatch.

## Problem

- Standard embodied benchmarks such as Habitat, ALFRED and BEHAVIOR reset the environment every trial, so they never test whether stored experience carries over to later episodes.
- Persistent-memory benchmarks like GOAT-Bench, iterative VLN and MultiON let memory accumulate but never control how past trajectories relate to the test episode.
- Memory benchmarks like LongBench and FindingDory measure recall or retrieval, not whether a policy can apply stored experience after the start pose, route or task relevance changes.

## Method

- Controlled warehouse benchmark: 100 navigation cases across ten task types (search, multi-object, return loops), each with four expert demonstrations from different starts plus new-start and blocked-route test episodes.
- Unified ==build-then-access== formulation: each memory is built once from demonstrations and read out per step, then passed to a frozen Intern-S2-Preview-397B policy alongside a shared six-step ==working-memory window==.
- ==Episodic memory== matches the current view to a stored frame with a ==ViT-B/16== encoder and returns the next six expert actions; follow and recovery rates measure behavior on blocked routes.

## Results

- With one demonstration, Full-context and Episodic reach **95.3%** and **100.0%** success from the original start but fall to **46.7%** and **51.7%** from a new start; Summary barely changes (**43.0%** to **44.3%**).
- After route blocking, Summary keeps only **39.3%** of its success, versus **44.8%** for Working memory and **56-58%** for the trajectory memories; recovery after hitting the blockage is around **30%** for both trajectory memories.
- Going from one to four relevant demonstrations raises Episodic success from **51.7%** to **66.0%**, while other memories gain at most **1.3** points; swapping in other-task histories drops Episodic to about **49%**.

## Takeaways

> [!tip] Key Insights
> - Robustness to one mismatch does not predict robustness to another: abstract scene summaries handle start-pose changes but break when stored routes go out of date.
> - How memory is accessed matters as much as what it stores; retrieving a local continuation matched to the current view scales with more experience, while full-document memory does not.
> - Memory should separate still-valid knowledge, like object locations, from route plans that can go stale, and revise the latter online using feedback from the environment.

## Detailed Report

### 1. Overview

A robot working repeatedly in a warehouse could use prior experience to avoid rediscovering an object's location. A new task may start elsewhere, though. An aisle may be blocked, or the accumulated history may include experience for other goals. MemTransfer tests each of these mismatches separately while holding the policy and interaction interface fixed. The authors' point is that performance on a matched repeat does not establish that memory will transfer to a changed task. They do not claim that one memory wins in every condition.

The simulated benchmark's clearest opening result uses one demonstration per task. In that setting, Episodic memory's success rate is 100.0% at the original demonstration start and 51.7% at a new test start. Both conditions use the same frozen VLM policy, and the new-start condition is averaged over three runs.

### 2. How the tests work

MemTransfer contains 100 navigation cases across ten task types in a simulated warehouse, with expert demonstrations as the historical experience. The study compares six configurations:

- **Working memory** is the baseline. It keeps recent interactions.
- **Full-context** supplies recorded actions and keyframes.
- **Episodic** retrieves a view-matched local continuation.
- **Summary** stores locations, landmarks, and routes.
- **Semantic** stores generalized spatial and navigation knowledge.
- **Hybrid** concatenates Summary and Semantic documents.

All historical forms supplement the recent-interaction window used by the baseline.

The benchmark varies three things: the test starting pose, route availability, and the amount and task relevance of history. Success rate (SR) is the percentage of 100 cases in which the agent completes all required visits, respects any prescribed order, and ends at the required location within the 200-step limit.

The two start conditions play different roles. The original-start result is a replay reference, an intentionally favorable match, and does not test generalization. The new-start result is the transfer test.

### 3. Start mismatch and route mismatch are different problems

Full-context and Episodic memory both expose expert actions, but they deliver them differently. Full-context provides the whole retained trajectory. Episodic retrieves a local continuation matched to the current view. At a new start, the policy has to relate the current state to those actions. Episodic's drop from 100.0% to 51.7% is consistent with sensitivity to this mismatch, but it does not prove a single cause.

A separate test fixes the test start at the original pose and changes where the demonstration started. There, Episodic outperforms Full-context for opposite-heading and nearby-start demonstrations. Both do poorly for distant-start demonstrations.

Tolerating a different start does not imply handling a blocked route. Summary changes little between the original and new test starts. The blocked-route test uses four demonstrations per task and a new start. Retention there means blocked-route SR divided by unchanged-route SR:

MemoryRetention of unchanged-route SR after blockingSummary39.3%Working memory44.8%Episodic56.1%Full-context58.3%

Blocking also reduces SR for Working memory. These results therefore do not show that historical memory alone causes the difficulty. Retaining more SR also does not prove better recovery after the agent encounters an obstacle.

These comparisons support the authors' interpretation that storage alone is insufficient: access and fit to the current state matter. They do not establish that any one representation is generally robust.

### 4. What the benchmark contributes

MemTransfer separates two questions that are often blurred together: what experience is stored, and whether the policy can use it under the current conditions. The study is a controlled comparison in one warehouse with one frozen VLM. It is not evidence that the same pattern holds across robots, policies, or environments. Memories also remain fixed during execution, so the study does not test selective updating or forgetting.
